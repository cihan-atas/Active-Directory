## 1. Kavramsal Temel — Neden Var?

Yanal hareketin ([Blue M04](../Modul_04_Yanal_Hareket_Tespiti/)) en yıkıcı biçimi **kimlik bilgisi hırsızlığıyla dikey tırmanıştır**: saldırgan bir iş istasyonundan Domain Admin'e ulaşır. Bunun kök nedeni neredeyse her zaman aynıdır: **ayrıcalıklı bir hesabın düşük güvenlikli bir makinede oturum açması.** Bir Domain Admin bir kullanıcının bilgisayarında oturum açtığında, kimlik bilgisi o makinenin LSASS'ine düşer ([Blue M03](../Modul_03_Kimlik_Bilgisi_Korumasi/)); o makine ele geçmişse admin de ele geçmiştir.

**Tier Model (Katmanlı Yönetim Modeli)**, bu "credential exposure" zincirini **mimari olarak** kırar. Varlıkları ve kimlikleri üç katmana böler ve **katmanlar arası oturum açmayı yasaklar**:

- **Tier 0:** Domain'in kontrolü — DC'ler, AD, ADFS, PKI, Tier 0 yönetici hesapları.
- **Tier 1:** Sunucular ve uygulamalar — üye sunucular, veritabanları.
- **Tier 2:** İş istasyonları ve kullanıcı cihazları.

> **İlke:** Yüksek katman kimliği, düşük katman makinesine **hiç uğramamalı.** Tier 0 admin yalnızca Tier 0 makinelerinde (DC/PAW) oturum açar. Böylece Tier 2 ele geçse bile Tier 0 sırrı orada **hiç bulunmaz.**

Bu, [03.3 Protected Users/Silos](../Modul_03_Kimlik_Bilgisi_Korumasi/03.3_Protected_Users_ve_Authentication_Policies.md)'ın "nereden oturum açılır" kilidinin **kurumsal mimari** düzeyidir ve [Sistem 10.3 Hardening](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.3_Hardening_Temelleri.md)'in Tier Model temelini operasyonelleştirir.

## 2. Teknik Derinlik

### 2.1 Katmanlar ve yasak akışlar

```
   ┌─────────────────── TIER 0 (Domain Kontrolü) ───────────────────┐
   │  DC'ler · AD · PKI · ADFS · Tier0 admin · PAW-T0                │
   │  Oturum: yalnızca Tier 0 makinelerinden                        │
   └───────▲──────────────────────────────────────────────┬────────┘
           │ ✗ YASAK (aşağıdan yukarı yönetim)             │ yönetir ▼
   ┌───────┴──────────────── TIER 1 (Sunucular) ───────────┴────────┐
   │  Üye sunucular · uygulamalar · DB · Tier1 admin · PAW-T1        │
   └───────▲──────────────────────────────────────────────┬────────┘
           │ ✗ YASAK                                        │ yönetir ▼
   ┌───────┴──────────────── TIER 2 (İstemciler) ──────────┴────────┐
   │  İş istasyonları · kullanıcılar · helpdesk (Tier2 admin)        │
   └────────────────────────────────────────────────────────────────┘
   Kural: Bir kimlik SADECE kendi katmanının makinelerinde oturum açar.
          Kontrol yukarıdan aşağı akar; kimlik asla aşağıya inmez.
```

### 2.2 Neden "aşağıya inmek" ölümcül?

Bir Tier 0 hesabı bir Tier 2 istemcide oturum açarsa, kimlik bilgisi (hash/bilet/DPAPI) o makinede önbelleğe/belleğe düşer. Tier 2 en çok saldırıya uğrayan katmandır (phishing, tarayıcı). Saldırgan Tier 2'yi ele geçirip oradaki Tier 0 sırrını çalarsa, **tek adımda domain düşer.** Tier Model bu tek adımı imkânsız kılar: Tier 0 sırrı Tier 2'de **hiç yoktur.**

### 2.3 Zorlayıcı mekanizmalar (sadece politika değil, teknik kilit)

Tier Model bir "kağıt kural" değildir; teknik olarak zorlanır:
- **Logon restrictions (GPO):** "Deny logon" hakları ([Sistem 04.1](../../1-Sistem_Yoneticisi/Modul_04_Grup_Ilkeleri_GPO/04.1_GPO_Mimarisi_ve_Isleyis.md)) ile Tier 0 hesabının Tier 1/2'de oturumu **reddedilir**.
- **Authentication Policy Silos:** [03.3](../Modul_03_Kimlik_Bilgisi_Korumasi/03.3_Protected_Users_ve_Authentication_Policies.md) — Kerberos düzeyinde kilit.
- **PAW (Privileged Access Workstation):** Yönetim yalnızca sertleştirilmiş özel makinelerden.
- **OU + grup ayrımı:** Her katmanın kendi admin grubu ve OU'su.

## 3. Pratik Uygulama

### 3.1 "Deny logon" ile katman kilidi (GPO)
```text
GPO (Tier 2 istemcilere link): Computer Config → Windows Settings →
  Security Settings → Local Policies → User Rights Assignment →
   "Deny log on locally"            = Tier0-Admins, Tier1-Admins
   "Deny log on through RDP"        = Tier0-Admins, Tier1-Admins
   "Deny log on as a batch/service" = Tier0-Admins, Tier1-Admins
→ Tier 0/1 hesapları Tier 2 makinesinde OTURUM AÇAMAZ (kimlik düşmez)
```

### 3.2 Katman yapısını kur (OU + gruplar)
```powershell
# Tier 0 için ayrı OU + admin grubu
New-ADOrganizationalUnit -Name "Tier0" -Path "OU=Admin,DC=corp,DC=local"
New-ADGroup -Name "Tier0-Admins" -GroupScope Global -Path "OU=Tier0,OU=Admin,DC=corp,DC=local"
# Tier 0 hesaplarını Protected Users + Silo'ya bağla (03.3)
Add-ADGroupMember "Protected Users" -Members (Get-ADGroupMember "Tier0-Admins")
```

### 3.3 İhlal denetimi (Tier 0 nerede oturum açtı?)
```powershell
# Tier 0 hesabının Tier 0 DIŞINDA oturum açması = ihlal
$tier0 = (Get-ADGroupMember "Tier0-Admins").SamAccountName
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} |
  Where-Object { $t=$_; $tier0 | Where-Object { $t.Message -match "Account Name:\s+$_" } } |
  Where-Object { $_.Message -notmatch 'DC0|PAW-T0' }   # Tier 0 makineleri hariç → kalan = ihlal
```

## 4. Tespit Değeri — Katman İhlali Alarmı

```yaml
# Sigma — Tier 0 kimliğinin düşük katmanda oturum açması (mimari ihlal)
title: Tier0 Kimligi Dusuk Katman Makinesinde - Credential Exposure
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: 4624
    TargetUserName|startswith: 'adm_t0_'      # Tier 0 adlandırma standardı
  filter:
    ComputerName|startswith: ['DC', 'PAW-T0']  # izinli Tier 0 makineleri
  condition: sel and not filter
level: critical
tags: [attack.privilege_escalation, attack.lateral_movement, attack.t1078.002]
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| Tier 0 hesabı Tier 1/2'de logon | 4624 | Credential exposure (mimari ihlal) | T1078.002 |
| Tier 0 gruba yeni üye | 4728/4756 | Ayrıcalık genişletme | T1098 |
| "Deny logon" hakkı değişimi | 4704/4705 | Katman kilidi gevşetme | T1484 |
| Tier 0 hesabıyla NTLM (4776) | Security | PAW dışı kullanım / PtH | T1550.002 |

## 5. Doğrulama / Lab

```powershell
# 1) Kilit kanıtı (izole lab): Tier0-Admin ile bir Tier 2 istemcide RDP dene
#    → BAŞARISIZ olmalı (Deny logon through RDP). Başarılıysa GPO uygulanmamış.
# 2) Envanter: Tier 0 gruplarının üyeliğini denetle (şişkinlik = risk)
Get-ADGroupMember "Domain Admins" | Measure-Object     # ideal: çok az, hepsi adm_t0_
# 3) Baseline: son 30 gün Tier 0 hesaplarının oturum açtığı TÜM makineleri listele
#    → Tier 0 dışı her makine bir bulgudur (temizlenmeli)
```
> **Kanıt:** "Tier 0 admin, Tier 2 istemcide oturum açamaz." Bu tek test, modelin kağıt üstünde değil teknik olarak zorlandığını gösterir.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Tier Model'i "kağıt kural" bırakmak:** Sadece dokümanda kalan katmanlar işe yaramaz; "Deny logon" GPO + Silos ile **teknik olarak zorla**.
- 🔴 **Domain Admins'i şişirmek:** Onlarca hesap DA olursa saldırı yüzeyi devasadır; DA üyeliği tek haneli ve yalnızca `adm_t0_` olmalı.
- ⚠️ **PAW'ı ihmal etmek:** Tier 0 admin PAW'dan yönetmeli; PAW yoksa admin yine bir istemciden yönetir ve model çöker.
- ⚠️ **Servis hesaplarını katmanlamamak:** Tier 0 servisleri Tier 1/2 makinelerinde çalışırsa credential exposure devam eder; gMSA + katman ayrımı.
- 🔍 **İzleme ipucu:** Tier 0 hesabının Tier 0 dışında **tek bir** 4624'ü bile mimari ihlaldir — eşiksiz, kritik alarm ([Blue M04](../Modul_04_Yanal_Hareket_Tespiti/) ile korele et).
