## 1. Kavramsal Temel — Neden Var?

GPO (Group Policy Object), bir OU'daki **tüm** makine ve kullanıcıya kod/ayar dağıtan güçlü bir mekanizmadır ([Sistem 04.1](../../1-Sistem_Yoneticisi/Modul_04_Grup_Ilkeleri_GPO/04.1_GPO_Mimarisi_ve_Isleyis.md)). Bu güç, saldırgan için de bir silahtır: bir GPO üzerinde **yazma hakkı** olan biri, o GPO'nun bağlı olduğu tüm makinelerde **zamanlanmış görev, script veya yerel admin ekleme** yoluyla kod çalıştırabilir. Bir DC'lere bağlı GPO'ya yazabilen saldırgan, tüm domain'i ele geçirir.

Aynı şekilde **yetki devri (delegation)** — OU üzerinde birine verilen yönetim hakkı — dikkatsiz yapıldığında ayrıcalık yükseltme yoludur: bir OU'da "reset password" yetkisi verilen helpdesk hesabı, o OU'daki bir Tier 0 hesabını da sıfırlayabiliyorsa, Tier Model çöker.

> **İlke:** GPO bir "uzaktan kod çalıştırma" aracıdır; ona kim yazabiliyorsa, o kişi bağlı makinelerde SYSTEM'dir. GPO yazma hakkını ve OU delegation'ını **ayrıcalık gibi** koru.

Bu dosya, [Sistem 04.1](../../1-Sistem_Yoneticisi/Modul_04_Grup_Ilkeleri_GPO/04.1_GPO_Mimarisi_ve_Isleyis.md)/[04.2](../../1-Sistem_Yoneticisi/Modul_04_Grup_Ilkeleri_GPO/04.2_Hedefleme_ve_Filtreleme.md)'nin güvenlik denetimidir ve [05.2](./05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md) ACL hijyeninin GPO'ya özgü uygulamasıdır.

## 2. Teknik Derinlik

### 2.1 GPO abuse zinciri

```
   Saldırgan: bir GPO'da WriteProperty/GenericAll hakkı var
        │
        ▼
   GPT (SYSVOL) içeriğini değiştir  ─────► scheduledtasks.xml ekle
        │                                  (veya Registry.pol → yerel admin)
        ▼
   Bağlı OU'daki TÜM makineler bir sonraki gpupdate'te uygular
        │
        ▼
   SYSTEM olarak kod çalışır → yerel admin eklenir → yanal hareket/hakimiyet
   Not: MS16-072 sonrası GPO makine bağlamında okunur; yine de yazma = RCE.
```

### 2.2 GPO'nun iki parçası ve her ikisinin DACL'i

Bir GPO iki bölümden oluşur ([Sistem 04.1](../../1-Sistem_Yoneticisi/Modul_04_Grup_Ilkeleri_GPO/04.1_GPO_Mimarisi_ve_Isleyis.md)): **GPC** (AD'deki nesne) ve **GPT** (SYSVOL'deki dosyalar). Saldırgan **her ikisine de** yazabilmeli — ama pratikte GPC'deki `nTSecurityDescriptor` yazma hakkı yeterlidir (GPT izinleri genelde onu izler). Bu yüzden denetim, GPO nesnesinin DACL'ine ve SYSVOL izinlerine bakar.

### 2.3 Delegation hijyeni: en az ayrıcalık

OU delegation, "reset password", "create/delete user", "link GPO" gibi hakları verir. Tehlike: (a) çok geniş kapsam (tüm domain yerine tek OU), (b) yanlış OU (Tier 0 hesaplarının bulunduğu OU'da helpdesk yetkisi), (c) `Apply Group Policy` hakkının kötüye kullanımı. Her delegation **en dar kapsam + doğru OU** ilkesiyle verilmeli ve düzenli denetlenmeli.

## 3. Pratik Uygulama

### 3.1 GPO yazma hakkı denetimi (kim hangi GPO'ya yazabiliyor?)
```powershell
# Güvenilmeyen principal'lara yazma hakkı veren GPO'lar
Get-GPO -All | ForEach-Object {
  $gpo = $_
  Get-GPPermission -Guid $gpo.Id -All |
    Where-Object { $_.Permission -match 'GpoEditDeleteModifySecurity|GpoEdit' -and
                   $_.Trustee.Name -notmatch 'Domain Admins|Enterprise Admins|SYSTEM' } |
    ForEach-Object { [pscustomobject]@{ GPO=$gpo.DisplayName; Kim=$_.Trustee.Name; Hak=$_.Permission } }
}
```

### 3.2 DC'lere bağlı GPO'ları özel denetle (en kritik)
```powershell
# Default Domain Controllers Policy ve DC OU'suna bağlı GPO'lara kim yazabiliyor?
$dcOU = "OU=Domain Controllers,$((Get-ADDomain).DistinguishedName)"
(Get-ADOrganizationalUnit $dcOU -Properties gpLink).gpLink   # bağlı GPO'ları çıkar
# → her birinin GPPermission'ını yukarıdaki gibi denetle (Tier 0 dışı yazma = kritik)
```

### 3.3 OU delegation envanteri
```powershell
# Bir OU'daki delege edilmiş (miras olmayan) ACE'ler
$ou = "OU=Workstations,$((Get-ADDomain).DistinguishedName)"
(Get-Acl "AD:\$ou").Access | Where-Object { -not $_.IsInherited } |
  Select IdentityReference, ActiveDirectoryRights, ObjectType, AccessControlType
```

## 4. Tespit Değeri — GPO ve Delegation Değişimi

```yaml
# Sigma — GPO içeriği veya izni değişti (SYSVOL yazımı / DACL abuse)
title: GPO Degisimi veya Yetki Manipulasyonu
logsource: { product: windows, service: security }
detection:
  gpo_object:
    EventID: 5136
    ObjectClass: 'groupPolicyContainer'
  sysvol_write:
    EventID: 4663
    ObjectName|contains: '\SYSVOL\'
    ObjectName|endswith: ['ScheduledTasks.xml','Registry.pol','GptTmpl.inf']
  condition: gpo_object or sysvol_write
level: high
tags: [attack.privilege_escalation, attack.t1484.001]
```
```powershell
# Get-WinEvent — GPO nesnesi değişiklikleri (kim, hangi GPO)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=5136} |
  Where-Object { $_.Message -match 'groupPolicyContainer' } |
  Select TimeCreated, @{N='Detay';E={$_.Message.Split("`n")[0]}}
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| `groupPolicyContainer` değişimi | 5136 | GPO düzenleme/izin değişimi | T1484.001 |
| SYSVOL'de ScheduledTasks.xml yazımı | 4663 | GPO ile kod dağıtımı (abuse) | T1484.001 |
| OU'da yeni delegation ACE | 5136 | Yetki devri manipülasyonu | T1098 |
| `gpLink` değişimi | 5136 | GPO bağlama (yeni hedef) | T1484.001 |

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **GPO yazma hakkını hafife almak:** GPO'ya yazma = bağlı makinelerde SYSTEM; DC OU GPO'larına yalnızca Tier 0 yazabilmeli.
- 🔴 **SYSVOL izinlerini denetlememek:** GPC DACL temiz olsa da SYSVOL'de gevşek NTFS izni GPT'ye yazma yolu açabilir; ikisini birlikte denetle.
- ⚠️ **Delegation'ı geniş kapsamda vermek:** "Tüm domain'de reset password" yerine "yalnızca Tier 2 OU'da"; kapsamı ve katmanı daralt.
- ⚠️ **5136/4663 (SYSVOL) denetimini açmamak:** GPO abuse'un iki izi de bu olaylardır; audit kapalıysa görünmez.
- 🔍 **İzleme ipucu:** SYSVOL'de `ScheduledTasks.xml` veya `Registry.pol` yazımı, meşru GPO düzenlemesi dışında saldırganın kod dağıtma imzasıdır — GPMC değişiklik kaydıyla korele et.
