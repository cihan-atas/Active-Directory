## 1. Kavramsal Temel — Neden Var?

Tier Model ([05.1](./05.1_Admin_Tier_Model.md)) "kim nereden oturum açar"ı kilitler; ama AD'de yetki yalnızca grup üyeliğiyle değil, **her nesnenin üzerindeki DACL (Discretionary ACL) ile** de verilir. Bir kullanıcı "Domain Admins" üyesi olmasa bile, bir DA hesabı üzerinde **GenericAll** veya **ForceChangePassword** hakkı varsa, o hesabın parolasını sıfırlayıp DA olabilir. Bu **ACL tabanlı ayrıcalık yükseltme**, BloodHound'un ([Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/)) domain'i ele geçirmek için izlediği "attack path"lerin belkemiğidir.

Sorun sinsidir: bu tehlikeli haklar genelde **yıllar içinde biriken yanlış yapılandırmalardan** doğar — birine geçici yetki verilir, unutulur; bir grup yanlışlıkla geniş hak alır. Saldırgan bunları **keşif** ile bulur ([Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/)); savunma bunları **saldırgandan önce** bulup temizlemelidir.

> **İlke:** Grup üyeliği görünür, DACL görünmez. Saldırgan görünmez yetki yollarını arar; sen de aynı grafiği çizip **saldırıdan önce budamalısın.**

Bu, [Sistem 03.1 OU/Yetki Devri](../../1-Sistem_Yoneticisi/Modul_03_Nesne_ve_Kimlik_Yonetimi/03.1_OU_Tasarimi_ve_Yetki_Devri.md)'nin "delegation" tasarımının güvenlik denetimi karşılığıdır.

## 2. Teknik Derinlik

### 2.1 Tehlikeli haklar ve neyi mümkün kılar

```
   HAK (ACE)              NE YAPILABİLİR                          SALDIRI
   ─────────              ──────────────                          ───────
   GenericAll             Tam kontrol — parola sıfırla, SPN ekle  her şey
   GenericWrite           Attribute yaz — SPN/logon script ekle   Kerberoast/RBCD
   WriteDACL              ACL'i değiştir → kendine GenericAll ver  ayrıcalık zinciri
   WriteOwner             Sahipliği al → sonra WriteDACL           ayrıcalık zinciri
   ForceChangePassword    Parolayı sıfırla (eskisini bilmeden)    hesap ele geçirme
   AllExtendedRights      DCSync (Get-Changes) dahil uzantı hak.  DCSync → domain
   AddMember              Gruba üye ekle                          grup ele geçirme
```

### 2.2 ACL saldırı yolu (attack path) mantığı

BloodHound bir **grafik** kurar: düğümler (kullanıcı/grup/bilgisayar), kenarlar (haklar). Saldırgan, kontrolündeki bir düğümden "Domain Admins"e giden **en kısa yolu** arar:

```
   normaluser ──GenericWrite──► svc_helpdesk ──ForceChangePassword──► adm_helpdesk
        │                                                                  │
        └──────────► adm_helpdesk ──MemberOf──► "Server Admins" ──WriteDACL──► DC01
   Sonuç: normaluser 3 kenar üzerinden DC'yi ele geçirir. Her kenar bir DACL hatası.
```

Savunmanın görevi: bu grafiği **kendisi çizmek** (BloodHound'u savunma amaçlı kullanmak → [Blue M09](../Modul_09_Tehdit_Avciligi_ve_Degerlendirme/)) ve tehlikeli kenarları **kırmak**.

### 2.3 Kalıcı hak biriktirme kaynağı

Tehlikeli DACL'ler genelde: (a) eski/terk edilmiş delegation, (b) `Authenticated Users`/`Everyone`'a verilmiş geniş yazma hakkı, (c) iç içe grup üyelikleriyle miras alınan haklar. Düzenli denetim (audit) olmadan bunlar sessizce birikir.

## 3. Pratik Uygulama

### 3.1 Tehlikeli ACE avı (PowerShell — kritik nesneler)
```powershell
# Domain Admins üzerinde SAHİPLİK + tehlikeli hakları olan güvenilmeyen principal'lar
$da = Get-ADGroup "Domain Admins"
(Get-Acl "AD:\$($da.DistinguishedName)").Access |
  Where-Object { $_.ActiveDirectoryRights -match 'GenericAll|WriteDacl|WriteOwner|WriteProperty' -and
                 $_.IdentityReference -notmatch 'Domain Admins|Enterprise Admins|SYSTEM|Administrators' } |
  Select IdentityReference, ActiveDirectoryRights, ObjectType
```

### 3.2 DCSync hakkı olan principal'ları bul (kritik)
```powershell
# Domain kökünde replikasyon (DCSync) uzatılmış hakkı olanlar
$domainDN = (Get-ADDomain).DistinguishedName
(Get-Acl "AD:\$domainDN").Access |
  Where-Object { $_.ObjectType -in @(
    '1131f6aa-9c07-11d1-f79f-00c04fc2dcd2',   # DS-Replication-Get-Changes
    '1131f6ad-9c07-11d1-f79f-00c04fc2dcd2') } |   # Get-Changes-All
  Where-Object { $_.IdentityReference -notmatch 'Domain Controllers|Enterprise|SYSTEM' } |
  Select IdentityReference, ObjectType   # beklenmeyen = DCSync riski → Red M09
```

### 3.3 Savunma amaçlı BloodHound (kendi grafiğini çiz)
```text
1) SharpHound/AzureHound ile veri topla (yetkiyle, kendi ortamında).
2) BloodHound'da "Shortest Path to Domain Admins" sorgusu çalıştır.
3) Kısa yol üreten her tehlikeli kenarı (GenericAll vb.) belgele ve KIR.
4) Düzenli (haftalık/aylık) tekrar → yeni biriken haklar yakalanır. [Blue M09]
```

## 4. Tespit Değeri — ACL Değişimi ve Kötüye Kullanım

DACL'in **değiştirilmesi** (saldırganın kendine hak eklemesi) ve **kullanılması** (parola sıfırlama) izlenmelidir:

```yaml
# Sigma — Kritik nesne üzerinde DACL/sahiplik değişimi (yetki abuse)
title: Ayricalikli Nesne DACL Degisimi (WriteDACL/WriteOwner Abuse)
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: 5136                          # dizin nesnesi değişti
    AttributeLDAPDisplayName: 'nTSecurityDescriptor'
  condition: sel
level: high
tags: [attack.privilege_escalation, attack.t1222, attack.t1098]
```
```powershell
# Get-WinEvent — ForceChangePassword abuse (başkasının parolasını sıfırlama)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4724} |   # parola reset denemesi
  Where-Object { $_.Message -notmatch 'helpdesk_approved' } |
  Select TimeCreated, @{N='Kim';E={($_.Message -split 'Subject:.*Account Name:\s+')[1].Split("`n")[0]}}
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| `nTSecurityDescriptor` değişimi | 5136 | DACL/WriteDACL abuse | T1222 |
| Ayrıcalıklı hesap parola reset | 4724 | ForceChangePassword abuse | T1098 |
| DCSync hakkı ekleme | 5136 | Domain hakimiyeti hazırlığı | T1003.006 |
| Gruba üye ekleme (AddMember) | 4728/4756 | Grup ele geçirme | T1098 |

## 5. Doğrulama / Lab

```powershell
# 1) Attack path testi (izole lab): BloodHound'da Domain Admins'e giden
#    kısa yol var mı? → varsa her tehlikeli kenarı kır, tekrar tara → yol kalmamalı
# 2) Temizlik kanıtı: bir test kullanıcısına GenericAll ver → BloodHound yakalasın
#    → kaldır → yol kaybolsun. Denetimin işlediğini gösterir.
Invoke-AtomicTest T1098 -TestNumbers 1     # ACL değişimi → 5136 üretmeli, §4 kuralı alarm
```
> **Kanıt:** "Domain Admins'e giden en kısa yol yok" — BloodHound bunu doğruladığında ACL hijyeni sağlanmıştır. Tek bir tehlikeli kenar bile bir attack path'tir.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **DACL'i hiç denetlememek:** Tehlikeli haklar yıllar içinde sessizce birikir; yıllık değil **düzenli** (BloodHound) tarama şart.
- 🔴 **`Authenticated Users`/`Everyone`'a yazma hakkı:** Kritik nesnelerde bu, "herkes ayrıcalık yükseltebilir" demektir; derhal daralt.
- ⚠️ **Sadece Domain Admins'e bakmak:** AdminSDHolder, GPO'lar, DC bilgisayar nesneleri, DCSync hakları da denetlenmeli — attack path bunların herhangi birinden geçebilir.
- ⚠️ **5136 denetimini açmamak:** `nTSecurityDescriptor` değişimi görünmüyorsa WriteDACL abuse tespit edilemez → [Sistem 10.4](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.4_Denetim_ve_Uyumluluk.md).
- 🔍 **İzleme ipucu:** Beklenmeyen bir principal'a **DCSync hakkı** (Get-Changes-All) eklenmesi, domain hakimiyeti hazırlığının en güçlü erken işaretidir → [Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/).
