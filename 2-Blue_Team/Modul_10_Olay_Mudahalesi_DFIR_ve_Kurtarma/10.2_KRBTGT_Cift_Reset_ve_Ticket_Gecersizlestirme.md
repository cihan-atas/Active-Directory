## 1. Kavramsal Temel — Neden Var?

**krbtgt**, domain'in Kerberos anahtar dağıtım hesabıdır; onun parola hash'i tüm TGT'leri (Ticket Granting Ticket) imzalar/şifreler. Bir saldırgan bu hash'i ele geçirirse (DCSync → [Blue 05.2](../Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md)), **Golden Ticket** üretir: istediği kullanıcı/grup için, KDC'yi hiç görmeden, yıllarca geçerli **sahte TGT**. Bu, domain hakimiyetinin altın standardıdır ([Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/)) ve klasik önlemleri (parola değişimi, hesap kilitleme) **tamamen atlatır** — çünkü Golden Ticket herhangi bir hesabın parolasına bağlı değildir, krbtgt'ye bağlıdır.

Golden Ticket'ı geçersiz kılmanın **tek yolu krbtgt parolasını değiştirmektir** — ama bir **incelik** vardır: krbtgt'nin **iki parola geçmişi (N ve N-1)** tutulur ve KDC her ikisini de kabul eder. Tek reset, saldırganın çaldığı hash'i **N-1'e** taşır — hâlâ geçerli! Bu yüzden **iki kez reset** (aralarında replikasyon tamamlanacak kadar bekleyerek) gerekir: birinci reset çalınan hash'i N-1 yapar, ikincisi onu tamamen tarihe gömer.

> **İlke:** Golden Ticket parola değişimini umursamaz — yalnızca krbtgt reset onu keser. Ve krbtgt'nin iki-parola geçmişi yüzünden **tek reset yetmez; iki kez** (replikasyon bekleyerek) resetle.

Bu, [Sistem 10.2 Kurtarma](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.2_Yedekleme_ve_Kurtarma.md)'nın en kritik operasyonel prosedürüdür.

## 2. Teknik Derinlik

### 2.1 İki-reset mantığı ve N/N-1 geçmişi

```
   Başlangıç: krbtgt hash = H0 (saldırgan H0'ı ÇALDI → Golden Ticket H0 ile imzalı)
   KDC kabul eder: [N=H0]  [N-1=önceki]

   ① 1. RESET:  krbtgt → H1
      KDC kabul eder: [N=H1]  [N-1=H0]   ⚠ H0 HÂLÂ geçerli (Golden çalışır!)
      │  REPLİKASYON BEKLE (tüm DC'ler H1'i alsın — saatler)
      ▼
   ② 2. RESET:  krbtgt → H2
      KDC kabul eder: [N=H2]  [N-1=H1]   ✓ H0 ARTIK YOK → Golden Ticket ÖLDÜ
```

### 2.2 Neden replikasyon beklemek şart?

İki reset'i **art arda hızlıca** yaparsan, bazı DC'ler henüz H1'i replike etmemişken H2'ye geçersin — bu, meşru kullanıcıların biletlerini kırar (auth kesintisi) ve replikasyon tutarsızlığı yaratır. Doğru prosedür: 1. reset → **tüm DC'lere replikasyonu doğrula** → makul bekleme (bilet ömrü ~10 saat kadar, ama en az replikasyon tamamlanana dek) → 2. reset. Microsoft'un krbtgt reset script'i bu güvenli akışı sağlar.

### 2.3 Reset'in yan etkileri (planlama)

krbtgt reset, **mevcut tüm TGT'leri geçersiz kılar** — meşru kullanıcılar dahil. Etki: kullanıcılar yeniden kimlik doğrular (çoğu şeffaf), ama bazı hizmetler (uzun ömürlü bilete dayananlar) kısa kesinti yaşayabilir. Bu yüzden ikinci reset **kontrollü bir bakım penceresinde** ve iletişimle yapılır. Yine de saldırı altında bu kesinti kabul edilebilir bir bedeldir.

## 3. Pratik Uygulama

### 3.1 Reset öncesi: DCSync/Golden doğrula ve replikasyon sağlığı
```powershell
# krbtgt'nin mevcut parola yaşı (çok eskiyse zaten risk — 06.4/PingCastle)
Get-ADUser krbtgt -Properties PasswordLastSet | Select PasswordLastSet
# Replikasyon sağlığı (reset öncesi ŞART — bekleme süresini bununla doğrula)
repadmin /replsummary
repadmin /showrepl
```

### 3.2 Birinci reset (Microsoft güvenli script ile)
```powershell
# Microsoft "New-KrbtgtKeys.ps1" güvenli reset (önerilen yöntem)
# 1. RESET — tek DC'de, sonra replikasyonu bekle/zorla
.\New-KrbtgtKeys.ps1     # mode: single reset + replikasyon doğrulama
# Manuel alternatif (dikkatli): 
# Set-ADAccountPassword -Identity krbtgt -Reset (rastgele karmaşık parola)
repadmin /syncall /AdeP    # tüm DC'lere replikasyonu zorla
```

### 3.3 Replikasyonu doğrula, bekle, ikinci reset
```powershell
# 1. reset TÜM DC'lere ulaştı mı? (doğrula)
repadmin /showobjmeta * "CN=krbtgt,CN=Users,DC=corp,DC=local" | Select-String "pwdLastSet"
# Makul bekleme (replikasyon + bilet ömrü) SONRASINDA:
.\New-KrbtgtKeys.ps1     # 2. RESET → çalınan hash tamamen geçersiz
repadmin /syncall /AdeP
```

## 4. İzleme / Doğrulama Değeri — Reset Sonrası Golden Ölümü

```yaml
# Sigma — Reset SONRASI hâlâ eski krbtgt ile Kerberos (başarısız Golden = doğru)
title: KRBTGT Reset Sonrasi Gecersiz Bilet Kullanimi
logsource: { product: windows, service: security }
detection:
  sel: { EventID: 4769, FailureCode: '0x1F' }   # bilet bütünlük/decrypt hatası
  condition: sel
level: high
tags: [attack.credential_access, attack.t1558.001]
```
```powershell
# Get-WinEvent — reset sonrası Golden Ticket denemeleri artık BAŞARISIZ olmalı
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4769} |
  Where-Object { $_.Message -match 'Failure Code:\s+0x1F|0x1B' } |   # decrypt/integrity fail
  Select TimeCreated, @{N='Hesap';E={($_.Message -split 'Account Name:\s+')[1].Split("`n")[0]}}
```

| Sinyal | Event | Anlamı |
|--------|-------|--------|
| 4769 FailureCode 0x1F | Security | Eski (Golden) bilet artık geçersiz → reset başarılı |
| krbtgt pwdLastSet güncel | AD/repl | Reset uygulandı, replike oldu |
| Meşru auth kesintisi (geçici) | 4771 | Kullanıcılar yeniden auth (beklenen yan etki) |
| Reset sonrası hâlâ Golden çalışıyor | 4769 başarı | ⚠ İkinci reset eksik/replike olmadı |

## 5. Doğrulama / Lab

```powershell
# 1) Golden testi (izole lab): krbtgt hash'iyle Golden üret → çalıştığını gör →
#    1. reset → Golden HÂLÂ çalışır (N-1!) → 2. reset (replikasyon sonrası) →
#    Golden artık BAŞARISIZ (4769 0x1F). Bu, iki-reset zorunluluğunun kanıtıdır.
Invoke-AtomicTest T1558.001 -TestNumbers 1
# 2) Replikasyon doğrulama: repadmin ile krbtgt pwdLastSet tüm DC'lerde güncel mi?
# 3) Kesinti ölçümü: reset penceresinde meşru auth etkisi (planlama için)
```
> **Kanıt:** Tek reset sonrası Golden **hâlâ çalışır** (N-1 geçmişi); ancak ikinci reset (replikasyon beklenerek) sonrası **başarısız** olur. Bu ikili test, prosedürün neden iki adımlı olduğunu somutlar.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Tek kez resetlemek:** krbtgt'nin N-1 geçmişi yüzünden tek reset Golden'ı **kesmez**; iki kez (replikasyon bekleyerek) resetle.
- 🔴 **İki reset'i art arda hızlıca yapmak:** Replikasyon tamamlanmadan ikinci reset meşru biletleri kırar ve tutarsızlık yaratır; arada repadmin ile doğrula ve bekle.
- 🔴 **Sadece krbtgt resetleyip kaynağı bırakmak:** Saldırgan DCSync hakkını ([Blue 05.2](../Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md)) veya başka kalıcılığı koruyorsa yeni krbtgt'yi tekrar çalar; kaynağı ve tüm kalıcılığı ([10.1](./10.1_IR_Playbook_Tespitten_Containment.md)) da temizle.
- ⚠️ **Manuel reset'te zayıf parola:** Elle reset ederken parolayı sen seçme; Microsoft script'i rastgele güçlü anahtar üretir.
- 🔍 **İzleme ipucu:** Reset sonrası 4769 **0x1F (decrypt/integrity fail)** olayları, eski Golden biletlerinin artık reddedildiğinin — yani reset'in başarılı olduğunun — kanıtıdır; bunların görülmesi olumludur.
