## 1. Genel Bakış ve Savunma Mimarisi

Kurumsal şirketlerde Linux sunucular (veritabanı, Kubernetes worker'ları, CI/CD runner'ları) sıklıkla Active Directory etki alanına dahil edilir. Ancak savunma ekipleri güvenlik izleme ve sertleştirme çalışmalarını çoğunlukla yalnızca Windows uç noktalarına odaklar. Bu durum, etki alanına bağlı Linux sistemlerin **en zayıf halka** haline gelmesine yol açar.

Linux sistemlerde kimlik doğrulaması `SSSD (System Security Services Daemon)` ve `MIT Kerberos` kütüphaneleriyle yürütülür. Bu mimaride iki temel hassas varlık korunmalıdır:
1. **`/etc/krb5.keytab`:** Sunucunun etki alanındaki bilgisayar hesabının (`HOSTNAME$`) veya barındırdığı servislerin Kerberos anahtarlarını barındırır. Bu dosyanın sızdırılması, saldırgana parola gerektirmeden etki alanından bilet alma ve yanal hareket imkanı verir.
2. **Kerberos Bilet Önbellekleri (CCACHE):** Etki alanı kullanıcılarının (Domain Adminler dahil) SSH veya konsol oturumlarında oluşturulan TGT biletleri varsayılan olarak `/tmp/krb5cc_<uid>` dosyasında tutulur. Bu dosyaların disk yerine çekirdek hafızasında (Kernel Keyring / KCM) tutulması şarttır.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       GÜVENLİ LINUX AD DS MİMARİSİ                          │
└─────────────────────────────────────────────────────────────────────────────┘
                                       │
            ┌──────────────────────────┴──────────────────────────┐
            ▼                                                     ▼
┌───────────────────────────────────────┐   ┌───────────────────────────────────────┐
│     KEYTAB GÜVENLİĞİ VE İZLEME        │   │    BİLET ÖNBELLEK İZOLASYONU (KCM)    │
│  - Dosya İzni: 0600 (Sadece root)     │   │  - default_ccache_name = KCM:         │
│  - Sahip: root:root                   │   │  - /tmp dosya tabanlı bilet YASAKLI!  │
│  - auditd Kuralı: open/read alarmlama │   │  - Çekirdek bellek şifrelemesi aktif  │
│  - Periyodik makine parolası rotasyonu│   │  - Oturum kapandığında bilet imhası   │
└───────────────────────────────────────┘   └───────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                 SSSD VE KERBEROS KRİPTOGRAFİK SERTLEŞTİRME                  │
│  - RC4 / DES Şifreleme Yasak -> Zorunlu: AES-256 (aes256-cts-hmac-sha1-96)  │
│  - FAST (Flexible Authentication Secure Tunneling) Armoring Aktif           │
│  - ad_gpo_access_control = enforcing (GPO ile erişim denetimi)             │
│  - simple_allow_groups ile oturum açabilecek AD gruplarını kısıtlama        │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. Keytab ve SSSD Sertleştirme Yapılandırması

### 2.1. `/etc/krb5.keytab` İzinlerini Kısıtlama

Keytab dosyası hiçbir koşulda standart kullanıcılar veya yetkisiz servisler tarafından okunamaz olmalıdır:

```bash
# 1. Dosya sahipliğini ve izinlerini katılaştırma (0600)
chown root:root /etc/krb5.keytab
chmod 0600 /etc/krb5.keytab

# 2. İzinleri doğrulama
ls -la /etc/krb5.keytab
# Çıktı kesinlikle: -rw------- 1 root root ... olmalıdır!
```

### 2.2. `/etc/krb5.conf` Kriptografik Sıkılaştırma

Zayıf RC4 şifrelemeyi engellemek ve biletleri disk yerine çekirdek hafızasında (KCM) saklamak için `/etc/krb5.conf` yapılandırılır:

```ini
[libdefaults]
    default_realm = CORP.LOCAL
    dns_lookup_realm = false
    dns_lookup_kdc = true
    rdns = false
    ticket_lifetime = 10h
    renew_lifetime = 7d
    forwardable = true

    # BİLETLERİ /tmp YERİNE KCM ÇEKİRDEK HAFIZASINDA TUTMA (KRİTİK)
    default_ccache_name = KCM:

    # SADECE GÜÇLÜ AES ŞİFRELEME TÜRLERİNE İZİN VER
    default_tkt_enctypes = aes256-cts-hmac-sha1-96 aes128-cts-hmac-sha1-96
    default_tgs_enctypes = aes256-cts-hmac-sha1-96 aes128-cts-hmac-sha1-96
    permitted_enctypes = aes256-cts-hmac-sha1-96 aes128-cts-hmac-sha1-96
```

### 2.3. `/etc/sssd/sssd.conf` Güvenli Yapılandırma

```ini
[domain/corp.local]
    id_provider = ad
    auth_provider = ad
    access_provider = ad
    chpass_provider = ad

    # GPO ERİŞİM KONTROLÜNÜ ZORUNLU KIL
    ad_gpo_access_control = enforcing

    # SADECE BELİRLİ AD GRUPLARINA SSH OTURUMU AÇMA İZNİ VER
    access_provider = simple
    simple_allow_groups = Linux_Admins, DevOps_Team

    # KERBEROS BİLETLERİNİ ŞİFRELİ SSSD ÖNBELLEĞİNDE TUT
    krb5_ccachedir = /run/user/%U
    krb5_store_password_if_offline = false

    # SİSTEM KONTROL VE ENTEGRASYON DOĞRULAMASI
    ldap_id_mapping = True
    use_fully_qualified_names = False
```

```bash
# SSSD dosya izinlerini düzeltip servisi yeniden başlatma
chmod 0600 /etc/sssd/sssd.conf
chown root:root /etc/sssd/sssd.conf
systemctl restart sssd
```

## 3. Linux `auditd` ile Tehdit Avcılığı ve Telemetri

Saldırganlar keytab dosyalarını veya kullanıcı biletlerini okumaya çalıştığı an `auditd` çekirdek denetleyicisi alarm üretmelidir.

### 3.1. `/etc/audit/rules.d/active_directory.rules` Kural Kümesi

```bash
# 1. Keytab dosyasına tüm erişim ve okuma girişimlerini izleme
-w /etc/krb5.keytab -p rwa -k ad_keytab_tampering

# 2. Kerberos konfigürasyon dosyası değişikliklerini izleme
-w /etc/krb5.conf -p wa -k ad_krb5_conf_tampering
-w /etc/sssd/sssd.conf -p wa -k ad_sssd_conf_tampering

# 3. Geçici bilet dizinlerini denetleme (/tmp altındaki krb5cc dosyaları)
-w /tmp/ -p wa -k ad_tmp_ccache_creation

# 4. SSSD önbellek veritabanı erişimlerini izleme
-w /var/lib/sss/db/ -p rwa -k ad_sssd_cache_access

# 5. kinit ve klist yürütmelerini izleme
-w /usr/bin/kinit -p x -k ad_kinit_exec
-w /usr/bin/klist -p x -k ad_klist_exec
```

```bash
# Kuralları yükleme ve doğrulama
augenrules --load
auditctl -l
```

## 4. SIEM / Sigma Tespit Kuralı

### Sigma Kuralı: Yetkisiz Keytab Okuma Girişimi Tespiti

```yaml
title: Unauthorized Linux Keytab Access
id: 9a7b2c14-5d3e-4f8a-a12b-linux-keytab-read
status: production
description: Detects non-system or unauthorized processes attempting to read /etc/krb5.keytab on domain-joined Linux hosts.
logsource:
    product: linux
    service: auditd
detection:
    selection:
        key: 'ad_keytab_tampering'
        name: '/etc/krb5.keytab'
    filter_legitimate:
        exe:
            - '/usr/sbin/sssd'
            - '/usr/sbin/sssd_be'
            - '/usr/sbin/httpd'
            - '/usr/sbin/named'
    condition: selection and not filter_legitimate
falsepositives:
    - Legitimate administrative rotation via adcli or realm
level: critical
tags:
    - attack.credential_access
    - attack.t1558
```

## 5. Savunma Kontrol Listesi (Hardening Checklist)

1. [ ] `/etc/krb5.keytab` dosya izni `0600`, sahibi `root:root` olarak ayarlandı mı?
2. [ ] `/etc/krb5.conf` içinde `default_ccache_name = KCM:` tanımlandı mı? (Diskte bilet kalmayacak).
3. [ ] Zayıf Kerberos şifrelemeleri (`RC4-HMAC`, `DES`) engellenip yalnızca AES-128 ve AES-256 izin verildi mi?
4. [ ] `auditd` üzerinde `/etc/krb5.keytab` erişim kuralları aktif edildi ve SIEM'e yönlendirildi mi?
5. [ ] SSSD üzerinde `ad_gpo_access_control = enforcing` aktif edilerek etki alanı GPO politikaları işletiliyor mu?
6. [ ] Oturumu kapatılan kullanıcıların biletleri anında siliniyor mu (`pam_krb5` / `sssd` logout session destruction)?
