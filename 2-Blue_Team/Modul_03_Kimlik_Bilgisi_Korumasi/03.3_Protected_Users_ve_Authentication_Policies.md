## 1. Kavramsal Temel — Neden Var?

[03.1](./03.1_Credential_Guard_ve_LSASS_Korumasi.md) kimlik sırlarını bellekte korudu; ama en değerli hesapları (Domain Admins) **hiç riskli yere düşmemeleri** için kısıtlamak daha güçlüdür. Bir Domain Admin bir istemciye RDP ile bağlanırsa, kimlik bilgisi o istemcinin LSASS'ine düşer — istemci ele geçmişse admin de düşer. **En iyi savunma, kritik kimliğin ele geçmiş makineye hiç uğramamasıdır.**

Üç mekanizma bunu sağlar:
- **Protected Users** grubu: üyelerine katı kısıtlamalar dayatır (NTLM yok, RC4 yok, delegation yok, credential caching yok).
- **Authentication Policies:** TGT ömrü ve kimlik doğrulama koşullarını hesap bazında sınırlar.
- **Authentication Policy Silos:** Belirli hesapların **yalnızca belirli makinelerden** oturum açmasını zorlar (Tier 0'ı kaleye kilitler).

> **İlke:** En değerli kimliği koruManın en iyi yolu, onu **riskli yerden uzak tutmaktır.** Protected Users "nasıl" doğrulanacağını, Silo "nereden" doğrulanacağını kilitler.

Bu, [Blue M05 Tier Model](../Modul_05_Yetki_ve_ACL_Sikilastirma/)'in kimlik doğrulama düzeyindeki zorlayıcısıdır ve [Sistem 10.3](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.3_Hardening_Temelleri.md)'ün ileri uygulamasıdır.

## 2. Teknik Derinlik

### 2.1 Protected Users neyi kapatır

```
   Protected Users üyesi bir hesap için OTOMATİK kısıtlamalar:
   ┌────────────────────────────────────────────────────────────┐
   │ ✗ NTLM kimlik doğrulama       → Pass-the-Hash imkânsız       │
   │ ✗ Kerberos RC4/DES            → sadece AES (Kerberoast zor)  │
   │ ✗ Delegation (constrained/    → çalınan TGT delege edilemez  │
   │   unconstrained)                                             │
   │ ✗ Credential caching          → çevrimdışı oturum yok        │
   │ ✗ Uzun TGT (4 saat sabit)     → çalınan bilet çabuk ölür     │
   └────────────────────────────────────────────────────────────┘
   → Bir DA istemcide ele geçse bile: NTLM hash yok, cache yok, RC4 yok.
```

### 2.2 Authentication Policy Silo mantığı

```
  ┌── SILO: "Tier0-Silo" ──┐        Kullanıcı DA01, sadece PAW01/DC'lerden
  │  Üye kullanıcı: DA01    │◄──┐    oturum açabilir. Başka makineden TGT
  │  Üye bilgisayar: PAW01, │   │    isteği → KDC REDDEDER (armored/FAST).
  │  DC01, DC02            │   │
  │  TGTLifetime: 240 dk   │   └── DA01, ele geçmiş bir istemciden gelirse:
  └────────────────────────┘        kimlik doğrulama BAŞARISIZ → 4820/4821
```

Silo, Kerberos **FAST/armoring** (RFC 6113) ile zorlanır: hesabın bileti yalnızca izinli makinelerden verilir. Böylece çalınan bir DA kimlik bilgisi, saldırganın makinesinden **kullanılamaz**.

### 2.3 Katmanlarla ilişki

Protected Users + Silo, **Tier 0** kimliklerine uygulanır: Domain Admins yalnızca PAW (Privileged Access Workstation) ve DC'lerden oturum açar. Bu, [Blue M05](../Modul_05_Yetki_ve_ACL_Sikilastirma/)'in "credential theft yayılmasını katmanla durdur" ilkesinin teknik zorlayıcısıdır.

## 3. Pratik Uygulama

### 3.1 Protected Users'a ekleme (dikkatli!)
```powershell
# Önce ETKİYİ anla: NTLM/RC4/delegation kapanır. Uyumluluğu test et!
Add-ADGroupMember -Identity "Protected Users" -Members "DA01","DA02"
# Kimin korunduğunu listele
Get-ADGroupMember "Protected Users"
```

### 3.2 Authentication Policy + Silo oluştur
```powershell
# 1) Policy: TGT ömrü + koşul
New-ADAuthenticationPolicy -Name "Tier0-Policy" `
  -UserTGTLifetimeMins 240 -ProtectedFromAccidentalDeletion $true
# 2) Silo: hangi makinelerden oturum açılabilir
New-ADAuthenticationPolicySilo -Name "Tier0-Silo" `
  -UserAuthenticationPolicy "Tier0-Policy" `
  -ComputerAuthenticationPolicy "Tier0-Policy" -Enforce
# 3) Hesap + makineleri silo'ya ata
Grant-ADAuthenticationPolicySiloAccess -Identity "Tier0-Silo" -Account "DA01"
Set-ADUser "DA01" -AuthenticationPolicySilo "Tier0-Silo"
```

### 3.3 Audit modda dene (Enforce'tan önce)
```powershell
# Enforce yerine Audit: reddetmeden logla (kırılmaları gör)
New-ADAuthenticationPolicySilo -Name "Tier0-Silo" -AuditOnly   # 4820/4821 üretir
```

## 4. Tespit Değeri — Silo İhlali ve Politika Değişimi

Silo'ya aykırı bir oturum denemesi, **çalınan kimliğin yanlış makineden kullanımının** kesin izidir:

```yaml
# Sigma — Authentication Policy Silo ihlali (çalınan kimlik yanlış makinede)
title: Authentication Silo Ihlali - Kisitli Hesap Yanlis Makinede
logsource: { product: windows, service: security }
detection:
  sel: { EventID: [4820, 4821] }   # 4820=TGT reddedildi(claim), 4821=TGS reddedildi
  condition: sel
level: high
tags: [attack.lateral_movement, attack.credential_access, attack.t1078]
```
```powershell
# Get-WinEvent — Silo tarafından reddedilen kimlik doğrulama (son 24 saat)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4820,4821;
  StartTime=(Get-Date).AddDays(-1)} |
  Select TimeCreated, Id, @{N='Detay';E={$_.Message.Split("`n")[0]}}
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| 4820/4821 | Security (DC) | Silo dışı makineden kimlik denemesi | T1078 |
| Protected Users üyelik değişimi | 4728/4729 | Koruma kaldırma (yetki abuse) | T1098 |
| Auth Policy/Silo değişimi | 5136 | Kısıtlama gevşetme | T1484 |
| Kısıtlı hesap NTLM denemesi (4776) | Security | Protected Users NTLM kullanmamalı → anomali | T1550.002 |

## 5. Doğrulama / Lab

```powershell
# 1) Protected Users etkisini kanıtla (izole lab):
#    Korunan DA'nın NTLM ile bir kaynağa bağlanması BAŞARISIZ olmalı
# 2) Silo etkisini kanıtla: DA01 ile silo-dışı bir istemciden oturum aç
#    → BAŞARISIZ + 4820 üretilmeli, §4 kuralı alarm vermeli
# 3) PtH sınırı: korunan DA'nın hash'ini çalıp kullanmayı dene → NTLM kapalı = işe yaramaz
Get-ADUser DA01 -Properties AuthenticationPolicySilo, memberOf   # atamaları doğrula
```
> **Kanıt:** "DA01 kendi PAW'ından çalışır, başka istemciden çalışmaz." Bu ikili test, silonun gerçekten kilitlediğini gösterir.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Protected Users'a servis/uyumsuz hesap eklemek:** NTLM/RC4/delegation kapanır; bunlara bağımlı eski uygulamalar/servis hesapları kırılır. Yalnızca interaktif yönetici hesaplarına uygula, önce Audit'le test et.
- 🔴 **Silo'yu Audit'siz Enforce etmek:** Kilitlenme (lockout) riski; önce `-AuditOnly` ile 4820/4821'i gözle, kırılmaları düzelt, sonra Enforce.
- ⚠️ **Bilgisayar hesabını silo'ya eklemeyi unutmak:** Silo hem kullanıcıyı hem izinli makineleri kapsamalı; makine eksikse meşru oturum reddedilir.
- ⚠️ **Tier 0'ı korurken PAW'ı ihmal etmek:** Silo DA'yı PAW'a kilitler ama PAW'ın kendisi sertleştirilmemişse zayıf halka odur.
- 🔍 **İzleme ipucu:** Protected Users'tan **üye çıkarma** (4729) veya silo **devre dışı bırakma**, saldırganın koruma kaldırma hamlesidir — kritik alarm.
