## 1. Kavramsal Temel — Neden Var?

Windows'ta oturum açan her kullanıcının kimlik bilgisi (NTLM hash, Kerberos bileti, bazen düz parola) **LSASS (Local Security Authority Subsystem Service)** sürecinin belleğinde tutulur. Saldırgan bir makinede yönetici olursa, `mimikatz sekurlsa::logonpasswords` ile LSASS belleğini okuyup **oradaki tüm oturumların** kimlik bilgilerini çalar — Pass-the-Hash ve Pass-the-Ticket'ın yakıtı budur. Tek bir ele geçmiş makine, üzerinde oturum açmış bir Domain Admin varsa, tüm domain'in düşmesi demektir.

**Credential Guard**, bu saldırıyı **mimari olarak** kırar: sanallaştırma tabanlı güvenlik (VBS/Hyper-V) ile kimlik sırlarını LSASS'ten alıp, işletim sisteminin bile erişemediği izole bir "trustlet"e (**LSAISO / Isolated LSA**) taşır. Yönetici bile olsanız, o belleğe ulaşamazsınız — hipervizör engeller.

> **Analoji:** LSASS, tüm anahtarların durduğu bir çekmece. Mimikatz çekmeceyi açıp anahtarları alır. Credential Guard, anahtarları **duvarın arkasındaki, kapısı olmayan bir kasaya** koyar; sadece kimlik doğrulama işlemi "kasadan içeriden" yapılır, anahtar dışarı hiç çıkmaz.

Bu, [Sistem 10.3 Hardening](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.3_Hardening_Temelleri.md)'te "Protected Users/kimlik koruma" denilen katmanın en güçlü teknik uygulamasıdır.

## 2. Teknik Derinlik

### 2.1 VBS/Credential Guard mimarisi

```
  ┌──────────────── NORMAL DÜNYA (VTL0) ────────────────┐   ┌── İZOLE (VTL1) ──┐
  │  Kullanıcı / Kernel                                  │   │  Hipervizör-korum.│
  │  ┌───────────┐   mimikatz okur ✗ (artık boş)         │   │  ┌─────────────┐ │
  │  │ LSASS.exe │◄──── proxy (RPC) ──────────────────────┼──►│  │ LSAISO      │ │
  │  │ (kabuk)   │      "hash'i sen kullan, bana verme"   │   │  │ (sırlar     │ │
  │  └───────────┘                                        │   │  │  BURADA)    │ │
  │        ▲ Sysmon EID 10 (LSASS access) izler           │   │  └─────────────┘ │
  └────────┼─────────────────────────────────────────────┘   └──────────────────┘
           │ Saldırgan hash bulamaz; sadece "kör" LSASS kabuğu
     VBS = Hyper-V + Secure Boot + IOMMU/DMA koruması gerektirir
```

### 2.2 Neyi korur, neyi korumaz

| Korur ✅ | Korumaz ❌ |
|----------|-----------|
| NTLM hash bellekten çalınması | **Kerberoasting** (protokol düzeyi — [02.3](../Modul_02_SIEM_ve_Tespit_Muhendisligi/02.3_Kerberoasting_AS_REP_Tespiti.md)) |
| Kerberos TGT/anahtar sızması | Keylogger / düz parola girişi |
| Pass-the-Hash için hash hasadı | Diskteki DPAPI/SAM ([03.4](./03.4_DPAPI_ve_Onbelleklenmis_Kimlik.md)) |
| Domain kimlik sırları | RDP ile canlı kimlik bilgisi (unless Remote Cred Guard) |

Kritik: Credential Guard **tek başına yeterli değildir** — Kerberoasting'i durdurmaz, gümüş/altın bilet için krbtgt'yi korumaz. Katmanlı savunmanın bir parçasıdır.

### 2.3 Donanım gereksinimleri

VBS için: **UEFI Secure Boot**, **TPM 2.0** (anahtar mühürleme), **IOMMU/DMA koruması** (DMA saldırılarına karşı), CPU sanallaştırma (VT-x/AMD-V + SLAT). Bunlar yoksa Credential Guard etkinleşmez veya zayıf modda çalışır.

## 3. Pratik Uygulama

### 3.1 GPO ile etkinleştirme (Windows 11 22H2+ varsayılan açık)
```text
GPO: Computer Config → Administrative Templates → System → Device Guard →
     "Turn On Virtualization Based Security" = Enabled
       Platform Security Level: Secure Boot and DMA Protection
       Credential Guard Configuration: Enabled with UEFI lock
```

### 3.2 PowerShell ile durum doğrulama (ZORUNLU)
```powershell
# Credential Guard gerçekten ÇALIŞIYOR mu? (yapılandırıldı ≠ çalışıyor)
$dg = Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard
$dg.SecurityServicesRunning   # 1 = Credential Guard çalışıyor
$dg.VirtualizationBasedSecurityStatus  # 2 = VBS aktif
# LSAISO süreci var mı? (çalışıyorsa görünür)
Get-Process -Name LsaIso -ErrorAction SilentlyContinue
```

### 3.3 Ek LSASS koruması: RunAsPPL (PPL)
```powershell
# LSASS'i Protected Process Light yap (Credential Guard'a ek katman)
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" `
  -Name RunAsPPL -Value 1 -PropertyType DWORD -Force
# → mimikatz'in LSASS'e erişimi için sürücü (mimidrv) gerektirir; iz artar
```

## 4. Tespit Değeri — Koruma Atlatma Girişimi Alarmdır

Credential Guard'ı atlatmak veya PPL'i devre dışı bırakmak, saldırganın **gürültülü** bir hamlesidir ve tespit edilebilir:

```yaml
# Sigma — LSASS'e şüpheli erişim (Credential Guard/PPL atlatma denemesi)
title: LSASS Bellek Erisimi - Kimlik Hirsizligi
logsource: { product: windows, category: process_access }
detection:
  sel:
    TargetImage|endswith: '\lsass.exe'
    GrantedAccess: ['0x1010','0x1410','0x143a','0x1438']
  filter:
    SourceImage|endswith: ['\MsMpEng.exe','\wininit.exe']   # EDR/sistem
  condition: sel and not filter
level: high
tags: [attack.credential_access, attack.t1003.001]
```
```powershell
# Get-WinEvent — RunAsPPL/VBS registry manipülasyonu (Sysmon EID 13)
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' -FilterXPath `
 "*[System[EventID=13]]" | Where-Object { $_.Message -match 'RunAsPPL|DeviceGuard|LsaCfgFlags' }
```

| Sinyal | Kaynak | Anlamı | MITRE |
|--------|--------|--------|-------|
| LSASS access 0x1010/0x1410 | Sysmon EID 10 | Bellek dump girişimi | T1003.001 |
| `RunAsPPL` silinme/0 | Sysmon EID 13 | PPL kapatma (atlatma hazırlığı) | T1562.001 |
| `mimidrv` sürücü yüklenmesi | Sysmon EID 6 | PPL bypass için kernel sürücü | T1547.006 |
| VBS/DeviceGuard config değişimi | 4657/Sysmon 13 | Credential Guard sabotajı | T1562.001 |

```powershell

Invoke-AtomicTest T1003.001 -TestNumbers 1     # comsvcs.dll MiniDump
Invoke-AtomicTest T1003.001 -TestNumbers 2     # → Sysmon EID 10 üretmeli
Invoke-AtomicTest T1003.001 -Cleanup
```

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **"Yapılandırdım" ≠ "çalışıyor":** VBS donanım gereksinimi (Secure Boot/TPM/IOMMU) karşılanmazsa etkinleşmez; `Win32_DeviceGuard.SecurityServicesRunning=1` ile **doğrula**.
- 🔴 **Credential Guard'ı tek savunma sanmak:** Kerberoasting'i, disk kimlik bilgilerini, keylogger'ı durdurmaz; katmanla (Protected Users [03.3](./03.3_Protected_Users_ve_Authentication_Policies.md), LAPS [03.2](./03.2_LAPS_ile_Yerel_Admin_Parola_Yonetimi.md)).
- ⚠️ **UEFI lock'suz dağıtmak:** "Enabled without lock" bir saldırganın GPO ile kapatmasına açıktır; "with UEFI lock" fiziksel/firmware müdahalesi gerektirir.
- ⚠️ **Eski uygulama uyumu:** Credential Guard bazı eski VPN/kimlik doğrulama sürücülerini bozar; pilotla, uyumluluğu test et.
- 🔍 **İzleme ipucu:** `RunAsPPL` veya VBS registry değerinin **kapatılması** neredeyse her zaman kötü niyetlidir — yüksek öncelikli alarm yap.
