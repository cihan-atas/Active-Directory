## 1. Kavramsal Temel — Neden Var?

Kimlik bilgisi yalnızca LSASS belleğinde ([03.1](./03.1_Credential_Guard_ve_LSASS_Korumasi.md)) değil, **diskte de** durur: tarayıcı parolaları, kayıtlı RDP/kimlik bilgileri, WiFi anahtarları, sertifika özel anahtarları, uygulama sırları. Bunları **DPAPI (Data Protection API)** şifreler — Windows'un "veriyi kullanıcının parolasına bağlı bir anahtarla şifrele" servisi. Ayrıca DC'ye ulaşamayan makineler için son 10 domain oturumu **önbelleğe (cached credentials)** alınır ki laptop offline'ken de giriş yapılabilsin.

Sorun: Bunların ikisi de **saldırgan için hazine**dir. DPAPI ile korunan sırlar, kullanıcının masterkey'i ele geçirilirse (veya domain-yedek anahtarıyla) çözülür; cached credentials (`MSCACHEv2 / DCC2`) çevrimdışı kırılabilir. **Credential Guard bunları korumaz** — bu yüzden ayrı bir savunma katmanı gerekir.

> **İlke:** Kimlik bilgisi bellekte, diskte ve önbellekte yaşar. Belleği koruyup diski/önbelleği unutmak, kapıyı kilitleyip pencereyi açık bırakmaktır.

Bu dosya, kimlik koruma modülünü **disk ve önbellek** boyutuyla tamamlar; [Sistem 03.2 Hesap Yönetimi](../../1-Sistem_Yoneticisi/Modul_03_Nesne_ve_Kimlik_Yonetimi/03.2_Hesap_Yonetimi.md)'nin güvenlik karşılığıdır.

## 2. Teknik Derinlik

### 2.1 DPAPI anahtar hiyerarşisi

```
   Kullanıcı parolası / SHA1
          │  türetir
          ▼
   Prekey ──► MASTERKEY (%APPDATA%\Microsoft\Protect\<SID>\<GUID>)
                 │ şifreler
                 ▼
   Uygulama sırları: Chrome "Login Data", Credential Manager,
   RDP .rdp, WiFi, sertifika özel anahtarları
          ▲
          └── DOMAIN YEDEK ANAHTARI (DC'de): kullanıcı parolasını unutsa da
              domain, masterkey'i kurtarabilir → SALDIRGAN da bu anahtarı
              ele geçirirse TÜM kullanıcıların DPAPI sırlarını açar! (T1555)
```

### 2.2 Cached domain credentials (MSCACHEv2 / DCC2)

DC'ye ulaşılamadığında son oturumlar `HKLM\SECURITY\Cache` altında **MSCACHEv2** (DCC2) formatında saklanır. Bu **hash Pass-the-Hash'te kullanılamaz** (farklı algoritma) — ama `hashcat -m 2100` ile **çevrimdışı kırılabilir**. Saldırgan SYSTEM olursa bu hash'leri çeker ve zayıf parolaları kırar.

### 2.3 Domain DPAPI backup key riski (kritik)

DC'deki DPAPI **domain backup key** (`BackupKey`), tüm kullanıcıların masterkey'lerini çözebilir. Bir saldırgan bunu (örn. `mimikatz lsadump::backupkeys` ile DA yetkisiyle) ele geçirirse, offline olarak **her kullanıcının** kayıtlı sırlarını açabilir. Bu, Golden Ticket seviyesinde bir "master anahtardır" → [Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/).

## 3. Pratik Uygulama

### 3.1 Cached credential sayısını sınırla (GPO)
```text
GPO: Computer Config → Windows Settings → Security Settings → Local Policies →
     Security Options →
   "Interactive logon: Number of previous logons to cache" = 0 (sunucu/DC)
                                                            = 1-2 (laptop, offline gerekiyorsa)
→ 0 = hiç cache yok (ele geçmiş makinede kırılacak DCC2 hash'i kalmaz)
```

### 3.2 DPAPI ve cache artefaktlarını denetle
```powershell
# Cache ayarını doğrula
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" `
  -Name CachedLogonsCount
# DPAPI masterkey erişimi izlenmeli (Sysmon EID 11 - Protect klasörü)
# Domain backup key'e erişim → sadece Tier 0, denetlenmeli (4662)
```

### 3.3 Tier 0 ve servis hesaplarında cache'i kapat
```powershell
# Kritik sunucularda cache=0 uygula + Protected Users ile birleştir (03.3)
# Servis hesaplarını gMSA'ya taşı → disk/cache'te parola tutulmaz
Get-ADServiceAccount -Filter * | Select Name, Enabled   # gMSA envanteri
```

## 4. Tespit Değeri — DPAPI/Cache Hasadı İzleri

```yaml
# Sigma — DPAPI masterkey / domain backup key erişimi
title: DPAPI Masterkey veya Domain Backup Key Erisimi
logsource: { product: windows, category: file_event }
detection:
  masterkey:
    TargetFilename|contains: '\Microsoft\Protect\'      # kullanıcı masterkey
  backupkey:
    EventID: 4662
    Properties|contains: 'BCKUPKEY'                     # domain DPAPI backup key
  condition: masterkey or backupkey
level: high
tags: [attack.credential_access, attack.t1555.004, attack.t1003.005]
```
```powershell
# Get-WinEvent — SECURITY registry / cache'e erişim, mimikatz lsadump izleri
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' -FilterXPath `
 "*[System[EventID=10]]" | Where-Object { $_.Message -match 'lsass' -and
   $_.Message -match 'GrantedAccess:\s+0x1010' }   # DCC2/secret çekme sıklıkla LSASS üzerinden
```

| Sinyal | Kaynak | Anlamı | MITRE |
|--------|--------|--------|-------|
| `\Microsoft\Protect\` erişimi | Sysmon EID 11 | DPAPI masterkey hasadı | T1555.004 |
| `BCKUPKEY` okuma (4662) | Security (DC) | Domain DPAPI backup key çalınması | T1003.005 |
| `HKLM\SECURITY\Cache` erişimi | Sysmon/registry | Cached credential (DCC2) çekme | T1003.005 |
| Toplu tarayıcı "Login Data" okuma | Sysmon EID 11 | Tarayıcı parola hasadı | T1555.003 |

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Belleği koruyup diski/cache'i unutmak:** Credential Guard DPAPI ve DCC2'yi korumaz; cache=0 + gMSA + Protected Users ile katmanla.
- 🔴 **Domain DPAPI backup key'i korumasız bırakmak:** Tek anahtar tüm kullanıcı sırlarını açar; erişimi Tier 0'a kilitle ve 4662 ile denetle.
- ⚠️ **Cache'i her yerde 0 yapmak:** Gerçekten offline çalışan laptop'lar giriş yapamaz; sunucu/DC'de 0, mobil cihazda 1-2 dengele.
- ⚠️ **Tarayıcı/uygulama sırlarını görmezden gelmek:** Chrome "Login Data" DPAPI ile korunur ama kullanıcı bağlamında çözülür; EDR ile toplu okuma izlenmeli.
- 🔍 **İzleme ipucu:** `BCKUPKEY` (domain backup key) okuma olayı meşru senaryoda neredeyse hiç görülmez — görülürse yüksek olasılıkla domain hakimiyeti girişimidir → [Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/).
