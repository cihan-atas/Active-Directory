## 1. Kavramsal Temel — Neden Var?

Şablonlar temiz olsa bile ([07.1](./07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md)), **CA'nın (Certification Authority) kendisi** yanlış yapılandırılmışsa tüm PKI çöker. En kötü şöhretli örnek **ESC6**: CA'da **`EDITF_ATTRIBUTESUBJECTALTNAME2`** bayrağı açıksa, talep eden **herhangi bir şablonda** sertifika talebine keyfî bir SAN (Subject Alternative Name) ekleyebilir. Yani şablon "build from AD" olsa bile, saldırgan talebe `Administrator@corp.local` SAN'ı ekler ve DA sertifikası alır. Bu, tek bir CA ayarının **tüm şablonları ESC1'e çevirmesidir**.

Ek olarak **ESC7** (CA üzerinde ManageCA/ManageCertificates izni), **ESC5** (CA/PKI nesnelerinde zayıf ACL) ve CA'nın genel sertleştirmesi (audit, rol ayrımı, offline root) bu dosyanın kapsamıdır. CA, PKI'nın **kök güven noktasıdır** — ele geçerse iptal bile işe yaramaz.

> **İlke:** Bir tek CA bayrağı (`EDITF_ATTRIBUTESUBJECTALTNAME2`) tüm domain'i düşürebilir. CA'yı domain'in en kritik Tier 0 varlığı gibi sertleştir: bayrakları denetle, yönetim iznini daralt, her şeyi logla.

Bu, [Sistem 07.1 PKI Mimarisi](../../1-Sistem_Yoneticisi/Modul_07_PKI_ve_Sertifika_Servisleri/07.1_PKI_Mimarisi_ve_CA_Hiyerarsisi.md)'nin (offline root, issuing CA) güvenlik sertleştirmesidir.

## 2. Teknik Derinlik

### 2.1 ESC6: tek bayrak, tüm sistem

```
   CA'da EDITF_ATTRIBUTESUBJECTALTNAME2 AÇIK ise:
   ┌────────────────────────────────────────────────────────────────┐
   │ Talep eden (Domain Users) → herhangi bir şablonda sertifika iste │
   │   + talebe ekle: "san:upn=Administrator@corp.local"              │
   │                          │                                       │
   │                          ▼                                       │
   │ CA, şablon "build from AD" DESE BİLE, talep-tarafı SAN'ı KABUL   │
   │ eder → Administrator sertifikası verilir → PKINIT ile DA         │
   └────────────────────────────────────────────────────────────────┘
   Tek CA ayarı = tüm şablonlar ESC1 gibi davranır.
```

### 2.2 ESC7 ve CA yönetim rolleri

CA iki güçlü rol taşır: **ManageCA** (CA yapılandırması — bayrak değiştirme, şablon yayınlama) ve **Manage Certificates** (talep onaylama/iptal). ESC7, bu izinlere sahip düşük yetkili birinin bir şablonu açması veya beklemedeki bir talebi onaylamasıyla sömürülür. Bu izinler **yalnızca Tier 0 PKI yöneticilerinde** olmalıdır.

### 2.3 NTAuthCertificates ve güven zinciri

`NTAuthCertificates` nesnesi, "hangi CA'ların domain kimlik doğrulaması için güvenildiğini" tutar. Buraya bir saldırgan **kendi CA'sını** eklerse (ESC5/yazma hakkıyla), kendi ürettiği her sertifikayla kimlik doğrular. Bu nesnenin DACL'i kritik denetim noktasıdır.

## 3. Pratik Uygulama

### 3.1 ESC6 bayrağını denetle ve kapat
```powershell
# CA'da EDITF_ATTRIBUTESUBJECTALTNAME2 açık mı? (ESC6)
certutil -getreg policy\EditFlags
# Çıktıda EDITF_ATTRIBUTESUBJECTALTNAME2 GÖRÜNÜYORSA → kapat:
certutil -setreg policy\EditFlags -EDITF_ATTRIBUTESUBJECTALTNAME2
Restart-Service certsvc    # değişiklik için CA servisini yeniden başlat
```

### 3.2 CA yönetim izinlerini denetle (ESC7)
```powershell
# ManageCA / ManageCertificates izni olanlar (yalnızca Tier 0 PKI olmalı)
certutil -getreg CA\Security      # CA güvenlik tanımlayıcısını dök
# Certipy ile de: certipy find → CA Permissions bölümü (ManageCA/ManageCertificates)
```

### 3.3 NTAuthCertificates ve CA nesnesi DACL denetimi (ESC5)
```powershell
# NTAuthCertificates üzerinde güvenilmeyen yazma hakkı var mı?
$cfg = (Get-ADRootDSE).configurationNamingContext
$ntauth = "CN=NTAuthCertificates,CN=Public Key Services,CN=Services,$cfg"
(Get-Acl "AD:\$ntauth").Access |
  Where-Object { $_.ActiveDirectoryRights -match 'Write|GenericAll' -and
                 $_.IdentityReference -notmatch 'Domain Admins|Enterprise Admins|SYSTEM' }
```

### 3.4 CA audit'i tam aç
```powershell
# CA'da tüm olay denetimini etkinleştir (talep/verme/iptal/yönetim)
certutil -setreg CA\AuditFilter 127     # tüm audit kategorileri
Restart-Service certsvc
# + GPO: "Audit Certification Services" (DS Access) → 4886/4887/4888/4890...
```

## 4. Tespit Değeri — CA Yapılandırma Değişimi = Kritik

```yaml
# Sigma — CA policy/bayrak değişimi veya ManageCA kullanımı (ESC6/ESC7)
title: AD CS CA Yapilandirma Degisimi (ESC6/ESC7 Belirtisi)
logsource: { product: windows, service: security }
detection:
  ca_config:
    EventID: 4890        # certificate services policy settings changed
  ca_mgmt:
    EventID: [4882, 4885]  # CA security değişti / audit filter değişti
  condition: ca_config or ca_mgmt
level: critical
tags: [attack.privilege_escalation, attack.persistence, attack.t1649]
```
```powershell
# Get-WinEvent — CA policy/güvenlik değişiklikleri
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4890,4882,4885} |
  Select TimeCreated, Id, @{N='Detay';E={$_.Message.Split("`n")[0]}}
```

| Sinyal | Event (CA) | Anlamı | MITRE |
|--------|-----------|--------|-------|
| CA policy ayarı değişti | 4890 | EDITF/EditFlags manipülasyonu (ESC6) | T1649 |
| CA security değişti | 4882 | ManageCA izni ekleme (ESC7) | T1649 |
| NTAuthCert değişimi | 5136 | Sahte CA güven ekleme (ESC5) | T1649 |
| Audit filter değişti | 4885 | Denetimi kapatma (anti-forensics) | T1562.002 |

## 5. Doğrulama / Lab

```bash
# 1) Envanter: certipy find → CA'da EDITF_ATTRIBUTESUBJECTALTNAME2 = FALSE olmalı
certipy find -u blueteam@corp.local -p '***' -dc-ip 10.0.0.1 -stdout | grep -i "SAN\|EditFlags\|Permissions"
# 2) ESC6 testi (izole lab): bayrağı aç → "build from AD" şablonda bile SAN'lı
#    Administrator sertifikası alınabildiğini göster → §4 4890 alarmı → bayrağı kapat
# 3) ESC7 testi: ManageCA izni ile bir şablon yayınla → 4882 alarmı çıkmalı
```
> **Kanıt:** `EDITF_ATTRIBUTESUBJECTALTNAME2` kapalı, ManageCA/ManageCertificates yalnızca Tier 0'da, NTAuthCert DACL temiz. Bayrak açıkken tek talep DA sertifikası üretebiliyorsa kapatma zorunludur.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **`EDITF_ATTRIBUTESUBJECTALTNAME2` açık bırakmak:** Tek başına tüm şablonları ESC1 yapar; derhal kapat ve CA servisini yeniden başlat.
- 🔴 **CA'yı Tier 0 saymamak:** CA ele geçerse iptal işe yaramaz; CA'yı DC ile aynı katmanda (Tier 0) koru, ayrı yönetici.
- ⚠️ **ManageCA/ManageCertificates'i geniş vermek:** ESC7 bu izinlerle sömürülür; yalnızca Tier 0 PKI yöneticileri.
- ⚠️ **NTAuthCertificates DACL'ini denetlememek:** Buraya sahte CA eklenmesi tüm kimlik doğrulamayı sahteleştirir; yazma hakkını Tier 0'a kilitle.
- 🔍 **İzleme ipucu:** CA policy değişimi (**4890**) veya audit filter kapatma (**4885**) meşru senaryoda çok nadirdir — ikisi de kritik alarm ve olası ESC6/anti-forensics işareti.
