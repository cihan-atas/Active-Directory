## 1. Kavramsal Temel — Neden Var?

Önceki üç dosya olayı **üretti** ([01.2](./01.2_Advanced_Audit_Policy.md)/[01.3](./01.3_Sysmon_ile_Derin_Telemetri.md)) ve **merkeze taşıdı** ([01.1](./01.1_Windows_Event_Forwarding_WEF.md)). Ama ham olaylar farklı formatlarda, farklı alan adlarıyla gelir: Security log `TargetUserName` der, Sysmon `User` der, bir firewall `src_user` der. Tespit mühendisi ([Blue M02](../Modul_02_SIEM_ve_Tespit_Muhendisligi/)) bunların **hepsini tek bir sözlükle** sorgulayabilmeli. İşte bu dosya, ham telemetriyi **kullanılabilir, aranabilir, kalıcı** veriye çeviren boru hattını anlatır.

Üç ayrı mühendislik problemi:
1. **Toplama (collection):** Tüm kaynaklardan SIEM'e güvenilir akış.
2. **Saklama (retention):** Ne kadar süre, ne maliyetle, hangi uyumlulukla (GDPR/PCI/SOC 2 → [Sistem 10.4](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.4_Denetim_ve_Uyumluluk.md)).
3. **Normalizasyon (schema):** Farklı log'ları ortak alan modeline (ECS/ASIM/CIM) eşlemek.

> **İlke:** Toplanmayan log yoktur; normalleştirilmeyen log **aranamaz**; saklanmayan log **soruşturulamaz**. Üçü birlikte tespitin ve DFIR'in ([Blue M10](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/)) zeminidir.

## 2. Teknik Derinlik

### 2.1 Uçtan uca boru hattı

```
  KAYNAK            TOPLAMA           TAŞIMA/İŞLEME        DEPOLAMA        TÜKETİM
  ──────            ───────           ────────────        ────────        ───────
 Security log ─┐                    ┌─ parse/normalize   ┌─ hot (SSD)    ┌ Blue M02
 Sysmon       ─┤  WEF (01.1) ─► WEC │  (ECS/ASIM/CIM)    │  30-90 gün    │  tespit
 PowerShell   ─┤  → Winlogbeat/     │  enrich (GeoIP,    │              ├ Blue M09
 Firewall/DNS ─┤    NXLog/Splunk UF │   asset, threat    │─ warm/cold   │  avcılık
 Linux/syslog ─┘    forwarder       │   intel)           │  1-7 yıl     ├ Blue M10
                                    └─ index             └─ WORM/immutable │  DFIR
                        (RFC 5424 syslog / OTel)
```

### 2.2 Normalizasyon: neden ortak şema?

Aynı "başarısız oturum" farklı kaynaklarda farklı görünür. Ortak şema (schema) bunu birleştirir:

| Kavram | Windows Security | Sysmon | ECS (Elastic) | ASIM (Sentinel) |
|--------|------------------|--------|---------------|-----------------|
| Kullanıcı | `TargetUserName` | `User` | `user.name` | `TargetUsername` |
| Kaynak IP | `IpAddress` | `SourceIp` | `source.ip` | `SrcIpAddr` |
| Süreç | `NewProcessName` | `Image` | `process.executable` | `Process` |
| Olay türü | `EventID` | `EventID` | `event.code` | `EventType` |

Normalizasyon sayesinde **tek bir Sigma kuralı** (`user.name` üzerinden) hem Windows hem Sysmon hem firewall log'unda çalışır. Aksi halde her kaynak için kural yeniden yazılır — sürdürülemez.

### 2.3 Saklama katmanları ve maliyet

- **Hot (sıcak):** Son 30-90 gün, hızlı arama (SSD/indeksli) — aktif tespit ve avcılık.
- **Warm/Cold:** Aylar-yıllar, ucuz depolama, yavaş arama — soruşturma/uyumluluk.
- **Immutable/WORM:** Değiştirilemez saklama — saldırgan (veya insider) silemez; adli kanıt bütünlüğü.

Uyumluluk taban çizgileri: PCI-DSS **1 yıl** (90 gün hot), birçok çerçeve **≥180 gün**. Kısa saklama = geç fark edilen ihlalde (ortalama tespit süresi haftalar) **kanıt yok** demektir.

## 3. Pratik Uygulama

### 3.1 ForwardedEvents'i SIEM'e ilet (Winlogbeat örneği)
```yaml
# winlogbeat.yml — WEC üzerindeki ForwardedEvents'i Elastic'e gönder
winlogbeat.event_logs:
  - name: ForwardedEvents
    processors:
      - script: { lang: javascript, id: security, file: ./module/security/config/winlogbeat.js }
  - name: Microsoft-Windows-Sysmon/Operational
output.elasticsearch:
  hosts: ["https://siem.corp.local:9200"]
  pipeline: "sysmon-ecs-normalize"     # ingest pipeline ile ECS'e eşle
```

### 3.2 ForwardedEvents log boyutu ve arşiv (kayıp önleme)
```powershell
# Collector'da ForwardedEvents logunu büyüt + arşivle (döngüsel silme riskini azalt)
wevtutil sl ForwardedEvents /ms:2147483648   # 2 GB
wevtutil sl ForwardedEvents /rt:false /ab:true  # arşivle, üzerine yazma
# Log doluluk/sağlık kontrolü
Get-WinEvent -ListLog ForwardedEvents | Select LogName, FileSize, RecordCount, IsEnabled
```

### 3.3 Saklama/immutability (bütünlük)
```text
- SIEM index lifecycle (ILM/retention) politikası: hot 60g → cold 1y → delete 7y
- Immutable bucket (S3 Object Lock / Azure immutable blob): 1102/104 gibi kritik
  olayların kopyası WORM alanında → saldırgan/insider silemez.
```

## 4. Tespit Değeri — Pipeline Sağlığı ve Kaynak Sessizliği

Toplama katmanının **kör noktası** kendi kesintisidir. En kritik meta-tespit: bir kaynağın **beklenen log hacminin düşmesi**.

```kql
// KQL — 24 saatte log göndermeyi kesen host (telemetri kaybı = olası saldırı/körleştirme)
let baseline = SecurityEvent | where TimeGenerated between (ago(14d)..ago(1d))
  | summarize by Computer | distinct Computer;
let recent = SecurityEvent | where TimeGenerated > ago(1d)
  | summarize by Computer | distinct Computer;
baseline | where Computer !in (recent)   // dünden beri susan hostlar
```
```powershell
# Get-WinEvent — collector'a hiç veri gelmeyen abonelik kaynakları
(wecutil gr SEC-Critical) # Active/Inactive kaynak sayısını incele
```

| Sinyal | Kaynak | Anlamı |
|--------|--------|--------|
| Log hacmi ani düşüş | SIEM pipeline | Kaynak susturuldu / WEF koptu → körleştirme |
| **1102 / 104** WORM'da yok | Immutable store | Kritik olay arşive ulaşmamış → boru hattı hatası |
| Winlogbeat/UF offline | Forwarder | Toplama ajanı durdu → görünürlük kaybı |
| Zaman kayması (clock skew) | Tüm kaynaklar | Korelasyon bozulur → [Sistem 02.3 PDC/NTP](../../1-Sistem_Yoneticisi/Modul_02_Fiziksel_Altyapi_ve_Replikasyon/02.3_FSMO_Rolleri.md) |

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Saklama süresini kısa tutmak:** İhlaller ortalama haftalar-aylar sonra fark edilir; 30 gün log = kanıt yok. Uyumluluk tabanını ([Sistem 10.4](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.4_Denetim_ve_Uyumluluk.md)) karşıla, kritik olaylar için immutable kopya tut.
- 🔴 **Pipeline sağlığını izlememek:** En tehlikeli körlük, "log geliyor sanmak". Kaynak sessizliğini (§4) bir tespit kuralı yap.
- ⚠️ **Normalizasyonu atlamak:** Ham, eşlenmemiş log'da tek Sigma kuralı çalışmaz; her kaynak için ayrı kural = sürdürülemez teknik borç.
- ⚠️ **Zaman senkronizasyonunu ihmal etmek:** Kaynaklar arası clock skew, olay korelasyonunu (attack timeline) bozar; tüm host'lar PDC-Emulator hiyerarşisine bağlı NTP kullanmalı.
- 🔍 **İzleme ipucu:** Immutable/WORM alanına yazılan **1102** kopyası, yereldeki log silinse bile "burada bir temizlik oldu" kanıtını korur — anti-anti-forensics.
