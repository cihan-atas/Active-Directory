## 1. Kavramsal Temel — Neden Var?

[01.1](./01.1_Windows_Event_Forwarding_WEF.md) olayları **taşır**; ama önce olayın **üretilmesi** gerekir. Windows varsayılan olarak güvenlik açısından kritik olayların çoğunu **üretmez** — bir domain'i default kurarsan Kerberoasting'i, DCSync'i, ayrıcalıklı grup değişikliğini gösteren olaylar hiç oluşmaz. Denetim politikası, "hangi eylemler Security log'una yazılacak" kararıdır.

İki nesil denetim vardır:

- **Basic Audit Policy** (eski, 9 kategori) — kaba taneli; "Audit account logon events" dersen **her şey** gelir, gürültü boğar.
- **Advanced Audit Policy** (Vista+, 60+ alt kategori) — ince taneli; "sadece Kerberos servis bileti işlemlerini denetle" diyebilirsin.

**Altın kural:** Az ve değerli olay üret. Her şeyi denetlemek = hiçbir şeyi görmemek (§7). Bu dosya, [Sistem 10.4](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.4_Denetim_ve_Uyumluluk.md)'teki Event ID kataloğunun **hangi audit alt kategorisiyle açıldığını** gösterir; ürettiği olaylar [Blue M02](../Modul_02_SIEM_ve_Tespit_Muhendisligi/)'de tespit kurallarına dönüşür.

## 2. Teknik Derinlik

### 2.1 Basic ↔ Advanced çakışması (kritik tuzak)

```
   ┌──────────────────────────────────────────────────────────────┐
   │  Aynı GPO'da HEM Basic HEM Advanced tanımlıysa → ÇAKIŞMA       │
   │  Basic ayarı Advanced'i EZER ve alt kategoriler sıfırlanır!    │
   │                                                                │
   │  ÇÖZÜM: "Audit: Force audit policy subcategory settings        │
   │          to override audit policy category settings" = Enabled │
   │  (Security Options altında) → Advanced kazanır                 │
   └──────────────────────────────────────────────────────────────┘
```

Bu, gerçek ortamlarda en sık "logum neden gelmiyor" nedenidir: birileri eski Basic politikayı bir GPO'da bırakmıştır, Advanced ayarlar sessizce iptal olur.

### 2.2 Denetim mimarisi: kategori → alt kategori → olay

```
  Kategori (10)          Alt kategori (60+)              Üretilen Event ID
  ─────────────          ──────────────────              ─────────────────
  Account Logon    ──►   Kerberos Auth Service      ──►  4768 (TGT istendi)
                   ──►   Kerberos Service Ticket    ──►  4769 (TGS — Kerberoast izi)
  Account Mgmt     ──►   User Account Management     ──►  4720/4726/4738
                   ──►   Security Group Management   ──►  4728/4732/4756
  Logon/Logoff     ──►   Logon                       ──►  4624/4625 (LogonType!)
  DS Access        ──►   Directory Service Changes   ──►  5136/5137/5141
                   ──►   Directory Service Access    ──►  4662 (DCSync izi, SACL şart)
  Detailed Tracking──►   Process Creation            ──►  4688 (+ komut satırı)
```

### 2.3 Denetim yükü ve öncelik (DC vs üye sunucu vs istemci)

Aynı politikayı her yere uygulamak yanlıştır. **Domain Controller** politikası ayrı GPO'da olmalı (Kerberos/DS Access olayları sadece DC'de anlamlı). İstemcilerde 4688 (process creation) + komut satırı denetimi en değerli; DC'lerde 4662/4769/5136 kritik.

## 3. Pratik Uygulama

### 3.1 Kritik alt kategorileri aç (auditpol ile — test/tekil)
```powershell
# En değerli alt kategoriler (DC için)
auditpol /set /subcategory:"Kerberos Service Ticket Operations" /success:enable /failure:enable
auditpol /set /subcategory:"Security Group Management"          /success:enable
auditpol /set /subcategory:"User Account Management"            /success:enable
auditpol /set /subcategory:"Directory Service Changes"         /success:enable
auditpol /set /subcategory:"Directory Service Access"          /success:enable  # 4662 (SACL ile)
auditpol /set /subcategory:"Logon"                             /success:enable /failure:enable
# Mevcut durumu dök
auditpol /get /category:* | findstr /i "enable"
```

### 3.2 GPO ile domain geneli (üretim yöntemi)
```text
GPO (DC'lere link): Computer Config → Policies → Windows Settings → Security Settings →
   Advanced Audit Policy Configuration → Audit Policies →
     Account Logon    → Kerberos Service Ticket Operations : Success, Failure
     Account Mgmt      → Security Group Management          : Success
     DS Access         → Directory Service Changes          : Success
     DS Access         → Directory Service Access           : Success
   + Security Options → "Force audit policy subcategory settings..." : Enabled
```

### 3.3 Komut satırı denetimini aç (4688 zenginleştirme)
```text
GPO: Administrative Templates → System → Audit Process Creation →
     "Include command line in process creation events" = Enabled
→ 4688 olayına saldırganın çalıştırdığı TAM komut satırı eklenir (paha biçilmez).
```

## 4. Tespit Değeri — Politika Değişikliğinin Kendisi Bir Alarmdır

Saldırgan, iz bırakmamak için **denetim politikasını kapatmayı** dener. Bu eylem de bir olaydır:

```yaml
# Sigma — Denetim politikası manipülasyonu
title: Audit Policy Degisikligi veya Kapatma
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: [4719, 4739, 1102]   # 4719=System audit policy changed
  condition: sel
level: high
```
```powershell
# Get-WinEvent — son 24 saatte audit politikası değişikliği (4719)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4719;
  StartTime=(Get-Date).AddDays(-1)} |
  Select TimeCreated, @{N='Kim';E={$_.Properties[1].Value}}, Message
```

### Kritik Event ID kataloğu (bu politikaların ürettiği)

| Event ID | Alt kategori | Anlamı | Karşı Red saldırısı |
|----------|--------------|--------|---------------------|
| **4768/4769** | Kerberos Ticket Ops | TGT / TGS istendi | Kerberoasting → [Red M03](../../3-Red_Team/Modul_03_Kimlik_Bilgisi_Erisimi/) |
| **4728/4732/4756** | Security Group Mgmt | Ayrıcalıklı gruba ekleme | Yetki yükseltme → [Red M05](../../3-Red_Team/Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| **4662** | Directory Service Access | Dizin nesnesine erişim (SACL) | DCSync → [Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |
| **5136/5141** | Directory Service Changes | Nesne değişti/silindi | ACL/GPO/AdminSDHolder abuse → [Red M05](../../3-Red_Team/Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| **4688** | Process Creation | Süreç + komut satırı | Yerleşme/araç çalıştırma → [Red M02](../../3-Red_Team/Modul_02_Ilk_Erisim_ve_Yerlesme/) |
| **4719** | Policy Change | Denetim politikası değişti | Anti-forensics |

## 5. Doğrulama / Lab

```powershell
# 1) Politika gerçekten aktif mi? (çakışma yoksa "enable" görünmeli)
auditpol /get /subcategory:"Kerberos Service Ticket Operations"
# 2) Olay üretiliyor mu? Bir SPN'e TGS iste (Kerberoast simülasyonu) → 4769 bekle
# 3) Basic/Advanced çakışması testi: "Force subcategory" kapalıyken alt kategori
#    ayarlarının sıfırlandığını gözlemle → sonra Enabled yapıp tekrar doğrula
```
> Kural: Bir denetim ayarını açtıktan sonra, onu **tetikleyen bir eylem** yapıp Security log'unda ilgili Event ID'yi **gözünle gör**. Görmüyorsan politika uygulanmamıştır.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Basic/Advanced çakışması:** "Force subcategory settings" Enabled değilse Advanced ayarların **sessizce iptal olur**. Her denetim GPO'sunda bunu ilk kontrol et.
- 🔴 **4662'yi SACL olmadan beklemek:** Directory Service Access alt kategorisi açık olsa bile, nesnede **SACL yoksa** 4662 üretilmez → DCSync görünmez ([Sistem 10.4](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.4_Denetim_ve_Uyumluluk.md)).
- 🔴 **Her şeyi Success+Failure denetlemek:** 4624 (Logon) Success'i her makinede saniyede onlarca olay üretir; DC'de yönet, istemcide ölç. Gürültü = kör nokta.
- ⚠️ **Komut satırı denetimini unutmak:** 4688 komut satırı olmadan yarı değerdedir; "Include command line" mutlaka açılmalı.
- 🔍 **İzleme ipucu:** **4719** (audit policy changed) düşük hacimli ama yüksek değerlidir — meşru değişiklik nadirdir, saldırgan izini kapatmak için buraya dokunur.
