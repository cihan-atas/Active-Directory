## 1. Kavramsal Temel — Neden Var?

Windows'un yerleşik Security log'u ([01.2](./01.2_Advanced_Audit_Policy.md)) **kim ne yaptı**'yı iyi anlatır ama **süreçler arası ilişkiyi, ağ bağlantısını, DLL yüklemesini** yeterince göstermez. Örneğin `4688` bir sürecin başladığını söyler; ama o sürecin **hangi ana süreçten (parent) doğduğunu**, **hangi IP'ye bağlandığını**, **process'e uzaktan bellek yazıldığını** (LSASS dump!) göstermez.

**Sysmon (System Monitor)** — Sysinternals'ın ücretsiz sürücü tabanlı ajanı — bu boşluğu doldurur. Kernel seviyesinde çalışır, kendi log kanalına (`Microsoft-Windows-Sysmon/Operational`) **zenginleştirilmiş** olaylar yazar: her sürece **hash**, **parent process ağacı**, **komut satırı**, ağ bağlantısına **süreç eşlemesi**, imzasız DLL, named pipe, WMI kalıcılığı. Bu, tehdit avcılığının ([Blue M09](../Modul_09_Tehdit_Avciligi_ve_Degerlendirme/)) ve EDR-benzeri tespitin temelidir.

> **Analoji:** Security log güvenlik kamerası kayıtları ise, Sysmon her odaya yerleştirilmiş **hareket + parmak izi + DNA** sensörüdür. Saldırganın "yaşam belirtilerini" (living-off-the-land) yakalar.

Kritik nokta: **Sysmon'un değeri konfigürasyonundadır.** Ham kurulum gürültü üretir; iyi bir config (SwiftOnSecurity / Olaf Hartong) sinyali süzer.

## 2. Teknik Derinlik

### 2.1 En değerli Sysmon Event ID'leri

```
  ┌──────────── SALDIRI ZİNCİRİ ─────────────┐   ┌──── SYSMON GÖRÜR ────┐
  │ Phishing makro → powershell.exe          │──►│ EID 1: ProcessCreate │
  │   parent=winword.exe  (anormal ağaç!)    │   │  + Hash + CmdLine    │
  │ powershell → C2 sunucusuna bağlanır      │──►│ EID 3: NetworkConnect│
  │   (443/tcp dış IP)                       │   │  + süreç eşlemesi    │
  │ mimikatz → LSASS belleğini okur          │──►│ EID 10: ProcessAccess│
  │   (GrantedAccess 0x1010/0x1410)          │   │  → LSASS dump alarmı! │
  │ kalıcılık: Run anahtarı / WMI abonelik   │──►│ EID 13 / 19-20-21    │
  └──────────────────────────────────────────┘   └──────────────────────┘
```

| EID | Olay | Neden kritik (tespit) |
|-----|------|------------------------|
| **1** | Process Create | Hash + tam komut satırı + **parent ağacı** (LOLBin tespiti) |
| **3** | Network Connect | Süreç → IP/port eşlemesi (C2 beaconing) |
| **7** | Image Load | İmzasız/anormal DLL (DLL sideloading) |
| **8** | CreateRemoteThread | Süreç enjeksiyonu (process injection) |
| **10** | Process Access | **LSASS'e erişim** — kimlik bilgisi hırsızlığı → [Red M03](../../3-Red_Team/Modul_03_Kimlik_Bilgisi_Erisimi/) |
| **11** | File Create | Dropper, payload yazımı |
| **13** | Registry Set | Run key / kalıcılık |
| **15** | FileCreateStreamHash | ADS (Alternate Data Stream) gizleme |
| **19/20/21** | WMI Event | WMI kalıcılık (fileless persistence) |
| **22** | DNS Query | Süreç → DNS eşlemesi (DGA/tünelleme) |
| **25** | Process Tampering | Process hollowing / herpaderping |

### 2.2 LSASS erişim tespitinin mekaniği (EID 10)

Mimikatz `sekurlsa::logonpasswords` çalıştırdığında `lsass.exe` süreç belleğini `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION` haklarıyla açar. Sysmon EID 10, `TargetImage: lsass.exe` ve `GrantedAccess: 0x1010` / `0x1410` değerini yakalar. Meşru erişim (AV, EDR) beyaz listeye alınır; geri kalan **her** LSASS erişimi yüksek öncelikli alarmdır. Bu, [Blue M03 — Kimlik Bilgisi Koruması](../Modul_03_Kimlik_Bilgisi_Korumasi/)'nun temel tespitidir.

## 3. Pratik Uygulama

### 3.1 Kurulum (iyi bir config ile)
```powershell
# SwiftOnSecurity veya Olaf Hartong config'i ile kur (ham config KULLANMA)
sysmon64.exe -accepteula -i sysmonconfig-export.xml
# Config güncelle (yeni sürüm)
sysmon64.exe -c sysmonconfig-export.xml
# Kurulu mu / hangi config?
sysmon64.exe -c            # aktif konfigürasyonu göster
Get-Service Sysmon64
```

### 3.2 Config mantığı (include/exclude — gürültü kontrolü)
```xml
<!-- LSASS erişimini yakala, meşru EDR'ı hariç tut -->
<ProcessAccess onmatch="include">
  <TargetImage condition="image">lsass.exe</TargetImage>
</ProcessAccess>
<ProcessAccess onmatch="exclude">
  <SourceImage condition="image">MsMpEng.exe</SourceImage>   <!-- Defender -->
</ProcessAccess>
```

### 3.3 WEF ile Sysmon logunu topla
```text
[01.1] aboneliğine Sysmon kanalını ekle:
  <Select Path="Microsoft-Windows-Sysmon/Operational">*</Select>
→ Sysmon olayları da merkezî ForwardedEvents'e akar.
```

## 4. Tespit Değeri — Sigma / KQL / Get-WinEvent

```yaml
# Sigma — Office'ten doğan şüpheli süreç (makro → shell)
title: Office Uygulamasindan Sup­heli Cocuk Surec
logsource: { product: windows, category: process_creation }
detection:
  parent:
    ParentImage|endswith: ['\winword.exe','\excel.exe','\powerpnt.exe']
  child:
    Image|endswith: ['\powershell.exe','\cmd.exe','\wscript.exe','\mshta.exe']
  condition: parent and child
level: high
```
```kql
// KQL (Sentinel/Defender) — LSASS'e şüpheli erişim
Event
| where Source == "Microsoft-Windows-Sysmon" and EventID == 10
| where TargetImage endswith "lsass.exe"
| where GrantedAccess in ("0x1010","0x1410","0x143a")
| where SourceImage !in ("...EDR beyaz liste...")
```
```powershell
# Get-WinEvent — Sysmon EID 1: powershell'i başlatan anormal parent'lar
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' -FilterXPath `
 "*[System[EventID=1]]" -MaxEvents 200 |
 Where-Object { $_.Message -match 'powershell' -and $_.Message -match 'winword|excel' }
```

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Ham/boş config ile kurmak:** Varsayılan Sysmon her şeyi loglar → gürültü seli, disk dolması. SwiftOnSecurity/Olaf Hartong config'i ile başla, ortamına göre uyarla.
- 🔴 **Sysmon'u tek başına "EDR" sanmak:** Sysmon telemetri **üretir**, tespit/yanıt yapmaz; SIEM + kural + [Blue M02](../Modul_02_SIEM_ve_Tespit_Muhendisligi/) olmadan yarım kalır.
- ⚠️ **Config'i imzalamamak / korumamak:** Saldırgan `sysmon -c` ile config'i **boşaltabilir** veya servisi durdurabilir → EID 4/255 (Sysmon durumu değişti) izlenmeli.
- ⚠️ **LSASS exclude listesini fazla geniş tutmak:** "Tüm imzalı süreçleri hariç tut" dersen mimikatz kendini imzalı gösterebilir; hariç tutmayı **belirli EDR imajlarıyla** sınırla.
- 🔍 **İzleme ipucu:** Sysmon servisinin durması (**EID 4/255**) veya config değişimi, saldırganın körleştirme girişimidir → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).
