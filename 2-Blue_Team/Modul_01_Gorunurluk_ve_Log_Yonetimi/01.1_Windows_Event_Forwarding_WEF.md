## 1. Kavramsal Temel — Neden Var?

Savunmanın **birinci yasası:** göremediğini savunamazsın. Bir saldırgan DC'ye eriştiği anda ilk işlerinden biri **yerel Security log'unu temizlemektir** (Event ID **1102**). Log DC'nin kendi diskinde durduğu sürece, saldırganın onu silmesiyle senin onu okuman arasında **yarış** vardır — ve saldırgan bu yarışı neredeyse her zaman kazanır.

**Windows Event Forwarding (WEF)**, bu yarışı ortadan kaldırır: olaylar üretildikleri **anda** (near-real-time) merkezî bir **toplayıcıya (collector)** itilir/çekilir. Saldırgan kaynaktaki logu silse bile **kopya çoktan güvenli bir sunucudadır.** WEF, ajan gerektirmez (agentless) — Windows'un yerleşik **WinRM** ve **Event Collector (Wecsvc)** servislerini kullanır. Bu yüzden kurumsal SOC'ların temel taşıdır: sıfır lisans, sıfır ajan, imzalı/şifreli taşıma.

> **Analoji:** Her DC'nin kendi güvenlik kamerası kaydını yerelde tutması, hırsızın çıkarken kaseti alıp götürmesi demektir. WEF, görüntüyü **canlı olarak uzaktaki bir kayıt merkezine** akıtır — hırsız kamerayı kırsa bile kayıt zaten dışarıda.

Bu dosya, [Sistem 10.4](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.4_Denetim_ve_Uyumluluk.md)'te "merkezî toplama şart" denilen adımın **nasıl** yapıldığını anlatır ve tüm Blue Team tespit zincirinin ([Blue M02](../Modul_02_SIEM_ve_Tespit_Muhendisligi/)) **ham maddesini** üretir.

## 2. Teknik Derinlik

### 2.1 Mimari: Source-Initiated vs Collector-Initiated

WEF iki abonelik (subscription) modeliyle çalışır:

```
  ┌─────────────── SOURCE-INITIATED (PUSH) — kurumsal standart ───────────────┐
  │                                                                            │
  │   [DC / Sunucu / İstemci]                          [WEC — Toplayıcı]       │
  │   ┌───────────────────┐   ① GPO ile collector       ┌──────────────────┐  │
  │   │ EventLog servisi  │      adresi + abonelik       │ Wecsvc           │  │
  │   │ (kaynak olaylar)  │─────────────────────────────►│ ForwardedEvents  │  │
  │   │ WinRM (5985/5986) │   ② WinRM üzerinden HTTPS/    │ log'una yazar    │  │
  │   └───────────────────┘      Kerberos ile PUSH       └────────┬─────────┘  │
  │       Kaynak "ben varım" der, kendi olaylarını iter           │            │
  └───────────────────────────────────────────────────────────────┼────────────┘
                                                                   ▼
                                                       [SIEM / Splunk / Elastic]
                                                        → [Blue M02] tespit

  COLLECTOR-INITIATED (PULL): Toplayıcı her kaynağa tek tek bağlanıp çeker.
  Sadece küçük/sabit ortamda; ölçeklenmez, her hedefe WinRM erişimi gerekir.
```

**Neden Source-Initiated?** Binlerce makineyi GPO ile tek noktadan yönetirsin; yeni makine domain'e katıldığında otomatik abone olur. Collector'ın her kaynağın IP'sini bilmesi gerekmez — kaynak collector'a gelir. Kurumsal dağıtımların **%95'i** bu modeldir.

### 2.2 Taşıma güvenliği: Kerberos vs HTTPS

| Mod | Port | Kimlik doğrulama | Şifreleme | Kullanım |
|-----|------|------------------|-----------|----------|
| **HTTP + Kerberos** | 5985 | Kerberos (domain) | Kerberos ile **payload şifreli** | Domain içi standart |
| **HTTPS + Sertifika** | 5986 | İstemci sertifikası | TLS | Workgroup / DMZ / domain-dışı |

Yaygın yanılgı: "HTTP = şifresiz". Domain ortamında **HTTP taşıması Kerberos ile zaten şifrelidir** (message-level encryption); sertifika altyapısı sadece domain'e üye olmayan makineler için gerekir.

### 2.3 Kaynağın collector'a yazma yetkisi

Kaynak makineler, `Network Service` hesabı adına olay iletir. Collector'da **`Event Log Readers`** yerel grubu ve WinRM ACL'i, kaynağın `Domain Computers` üyeliğiyle iletim yetkisini verir. Yanlış yapılandırmada olaylar sessizce **düşer** — bu yüzden §3'teki doğrulama kritiktir.

## 3. Pratik Uygulama (Kurulum + Doğrulama)

### 3.1 Collector'ı etkinleştir (WEC sunucusunda)
```powershell
# Windows Event Collector servisini başlat ve otomatik yap
wecutil qc /quiet
# WinRM dinleyicisini aç (kaynaklar buraya gelecek)
winrm quickconfig -quiet
```

### 3.2 GPO ile kaynakları yönlendir (domain geneli)
```text
GPO: Computer Config → Policies → Administrative Templates → Windows Components →
     Event Forwarding → "Configure target Subscription Manager" → Enabled
  Değer: Server=http://WEC01.corp.local:5985/wsman/SubscriptionManager/WEC
```
```powershell
# Kaynak makinede Network Service'i Event Log Readers'a ekle (GPO ile de dağıtılır)
net localgroup "Event Log Readers" "NT AUTHORITY\NETWORK SERVICE" /add
```

### 3.3 Abonelik oluştur (hangi olaylar toplanacak)
```xml
<!-- subscription.xml — kritik güvenlik olaylarını topla -->
<Subscription xmlns="http://schemas.microsoft.com/2006/03/windows/events/subscription">
  <SubscriptionId>SEC-Critical</SubscriptionId>
  <SubscriptionType>SourceInitiated</SubscriptionType>
  <ConfigurationMode>Custom</ConfigurationMode>
  <Delivery Mode="Push">
    <Batching><MaxLatencyTime>30000</MaxLatencyTime></Batching>
  </Delivery>
  <Query><![CDATA[
    <QueryList><Query Id="0">
      <Select Path="Security">*[System[(EventID=4624 or EventID=4625 or
        EventID=4720 or EventID=4728 or EventID=4732 or EventID=4740 or
        EventID=4768 or EventID=4769 or EventID=1102 or EventID=4662)]]</Select>
    </Query></QueryList>
  ]]></Query>
</Subscription>
```
```powershell
wecutil cs subscription.xml      # aboneliği yükle
wecutil gs SEC-Critical          # abonelik durumunu gör
wecutil es                       # tüm abonelikleri listele
```

### 3.4 Doğrulama (çalışıyor mu?) — ZORUNLU
```powershell
# 1) Kaç kaynak aktif abone oldu? (RunTimeStatus)
wecutil gr SEC-Critical
# 2) ForwardedEvents log'una veri akıyor mu?
Get-WinEvent -LogName ForwardedEvents -MaxEvents 20 |
  Group-Object -Property MachineName | Select-Object Count, Name
# 3) Bir test olayı üret ve iletildiğini gör (kaynakta yanlış parola dene → 4625)
```

## 4. Tespit Değeri — WEF'in Beslediği Kurallar

WEF tek başına tespit yapmaz; **veriyi toplar**. İlk ve en kritik tespit kuralı, WEF pipeline'ının **kendisinin sağlığıdır**:

```yaml
# Sigma — Log temizleme / iletim durması (yüksek öncelik)
title: Security Event Log Temizlendi veya WEF Kesildi
logsource: { product: windows, service: security }
detection:
  clear_log:
    EventID: [1102, 104]        # 1102=Security temizlendi, 104=log temizlendi
  wef_gap:
    EventID: 1100               # EventLog servisi kapandı
  condition: clear_log or wef_gap
level: high
```
```powershell
# Get-WinEvent — bir kaynaktan 1 saattir olay gelmiyorsa (sessiz kaynak = alarm)
$since = (Get-Date).AddHours(-1)
Get-WinEvent -LogName ForwardedEvents |
  Where-Object TimeCreated -gt $since |
  Group-Object MachineName | Where-Object Count -eq 0
```

| Event ID | Kaynak | Anlamı | Neden WEF'te kritik |
|----------|--------|--------|---------------------|
| **1102** | Security | Security log temizlendi | Saldırgan iz siliyor → WEF kopyayı zaten aldı |
| **104** | System | Bir event log temizlendi | Aynı — anti-forensics |
| **1100** | System | EventLog servisi kapatıldı | Telemetri kör edilmeye çalışılıyor |
| **4** (WEC) | Eventlog-Forwarding | Abonelik hatası | Kaynak iletemiyor → görünürlük kaybı |

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Logu yerelde bırakmak:** WEF olmadan denetim kâğıt üzerindedir; ilk şey merkezî toplama.
- 🔴 **`ForwardedEvents` log boyutunu küçük bırakmak:** Varsayılan ~20 MB hızla dolar, eski olay döngüsel silinir. Collector'da bu logu **1 GB+**'a çıkar ve SIEM'e beslendiğinden emin ol.
- ⚠️ **Aboneliği kurup doğrulamamak:** `wecutil gr` ile kaç kaynağın gerçekten abone olduğunu kontrol et; GPO uygulanmadan kaynak sessizce eksik kalır.
- ⚠️ **Sadece Security log toplamak:** PowerShell (4103/4104), Sysmon ([01.3](./01.3_Sysmon_ile_Derin_Telemetri.md)) ve WMI logları da toplanmalı — saldırgan bunlarda iz bırakır.
- 🔍 **İzleme ipucu:** WEF pipeline'ının **sessizleşmesi** (bir kaynaktan olay akışının durması) saldırının kendisi kadar kritik bir sinyaldir → §4 "sessiz kaynak" sorgusu.
