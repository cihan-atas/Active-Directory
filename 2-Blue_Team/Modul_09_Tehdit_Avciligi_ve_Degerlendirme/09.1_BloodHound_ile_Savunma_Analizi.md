## 1. Kavramsal Temel — Neden Var?

Önceki Blue modülleri tekil kontrolleri sertleştirdi ([Blue M05](../Modul_05_Yetki_ve_ACL_Sikilastirma/)–[Blue M08](../Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/)); ama saldırgan tekil kontrollere değil, **zincirlere** bakar: "Bu düşük yetkili kullanıcıdan Domain Admin'e giden bir yol var mı?" Bu bakış açısını benimsemenin en güçlü yolu, saldırganın kendi aracını **savunma için** kullanmaktır: **BloodHound**. BloodHound, AD'yi bir **grafik** olarak modeller (düğümler: kullanıcı/grup/bilgisayar/GPO; kenarlar: haklar/oturumlar/üyelikler) ve "Domain Admins'e giden en kısa yol" gibi **attack path** sorgularını yanıtlar.

Savunma amaçlı kullanım (bazen "BloodHound for Blue" veya proaktif değerlendirme) fikri basittir: **saldırgandan önce aynı grafiği çiz, en kısa yolları bul, tehlikeli kenarları kır.** Bu, [Blue 05.2 DACL hijyeni](../Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md)'nin nokta-denetimini **grafik-düzeyi** stratejiye çıkarır.

> **İlke:** Saldırgan tekil hataya değil, hatalar zincirine bakar. Savunma da öyle bakmalı: attack path'i saldırgandan önce çiz ve kır. Tek bir kenarı kırmak bazen tüm yolu kapatır.

Bu, tehdit avcılığı (threat hunting) ve **saldırı yüzeyi yönetiminin (attack surface management)** temel aracıdır; [Blue M02 tespit](../Modul_02_SIEM_ve_Tespit_Muhendisligi/) reaktifken bu **proaktiftir**.

## 2. Teknik Derinlik

### 2.1 Grafik modeli ve saldırı yolu

```
   BloodHound grafiği: DÜĞÜM'ler ve KENAR'lar
   ┌──────────────────────────────────────────────────────────────┐
   │ [normaluser] ──MemberOf──► [IT Staff] ──GenericAll──► [svc01]  │
   │       │                                                  │      │
   │       │ HasSession                            ForceChangePassword│
   │       ▼                                                  ▼      │
   │ [WKS042] ◄──AdminTo── [helpdesk] ──MemberOf──► [Server Admins]  │
   │                                                          │      │
   │                                         WriteDACL        ▼      │
   │                                       ──────────► [Domain Admins]│
   └──────────────────────────────────────────────────────────────┘
   Sorgu: "Shortest Path to Domain Admins" → kırılacak kenarları bulur.
```

### 2.2 SharpHound: veri toplama (collector)

**SharpHound** (veya BloodHound CE'de AzureHound/native collector), AD'den grafiği besleyen veriyi toplar: ACL'ler (DACL kenarları), grup üyelikleri, oturumlar (kim nerede oturum açmış — HasSession), yerel admin hakları (AdminTo), delegation, GPO bağlantıları, sertifika (ESC) yolları. Toplama **collection method** ile ayarlanır (`All`, `DCOnly`, `Session`). Savunma amaçlı toplama, yetkiyle ve kayıt altında yapılmalıdır.

### 2.3 BloodHound CE ve sertifika/ADCS yolları

Modern BloodHound Community Edition, AD CS **ESC** yollarını ([Blue M07](../Modul_07_AD_CS_PKI_Guvenligi/)) ve Azure/Entra kenarlarını da modelller. "Tier Zero" işaretlemesi ile kritik varlıklar (DC, DA, CA) etiketlenir; grafiğin bu düğümlere giden tüm yolları öncelikli değerlendirilir → [09.3 Forest Druid](./09.3_Purple_Knight_ve_Forest_Druid.md).

## 3. Pratik Uygulama

### 3.1 Savunma amaçlı veri toplama (SharpHound)
```powershell
# Kendi ortamında, yetkiyle, kayıt altında topla (SharpHound collector)
# Collection: ACL/session/local admin/delegation/cert dahil
.\SharpHound.exe -c All --outputdirectory C:\BH_Audit --zipfilename corp_audit
# (BloodHound CE'de native collector / AzureHound da kullanılabilir)
```

### 3.2 Kritik attack path sorguları (BloodHound / Cypher)
```cypher
// Domain Admins'e giden en kısa yollar (herhangi kullanıcıdan)
MATCH p=shortestPath((u:User)-[*1..]->(g:Group {name:"DOMAIN ADMINS@CORP.LOCAL"}))
RETURN p LIMIT 25

// Tier Zero'ya ACL üzerinden ulaşabilen non-Tier0 principal'lar
MATCH p=(n)-[:GenericAll|WriteDacl|WriteOwner|ForceChangePassword*1..]->(t)
WHERE t.system_tags CONTAINS "admin_tier_0" AND NOT n.system_tags CONTAINS "admin_tier_0"
RETURN p
```

### 3.3 Kenarları kır ve tekrar ölç
```text
1) En kısa yoldaki her tehlikeli kenarı belgele (kim → ne hakkı → hedef).
2) Kenarı kaynağında kır: [Blue 05.2] fazla DACL kaldır, [Blue 05.1] Tier ihlali düzelt.
3) Yeniden topla ve sorgula → yol kısalmalı/kapanmalı. Tek kenar bazen tüm yolu keser.
4) Düzenli tekrarla (09.4) — yeni biriken kenarlar yakalanır.
```

## 4. Tespit Değeri — SharpHound Toplama Aktivitesi

Savunma SharpHound'u kullanır; ama **saldırgan da** kullanır ([Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/)). Yetkisiz toplama tespit edilmelidir:

```yaml
# Sigma — SharpHound/BloodHound keşif (yoğun LDAP + oturum enumerasyonu)
title: SharpHound-BloodHound Kesif Aktivitesi
logsource: { product: windows, service: security }
detection:
  ldap_recon:
    EventID: 1644            # LDAP pahalı/verimsiz arama (yoğun enum)
  session_enum:
    EventID: 4624
    LogonType: 3
    # kısa sürede ÇOK makineye SAMR/oturum sorgusu (fan-out)
  condition: ldap_recon
level: medium
tags: [attack.discovery, attack.t1069, attack.t1087]
```
```powershell
# Get-WinEvent — kısa sürede yoğun LDAP arama (1644) = enumerasyon dalgası
Get-WinEvent -FilterHashtable @{LogName='Directory Service'; Id=1644;
  StartTime=(Get-Date).AddMinutes(-15)} | Measure-Object   # ani artış = SharpHound
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| Yoğun LDAP arama (1644) | Directory Service | Grafik enumerasyonu | T1069 |
| SAMR/oturum fan-out | 4624/4661 | Yerel admin/session keşfi | T1087 |
| Honeytoken'a temas | 4769 | Keşif tuzağı ([Blue 04.4](../Modul_04_Yanal_Hareket_Tespiti/04.4_Honeytoken_ve_Honey_Account.md)) | T1087 |

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Grafiği hiç çizmemek:** Nokta-denetimler zinciri göremez; saldırgan zincire bakar. BloodHound ile attack path'i düzenli ölç.
- 🔴 **Toplayıp temizlememek:** BloodHound verisi (ACL, oturum, admin haritası) ele geçerse saldırgana hazır plan verir; çıktıları güvenli sakla/sil, erişimi Tier 0 sınırla.
- ⚠️ **Tek kenar yerine tüm düğümü silmek:** Bazen tek bir tehlikeli kenarı kırmak tüm yolu kapatır; en verimli kenarı (choke point) hedefle.
- ⚠️ **Session verisini görmezden gelmek:** "HasSession" kenarları (bir DA'nın nerede oturum açtığı) Tier ihlallerini ([Blue 05.1](../Modul_05_Yetki_ve_ACL_Sikilastirma/05.1_Admin_Tier_Model.md)) ortaya çıkarır; sadece ACL'e bakma.
- 🔍 **İzleme ipucu:** Kısa sürede yoğun LDAP arama (1644) + geniş oturum enumerasyonu, meşru yönetimde nadirdir ve aktif SharpHound keşfinin (saldırgan veya yetkisiz) güçlü işaretidir.
