## 1. Kavramsal Temel — Neden Var?

BloodHound ([09.1](./09.1_BloodHound_ile_Savunma_Analizi.md)) attack path'i, PingCastle ([09.2](./09.2_PingCastle_ile_Risk_Skorlama.md)) genel skoru verir; ama bir savunmacının cevaplaması gereken en temel soru şudur: **"Tier 0 tam olarak neyi kapsıyor?"** Yani domain'i kontrol edebilecek her varlık (hesap, grup, bilgisayar, GPO, ACL yolu) hangileri? Çoğu ortamda bu sınır **bulanıktır** — kimse "Tier 0 nedir" listesini tam bilmez; yanlışlıkla Tier 0'a ulaşan yollar (bir GPO, bir servis hesabı, bir ACL) gözden kaçar.

İki araç bu boşluğu doldurur:
- **Purple Knight** (Semperis): PingCastle benzeri, AD/Entra güvenlik göstergelerini (Indicators of Exposure/Compromise) tarayan ücretsiz değerlendirme aracı; özellikle **IoE/IoC** kategorileriyle güçlüdür.
- **Forest Druid** (Semperis): **Tier 0 attack path** aracı — geleneksel "dışarıdan içeri" (attack path) yaklaşımının tersine, **"Tier 0'dan dışarı"** bakar: "Tier 0'a kimler ulaşabiliyor?" sorusunu haritalar ve Tier 0 sınırını netleştirir.

> **İlke:** Tier 0'ı savunmak için önce **ne olduğunu bilmelisin.** Forest Druid, "Tier 0'a giden tüm yolları" tersinden haritalayarak görünmez ayrıcalık köprülerini ortaya çıkarır; Purple Knight duruşu IoE/IoC ile ölçer.

Bu, [Blue 05.1 Tier Model](../Modul_05_Yetki_ve_ACL_Sikilastirma/05.1_Admin_Tier_Model.md)'in "Tier 0 kapsamını netleştirme" adımının aracıdır.

## 2. Teknik Derinlik

### 2.1 Forest Druid: "içeriden dışarı" attack path

```
   GELENEKSEL (BloodHound): dışarıdan → içeri
     [normaluser] ──►──►──► [Domain Admins]   (her düşük düğümden yol ara)

   FOREST DRUID: içeriden → dışarı (Tier 0 sınırı)
     [Domain Admins / DC / CA]  ◄──?── kim ulaşabiliyor?
        │  "Tier 0'a ACL/üyelik/GPO ile ulaşan HER principal"
        ▼
     ┌─────────────────────────────────────────────────┐
     │ Beklenen Tier 0: DA, EA, DC$, krbtgt, CA         │
     │ ⚠ Beklenmeyen: svc_backup (GPO yolu), helpdesk   │
     │    (WriteDACL), eski admin (orphaned adminCount) │
     └─────────────────────────────────────────────────┘
     → "Tier 0 sınırı" = bu kümenin tamamı; beklenmeyenleri temizle.
```

### 2.2 IoE vs IoC (Purple Knight)

- **IoE (Indicator of Exposure):** Henüz sömürülmemiş ama sömürülebilir zayıflık (örn. açık DCSync hakkı, zayıf krbtgt). Proaktif düzeltme hedefi.
- **IoC (Indicator of Compromise):** Aktif/geçmiş saldırı izi (örn. AdminSDHolder değişimi, şüpheli SPN). Bu, olay müdahalesini ([Blue M10](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/)) tetikler.

Purple Knight ikisini de kategorilere ayırıp puanlar — bu ayrım, "düzeltilecek zayıflık" ile "hemen müdahale edilecek ihlal" arasındaki önceliklendirmeyi netleştirir.

### 2.3 Tier 0 sınırının pratik önemi

Tier 0 sınırı netleşince, tüm diğer kontroller odaklanır: hangi hesaplar Protected Users/Silo'ya girmeli ([Blue 03.3](../Modul_03_Kimlik_Bilgisi_Korumasi/03.3_Protected_Users_ve_Authentication_Policies.md)), hangi makineler "Deny logon" ile korunmalı ([Blue 05.1](../Modul_05_Yetki_ve_ACL_Sikilastirma/05.1_Admin_Tier_Model.md)), hangi nesneler SACL ile denetlenmeli. Sınır bulanıksa savunma da bulanıktır.

## 3. Pratik Uygulama

### 3.1 Purple Knight değerlendirmesi
```text
1) Purple Knight'ı düşük yetkili bir hesapla çalıştır (Semperis, ücretsiz indirme).
2) AD + Entra ID göstergelerini tara → IoE/IoC kategorileri + skor + düzeltme.
3) IoC bulgularını IR'a ([Blue M10]) yönlendir; IoE'leri düzeltme kuyruğuna al.
4) Çıktı raporunu Tier 0'da güvenli sakla (PingCastle gibi hassas).
```

### 3.2 Forest Druid ile Tier 0 haritalama
```text
1) Forest Druid'i çalıştır → "Tier 0'a ulaşabilen tüm principal'lar" listesi.
2) Beklenen Tier 0 (DA/EA/DC$/krbtgt/CA) ile karşılaştır.
3) BEKLENMEYEN her yol bir bulgudur:
   - GPO üzerinden ulaşan hesap → [Blue 05.3] GPO yazma hakkını kaldır
   - ACL (WriteDACL/GenericAll) → [Blue 05.2] fazla hakkı kaldır
   - orphaned adminCount → [Blue 05.4] temizle
4) Temizlenen Tier 0 kümesini "onaylı Tier 0" olarak belgele ve izle.
```

### 3.3 Bulguları PowerShell ile doğrula (örnek: Tier 0 ACL yolu)
```powershell
# Forest Druid'in işaret ettiği bir Tier 0 ACL yolunu manuel doğrula
$dcOU = "OU=Domain Controllers,$((Get-ADDomain).DistinguishedName)"
(Get-Acl "AD:\$dcOU").Access | Where-Object { -not $_.IsInherited -and
  $_.IdentityReference -notmatch 'Domain Admins|Enterprise Admins|SYSTEM|Enterprise' } |
  Select IdentityReference, ActiveDirectoryRights
```

## 5. Doğrulama / Lab

```powershell
# 1) Tier 0 baseline: Forest Druid ile "onaylı Tier 0" kümesini belgele
# 2) Kapsam testi (izole lab): bir test hesabına DC OU'da WriteDACL ver →
#    Forest Druid yeni Tier 0 yolunu göstermeli → kaldır → yol kaybolmalı
# 3) IoC testi: AdminSDHolder değişimi (05.4) yap → Purple Knight IoC olarak yakalamalı
# 4) Trend: Tier 0 kümesi zaman içinde küçülmeli/sabit kalmalı (scope creep yok)
```
> **Kanıt:** "Onaylı Tier 0" kümesi net ve sabit olmalı; her yeni/beklenmeyen yol bir bulgudur. Forest Druid + Purple Knight, BloodHound/PingCastle'ı Tier 0 odağıyla tamamlar.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Tier 0 kapsamını hiç tanımlamamak:** "Tier 0 nedir" listesi yoksa savunma odaksızdır; Forest Druid ile sınırı netleştir ve belgele.
- 🔴 **IoE ile IoC'yi karıştırmak:** IoE düzeltme kuyruğu, IoC hemen IR'dır ([Blue M10](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/)); ikisini ayır, önceliği doğru ver.
- ⚠️ **Scope creep'i izlememek:** Tier 0 zamanla sessizce büyür (yeni servis hesabı, GPO yolu); düzenli haritalama ([09.4](./09.4_Duzenli_Proaktif_Degerlendirme.md)) ile küçük tut.
- ⚠️ **Tek araca güvenmek:** BloodHound + PingCastle + Forest Druid/Purple Knight birbirini tamamlar; farklı perspektifler farklı boşlukları yakalar.
- 🔍 **İzleme ipucu:** "Onaylı Tier 0" listesi dışındaki bir principal'a Tier 0 grup/ACL ekleme (4728/5136), kapsam kaymasının veya kalıcılığın işaretidir — Forest Druid baseline'ıyla korele et.
