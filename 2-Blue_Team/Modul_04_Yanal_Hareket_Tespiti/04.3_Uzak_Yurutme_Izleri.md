## 1. Kavramsal Temel — Neden Var?

Çalınan kimlik ([04.2](./04.2_Pass_the_Hash_Ticket_Tespiti.md)) tek başına yetmez; saldırgan hedef makinede **komut çalıştırmak** ister. Bunun için "yaşayan araçları" (living-off-the-land) kullanır — Windows'un meşru uzaktan yönetim kanallarını: **PsExec** (SMB + servis), **WMI** (`wmic`/`Win32_Process`), **WinRM** (PowerShell Remoting), **zamanlanmış görev** (`schtasks`), **DCOM**. Her biri meşru yönetim için de kullanılır — bu yüzden tespit "aracın var olması"nı değil, **kimin, nereden, neyle** kullandığını ayırt eder.

Her uzak yürütme yöntemi **kendine özgü bir artefakt** bırakır: PsExec bir servis (7045) ve named pipe, WMI bir `WmiPrvSE.exe` çocuk süreci, WinRM bir `wsmprovhost.exe`. Bu artefaktları tanımak, yanal hareketin "çalıştırma" adımını yakalamanın anahtarıdır.

> **İlke:** Yanal hareket iki adımdır — kimliğe bürün ([04.2](./04.2_Pass_the_Hash_Ticket_Tespiti.md)) + komut çalıştır (bu dosya). Her çalıştırma kanalı benzersiz bir iz bırakır; o izleri tanı.

Bu, [Sistem 09.2 PowerShell](../../1-Sistem_Yoneticisi/Modul_09_Otomasyon_ve_Arayuzler/09.2_PowerShell_AD_Modulu.md) ve [Sistem 09.4 WAC/uzak yönetim](../../1-Sistem_Yoneticisi/Modul_09_Otomasyon_ve_Arayuzler/09.4_REST_API_ve_WAC.md)'ın kötüye kullanımının savunma karşılığıdır.

## 2. Teknik Derinlik

### 2.1 Her yöntemin parmak izi

```
  YÖNTEM     KANAL        SUNUCU-TARAFI ARTEFAKT          ANA EVENT
  ──────     ─────        ──────────────────────          ─────────
  PsExec     SMB+Servis   PSEXESVC.exe + \\pipe\psexesvc   7045, 4624 T3, Sysmon 1/17-18
  WMI        DCOM/RPC     WmiPrvSE.exe → child process     4624 T3, Sysmon 1(parent=WmiPrvSE)
  WinRM      HTTP 5985    wsmprovhost.exe                  4624 T3, 4103/4104(PS), Sysmon 1
  schtasks   RPC          yeni görev                       4698(oluştur), 4700/4702
  DCOM       RPC          mmc.exe/excel spawn              Sysmon 1(anormal parent)
  service    SCM          yeni servis                      7045, 4697
```

### 2.2 PsExec derin analizi (en yaygın)

PsExec, hedefe `PSEXESVC.exe` yükler (SMB `ADMIN$` üzerinden — Sysmon EID 11 dosya yazımı), bir **servis** olarak kaydeder (**7045**), ve komutları **named pipe** (`\\.\pipe\psexesvc`, Sysmon EID 17/18) üzerinden yürütür. Bu üçlü (dosya + servis + pipe) neredeyse kesin bir PsExec imzasıdır. Impacket'in `psexec.py`/`smbexec.py` varyantları benzer ama rastgele servis/pipe adları kullanır — davranış (ADMIN$ + servis + pipe) sabit kalır.

### 2.3 WMI ve WinRM'in "temiz" tehlikesi

WMI ve WinRM **dosya bırakmaz** (fileless), bu yüzden PsExec'ten daha sinsidir. İz, **süreç ağacında**dır: WMI ile başlatılan süreç `WmiPrvSE.exe`'nin çocuğudur; WinRM ile başlatılan süreç `wsmprovhost.exe`'nin çocuğudur. Sysmon EID 1 parent-child ilişkisi ([Blue 01.3](../Modul_01_Gorunurluk_ve_Log_Yonetimi/01.3_Sysmon_ile_Derin_Telemetri.md)) bu izin taşıyıcısıdır.

## 3. Pratik Uygulama

### 3.1 PsExec imzası (servis + Get-WinEvent)
```powershell
# Şüpheli servis kurulumları (7045) — PSEXESVC / rastgele exe ADMIN$'ten
Get-WinEvent -FilterHashtable @{LogName='System'; Id=7045} |
  Where-Object { $_.Message -match 'PSEXESVC|\\ADMIN\$\\|%SystemRoot%\\[a-zA-Z0-9]{8}\.exe' } |
  Select TimeCreated, @{N='Servis';E={($_.Message -split 'Service Name:\s+')[1].Split("`n")[0]}}
```

### 3.2 WMI/WinRM süreç-ağacı avı (Sysmon EID 1)
```powershell
# WmiPrvSE veya wsmprovhost'tan doğan şüpheli süreçler
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' -FilterXPath `
 "*[System[EventID=1]]" -MaxEvents 500 |
  Where-Object { $_.Message -match 'ParentImage:.*(WmiPrvSE|wsmprovhost)\.exe' -and
                 $_.Message -match 'Image:.*(cmd|powershell|rundll32|regsvr32)\.exe' }
```

### 3.3 PowerShell Remoting içeriği (4104)
```powershell
# WinRM üzerinden çalışan şüpheli PowerShell (script block logging)
Get-WinEvent -LogName 'Microsoft-Windows-PowerShell/Operational' -FilterXPath `
 "*[System[EventID=4104]]" |
  Where-Object { $_.Message -match 'IEX|DownloadString|FromBase64|-enc ' }
```

## 4. Tespit Değeri — Sigma / KQL

```yaml
# Sigma — WMI/WinRM ile uzak komut yürütme (fileless yanal hareket)
title: WMI-WinRM Uzak Surec Yurutme
logsource: { product: windows, category: process_creation }
detection:
  parent:
    ParentImage|endswith: ['\WmiPrvSE.exe','\wsmprovhost.exe','\services.exe']
  child:
    Image|endswith: ['\cmd.exe','\powershell.exe','\rundll32.exe','\mshta.exe']
  condition: parent and child
level: high
tags: [attack.lateral_movement, attack.t1047, attack.t1021.006]
```
```kql
// KQL — PsExec imzası: ADMIN$ servis + 4624 Type 3 korelasyonu
DeviceEvents
| where ActionType == "ServiceInstalled"
| where FileName has_any ("PSEXESVC", "ADMIN$")
| join (SecurityEvent | where EventID==4624 and LogonType==3) on DeviceName
```

| WMI | Sysmon 1 | parent=WmiPrvSE.exe | T1047 |
| WinRM | 4104 + Sysmon 1 | parent=wsmprovhost.exe | T1021.006 |

## 5. Doğrulama / Lab (Atomic Red Team)

```powershell
# Uzak yürütme izlerini üret (izole lab) → §4 kuralları alarm vermeli
Invoke-AtomicTest T1021.002 -TestNumbers 1     # PsExec → 7045 + pipe
Invoke-AtomicTest T1047   -TestNumbers 1       # WMI → WmiPrvSE child
Invoke-AtomicTest T1021.006 -TestNumbers 1     # WinRM → wsmprovhost child
Invoke-AtomicTest T1021.002 -Cleanup
# Beklenen: PsExec servis+pipe imzası, WMI/WinRM süreç-ağacı kuralları tetiklenir.
```
> **Kanıt:** Aynı komutu üç farklı kanalla çalıştır; her birinin farklı artefakt (servis/pipe vs süreç-ağacı) bıraktığını gözlemle — bu, kapsamın tam olduğunu doğrular.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **PowerShell logging kapalı:** 4103/4104 (script block/module logging) olmadan WinRM içeriği görünmez; GPO ile aç ([Blue 01.2](../Modul_01_Gorunurluk_ve_Log_Yonetimi/01.2_Advanced_Audit_Policy.md)).
- 🔴 **Sadece PsExec aramak:** WMI/WinRM fileless'tır; süreç-ağacı (parent=WmiPrvSE/wsmprovhost) tespiti olmadan sinsi kanallar kaçar.
- ⚠️ **Meşru yönetimden ayırmamak:** SCCM/WAC/yönetici PowerShell Remoting meşru kullanır; kaynak makine + hesap + hedef baseline ([04.1](./04.1_Anormal_Oturum_Acma_Analizi.md)) ile ayır.
- ⚠️ **Impacket varyantlarını gözden kaçırmak:** `smbexec.py`/`wmiexec.py` rastgele servis/pipe adı kullanır; sabit isim yerine **davranışa** (ADMIN$ + servis + pipe) kural yaz.
- 🔍 **İzleme ipucu:** `cmd.exe`/`powershell.exe`'nin `services.exe`, `WmiPrvSE.exe` veya `wsmprovhost.exe` çocuğu olması, interaktif kullanımda neredeyse hiç görülmez — güçlü uzak-yürütme sinyali.
