## 1. Kavramsal Temel — Neden Var?

Kerberos ve NTLM'in temel zaafı: **kimlik doğrulaması parolanın kendisini değil, ondan türetilen bir "sırrı" (NTLM hash veya Kerberos bileti) kullanır.** Saldırgan bu sırrı çalarsa ([Blue M03](../Modul_03_Kimlik_Bilgisi_Korumasi/)), parolayı hiç bilmeden kimliğe bürünür:

- **Pass-the-Hash (PtH):** Çalınan **NTLM hash** ile NTLM kimlik doğrulaması yapar.
- **Pass-the-Ticket (PtT):** Çalınan **Kerberos bileti** (TGT/TGS) ile kimliğe bürünür.
- **Overpass-the-Hash (Pass-the-Key):** NTLM hash'i kullanarak **Kerberos TGT** alır (hibrit).

Bu saldırılar **meşru protokol** kullanır — "geçersiz parola" gibi bir hata üretmezler. Tespit, protokolün **anormal kullanımını** aramaktır: NTLM'in beklenmedik yerde kullanılması, biletin makinesiyle uyuşmayan kaynak, imkânsız oturum desenleri. Bu, [03.3 Protected Users](../Modul_03_Kimlik_Bilgisi_Korumasi/03.3_Protected_Users_ve_Authentication_Policies.md)'ın neden NTLM'i kapattığını savunma tarafından tamamlar.

> **İlke:** PtH/PtT "yanlış parola" demez; "doğru sır, yanlış bağlam" der. Tespit, bağlamın anomalisidir.

## 2. Teknik Derinlik

### 2.1 PtH'nin bıraktığı iz (NTLM anatomisi)

```
  Saldırgan (çalınan NTLM hash)                    Hedef + DC
     │  ① NTLM auth (hash ile, parola YOK)          │
     │─────────────────────────────────────────────►│  Hedef: 4624 LogonType 3
     │                                              │        AuthPackage: NTLM
     │                                              │        (Kerberos ortamında NTLM = şüphe)
     │                                              │  DC:   4776 (NTLM doğrulama)
     │  Mimikatz sekurlsa::pth imzası: LogonType 9  │
     │  + seclogo + NTLM + yeni süreç                │  Kaynak: 4624 Type 9 (overpass)
```

**Kilit sinyal:** Modern domain'de kimlik doğrulama **Kerberos** olmalı. Bir iş istasyonundan sunucuya **NTLM** (4776/AuthPackage=NTLM) oturumu, özellikle ayrıcalıklı hesapla, güçlü bir PtH işaretidir.

### 2.2 Overpass-the-Hash imzası (LogonType 9)

Mimikatz `sekurlsa::pth`, yeni bir süreci **çalınan hash'le** başlatır; bu, 4624 **LogonType 9** (NewCredentials) + **LogonProcessName: seclogo** + **AuthenticationPackageName: Negotiate/NTLM** kombinasyonunu üretir. Bu üçlü, meşru `runas /netonly` dışında nadirdir ve güçlü bir imzadır.

### 2.3 Pass-the-Ticket ve bilet anomalileri

PtT'de saldırgan çalınan TGT/TGS'i **kendi oturumuna enjekte eder**. İzler: biletin **kaynak makinesiyle uyuşmayan** kullanımı, olağandışı bilet ömrü, `4769` isteğinde olmayan bir TGT'nin kullanılması. Golden/Silver Ticket ise farklı bir katmandır → [Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) / [Blue M10](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/).

## 3. Pratik Uygulama

### 3.1 PtH avı: ayrıcalıklı hesapla NTLM (Get-WinEvent)
```powershell
# DC'de: yönetici hesaplarının NTLM doğrulaması (4776) — Kerberos olmalıydı
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4776;
  StartTime=(Get-Date).AddHours(-6)} |
  Where-Object { $_.Message -match 'admin|DA_|svc_' } |
  Select TimeCreated, @{N='Hesap';E={($_.Message -split 'Account:\s+')[1].Split("`n")[0]}}
```

### 3.2 Overpass-the-Hash: LogonType 9 + seclogo
```powershell
# Overpass imzası: Type 9 + seclogo + NTLM
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} |
  Where-Object { $_.Message -match 'Logon Type:\s+9' -and
                 $_.Message -match 'Logon Process:\s+seclogo' -and
                 $_.Message -match 'Authentication Package:\s+Negotiate' }
```

### 3.3 NTLM kullanımını sınırla (önlem — tespit + hardening birlikte)
```text
GPO: Network Security: Restrict NTLM → "Audit" ile başla (kimin NTLM kullandığını gör)
→ sonra ayrıcalıklı hesaplarda "Deny" + Protected Users (03.3) → PtH imkânsızlaşır
→ derin protokol sertleştirme: [Blue M08]
```

## 4. Tespit Değeri — Sigma / KQL

```yaml
# Sigma — Overpass-the-Hash (LogonType 9 + seclogo imzası)
title: Overpass-the-Hash - Mimikatz sekurlsa::pth Imzasi
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: 4624
    LogonType: 9
    LogonProcessName: 'seclogo'
    AuthenticationPackageName: 'Negotiate'
  condition: sel
level: high
tags: [attack.lateral_movement, attack.t1550.002]
```
```kql
// KQL — ayrıcalıklı hesabın NTLM ile kimlik doğrulaması (Kerberos beklenirken)
SecurityEvent
| where EventID == 4776
| where TargetAccount in ("DA01","DA02","adm_helpdesk")   // ayrıcalıklı liste
| summarize count() by TargetAccount, Workstation, bin(TimeGenerated, 1h)
```

| Saldırı | Ana Event | İmza | MITRE | Karşı önlem |
|---------|-----------|------|-------|-------------|
| Pass-the-Hash | 4624 T3 + 4776 | NTLM (Kerberos yerine) | T1550.002 | Protected Users, NTLM kısıtlama |
| Overpass-the-Hash | 4624 T9 | seclogo + Negotiate | T1550.002 | Protected Users (RC4/NTLM yok) |
| Pass-the-Ticket | 4624/4769 | bilet-makine uyumsuzluğu | T1550.003 | AES, kısa TGT ömrü |

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Kerberos ortamında NTLM'i görmezden gelmek:** Ayrıcalıklı hesapla NTLM (4776) neredeyse her zaman şüphelidir; "NTLM audit" ile baseline çıkar, sonra kısıtla.
- 🔴 **Sadece tespit, önlem yok:** PtH'nin gerçek çözümü Protected Users + LAPS + NTLM kısıtlamadır; tespit son savunma hattıdır.
- ⚠️ **LogonType 9'u meşru runas ile karıştırmak:** seclogo + Negotiate + NTLM üçlüsü ve **hesabın ayrıcalık düzeyi** ile meşru netonly'den ayır.
- ⚠️ **Makine hesabı NTLM'ini alarm sanmak:** Bazı eski servisler meşru NTLM kullanır; ayrıcalıklı *insan* hesaplarına odaklan.
- 🔍 **İzleme ipucu:** Aynı hesabın kısa sürede hem 4624 Type 9 (kaynak overpass) hem uzak makinede Type 3 üretmesi = tam PtH zinciri; iki olayı korele et.
