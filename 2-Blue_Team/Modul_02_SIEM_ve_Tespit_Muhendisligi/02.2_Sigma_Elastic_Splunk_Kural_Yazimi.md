## 1. Kavramsal Temel — Neden Var?

[02.1](./02.1_Kritik_Event_ID_Katalogu.md) "hangi olay saldırıyı ele verir"i belirledi. Ama her SIEM'in kendi sorgu dili vardır: Splunk **SPL**, Elastic **KQL/EQL**, Sentinel **KQL**, ArcSight kendi dili. Bir tespit fikrini her SIEM için ayrı ayrı yazmak sürdürülemez. **Sigma** bu sorunu çözer: SIEM-bağımsız, YAML tabanlı **taşınabilir tespit dili**. Bir kez Sigma'da yaz, `sigma-cli` ile Splunk/Elastic/Sentinel'e **çevir**.

Bu, tespit mühendisliğini **kod gibi** yönetmeyi (detection-as-code) mümkün kılar: Git'te versiyonla, PR ile gözden geçir, CI'da test et, dağıt. Kurumun tespit kütüphanesi (detection library) böyle büyür.

> **İlke:** Tespit taşınabilir olmalı. Fikir (Sigma) bir kez yazılır, hedefe (Splunk/Elastic) derlenir; SIEM değişse bile kütüphane yaşar.

Bu dosya, [02.1](./02.1_Kritik_Event_ID_Katalogu.md) kataloğunu **çalışan kurallara** dönüştürmenin mühendisliğidir; [02.4](./02.4_Atomic_Red_Team_ile_Dogrulama.md)'te bu kurallar test edilir.

## 2. Teknik Derinlik

### 2.1 Sigma kuralının anatomisi

```
  ┌──────────────────────── SIGMA YAML ────────────────────────┐
  │ title / id / status / level  → metadata + önem             │
  │ logsource: {product, service, category} → NEREDE arasın     │
  │ detection:                                                  │
  │   selection: { field: value }  → EŞLEŞME koşulu (AND)       │
  │   filter:    { field: value }  → HARİÇ tutma (yanlış-poz.)  │
  │   condition: selection and not filter → MANTIK              │
  │ fields / falsepositives / tags(MITRE) → bağlam              │
  └────────────────────────────────────────────────────────────┘
         │  sigma-cli convert -t splunk / -t elastic
         ▼
  index=windows EventCode=4769 Ticket_Encryption_Type=0x17 ...
```

### 2.2 Tespit olgunluğu piramidi (Pyramid of Pain)

Kural neyi yakaladıkça saldırgana daha çok "acı" verir:

```
        ▲ TTP (davranış: parent-child, LogonType 9)  ← en dayanıklı, en zor atlatılır
        │ Araç (Rubeus/mimikatz imzası)
        │ Ağ/host artefaktı (named pipe, servis adı)
        │ Domain adı
        │ IP adresi
        ▼ Hash değeri                                 ← saldırgan 1 sn'de değiştirir
```

**Kötü kural** hash/IP'ye bağlanır (kolayca kaçılır). **İyi kural** davranışa (TTP) bağlanır: "RC4 + servis hesabı + hacim" — saldırganın protokolü değiştirmesi gerekir.

### 2.3 Yanlış-pozitif mühendisliği

Bir kural iki yönde başarısız olur: **kaçırma** (false negative — saldırı görünmez) ve **gürültü** (false positive — analist körelir). Denge, `filter` blokları (meşru servis hesapları, tarama sunucuları) ve **eşikleme** (thresholding) ile kurulur. Ölçüt: kuralın **precision** (doğru alarm oranı) ve **recall** (yakalama oranı) değeri izlenmeli.

## 3. Pratik Uygulama — Aynı Tespit, Üç Dil

### 3.1 Sigma (kaynak / taşınabilir)
```yaml
title: Sup­heli Servis Kurulumu (Yanal Hareket)
id: 5a2f1c00-blue-4d02-svc7-installer0001
status: stable
logsource: { product: windows, service: system }
detection:
  selection: { EventID: 7045 }                    # yeni servis kuruldu
  suspicious:
    ServiceFileName|contains: ['\\ADMIN$\\','powershell','cmd /c','%COMSPEC%']
  condition: selection and suspicious
level: high
tags: [attack.lateral_movement, attack.t1021.002, attack.t1569.002]
falsepositives: [ 'Mesru yazilim dagitimi (SCCM) - beyaz listeye al' ]
```

### 3.2 Splunk (SPL — çevrilmiş)
```
index=windows sourcetype=WinEventLog:System EventCode=7045
| where match(Service_File_Name, "(?i)ADMIN\$|powershell|cmd /c|%COMSPEC%")
| stats count min(_time) as first by ComputerName, Service_Name, Service_File_Name
```

### 3.3 Elastic (KQL / EQL)
```
event.code:"7045" and winlog.event_data.ServiceFileName:(*ADMIN$* or *powershell* or *cmd*)
```
```eql
/* EQL — davranışsal: PsExec named pipe + servis */
sequence by host.name with maxspan=1m
  [ process where process.name == "PSEXESVC.exe" ]
  [ network where destination.port == 445 ]
```

### 3.4 Kural yönetimi (detection-as-code)
```bash
# Sigma kütüphanesini hedef SIEM'e derle
sigma convert -t splunk -p sysmon rules/lateral_movement/ > splunk_rules.txt
sigma convert -t elasticsearch -p ecs_windows rules/ -o elastic/
# CI: her PR'da kural sözdizimi + Atomic testiyle doğrula (02.4)
```

## 4. Tespit Değeri — Kural Kalite Metrikleri

```yaml
# Sigma — Overpass-the-Hash (LogonType 9 + explicit cred)
title: Overpass-the-Hash Belirtisi (Type 9 Logon)
logsource: { product: windows, service: security }
detection:
  sel: { EventID: 4624, LogonType: 9, LogonProcessName: 'seclogo' }
  condition: sel
level: high
tags: [attack.lateral_movement, attack.t1550.002]
```

| Kural özelliği | Kötü (kırılgan) | İyi (dayanıklı — TTP) |
|----------------|-----------------|------------------------|
| Bağlanma noktası | Rubeus.exe hash'i | LogonType 9 + davranış |
| Atlatma maliyeti | Saniyeler (yeniden derle) | Yüksek (protokol değişimi) |
| Yanlış-pozitif | Yüksek (isim değişir) | Düşük (filter ile) |
| MITRE eşlemesi | Yok | T-numarası + Atomic test |

## 5. Doğrulama / Lab (Atomic + CI)

```powershell
# Kuralı üreten tekniği Atomic ile tetikle → kural yakalıyor mu?
Invoke-AtomicTest T1021.002 -TestNumbers 1   # PsExec → 7045/Sysmon
Invoke-AtomicTest T1550.002 -TestNumbers 1   # PtH → 4624 Type 9
# Beklenen: §3/§4 Sigma kuralları SIEM'de alarm üretir.
# CI pipeline: sigma test → tetikle → alarm say → precision/recall raporla
```
> Yazılıp **test edilmemiş kural** güvenlik tiyatrosudur. Her kural, karşılık gelen MITRE tekniğinin [Atomic testiyle](./02.4_Atomic_Red_Team_ile_Dogrulama.md) doğrulanır.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Hash/IP'ye kural bağlamak:** Pyramid of Pain'in dibi; saldırgan saniyede değiştirir. Davranışa (TTP) bağlan.
- 🔴 **Kuralı üretime test etmeden koymak:** Kaçıran (false negative) kural, olmayandan beterdir — sahte güven verir. [02.4](./02.4_Atomic_Red_Team_ile_Dogrulama.md) ile doğrula.
- ⚠️ **Yanlış-pozitifi yönetmemek:** Gürültülü kural analisti köreltir (alert fatigue); `filter` + eşikleme + tuning şart.
- ⚠️ **`logsource`/`category` yanlış eşlemek:** Kural doğru ama yanlış indekste arıyorsa hiç tetiklenmez; alan eşlemesini (ECS/ASIM) doğrula.
- 🔍 **İzleme ipucu:** Tespit kütüphanesini Git'te tut; her kuralın MITRE T-no, falsepositive notu ve son test tarihi olsun — "kör kural" bırakma.
