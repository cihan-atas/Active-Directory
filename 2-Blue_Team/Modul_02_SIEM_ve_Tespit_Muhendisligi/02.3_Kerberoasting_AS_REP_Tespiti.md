## 1. Kavramsal Temel — Neden Var?

Kerberos, kimliği doğrulanmış her kullanıcının **herhangi bir servis için bilet (TGS) isteyebilmesine** izin verir — ve bu bilet, servis hesabının parola hash'iyle (NTLM/RC4 veya AES) **şifrelenir**. Saldırgan bu bileti çevrimdışı kırarak servis hesabının parolasını ele geçirir: **Kerberoasting**. Kardeş teknik **AS-REP Roasting**, "Kerberos pre-authentication gerektirmeyen" hesaplara TGT isteyip yanıtı çevrimdışı kırar.

İkisi de **meşru Kerberos trafiği** gibi görünür — bu yüzden tespiti bir "kötü olay" aramak değil, **anomali** aramaktır: yanlış şifreleme türü (RC4), tek kaynaktan çok sayıda SPN isteği, pre-auth kapalı hesaplar. Bu, [Sistem 03.4 gMSA](../../1-Sistem_Yoneticisi/Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md)'nın neden var olduğunu (kırılamaz 240-bit parola) savunma tarafından açıklar.

> **İlke:** Kerberoasting görünür bir saldırı değil, **görünmez bir sapmadır.** RC4 + hacim + hesap-tipi üçlüsü onu ele verir.

## 2. Teknik Derinlik

### 2.1 Kerberoasting protokol akışı ve tespit noktası

```
  Saldırgan (herhangi domain kullanıcısı)              DC (KDC)
     │  ① TGS-REQ: "MSSQLSvc/db01 için bilet"            │
     │─────────────────────────────────────────────────►│  → EVENT 4769
     │                                                   │    Service Name: MSSQLSvc/db01
     │  ② TGS-REP: servis hesabı hash'iyle şifreli bilet │    Encryption Type: 0x17 (RC4!)  ◄── SİNYAL
     │◄─────────────────────────────────────────────────│    Client: normaluser
     │  ③ Bileti çevrimdışı kır (hashcat -m 13100)       │
     │     ► servis hesabı parolası ELE GEÇTİ            │  (bu adım DC'de İZ BIRAKMAZ!)
```

**Kritik içgörü:** Kırma adımı (③) çevrimdışıdır, **hiç iz bırakmaz**. Tespit **yalnızca ① ②** anında, yani **4769**'da mümkündür. Bu yüzden 4769 denetimi ([Blue 01.2](../Modul_01_Gorunurluk_ve_Log_Yonetimi/01.2_Advanced_Audit_Policy.md)) kapalıysa Kerberoasting **tamamen görünmezdir**.

### 2.2 RC4 neden sinyal?

Modern Windows AES (0x11/0x12) kullanır. Saldırgan **bilerek RC4 (0x17)** ister çünkü RC4 hash'i çok daha hızlı kırılır (`hashcat -m 13100`). Dolayısıyla **RC4'lü 4769**, hesabın AES desteklemediği eski servisler dışında, güçlü bir "downgrade" sinyalidir.

### 2.3 AS-REP Roasting'in ayrımı

| | Kerberoasting | AS-REP Roasting |
|--|---------------|-----------------|
| Hedef | SPN'li servis hesapları | `DONT_REQ_PREAUTH` bayraklı hesaplar |
| Olay | **4769** (TGS) | **4768** (AS-REQ/REP) |
| Sinyal | EncType 0x17 (RC4) | PreAuthType **0** |
| Ön koşul | Herhangi domain kullanıcısı | Kimlik doğrulama bile gerekmez |
| hashcat modu | 13100 | 18200 |

## 3. Pratik Uygulama

### 3.1 Kerberoast avı (Get-WinEvent)
```powershell
# RC4 şifrelemeli, krbtgt/makine-hesabı olmayan TGS istekleri (son 6 saat)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4769;
  StartTime=(Get-Date).AddHours(-6)} |
  Where-Object { $_.Message -match 'Encryption Type:\s+0x17' -and
                 $_.Message -notmatch 'Service Name:\s+krbtgt' -and
                 $_.Message -notmatch 'Service Name:\s+\w+\$' } |
  ForEach-Object {
    [pscustomobject]@{
      Zaman  = $_.TimeCreated
      Client = ($_.Message -split 'Account Name:\s+')[1].Split("`n")[0]
      SPN    = ($_.Message -split 'Service Name:\s+')[1].Split("`n")[0]
    }
  } | Group-Object Client | Where-Object Count -ge 5   # tek kullanıcı çok SPN = alarm
```

### 3.2 Kerberoast'a açık hesap envanteri (proaktif)
```powershell
# SPN'li kullanıcı hesapları = potansiyel kurban → gMSA'ya taşı
Get-ADUser -Filter {ServicePrincipalName -like '*'} -Properties ServicePrincipalName,PasswordLastSet,msDS-SupportedEncryptionTypes |
  Select Name, PasswordLastSet, ServicePrincipalName
# AS-REP'e açık hesaplar (pre-auth kapalı)
Get-ADUser -Filter {DoesNotRequirePreAuth -eq $true} -Properties DoesNotRequirePreAuth
```

## 4. Tespit Değeri — Sigma / KQL

```yaml
# Sigma — Kerberoasting (RC4 downgrade + hacim davranışı)
title: Kerberoasting - RC4 TGS Istekleri
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: 4769
    TicketEncryptionType: '0x17'         # RC4
    TicketOptions: '0x40810000'
  filter:
    ServiceName|endswith: '$'            # makine hesapları hariç
  condition: sel and not filter
level: high
tags: [attack.credential_access, attack.t1558.003]
```
```kql
// KQL (Sentinel) — bir hesabın kısa sürede çok SPN'e RC4 TGS istemesi
SecurityEvent
| where EventID == 4769 and TicketEncryptionType == "0x17"
| where ServiceName !endswith "$" and ServiceName != "krbtgt"
| summarize SPNs=dcount(ServiceName), by Account, bin(TimeGenerated, 10m)
| where SPNs >= 5     // 10 dk'da 5+ farklı servis = Kerberoast davranışı
```

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **4769 denetimini kapalı bırakmak:** Kırma adımı iz bırakmaz; tek tespit anı 4769'dur. Kapalıysa Kerberoasting %100 görünmez.
- 🔴 **Sadece tespit edip önlem almamak:** Gerçek çözüm SPN'li hesapları gMSA'ya taşımak + RC4 kapatmak; tespit yalnızca "geç kalmış alarmdır".
- ⚠️ **RC4'ü tümden sinyal saymak:** Bazı eski servisler meşru RC4 kullanır; hesap bazlı beyaz liste + hacim/hesap-tipi korelasyonu ekle.
- ⚠️ **AS-REP'i unutmak:** `DoesNotRequirePreAuth` hesapları düzenli envanterle; genelde eski/yanlış yapılandırılmış hesaplardır.
- 🔍 **İzleme ipucu:** Tek `normaluser`'ın 10 dakikada 20 farklı SPN'e RC4 TGS istemesi, meşru kullanımda neredeyse hiç görülmez — bu davranışsal eşik en güvenilir sinyaldir.
