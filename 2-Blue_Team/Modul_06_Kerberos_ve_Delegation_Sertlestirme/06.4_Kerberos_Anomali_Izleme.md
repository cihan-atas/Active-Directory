## 1. Kavramsal Temel — Neden Var?

Sertleştirme ([06.1](./06.1_Delegation_Envanteri_ve_Temizligi.md)–[06.3](./06.3_AES_Zorlama_RC4_ve_PAC.md)) saldırı yüzeyini **daraltır**; ama hiçbir sertleştirme mükemmel değildir. Kerberos'un kalan riskleri — Golden Ticket (forge TGT), Silver Ticket (forge TGS), Overpass-the-Hash, kalan RC4 kullanımı — **davranışsal anomali** ile yakalanmalıdır. Bu dosya, Kerberos protokol olaylarını (4768/4769/4770/4771) **bir bütün olarak** okuyup "normal Kerberos trafiği" ile "forge/abuse" arasındaki farkı görmeye adanmıştır.

Kerberos anomali izleme özellikle **Golden Ticket** için kritiktir: krbtgt hash'ini ele geçiren saldırgan ([Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/)) istediği kullanıcı/grup için **geçerli görünen** bir TGT üretir — KDC'yi hiç görmeden. Bu bilet "mükemmel" olduğundan, tespit ancak **tutarsızlıkları** aramakla mümkündür: var olmayan bir hesap için bilet, anormal bilet ömrü, TGS isteği olan ama TGT logu olmayan oturumlar.

> **İlke:** Sertleştirme yüzeyi daraltır; anomali izleme kalan boşlukları kapatır. Golden Ticket "mükemmel" görünür — onu tutarsızlıklardan (var olmayan hesap, anormal ömür, eksik TGT) yakalarsın.

Bu, [Blue M02 tespit mühendisliği](../Modul_02_SIEM_ve_Tespit_Muhendisligi/)'nin Kerberos'a özgü derinleşmesidir ve [Blue M10 IR](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/)'a (krbtgt reset) besleme yapar.

## 2. Teknik Derinlik

### 2.1 Kerberos olay akışı ve normal desen

```
   Kullanıcı oturumu (normal):
   4768 (AS-REQ: TGT al) ──► 4769 (TGS-REQ: servis bileti) ──► servise erişim
      │ bir kez, oturum başında        │ her yeni servise
      ▼                                 ▼
   Golden Ticket (anomali):     Silver Ticket (anomali):
   TGT FORGE edilir → 4768 YOK  TGS FORGE edilir → 4769 KDC'de YOK
   ama 4769'lar var (TGT'siz    ama servise erişim var
   TGS = tutarsızlık!)          (KDC bypass)
```

### 2.2 Golden/Silver Ticket'ın izleri

- **Golden Ticket:** Forge TGT, KDC'yi atlar → **4768 (TGT) logu olmadan** 4769 (TGS) istekleri; anormal uzun bilet ömrü (mimikatz varsayılan 10 yıl); var olmayan/devre dışı hesap için bilet; RC4 (0x17) ile forge (klasik mimikatz).
- **Silver Ticket:** Forge TGS, sadece hedef servisi hedefler → hedefte erişim var ama DC'de **karşılık gelen 4769 yok**; PAC doğrulama devre dışıysa daha kolay.

### 2.3 krbtgt ve "iki kez reset" bağlantısı

Golden Ticket krbtgt hash'ine dayanır. Tespit edildiğinde tek çözüm krbtgt parolasını **iki kez** (art arda değil, replikasyon bekleyerek) sıfırlamaktır → mevcut tüm Golden Ticket'lar geçersizleşir ([Blue M10](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/)). Anomali izleme bu IR'ı **tetikleyen** erken uyarıdır.

## 3. Pratik Uygulama

### 3.1 Golden Ticket avı: TGT'siz TGS (tutarsızlık)
```powershell
# Bir hesap için 4769 (TGS) var ama son X saatte 4768 (TGT) YOK → Golden şüphesi
$since = (Get-Date).AddHours(-10)
$tgs = Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4769; StartTime=$since} |
       ForEach-Object { ($_.Message -split 'Account Name:\s+')[1].Split("`n")[0].Trim() } | Sort -Unique
$tgt = Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4768; StartTime=$since} |
       ForEach-Object { ($_.Message -split 'Account Name:\s+')[1].Split("`n")[0].Trim() } | Sort -Unique
$tgs | Where-Object { $_ -notin $tgt -and $_ -notmatch '\$$' }   # TGT'siz TGS = anomali
```

### 3.2 Anormal bilet ömrü / var olmayan hesap
```powershell
# Var olmayan/devre dışı hesap için Kerberos bileti (Golden forge izi)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4769} |
  ForEach-Object {
    $acct = ($_.Message -split 'Account Name:\s+')[1].Split("`n")[0].Trim()
    if (-not (Get-ADUser -Filter "SamAccountName -eq '$acct'" -EA SilentlyContinue) -and $acct -notmatch '\$$') {
      [pscustomobject]@{ Zaman=$_.TimeCreated; Hesap=$acct; Not='AD''de yok!' } } }
```

## 4. Tespit Değeri — Sigma / KQL

```yaml
# Sigma — Golden Ticket belirtisi: encryption downgrade + anormal bilet
title: Golden Ticket Belirtisi (RC4 forge / tutarsiz TGT-TGS)
logsource: { product: windows, service: security }
detection:
  rc4_tgt:
    EventID: 4768
    TicketEncryptionType: '0x17'      # mimikatz klasik RC4 forge
  weird_account:
    EventID: 4769
    TargetUserName|re: '.*'           # korelasyon: AD'de olmayan hesap (§3.2)
  condition: rc4_tgt
level: high
tags: [attack.credential_access, attack.t1558.001, attack.t1558.002]
```
```kql
// KQL — TGT'siz TGS (Golden) ve anormal bilet ömrü
SecurityEvent
| where EventID == 4769
| join kind=leftanti (SecurityEvent | where EventID==4768 | project Account) on Account
| where Account !endswith "$"     // TGT logu olmadan servis bileti = KDC bypass
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| TGT'siz TGS (4769, 4768 yok) | 4769 | Golden Ticket (KDC bypass) | T1558.001 |
| Var olmayan hesap için bilet | 4769 | Forge PAC | T1558.001 |
| Anormal uzun bilet ömrü | 4768/4769 | mimikatz varsayılan | T1558.001 |
| Servis erişimi, DC'de 4769 yok | 4624/servis | Silver Ticket | T1558.002 |
| Kalan RC4 forge (0x17) | 4768 | Klasik Golden | T1558.001 |

## 5. Doğrulama / Lab

```powershell
# 1) Golden Ticket tespitini doğrula (izole lab): forge bir TGT ile servise eriş
Invoke-AtomicTest T1558.001 -TestNumbers 1   # Golden → TGT'siz TGS / RC4 forge
# → §4 "TGT'siz TGS" ve "AD'de olmayan hesap" kuralları alarm vermeli
# 2) Silver Ticket: T1558.002 → DC'de 4769 olmadan servis erişimi
Invoke-AtomicTest T1558.002 -TestNumbers 1
# 3) IR bağlantısı: tespit sonrası krbtgt 2x reset prosedürünü (Blue M10) test et
```
> **Kanıt:** Golden Ticket "geçerli" görünür; tespit tutarsızlıkla (TGT'siz TGS, var olmayan hesap) yapılır. Doğrulama, forge bileti üretip kuralın onu tutarsızlıktan yakaladığını göstermektir.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Sadece sertleştirmeye güvenmek:** AES/RC4 kapatma yüzeyi daraltır ama Golden/Silver'ı tümden engellemez; anomali izleme şart.
- 🔴 **4768 denetimini kapalı bırakmak:** "TGT'siz TGS" tespiti hem 4768 hem 4769 gerektirir; biri kapalıysa Golden görünmez ([Blue 01.2](../Modul_01_Gorunurluk_ve_Log_Yonetimi/01.2_Advanced_Audit_Policy.md)).
- ⚠️ **Makine hesaplarını ($) filtrelememek:** Makine hesapları meşru olarak farklı desenler üretir; anomali kurallarında `$` hesaplarını ayır.
- ⚠️ **Tespit sonrası krbtgt'yi bir kez resetlemek:** Golden'ı geçersizleştirmek için **iki kez** (replikasyon bekleyerek) reset gerekir → [Blue M10](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/).
- 🔍 **İzleme ipucu:** AD'de var olmayan bir hesap adına düzenlenmiş **tek bir** 4769, neredeyse kesin bir forge (Golden) işaretidir — kritik alarm + IR tetikle.
