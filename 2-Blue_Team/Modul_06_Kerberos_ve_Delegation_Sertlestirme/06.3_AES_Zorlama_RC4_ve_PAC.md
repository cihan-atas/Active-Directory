## 1. Kavramsal Temel — Neden Var?

Kerberos'un güvenliği kullandığı **şifreleme algoritmasına** bağlıdır. Eski **RC4-HMAC (etype 0x17)**, kullanıcının NTLM hash'ini doğrudan anahtar olarak kullanır ve **çok hızlı kırılır** — Kerberoasting ([Blue 02.3](../Modul_02_SIEM_ve_Tespit_Muhendisligi/02.3_Kerberoasting_AS_REP_Tespiti.md)) tam olarak bunu sömürür. **AES (etype 0x11/0x12)** ise tuzlanmış (salted), yavaş türetilen bir anahtar kullanır; kırılması pratikte imkânsızdır. Dolayısıyla **RC4'ü devre dışı bırakıp AES'i zorlamak**, Kerberoasting'in ve birçok Kerberos saldırısının etkinliğini kökten düşürür.

İkinci koruma **PAC (Privilege Attribute Certificate) doğrulamasıdır**. PAC, Kerberos biletinin içinde kullanıcının **grup üyeliklerini/SID'lerini** taşır. Saldırganlar bileti forge edip ([Golden/Silver Ticket](../Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/)) PAC'a sahte yetki yazar. Microsoft'un PAC güçlendirmeleri (KB5008380, KB5020805 — güçlü sertifika/PAC imza doğrulama) bu forge'u zorlaştırır.

> **İlke:** Zayıf şifreleme (RC4) = kırılabilir bilet; forge edilebilir PAC = sahte yetki. AES zorla, RC4'ü kapat, PAC imzasını doğrula — Kerberos'un temelini sağlamlaştır.

Bu, [Sistem 03.4 gMSA](../../1-Sistem_Yoneticisi/Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md) (AES destekli, kırılamaz servis parolası) ve [Sistem 10.3 Hardening](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.3_Hardening_Temelleri.md)'in Kerberos katmanının derinleştirilmesidir.

## 2. Teknik Derinlik

### 2.1 Şifreleme türleri (etype) ve risk

```
   etype   Algoritma        Kırılabilirlik           Durum
   ─────   ─────────        ──────────────           ─────
   0x01/03 DES              trivial                  YASAK (devre dışı olmalı)
   0x17    RC4-HMAC         hızlı (hashcat 13100)    KAPAT (Kerberoast yakıtı)
   0x11    AES128-CTS       pratikte imkânsız        ✅ kabul
   0x12    AES256-CTS       pratikte imkânsız        ✅ tercih
```

### 2.2 msDS-SupportedEncryptionTypes mekaniği

Her hesabın `msDS-SupportedEncryptionTypes` özniteliği, KDC'nin o hesap için hangi etype'ı kullanacağını belirler. Değer bit maskesidir: AES128=0x8, AES256=0x10, RC4=0x4. `0x18` (24) = yalnızca AES128+AES256. Bu öznitelik boşsa veya RC4 içeriyorsa, saldırgan **RC4 downgrade** yapabilir (bilerek zayıf bilet ister). Bu yüzden hesaplarda **RC4 bitini temizlemek** kritiktir.

### 2.3 PAC doğrulama ve sertifika eşleme sertleştirmesi

Silver/Golden Ticket, forge edilmiş PAC ile sahte grup üyeliği enjekte eder. Microsoft'un PAC güçlendirmeleri (KB5008380 "Enforcement", KB5020805) KDC'nin PAC imzasını daha katı doğrulamasını sağlar. Ayrıca sertifika tabanlı kimlikte **güçlü eşleme (strong mapping)** zorunluluğu (KB5014754 → [Blue M07](../Modul_07_AD_CS_PKI_Guvenligi/)) sahte sertifika ile bilet almayı engeller.

## 3. Pratik Uygulama

### 3.1 RC4 kullanan hesapları bul
```powershell
# RC4'e izin veren veya etype belirsiz hesaplar (downgrade riski)
Get-ADObject -LDAPFilter "(|(msDS-SupportedEncryptionTypes=4)(!(msDS-SupportedEncryptionTypes=*)))" `
  -Properties msDS-SupportedEncryptionTypes, samAccountName |
  Select samAccountName, msDS-SupportedEncryptionTypes
```

### 3.2 AES'i zorla (hesap + domain düzeyi)
```powershell
# Bir hesabı yalnızca AES128+AES256 yap (0x18 = 24)
Set-ADUser "svc_sql" -Replace @{'msDS-SupportedEncryptionTypes'=24}
```
```text
GPO (domain geneli): Computer Config → Windows Settings → Security Settings →
   Local Policies → Security Options →
   "Network security: Configure encryption types allowed for Kerberos"
     ✓ AES128_HMAC_SHA1  ✓ AES256_HMAC_SHA1   ✗ RC4_HMAC_MD5  ✗ DES
→ DİKKAT: hesapların AES anahtarı üretilmiş olmalı (parola değişimi sonrası);
  yoksa auth kırılır. Önce AES key üretilmesini sağla (parola reset), sonra RC4 kapat.
```

### 3.3 PAC/sertifika sertleştirmesi uygula
```powershell
# PAC enforcement ve strong mapping ile ilgili KB'lerin kurulu/enforce olduğunu doğrula
# KB5008380 (PAC), KB5014754 (cert strong mapping) → registry enforcement modu
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\Kdc" -Name PacRequestorEnforcement -EA SilentlyContinue
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\Kerberos\Parameters" -EA SilentlyContinue
```

## 4. Tespit Değeri — RC4 Downgrade ve Zayıf etype

```yaml
# Sigma — RC4 downgrade (AES yeteneği olan hesaba RC4 bilet isteği)
title: Kerberos RC4 Downgrade (Kerberoast/Golden Belirtisi)
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: [4768, 4769]
    TicketEncryptionType: '0x17'      # RC4
  filter:
    ServiceName|endswith: '$'         # bazı makine hesapları meşru
  condition: sel and not filter
level: medium
tags: [attack.credential_access, attack.t1558.003]
```
```powershell
# Get-WinEvent — AES beklerken RC4 (0x17) gören bilet istekleri
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4769} |
  Where-Object { $_.Message -match 'Ticket Encryption Type:\s+0x17' } |
  Group-Object { ($_.Message -split 'Account Name:\s+')[1].Split("`n")[0] }
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| RC4 (0x17) TGS/TGT | 4768/4769 | Downgrade / Kerberoast | T1558.003 |
| DES (0x01/0x03) kullanımı | 4768/4769 | Yasak zayıf şifreleme | T1558 |
| `msDS-SupportedEncryptionTypes` değişimi | 5136 | etype gevşetme (RC4 geri açma) | T1484 |
| PAC doğrulama hatası | KDC log | Bilet forge denemesi | T1558.001 |

## 5. Doğrulama / Lab

```powershell
# 1) Envanter: RC4'e izin veren hesap sayısı → hedef minimum (kritik hesaplar 0)
# 2) AES zorlaması testi (izole lab): svc_sql etype=24 iken RC4 TGS istenirse
#    KDC RC4 VERMEMELİ (AES döner) → Kerberoast RC4 hash'i alınamaz
Invoke-AtomicTest T1558.003 -TestNumbers 1   # Kerberoast → RC4 kapalıysa AES bilet (kırılamaz)
# 3) PAC testi: KB enforcement modunun aktif olduğunu registry'den doğrula (§3.3)
```
> **Kanıt:** AES zorlanınca aynı Kerberoast denemesi RC4 yerine AES bilet döner — hashcat pratikte kıramaz. RC4 sayısını sıfıra indirmek Kerberoasting'i etkisizleştirir.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **RC4'ü AES anahtarı üretmeden kapatmak:** Hesabın AES anahtarı yoksa (parola RC4 döneminden kalmışsa) kimlik doğrulama kırılır; önce parola reset/AES key üretimi, sonra RC4 kapatma.
- 🔴 **`msDS-SupportedEncryptionTypes` boş bırakmak:** Boş = downgrade'e açık; kritik hesaplarda açıkça 0x18 (yalnız AES) ayarla.
- ⚠️ **DES'i unutmak:** Nadir ama bazı eski hesaplarda DES açık kalabilir; tümden yasakla.
- ⚠️ **PAC/strong mapping KB'lerini enforce etmemek:** "Compatibility" modunda bırakılan enforcement, forge/sahte sertifika saldırılarına kapı açar; enforcement moduna geç.
- 🔍 **İzleme ipucu:** AES yeteneği olan bir hesaba gelen **RC4 (0x17)** bilet isteği, meşru senaryoda azdır ve çoğu zaman downgrade/Kerberoast girişimidir → [Blue 02.3](../Modul_02_SIEM_ve_Tespit_Muhendisligi/02.3_Kerberoasting_AS_REP_Tespiti.md).
