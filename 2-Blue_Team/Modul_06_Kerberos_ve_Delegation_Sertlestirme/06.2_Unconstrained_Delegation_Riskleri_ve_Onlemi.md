## 1. Kavramsal Temel — Neden Var?

Unconstrained delegation, delegation türleri içinde ([06.1](./06.1_Delegation_Envanteri_ve_Temizligi.md)) **en tehlikelisidir** ve kendi başına derin bir inceleme hak eder. Mekanizması basit ama yıkıcıdır: unconstrained delegation'a sahip bir sunucuya kimlik doğrulaması yapan **her kullanıcının TGT'si (Ticket Granting Ticket)**, o sunucunun belleğinde saklanır — çünkü sunucu "kullanıcı adına her yere gidebilmek" için tam bileti taşır. Saldırgan o sunucuyu ele geçirirse, bellekteki tüm TGT'leri toplar ve o kullanıcılara **tam olarak bürünür.**

Asıl tehlike, bunun **koersiyon (coercion)** ile birleşmesidir: saldırgan, unconstrained sunucuyu ele geçirdikten sonra bir **DC'yi** (PrinterBug/PetitPotam ile → [Blue M08](../Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/)) bu sunucuya kimlik doğrulaması yapmaya **zorlar**. DC'nin makine hesabı TGT'si sunucuya düşer; saldırgan onunla DCSync yapıp domain'i ele geçirir. Bu, "tek unconstrained sunucu → tüm domain" zinciridir.

> **İlke:** Unconstrained delegation, "bana bağlanan herkesin ana anahtarını bende bırak" demektir. Koersiyonla birleşince tek sunucu tüm domain'i düşürür. Bu yüzden ideal hedef: **DC dışında sıfır unconstrained.**

## 2. Teknik Derinlik

### 2.1 Saldırı zinciri (unconstrained + koersiyon)

```
  ① Saldırgan unconstrained sunucu SRV1'i ele geçirir (yerel admin)
        │
  ② Rubeus monitor: SRV1 belleğine düşen TGT'leri dinler
        │
  ③ PetitPotam/PrinterBug ile DC01'i SRV1'e auth olmaya ZORLAR (coercion)
        │            └────► [Blue M08 relay/coercion önleme]
  ④ DC01$ makine hesabının TGT'si SRV1 belleğine düşer
        │
  ⑤ Saldırgan DC01$ TGT'siyle DCSync → krbtgt hash → Golden Ticket
        │
  ⑥ DOMAIN HAKİMİYETİ  ([Red M09])
```

### 2.2 Neden constrained/RBCD daha güvenli?

Constrained delegation yalnızca **belirli SPN'lere** bürünmeye izin verir (`msDS-AllowedToDelegateTo`); TGT tam olarak saklanmaz, sınırlı S4U biletleri kullanılır. RBCD ise kontrolü **kaynak tarafına** verir. İkisi de "her yere bürünme" yeteneğini ortadan kaldırır — bu yüzden unconstrained'dan bunlara geçiş temel sertleştirmedir.

### 2.3 "Sensitive, cannot be delegated" ve Protected Users

Bir hesap `NOT_DELEGATED` (0x100000) bayrağı taşırsa (`AccountNotDelegated $true`), TGT'si **hiçbir** delegation sunucusunda saklanmaz — unconstrained sunucuya bağlansa bile bileti düşmez. [Protected Users](../Modul_03_Kimlik_Bilgisi_Korumasi/03.3_Protected_Users_ve_Authentication_Policies.md) üyeleri bunu otomatik alır. Tier 0 için zorunludur.

## 3. Pratik Uygulama

### 3.1 Unconstrained sunucuları bul ve dönüştür
```powershell
# TÜM unconstrained hesapları listele (DC'ler beklenen; gerisi bulgu)
Get-ADComputer -LDAPFilter "(userAccountControl:1.2.840.113556.1.4.803:=524288)" `
  -Properties TrustedForDelegation, OperatingSystem |
  Select Name, OperatingSystem, TrustedForDelegation
# Bulunan bir sunucuyu constrained'a çevir
Set-ADAccountControl "SRV1$" -TrustedForDelegation $false
Set-ADComputer "SRV1$" -Add @{'msDS-AllowedToDelegateTo'='HTTP/backend.corp.local'}
```

### 3.2 Tier 0 hesaplarını koru (delegation'dan muaf)
```powershell
# Tüm ayrıcalıklı hesapları "cannot be delegated" yap
Get-ADGroupMember "Domain Admins" | ForEach-Object {
  Set-ADAccountControl -Identity $_.SamAccountName -AccountNotDelegated $true }
# + Protected Users'a ekle (otomatik uygular)
```

### 3.3 Koersiyon yüzeyini kapat (birlikte savunma)
```text
Unconstrained önlemi tek başına yetmez — koersiyonu da kapat:
- PetitPotam/PrinterBug yamaları + EPA + SMB signing → [Blue M08]
- Print Spooler'ı DC'lerde durdur
- RPC filtreleme (MS-EFSRPC / MS-RPRN kısıtlama)
```

## 4. Tespit Değeri — TGT Hasadı ve Koersiyon İzleri

```yaml
# Sigma — Unconstrained sunucuya DC/ayrıcalıklı hesap kimlik doğrulaması (TGT exposure)
title: Unconstrained Sunucuya Ayricalikli Kerberos Auth
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: 4768          # TGT istendi
    TargetUserName|endswith: '$'      # makine hesabı (DC dahil)
  condition: sel
  # korelasyon: unconstrained sunucu envanteri (§3.1) ile eşleştir
level: high
tags: [attack.credential_access, attack.t1558, attack.t1187]
```
```powershell
# Get-WinEvent — koersiyon izi: DC'ye beklenmedik EFSRPC/RPRN çağrısı + sonrasında
# unconstrained sunucuya 4624 makine oturumu (korele et)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} |
  Where-Object { $_.Message -match 'Account Name:\s+DC0\d\$' -and $_.Message -match 'Logon Type:\s+3' }
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| DC makine hesabı unconstrained sunucuda | 4624/4768 | TGT hasadı hazırlığı | T1558 |
| PetitPotam/PrinterBug çağrısı | (ağ/EDR) | Koersiyon tetikleme | T1187 |
| Yeni `TRUSTED_FOR_DELEGATION` | 5136/4738 | Unconstrained ekleme | T1558 |
| DCSync unconstrained sonrası | 4662 | Domain hakimiyeti | T1003.006 |

## 5. Doğrulama / Lab

```powershell
# 1) Envanter kanıtı: DC dışı unconstrained = 0 (§3.1 sorgusu boş dönmeli)
# 2) Koruma testi (izole lab): Tier 0 hesabı AccountNotDelegated iken unconstrained
#    sunucuya bağlan → Rubeus monitor TGT YAKALAYAMAMALI (bilet düşmez)
Invoke-AtomicTest T1558 -TestNumbers 1     # delegation abuse → §4 alarm
# 3) Koersiyon testi: DC'de PrinterBug/PetitPotam yaması + spooler kapalı → çağrı reddedilmeli
```
> **Kanıt:** İki katmanlı — (a) DC dışı unconstrained sıfır, (b) Tier 0 hesapları `AccountNotDelegated`. İkisi birlikte "tek sunucu → domain" zincirini kırar; koersiyon önlemi ([Blue M08](../Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/)) zinciri tamamen keser.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Unconstrained'ı "eski ama çalışıyor" diye bırakmak:** Tek ele geçmiş unconstrained sunucu + koersiyon = domain düşer; constrained/RBCD'ye geçiş önceliklidir.
- 🔴 **Tier 0'ı korumasız bırakmak:** DA'lar `AccountNotDelegated` değilse, bir unconstrained sunucuya uğradıklarında TGT'leri toplanır.
- ⚠️ **Sadece delegation'a odaklanıp koersiyonu unutmak:** Zincir iki uçludur; PetitPotam/PrinterBug önlemi ([Blue M08](../Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/)) olmadan savunma yarım kalır.
- ⚠️ **Print Spooler'ı DC'de açık bırakmak:** PrinterBug koersiyonunun aracıdır; DC'lerde Spooler durdurulmalı.
- 🔍 **İzleme ipucu:** Bir DC'nin makine hesabının (`DC01$`) beklenmedik bir üye sunucuda 4624/4768 üretmesi, koersiyon+TGT hasadı zincirinin güçlü işaretidir — kritik alarm.
