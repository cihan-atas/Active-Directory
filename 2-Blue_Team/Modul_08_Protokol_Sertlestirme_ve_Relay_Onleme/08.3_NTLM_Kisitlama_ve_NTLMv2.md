## 1. Kavramsal Temel — Neden Var?

Signing ([08.1](./08.1_LDAP_Signing_ve_Channel_Binding.md)/[08.2](./08.2_SMB_Signing_Zorlama.md)) relay'i **belirli protokollerde** durdurur; ama en köklü çözüm, **NTLM'i baştan kullanmamaktır**. NTLM, Kerberos'tan önceki nesil bir kimlik doğrulama protokolüdür ve yapısal zaaflar taşır: challenge-response tasarımı **relay'e** açıktır, **NTLMv1** kolayca kırılır (DES tabanlı), ve Pass-the-Hash ([Blue 04.2](../Modul_04_Yanal_Hareket_Tespiti/04.2_Pass_the_Hash_Ticket_Tespiti.md)) doğrudan NTLM hash'ini kullanır. Modern AD ortamı **Kerberos'a** dayanmalı, NTLM yalnızca kaçınılmaz eski uygulamalar için, sıkı kısıtlamayla kalmalıdır.

İki katmanlı yaklaşım:
- **NTLMv1/LM'i tamamen yasakla:** Yalnızca NTLMv2 kabul et (LmCompatibilityLevel).
- **NTLM'i mümkün olduğunca kısıtla:** `Restrict NTLM` politikalarıyla önce **audit** (kim NTLM kullanıyor?), sonra **deny** (özellikle DC'lere gelen NTLM).

> **İlke:** NTLM her relay ve Pass-the-Hash saldırısının ortak paydasıdır. Önce görünür kıl (audit), sonra kes (deny). Kerberos'a git; NTLM'i eski uygulamaların gettosunda tut.

Bu, [Sistem 10.3 Hardening](../../1-Sistem_Yoneticisi/Modul_10_Guvenlik_Yedekleme_ve_Kurtarma/10.3_Hardening_Temelleri.md)'in "NTLMv2/protokol" temelinin en agresif uygulamasıdır ve [Blue 03.3 Protected Users](../Modul_03_Kimlik_Bilgisi_Korumasi/03.3_Protected_Users_ve_Authentication_Policies.md) (NTLM'i tümden kapatır) ile tamamlanır.

## 2. Teknik Derinlik

### 2.1 NTLM sürümleri ve risk

```
   Sürüm     Algoritma         Zaaf                          Durum
   ─────     ─────────         ────                          ─────
   LM        DES (7-char!)     saniyeler içinde kırılır      YASAK
   NTLMv1    DES(MD4 hash)     kırılır + relay               YASAK
   NTLMv2    HMAC-MD5 + zaman  relay'e açık (imza yoksa)     kısıtla/audit
   Kerberos  AES + bilet       relay'e kapalı (mutual auth)  TERCİH
```

### 2.2 LmCompatibilityLevel

Bu politika, hangi NTLM sürümlerinin gönderileceğini/kabul edileceğini kontrol eder. **Seviye 5** ("Send NTLMv2 response only. Refuse LM & NTLM") hedeftir: LM ve NTLMv1 tamamen reddedilir, yalnızca NTLMv2. Daha düşük seviyeler downgrade saldırılarına ve NTLMv1 kırmaya açıktır.

### 2.3 Restrict NTLM aşamalı dağıtımı

`Network security: Restrict NTLM` politikaları güçlüdür ama körlemesine "deny" iş kesintisi yaratır. Doğru yol **audit → analiz → deny**:
1. **Audit incoming/outgoing NTLM traffic:** Event 8001-8004 üretilir; kimin nereye NTLM kullandığı görünür.
2. **İstisna listesi:** Gerçekten NTLM gereken eski sunucuları belirle.
3. **Deny NTLM (DC'ye):** `Restrict NTLM: NTLM authentication in this domain` = Deny for domain servers (istisnalar hariç).

## 3. Pratik Uygulama

### 3.1 NTLMv1/LM'i yasakla (GPO)
```text
GPO: Computer Config → Windows Settings → Security Settings → Local Policies →
  Security Options →
   "Network security: LAN Manager authentication level"
       = Send NTLMv2 response only. Refuse LM & NTLM   (Seviye 5)
   "Network security: Do not store LAN Manager hash value on next password change" = Enabled
```

### 3.2 NTLM kullanımını denetle (audit — deny'den önce ZORUNLU)
```text
GPO Security Options:
   "Network security: Restrict NTLM: Audit Incoming NTLM Traffic" = Enable all
   "Network security: Restrict NTLM: Audit NTLM authentication in this domain" = Enable all
```
```powershell
# NTLM audit olaylarını topla (kim NTLM kullanıyor?) — Operational log
Get-WinEvent -LogName 'Microsoft-Windows-NTLM/Operational' -MaxEvents 200 |
  Where-Object Id -in 8001,8002,8003,8004 |
  Group-Object { ($_.Message -split 'Secure Channel name:\s+')[1] } | Sort Count -Desc
```

### 3.3 Analiz sonrası kısıtla (deny)
```text
Audit ile NTLM kullananları belirledikten ve istisna eklendikten sonra:
   "Restrict NTLM: NTLM authentication in this domain" = Deny for domain servers
   "Restrict NTLM: Add server exceptions..." = (gerçekten gereken eski sunucular)
→ Tier 0 hesapları için Protected Users (03.3) NTLM'i zaten tümden kapatır.
```

## 4. Tespit Değeri — NTLMv1 ve Anormal NTLM

```yaml
# Sigma — NTLMv1 kullanımı (yasaklı, kırılabilir) veya ayrıcalıklı NTLM
title: NTLMv1 Kullanimi veya Ayricalikli NTLM Auth
logsource: { product: windows, service: security }
detection:
  ntlmv1:
    EventID: 4624
    LmPackageName: ['NTLM V1', 'LM']       # NTLMv1/LM = yasak
  priv_ntlm:
    EventID: 4776
    TargetUserName|startswith: ['adm_', 'DA_']   # ayrıcalıklı hesap NTLM
  condition: ntlmv1 or priv_ntlm
level: high
tags: [attack.credential_access, attack.lateral_movement, attack.t1550.002]
```
```powershell
# Get-WinEvent — 4624'te NTLMv1/LM paketi (yasaklı olmalı, görülürse anomali)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} |
  Where-Object { $_.Message -match 'Package Name \(NTLM only\):\s+(NTLM V1|LM)' } |
  Select TimeCreated, @{N='Hesap';E={($_.Message -split 'Account Name:\s+')[2].Split("`n")[0]}}
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| NTLMv1/LM paketi (4624) | Security | Yasaklı zayıf protokol | T1550.002 |
| Ayrıcalıklı hesap NTLM (4776) | Security (DC) | PtH/relay adayı | T1550.002 |
| NTLM audit 8004 (deny olurdu) | NTLM/Operational | Kısıtlama kapsamı dışı NTLM | T1557 |
| Beklenmedik sunucuya NTLM | 8003 | Relay/lateral | T1557.001 |

## 5. Doğrulama / Lab

```powershell
# 1) NTLMv1 testi: LmCompatibilityLevel=5 iken NTLMv1 auth BAŞARISIZ olmalı
Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name LmCompatibilityLevel
# 2) Audit kanıtı: NTLM/Operational log'da 8001-8004 olayları toplanıyor mu?
# 3) Relay zorlaştırma testi (izole lab): NTLM deny sonrası ntlmrelayx zinciri kırılmalı
Invoke-AtomicTest T1550.002 -TestNumbers 1
# 4) Tier 0 kanıtı: Protected Users üyesi hesap NTLM ile auth EDEMEMELİ (03.3)
```
> **Kanıt:** LmCompatibilityLevel=5 ile NTLMv1 reddedilmeli; ayrıcalıklı hesaplar (Protected Users) hiç NTLM üretmemeli. Deny'den önce mutlaka audit ile kapsamı ölç — yoksa eski uygulamalar kırılır.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **NTLMv1/LM'i açık bırakmak:** DES tabanlı, saniyeler içinde kırılır; LmCompatibilityLevel=5 ile tümden yasakla.
- 🔴 **Audit'siz "deny" yapmak:** Restrict NTLM'i körlemesine deny etmek eski uygulamaları kırar; önce audit (8001-8004) → analiz → istisna → deny.
- ⚠️ **Kerberos'a geçmeyi ihmal etmek:** NTLM'i kısıtlamak yeterli değil; asıl hedef uygulamaları Kerberos'a taşımak (SPN, DNS doğru yapılandırma).
- ⚠️ **Tier 0'ı NTLM'e açık bırakmak:** DA'lar Protected Users ile NTLM'i tümden kapatmalı; tek NTLM auth bir PtH/relay hediyesidir.
- 🔍 **İzleme ipucu:** Ayrıcalıklı bir hesabın (adm_/DA_) **herhangi bir NTLM (4776)** üretmesi, meşru senaryoda neredeyse görülmez — yüksek öncelikli alarm.
