## 1. Kavramsal Temel — Neden Var?

NTLM relay ([08.1](./08.1_LDAP_Signing_ve_Channel_Binding.md)–[08.3](./08.3_NTLM_Kisitlama_ve_NTLMv2.md)) bir kurbanın kimlik doğrulamasını **yakalamayı** gerektirir. Ama saldırgan pasif beklemek zorunda değildir — **koersiyon (coercion)** ile bir makineyi, hatta bir **Domain Controller'ı**, kendi sunucusuna kimlik doğrulaması yapmaya **zorlayabilir**. Windows'un çeşitli RPC arayüzleri, "şu yola git ve kimlik doğrula" demeye izin verir:

- **PrinterBug (MS-RPRN):** Print Spooler servisi, hedef sunucuyu saldırganın makinesine auth olmaya zorlar.
- **PetitPotam (MS-EFSRPC):** Şifreleme dosya sistemi RPC'si ile DC'yi zorlar (kimlik doğrulama gerekmeden!).
- **DFSCoerce (MS-DFSNM), ShadowCoerce (MS-FSRVP):** Benzer RPC koersiyon yöntemleri.

Koersiyon + relay + unconstrained/AD CS = **domain hakimiyeti**: saldırgan DC'yi kendine çeker, DC'nin kimlik doğrulamasını AD CS'e (ESC8) veya LDAP'a relay eder, DC sertifikası/RBCD alır → DCSync. Bu yüzden koersiyon önleme, relay savunmasının **tetikleyici ucunu** kapatır.

> **İlke:** Relay için saldırganın beklemesi gerekmez — koersiyon DC'yi bile zorla getirir. Signing/relay önlemi savunmanın bir ucu, koersiyon yüzeyini kapatmak diğer ucudur. İkisi olmadan zincir kırılmaz.

Bu, [Blue M06 unconstrained](../Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.2_Unconstrained_Delegation_Riskleri_ve_Onlemi.md) ve [Blue M07 ESC8](../Modul_07_AD_CS_PKI_Guvenligi/) zincirlerinin tetikleyici tarafıdır.

## 2. Teknik Derinlik

### 2.1 Koersiyon → relay → hakimiyet zinciri

```
   ① Saldırgan: DC01'i zorla (PetitPotam MS-EFSRPC / PrinterBug MS-RPRN)
        │  "DC01, git \\attacker\share'e auth ol"
        ▼
   ② DC01$ makine hesabı, attacker sunucusuna NTLM auth yapar
        │
        ▼
   ③ Saldırgan bu auth'u RELAY eder:
        ├─► AD CS web enrollment'a (ESC8) → DC01 sertifikası → [Blue M07]
        ├─► LDAP'a → RBCD kur → [Blue M06]
        └─► unconstrained sunucuya → TGT hasadı
        ▼
   ④ DC01 kimliğiyle DCSync → krbtgt → DOMAIN
   Savunma: her adımı kes — koersiyonu(①), relay'i(③), delegation'ı kapat.
```

### 2.2 Neden PetitPotam özellikle tehlikeli?

PrinterBug kimlik doğrulama gerektirir (bir hesap lazım). **PetitPotam (orijinal)** ise **kimlik doğrulama olmadan** (unauthenticated) DC'yi zorlayabiliyordu — bu yüzden yamandı (CVE-2021-36942) ama tüm varyantlar tam kapatılmadı. Print Spooler'ın DC'lerde çalışması ise PrinterBug'ı hâlâ mümkün kılar. Bu yüzden **çok katmanlı** önlem gerekir: yamalar + servis kapatma + RPC filtreleme + relay önleme.

### 2.3 RPC filtreleme (derin savunma)

Windows Firewall'un **RPC filtreleme** yeteneği, belirli RPC arayüzlerine (MS-RPRN, MS-EFSRPC UUID'leri) erişimi kısıtlayabilir. Bu, yamaların kaçırdığı varyantları da kapatan bir ağ-katmanı savunmasıdır.

## 3. Pratik Uygulama

### 3.1 Print Spooler'ı DC'lerde kapat (PrinterBug)
```powershell
# DC'lerde Print Spooler durdur ve devre dışı bırak (DC yazdırmaz)
Stop-Service Spooler -Force
Set-Service Spooler -StartupType Disabled
Get-Service Spooler | Select Name, Status, StartType   # doğrula
```

### 3.2 PetitPotam yamaları ve EFS kısıtlama
```text
- Güncel Windows yamalarını uygula (CVE-2021-36942 ve sonrası MS-EFSRPC düzeltmeleri).
- NTLM'i AD CS web servislerinde kapat / EPA zorla (ESC8 relay'i kes → Blue M07).
- Mümkünse EFSRPC'yi kısıtla (RPC filtreleme aşağıda).
```

### 3.3 RPC filtreleme (MS-RPRN / MS-EFSRPC)
```text
# netsh rpc filter ile MS-EFSRPC (PetitPotam) arayüzünü engelle (örnek)
netsh rpc filter
  add rule layer=um actiontype=block
  add condition field=if_uuid matchtype=equal data=c681d488-d850-11d0-8c52-00c04fd90f7e
  add filter
  quit
# → MS-EFSRPC (c681d488...) ve MS-RPRN (12345678-1234-abcd...) UUID'lerini blokla
```

### 3.4 Relay hedeflerini de kapat (birlikte savunma)
```text
- LDAP signing + Channel Binding [08.1], SMB signing [08.2] → relay hedefi kapanır
- AD CS web enrollment'ta EPA + HTTPS + NTLM kapat [Blue M07] → ESC8 kapanır
- DC'leri unconstrained delegation'dan uzak tut, Tier 0 AccountNotDelegated [Blue M06]
```

## 4. Tespit Değeri — Koersiyon Çağrıları

```yaml
# Sigma — DC makine hesabının beklenmedik sunucuya giden NTLM auth'u (koersiyon izi)
title: DC Makine Hesabi Beklenmedik NTLM Auth (Koersiyon Belirtisi)
logsource: { product: windows, service: security }
detection:
  sel:
    EventID: 4624
    TargetUserName|re: 'DC\d+\$'          # DC makine hesabı
    LogonType: 3
    AuthenticationPackageName: 'NTLM'
  filter:
    WorkstationName|startswith: 'DC'       # DC'ler arası meşru
  condition: sel and not filter
level: high
tags: [attack.credential_access, attack.t1187]
```
```powershell
# Get-WinEvent — Spooler/EFSRPC ile ilişkili named pipe erişimi (Sysmon EID 18)
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' -FilterXPath `
 "*[System[EventID=18]]" | Where-Object { $_.Message -match '\\spoolss|\\efsrpc|\\lsarpc' }
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| DC$ beklenmedik NTLM (Type 3) | 4624 | Koersiyon+relay adayı | T1187 |
| `\spoolss` pipe erişimi | Sysmon 18 | PrinterBug (MS-RPRN) | T1187 |
| `\efsrpc`/`\lsarpc` pipe | Sysmon 18 | PetitPotam (MS-EFSRPC) | T1187 |
| DC$ sertifika talebi (4886/4887) | CA | ESC8 relay sonucu | T1649 |

## 5. Doğrulama / Lab

```powershell
# 1) Spooler kanıtı: DC'lerde Spooler = Disabled (§3.1 doğrula)
# 2) Koersiyon testi (izole lab): PetitPotam/PrinterBug ile DC'yi zorla →
#    yama + spooler kapalı + RPC filtre ile çağrı BAŞARISIZ olmalı; §4 alarm çıkmalı
Invoke-AtomicTest T1187 -TestNumbers 1
# 3) Zincir testi: koersiyon + ntlmrelayx→AD CS (ESC8) → EPA/NTLM kapalıysa relay kırılır
```
> **Kanıt:** Koersiyon zinciri **çok noktalı** kesilir — (a) koersiyon çağrısı (spooler/EFSRPC) reddedilir, (b) relay hedefi (signing/EPA) reddeder, (c) delegation kapalıdır. Tek katman yeterli değil; hepsini doğrula.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Print Spooler'ı DC'lerde açık bırakmak:** PrinterBug'ın doğrudan aracı; DC'ler yazdırmaz, Spooler'ı devre dışı bırak.
- 🔴 **Tek katmana güvenmek:** Yalnızca yama veya yalnızca signing yetmez; koersiyon+relay+delegation zinciri çok noktalı kesilmeli.
- ⚠️ **PetitPotam varyantlarını "yama var" diye kapalı saymak:** Tüm varyantlar tam kapanmadı; RPC filtreleme + AD CS EPA ile derinleştir.
- ⚠️ **RPC filtrelemeyi test etmeden uygulamak:** Yanlış UUID/kural meşru servisleri bozabilir; izole ortamda doğrula, sonra dağıt.
- 🔍 **İzleme ipucu:** Bir DC'nin makine hesabının (`DC01$`) başka bir sunucuya **NTLM (Type 3)** kimlik doğrulaması, meşru senaryoda çok nadirdir ve koersiyon+relay zincirinin en güçlü erken işaretidir → [Blue 06.2](../Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.2_Unconstrained_Delegation_Riskleri_ve_Onlemi.md).
