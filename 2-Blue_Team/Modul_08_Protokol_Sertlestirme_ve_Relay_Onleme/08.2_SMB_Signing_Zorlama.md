## 1. Kavramsal Temel — Neden Var?

SMB (Server Message Block), Windows dosya paylaşımı ve birçok yönetim işleminin (PsExec → [Blue 04.3](../Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md)) taşıyıcısıdır. **SMB relay**, LDAP relay ([08.1](./08.1_LDAP_Signing_ve_Channel_Binding.md)) ile aynı mantığı SMB üzerinde uygular: saldırgan bir kurbanın SMB kimlik doğrulamasını yakalar ve başka bir sunucuya iletir. Kurban o sunucuda yönetici ise, saldırgan **PsExec ile kod çalıştırır** — klasik "SMB relay ile yanal hareket".

**SMB Signing**, her SMB mesajını kriptografik olarak imzalar. İletilen (relay) trafik imzayı taşıyamayacağından hedef sunucu tarafından **reddedilir**. Bu, SMB relay'i tek hamlede etkisizleştiren en temel ve en etkili sertleştirmedir — ama tarihsel olarak **performans endişesiyle kapalı** bırakıldığından hâlâ birçok ortamda açık bir yaradır.

> **İlke:** İmzalanmayan SMB, "aradaki biri" için açık bir davetiyedir. SMB Signing zorunlu olduğunda, relay edilen oturum imzayı üretemez ve düşer — SMB relay ölür.

Bu, [Sistem 06.1 DFS-N](../../1-Sistem_Yoneticisi/Modul_06_Depolama_ve_Dosya_Servisleri/06.1_DFS_Namespaces.md) / SMB altyapısının güvenlik sertleştirmesidir.

## 2. Teknik Derinlik

### 2.1 SMB relay akışı ve signing'in kestiği yer

```
   Kurban (SRV2'de admin)     Saldırgan (relay)         Hedef SRV2
      │ ① Responder/koersiyon    │                          │
      │ ile SMB auth başlatılır   │                          │
      │──────────────────────────►│ ② SMB auth'u SRV2'ye İLET │
      │                           │─────────────────────────►│ ③ PsExec/servis
      │                           │  (kurbanın admin yetkisi) │    → RCE
      │                           │                          │
   ✗ SMB SIGNING (SRV2'de "Require"): iletilen oturumun imzası yok → SRV2 REDDEDER
```

### 2.2 Signing politikaları ve varsayılanlar

- **Server tarafı:** `Microsoft network server: Digitally sign communications (always)` — sunucu imza **zorunlu** kılar.
- **Client tarafı:** `Microsoft network client: Digitally sign communications (always)` — istemci imza **zorunlu** ister.

Kritik varsayılan farkı: **DC'ler** SMB signing'i zorunlu kılar (SYSVOL/NETLOGON için), ama **üye sunucu ve istemcilerde varsayılan olarak zorunlu değildir** — işte SMB relay tam bu boşlukta yaşar. SMB3'te "encryption" da ek koruma sağlar ama signing relay için yeterli ve zorunludur.

### 2.3 Performans miti

Eski donanımda SMB signing ölçülebilir bir yük getirirdi; modern CPU'larda (AES-NI, SMB3 imza algoritmaları) bu yük ihmal edilebilir. "Performans için kapatmak" bugün savunulamaz bir risktir — Microsoft da Windows 11/Server 2025'te signing'i **varsayılan zorunlu** yapmaya başlamıştır.

## 3. Pratik Uygulama

### 3.1 SMB Signing'i zorunlu yap (GPO — tüm sunucu/istemciler)
```text
GPO: Computer Config → Windows Settings → Security Settings → Local Policies →
  Security Options →
   "Microsoft network server: Digitally sign communications (always)" = Enabled
   "Microsoft network client: Digitally sign communications (always)" = Enabled
```

### 3.2 PowerShell ile durum denetimi ve zorlama
```powershell
# Mevcut SMB signing durumu (server + client)
Get-SmbServerConfiguration | Select RequireSecuritySignature, EnableSecuritySignature
Get-SmbClientConfiguration | Select RequireSecuritySignature
# Zorunlu yap (server)
Set-SmbServerConfiguration -RequireSecuritySignature $true -Force
```

### 3.3 Signing yapmayan sistemleri bul (envanter)
```powershell
# Ağdaki sunucularda SMB signing durumu (relay'e açık olanları listele)
$servers = Get-ADComputer -Filter {OperatingSystem -like "*Server*"} | Select -Expand Name
foreach ($s in $servers) {
  try {
    $cfg = Invoke-Command -ComputerName $s -ScriptBlock { (Get-SmbServerConfiguration).RequireSecuritySignature } -EA Stop
    if (-not $cfg) { "RELAY'E ACIK: $s" }
  } catch { "Erisilemedi: $s" }
}
```

## 4. Tespit Değeri — Relay Denemesi ve İmzasız SMB

```yaml
# Sigma — SMB relay/PsExec sonrası şüpheli servis (signing boşluğu sömürüsü)
title: SMB Relay Sonrasi Supheli Servis (PsExec Imzasi)
logsource: { product: windows, service: system }
detection:
  sel:
    EventID: 7045
    ServiceFileName|contains: ['\\ADMIN$\\', 'PSEXESVC']
  condition: sel
level: high
tags: [attack.lateral_movement, attack.t1021.002, attack.t1557.001]
```
```powershell
# Get-WinEvent — beklenmedik makine hesabıyla SMB (Type 3) + hemen servis kurulumu
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} |
  Where-Object { $_.Message -match 'Logon Type:\s+3' -and $_.Message -match 'Authentication Package:\s+NTLM' } |
  Select TimeCreated, @{N='Hesap';E={($_.Message -split 'Account Name:\s+')[2].Split("`n")[0]}}
```

| Sinyal | Event | Anlamı | MITRE |
|--------|-------|--------|-------|
| PsExec servisi ADMIN$'ten (7045) | System | Relay/yanal yürütme | T1021.002 |
| NTLM + Type 3 SMB (imzasız yüzey) | 4624/4776 | Relay adayı oturum | T1557.001 |
| Responder/LLMNR yanıtı | ağ/Sysmon | Poisoning (relay kaynağı) | T1557.001 |
| Beklenmedik makine hesabı SMB | 4624 | Koersiyon+relay | T1187 |

## 5. Doğrulama / Lab

```powershell
# 1) Envanter: RequireSecuritySignature=$false olan sunucu = 0 hedefi (§3.3)
# 2) Relay engelleme testi (izole lab): Responder + ntlmrelayx ile SMB relay dene →
#    Signing "Require" iken relay BAŞARISIZ olmalı (imza tutmaz)
Invoke-AtomicTest T1557.001 -TestNumbers 1
# 3) Doğrula: Get-SmbServerConfiguration RequireSecuritySignature = True
```
> **Kanıt:** ntlmrelayx ile SMB relay denendiğinde, signing zorunluyken hedef reddetmeli. Envanterle "signing kapalı sunucu = 0" hedefine ulaş; her açık sunucu bir relay hedefidir.

## 7. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **SMB signing'i "performans" için kapalı bırakmak:** Modern donanımda yük ihmal edilebilir; kapalı signing = açık SMB relay yarası.
- 🔴 **Yalnızca DC'lerde signing'e güvenmek:** Üye sunucu/istemcilerde varsayılan zorunlu değildir; relay tam bu boşlukta yaşar — her yerde zorla.
- ⚠️ **Client signing'i unutmak:** Yalnızca server tarafı yetmez; hem client hem server "always" olmalı.
- ⚠️ **SMBv1'i açık bırakmak:** Eski, imzasız, zafiyetli; tamamen kaldır (`Disable-WindowsOptionalFeature ... SMB1Protocol`).
- 🔍 **İzleme ipucu:** ADMIN$ üzerinden PsExec servisi (7045) + NTLM Type 3 oturum kombinasyonu, signing boşluğundan yararlanan relay/yanal hareketin klasik imzasıdır → [Blue 04.3](../Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md).
