# 05.4 — DNS Sorun Giderme: nslookup, Resolve-DnsName, dcdiag /test:dns

> **Modül:** 05 — DNS ve Ad Çözümleme · **Kol:** Sistem Yöneticisi
> **Ön koşul:** [05.3 — DNSSEC ve Secure Updates](./05.3_DNSSEC_ve_Secure_Updates.md) · **Sonraki modül:** [Modül 06 — Depolama ve Dosya Servisleri](../Modul_06_Depolama_ve_Dosya_Servisleri/)

## 1. Kavramsal Temel — Neden Var?

AD'de "oturum açamıyorum", "replikasyon çalışmıyor", "GPO gelmiyor", "trust kırıldı" şikayetlerinin şaşırtıcı derecede büyük kısmının kök nedeni **DNS**tir. Çünkü AD'nin her parçası ([02.1](../Modul_02_Fiziksel_Altyapi_ve_Replikasyon/02.1_Domain_Controller_ve_Site_Topolojisi.md) DC Locator, Kerberos, replikasyon) DNS ile çalışır. Bu yüzden AD teşhisinde **ilk bakılacak yer sık sık DNS'tir.**

> **Altın kural:** Bir AD sorununda önce DNS'i ele. `dcdiag /test:dns` ve `nslookup`/`Resolve-DnsName` ile SRV kayıtlarının ve çözümlemenin sağlığını doğrula; çoğu zaman kök neden burada çıkar.

---

## 2. Teknik Derinlik — Teşhis Zinciri

```
1. İstemci doğru DNS'i mi kullanıyor?  → DNS istemci ayarı bir DC/DNS sunucusu mu?
2. Temel çözümleme çalışıyor mu?        → Resolve-DnsName dc01.corp.local
3. SRV kayıtları var mı?                → _ldap._tcp.dc._msdcs... çözülüyor mu?
4. DC kendini duyuruyor mu?             → dcdiag /test:Advertising /test:dns
5. Forwarder/conditional forwarder?     → dış/trust çözümleme çalışıyor mu?
6. Replikasyon/zone sağlığı?            → _msdcs zone replike mi? (Modül 02)
7. Ters çözümleme (PTR) gerekiyor mu?   → bazı servisler/denetim için
```

**En sık kök nedenler:**
- **Yanlış DNS istemci ayarı:** İstemci/sunucu, DC olmayan (örn. ISP/genel) bir DNS'i gösteriyor → SRV bulunamaz, domain işlemleri kırılır.
- **Eksik/bozuk SRV kayıtları:** netlogon kaydı yapılmamış → DC bulunamaz. `nltest /dsregdns` ile yeniden kaydet.
- **Forwarder eksikliği:** İç zone çalışır ama internet/trust çözümlemesi başarısız.
- **Stale/yanlış kayıt:** Eski IP'ye çözümleme → [05.2](./05.2_Aging_ve_Scavenging.md).
- **`_msdcs` replikasyon sorunu:** Forest DC bulma çöker → [02.2](../Modul_02_Fiziksel_Altyapi_ve_Replikasyon/02.2_Replikasyon_KCC_ve_Bridgehead.md).

## 3. Pratik Uygulama

### Temel çözümleme testleri
```powershell
# Modern (PowerShell) — ayrıntılı ve script dostu
Resolve-DnsName dc01.corp.local
Resolve-DnsName -Type SRV "_ldap._tcp.dc._msdcs.corp.local"
Resolve-DnsName -Server 10.0.0.10 corp.local   # belirli bir DNS sunucusuna sor

# Klasik nslookup (interaktif de kullanılır)
# nslookup
#   > set type=srv
#   > _ldap._tcp.dc._msdcs.corp.local
#   > set type=all
#   > corp.local
```

### dcdiag — DNS'e özel testler (en kapsamlı)
```powershell
# DC'nin DNS sağlığı: kayıtlar, forwarder, delegation, dinamik güncelleme
dcdiag /test:dns /v

# Belirli alt testler
dcdiag /test:dns /dnsbasic /dnsforwarders /dnsrecordregistration /s:DC01

# DC kendini KDC/GC/DC olarak duyuruyor mu (SRV kayıt sağlığına bağlı)
dcdiag /test:Advertising
```

### SRV kayıtlarını yeniden oluşturma / DNS istemci ayarı
```powershell
# DC'de netlogon kayıtlarını (SRV/A) yeniden kaydet
nltest /dsregdns
# veya: Restart-Service netlogon

# İstemci/sunucu DNS ayarını doğrula (DC'leri göstermeli)
Get-DnsClientServerAddress -AddressFamily IPv4

# DNS istemci önbelleğini temizle (yanlış/stale çözümleme şüphesinde)
Clear-DnsClientCache
ipconfig /flushdns ; ipconfig /registerdns
```

### Sunucu tarafı zone/forwarder kontrolü
```powershell
Import-Module DnsServer
Get-DnsServerZone                                  # zone envanteri
Get-DnsServerForwarder                              # dış çözümleme için forwarder
Get-DnsServerZone -Name "_msdcs.corp.local"        # forest DC-bulma zone'u sağlığı
Get-DnsServerResourceRecord -ZoneName "corp.local" -RRType SRV | Select-Object -First 20
```

### DNS olay logları
```text
Event Viewer → Applications and Services Logs → DNS Server
+ (istemci) Microsoft-Windows-DNS-Client/Operational
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **DNS'i teşhis rutininin başına koy:** AD sorunlarında `dcdiag /test:dns` ilk adımlardan olmalı; zaman kazandırır.
- **DNS istemci ayarını standartla:** DC'ler ve üyeler yalnızca iç DC/DNS sunucularını göstermeli; genel DNS forwarder üzerinden verilmeli.
- **`_msdcs` sağlığını izle:** Forest DC-bulma çekirdeği; replikasyon ve kayıt bütünlüğünü periyodik doğrula.
- **Otomatik sağlık kontrolü:** `dcdiag`/`Resolve-DnsName` kontrollerini zamanlanmış script ile izleyip merkezî logla → [Modül 09](../Modul_09_Otomasyon_ve_Arayuzler/), [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- ⚠️ **Genel/ISP DNS'i istemcilere vermek:** Domain işlemleri kırılır; ayrıca çözümleme güven zincirini dışa taşır. İç DC/DNS kullan, dışı forwarder ile çöz.
- ⚠️ **Önbellek kaynaklı yanlış çözümlemeyi atlamak:** `Clear-DnsClientCache`/`ipconfig /flushdns` yapmadan teşhis yanıltıcı olabilir.
- 🔴 **Teşhis ≠ yalnızca operasyon:** Beklenmedik çözümleme (bir servis adının yanlış IP'ye gitmesi) sadece arıza değil, **DNS/ad zehirleme** işareti de olabilir → [Red M02](../../3-Red_Team/Modul_02_Ilk_Erisim_ve_Yerlesme/). "Neden bu isim başka IP'ye çözülüyor?" sorusunu güvenlik gözüyle de sor.
- 🔍 **İzleme ipucu:** DNS Server olay logu + istemci DNS-Client Operational logu merkezî toplanmalı; ani SRV/`_msdcs` kaybı ya replikasyon sorunudur ya da manipülasyon → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).
