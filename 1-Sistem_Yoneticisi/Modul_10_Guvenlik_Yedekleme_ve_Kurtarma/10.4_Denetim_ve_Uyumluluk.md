# 10.4 — Denetim ve Uyumluluk: SACL, Denetim Politikaları ve Standartlar

## 1. Kavramsal Temel — Neden Var?

Hardening ([10.3](./10.3_Hardening_Temelleri.md)) saldırıyı **zorlaştırır**; denetim (auditing) ise olan biteni **görünür** kılar ve **kanıtlar**. İki farklı ihtiyaç:

1. **Güvenlik görünürlüğü:** "Kim, neyi, ne zaman değiştirdi/erişti?" — bir saldırıyı tespit etmenin ve olay sonrası soruşturmanın temeli.
2. **Uyumluluk (compliance):** ISO 27001, SOC 2, GDPR, PCI-DSS gibi standartlar, kimlik/erişim yönetiminde **denetlenebilirlik ve kontrol** ister. Denetim, bu gereksinimlerin **kanıtını** üretir.

Bu, Sistem Yöneticisi kolunun son halkasıdır ve doğrudan Blue Team'e köprüdür: **denetim, tespitin (detection) ham maddesidir** → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/), [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).

## 2. Teknik Derinlik

### 2.1 İki tür ACL: DACL vs SACL

Bir güvenlik tanımlayıcısında ([03.1](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.1_OU_Tasarimi_ve_Yetki_Devri.md)) iki liste vardır:
- **DACL (Discretionary ACL):** Kim **erişebilir** (izin) → yetkilendirme.
- **SACL (System ACL):** Kimin erişimi **loglanır** (denetim) → görünürlük.

SACL, "bu OU'da parola değişikliği yapan herkesi denetle" gibi kuralları taşır. Advanced Audit Policy ile birlikte, hangi olayların kaydedileceğini belirler.

### 2.2 Denetim boru hattı (audit pipeline)

```
   ① Ne denetlenecek?           ② Nerede üretilir?        ③ Nereye toplanır?
  ┌─────────────────────┐      ┌──────────────────┐      ┌────────────────────┐
  │ Advanced Audit      │      │ Her DC / sunucu  │ WEF  │ Merkezî toplayıcı  │
  │ Policy (GPO) +      │─────►│ Security event   │─────►│ (WEC) → SIEM       │
  │ SACL (nesne bazlı)  │      │ log üretir       │      │ (Sigma/korelasyon) │
  └─────────────────────┘      └──────────────────┘      └────────────────────┘
    örn: 4720,4728,4662,4624...   (yerel logda kalırsa      Blue M01 (toplama) →
                                   saldırgan siler!)         Blue M02 (tespit)
```

Kritik: Loglar **yerel DC'de kalmamalı** — bir saldırgan izlerini siler. **Windows Event Forwarding (WEF)** ile merkezî toplama şart → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).

### 2.3 İzlenmesi gereken kritik Event ID'ler (özet)

| Event ID | Anlamı | Neden kritik |
|----------|--------|--------------|
| **4624 / 4625** | Başarılı / başarısız oturum açma | Brute-force, anormal oturum |
| **4720 / 4726** | Kullanıcı oluşturma / silme | Yetkisiz hesap |
| **4728 / 4732 / 4756** | Ayrıcalıklı gruba üye ekleme (global/DL/universal) | Yetki yükseltme → [03.3](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.3_Grup_Ustaligi_AGDLP.md) |
| **4740** | Hesap kilitleme | Brute-force / saldırı |
| **4662** | Dizin nesnesine erişim (SACL) | DCSync tespiti (replikasyon GUID'leri) → [Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |
| **4768 / 4769** | Kerberos TGT / servis bileti | Kerberoasting, Golden/Silver Ticket |
| **5136 / 5141** | Dizin nesnesi değişikliği / silme | GPO/ACL/AdminSDHolder manipülasyonu |

Bu liste, Sistem Yöneticisinin **hangi SACL/audit politikalarını açacağını** belirler; Blue Team bunları tespit kurallarına çevirir → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).

### 2.4 Uyumluluk çerçeveleri ve AD

| Çerçeve | AD ile ilgisi |
|---------|---------------|
| **ISO/IEC 27001** | Erişim kontrolü (A.9), loglama/izleme (A.12); AD kimlik/erişim yönetiminin merkezidir |
| **SOC 2** | Güven ilkeleri (güvenlik/erişim); ayrıcalıklı erişim ve denetim izi kanıtı |
| **GDPR** | Kişisel veriye erişimin denetlenebilirliği, en az ayrıcalık, ihlal tespiti |
| **PCI-DSS** | Ayrıcalıklı erişim izleme, güçlü kimlik doğrulama, log saklama |

Ortak paydalar: **en az ayrıcalık, ayrıcalıklı erişim denetimi, log toplama ve saklama, değişiklik yönetimi.** AD denetim politikaları bunların hepsine kanıt üretir.

## 3. Pratik Uygulama

### Advanced Audit Policy (GPO ile — domain geneli)
```text
GPO: Computer Config → Policies → Windows Settings → Security Settings →
     Advanced Audit Policy Configuration → örnekler:
  • Account Management → Audit User/Security Group Management: Success
  • DS Access → Audit Directory Service Changes: Success (5136/5137)
  • Logon/Logoff → Audit Logon: Success+Failure (4624/4625)
  • Account Logon → Audit Kerberos Service Ticket Operations (4769)
```
```powershell
# Etkin denetim ayarlarını gör
auditpol /get /category:*
```

### SACL ekleme (nesne bazlı denetim)
```powershell
# Örn: kritik bir OU'da "Write" işlemlerini denetle (Everyone için audit ACE)
$path = "AD:\OU=Admin,DC=corp,DC=local"
$acl = Get-Acl $path -Audit
$rule = New-Object System.DirectoryServices.ActiveDirectoryAuditRule(
  [System.Security.Principal.NTAccount]"Everyone",
  [System.DirectoryServices.ActiveDirectoryRights]"WriteProperty",
  [System.Security.AccessControl.AuditFlags]"Success",
  [System.DirectoryServices.ActiveDirectorySecurityInheritance]"Descendents")
$acl.AddAuditRule($rule); Set-Acl $path $acl
```

### Kritik olay sorgulama (yerel — merkezî için WEF→SIEM)
```powershell
# Ayrıcalıklı gruba üye ekleme olayları (son 24 saat)
Get-WinEvent -FilterHashtable @{ LogName='Security'; Id=4728,4732,4756;
  StartTime=(Get-Date).AddDays(-1) } |
  Select-Object TimeCreated, Id, @{N='Detay';E={$_.Message.Split("`n")[0]}}
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Advanced Audit Policy kullan (klasiki değil):** Granüler kontrol; yalnızca değerli olayları üret (gürültüyü azalt).
- **SACL'i kritik nesnelere hedefle:** AdminSDHolder, Tier 0 OU'ları, GPO'lar, PKI nesneleri — her yeri değil, önemli yeri denetle.
- **Merkezî toplama (WEF) şart:** Yerelde kalan log güvenilmez; saldırgan siler. WEC/SIEM'e ilet → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).
- **Saklama süresini uyumluluğa göre ayarla:** GDPR/SOC 2/PCI log saklama gereksinimlerini karşıla.
- **Denetimi tespide bağla:** Ham log değer üretmez; kritik Event ID'leri tespit kurallarına (Sigma) çevir → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Logları yerelde bırakmak:** Saldırgan DC'de izlerini siler (log temizleme). Merkezî WEF/SIEM olmadan denetim kâğıt üzerindedir → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).
- 🔴 **Her şeyi denetleyip hiçbir şeyi görmemek:** Aşırı denetim = gürültü = önemli olayın kaybolması. Hedefli SACL + kritik Event ID.
- ⚠️ **SACL'i kritik nesnelere koymayı unutmak:** DCSync (4662) tespiti, replikasyon nesnesine SACL gerektirir; yoksa saldırı görünmez.
- ⚠️ **Uyumluluğu "kutu doldurma" sanmak:** Gerçek güvenlik kontrolleri (en az ayrıcalık, Tier Model, izleme) uyumluluğun da özüdür; denetim onların kanıtıdır.
- 🔍 **İzleme ipucu:** Log temizleme olayının kendisi (**1102** – Security log temizlendi) yüksek öncelikli alarmdır; denetim politikası değişiklikleri de izlenmeli → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
