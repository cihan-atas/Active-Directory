## 1. Genel Bakış ve Mimarisi

Bir Active Directory altyapısını güvenli yönetmenin, tespit kurallarını doğrulamanın (Detection Engineering) ve sızma testleri gerçekleştirmenin ön şartı; **üretim ortamını riske atmadan gerçekçi saldırı senaryolarının koşturulabileceği kontrollü bir test laboratuvarına** sahip olmaktır.

Sıfırdan manuel olarak onlarca kullanıcı, OU, servis hesabı, orman güven ilişkisi ve sertifika şablonu oluşturmak günler sürer. Bu ihtiyacı çözmek için modern siber güvenlik dünyasında iki temel açık kaynaklı laboratuvar mimarisi kabul görmüştür:

1. **GOAD (Game of Active Directory):** Orange Cyberdefense ve Mayfly tarafından geliştirilen, kurumsal bir holding altyapısını simüle eden **5 sanal makineli, 2 ormanlı ve 3 etki alanlı** devasa bir Active Directory laboratuvarıdır. İçinde AD CS, MSSQL, IIS, Sertifika zafiyetleri (ESC1-ESC8), Kerberos yetki devirleri ve Linux etki alanı üyesi hazır gelir.
2. **Vulnerable-AD-Plus:** Halihazırda kurulu tek bir sanal etki alanı üzerinde, tek satırlık PowerShell betiğiyle saniyeler içinde 40'tan fazla gerçekçi zafiyet (DACL açıkları, Kerberoasting SPN'leri, zayıf parolalar, RBCD kurguları) oluşturan ve test bitiminde sistemi temizleyen hafif simülasyon aracı.

## 2. GOAD (Game of Active Directory) Otomatik Dağıtımı

GOAD, Vagrant ve Ansible kullanarak tüm sanal makineleri (Windows Server 2019, Windows 10, Ubuntu) otomatik olarak indirir, kurar ve zafiyet senaryolarını işletir.

### 2.1. Ön Gereksinimler

- **Donanım:** 32 GB RAM (Tüm GOAD için) veya 16 GB RAM (GOAD-Light - 3 VM için).
- **Yazılım:** Vagrant, VirtualBox (veya VMware / Proxmox), Ansible, Git, Python 3.

```bash
# Ubuntu / Debian ana makinesinde gerekli araçların kurulumu
sudo apt update && sudo apt install -y vagrant virtualbox virtualbox-ext-pack ansible git python3-pip
pip3 install pywinrm
```

### 2.2. GOAD Deposunu Çekme ve Kurulumu Başlatma

```bash
# 1. Depoyu klonlama
git clone https://github.com/Orange-Cyberdefense/GOAD.git /opt/GOAD
cd /opt/GOAD

# 2. Ön gereksinimleri kontrol etme
./goad.sh -t check -l GOAD -p virtualbox -m local

# 3. Sanal makineleri başlatma ve zafiyet dağıtımını icra etme
# (Bu işlem internet hızınıza bağlı olarak 1-2 saat sürebilir)
./goad.sh -t start -l GOAD -p virtualbox -m local
```

### 2.3. GOAD Bileşenleri ve Rolleri

| Sanal Makine | İşletim Sistemi | IP Adresi | Rol ve Barındırılan Servisler |
|---|---|---|---|
| **GOAD-DC01 (kingslanding)** | Windows Server 2019 | `192.168.56.10` | Forest Root DC (`sevenkingdoms.local`), AD CS Kurulu (ESC1-ESC8) |
| **GOAD-DC02 (winterfell)** | Windows Server 2019 | `192.168.56.11` | Child DC (`north.sevenkingdoms.local`), LAPS, Constrained Delegation |
| **GOAD-SRV01 (castelblack)** | Windows Server 2019 | `192.168.56.22` | Üye Sunucu, IIS Web Sunucusu, MSSQL Servisi |
| **GOAD-DC03 (braavos)** | Windows Server 2019 | `192.168.56.12` | Forest Root DC (`essos.local`), Cross-Forest Trust, Unconstrained Del. |
| **GOAD-SRV02 (meereen)** | Ubuntu 20.04 Linux | `192.168.56.23` | Linux Domain Member (SSSD/Realmd), Nginx, Kerberos Keytab |

## 3. Vulnerable-AD-Plus ile Anında Zafiyet Enjeksiyonu

Mevcut bir Windows Server laboratuvarınız varsa ve sıfırdan 5 makine kuracak donanım kaynağınız yoksa, tek bir DC üzerinde tüm sızma testi açıklarını oluşturmak için `Vulnerable-AD-Plus` kullanılır.

### 3.1. Zafiyetlerin Dağıtımı (PowerShell)

```powershell
# 1. DC üzerinde betiği indirme
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/WaterExecution/vulnerable-AD-plus/master/vulnerable-AD-plus.ps1" -OutFile "C:\vulnerable-AD.ps1"

# 2. Zafiyetleri etki alanına enjekte etme
C:\vulnerable-AD.ps1 -Create

# 3. Oluşturulan kullanıcı, grup ve ACL açıklarını listeleme
Get-ADUser -Filter "Description -like '*Vulnerable*'" | Select-Object Name, Description
```

### 3.2. Enjekte Edilen Başlıca Zafiyet Senaryoları

- **Kerberoasting:** Zayıf parola taşıyan servis hesaplarına SPN atanması (`MSSQLSvc/sql.corp.local`).
- **AS-REP Roasting:** `DONT_REQ_PREAUTH` bayrağı aktif kullanıcı hesapları.
- **Tehlikeli DACL İzinleri:** Standart kullanıcılara tanınan `GenericAll`, `WriteDacl` ve `ForceChangePassword` hakları.
- **RBCD (Kaynak Tabanlı Kısıtlı Yetki Devri):** Makine hesaplarının `msDS-AllowedToActOnBehalfOfOtherIdentity` özniteliklerine yazma hakkı.
- **AdminSDHolder Arka Kapısı:** Korunan yönetimsel şablona düşük yetkili bir kullanıcının eklenmesi.

### 3.3. Test Sonrası Temizlik (Cleanup)

Laboratuvar çalışması bittiğinde veya sistem sıfırlanmak istendiğinde:

```powershell
# Tüm yapay zafiyetleri ve oluşturulan test nesnelerini etki alanından silme
C:\vulnerable-AD.ps1 -Clean
```

## 4. Özel Çoklu-İşletim Sistemli Laboratuvar Tasarım Standartları

Eğer kendi laboratuvarınızı manuel tasarlıyorsanız, gerçek dünya kurumsal ağını yansıtması için şu 4 makine asgari standarttır:

1. **DC01 (Domain Controller):** Windows Server 2022 (DNS, DHCP, AD DS, AD CS).
2. **SRV01 (Veritabanı Sunucusu):** Windows Server 2019 (MSSQL Express, gMSA hesabı).
3. **LNX01 (Linux Domain Üyesi):** Ubuntu 22.04 LTS veya Rocky Linux 9 (`realmd` + `sssd` ile dahil edilmiş).
4. **CLI01 (İstemci):** Windows 10/11 Enterprise (Standart çalışan hesabı, Office yazılımları).

## 5. Güvenlik ve İzolasyon Kuralları (Safety Guidelines)

> [!CAUTION]
> **Üretim Ortamında Asla Kullanmayın!**  
> GOAD ve Vulnerable-AD betikleri bilerek ve isteyerek etki alanını tamamen savunmasız hale getirir. Bu betikler kesinlikle şirket içi canlı ağlarda (Production) çalıştırılmamalıdır.

1. **Host-Only Ağ:** Tüm test sanal makineleri sadece kendi aralarında haberleşebilen izole bir `Host-Only` veya `Internal Network` köprüsünde tutulmalıdır.
2. **İnternet İzolasyonu:** Zafiyetli makinelerin dışarıya açık statik IP alması veya port yönlendirmesiyle internete açılması kesinlikle engellenmelidir.
3. **Anlık Görüntü (Snapshot):** Kurulum tamamlandığında her makinenin temiz bir "Clean Baseline" anlık görüntüsü alınmalıdır. Saldırı tatbikatları bittiğinde bu noktaya geri dönülmelidir.
