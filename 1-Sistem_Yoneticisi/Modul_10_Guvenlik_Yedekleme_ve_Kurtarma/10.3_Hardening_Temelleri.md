> **Ön koşul:** Modül 01–09 (bütün altyapı) · **Sonraki:** [10.4 — Denetim ve Uyumluluk](./10.4_Denetim_ve_Uyumluluk.md)

## 1. Kavramsal Temel — Neden Var?

Şimdiye kadar AD'yi **kurmayı** öğrendik. Bu dosya, "kurdum, çalışıyor" ile "kurdum, **savunuldu**" arasındaki farkı kapatır. Varsayılan AD, geriye dönük uyumluluk için birçok **zayıf ayarı açık** bırakır (eski protokoller, zayıf şifreleme, düz güven modeli). Hardening, bu varsayılan zafiyetleri sistematik olarak kapatmaktır.

Hardening üç eksende yapılır ve bu, aynı zamanda tüm Blue Team kolunun sistem-yöneticisi tarafındaki özetidir:

1. **Protokol güvenliği** — eski/zayıf protokolleri kapat, imzalama zorla.
2. **Hesap güvenliği** — ayrıcalıklı hesapları koru, sırları yönet.
3. **Mimari güvenlik** — Tier Model ile yetki katmanlarını izole et.

> **Not:** Bu dosya *temelleri* ve mimarın uygulama noktalarını verir; **derinlemesine savunma** Blue Team kolundadır. Her başlık ilgili Blue modülüne köprülenir.

## 2. Teknik Derinlik

### 2.1 Protokol güvenliği (attack surface reduction)

| Ayar | Neyi kapatır | Karşı saldırı |
|------|--------------|---------------|
| **LDAP Signing + Channel Binding** | İmzasız/relay LDAP bind | LDAP relay → [Red M08](../../3-Red_Team/Modul_08_Koersiyon_ve_NTLM_Relay/) |
| **SMB Signing (zorunlu)** | İmzasız SMB, SMB relay | NTLM relay → [Red M08](../../3-Red_Team/Modul_08_Koersiyon_ve_NTLM_Relay/) |
| **NTLM kısıtlama / NTLMv1 & LM devre dışı** | Zayıf NTLM/LM hash'leri | PtH, relay, cracking → [Red M04](../../3-Red_Team/Modul_04_Yanal_Hareket/) |
| **Kerberos: RC4/DES kapat, AES zorla** | Zayıf şifreleme | Kerberoasting kolaylığı → [Red M03](../../3-Red_Team/Modul_03_Kimlik_Bilgisi_Erisimi/) |
| **LLMNR / NBT-NS / mDNS kapat** | Ad çözümleme fallback | Responder poisoning → [Red M02](../../3-Red_Team/Modul_02_Ilk_Erisim_ve_Yerlesme/) |

Bunlar çoğunlukla **GPO** ([Modül 04](../Modul_04_Grup_Ilkeleri_GPO/)) ile dağıtılır ve **DFL/fonksiyon seviyesi** ([01.3](../Modul_01_Mimari_ve_Temeller/01.3_Fonksiyon_Seviyeleri.md)) bazılarını gerektirir. Derin uygulama → [Blue M08](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/).

### 2.2 Hesap güvenliği

- **Protected Users grubu** (DFL 2012 R2 → [01.3](../Modul_01_Mimari_ve_Temeller/01.3_Fonksiyon_Seviyeleri.md)): Üyeleri için NTLM/DES/RC4/delegation'ı ve kimlik bilgisi önbelleklemeyi kapatır. Tier 0 hesapları buraya.
- **Sensitive & cannot be delegated** (`AccountNotDelegated` → [03.2](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.2_Hesap_Yonetimi.md)): Ayrıcalıklı hesapların delege edilmesini engeller (unconstrained delegation hırsızlığına karşı).
- **LAPS / Windows LAPS:** Her makinede benzersiz, otomatik dönen yerel admin parolası → yanal hareketi kırar. GPP cpassword'ün doğru alternatifi ([04.3](../Modul_04_Grup_Ilkeleri_GPO/04.3_Pratik_Uygulamalar_ADMX_GPP.md)) → [Blue M03](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/).
- **gMSA** servis hesapları için ([03.4](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md)): Kerberoasting savunması.
- **krbtgt düzenli reset + ayrıcalıklı grup hijyeni** ([03.3](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.3_Grup_Ustaligi_AGDLP.md)).

### 2.3 Mimari güvenlik: Admin Tier Model

En güçlü mimari savunma, yetkiyi **katmanlara** ayırıp katmanlar arası kimlik bilgisi sızıntısını engellemektir:

```
  TIER 0  ── Domain/Forest kontrolü ──────────────────────────────┐
  (DC'ler, AD CS, Entra Connect, Domain/Enterprise Admins)        │
     ▲  Tier 0 hesabı ASLA Tier 1/2 makinelere oturum açmaz       │
     │  (aksi halde hash'i o makinede kalır → çalınır)            │
  TIER 1  ── Sunucular / uygulamalar ─────────────────────────────┤  Kimlik bilgisi
  (üye sunucular, uygulama admin'leri)                            │  "aşağı akmaz":
     ▲                                                             │  her katman kendi
     │                                                             │  admin'i + PAW
  TIER 2  ── İş istasyonları / kullanıcılar ──────────────────────┘
  (son kullanıcı cihazları, help desk)

  Uygulama: "Deny log on" User Rights (GPO) + ayrı admin hesapları + PAW
```

- **Neden çalışır:** Bir Tier 2 makinesi ele geçse bile, orada Tier 0 kimlik bilgisi *bulunmadığı* için saldırgan yukarı sıçrayamaz. Pass-the-Hash/Ticket zincirini ([Red M04](../../3-Red_Team/Modul_04_Yanal_Hareket/)) kırar.
- **Uygulama noktaları:** User Rights Assignment GPO'ları ([04.3](../Modul_04_Grup_Ilkeleri_GPO/04.3_Pratik_Uygulamalar_ADMX_GPP.md)), ayrı yönetim hesapları, **PAW (Privileged Access Workstation)**, Authentication Policies/Silos. Derin uygulama → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).

## 3. Pratik Uygulama

### Protokol sertleştirme (GPO/registry örnekleri)
```powershell
# LDAP signing zorunlu (DC tarafı) — GPO: Domain Controller: LDAP server signing = Require
# SMB signing zorunlu
Set-SmbServerConfiguration -RequireSecuritySignature $true -Force

# NTLMv1/LM devre dışı (LmCompatibilityLevel = 5: yalnız NTLMv2)
Set-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name LmCompatibilityLevel -Value 5

# Kerberos'ta yalnız AES (hesap bazında supported enc types) — RC4'ü kaldır
Set-ADUser "svc-app" -Replace @{ 'msDS-SupportedEncryptionTypes' = 24 }  # AES128+AES256
```

### Hesap sertleştirme
```powershell
# Tier 0 hesaplarını Protected Users'a al
Add-ADGroupMember "Protected Users" -Members "admin-tier0-ali"

# Ayrıcalıklı hesapları delege-edilemez işaretle
Get-ADGroupMember "Domain Admins" | ForEach-Object {
  Set-ADAccountControl $_.SamAccountName -AccountNotDelegated $true
}

# Ayrıcalıklı grup üyeliklerini denetle (boş/minimum olmalı)
"Domain Admins","Enterprise Admins","Schema Admins" | ForEach-Object {
  "$_ = " + ((Get-ADGroupMember $_).Count)
}
```

### Baseline uygulama
```text
Microsoft Security Baselines (Security Compliance Toolkit) veya CIS/STIG içeriğini
GPO'ya aktar; domain seviyesinde Enforced ile dayat (04.1). DSC ile drift'e karşı
otomatik düzelt (09.3).
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Varsayılanı güvenmeme:** AD varsayılanları uyumluluk için gevşektir; hardening bir proje olarak planlanır (envanter → pilot → dayatma).
- **Tier Model'i erken kur:** Sonradan uygulamak çok zordur; DC/admin OU ayrımını baştan yap ([03.1](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.1_OU_Tasarimi_ve_Yetki_Devri.md)).
- **Test et, sonra dayat:** SMB/LDAP signing, NTLM kısıtlama gibi ayarlar yanlış uygulanırsa erişim kırar; pilot OU'da doğrula ([04.4](../Modul_04_Grup_Ilkeleri_GPO/04.4_Sorun_Giderme_ve_Analiz.md)).
- **Baseline + drift savunması:** Microsoft/CIS baseline'ını GPO ile dağıt, DSC `ApplyAndAutoCorrect` ile koru ([09.3](../Modul_09_Otomasyon_ve_Arayuzler/09.3_Configuration_as_Code_DSC.md)).
- **Değerlendir (assess):** BloodHound/PingCastle/Purple Knight ile mevcut zafiyetleri ölç → [Blue M09](../../2-Blue_Team/Modul_09_Tehdit_Avciligi_ve_Degerlendirme/).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Tier ihlali (credential theft'in ana yolu):** Tier 0 hesabıyla bir Tier 2 iş istasyonuna oturum açmak, o hesabın hash/bilet'ini o makineye bırakır; makine ele geçerse domain düşer → [Red M04](../../3-Red_Team/Modul_04_Yanal_Hareket/). Tier ayrımı katı olmalı.
- 🔴 **Eski protokolleri açık bırakmak:** NTLMv1/LM, RC4/DES, imzasız SMB/LDAP, LLMNR — hepsi doğrudan saldırı yolu. Kapat.
- ⚠️ **Test etmeden dayatmak:** Signing/NTLM kısıtlama yanlış uygulanırsa erişim kesintisi; pilotla.
- ⚠️ **Ayrıcalıklı grupları şişkin bırakmak:** Domain Admins minimize edilmeli; JIT/PAM ile zaman-sınırlı üyelik.
- 🔍 **İzleme ipucu:** NTLMv1/LM kullanım, imzasız bind, Tier ihlali (Tier 0 hesabının düşük katman makinede oturumu) ve ayrıcalıklı grup değişiklikleri izlenmeli → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
