## 1. Kavramsal Temel — Neden Var?

Çoğu kurum artık **hibrittir**: hem şirket içi (on-premises) AD hem de bulutta **Microsoft Entra ID** (eski adıyla Azure AD) kullanır. Kullanıcı aynı hesapla hem yerel dosya sunucusuna hem Microsoft 365'e girmek ister. Bunu sağlayan köprü **Microsoft Entra ID Connect** (eski adıyla Azure AD Connect) yazılımıdır: on-prem AD nesnelerini (kullanıcı, grup) buluta **senkronize eder**.

> **Neden AD kolunda?** Çünkü hibrit dünyada AD'nin güvenlik sınırı artık yalnızca on-prem değildir. On-prem'i ele geçiren, çoğu zaman **buluta da sıçrayabilir** (ve tersi) → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/). Senkronizasyon sunucusu ve hesabı, yeni ve kritik bir **Tier 0** varlığıdır.

## 2. Teknik Derinlik

### 2.1 Bileşenler ve veri akışı

```
   ON-PREM AD                 ENTRA CONNECT SUNUCUSU                 ENTRA ID (bulut)
  ┌───────────┐        ┌──────────────────────────────────┐        ┌───────────┐
  │  DC'ler   │  import │  AD Connector Space              │        │ Azure AD  │
  │ (LDAP +   │───────►│         │ (inbound sync rules)     │        │ Connector │
  │  replikas)│        │         ▼                          │        │  Space    │
  └───────────┘        │     ┌─────────────┐   (outbound)   │ export └─────┬─────┘
       ▲               │     │  METAVERSE  │───────────────►│──────────────► Entra
       │ PHS: NTLM     │     │ (birleşik   │   sync rules   │        nesneleri
       │ hash okuma    │     │  görünüm)   │                │
       │ (DCSync yetki)│     └─────────────┘                │
       └───────────────┤  Sync rules: hangi öznitelik,      │
                       │  nasıl dönüştürülüp akacak?         │
                       └──────────────────────────────────┘
   Adımlar: 1) Import (AD'den connector space'e)  2) Sync (→ metaverse, kurallar)
            3) Export (metaverse → Entra).  Delta döngüsü varsayılan ~30 dk.
```

- **Entra Connect Sync (sunucu):** On-prem'de çalışan, senkronizasyonu yürüten yazılım. Bir SQL (LocalDB veya tam SQL) veritabanı (metaverse) tutar.
- **Connector Space (CS):** Her bağlı dizinin (on-prem AD, Entra) yerel "ara bellek" temsili. **Metaverse (MV):** tüm kaynakların birleştirilmiş tek görünümü. Bir on-prem kullanıcı → AD CS'te nesne → MV'de birleşik kimlik → Entra CS → bulut nesnesi.
- **Sync Rules (inbound/outbound):** Hangi özniteliğin CS↔MV↔CS arasında nasıl (dönüşümle) akacağını belirleyen kural motoru. Özel öznitelik akışı (örn. `employeeID` → bulut) burada tanımlanır.
- **Import/Sync/Export döngüsü:** Delta döngüsü varsayılan ~30 dk; parola hash senkronu ayrı ve daha sık (~2 dk).
- **Senkronizasyon hesapları (dikkat!):**
  - **AD DS Connector hesabı** (on-prem'i okur; PHS ise parola hash'lerini okuma yetkisi = **DCSync benzeri** yetki → aşağıda §2.4).
  - **Entra Connector hesabı** (buluta yazar).
  - Eskiden `MSOL_...`, `AAD_...` adlı hesaplar; yüksek yetkilidir.

### 2.2 Nesne eşleme: sourceAnchor / ImmutableID

On-prem nesnesi ile bulut nesnesi **kalıcı bir bağ** ile eşlenir:
- **sourceAnchor / ImmutableID:** Değişmez bir tanımlayıcı (modern kurulumlarda `ms-DS-ConsistencyGuid`, temelde `objectGUID` → [01.1](../Modul_01_Mimari_ve_Temeller/01.1_Mantiksal_Hiyerarsi.md)). Nesne yeniden adlandırılsa/taşınsa bile bağ korunur.
- **UPN uyumu kritik:** Bulut oturum açması UPN'e dayanır; on-prem UPN son eki yönlendirilebilir olmalı (`@corp.com`), `.local` değil → [03.2](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.2_Hesap_Yonetimi.md), [05.1](../Modul_05_DNS_ve_Ad_Cozumleme/05.1_AD_Integrated_Zones_ve_SRV.md).

### 2.3 Topolojiler

| Topoloji | Açıklama | Kullanım |
|----------|----------|----------|
| **Tek Connect + staging** | Bir aktif sync sunucusu + bir **staging mode** (pasif yedek) sunucu | Standart HA deseni |
| **Filtreli sync** | OU/domain/öznitelik bazlı filtreleme (yalnızca gerekli nesneler buluta) | Kapsam kontrolü, güvenlik |
| **Çoklu forest → tek tenant** | Birden çok on-prem forest tek Entra tenant'a | M&A, çoklu-forest kurumlar |
| **Entra Cloud Sync (agent)** | Ağır Connect yerine hafif bulut-yönetimli agent | Basit/dağıtık senaryolar |

- **Staging mode:** Yedek sunucu her şeyi işler ama buluta **yazmaz**; aktif sunucu düşerse devreye alınır.
- **Filtreleme:** Yalnızca gerekli OU'ları senkronla — gereksiz nesne bulut saldırı yüzeyini artırır.

### 2.4 ⚠️ Güvenlik: Sync sunucusu = Tier 0

- **PHS senkron hesabı DCSync yapabilir:** Password Hash Sync ([08.2](./08.2_Kimlik_Dogrulama_PHS_PTA_Federation.md)) için AD Connector hesabına **`Replicating Directory Changes` / `...All`** izinleri verilir — yani bu hesap **tüm parola hash'lerini çekebilir** ([02.2](../Modul_02_Fiziksel_Altyapi_ve_Replikasyon/02.2_Replikasyon_KCC_ve_Bridgehead.md) DCSync ile aynı yetki). Bu hesabı/sunucuyu ele geçiren, domain'in tüm hash'lerini alır → [Red M09](../../3-Red_Team/Modul_09_Domain_Hakimiyeti_ve_Kalicilik/).
- **Connect sunucusu her iki dünyaya köprüdür:** On-prem yüksek yetki + bulut yazma yetkisi aynı makinede. Bu yüzden **Domain Controller ile eşdeğer (Tier 0)** korunmalı; ayrı, sıkılaştırılmış, izlenen bir sunucu olmalı → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).
- **Password writeback / Device writeback:** Buluttan on-prem'e yazan özellikler (SSPR parola geri yazma) ek yetki gerektirir; kapsamı denetlenmeli.

## 3. Pratik Uygulama

### Senkronizasyon durumunu inceleme (Connect sunucusunda)
```powershell
Import-Module ADSync

# Scheduler durumu ve senkron döngüsü
Get-ADSyncScheduler | Select-Object SyncCycleEnabled, NextSyncCyclePolicyType, StagingModeEnabled

# Connector'lar (on-prem AD + Entra)
Get-ADSyncConnector | Select-Object Name, Type

# Elle tam senkron tetikle (dikkatli)
Start-ADSyncSyncCycle -PolicyType Initial   # veya Delta
```

### ImmutableID / eşleme doğrulama
```powershell
# On-prem kullanıcının objectGUID → ImmutableID karşılığı
$u = Get-ADUser "aliveli" -Properties objectGUID
[System.Convert]::ToBase64String($u.objectGUID.ToByteArray())   # = ImmutableID (Base64)
```

### Senkron hesabı yetkisini denetleme (kritik)
```powershell
# AD DS Connector hesabının DCSync (Replicating Directory Changes) yetkisi var mı?
$acc = "CORP\MSOL_xxxxxxxx"   # Connect kurulumunun oluşturduğu hesap
(Get-Acl "AD:\DC=corp,DC=local").Access |
  Where-Object { $_.IdentityReference -like "*MSOL_*" -and
    $_.ObjectType -match '1131f6a[ad]-9c07-11d1-f79f-00c04fc2dcd2' } |
  Select-Object IdentityReference, ActiveDirectoryRights
# → bu hesap Tier 0; sunucusu ve parolası DC gibi korunmalı
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Connect sunucusunu Tier 0 yap:** DC ile eşdeğer koruma; ayrı, sıkılaştırılmış, PAW'dan yönetilen, izlenen bir sunucu → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).
- **Staging mode ile HA:** İkinci sunucu staging'de hazır; felakette hızlı devralma.
- **Kapsamı filtrele:** Yalnızca gerekli OU/nesneleri senkronla; sync kapsamını en aza indir.
- **ms-DS-ConsistencyGuid kullan:** Kalıcı sourceAnchor; forest birleştirme/taşımada dayanıklılık.
- **Senkron hesabı sırlarını koru:** Connect hesaplarının parolaları/anahtarları hassastır; Entra Connect Health ile izle.

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Connect sunucusunu sıradan sunucu gibi görmek:** Bu makine on-prem tüm hash'lere (PHS) ve bulut yazma yetkisine sahiptir — **Tier 0**dır. Ele geçirilirse hem domain hem tenant düşer → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).
- 🔴 **Senkron hesabının DCSync yetkisi:** PHS hesabı domain'in tüm parola hash'lerini çekebilir; parolası/sunucusu DC gibi korunmalı.
- ⚠️ **`.local` UPN ile buluta gitmek:** Bulutta çözülmez; yönlendirilebilir UPN son eki şart → [03.2](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.2_Hesap_Yonetimi.md).
- ⚠️ **Aşırı geniş sync kapsamı:** Gereksiz nesneleri buluta taşımak saldırı yüzeyini büyütür; filtrele.
- 🔍 **İzleme ipucu:** Connect sunucusunda olağandışı işlemler, senkron hesabıyla anormal LDAP/replikasyon ve Entra Connect Health uyarıları izlenmeli → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
