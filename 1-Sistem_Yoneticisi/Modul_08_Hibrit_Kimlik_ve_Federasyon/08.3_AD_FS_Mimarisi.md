# 08.3 — AD FS Mimarisi ve Operasyonu

## 1. Kavramsal Temel — Neden Var?

**AD FS (Active Directory Federation Services)**, on-prem AD kimliğini dış/bulut uygulamalarına **federation token** (SAML/WS-Fed/OAuth) olarak sunan bir kimlik sağlayıcıdır (IdP). Kullanıcı bir uygulamaya girmek isteyince, uygulama "kimliğini AD FS'ten al" der; AD FS kullanıcıyı AD'de doğrular ve içine **claim**'ler (kim, hangi gruplar, hangi öznitelikler) koyduğu **imzalı bir token** üretir. Uygulama bu imzaya güvenir.

> **Neden hâlâ öğreniyoruz — ama dikkatle?** AD FS güçlü ama **büyük saldırı yüzeyidir**: token imzalama sertifikası çalınırsa **Golden SAML** ([08.2](./08.2_Kimlik_Dogrulama_PHS_PTA_Federation.md)) ile tüm kimlikler taklit edilir. Modern eğilim AD FS'ten **PHS + bulut kimlik (Entra)**'a geçmektir. Bu dosya hem operasyonu hem de "neden emekliye ayrılmalı"yı anlatır.

## 2. Teknik Derinlik

### 2.1 Token akışı (WS-Fed/SAML) — uçtan uca

```
  ①İstek            ②Yönlendir        ③Kimlik doğrula      ④İmzalı token       ⑤Güven
Kullanıcı ─────► Uygulama ───────► WAP (DMZ) ───────► AD FS ───────► Uygulama
 (tarayıcı)      (RPT sahibi)      ters proxy         │  AD'de       │ token imzayı
    ▲                                                  │  doğrula     │ doğrular → erişim
    │                                                  ▼
    │                                    ┌──────────────────────────┐
    │                                    │ Claims Pipeline:         │
    │                                    │ Acceptance → Transform → │
    │                                    │ Issuance (grup/öznitelik)│
    │                                    └──────────┬───────────────┘
    │                                               ▼
    └───────────────── SAML/JWT token ◄── TOKEN SIGNING CERT ile İMZALANIR
                        (claim'ler + imza)     ▲
                                    Bu özel anahtar çalınırsa → Golden SAML
```

### 2.1 Bileşenler

- **Federation Server (AD FS farm):** Token üreten çekirdek. HA için çiftlik (farm) + yük dengeleyici.
- **Web Application Proxy (WAP):** DMZ'de duran, dış kullanıcıları iç AD FS'e güvenli ileten ters proxy (AD FS sunucularını doğrudan internete açmamak için).
- **Configuration database:** WID (Windows Internal Database) veya SQL — farm yapılandırması, relying party trust'lar.
- **Relying Party Trust (RPT):** AD FS'in token verdiği her uygulama/servis (örn. Entra ID, üçüncü-parti SaaS) bir RPT'dir.
- **Claims Rules:** Hangi AD özniteliklerinin/gruplarının token'a nasıl aktarılacağını belirleyen kurallar (claim pipeline: acceptance → transform → issuance).

### 2.2 En kritik varlık: Token Signing Certificate

- AD FS her token'ı **token signing certificate**'ın özel anahtarıyla imzalar. Uygulamalar bu imzayla token'ın gerçekliğine güvenir.
- **Golden SAML:** Bu özel anahtar (ve AD FS'in DKM master key'i) çalınırsa, saldırgan **AD FS'e hiç dokunmadan**, istediği kullanıcı ve claim'lerle **geçerli imzalı token** üretir — MFA dahil her kontrolü atlar → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/). Bu yüzden token signing anahtarı **en yüksek değerli sırlardan** biridir.
- **DKM (Distributed Key Manager):** AD FS, token signing özel anahtarını AD içinde (bir konteynerde) şifreli tutar; şifre çözme anahtarı (DKM master key) belirli bir AD nesnesindedir. Golden SAML bu ikisini birlikte hedefler.

### 2.3 Operasyon: sertifika rollover ve yama

- **Otomatik sertifika yenileme (AutoCertificateRollover):** AD FS token signing/decryption sertifikalarını otomatik yeniler. Yenilemede **Entra ile federation metadata senkron** kalmalı (aksi halde token doğrulama kırılır).
- **Extranet Lockout / Smart Lockout:** WAP üzerinden gelen brute-force'a karşı hesap kilitleme koruması; yapılandırılmalı.
- **Yama ve sürüm:** AD FS geçmişte kritik zafiyetler barındırdı; güncel tutulması ve internete yalnızca WAP üzerinden açılması şart.

## 3. Pratik Uygulama

### AD FS sağlık ve yapılandırma
```powershell
# AD FS servis ve özellikleri
Get-AdfsProperties | Select-Object HostName, AutoCertificateRollover, ExtranetLockoutEnabled

# Token signing/decryption sertifikaları (parmak izleri ve süreler)
Get-AdfsCertificate -CertificateType Token-Signing
Get-AdfsCertificate -CertificateType Token-Decrypting

# Relying party trust'lar (kime token veriliyor)
Get-AdfsRelyingPartyTrust | Select-Object Name, Identifier, Enabled
```

### Token signing sertifikasını koruma/rollover
```powershell
# Manuel sertifika rollover (planlı; Entra metadata güncellemesi gerekir)
Update-AdfsCertificate -CertificateType Token-Signing -Urgent:$false

# Entra tarafında federation metadata güncelle (rollover sonrası)
# Update-MgDomainFederationConfiguration ... (Graph)
```

### Extranet lockout (brute-force savunması)
```powershell
Set-AdfsProperties -EnableExtranetLockout $true `
  -ExtranetLockoutThreshold 5 -ExtranetObservationWindow (New-TimeSpan -Minutes 30)
```

### Federation'dan PHS'e geçiş (emeklilik yolu)
```text
Yön: AD FS → PHS + Seamless SSO (08.4).
1) Entra Connect'te PHS'i etkinleştir (yedek olarak zaten açık olmalı).
2) Domain'i Federated → Managed'a çevir (Graph/MSOnline).
3) AD FS RPT'lerini/altyapısını kademeli emekliye ayır.
Kritik/planlı değişiklik; test şart.
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **AD FS = Tier 0:** Federation sunucuları, WID/SQL ve token signing anahtarı DC ile eşdeğer korunmalı → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).
- **İnternete yalnızca WAP ile aç:** AD FS sunucularını doğrudan internete koyma; DMZ'de WAP kullan.
- **Token signing anahtarını izle ve koru:** DKM master key erişimini denetle; anahtar erişimi Golden SAML'in ön koşuludur.
- **Extranet lockout + MFA:** Brute-force ve token çalma senaryolarına karşı katman.
- **Emeklilik planı:** Gerçek gereksinim yoksa AD FS'ten PHS + Entra bulut kimliğe geçişi hedefle — saldırı yüzeyini küçültür.

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Token signing anahtarını yeterince korumamak:** Golden SAML'in tek şartı bu anahtar (+ DKM). Ele geçerse tüm federated kimlikler ve MFA atlanır → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).
- 🔴 **AD FS'i doğrudan internete açmak:** Saldırı yüzeyi ve brute-force riski; WAP + extranet lockout kullan.
- ⚠️ **Sertifika rollover ile metadata senkronunu kaçırmak:** Token doğrulama kırılır, federated oturum açma durur.
- ⚠️ **AD FS'i güncellememek:** Geçmiş kritik zafiyetler; yama şart.
- 🔍 **İzleme ipucu:** Token signing sertifikası/DKM erişimi, RPT değişiklikleri, olağandışı token üretimi ve extranet lockout olayları izlenmeli → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
