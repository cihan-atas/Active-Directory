## 1. Kavramsal Temel — Neden Var?

Hibrit ortamda kullanıcı ideal olarak **domain'e giriş yaptığında bulut uygulamalarına da tekrar parola sormadan** erişmeli (Single Sign-On). Bunu sağlayan mekanizma, cihazın **bulut kimliğine nasıl bağlandığına** bağlıdır:

- **Modern cihazlar (Hybrid Azure AD Join / Entra Join):** PRT (Primary Refresh Token) ile sorunsuz bulut SSO — tercih edilen yol.
- **Eski/basit senaryolar (Seamless SSO / SSSO):** AD FS kurmadan, PHS/PTA ile birlikte kullanılan bir Kerberos-tabanlı SSO özelliği.

> **Neden güvenlik kritik?** Seamless SSO, arka planda **`AZUREADSSOACC$`** adlı bir bilgisayar hesabı oluşturur ve buna dayanır. Bu hesabın Kerberos anahtarı çalınırsa, saldırgan **bulut için Silver Ticket** üretip herhangi bir kullanıcının SSO'sunu taklit edebilir → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/). Bu hesap özel korunmalı ve anahtarı düzenli döndürülmelidir.

## 2. Teknik Derinlik

### 2.1 Seamless SSO (SSSO) mekaniği

- **Kurulum:** Entra Connect kurarken "Enable single sign-on" seçilir; on-prem AD'de **`AZUREADSSOACC$`** bilgisayar hesabı oluşur ve Entra'ya kaydedilir.
- **Nasıl çalışır (Kerberos akışı):**

```
  Domain'e katılı istemci                on-prem KDC (DC)            Entra ID
  ┌──────────────────┐                   ┌──────────────┐          ┌──────────┐
  │ 1. Bulut app'e   │                   │              │          │          │
  │    git → Entra   │──"SSO dene"──────────────────────────────► │ 401 +    │
  │                  │◄─────────────────────────────────────────── │ Kerberos │
  │ 2. AZUREADSSOACC │──TGS-REQ (SPN)───►│ 3. Servis    │          │ iste     │
  │    için bilet al │◄──servis bileti───│ bileti ver   │          │          │
  │                  │   (AZUREADSSOACC$ │  (bu hesabın │          │          │
  │ 4. Bileti Entra'ya│   anahtarıyla    │   anahtarıyla│          │          │
  │    sun ──────────┼───şifreli)────────┼─────────────────────► │ 5. Bileti│
  │                  │                   │              │          │ çöz→ ✓   │
  └──────────────────┘                   └──────────────┘          └──────────┘
   ⚠️ Entra, bileti AZUREADSSOACC$ hesabının paylaşılan anahtarıyla çözer.
      Bu anahtar saldırganın elindeyse, kendi "geçerli" biletini üretir → Silver Ticket.
```

  Kısaca: tarayıcı `AZUREADSSOACC` için bir **Kerberos servis bileti** alır ve Entra'ya sunar; Entra bileti bu hesabın paylaşılan anahtarıyla doğrulayıp kullanıcıyı parolasız içeri alır.
- ⚠️ **Kritik risk:** `AZUREADSSOACC$` hesabının **parolası/Kerberos anahtarı otomatik dönmez** (varsayılan) ve statik kalabilir. Bu anahtar (NTLM hash / AES key) ele geçirilirse, **her kullanıcı için Silver Ticket** ([Red M09'daki bilet forge mantığı → hibrit varyant]) üretilip bulut SSO taklit edilir → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/). Bu hesabın anahtarı **düzenli döndürülmelidir** (rollover script'i ile).

### 2.2 Hybrid Azure AD Join ve PRT

- **Hybrid Join:** On-prem domain'e katılı cihazlar, aynı zamanda Entra ID'ye de kaydedilir (SCP / Entra Connect ile). Kullanıcı domain'e girince cihaz bir **PRT (Primary Refresh Token)** alır; bu PRT bulut uygulamalarına sorunsuz SSO sağlar.
- **PRT güvenliği:** PRT cihazın TPM'inde korunur; çalınması (token theft) güçlü bir bulut erişim yoludur → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/). Cihaz uyumluluğu ve koşullu erişim ile korunur.
- **Modern yön:** Yeni cihazlar için **Microsoft Entra Join** (salt bulut katılım) tercih edilir; Hybrid Join geçiş dönemi/eski uygulama bağımlılıkları içindir.

### 2.3 SSO seçimi

| Yöntem | Ne zaman | Not |
|--------|----------|-----|
| **Entra Join + PRT** | Yeni/modern cihazlar | En temiz bulut-öncelikli SSO |
| **Hybrid Azure AD Join** | On-prem bağımlılığı olan cihazlar | Geçiş; PRT ile SSO |
| **Seamless SSO (SSSO)** | AD FS'siz, eski tarayıcı/senaryo | `AZUREADSSOACC$` anahtar rotasyonu şart |

## 3. Pratik Uygulama

### Seamless SSO durumu ve hesap kontrolü
```powershell
# Seamless SSO etkin mi? (Connect sunucusu)
Import-Module "$env:ProgramFiles\Microsoft Azure Active Directory Connect\AzureADSSO.psd1"
# New-AzureADSSOAuthenticationContext / Get-AzureADSSOStatus (kimlik doğrulama gerektirir)

# AZUREADSSOACC$ bilgisayar hesabını ve parolasının yaşını gör (rotasyon takibi)
Get-ADComputer "AZUREADSSOACC" -Properties PasswordLastSet, whenChanged |
  Select-Object Name, PasswordLastSet, whenChanged
```

### AZUREADSSOACC anahtarını döndürme (kritik güvenlik görevi)
```powershell
# Seamless SSO Kerberos decryption key rollover (Connect sunucusunda)
Import-Module "$env:ProgramFiles\Microsoft Azure Active Directory Connect\AzureADSSO.psd1"
$c = New-AzureADSSOAuthenticationContext          # global admin kimlik doğrulaması
Update-AzureADSSOForest -OnPremCredentials (Get-Credential)   # anahtarı yeniler
# → Bu görev periyodik (ör. 30 günde bir) yapılmalı; statik anahtar = Silver Ticket riski.
```

### Hybrid Join doğrulama (istemcide)
```powershell
# Cihazın join durumu: AzureAdJoined / DomainJoined / PRT
dsregcmd /status
# → 'AzureAdJoined : YES', 'DomainJoined : YES', 'AzureAdPrt : YES' bakılır
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Modern cihaz için Entra Join:** Yeni cihazları bulut-öncelikli katılımla kur; Hybrid Join'i geçiş/bağımlılık için sakla.
- **Seamless SSO kullanıyorsan anahtarı döndür:** `AZUREADSSOACC$` Kerberos anahtarını **düzenli rotasyona** al (statik anahtar = Silver Ticket riski) → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).
- **Koşullu Erişim + cihaz uyumluluğu:** PRT/token çalma senaryolarına karşı cihaz uyumluluğu, MFA ve oturum kontrolleri.
- **AZUREADSSOACC$'ı özel koru:** Bu hesabın hash'ine erişebilecek yolları (DC uzlaşması, DCSync) izle; hesabı ayrıcalıklı varlık gibi ele al.

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **AZUREADSSOACC$ anahtarını hiç döndürmemek:** Statik Kerberos anahtarı, ele geçirilirse **her kullanıcı için bulut SSO Silver Ticket** üretir. Düzenli rotasyon şart → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).
- 🔴 **PRT'yi korumasız bırakmak:** Cihazdan PRT çalınması güçlü bir bulut erişimidir; TPM + cihaz uyumluluğu + koşullu erişim gerekir.
- ⚠️ **Koşullu Erişim/MFA'sız SSO:** SSO kolaylık sağlar ama tek başına kimlik güvenliği değildir; MFA/koşullu erişim katmanı zorunlu.
- 🔍 **İzleme ipucu:** `AZUREADSSOACC$` parola yaşı, olağandışı Kerberos bilet istekleri, PRT/token anomalileri ve yeni cihaz kayıtları izlenmeli → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
