# 04.3 — Pratik Uygulamalar: Güvenlik Politikaları, ADMX/Central Store, GPP

> **Modül:** 04 — Grup İlkeleri (GPO) · **Kol:** Sistem Yöneticisi
> **Ön koşul:** [04.2 — Hedefleme ve Filtreleme](./04.2_Hedefleme_ve_Filtreleme.md) · **Sonraki:** [04.4 — Sorun Giderme ve Analiz](./04.4_Sorun_Giderme_ve_Analiz.md)

## 1. Kavramsal Temel — Neden Var?

Mekanizmayı ([04.1](./04.1_GPO_Mimarisi_ve_Isleyis.md)/[04.2](./04.2_Hedefleme_ve_Filtreleme.md)) öğrendik; şimdi **GPO ile gerçekte ne yapılır?** Dört ana kullanım alanı:

1. **Güvenlik Politikaları** — parola/kilitleme, kullanıcı hakları, denetim, kısıtlı gruplar. (Sertleştirmenin motoru.)
2. **Administrative Templates (ADMX/ADML)** — Windows ve uygulama davranışlarının binlerce registry-tabanlı ayarı; **Central Store** ile merkezî yönetilir.
3. **Group Policy Preferences (GPP)** — sürücü eşleme, yazıcı, kısayol, registry, zamanlanmış görev gibi "tercih" ayarları (kullanıcı değiştirebilir).
4. **Yazılım Dağıtımı** — MSI ile (büyük ölçüde eskimiş; modern alternatif Intune/SCCM).

Bu dosya aynı zamanda AD'nin **en ünlü GPO zafiyetini** (GPP cpassword) da içerir — çünkü "pratik uygulama" derken güvenli pratiği de öğretmeliyiz.

## 2. Teknik Derinlik

### 2.1 Güvenlik Politikaları (Security Settings)

`Computer Configuration → Policies → Windows Settings → Security Settings` altında:

- **Account Policies** (parola/kilitleme/Kerberos) — domain hesapları için **yalnızca domain seviyesinde** etkir ([04.1](./04.1_GPO_Mimarisi_ve_Isleyis.md) §2.7); istisna FGPP → [03.4](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md).
- **User Rights Assignment** — "Log on as a service", "Allow log on through RDP", "Deny log on locally" gibi ayrıcalıklar. **Tier Model'in uygulanma yeri**: örn. Tier 0 hesaplarının Tier 1/2 makinelere oturum açmasını *Deny* ile engellersin → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).
- **Restricted Groups / Group Policy'de grup üyeliği** — bir yerel grubun (örn. yerel Administrators) üyeliğini GPO ile dayatma. Modern alternatif GPP "Local Users and Groups" (daha esnek).
- **Security Options** — SMB signing, LDAP signing, NTLM kısıtlama, UAC gibi yüzlerce sertleştirme anahtarı → [Blue M08](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/).
- **Audit Policy / Advanced Audit Policy** — hangi olayların loglanacağı → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).

### 2.2 Administrative Templates ve Central Store (ADMX/ADML)

- **ADMX** dosyaları ayarın *tanımını* (registry yolu, seçenekler), **ADML** ise *dile özgü etiketleri* taşır. Bunlar bir ayarın nasıl göründüğünü ve nereye yazacağını belirler.
- **Sorun:** ADMX'ler varsayılan olarak her yöneticinin **kendi bilgisayarında** (`C:\Windows\PolicyDefinitions`) durur. Farklı sürümdeki makinelerden GPO düzenleyen yöneticiler tutarsız/eksik ayar görür.
- **Çözüm — Central Store:** SYSVOL'de merkezî bir `PolicyDefinitions` klasörü oluşturursun:
  `\\corp.local\SYSVOL\corp.local\Policies\PolicyDefinitions\`
  GPMC bu klasör varsa **oradan** ADMX okur; tüm yöneticiler aynı, güncel şablon setini görür. Yeni Windows/Office sürümleri çıktıkça yeni ADMX'ler buraya eklenir.

### 2.3 Group Policy Preferences (GPP)

GPP, "Policies" altındaki katı ayarların aksine **tercihlerdir**: uygulanır ama kullanıcı sonradan değiştirebilir (bazıları "apply once" veya "her yenilemede yeniden uygula" ayarlanabilir). Kapsamı geniştir:

- Drive Maps (sürücü eşleme), Printers, Shortcuts
- Registry, Environment, Files, Folders
- Scheduled Tasks, Services, **Local Users and Groups**
- Her öğe **Item-Level Targeting** ([04.2](./04.2_Hedefleme_ve_Filtreleme.md)) ile ayrı hedeflenebilir.

### 2.4 ⚠️ GPP cpassword — Meşhur zafiyet (MS14-025)

Eskiden GPP ile bir yerel hesap oluşturup **parolasını** GPP içinde saklayabiliyordun (örn. yerel admin parolası dağıtmak için). Bu parola SYSVOL'deki XML dosyasına (`Groups.xml`, `Services.xml`, `ScheduledTasks.xml`, `Drives.xml`) **`cpassword`** alanında yazılırdı — **AES-256 ile şifreli ama Microsoft anahtarı herkese açık yayınladığı için pratikte düz metin.** SYSVOL herkesçe okunabildiğinden, herhangi bir authenticated user bunu okuyup çözebilir.

- **MS14-025 (2014):** Yeni cpassword *oluşturma* yeteneğini kaldırdı — ama **eski/mevcut** GPP dosyalarındaki cpassword'ler SYSVOL'de kalmaya devam eder.
- **Saldırı:** `findstr /S cpassword \\corp.local\SYSVOL\*.xml` veya PowerView `Get-GPPPassword` → anında parola. Bu, en kolay ilk-erişim/yetki-yükseltme yollarından biridir → [Red M03](../../3-Red_Team/Modul_03_Kimlik_Bilgisi_Erisimi/), [Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/).
- **Doğru çözüm:** Yerel admin parolası dağıtımı için GPP **asla** kullanılmaz — **LAPS/Windows LAPS** kullanılır → [Blue M03](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/). Mevcut cpassword artıkları SYSVOL'den temizlenmelidir.

## 3. Pratik Uygulama

### Central Store kurma ve doğrulama
```powershell
# Central Store oluştur (yerel PolicyDefinitions'ı SYSVOL'e kopyala)
$dst = "\\corp.local\SYSVOL\corp.local\Policies\PolicyDefinitions"
New-Item -ItemType Directory -Path $dst -Force
Copy-Item "C:\Windows\PolicyDefinitions\*" -Destination $dst -Recurse -Force
# (dil klasörü de, örn. en-US / tr-TR)

# GPMC artık Central Store kullanıyor mu? GPO düzenlerken
# "Administrative Templates: Policy definitions (ADMX files) retrieved from the central store" yazmalı.
Test-Path $dst
```

### Güvenlik ayarı örneği: User Rights (Tier ayrımı)
```powershell
# Örnek yaklaşım (GUI: Computer Config → Windows Settings → Security Settings → Local Policies → User Rights):
# "Deny log on locally" ve "Deny log on through Remote Desktop Services" içine
# Tier 0 gruplarını ekleyerek düşük katman makinelere admin oturumunu engelle.
# PowerShell tarafında secedit/GPO API veya DSC ile yönetilir (bkz. Modül 09).
```

### GPP cpassword denetimi (savunma amaçlı tarama)
```powershell
# SYSVOL'de cpassword artığı var mı? (temizlenmeli)
Select-String -Path "\\corp.local\SYSVOL\corp.local\Policies\*\*\*.xml" -Pattern "cpassword" -SimpleMatch |
  Select-Object Path
# Bulunursa: ilgili GPP öğesini kaldır ve LAPS'e geç (Blue M03).
```

### GPP ile sürücü eşleme (GUI yolu)
`gpmc.msc` → GPO → `User Configuration → Preferences → Windows Settings → Drive Maps` → New → sürücü harfi + UNC yol → **Common → Item-level targeting** ile hedefle.

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Central Store'u ilk gün kur:** Tutarlı ADMX yönetimi için standarttır; yeni OS/Office sürümlerinin ADMX'lerini düzenli ekle.
- **Sertleştirmeyi GPO baseline'ı ile dağıt:** Microsoft Security Baselines / CIS / STIG içeriğini GPO'ya aktar; domain seviyesinde Enforced → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/), [Blue M08](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/).
- **GPP'ye asla sır koyma:** Parola/anahtar GPP'de saklanmaz. Yerel admin için LAPS, servis için gMSA ([03.4](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md)).
- **Yazılım dağıtımı için modern araç:** GPO-MSI eskidir; ölçekte Intune/SCCM tercih et. GPO'yu yapılandırma/sertleştirme için kullan.
- **User Rights = Tier Model uygulama noktası:** Katmanlar arası oturum açmayı Deny politikalarıyla dayat.

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **GPP cpassword bırakmak:** SYSVOL'de kalan herhangi bir `cpassword`, authenticated user tarafından çözülüp düz metin parolaya döner. Düzenli tara ve temizle; LAPS'e geç → [Red M03](../../3-Red_Team/Modul_03_Kimlik_Bilgisi_Erisimi/), [Blue M03](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/).
- ⚠️ **Central Store olmadan çok yöneticili ortam:** Tutarsız ADMX → bazı ayarlar görünmez/yanlış; "ben bu ayarı göremiyorum" karmaşası.
- ⚠️ **Restricted Groups'u yanlış kullanmak:** "Members" modu grubun üyeliğini **tamamen değiştirir** (var olanları siler). İstemeden yerel admin gruplarını boşaltabilirsin; dikkatli kullan veya GPP Local Groups tercih et.
- ⚠️ **Sertleştirme ayarını test etmeden dayatmak:** SMB/LDAP signing, NTLM kısıtlama gibi ayarlar yanlış uygulanırsa uygulama/erişim kırar; pilot OU'da test et → [Blue M08](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/).
- 🔍 **İzleme ipucu:** SYSVOL'e GPP dosya ekleme/değişiklikleri, yeni Scheduled Task/Service GPP öğeleri (kod çalıştırma yolu) izlenmeli; olağandışı GPP başlangıç görevi kalıcılık işareti olabilir → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
