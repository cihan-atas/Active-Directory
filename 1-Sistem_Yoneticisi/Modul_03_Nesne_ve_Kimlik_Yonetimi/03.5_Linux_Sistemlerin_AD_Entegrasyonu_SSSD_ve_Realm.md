## 1. Genel Bakış ve Mimari

Modern kurumsal ortamlarda kritik iş yükleri (PostgreSQL, Oracle, Nginx, Docker, Kubernetes worker düğümleri) ağırlıklı olarak Linux üzerinde barındırılır. Bu sistemlerin yerel `/etc/passwd` ve `/etc/shadow` dosyaları üzerinden tekil hesaplarla yönetilmesi; merkezi denetim, parola rotasyonu ve işten ayrılan personelin yetkilerinin iptal edilmesi süreçlerinde büyük güvenlik açıkları doğurur.

Active Directory, kurumsal Linux sunucular için de tek ve merkezi kimlik sağlayıcı (Single Source of Truth) olarak konumlandırılmalıdır. Günümüzde Linux sistemleri etki alanına dahil etmek için endüstri standardı yöntem **`realmd` ve `SSSD (System Security Services Daemon)`** ikilisidir.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       LINUX - ACTIVE DIRECTORY MİMARİSİ                     │
└─────────────────────────────────────────────────────────────────────────────┘
  [ Kullanıcı / SSH İstemcisi ]
               │
               ▼
  [ Linux PAM (Pluggable Authentication Modules) & NSS (Name Service Switch) ]
               │
               ▼
  [ SSSD (System Security Services Daemon) ]
       │                                │
       ├─► [ Kerberos (MIT krb5) ]      ├─► [ LDAP / AD WS ]
       │   - Port 88 (TCP/UDP)          │   - Port 389 / 636 (LDAPS)
       │   - TGT & TGS Bilet Değişimi   │   - Kullanıcı, Grup ve UID/GID Eşleme
       │   - /etc/krb5.keytab (Makine)  │   - GPO Erişim Denetimi
       │                                │
       ▼                                ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                 ACTIVE DIRECTORY ETKİ ALANI DENETLEYİCİSİ                   │
│                                                                             │
│   - Bilgisayar Hesabı: CN=LINUX01,OU=Linux,DC=corp,DC=local                 │
│   - Kimlik Sağlayıcı (Kerberos KDC)                                         │
│   - Güvenlik Grupları (Linux Admins -> Sudo Yetkisi)                       │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Temel Entegrasyon Bileşenleri:
1. **`realmd`:** Etki alanı keşfi, Kerberos yapılandırması ve Active Directory katılımını (join) tek komutla basitleştiren D-Bus tabanlı orkestrasyon aracı.
2. **`SSSD`:** Kimlik bilgilerini (NSS) ve kimlik doğrulamasını (PAM) yöneten; çevrimdışı önbellekleme (offline caching) ve GPO kural işletimi sunan ana servis.
3. **`adcli`:** Active Directory bilgisayar hesaplarını oluşturan, parola rotasyonunu yapan ve `/etc/krb5.keytab` anahtar kovanını yöneten arka plan aracı.
4. **`chrony / systemd-timesyncd`:** Kerberos protokolünün azami 5 dakikalık saat farkı toleransı (Clock Skew) nedeniyle zorunlu olan zaman senkronizasyon servisi.

## 2. Ön Hazırlıklar: Ağ, DNS ve NTP Senkronizasyonu

Etki alanına dahil etmeden önce Linux sunucunun DNS ve zaman ayarları Active Directory etki alanı denetleyicileriyle tam uyumlu olmalıdır.

### 2.1. DNS Çözümleme Yapılandırması (`/etc/resolv.conf`)

Linux sunucu, AD etki alanı SRV kayıtlarını (`_ldap._tcp.corp.local`, `_kerberos._tcp.corp.local`) çözebilmek için doğrudan Etki Alanı Denetleyicisini (DC) DNS sunucusu olarak görmelidir:

```bash
# /etc/resolv.conf veya netplan / NetworkManager üzerinden DNS tanımlama
cat << 'EOF' > /etc/resolv.conf
nameserver 10.0.0.10
nameserver 10.0.0.11
search corp.local
EOF
```

### 2.2. NTP Zaman Senkronizasyonu (Chrony)

```bash
# 1. Chrony paketini kurma
apt install -y chrony # veya dnf install -y chrony

# 2. /etc/chrony/chrony.conf içine etki alanı denetleyicisini ekleme
echo "server dc01.corp.local iburst" >> /etc/chrony/chrony.conf
systemctl restart chrony
chronyc tracking
```

## 3. Etki Alanına Dahil Etme (Domain Join)

### 3.1. Gerekli Paketlerin Kurulumu

```bash
# Ubuntu / Debian için:
apt update && apt install -y realmd sssd sssd-tools libnss-sss libpam-sss adcli krb5-user packagekit

# RHEL / Rocky Linux / AlmaLinux için:
dnf install -y realmd sssd adcli krb5-workstation oddjob oddjob-mkhomedir samba-common-tools
```

### 3.2. Etki Alanı Keşfi ve Katılım (`realm`)

```bash
# 1. Etki alanını ağ üzerinden keşfetme
realm discover corp.local

# 2. Belirli bir OU hedefleyerek etki alanına dahil etme
realm join --user=Administrator --computer-ou="OU=Linux Servers,DC=corp,DC=local" corp.local
```

Katılım tamamlandığında:
- Active Directory üzerinde `CN=LINUX01,OU=Linux Servers,DC=corp,DC=local` bilgisayar nesnesi açılır.
- Sunucuda `/etc/krb5.keytab` oluşturulur ve içine `LINUX01$@CORP.LOCAL` SPN anahtarları işlenir.

## 4. Güvenli SSSD ve Erişim Yapılandırması

### 4.1. `/etc/sssd/sssd.conf` Sertleştirilmiş Şablonu

```ini
[sssd]
domains = corp.local
config_file_version = 2
services = nss, pam

[domain/corp.local]
default_shell = /bin/bash
krb5_store_password_if_offline = True
cache_credentials = True
krb5_realm = CORP.LOCAL
realmd_tags = manages-system joined-with-adcli 
id_provider = ad
auth_provider = ad
chpass_provider = ad
access_provider = ad

# GPO TABANLI ERİŞİM KONTROLÜNÜ ZORUNLU KIL
ad_gpo_access_control = enforcing

# KISA KULLANICI ADLARI (domain\ olmadan sadece 'jdoe' ile oturum)
use_fully_qualified_names = False
fallback_homedir = /home/%u

# GÜVENLİK İÇİN BİLETLERİ KCM ÇEKİRDEK BELLEĞİNDE SAKLA
krb5_ccachedir = /run/user/%U
```

```bash
# SSSD dosya izinlerini 0600 yaparak servisi yeniden başlatma
chmod 0600 /etc/sssd/sssd.conf
systemctl restart sssd
```

### 4.2. İlk Girişte Otomatik Ev Dizini Oluşturma (mkhomedir)

```bash
# PAM mkhomedir modülünü aktifleştirme (Ubuntu/Debian)
pam-auth-update --enable mkhomedir

# RHEL tabanlı sistemlerde:
authselect select sssd with-mkhomedir --force
systemctl enable --now oddjobd.service
```

## 5. Sudo Yetkilerinin Active Directory Gruplarına Devredilmesi

Linux sunucularda root yetkisi gerektiren komutları yönetmek için yerel kullanıcı oluşturmak yerine doğrudan AD Güvenlik Grupları yetkilendirilir.

```bash
# /etc/sudoers.d/active_directory dosyasını oluşturma
cat << 'EOF' > /etc/sudoers.d/active_directory
# "Linux_Admins" AD grubu üyelerine tüm sunucuda tam root hakkı tanıma
%Linux_Admins ALL=(ALL:ALL) ALL

# "DevOps_Team" grubuna sadece servisleri yeniden başlatma hakkı tanıma
%DevOps_Team ALL=(ALL) /bin/systemctl restart nginx, /bin/systemctl status nginx
EOF

# Dosya iznini 0440 olarak ayarlama
chmod 0440 /etc/sudoers.d/active_directory
visudo -c
```

## 6. Erişim Kısıtlama ve Oturum Filtreleme

Varsayılan olarak tüm etki alanı kullanıcıları sunucuya SSH yapabilir. Bunu sadece yetkili ekiplerle sınırlandırmak şarttır:

```bash
# Yalnızca belirli bir AD grubunun oturum açmasına izin verme
realm permit -g "Linux_Admins" "DevOps_Team"

# Tüm diğer kullanıcıları engelle
realm deny --all
```

## 7. Sorun Giderme ve Bakım (Troubleshooting)

| Sorun | Neden | Çözüm |
|---|---|---|
| `Cannot contact any KDC for realm` | DNS SRV kayıtları çözümlenemiyordur veya Port 88 kapalıdır. | `nslookup -type=srv _kerberos._tcp.corp.local` çıktısını ve güvenlik duvarını kontrol edin. |
| `Clock skew too great (37)` | Linux ile DC arasındaki saat farkı 5 dakikayı aşmıştır. | `chronyc sources` ile DC'ye senkronize olun: `chronyd -q 'server dc01.corp.local iburst'`. |
| `AD kullanıcısı id komutunda görünmüyor` | SSSD önbelleği eskidir veya servis durmuştur. | Önbelleği temizleyip yeniden başlatın: `sss_cache -E && systemctl restart sssd`. |
| `Makine hesabı parolası süresi doldu` | adcli otomatik parola yenilemeyi yapamamıştır. | Parolayı ve keytab'ı manuel yenileyin: `adcli update --computer-password-lifetime=30`. |
