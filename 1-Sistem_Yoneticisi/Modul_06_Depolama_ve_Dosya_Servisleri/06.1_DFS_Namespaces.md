# 06.1 — DFS Namespaces (DFS-N) Tasarımı

## 1. Kavramsal Temel — Neden Var?

Kullanıcılar dosya paylaşımlarına genelde `\\FS01\Muhasebe` gibi **fiziksel sunucu adıyla** bağlanır. Bu kırılgandır: sunucu değişirse (`FS01` → `FS05`), taşınırsa, ya da farklı lokasyonlarda kopyaları varsa, tüm kullanıcıların kısayolları/haritaları bozulur. Ayrıca kullanıcı "en yakın kopyaya" nasıl yönlendirilir?

**DFS Namespaces (DFS-N)**, fiziksel paylaşımların önüne **sanal bir isim alanı** koyar:

```
Kullanıcı görür:   \\corp.local\Paylasim\Muhasebe   (mantıksal, sabit)
                              │
                    DFS-N yönlendirir ▼ (site farkındalıklı)
Gerçek hedefler:   \\FS01\Muhasebe   (Ankara)
                   \\FS05\Muhasebe   (İzmir — DFS-R kopyası)
```

Kullanıcı hep aynı sanal yolu kullanır; DFS-N onu **en uygun fiziksel hedefe** (site/maliyet farkındalıklı) yönlendirir. Sunucu değişse bile kullanıcı yolu değişmez.

> **DFS-N ≠ DFS-R.** DFS-N *isim alanı ve yönlendirme* sağlar (bu dosya). DFS-R ise hedefler arası *veri replikasyonu* yapar → [06.2](./06.2_DFS_R_Replikasyon.md). İkisi sık birlikte kullanılır (çoklu-lokasyon yüksek erişilebilirlik) ama ayrı servislerdir.

## 2. Teknik Derinlik

### 2.1 İki namespace türü

| Tür | Kök yolu | Metadata nerede | Ölçek/HA |
|-----|----------|-----------------|----------|
| **Domain-based** | `\\corp.local\Paylasim` | **AD'de** (Configuration NC / namespace nesnesi) + namespace sunucularında | Yüksek erişilebilirlik (birden çok namespace sunucusu), AD ile bulunur |
| **Standalone** | `\\FS01\Paylasim` | Yalnızca tek sunucunun registry'sinde | AD gerektirmez ama tek nokta arıza; failover cluster hariç |

Kurumsal AD ortamında neredeyse her zaman **domain-based** kullanılır — `\\domain\...` yolu AD ile çözülür, birden çok namespace sunucusuyla dayanıklıdır.

### 2.2 Yapı: Namespace → Folder → Folder Target

```
Namespace kökü:  \\corp.local\Paylasim
   └── Folder:    Muhasebe          (mantıksal klasör)
         ├── Folder Target: \\FS01\Muhasebe   (Ankara)
         └── Folder Target: \\FS05\Muhasebe   (İzmir)   ← DFS-R ile senkron
```

- **Folder Target:** Bir mantıksal klasörün arkasındaki gerçek paylaşım(lar). Birden çok hedef = yüksek erişilebilirlik + yük dağıtımı.
- **Referral:** İstemci namespace'e eriştiğinde DFS-N ona hedef listesini ("referral") döner; istemci sıradaki hedefe bağlanır.

### 2.3 Referral sıralama ve site farkındalığı

DFS-N, istemciyi **kendi site'ındaki** hedefe yönlendirmeye çalışır (site maliyeti → [02.1](../Modul_02_Fiziksel_Altyapi_ve_Replikasyon/02.1_Domain_Controller_ve_Site_Topolojisi.md)):

- **Lowest cost / site-aware:** İstemcinin site'ındaki hedef en üstte; yoksa en düşük maliyetli site.
- **Failover:** İlk hedef erişilemezse istemci listedeki bir sonrakine geçer.
- **Target priority:** Belirli hedefleri "ilk/son" olarak zorlayabilirsin.
- **Failback:** Yerel hedef geri geldiğinde istemcinin ona dönmesi (etkinleştirilmeli).

### 2.4 Access-Based Enumeration (ABE)

ABE açıkken, kullanıcı namespace/klasör listesinde **yalnızca erişim izni olduğu** klasörleri görür. Bu bir yetkilendirme değil (izin ACL'de) ama **bilgi ifşasını azaltır** — kullanıcı erişemeyeceği paylaşım adlarını bile görmez. Güvenlik hijyeni açısından önerilir.

## 3. Pratik Uygulama

### Domain-based namespace ve klasör oluşturma
```powershell
# Rol: File Server + DFS Namespaces
# Install-WindowsFeature FS-DFS-Namespace -IncludeManagementTools

# Domain-based namespace kökü (birden çok namespace sunucusu HA için)
New-DfsnRoot -TargetPath "\\FS01\Paylasim" -Type DomainV2 -Path "\\corp.local\Paylasim"
New-DfsnRootTarget -TargetPath "\\FS02\Paylasim" -Path "\\corp.local\Paylasim"   # ikinci namespace sunucusu

# Mantıksal klasör + iki hedef (çoklu-lokasyon)
New-DfsnFolder -Path "\\corp.local\Paylasim\Muhasebe" -TargetPath "\\FS01\Muhasebe"
New-DfsnFolderTarget -Path "\\corp.local\Paylasim\Muhasebe" -TargetPath "\\FS05\Muhasebe"
```

### Referral, öncelik ve ABE
```powershell
# Referral sıralama: en düşük maliyet + failback
Set-DfsnFolder -Path "\\corp.local\Paylasim\Muhasebe" `
  -EnableTargetFailback $true -ReferralPriorityClass SiteCostNormal

# Bir hedefi öncelikli/son yap
Set-DfsnFolderTarget -Path "\\corp.local\Paylasim\Muhasebe" -TargetPath "\\FS05\Muhasebe" `
  -ReferralPriorityClass GlobalLow

# Access-Based Enumeration'ı namespace'te aç
Set-DfsnRoot -Path "\\corp.local\Paylasim" -EnableAccessBasedEnumeration $true
```

### Namespace/hedef durumunu görme
```powershell
Get-DfsnRoot
Get-DfsnFolder -Path "\\corp.local\Paylasim\*"
Get-DfsnFolderTarget -Path "\\corp.local\Paylasim\Muhasebe" | Select-Object TargetPath, State, ReferralPriorityClass
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Domain-based (V2) kullan:** AD ile bulunan, çoklu namespace sunucusuyla dayanıklı yapı standarttır.
- **Mantıksal isimlendirme:** Namespace klasör adları organizasyona göre sabit ve anlamlı olmalı; kullanıcı bir daha fiziksel sunucu adı görmemeli.
- **Çoklu hedef + DFS-R = HA:** Yüksek erişilebilirlik ve yerel erişim için hedefleri farklı site'lara koy ve DFS-R ile senkronla → [06.2](./06.2_DFS_R_Replikasyon.md).
- **ABE'yi aç:** Bilgi ifşasını azaltır; kullanıcı yalnızca erişebildiğini görür.
- **İzinleri paylaşım+NTFS katmanında yönet (AGDLP):** Erişim DFS-N ile değil, hedef paylaşımın ACL'i ile kontrol edilir; Domain Local gruplarla ver → [03.3](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.3_Grup_Ustaligi_AGDLP.md).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- ⚠️ **Standalone namespace ile tek nokta arıza:** Kurumsal ortamda domain-based tercih et; standalone yalnızca özel durumlar/cluster için.
- ⚠️ **DFS-N'i erişim kontrolü sanmak:** DFS-N yönlendirmedir; gerçek yetkilendirme hedef paylaşımın **NTFS/paylaşım ACL'idir.** İzinleri orada, AGDLP ile ver.
- 🔴 **Açık paylaşımlar = keşif/kimlik bilgisi hazinesi:** DFS namespace'leri saldırgana tüm dosya sunucusu topolojisini ve içindeki paylaşımları sunar; `Snaffler`/PowerView paylaşımlarda gömülü parola/anahtar arar → [Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/). ABE + sıkı ACL + hassas veri hijyeni gerekir.
- 🔍 **İzleme ipucu:** Namespace/hedef değişiklikleri ve hassas paylaşımlara olağandışı erişim (dosya erişim denetimi) izlenmeli → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).
