## 1. Kavramsal Temel — Neden Var?

AD, izole bir ada değildir: İK sistemleri, kimlik yönetişimi (IGA) platformları, self-servis portallar ve bulut uygulamaları AD ile **entegre** olmalı — kullanıcı işe alındığında otomatik hesap, işten ayrıldığında otomatik devre dışı. Bu entegrasyon iki köprüden birini kullanır:

1. **On-prem AD ↔ LDAP/PowerShell:** Klasik, doğrudan dizin erişimi (Python `ldap3`, .NET, PowerShell → [09.1](./09.1_LDAP_Mimarisi_ve_Sorgulama.md)/[09.2](./09.2_PowerShell_AD_Modulu.md)).
2. **Entra ID ↔ Microsoft Graph REST API:** Modern bulut kimliği için standart (hibrit → [Modül 08](../Modul_08_Hibrit_Kimlik_ve_Federasyon/)).

Ayrıca yönetim arayüzü de modernleşti: **Windows Admin Center (WAC)**, `dsa.msc`/`gpmc.msc` gibi MMC araçlarını tarayıcı-tabanlı, merkezî bir panelde toplar.

> **Güvenlik ekseni:** Her entegrasyon bir **kimlik + yetki** taşır. Bir İK-AD provizyon servisi ya da bir Graph app registration, çok geniş yetki alırsa yeni bir saldırı yoluna dönüşür. Entegrasyon = otomasyon kolaylığı **+** yeni ayrıcalık yüzeyi.

## 2. Teknik Derinlik

### 2.1 İki entegrasyon dünyası

```
   ON-PREM AD (dizin)                         ENTRA ID (bulut)
  ┌──────────────────┐                      ┌──────────────────┐
  │  LDAP / LDAPS    │                      │ Microsoft Graph  │
  │  (389/636/3268)  │                      │  REST API (HTTPS)│
  └────────▲─────────┘                      └────────▲─────────┘
           │ ldap3 / .NET / PowerShell               │ OAuth2 token (app reg /
           │ (bind: Kerberos/LDAPS)                  │  service principal + scopes)
   ┌───────┴────────┐                        ┌───────┴────────┐
   │ İK sistemi,    │  provizyon/deprovizyon │ IGA, self-servis│
   │ IGA, scriptler │◄──────────────────────►│ portal, otomasyon│
   └────────────────┘                        └────────────────┘
      Hibrit: değişiklik on-prem'de yapılır, Entra Connect ile buluta akar (Modül 08)
```

### 2.2 On-prem LDAP entegrasyonu (Python örneği ile)

- **Bağlanma:** LDAPS (636) + Kerberos/simple bind (yalnız TLS üstünde). Entegrasyon hesabı **gMSA** veya dar yetkili servis hesabı olmalı ([03.4](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md)).
- **İşlemler:** search (provizyon öncesi kontrol), add (hesap oluştur), modify (öznitelik güncelle), modify-DN (taşı/yeniden adlandır).
- **En az ayrıcalık:** Entegrasyon hesabı yalnızca ilgili OU'da, yalnızca gereken özniteliklerde yazabilmeli (delegation → [03.1](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.1_OU_Tasarimi_ve_Yetki_Devri.md)).

### 2.3 Microsoft Graph REST API (Entra)

- **Kimlik doğrulama:** OAuth2. Bir **app registration / service principal** oluşturulur; **application permissions** (örn. `User.ReadWrite.All`, `Group.ReadWrite.All`) verilir ve **admin consent** alınır.
- **⚠️ Yetki riski:** Graph application permissions çok güçlüdür; `RoleManagement.ReadWrite.Directory` gibi bir izin, uygulamayı **Global Admin'e yükseltebilir**. App registration'ların gizli anahtarları (client secret/certificate) ve izinleri, ayrıcalıklı hesaplar kadar dikkatle korunmalı → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).
- **En az ayrıcalık:** Mümkünse delegated permission + dar scope; application permission'da yalnızca gerekeni ver ve süreli/sertifika-tabanlı kimlik kullan.

### 2.4 Windows Admin Center (WAC)

- **Ne:** Tarayıcı-tabanlı, MMC araçlarını (kullanıcı/grup, GPO, DNS, DHCP, sertifika, olay günlüğü) tek panelde toplayan modern yönetim arayüzü.
- **Mimari:** Bir **gateway** (masaüstü modunda tek makine, hizmet modunda merkezî sunucu) hedef sunuculara **WinRM/PowerShell Remoting** ile bağlanır.
- **⚠️ Gateway = kritik varlık:** WAC gateway, yönettiği tüm sunuculara ayrıcalıklı erişim taşır. Ele geçirilirse çok sayıda sunucu risk altındadır → **Tier 0/1** gibi korunmalı, PAW'dan erişilmeli, ayrı kimlik doğrulama (Entra ID + MFA) ile → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).

## 3. Pratik Uygulama

### On-prem LDAP entegrasyonu (Python ldap3)
```python
from ldap3 import Server, Connection, Tls, ALL, SUBTREE
import ssl
tls = Tls(validate=ssl.CERT_REQUIRED)                 # LDAPS zorunlu
srv = Server("dc01.corp.local", port=636, use_ssl=True, tls=tls, get_info=ALL)
conn = Connection(srv, user="CORP\\svc-ldap", password="***", auto_bind=True)  # gMSA tercih

# Provizyon öncesi kontrol (var mı?)
conn.search("OU=Users,DC=corp,DC=local", "(sAMAccountName=aliveli)", SUBTREE, attributes=["mail"])
print(conn.entries)
```

### Microsoft Graph (PowerShell SDK) ile bulut provizyon
```powershell
Connect-MgGraph -Scopes "User.ReadWrite.All","Group.ReadWrite.All"
# Kullanıcı oluştur (bulut) / grup üyeliği
New-MgUser -DisplayName "Ali Veli" -UserPrincipalName "ali.veli@corp.com" `
  -MailNickname "aliveli" -AccountEnabled -PasswordProfile @{ Password = "***"; ForceChangePasswordNextSignIn = $true }

# App registration izinlerini denetle (aşırı yetki avı)
Get-MgServicePrincipal -All | ForEach-Object {
  Get-MgServicePrincipalAppRoleAssignment -ServicePrincipalId $_.Id
} | Where-Object { $_.AppRoleId }   # geniş app permission'ları gözden geçir
```

### WAC gateway kurulumu (özet)
```powershell
# WAC gateway kurulumu (msi ile); hizmet modunda merkezî sunucu
# msiexec /i WindowsAdminCenter.msi /qn SME_PORT=443 SSL_CERTIFICATE_OPTION=installed
# Erişim: https://wac.corp.local  → Entra ID + MFA ile kimlik doğrulama önerilir
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Entegrasyon hesapları en az ayrıcalık + gMSA:** İK/IGA servisleri yalnızca ilgili OU/özniteliklerde yazabilmeli; geniş "Account Operators"/Domain Admin verme.
- **Graph app permission'larını denetle:** Aşırı `*.ReadWrite.All`/`RoleManagement.*` izinlerini periyodik gözden geçir; sertifika-tabanlı kimlik + kısa ömürlü sır.
- **LDAPS zorunlu:** Tüm entegrasyonlar TLS üstünde; düz 389 + simple bind yasak → [09.1](./09.1_LDAP_Mimarisi_ve_Sorgulama.md).
- **WAC gateway'i sıkılaştır:** MFA, RBAC, PAW'dan erişim, güncel tut; gateway'i Tier 0/1 gibi koru → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).
- **Değişiklikleri logla:** Provizyon/deprovizyon ve API çağrıları denetim izine düşmeli → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Aşırı yetkili Graph app registration:** `RoleManagement.ReadWrite.Directory` gibi izinler uygulamayı Global Admin'e yükseltir; client secret sızarsa tenant düşer → [Red M10](../../3-Red_Team/Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/). Dar scope + sertifika + denetim.
- 🔴 **WAC gateway'i korumasız bırakmak:** Yönettiği tüm sunuculara ayrıcalıklı erişim taşır; MFA/RBAC/PAW ile sıkılaştır.
- 🔴 **Entegrasyon hesabına geniş yetki:** İK provizyon servisi Domain Admin ise, o servisi kıran domaini kırar. En az ayrıcalık + gMSA.
- ⚠️ **Düz LDAP (389) entegrasyonu:** Simple bind parolası ağda açık; LDAPS zorunlu.
- 🔍 **İzleme ipucu:** Yeni/aşırı app registration izinleri, service principal secret ekleme, olağandışı provizyon dalgaları ve WAC gateway erişimi izlenmeli → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
