# 09.2 — PowerShell ActiveDirectory Modülü Ustalığı

> **Modül:** 09 — Otomasyon ve Arayüzler · **Kol:** Sistem Yöneticisi
> **Ön koşul:** [09.1 — LDAP Mimarisi ve Sorgulama](./09.1_LDAP_Mimarisi_ve_Sorgulama.md) · **Sonraki:** [09.3 — Configuration as Code (DSC)](./09.3_Configuration_as_Code_DSC.md)

---

## 1. Kavramsal Temel — Neden Var?

`dsa.msc` (GUI) 5000 kullanıcıyı tek tek düzenlemek için işe yaramaz. **PowerShell `ActiveDirectory` modülü**, AD yönetimini **otomatikleştirilebilir, tekrarlanabilir ve denetlenebilir** hale getirir. Bu modülün her cmdlet'i aslında bir **LDAP sorgusu/değişikliği** ([09.1](./09.1_LDAP_Mimarisi_ve_Sorgulama.md)) üretir — yani GUI'nin yaptığı her şeyi (ve fazlasını) script'le yapabilirsin.

> **Neden ustalık?** Çünkü modülü yüzeysel kullanmak (her şeyi `-Properties *` ile çekmek, filtreyi istemcide yapmak) hem yavaş hem hatalıdır. Ustalık, **doğru filtre + doğru öznitelik + doğru kapsam** üçlüsünü LDAP verimliliğiyle kurmaktır.

## 2. Teknik Derinlik

### 2.1 Kurulum ve modül

```powershell
# RSAT (istemcide) veya AD DS rolü (sunucuda) modülü getirir
# İstemci: Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0
Import-Module ActiveDirectory
Get-Command -Module ActiveDirectory | Measure-Object   # ~150+ cmdlet
```
`ActiveDirectory:` adında bir **PSDrive** de gelir (`cd AD:\` ile dizinde gezinilir).

### 2.2 Cmdlet → LDAP eşlemesi (en kritik kavram)

```
  PowerShell cmdlet          Arka planda LDAP
  ─────────────────          ────────────────
  Get-ADUser -Filter ...  →  Search: base=defaultNC, scope=Subtree, filter=(...)
  Get-ADObject -LDAPFilter → Search: senin ham LDAP filtren birebir
  Set-ADUser              →  Modify operation (öznitelik yaz)
  New-ADUser              →  Add operation
  -Server DC02            →  o DC'ye bağlan (aksi halde en yakın DC)
  -SearchBase / -SearchScope → base DN + Base/OneLevel/Subtree
```

### 2.3 `-Filter` vs `-LDAPFilter` — iki dil

- **`-Filter`** (PowerShell sözdizimi): `Get-ADUser -Filter "Enabled -eq \$true -and Department -eq 'IT'"`. Okunur ama arka planda LDAP'a çevrilir.
- **`-LDAPFilter`** (ham LDAP): `Get-ADUser -LDAPFilter "(&(objectClass=user)(department=IT))"`. Bit-testleri ve karmaşık filtreler için tek yol ([09.1](./09.1_LDAP_Mimarisi_ve_Sorgulama.md)).

> **Kural:** Basit koşullarda `-Filter`; UAC bit-testi gibi ham sorgularda `-LDAPFilter`. **`-Filter *` + istemcide `Where-Object` = anti-pattern** (tüm dizini çekip elde eler → yavaş, DC yükü).

### 2.4 `-Properties` ve varsayılan öznitelikler

`Get-ADUser` varsayılan yalnızca birkaç öznitelik döner (name, SID, UPN, enabled...). Diğerleri için **`-Properties`** gerekir:
```powershell
Get-ADUser aliveli -Properties LastLogonTimestamp, memberOf, servicePrincipalName
```
`-Properties *` her şeyi çeker ama **pahalıdır** — yalnızca ihtiyacın olanları iste (LDAP "attributes" listesi = ağ + DC yükü).

### 2.5 Büyük veri, sunucu seçimi, tutarlılık

- **Sunucu tutarlılığı:** Farklı DC'ler replikasyon gecikmesiyle ([02.2](../Modul_02_Fiziksel_Altyapi_ve_Replikasyon/02.2_Replikasyon_KCC_ve_Bridgehead.md)) farklı sonuç verebilir. Kritik çok-adımlı işlemlerde **`-Server`** ile aynı DC'yi sabitle (örn. oluştur + hemen grup ekle).
- **GC sorgusu:** Forest-geneli arama için `-Server "dc01:3268"` ([01.2](../Modul_01_Mimari_ve_Temeller/01.2_Schema_Global_Catalog_Partitionlar.md)).
- **Sayfalama otomatiktir:** Modül paged search'ü kendi yapar (1000 sınırı → [09.1](./09.1_LDAP_Mimarisi_ve_Sorgulama.md)); ama `-ResultSetSize`/`-ResultPageSize` ile kontrol edilebilir.

## 3. Pratik Uygulama

### Verimli sorgular (doğru desen)
```powershell
# İYİ: filtre sunucuda, yalnız gereken öznitelikler
Get-ADUser -LDAPFilter "(&(objectCategory=person)(objectClass=user)(!userAccountControl:1.2.840.113556.1.4.803:=2))" `
  -Properties LastLogonTimestamp -SearchBase "OU=Users,DC=corp,DC=local" |
  Select SamAccountName, @{N='SonGiris';E={[datetime]::FromFileTime($_.LastLogonTimestamp)}}

# KÖTÜ (anti-pattern): her şeyi çek, istemcide ele
# Get-ADUser -Filter * -Properties * | Where-Object {$_.Enabled}
```

### Toplu işlem (CSV'den kullanıcı oluşturma)
```powershell
Import-Csv .\yeni_kullanicilar.csv | ForEach-Object {
  New-ADUser -Name $_.Ad -SamAccountName $_.Kullanici -UserPrincipalName "$($_.Kullanici)@corp.com" `
    -Path "OU=Users,OU=Kurumsal,DC=corp,DC=local" -Department $_.Departman `
    -AccountPassword (ConvertTo-SecureString $_.Parola -AsPlainText -Force) `
    -Enabled $true -ChangePasswordAtLogon $true -Server "dc01.corp.local"   # aynı DC
}
```

### Güvenlik denetimi tek satırlarla
```powershell
# Ayrıcalıklı grup üyeleri (recursive)
Get-ADGroupMember "Domain Admins" -Recursive | Select SamAccountName

# 90 gündür atıl etkin hesaplar
Search-ADAccount -AccountInactive -TimeSpan 90.00:00:00 -UsersOnly |
  Where Enabled | Select SamAccountName, LastLogonDate

# Değişiklik yapmadan önce prova: -WhatIf
Disable-ADAccount -Identity "eskiuser" -WhatIf
```

### ADSI/.NET fallback (modül yoksa / ağır entegrasyon)
```powershell
# Modül olmadan da LDAP'a erişim (09.1'deki DirectorySearcher)
$u = [ADSI]"LDAP://CN=Ali Veli,OU=Users,DC=corp,DC=local"
$u.Properties["description"].Value = "Güncellendi"; $u.SetInfo()
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Filtreyi sunucuda yap:** `-Filter`/`-LDAPFilter` ile DC'de daralt; `-Filter *`+`Where-Object`'ten kaçın.
- **Yalnız gereken öznitelikler:** `-Properties *` yerine adlandırılmış liste; performans ve netlik.
- **Çok-adımlı işlemde `-Server` sabitle:** Replikasyon gecikmesi kaynaklı "nesne bulunamadı" hatalarını önler.
- **`-WhatIf`/`-Confirm` ile prova:** Yıkıcı toplu işlemlerden önce daima kuru çalıştır.
- **En az ayrıcalık + gMSA:** Otomasyon hesapları dar yetkili; zamanlanmış görevler gMSA ile → [03.4](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md).
- **Loglama:** PowerShell ScriptBlock/Module logging açık olmalı (kimin ne çalıştırdığı) → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Aşırı yetkili otomasyon hesabı:** Script'lerin çalıştığı hesap Domain Admin ise, script'in bulunduğu her yer Tier 0 riskidir. Dar yetki + gMSA + PAW → [03.4](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md).
- 🔴 **Parolaları script'e gömmek:** Düz metin parola/anahtar script/CSV'de saklanmaz; gMSA veya güvenli sır kasası kullan.
- ⚠️ **`-Filter *` + `Where-Object`:** Büyük dizinde DC'yi yorar, yavaş, bazen 1000 sınırıyla eksik. Filtreyi sunucuda yap.
- ⚠️ **Replikasyon gecikmesini yok saymak:** Oluştur→hemen değiştir zincirinde farklı DC → "bulunamadı". `-Server` sabitle.
- 🔍 **İzleme ipucu:** PowerShell ScriptBlock logging (Event **4104**), olağandışı toplu AD değişiklikleri ve AD modülü ile kütle-enumerasyon izlenmeli — aynı araç savunmacının ve saldırganın elinde → [Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/).
