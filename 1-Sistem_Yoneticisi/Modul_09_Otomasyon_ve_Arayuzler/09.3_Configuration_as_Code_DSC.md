## 1. Kavramsal Temel — Neden Var?

[09.2](./09.2_PowerShell_AD_Modulu.md)'deki script'ler **imperatif**tir: "şunu yap, sonra şunu yap." Ama script iki kez çalışırsa ne olur? Ya biri sunucuya elle girip ayarı değiştirirse (**configuration drift**)? İmperatif script bunu bilmez.

**Configuration as Code (IaC)** farklı bir paradigma sunar — **deklaratif**: "sonuç şöyle olmalı" dersin, altyapı da mevcut durumu **istenen duruma** getirir ve **öyle tutar**. **PowerShell DSC (Desired State Configuration)** bunun Windows'taki uygulamasıdır. AD/altyapı yapılandırmasını versiyonlanabilir, tekrarlanabilir, drift'e dirençli kod haline getirir.

> **Anahtar fark:** İmperatif = "ADIMLAR". Deklaratif (DSC) = "SONUÇ" + **idempotency** (kaç kez uygularsan uygula, sonuç aynı; zaten doğruysa dokunmaz).

## 2. Teknik Derinlik

### 2.1 DSC'nin çalışma modeli

```
   Configuration (kod)          Derleme            LCM (her sunucuda)
  ┌────────────────────┐       ┌────────┐         ┌──────────────────────┐
  │ Configuration Web {│       │        │  MOF    │ Local Config Manager │
  │  Node "SRV01" {    │──────►│ .ps1 → │────────►│ • MOF'u uygular       │
  │   WindowsFeature IIS│      │  MOF   │         │ • drift'i tespit eder │
  │   { Ensure='Present'}│     │        │         │ • ConfigurationMode'a │
  │  }                 │       └────────┘         │   göre düzeltir       │
  │ }                  │                          └──────────────────────┘
  └────────────────────┘         ▲
    Deklaratif "istenen durum"    │  Push (elle gönder) VEYA Pull (sunucu çeker)
```

- **Configuration:** İstenen durumu tanımlayan PowerShell bloğu.
- **MOF:** Derlenmiş, makine-okur yapılandırma dosyası (her Node için bir MOF).
- **LCM (Local Configuration Manager):** Her hedef makinede çalışan ajan; MOF'u uygular, **drift'i tespit edip düzeltir** (`ConfigurationMode = ApplyAndAutoCorrect`).

### 2.2 Push vs Pull

| Model | Nasıl | Kullanım |
|-------|-------|----------|
| **Push** | MOF elle hedefe gönderilir (`Start-DscConfiguration`) | Küçük ölçek, test |
| **Pull** | Hedefler bir **Pull Server**'dan yapılandırmayı düzenli çeker | Ölçek, merkezî yönetim, otomatik drift düzeltme |

### 2.3 Idempotency ve drift düzeltme

DSC kaynakları **idempotent**tir: LCM önce "**Test**" (mevcut durum istenen mi?) çalıştırır, değilse "**Set**" (düzelt) yapar. `ApplyAndAutoCorrect` modunda LCM periyodik olarak (varsayılan 15/30 dk) drift'i **kendiliğinden** geri alır — biri elle bozarsa DSC düzeltir. Bu, güvenlik baseline'ını *dayatmanın* güçlü bir yoludur → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).

### 2.4 AD için DSC kaynakları (ActiveDirectoryDsc)

`ActiveDirectoryDsc` modülü AD'yi kodla yönetir: `ADDomain` (yeni forest/domain), `ADDomainController` (DC promote), `ADUser`, `ADGroup`, `ADOrganizationalUnit`, `ADReplicationSite`, `ADObjectPermissionEntry` (ACL) vb. Bir DC'yi sıfırdan kurmayı bile kodla tanımlayabilirsin.

### 2.5 DSC'nin bugünü (sürüm notu)

- **DSC 1.1/2.0 (Windows PowerShell):** WMF ile gelen klasik DSC; hâlâ yaygın.
- **DSC 3 (PowerShell 7 / cross-platform)** ve **Azure Machine Configuration (eski adı Guest Configuration):** Modern, bulut-yönetimli drift denetimi/uygulaması — hibrit ortamlarda ([Modül 08](../Modul_08_Hibrit_Kimlik_ve_Federasyon/)) merkezî uyumluluk için. Yeni tasarımlarda bu yönü değerlendir.

## 3. Pratik Uygulama

### Basit bir DSC configuration (idempotent)
```powershell
Configuration DcBaseline {
    Import-DscResource -ModuleName PSDesiredStateConfiguration
    Node "DC01" {
        WindowsFeature ADPowerShell {
            Name   = "RSAT-AD-PowerShell"
            Ensure = "Present"
        }
        Service W32Time {
            Name        = "W32Time"
            State       = "Running"
            StartupType = "Automatic"
        }
        Registry SmbSigning {
            Key       = "HKLM:\SYSTEM\CurrentControlSet\Services\LanManServer\Parameters"
            ValueName = "RequireSecuritySignature"
            ValueData = "1"
            ValueType = "Dword"
            Ensure    = "Present"
        }
    }
}
DcBaseline -OutputPath C:\DSC          # MOF derle
```

### LCM'i drift-düzeltmeye ayarla ve uygula (push)
```powershell
[DSCLocalConfigurationManager()]
Configuration LcmAyar {
    Node "DC01" {
        Settings {
            ConfigurationMode = "ApplyAndAutoCorrect"   # drift'i otomatik geri al
            ConfigurationModeFrequencyMins = 30
            RefreshMode = "Push"
        }
    }
}
LcmAyar -OutputPath C:\DSC\LCM
Set-DscLocalConfigurationManager -Path C:\DSC\LCM

Start-DscConfiguration -Path C:\DSC -Wait -Verbose   # MOF'u uygula
Test-DscConfiguration -Detailed                       # drift var mı?
Get-DscConfigurationStatus                             # son uygulama sonucu
```

### AD nesnesini kodla (ActiveDirectoryDsc)
```powershell
# Install-Module ActiveDirectoryDsc
Configuration AdOU {
    Import-DscResource -ModuleName ActiveDirectoryDsc
    Node "DC01" {
        ADOrganizationalUnit ServiceAccounts {
            Name = "ServiceAccounts"; Path = "DC=corp,DC=local"
            ProtectedFromAccidentalDeletion = $true; Ensure = "Present"
        }
    }
}
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Deklaratif > imperatif (durum yönetiminde):** Sürekli olması gereken yapılandırmalar (baseline, roller, servisler) DSC ile; tek seferlik işler script ile.
- **`ApplyAndAutoCorrect` ile drift'e karşı savun:** Güvenlik baseline'ının elle bozulmasını LCM otomatik geri alır → [Blue M05](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/).
- **Kodu versiyonla:** Configuration'ları git'te tut; değişiklik denetimi + geri alma.
- **Pull server ile ölçekle:** Çok sunuculu ortamda merkezî pull + otomatik drift düzeltme.
- **Modern yönü değerlendir:** Yeni/hibrit ortamlarda DSC 3 / Azure Machine Configuration ile bulut-yönetimli uyumluluk → [Modül 08](../Modul_08_Hibrit_Kimlik_ve_Federasyon/).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **MOF içine sır gömmek:** MOF dosyaları düz metin olabilir; parola/anahtar gömme. Kimlik bilgileri için sertifika ile şifreleme (`CertificateID`) veya sır kasası kullan.
- 🔴 **Pull server/DSC altyapısını korumamak:** DSC hedeflere yapılandırma (ve dolaylı olarak kod) dağıtır; altyapısı ele geçirilirse kütlesel değişiklik yapılır → Tier 0 gibi koru.
- ⚠️ **Drift modunu yanlış seçmek:** `ApplyAndMonitor` yalnızca raporlar, düzeltmez; baseline dayatma istiyorsan `ApplyAndAutoCorrect`.
- ⚠️ **Test etmeden production'a uygulamak:** DSC güçlüdür; hatalı configuration kütlesel bozulma yapar. Önce lab/pilot.
- 🔍 **İzleme ipucu:** DSC uygulama/drift olayları (Microsoft-Windows-DSC operational log) merkezî toplanmalı; beklenmedik drift bir manipülasyon işareti olabilir → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
