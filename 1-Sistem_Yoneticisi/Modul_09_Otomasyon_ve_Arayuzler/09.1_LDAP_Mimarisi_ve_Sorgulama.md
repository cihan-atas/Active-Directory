## 1. Kavramsal Temel — Neden Var?

AD'nin kalbinde bir **LDAP (Lightweight Directory Access Protocol) dizini** vardır ([01.2](../Modul_01_Mimari_ve_Temeller/01.2_Schema_Global_Catalog_Partitionlar.md)). Tüm araçlar — `dsa.msc`, PowerShell AD modülü ([09.2](./09.2_PowerShell_AD_Modulu.md)), BloodHound, hatta saldırı araçları — aslında **LDAP sorguları** çalıştırır. Bu yüzden LDAP'ı ham seviyede anlamak, otomasyonun ve güvenlik analizinin temelidir: bir aracın "arka planda" ne yaptığını, neyi görebildiğini ve nasıl kısıtlanacağını ancak LDAP'ı bilerek anlarsın.

> **Anahtar:** Her AD sorgusu = **(1)** bir başlangıç noktası (base DN) + **(2)** bir kapsam (scope) + **(3)** bir filtre + **(4)** dönecek öznitelik listesi. Bu dördünü kavrayan, hem yönetimde hem güvenlikte LDAP'ın diline hâkim olur.

---

## 2. Teknik Derinlik

### 2.1 Protokol, portlar ve bind (bağlanma)

- **Portlar:** LDAP `389` (düz), LDAPS `636` (TLS); Global Catalog `3268`/`3269` (forest-geneli → [01.2](../Modul_01_Mimari_ve_Temeller/01.2_Schema_Global_Catalog_Partitionlar.md)).
- **Bind türleri:**
  - **Simple bind:** kullanıcı DN + parola (düz metin!). LDAP (389) üzerinde şifresizdir → kimlik bilgisi ağda açık. **Sadece LDAPS ile** kullanılmalı.
  - **SASL/GSSAPI (Kerberos/NTLM):** kimlik doğrulamalı, imzalı bind. AD'de tercih edilen yol; `dsa.msc`/PowerShell bunu kullanır.
  - **Anonymous bind:** Kimlik doğrulamasız. Modern AD'de büyük ölçüde kısıtlıdır (RootDSE dışında az şey görünür) ama yanlış yapılandırma bilgi ifşasına yol açar.

### 2.2 LDAP arama operasyonunun anatomisi

```
LDAP Search = 4 parça:

  ① Base DN (nereden başla)   →  OU=Users,DC=corp,DC=local
  ② Scope (ne kadar derin)    →  Base / OneLevel / Subtree
  ③ Filter (hangi nesneler)   →  (&(objectClass=user)(sAMAccountName=ali*))
  ④ Attributes (ne getir)     →  cn, mail, memberOf

  ┌──────────────────────────────────────────────────────────┐
  │ Scope görsel:                                            │
  │   Base      = yalnız base DN nesnesinin kendisi          │
  │   OneLevel  = base'in DOĞRUDAN çocukları                 │
  │   Subtree   = base ve ALTINDAKİ her şey (en yaygın)      │
  └──────────────────────────────────────────────────────────┘
```

### 2.3 LDAP filtre sözdizimi (RFC 4515) — polonya notasyonu

LDAP filtreleri **önek (prefix)** notasyonu kullanır; operatör başta, koşullar parantez içinde:

| Operatör | Anlam | Örnek |
|----------|-------|-------|
| `=` | eşit | `(sAMAccountName=aliveli)` |
| `&` | VE | `(&(objectClass=user)(mail=*))` |
| `\|` | VEYA | `(\|(l=Ankara)(l=Izmir))` |
| `!` | DEĞİL | `(!(userAccountControl:1.2.840.113556.1.4.803:=2))` = *devre dışı olmayanlar* |
| `*` | joker/var | `(servicePrincipalName=*)` = SPN'i olanlar |
| `:1.2.840...803:` | bitwise AND | UAC bit testi (aşağıda) |

**Bitwise (bit) kuralları — güvenlik denetiminin dili:**
```
(userAccountControl:1.2.840.113556.1.4.803:=2)        → ACCOUNTDISABLE bit'i açık
(userAccountControl:1.2.840.113556.1.4.803:=524288)   → TRUSTED_FOR_DELEGATION (0x80000)
(userAccountControl:1.2.840.113556.1.4.803:=4194304)  → DONT_REQ_PREAUTH (AS-REP)
```
Bunlar [03.2](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.2_Hesap_Yonetimi.md)'deki UAC bayraklarının ham LDAP karşılığıdır — hem yöneticinin denetim hem saldırganın keşif dilidir → [Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/).

### 2.4 Paged results (sayfalama) — 1000 sınırı

AD, tek sorguda varsayılan olarak en fazla **`MaxPageSize` = 1000** nesne döner. Daha fazlası için istemci **paged search control** kullanmalıdır (araçlar bunu otomatik yapar). Büyük dizinlerde script yazarken sayfalama unutulursa sonuçlar eksik gelir. `MaxPageSize` DC'nin LDAP policy'sinde ayarlanır (`ntdsutil` → LDAP policies).

## 3. Pratik Uygulama

### LDP.exe ile ham sorgulama (GUI)
```text
ldp.exe → Connection → Connect (server: dc01.corp.local, port 389/636)
       → Connection → Bind (kimlik doğrula, GSSAPI önerilir)
       → View → Tree (base DN seç)  veya  Browse → Search:
          Base DN: DC=corp,DC=local
          Filter:  (&(objectClass=user)(servicePrincipalName=*))
          Scope:   Subtree
```
`LDP.exe`, bir aracın ne gördüğünü ham LDAP olarak doğrulamanın en saf yoludur; saldırı tarafında `ldapsearch`/PowerView aynı işi yapar → [Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/).

### Komut satırı (dsquery / ldapsearch tarzı)
```powershell
# Yerleşik dsquery ile ham LDAP filtresi
dsquery * "DC=corp,DC=local" -filter "(&(objectClass=user)(servicePrincipalName=*))" -attr sAMAccountName servicePrincipalName -limit 0

# PowerShell'de ham LDAP filtresi (AD modülü → 09.2)
Get-ADObject -LDAPFilter "(userAccountControl:1.2.840.113556.1.4.803:=4194304)" `
  -SearchBase "DC=corp,DC=local" -Properties sAMAccountName | Select sAMAccountName

# .NET DirectorySearcher (modülsüz, saf LDAP — script/entegrasyon için)
$ds = New-Object DirectoryServices.DirectorySearcher
$ds.SearchRoot = [ADSI]"LDAP://DC=corp,DC=local"
$ds.Filter = "(&(objectClass=group)(cn=Domain Admins))"
$ds.PageSize = 1000                       # sayfalama — 1000 sınırını aş
$ds.PropertiesToLoad.AddRange(@("member"))
$ds.FindAll() | ForEach-Object { $_.Properties["member"] }
```

### RootDSE — dizin hakkında dizin
```powershell
# Kimlik doğrulamadan bile okunabilen "dizinin meta bilgisi"
([ADSI]"LDAP://RootDSE").Properties |
  ForEach-Object { $_ }   # defaultNamingContext, configurationNamingContext, supportedControl...
```

## 4. Tasarım İlkeleri (Mimarın Bakışı)

- **Her zaman LDAPS/GSSAPI:** Simple bind'i düz LDAP (389) üzerinde kullanma — parola açığa çıkar. Entegrasyonlarda LDAPS (636) veya Kerberos zorunlu.
- **Sayfalamayı unutma:** 1000+ nesne dönen scriptlerde paged search; aksi halde sessizce eksik veri.
- **Filtreyi sunucuda daralt:** Tüm nesneleri çekip istemcide filtrelemek yerine, LDAP filtresini olabildiğince spesifik yaz (DC yükü + hız).
- **En az ayrıcalıkla bağlan:** Entegrasyon hesapları yalnızca gereken OU/öznitelikleri okuyabilmeli; gMSA tercih et → [03.4](../Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md).
- **LDAP imzalama/channel binding'i zorla:** DC'ler imzasız/şifresiz bind'leri reddetmeli → [Blue M08](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/).

## 6. Güvenlik Notu ve Sık Yapılan Hatalar

- 🔴 **Simple bind + düz LDAP (389):** Parola ağda açık gider; NTLM relay/dinleme ile yakalanır. Daima LDAPS/GSSAPI.
- 🔴 **LDAP = keşfin ana dili:** Aynı sorgu dili, yönetici için envanter, saldırgan için saldırı yolu haritasıdır. Düşük yetkili bir hesap bile domain'in büyük kısmını enumerate edebilir → [Red M01](../../3-Red_Team/Modul_01_Kesif_ve_Numaralandirma/). Bunu engelleyemezsin ama **izleyebilirsin** (olağandışı geniş subtree sorguları) → [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
- ⚠️ **Anonymous/zayıf bind ifşası:** Anonim bind'in görebildiklerini denetle; gereksiz açık bırakma.
- ⚠️ **Sayfalama hatası:** Büyük sonuç kümesinde eksik veri → yanlış kararlar/otomasyon hataları.
- 🔍 **İzleme ipucu:** İmzasız/anonim bind girişimleri (LDAP interface events, Event **2889**), olağandışı geniş subtree sorguları izlenmeli → [Blue M08](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/), [Blue M02](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/).
