## 1. Genel Bakış ve Mimari

Klasik LDAP sorguları hedefe dair **düz ve ayrık listeler** sunar: 5.000 kullanıcı, 900 grup, 10.000 ACL girdisi. Ancak modern Active Directory ortamlarında Domain Admin seviyesine giden yol düz bir liste değil, **karmaşık bir ilişki grafiğidir (graph)**:

> **Active Directory bir grafiktir.** 
> - **Düğümler (Nodes):** Kullanıcılar (`User`), Gruplar (`Group`), Bilgisayarlar (`Computer`), Domain (`Domain`), OU (`OU`), GPO (`GPO`), Sertifika Şablonları (`CertTemplate`).
> - **Kenarlar (Edges):** `MemberOf`, `AdminTo`, `HasSession`, `GenericAll`, `WriteDacl`, `WriteOwner`, `ForceChangePassword`, `AllowedToDelegate`, `AddKeyCredentialLink`.

Bir saldırgan için kritik hedef (Tier 0 / Domain Admins), bu graf üzerinde başlangıç düğümünden (`Owned`) hedef düğüme uzanan **en kısa ve en az gürültülü kenar zincirini (Shortest Attack Path)** bulmaktır.

```
       [ Saldırgan Makinesi ]
                 │
                 ├── (1) SharpHound Veri Toplama ──► [ DC & İstemciler ]
                 │       (LDAP 389/636, SMB 445, RPC 135/SAMR)
                 │
                 ├── (2) JSON / ZIP Arşivi
                 ▼
       [ BloodHound CE / Neo4j ]
       ┌─────────────────────────────────────────────────────────────┐
       │                       GRAF VERİTABANI                       │
       │                                                             │
       │  [jdoe] ──MemberOf──► [Helpdesk] ──GenericAll──► [svc-sql] │
       │                                                     │       │
       │  [DA] ◄──DCSync── [Domain] ◄──AdminTo── [SRV01] ◄─HasSess──┘│
       └─────────────────────────────────────────────────────────────┘
```

BloodHound mimarisi iki temel bileşenden oluşur:
1. **Toplayıcı (Collector - SharpHound / BloodHound.py):** Hedef ortamda LDAP, SMB ve RPC protokollerini kullanarak nesneleri, oturumları ve izinleri toplayan ve JSON/ZIP üreten araç.
2. **Analizör ve Arayüz (BloodHound CE & Neo4j):** Toplanan JSON verilerini graf veri modeline aktaran, REST API ve Web arayüzü sunan, **Cypher** sorgu dili ile karmaşık saldırı yollarını milisaniyeler içinde çözen analiz motoru.

## 2. Teknik Derinlik ve Protokol Analizi

### 2.1 SharpHound Toplama Kanalları ve Protokol Detayları

SharpHound, verileri tek bir kaynaktan değil, üç farklı ağ kanalını harmanlayarak elde eder:

| Protokol / Port | Sorgulanan Servis | Toplanan Veri ve Kenarlar | OPSEC Gürültü Seviyesi |
| :--- | :--- | :--- | :--- |
| **LDAP / LDAPS** (TCP 389 / 636) | Active Directory Domain Service | Kullanıcılar, gruplar, bilgisayarlar, SPN'ler, GPO'lar, OU hiyerarşisi, nesne DACL'leri (`GenericAll`, `WriteDacl`). | **Düşük:** Normal DC LDAP trafiğiyle karışır. |
| **SMB** (TCP 445 / Named Pipes) | `\pipe\samr`, `\pipe\srvsvc`, `\pipe\lsarpc` | Uzak makinelerdeki yerel `Administrators`, `Remote Desktop Users` grup üyeleri (`AdminTo`, `CanRDP`). | **Orta-Yüksek:** Her iş istasyonuna TCP 445 bağlantısı açar. |
| **MSRPC** (TCP 135 + Dinamik Portlar) | `NetSessionEnum`, `NetWkstaUserEnum` | Hangi kullanıcının hangi bilgisayarda aktif oturumu olduğu (`HasSession`). | **Yüksek:** EDR sistemleri tarafından port taraması ve RPC anomalisi olarak yakalanır. |

### 2.2 Toplama Metotları (`CollectionMethod`) Karşılaştırması

```
Metot Bayrağı     Kapsam                         Hedef Sistemler      Tavsiye Edilen Senaryo
─────────────────────────────────────────────────────────────────────────────────────────────
DCOnly            Sadece LDAP + Trusts          Yalnızca DC'ler      Gizli operasyonlar (OPSEC dostu)
LocalAdmin        Yerel grup üyeleri            Tüm domain hostları  Yanal hareket hedefleri belirleme
Session           Aktif oturumlar               Tüm domain hostları  Domain Admin avlama (HasSession)
LoggedOn          Kayıt defteri oturumları      Tüm domain hostları  Local admin gerektirir (ayrıntılı)
ObjectProps       Nesne öznitelikleri           Yalnızca DC'ler      SPN, UAC, parola yaşı analizi
ACL               Nesne DACL izinleri           Yalnızca DC'ler      Yetki yükseltme kenarları çıkarma
Container         OU ve Container yapısı        Yalnızca DC'ler      GPO uygulama alanlarını haritalama
All               Yukarıdakilerin tamamı        Tüm ağ ve DC'ler     Zaman kısıtlı CTF veya tam denetim
```

## 3. Pratik Uygulama ve İleri Düzey Senaryolar

### Senaryo 1: Windows Host Üzerinden SharpHound ile Veri Toplama
Hedef Windows makinede bellekte (in-memory) veya diskten kontrollü veri toplama:

```powershell
# 1. En Sessiz Mod (DCOnly) — Sadece Domain Controller ile iletişim kurar
.\SharpHound.exe -c DCOnly --domain corp.local --outputdirectory C:\Windows\Temp --zipfilename silent_dc

# 2. Standart Toplama (ACL, Grup, Bilgisayar ve Nesne Özellikleri)
.\SharpHound.exe -c Default --domain corp.local --outputdirectory C:\Windows\Temp --zipfilename loot_default

# 3. Yüksek OPSEC Koruması (İstekler arasına gecikme ve rastgelelik ekleme)
.\SharpHound.exe -c All --throttle 1500 --jitter 40 --domain corp.local --outputdirectory C:\Windows\Temp
```

---

### Senaryo 2: Linux Üzerinden bloodhound-python ile Uzaktan Toplama
Windows makinelere doğrudan bulaşmadan, ağ üzerinden doğrudan DC ve sunucuları sorgulama:

```bash
# 1. Tam toplama (Tüm metotlar açık, Kerberos veya NTLM ile)
bloodhound-python -u jdoe -p 'Summer2024!' -d corp.local -dc DC01.corp.local -c All --zip

# 2. Yalnızca LDAP odaklı gizli toplama (DCOnly eşdeğeri)
bloodhound-python -u jdoe -p 'Summer2024!' -d corp.local -dc DC01.corp.local -c DCOnly --zip -ns 10.10.10.5

# 3. NetExec (nxc) ile tek satırda otomatik toplama
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --bloodhound --collection-method All -ns 10.10.10.5
```

### Senaryo 4: Kritik Cypher Sorgu Reçeteleri (Operasyonel İstihbarat)

BloodHound Web arayüzünde "Raw Cypher Query" alanına girilerek en kritik hedefler filtrelenir:

```cypher
// 1. Ele geçirilen hesaptan (Owned) Domain Admins grubuna giden EN KISA yol
MATCH p=shortestPath((u:User {name:"JDOE@CORP.LOCAL"})-[*1..]->(g:Group {name:"DOMAIN ADMINS@CORP.LOCAL"}))
RETURN p

// 2. Kerberoastable olup DA grubuna saldırı yolu bulunan hesaplar (Yüksek Öncelik)
MATCH (u:User {hasspn:true}), p=shortestPath((u)-[*1..]->(g:Group {name:"DOMAIN ADMINS@CORP.LOCAL"}))
RETURN u.name, length(p) ORDER BY length(p) ASC

// 3. Ele geçirilmiş makinelerde (Owned) aktif oturumu olan Tier 0 / Admin hesaplar
MATCH (c:Computer {owned:true})<-[:HasSession]-(u:User)
WHERE u.admincount = true
RETURN c.name, u.name

// 4. Doğrudan veya dolaylı DCSync yetkisine sahip zafiyetli kullanıcılar
MATCH (n)-[:MemberOf|GetChanges|GetChangesAll*1..]->(d:Domain {name:"CORP.LOCAL"})
WHERE NOT n.name STARTS WITH "DOMAIN CONTROLLERS" AND NOT n.name STARTS WITH "ENTERPRISE DOMAIN CONTROLLERS"
RETURN DISTINCT n.name, labels(n)

// 5. Unconstrained Delegation açık olan ve Tier 0 hedeflere ulaşabilen bilgisayarlar
MATCH (c:Computer {unconstraineddelegation:true}), p=shortestPath((c)-[*1..]->(g:Group {name:"DOMAIN ADMINS@CORP.LOCAL"}))
RETURN c.name, length(p)
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Mesajı / Kod | Olası Kök Neden | Çözüm Adımı |
| :--- | :--- | :--- |
| `Failed to connect to the computer (0x800706BA) - The RPC server is unavailable` | Hedef host kapalı, Windows Güvenlik Duvarı RPC portlarını (`135`, dinamik RPC) blokluyor veya host çevrimdışı. | Toplama metodunu `-c DCOnly` olarak değiştirin; iş istasyonlarını atlayıp yalnızca DC'yi tarayın. |
| `Status: 0xc0000022 (Access Denied) NetSessionEnum` | Windows 10/11 ve Server 2016+ üzerinde `NetSessionEnum` varsayılan olarak standart kullanıcılara kısıtlanmıştır. | Standart `Session` yerine yerel admin yetkisi elde ettikten sonra `-c LoggedOn` kullanın. |
| `System.OutOfMemoryException` | Binlerce bilgisayar ve yüzbinlerce nesne içeren ormanlarda SharpHound RAM sınırını aşar. | `--memcache` parametresini kapatın veya `--searchforest false` ile sadece geçerli domain'e odaklanın. |
| `Neo4j Error: Database is locked by another process` | Neo4j veritabanı konteyneri veya servisi beklenmedik şekilde kapandı ve lock dosyası kaldı. | `docker compose down`, ardından neo4j data klasöründeki `.lock` dosyasını silip tekrar başlatın. |
| `bloodhound-python: ldap3.core.exceptions.LDAPSocketOpenError` | DC DNS adı Linux üzerinde çözülemiyor veya 389/636 portları ağ seviyesinde filtreleniyor. | `/etc/hosts` dosyasına DC FQDN kaydını ve IP'sini ekleyin; `-ns 10.10.10.5` ile doğrudan IP belirtin. |
| `Upload Failed: Invalid JSON or corrupt ZIP` | SharpHound çalıştırma sırasında yarıda kesildi veya arşiv sıkıştırma bozuldu. | ZIP arşivini açıp JSON dosyalarının bütünlüğünü kontrol edin; SharpHound'u tekrar çalıştırın. |

## 5. Bıraktığı İz ve Karşı Tespit (OPSEC & Blue Eşleştirmesi)

### 5.1 Bıraktığı İzler (Artifacts & Telemetri)
* **Windows Security Event ID 4624 (Type 3 - Network Logon):** SharpHound oturum veya yerel admin sorguları yaparken ağdaki yüzlerce bilgisayara aynı anda oturum açar. Kısa sürede anormal oturum artışı görülür.
* **SMB Named Pipe Bağlantıları (Sysmon Event ID 18):** `\pipe\samr`, `\pipe\srvsvc`, `\pipe\wkssvc` borularına arka arkaya yapılan erişimler.
* **Process Creation (Event ID 4688 / Sysmon Event ID 1):** SharpHound.exe dosyasının diskten çalıştırılması ve PE metadata imzaları.

### 5.2 Ağ ve EDR İmzaları
* **Toplu RPC/SMB Taraması:** Tek bir istemci IP adresinden alt ağdaki tüm makinelere doğru TCP 445 ve TCP 135 portlarına yönelik hızlı syn-ack trafiği EDR ve NIDS tarafından "Port Scan / Lateral Recon" olarak etiketlenir.
* **Bellek İmzaları:** SharpHound'un varsayılan derlemesi AMSI tarafından imzalanmıştır; doğrudan PowerShell üzerinden yüklenmesi `ScriptBlockLogging (Event ID 4104)` üretir.

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Kullanım Senaryosu |
| :--- | :--- | :--- |
| **[T1069.002](https://attack.mitre.org/techniques/T1069/002/)** | Permission Groups Discovery: Domain Groups | Domain ve yerel admin grup üyeliklerinin çıkarılması. |
| **[T1049](https://attack.mitre.org/techniques/T1049/)** | System Network Connections Discovery | `NetSessionEnum` ile aktif oturumların haritalanması. |
| **[T1087.002](https://attack.mitre.org/techniques/T1087/002/)** | Account Discovery: Domain Account | Kullanıcı, bilgisayar ve servis hesaplarının taranması. |
| **[T1078](https://attack.mitre.org/techniques/T1078/)** | Valid Accounts | Elde edilen geçerli kimlik bilgisiyle izin verilen tüm nesneleri sorgulama. |

### 5.4 OPSEC Tavsiyeleri ve Savunma Karşılığı

| Kırmızı Takım Operatör Riski | OPSEC İyileştirme Adımı | Savunma (Blue Team) Karşı Tedbiri |
| :--- | :--- | :--- |
| Ağ genelinde 4624 patlaması ve port alarmı | `-c All` yerine **`-c DCOnly`** kullanın; iş istasyonlarına dokunmayın. | Tek bir istemciden ağdaki birden fazla makineye 10 dakika içinde yapılan Type 3 oturumları SIEM kuralıyla alarmlayın. |
| `\pipe\samr` üzerinden yerel admin keşfi | Uzak SAM sorgusu yerine yalnızca LDAP üzerinden nesne DACL izinlerini çıkarın. | `Network access: Restrict clients allowed to make remote calls to SAM` GPO ilkesini uygulayın. |
| SharpHound binary tespit edilmesi | Diske yazmadan `execute-assembly` ile bellekten çalıştırın veya Linux `bloodhound-python` kullanın. | PowerShell Script Block Logging, Constrained Language Mode ve EDR bellek taraması uygulayın. |

## 6. En Çok Kullanılan Komutlar (Hızlı Referans / Cheat Sheet)

```powershell
# 1. En Sessiz Toplama (Sadece DC LDAP - Sıfır İstemci İzi)
.\SharpHound.exe -c DCOnly --domain corp.local --zipfilename dc_only.zip
# Ne Yapar?: Yalnızca DC üzerindeki LDAP veritabanını ve trust ilişkilerini çeker.
# Ne Zaman Kullanılır?: EDR ve NIDS tespitinden kaçınmak gereken gizli operasyonlarda.
# Parametreler: -c DCOnly (sadece DC odaklı metot), --domain (hedef domain).

# 2. Tam Toplama ve İstek Yavaşlatma (Stealth / Throttled)
.\SharpHound.exe -c All --throttle 1000 --jitter 30 --zipfilename all_stealth.zip
# Ne Yapar?: Oturumlar dahil her şeyi toplar; her istek arasına 1 saniye ± %30 gecikme ekler.
# Ne Zaman Kullanılır?: Derin analiz gerekirken EDR eşik değerlerine takılmamak için.
# Parametreler: --throttle (milisaniye cinsinden bekleme), --jitter (rastgelelik yüzdesi).

# 3. Linux Üzerinden bloodhound-python ile Dışarıdan Toplama
bloodhound-python -u jdoe -p 'Summer2024!' -d corp.local -dc DC01.corp.local -c All --zip
# Ne Yapar?: Windows makineye hiçbir dosya yüklemeden Linux saldırı makinesinden verileri çeker.
# Ne Zaman Kullanılır?: İlk foothold Linux/VPN üzerindeyken veya Windows endpoint izi bırakılmak istenmediğinde.

# 4. Yalnızca Oturum Bilgisi Toplama (Session Loop)
.\SharpHound.exe -c Session --loop --loopinterval 1800 --loopduration 12:00:00
# Ne Yapar?: 12 saat boyunca her 30 dakikada bir oturumları tarayarak admin hareketlerini yakalar.
# Ne Zaman Kullanılır?: Hedef yöneticilerin oturum açma saatlerini ve jump host'larını belirlemek için.

# 5. NetExec ile Hızlı BloodHound Çıktısı Üretme
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --bloodhound -c DCOnly -ns 10.10.10.5
# Ne Yapar?: NetExec üzerinden tek komutla LDAP'ı tarayıp otomatik BloodHound ZIP'i oluşturur.
# Ne Zaman Kullanılır?: Hızlı pentest senaryolarında vakit kaybetmeden graf oluşturmak için.

# 6. Docker ile BloodHound CE Sunucusunu Başlatma
docker compose -f docker-compose.yml up -d
# Ne Yapar?: BloodHound CE web arayüzünü ve arka plandaki Neo4j veritabanını konteynerde başlatır.
# Ne Zaman Kullanılır?: Toplanan ZIP dosyalarını analiz etmek ve Cypher sorguları çalıştırmak için.
```
