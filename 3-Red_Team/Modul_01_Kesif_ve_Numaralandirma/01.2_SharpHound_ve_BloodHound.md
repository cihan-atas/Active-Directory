## 1. Kavramsal Temel — Neden Var?

LDAP enumerasyonu sana **ham liste** verir: 4000 kullanıcı, 800 grup, 1200 ACL. Ama saldırı planı bu listede değil, **ilişkilerdedir**. Kilit içgörü:

> **AD bir grafiktir (graph).** Düğümler (nodes) = kullanıcı/grup/bilgisayar/GPO/OU/domain. Kenarlar (edges) = "üyesidir", "yönetici olarak oturum açar", "GenericAll yetkisi var", "parolasını değiştirebilir", "delegation'a güvenilir". **Domain admin'e giden yol, bu grafikte bir dizi kenardan ibarettir.**

BloodHound bu grafiği çıkarır ve **Neo4j** graf veritabanında saklar. "Elimdeki `jdoe` hesabından Domain Admins'e kaç sıçramada varırım?" sorusuna **Cypher** sorgusuyla yanıt verir — insanın gözle bulamayacağı 5-6 kenarlık dolambaçlı yolları saniyede bulur.

**Analoji:** LDAP döküm = bir şehrin tüm bina/sokak listesi. BloodHound = Google Maps'in "en kısa yol" motoru. Saldırgan hedefe (DA) giden en kısa/en az gürültülü rotayı ister.

**İki parça:**
- **SharpHound** = toplayıcı (collector). LDAP + SMB + RPC ile veriyi toplar, JSON/ZIP üretir.
- **BloodHound** = analizör (GUI + Neo4j). ZIP'i içe alır, grafiği çizer, saldırı yollarını hesaplar.

## 2. Teknik Derinlik — SharpHound Ne Toplar, Nasıl?

### 2.1 Toplama metotları (CollectionMethods)

SharpHound farklı veri türlerini farklı protokollerle toplar:

```
                       SharpHound Toplama Kanalları
  ┌───────────────────────────────────────────────────────────────┐
  │  LDAP (389/636)   → nesneler, üyelikler, ACL'ler, SPN, UAC     │
  │  SMB  (445)       → yerel grup üyeliği (RPC/SAMR), oturumlar    │
  │  RPC  (135+dyn)   → NetSessionEnum, NetWkstaUserEnum (oturumlar)│
  │  DNS              → bilgisayar adı çözümleme                    │
  └───────────────────────────────────────────────────────────────┘
```

| CollectionMethod | Ne toplar | Gürültü |
|------------------|-----------|---------|
| `Group` | Grup üyelikleri | Düşük (sadece LDAP) |
| `LocalAdmin` / `LocalGroup` | Uzak makinelerde yerel admin (SAMR) | **Orta-yüksek** (her makineye RPC) |
| `Session` | Kimin nerede oturumu var (**lateral movement altını**) | **Yüksek** (NetSessionEnum tüm makinelere) |
| `ACL` | DACL kenarları (GenericAll vb.) | Düşük (LDAP) |
| `Trusts` | Domain/forest güvenleri | Düşük |
| `DCOnly` | **Sadece DC'den LDAP** — makinelere dokunmaz | **En sessiz** |
| `All` | Hepsi | En gürültülü |

> **Session kenarı neden altın?** `svc-admin` hesabı `WS042` üzerinde oturum açtıysa ve sen `WS042`'de yerel adminsen → o makinede LSASS'tan `svc-admin` kimlik bilgisini çalabilirsin ([Modül 03](../Modul_03_Kimlik_Bilgisi_Erisimi/)). Session verisi "nerede avlanacağımı" söyler.

### 2.2 Grafik veri modeli — kenar türleri

```
[jdoe:User] ──MemberOf──▶ [IT-Support:Group]
                              │
                              ├─GenericAll──▶ [svc-sql:User]        (parolasını sıfırla!)
                              │
[svc-sql:User] ──HasSession──▶ [SRV05:Computer]
                                   │
                                   └─AdminTo──▶ ... ──DCSync──▶ [corp.local:Domain]  🏁
```

BloodHound'un **"Shortest Path to Domain Admins"** ön-tanımlı sorgusu bu zinciri otomatik bulur. Her kenar, sömürü tekniğine karşılık gelir (GenericAll → [Modül 05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/), HasSession → kimlik hırsızlığı).

### 2.3 Kenar türü → sömürü modülü tam eşlemesi

| BloodHound kenarı | Anlamı | Sömürü |
|-------------------|--------|--------|
| `MemberOf` | Grup üyeliği (zincirli) | Miras yetkiler |
| `AdminTo` / `CanRDP` / `CanPSRemote` | Makinede yerel admin/erişim | [Modül 04](../Modul_04_Yanal_Hareket/) |
| `HasSession` | Kimlik o makinede cache'li | LSASS → [Modül 03](../Modul_03_Kimlik_Bilgisi_Erisimi/) |
| `GenericAll`/`GenericWrite`/`WriteDacl`/`WriteOwner` | ACL kontrolü | [Modül 05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| `ForceChangePassword` | Parola sıfırlama | [Modül 05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| `AllowedToDelegate` / `AllowedToAct` | Constrained/RBCD | [Modül 06](../Modul_06_Kerberos_Delegation_Saldirilari/) |
| `AddKeyCredentialLink` | Shadow Credentials | [Modül 07](../Modul_07_AD_CS_PKI_Saldirilari/) |
| `DCSync` (GetChanges+GetChangesAll) | Hash replikasyonu | [Modül 09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |
| `GPLink` / `WriteGPLink` | GPO ile makine kontrolü | [Modül 05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |

### 2.4 Toplama zamanı ve "zaman penceresi" gerçeği

`HasSession` kenarı **anlıktır** — SharpHound koştuğu anda kim oturumdaysa onu görür. Bir domain admin gündüz jump host'a bağlanıp akşam çıkarsa, SharpHound'u yanlış zamanda koştuysan o altın kenarı kaçırırsın.

> **Profesyonel taktik:** Session toplamayı **farklı saatlerde tekrarla** (sabah/öğle/akşam) ve BloodHound'a ayrı ZIP olarak yükle — grafiğin `HasSession` kenarları birikir. Böylece "hangi admin, hangi makinede, ne zaman" zaman-haritasını çıkarırsın. Tek atış = eksik grafik.

## 3. Pratik Uygulama — Toplama ve Analiz

### 3.1 SharpHound ile toplama (birden çok yol)

```powershell
# A) Windows üzerinde derlenmiş SharpHound.exe (en sessiz: DCOnly)
.\SharpHound.exe -c DCOnly --outputdirectory C:\temp --zipfilename loot

# B) Tam toplama (Session dahil — gürültülü ama zengin)
.\SharpHound.exe -c All --domain corp.local --stealth

# C) Zamanlama gizleme (jitter) — EDR desen tespitini zorlaştır
.\SharpHound.exe -c All --throttle 1000 --jitter 30   # istekler arası 1s ± %30
```

```bash
# D) Linux'tan uzaktan — bloodhound-python (araç Windows'a dokunmaz, sadece DC LDAP/SMB)
bloodhound-python -u jdoe -p 'Summer2024!' -d corp.local -ns 10.10.10.5 -c All --zip

# E) NetExec ile (nxc) tek satır toplama
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --bloodhound --collection-method All \
  -ns 10.10.10.5
```

**Örnek çıktı:**
```
2026-07-05 ... INFO: Found 412 users
2026-07-05 ... INFO: Found 87 groups
2026-07-05 ... INFO: Found 63 computers
2026-07-05 ... INFO: Compressing data into 20260705_bloodhound.zip
```

### 3.2 BloodHound'a yükleme (CE / Neo4j)

```bash
# BloodHound Community Edition (Docker)
curl -L https://ghst.ly/getbhce | docker compose -f - up
# tarayıcı: http://localhost:8080  → ZIP'i "Upload Data" ile içe al
```

### 3.3 Yerleşik ve özel Cypher sorguları

```cypher
// En kısa yol: elimdeki hesaptan Domain Admins'e
MATCH p=shortestPath((u:User {name:"JDOE@CORP.LOCAL"})-[*1..]->(g:Group {name:"DOMAIN ADMINS@CORP.LOCAL"}))
RETURN p

// Kerberoastable + yüksek yetkili (öncelikli hedefler)
MATCH (u:User {hasspn:true}) WHERE u.admincount=true RETURN u.name

// "Owned" işaretlediğim düğümlerden ulaşılabilen her şey (sömürü sonrası genişleme)
MATCH p=shortestPath((o {owned:true})-[*1..]->(t)) RETURN p

// Unconstrained delegation makineleri (Modül 06 hedefleri)
MATCH (c:Computer {unconstraineddelegation:true}) RETURN c.name
```

### 3.4 İleri Cypher — operatör sorguları

```cypher
// Kerberoastable → Domain Admins'e giden yolu OLAN hesaplar (öncelikli roast hedefi)
MATCH (u:User {hasspn:true}), p=shortestPath((u)-[*1..]->(g:Group {name:"DOMAIN ADMINS@CORP.LOCAL"}))
RETURN u.name, length(p) ORDER BY length(p)

// Sahibi olduğum makinelerde HasSession'ı olan yüksek-değerli hesaplar (avlanacak kimlik)
MATCH (c:Computer {owned:true})<-[:HasSession]-(u:User) WHERE u.admincount RETURN c.name, u.name

// DCSync yapabilen (yanlış ACL'li) principal'lar
MATCH (n)-[:MemberOf|GetChanges|GetChangesAll*1..]->(d:Domain {name:"CORP.LOCAL"})
WHERE n.name =~ '(?i).*' RETURN DISTINCT n.name

// En "değerli" kısa yol: owned düğümden 3 kenardan az uzaklıktaki Tier 0
MATCH p=shortestPath((o {owned:true})-[*1..3]->(t {highvalue:true})) RETURN p
```

### 3.5 Analiz akışı (Red operatör pratiği)

1. Toplanan ZIP'i yükle → **"Mark Domain Users as Owned"** ile başlangıç düğümünü işaretle.
2. **"Shortest Paths to Domain Admins"** ve **"Shortest Paths from Owned Principals"** çalıştır.
3. Her kenarın "Help → Abuse Info" sekmesi tam sömürü komutunu verir (BloodHound içinde reçete).
4. En az-gürültülü/en-kısa yolu seç → ilgili modüle geç.

### 3.6 Gerçek-dünya zincir örneği (grafikten aksiyona)

```
   [jdoe] ─MemberOf→ [HELPDESK] ─ForceChangePassword→ [svc-sql]
                                        │  (Modül 05: parolayı sıfırla)
   [svc-sql] ─HasSession→ [SRV05]  ─AdminTo→ [SRV05]
                                        │  (Modül 03/04: SRV05'te LSASS dump)
   [SRV05 LSASS] → [backup-admin NT hash] ─MemberOf→ [BACKUP OPERATORS]
                                        │  (SeBackupPrivilege → NTDS.dit kopyala, Modül 09)
   → DCSync/NTDS → DOMAIN ADMIN 🏁
   Dört kenar, dört modül, tek grafik. BloodHound bu zinciri saniyede çizer.
```

| Session toplama (NetSessionEnum) | **T1049** (System Network Connections Discovery) | Kısa sürede **çok sayıda makineye** SMB/RPC bağlantısı; 4624 Type 3 patlaması | [Blue 04.1 — Anormal oturum](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.1_Anormal_Oturum_Acma_Analizi.md) |

| ACL/grup toplama | **T1069** / T1087 | Kısa sürede geniş LDAP tarama | [Blue 09.2 — PingCastle](../../2-Blue_Team/Modul_09_Tehdit_Avciligi_ve_Degerlendirme/09.2_PingCastle_ile_Risk_Skorlama.md) |

**OPSEC notları:**
- **`-c DCOnly`** ile başla: yalnızca DC'ye LDAP yapar, iş istasyonlarına hiç dokunmaz → Session/LocalAdmin verisi kaybolur ama **iz de kaybolur**. Gürültülü Session toplamayı yalnızca gerekince, `--stealth` + `--jitter` ile yap.
- Toplayıcıyı diskten çalıştırmak yerine **bellek-içi** (Cobalt Strike `execute-assembly`, `.NET reflection`) çalıştır → AMSI/EDR imza tespitini azalt. AMSI/ETW bypass detayı → [Modül 10.4](../Modul_10_Trust_Forest_ve_Hibrit_Saldirilar/).
- Savunma tarafı **aynı grafiği** çizip riski önden kapatabilir — bu yüzden gördüğün yol, tespit edildiyse yamalanmış olabilir.
