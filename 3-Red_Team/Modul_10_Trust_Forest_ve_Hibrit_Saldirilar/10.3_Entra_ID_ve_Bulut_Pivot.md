## 1. Kavramsal Temel — Neden Var?

Modern kurumlar tamamen on-prem değil: on-prem AD, **Entra ID (eski Azure AD)** ile senkronize edilir ([hibrit kimlik](../../1-Sistem_Yoneticisi/Modul_08_Hibrit_Kimlik_ve_Federasyon/)). Bu köprü çift yönlü bir saldırı yüzeyidir: on-prem AD'yi ele geçiren saldırgan **buluta** sıçrayabilir (Microsoft 365, Azure abonelikleri); tersine, bulutta ele geçirilen belirli kimlikler **on-prem'e** iner. "Domain hakimiyeti" artık forest'ta bitmez — **tenant hakimiyetine** kadar uzanır.

**Analoji:** On-prem AD ve Entra ID, aralarında sürekli mal taşıyan iki depo gibidir. Senkronizasyon köprüsü (**Entra Connect** sunucusu) bu iki depoyu birbirine bağlayan **köprü kamyonudur**. Kamyonun şoförünü (Connect servis hesabı) ele geçirirsen, her iki depoya da mal sokup çıkarabilirsin. Üstelik köprünün kimlik doğrulama modeli (PHS/PTA/Federation) hangi kapıların açık olduğunu belirler.

**Neden kritik:** Entra Connect sunucusu **çok ayrıcalıklıdır** — hem on-prem'de `DCSync` yapabilen bir hesap (`MSOL_...`) tutar, hem de buluta yazma yetkisi vardır. Bu sunucu genellikle Tier-0 gibi korunmaz → saldırganın favori pivot noktasıdır. Federation (AD FS) senaryosunda ise **token imzalama sertifikası** çalınırsa **Golden SAML** ile herhangi bir bulut kullanıcısı taklit edilir.

## 2. Teknik Derinlik — Hibrit Kimlik Modelleri ve Pivot Yolları

Senkronizasyonun kimlik doğrulama modeli saldırı yüzeyini belirler ([Sistem 08.2](../../1-Sistem_Yoneticisi/Modul_08_Hibrit_Kimlik_ve_Federasyon/08.2_Kimlik_Dogrulama_PHS_PTA_Federation.md)):

| Model | Nasıl çalışır | Saldırı yüzeyi |
|---|---|---|
| **PHS** (Password Hash Sync) | Parola hash'inin hash'i buluta senkronlanır | Connect sunucusundan `MSOL_` hesabı DCSync; on-prem hash → bulut |
| **PTA** (Pass-Through Auth) | Doğrulama on-prem agent'a geçer | PTA agent'a DLL enjeksiyonu → tüm parolaları yakala |
| **Federation** (AD FS) | Token AD FS imzalar (SAML) | Token imzalama sertifikası çalınırsa **Golden SAML** |

**On-prem → Bulut pivot (Connect sunucusu):**
```
 Entra Connect Sunucusu (ele geçirildi)
   ├── MSOL_xxxxxxxx hesabı (on-prem DCSync yetkili) ──▶ tüm on-prem hash'ler
   ├── ADSync veritabanı (şifreli) ──▶ AADConnect anahtarlarını çöz ──▶ Sync hesabı bulut token'ı
   └── Seamless SSO ──▶ AZUREADSSOACC$ hesabı hash'i ──▶ Silver Ticket (bulut)
```

**AADInternals ile ADSync decrypt:** Connect sunucusundaki `ADSync` SQL veritabanı (LocalDB), senkronizasyon hesabının kimlik bilgilerini şifreli tutar; ama şifreleme anahtarı aynı sunucudaki **DPAPI** (mcrypt anahtarı, `keyset` GUID'i) ile korunur → yerel admin, `Get-AADIntSyncCredentials` ile bunu çözer. Sonuç iki kimlik verir: (1) on-prem `MSOL_xxxx` hesabı (DCSync yetkili) → tüm on-prem hash'ler; (2) bulut **Directory Synchronization Account** (Sync_*) → tenant'a yazma. Yani tek sunucudan **her iki yöne** de tam erişim çıkar.

**Golden SAML (Federation):** AD FS, buluta SAML token'ları imzalar. **Token-signing sertifikasının özel anahtarı** (AD FS sunucusunda DPAPI-DKM ile korunur) çalınırsa, saldırgan **herhangi bir kullanıcı için, MFA'yı bile atlayarak** geçerli SAML token üretir → bulutta o kullanıcı. Kerberos'taki [Golden Ticket](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/09.2_Golden_Silver_Diamond_Sapphire_Ticket.md)'ın bulut karşılığı.

**Seamless SSO (`AZUREADSSOACC$`):** Bu makine hesabının parolası nadiren değişir; hash'i alınırsa **bulut için Silver Ticket** üretilir → kesintisiz oturum taklidi.

**Golden SAML akış detayı (neden MFA'yı atlar):** SAML federasyonunda güven zinciri şöyledir: kullanıcı → AD FS (kimliği doğrular, SAML token imzalar) → Entra ID (imzaya güvenir, oturum açar). MFA **AD FS aşamasında** uygulanır. Golden SAML, AD FS'i **tamamen baypas ederek** token-signing özel anahtarıyla doğrudan geçerli bir SAML assertion üretir — kullanıcı hiç AD FS'e uğramaz, dolayısıyla MFA hiç tetiklenmez. Entra ID yalnızca imzanın geçerliliğine baktığından token'ı kabul eder. Bu, on-prem [Golden Ticket](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/09.2_Golden_Silver_Diamond_Sapphire_Ticket.md)'ın (krbtgt yerine token-signing key) tam bulut analoğudur ve **parola/MFA değişiminden bağımsızdır** — tek çözüm sertifika rotasyonudur.

**PRT (Primary Refresh Token) anatomisi:** Entra-joined/hybrid-joined cihazlarda, kullanıcının oturumu bir **PRT** ile temsil edilir; bu token cihazın TPM'inde korunan bir anahtarla bağlanır ve tarayıcıya SSO sağlar. `sekurlsa::cloudap` ile PRT + oturum anahtarı (POP key) LSASS'ten çıkarılır. PRT zaten MFA'dan geçmiş bir oturumu temsil ettiğinden, çalınan PRT ile üretilen erişim token'ları **MFA'yı yeniden istemez** → Conditional Access "uyumlu/hybrid cihaz" koşulu bunun tek gerçek freni.

**Model bazlı saldırı seçimi:**
| Model | Birincil vektör | Tek çözüm |
|---|---|---|
| PHS | Connect `MSOL_` DCSync + Sync hesabı | Connect'i Tier-0 koru |
| PTA | Agent'a DLL enjeksiyon (tüm parolaları yakala) | Agent host'unu Tier-0 koru |
| Federation | Golden SAML (token-signing çalma) | Sertifika rotasyonu + AD FS Tier-0 |

## 3. Pratik Uygulama — Çok Araçlı

**A) Entra Connect sunucusundan sync kimliği çıkarma (AADInternals):**
```powershell
# Connect sunucusunda (yerel admin)
Import-Module AADInternals
Get-AADIntSyncCredentials          # MSOL_ + Sync hesabı kimlik bilgileri (decrypt)
# On-prem DCSync (MSOL_ hesabıyla):
Get-AADIntSyncCredentials | ...    # → DCSync yetkisi doğrulanır
```

**B) Golden SAML (AD FS token-signing çalma):**
```powershell
# AD FS sunucusunda: token imzalama sertifikasını + DKM anahtarını çıkar
Export-AADIntADFSSigningCertificate
# Herhangi bir kullanıcı için SAML token üret:
New-AADIntSAMLToken -UserPrincipalName victim@corp.com -Certificate signing.pfx
```

**C) PRT (Primary Refresh Token) çalma — join'li cihazdan:**
```
# Mimikatz — PRT + oturum anahtarı (cihazda)
privilege::debug ; sekurlsa::cloudap
# ROADtoken / AADInternals ile PRT'yi kullan → bulut erişimi (MFA atlatma)
```

**D) Bulut keşif + yol analizi:**
```bash
# ROADtools — Entra ID grafiğini dök, ayrıcalıklı rolleri bul
roadrecon gather ; roadrecon plugin gui
# AzureHound — BloodHound bulut saldırı yolları
azurehound -u user -p pass list --tenant <id> -o output.json
```

**Vektör → sonuç özeti:**

| Vektör | Ele geçirilen | Sonuç |
|---|---|---|
| `Get-AADIntSyncCredentials` | Connect sync kimliği | On-prem DCSync + tenant yazma |
| Golden SAML | Token-signing key | Her kullanıcı, MFA'sız (AD FS) |
| PRT çalma (`cloudap`) | PRT + POP key | Cihaz oturumu, MFA atlar |
| Seamless SSO | `AZUREADSSOACC$` hash | Bulut Silver Ticket |

**E) PRT ile bulut erişimi (join'li cihazdan, MFA atlar):**
```
# Cihazda PRT + POP key çıkar, ROADtoken ile access token üret
privilege::debug ; sekurlsa::cloudap        # Mimikatz: PRT + session key
roadtx browserprtauth --prt <PRT> --prt-sessionkey <key>   # tarayıcı SSO → bulut
```

**Gerçek-dünya zinciri:**
```
on-prem DA ──▶ Entra Connect sunucusu (Tier-0 değil!) ──▶ Get-AADIntSyncCredentials
        │                                                        │
        ▼                                                        ▼
   MSOL_ DCSync (on-prem hash) + Sync hesabı bulut token ──▶ Global Admin ekle ──▶ 🏁 tenant
```

**Gerçek-dünya notu:** Birçok kurumda Entra Connect sunucusu "sıradan bir üye sunucu" gibi Tier-1'de tutulur — oysa on-prem DCSync yetkisi + bulut yazma yetkisiyle **gizli bir Tier-0 varlığıdır**. Bu tek sunucu, hem on-prem forest'ı hem bulut tenant'ı köprüler; ele geçirilmesi çift taraflı tam kompromiz demektir.

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Kaynak İz (IOC) | Karşı Blue |
|---|---|---|---|
| Golden SAML | **T1606.002** (Forge Web Credentials: SAML) | AD FS dışı token; olağandışı `Issuer`; MFA'sız yüksek erişim | [Blue 10.1](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.1_IR_Playbook_Tespitten_Containment.md) |
| Connect sync kimliği | T1003 / T1078.004 | `MSOL_` DCSync (4662); ADSync DB erişimi | [Blue 9.x](../../2-Blue_Team/Modul_09_Tehdit_Avciligi_ve_Degerlendirme/) |
| PRT çalma | **T1550.001** | `sekurlsa::cloudap`; olağandışı cihazdan bulut erişimi | [Blue 3.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md) |
| Seamless SSO Silver | T1558.002 | `AZUREADSSOACC$` bilet anomalisi | [Blue 6.x](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/) |

**OPSEC notları:**
- **Bulut telemetrisi ayrıdır:** On-prem 4662/4624 ile bulut **Entra ID Sign-in / Audit logs** (ör. "yeni Global Admin", "olağandışı konumdan token") farklı yerlerde toplanır. Golden SAML özellikle sinsidir çünkü AD FS log'unda **hiç oturum görünmez** (token AD FS'i baypas ederek üretilir) — Blue tarafı bunu "AD FS'te karşılığı olmayan bulut oturumu" korelasyonuyla avlar.
- **Connect sunucusu = gizli Tier-0:** Çoğu ortamda yanlışlıkla Tier-1 gibi korunur. Saldırgan için düşük gürültülü altın madeni; Blue için ise onu Tier-0 sınıflandırmak en önemli önlemdir.
- **PRT + MFA:** Çalınan PRT, cihaz zaten MFA geçmiş olduğundan **MFA'yı atlar**. Conditional Access "uyumlu cihaz" zorlaması bunu kısmen kırar.
- **Kurtarma:** Bulut ihlali on-prem krbtgt reset'iyle bitmez — **token-signing sertifikası rotasyonu, sync hesabı reset, Global Admin denetimi** gerekir. AADInternals izleri bulut audit'te kalır.
- **Çift yönlü risk:** Pivot yalnızca on-prem→bulut değildir. Bulutta ele geçirilen bir **Global Admin**, "on-prem'e yaz" yetkisiyle (Intune/hybrid) veya Connect sunucusu üzerinden **on-prem'e inebilir**. Bu yüzden Tier-0 tanımı artık forest + tenant'ı birlikte kapsar.
- **Conditional Access bypass sınırı:** Çalınan PRT MFA'yı atlar ama CA "yalnızca uyumlu cihazdan" koşulu, PRT'nin bağlı olduğu cihaz saldırgan makinesinde olmadığından erişimi kısabilir — bu yüzden saldırgan PRT'yi **join'li cihazda** kullanmaya çalışır.

**Tespit mantığı (Blue bakışı):** Bulut telemetrisi on-prem'den ayrıdır: (1) **Entra ID Sign-in logs** — olağandışı konum/cihazdan token, MFA'sız yüksek erişim; (2) **Audit logs** — "Add member to Global Administrator", yeni federasyon dom'ı/uygulama kimlik bilgisi; (3) **AD FS** — token-signing sertifikasına erişim (Event 500/501) veya AD FS'te karşılığı olmayan bulut oturumu (Golden SAML imzası). Bu korelasyon [Blue 10.1 IR playbook](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.1_IR_Playbook_Tespitten_Containment.md) hibrit kapsamındadır.

## 5. Doğrulama / Lab

```powershell
# Lab: hibrit test tenant + Entra Connect sunucusu (PHS)
# 1) Get-AADIntSyncCredentials ile sync kimliğini çıkar, MSOL_ DCSync doğrula
# 2) (Federation lab) Export-AADIntADFSSigningCertificate + New-AADIntSAMLToken ile taklit test et
# Blue doğrulama (bulut tarafı — yeni ayrıcalıklı rol):
# Entra ID Audit Log: "Add member to role" (Global Administrator) olağandışı aktör
# AD FS: token-signing sertifikası erişimi (Event 500/501)
```

**KQL (Entra ID Sign-in — Golden SAML / olağandışı yüksek erişim):**
```kusto
// AD FS federasyonlu tenant'ta MFA olmadan, olağandışı IP'den yönetici erişimi
SigninLogs
| where AuthenticationRequirement == "singleFactorAuthentication"
| where ResultType == 0
| where AppDisplayName in ("Azure Portal","Microsoft Graph")
| join kind=inner (
    AuditLogs | where OperationName has "Add member to role"
    | where TargetResources has "Global Administrator")
  on $left.UserPrincipalName == $right.InitiatedBy
| project TimeGenerated, UserPrincipalName, IPAddress, Location
```

**Sigma kuralı (Connect sunucusunda AADInternals / ADSync erişimi):**
```yaml
title: Entra Connect Server - Sync Credential Extraction
logsource: { product: windows, category: process_creation }
detection:
  aadint: { CommandLine|contains: ['Get-AADIntSyncCredentials','Export-AADIntADFSSigningCertificate'] }
  adsync_db: { CommandLine|contains|all: ['ADSync','mcrypt'] }
  condition: aadint or adsync_db
level: critical
```
Golden SAML'ın en sinsi yanı: AD FS log'unda **karşılığı yoktur** → Blue "AD FS'te oturum olmadan gerçekleşen federatif bulut girişi" korelasyonuyla ([Blue 10.1](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.1_IR_Playbook_Tespitten_Containment.md)) avlar.
