## 1. Kavramsal Temel — Neden Var?

Buraya kadarki her teknik bir **iz** bıraktı (4662, 4769, 5136…). Olgun bir savunma bu izleri EDR, AMSI ve ETW ile toplar; bir kırmızı takım operasyonu **tespit edilmeden** ilerlemek zorundadır. Bu bölüm, saldırının "görünmezlik katmanını" — Windows'un görünürlük mekanizmalarını (AMSI, ETW, script logging) nasıl kör ettiğini ve izlerin nasıl azaltıldığını — inceler. Amaç yıkım değil, **savunmanın hangi noktada kör olduğunu göstererek onu güçlendirmektir** ([Blue M01](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/)).

**Analoji:** Bir hırsız için asıl mesele kasayı açmak değil, **kameraları ve alarmları** yönetmektir. AMSI = binanın kapıda içeriği tarayan dedektörü; ETW = koridorlardaki kameralar; script block logging = güvenlik defterine yazan katip. Bu teknikler, dedektörü "her şey temiz" demeye zorlamak, kameraları kör noktaya çevirmek ve katibin kalemini kurutmaktır — ama **kesin sınır:** kırmızı takım bunu *rapor eder ve geri alır*, gerçek yıkım/kalıcı kör etme kapsam dışıdır (§6).

**Neden kill chain'in sonunda:** İz gizleme her aşamayı destekler ama en çok **hakimiyet fazında** (Red [09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/)–[10](./10.1_SID_History_Injection.md)) kritiktir; çünkü orada en gürültülü (DCSync, ticket forging) işlemler yapılır ve tespit maliyeti en yüksektir.

## 2. Teknik Derinlik — AMSI, ETW ve Logging Yüzeyleri

### AMSI (Antimalware Scan Interface)
AMSI, script içeriğini (PowerShell, VBA, JScript) **çalışma anında** AV motoruna gönderir. Kritik fonksiyon `amsi.dll!AmsiScanBuffer`'dır: bir buffer'ı tarar, `AMSI_RESULT_DETECTED` dönerse çalıştırma engellenir.

```
 PowerShell script ──▶ AmsiScanBuffer(buffer) ──▶ AV motoru ──▶ temiz/kötü?
                              │
        Bypass: bu fonksiyonu patch'le → her zaman AMSI_RESULT_CLEAN (0) dönsün
```

**Yaygın bypass yaklaşımları:**
- **Bellek patch'i:** `AmsiScanBuffer` girişine `mov eax, 0x80070057; ret` (E_INVALIDARG) yazarak taramayı "geçersiz argüman" ile atla — buffer hiç taranmaz.
- **`amsiInitFailed` bayrağı:** .NET AMSI başlatmayı başarısız gibi işaretle → tarama devre dışı.
- **Obfuscation:** İmza tabanlı tespiti string parçalama/encoding ile atla (fonksiyonu patch'lemeden).

### ETW (Event Tracing for Windows)
ETW, EDR'lerin telemetri omurgasıdır — özellikle `Microsoft-Windows-DotNETRuntime` (assembly yükleme) ve `Threat-Intelligence` provider'ları. `ntdll!EtwEventWrite` fonksiyonu patch'lenirse (`ret` ile), süreç ETW olayı üretmez → EDR görünürlüğü kısmen kör olur.

```
 .NET assembly yükle ──▶ EtwEventWrite(...) ──▶ ETW oturumu ──▶ EDR
                              │
        Bypass: EtwEventWrite'ı ret'le → olay hiç yazılmaz
```

### Script Block Logging (4104)
PowerShell 4104, çalıştırılan script bloklarını (deobfuscate edilmiş) loglar → en değerli Blue kaynağı ([Blue 1.3](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/01.3_Sysmon_ile_Derin_Telemetri.md)). Saldırganlar **PowerShell'i hiç kullanmayarak** (C#/BOF/unmanaged) veya AMSI/ETW patch'i ile bunu azaltır.

**Kritik gerçek:** Bu patch'ler **süreç-içidir** (in-memory, o process'e özgü) ve **kalıcı değildir** — Blue tarafı `AmsiScanBuffer`/`EtwEventWrite` bütünlük kontrolü, davranışsal EDR ve **merkezi WEF** ([Blue 1.1](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/01.1_Windows_Event_Forwarding_WEF.md)) ile yakalayabilir. Log'lar merkezde toplanıyorsa yerel patch onları geriye dönük silemez.

### Hardware breakpoint & syscall alternatifleri
İmza tabanlı AMSI/ETW patch tespiti yaygınlaştıkça saldırganlar daha sinsi yöntemlere kaydı:
- **Donanım breakpoint (Dr registers):** `AmsiScanBuffer`'a bellek yazmadan (patch imzası bırakmadan), CPU debug register'ları ile fonksiyona breakpoint konur; tetiklendiğinde dönüş değeri manipüle edilir. Bellek bütünlük kontrolünü atlatır çünkü kod değişmez.
- **Doğrudan syscall (Hell's Gate/Halo's Gate):** EDR'lerin `ntdll` içindeki user-mode hook'larını atlamak için, `NtAllocateVirtualMemory` gibi syscall'lar `ntdll`'i hiç çağırmadan doğrudan `syscall` talimatıyla yürütülür → EDR'nin hook noktası devre dışı kalır.
- **Unhooking:** EDR'nin `ntdll`'e yerleştirdiği hook'ları, diskteki temiz `ntdll` kopyasını belleğe yeniden eşleyerek kaldırma.

Bu tekniklerin ortak amacı **iz üretmeyi engellemek** (silmek değil) — çünkü merkezi toplanan bir log geriye dönük silinemez; oluşmasını önlemek tek etkili yoldur.

**Neden "kör etme" değil "sessizlik":** AMSI/ETW patch, tüm makineyi kalıcı köre çevirmez (§6 sınırı); yalnızca **saldırganın kendi sürecinin** telemetrisini bastırır. Diğer süreçler, WEF, ağ telemetrisi ve DC olayları (4662/4769) etkilenmez → bu yüzden domain-seviyesi izler ([Red 09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/)) yine kalır. Savunma atlatma **tamamlayıcıdır**, tek başına görünmezlik sağlamaz.

## 3. Pratik Uygulama — Çok Araçlı

**A) AMSI bypass (kavramsal — patch mantığı):**
```powershell
# Eğitim amaçlı: AmsiScanBuffer'ı bul + koruma bayrağını değiştir + patch
# (imza tespitinden kaçmak için string'ler parçalanır)
$a = [Ref].Assembly.GetType('System.Management.Automation.Amsi'+'Utils')
$f = $a.GetField('amsi'+'InitFailed','NonPublic,Static')
$f.SetValue($null,$true)   # AMSI başlatmayı başarısız işaretle
```

**B) ETW bypass (EtwEventWrite patch — kavramsal):**
```csharp
// ntdll!EtwEventWrite girişine 'ret' (0xC3) yaz → .NET assembly olayları susar
// VirtualProtect ile RX→RWX, tek byte patch, geri koru
```

**C) Araç/framework yaklaşımları:**
```
# Modern C2/loader'lar bunları yerleşik sunar (yetkili test bağlamında):
#  - Cobalt Strike / Sliver: in-memory AMSI+ETW patch seçeneği
#  - Invoke-Obfuscation: PowerShell imza kaçınma
#  - unmanaged / BOF (Beacon Object File): PowerShell yüzeyini tamamen atla
```

**D) İz azaltma (OPSEC hijyeni):**
```powershell
# Ticket/dosya temizliği (test sonrası)
klist purge ; Remove-Item *.kirbi,*.ccache,*.pfx -Force
# Yaratılan test nesnelerini geri al (RBCD, sIDHistory, sahte makine hesapları)
Set-ADComputer FAKE01 -Clear 'msDS-AllowedToActOnBehalfOfOtherIdentity'
Remove-ADComputer FAKE01 -Confirm:$false
```

**E) Test nesnelerinin envanteri (temizlik için — yetkili test hijyeni):**
```powershell
# Operasyon boyunca yaratılan tüm yapay nesneleri raporla + geri al
Get-ADComputer -Filter 'Name -like "FAKE*"'                     # sahte makine hesapları
Get-ADObject -LDAPFilter '(msDS-AllowedToActOnBehalfOfOtherIdentity=*)'  # RBCD kalıntıları
Get-ADObject -LDAPFilter '(msDS-KeyCredentialLink=*)'           # Shadow Cred kalıntıları
# → hepsi rapora eklenir ve testin sonunda temizlenir
```

**Gerçek-dünya zinciri (OPSEC katmanı):**
```
loader ──▶ AMSI patch ──▶ ETW patch ──▶ araç in-memory yükle (Rubeus/SharpHound)
        │                                        │
        ▼                                        ▼
   PowerShell yerine BOF ──▶ 4104 yok ──▶ DCSync/ticket ──▶ temizlik ──▶ rapor
```

**Gerçek-dünya notu:** Olgun kırmızı takımlar iz *silmez*, iz *üretmemeye* çalışır ve ürettiği her yapay nesneyi (hesap, ACE, ticket, PRT) kayıt altına alıp operasyon sonunda geri alır. Bu, hem §6 etik sınırının gereği hem de gerçek saldırgandan ayrışan profesyonel disiplindir — bulgular Blue'ya devredilir, ortam ilk haline döndürülür.

**OPSEC notları:**
- **En büyük yanılgı:** "AMSI/ETW patch'ledim, görünmezim." Yanlış — patch **süreç-içidir**, ama merkezi topланan log'lar (WEF/SIEM) zaten oluştuysa geri alınamaz ve **davranışsal EDR** patch'in kendisini yakalar (`amsi.dll`/`ntdll` bütünlük ihlali).
- **Log temizleme (1102) paradoksu:** Security log'u temizlemek en gürültülü işlemdir — **1102 olayının kendisi** merkezde alarm üretir. Merkezi loglama varsa temizlik faydasızdır; bu yüzden olgun saldırgan log **temizlemez**, **üretmemeye** çalışır.
- **En sessiz yaklaşım:** İz *silmek* değil, iz *bırakmamak* — PowerShell yerine unmanaged/BOF, LSASS dump yerine [DCSync](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/09.1_DCSync_ile_Hash_Cikarma.md), gürültülü toplu dökümler yerine hedefli tek-hesap işlemler.
- **§6 sınırı (mutlak):** Yetkili testte iz gizleme **savunmanın kör noktasını raporlamak** içindir. Yaratılan tüm arka kapılar/nesneler geri alınır, log'lar **silinmez**, bulgular Blue'ya devredilir. Gerçek anti-forensics/yıkım kapsam dışıdır.

## 5. Doğrulama / Lab

```powershell
# Lab: izole VM, EDR test sürümü
# 1) AMSI bypass öncesi/sonrası bilinen bir test string'inin (EICAR-benzeri) taranmasını karşılaştır
# 2) ETW patch sonrası .NET assembly yükleme olaylarının kaybolduğunu doğrula
# Blue doğrulama (savunma bozma avı):
Get-WinEvent -FilterHashtable @{LogName='Security';Id=1102}          # log temizleme
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PowerShell/Operational';Id=4104} |
  Where-Object { $_.Message -match 'Amsi|EtwEventWrite|VirtualProtect' }
```

**Sigma kuralı (AMSI/ETW bypass göstergeleri):**
```yaml
title: AMSI / ETW Bypass and Log Tampering Indicators
logsource: { product: windows, service: powershell }   # ScriptBlock 4104
detection:
  amsi_patch:
    ScriptBlockText|contains:
      - 'amsiInitFailed'
      - 'AmsiScanBuffer'
      - 'System.Management.Automation.AmsiUtils'
  etw_patch:
    ScriptBlockText|contains: ['EtwEventWrite','NtTraceEvent']
  log_clear: { EventID: 1102 }                          # Security log temizleme
  condition: amsi_patch or etw_patch or log_clear
level: high
```

**KQL (amsi.dll/ntdll bellek bütünlük ihlali — davranışsal EDR):**
```kusto
DeviceEvents
| where ActionType in ("WriteToLsassProcess","ProtectVirtualMemory")
| where InitiatingProcessFileName in~ ("powershell.exe","rundll32.exe")
| where AdditionalFields has_any ("amsi.dll","ntdll.dll")
| project Timestamp, DeviceName, InitiatingProcessCommandLine
```
**Kilit savunma dersi:** Yerel patch, **merkezi toplanmış** log'ları (WEF→SIEM) geri alamaz; bu yüzden [Blue 1.1 WEF](../../2-Blue_Team/Modul_01_Gorunurluk_ve_Log_Yonetimi/01.1_Windows_Event_Forwarding_WEF.md) mimarisi, saldırganın "iz bırakmama" stratejisinin tek gerçek panzehiridir — log yerelde silinemez, çünkü zaten merkeze akmıştır.
